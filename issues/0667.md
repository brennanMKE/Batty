# 0667 — There is no `batty tab new`, so an agent cannot open a terminal Tab, with or without a command

| | |
|---|---|
| **Status** | open |
| **Module** | Tabs / App |
| **Platform** | macOS |
| **First seen** | 2026-11-18 |
| **Target** | 1.5.0 |

## Description

Child of #0660. An agent can open a terminal *Pane* that runs a command (`pane split -c`), but not a *Tab*. A Tab is often the better fit: a long build or test run in a new Tab of the agent's own Pane keeps the layout as it is. Add `batty tab new [--pane <id>] [-c <command>] [--cwd <dir>] [--background] [--json]`, which is also an MCP tool (`tab_new`) because the catalog is built from `capabilities`.

### Current state

- `tab` has one verb, `focus` (`BattyKit/Sources/batty/TabCommand.swift:17`). `docs/batty-cli-design.md` §2 A lists `batty tab new [-c <cmd>]` as proposed, and `docs/batty-cli-agent-workflows.md:546-548` lists "creating a Tab" as not available.
- The app can add a Tab: `AppStateStore.addTab(toPaneID:inheritingCWDFrom:)` (`BattyKit/Sources/BattyKit/Runtime/AppStateStore.swift:1967`) and `PaneRuntime.addTab` (`BattyKit/Sources/BattyKit/Runtime/PaneRuntime.swift:290`), which builds a `TabRuntime` with no command parameter.
- `TabRuntime` already supports a per-Tab command: `pane split -c` passes it through and `applyShellAndAppearancePreferences` sets `command`, `wait-after-command = true` and `abnormal-command-exit-runtime = 0` for it (`BattyKit/Sources/BattyKit/Runtime/TabRuntime.swift:429-458`).
- `pane split` prints only the new Pane's id and has no `--json` (`BattyKit/Sources/batty/PaneCommand.swift:183-193`).

## Expected behavior

- New XPC verb `tabNew` with `TabNewRequest { paneID?, command?, workingDirectory?, background? }` and `TabNewReply { sessionID, paneID, tabID }`.
- Target: `--pane`, else `BATTY_PANE_ID`, else the focused Pane (`BattyTargetResolver`). A non-terminal target Pane is a failure (exit 4) with a clear message.
- Working directory: `--cwd` (resolved to an absolute path by the CLI), else the calling Tab's cwd when the target is the caller's Pane, else the Pane's active Tab's cwd (same inheritance as Cmd-T; see #0463 for the existing inconsistency, not fixed here).
- `-c`: same semantics as `pane split -c` (runs in place of the shell; the Tab stays open after the command exits until closed).
- By default the new Tab becomes the Pane's active Tab, without moving keyboard focus away from the caller's Pane. `--background` adds it without selecting it.
- Plain output: the new Tab's id. `--json`: the reply.
- Emits a watch event like the other mutations (existing names: `pane_split`, `tab_focused`, `session_created`; the planner picks a `tab_created`-style name).

## Acceptance criteria

1. Unit tests on `AppStateStore`: adds a Tab to the target Pane with the command and cwd; refuses a non-terminal Pane; unknown Pane id fails; `background` leaves the active Tab unchanged; the caller's Pane keeps focus.
2. `CapabilitiesInputSchemaTests` drift oracle covers `tab new`; `MCPToolCatalogTests` lists `tab_new`.
3. A UI test (type-checked with `./build.sh ui-typecheck`, run in the next daily VM run) creates a Tab with `-c` and checks the chip appears.
4. Behind `agentIntegration` until #0669, per `AGENTS.md` ("Unfinished features on `main` stay behind a feature flag").

## Open questions

1. **Focus.** Recommended as above: select the new Tab, keep keyboard focus where it was, so an agent never steals typing from the user.
2. **`--title`?** Recommended: not now; no Tab rename verb exists yet.
