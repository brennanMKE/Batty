# 0100 — Pre-release preflight script

| | |
|---|---|
| **Status** | open |
| **Module** | Build / Tests |
| **Platform** | macOS |
| **First seen** | 2026-05-12 |

## Description

The release pipeline has many gates: build clean, all tests pass, terminfo bundled, version strings in sync between `Build.xcconfig` and `project.pbxproj`, signing identity present, notary keychain profile present, EC2 env vars exported, fork SHA on the published branch. Running each one manually before `scripts/release.sh` is fine for a careful developer but easy to skip something.

A `scripts/preflight.sh` that runs every gate in a single pass — failing loudly the moment any one drops — reduces the cost of "is this actually shippable right now?" from "set aside an hour" to "30 seconds and a checklist."

## What this issue ships

`scripts/preflight.sh` that runs (and reports pass/fail for) each gate:

### Build gates

- `xcodebuild -scheme Batty -destination 'platform=macOS' build` succeeds (unsigned is fine; the signing gate is separate).
- `xcrun swift test --package-path BattyKit` passes.
- The built app contains `Contents/Resources/terminfo/78/xterm-ghostty` (the `#0003` sentinel).

### Version gates

- `MARKETING_VERSION` in `Configuration/Build.xcconfig` is non-empty.
- Same value appears in every `MARKETING_VERSION` line in `Batty.xcodeproj/project.pbxproj` (xcconfig vs pbxproj drift bites).
- Optionally fail when `MARKETING_VERSION` doesn't match a SemVer regex.

### Sparkle gates

- `BattyKit/Package.swift` mentions `Sparkle` as a dependency.
- If `SUFeedURL` should be set, check it's present in the built bundle's Info.plist (`plutil -extract SUFeedURL raw .../Contents/Info.plist`). Skip the check if a flag like `--allow-no-sparkle` is passed.

### Release-pipeline gates

- Developer ID Application certificate is in the keychain (run `security find-identity` against the expected `Developer ID Application: <name> (<team>)`).
- `notarytool history --keychain-profile Batty-notary` succeeds (proves the profile exists).
- `create-dmg` and `fileicon` Homebrew binaries are on PATH.

### Website gates

- `website/index.html` exists and is non-empty.
- `website/appcast.xml` parses as valid XML.
- If `BATTY_EC2_KEY`, `BATTY_EC2_HOST`, `BATTY_EC2_PATH` are exported: check key perms, target SSH up. Skip the SSH liveness check if the user passes `--skip-ssh-check`.

### Fork gate

- `BattyKit/Package.swift` either uses `.package(url:..., revision:...)` (good — reproducible) or `.package(path:...)` (warn — local-only).
- If URL+revision: do a `git ls-remote https://github.com/brennanMKE/libghostty-spm` and confirm the pinned SHA is on `refs/heads/batty-delegates` (so it's actually published).

### Workspace gate

- Working tree is clean (`git status --porcelain` is empty). Fail unless `--allow-dirty` is passed.
- HEAD is up-to-date with `origin/main` (no unpushed commits if we're tagging right now). Warn-only by default.

## Output

Color-coded, one line per gate:

```
[✓] xcodebuild build
[✓] swift test (216/216)
[✓] terminfo sentinel present in built app
[✓] MARKETING_VERSION = 1.0.0 (consistent across xcconfig + pbxproj)
[✗] SUFeedURL not set in built Info.plist (#0097)
[!] BattyKit/Package.swift on path:; not reproducible (#0098)
[✓] Developer ID cert present in keychain
...
[✓] working tree clean
```

`[✓]` pass, `[✗]` fail, `[!]` warning.

Exit 0 on all-pass + only warnings; exit 1 on any `[✗]`.

## Flags

- `--strict` — promote warnings to errors.
- `--allow-dirty` — don't fail on a dirty working tree.
- `--allow-no-sparkle` — skip the SUFeedURL check.
- `--skip-ssh-check` — don't actually SSH to the EC2 host.
- `--help` — usage.

## Acceptance criteria

- `scripts/preflight.sh` runs from a fresh shell and reports each gate.
- Exit code is 0 when all pass; 1 when any fail.
- Output is short and scannable (no command-spew unless `-v` is added later).
- The script doesn't mutate state — it only reads.
- The script handles missing tools gracefully (Sparkle's `generate_keys` may not be on PATH; that's a `[!]` not an `[✗]`).
- `scripts/RELEASE.md` is updated to recommend running `scripts/preflight.sh` as the first step.

## Out of scope

- Auto-fix mode (e.g. "I noticed Package.swift is on path:; want me to swap to URL+SHA?"). Tempting but adds risk.
- Notarization gate (would require submitting a binary to Apple; release.sh already does that).
- Smoke-test gate (clean Mac launch — requires another machine, can't be a CLI check).
- Continuous CI integration. The script is a developer convenience; CI is a separate axis.

## Notes

- Most of the gates are one-liners (`grep`, `plutil`, `security`, `git ls-remote`). Keep the script flat and shell-readable.
- The script doesn't need to be perfectly idempotent — it's read-only. Re-running on a half-built tree just reports the same warnings.
- This is a developer ergonomics tool, not a release barrier. Don't add gates that fail-by-default because the project lifecycle hasn't gotten there yet.
