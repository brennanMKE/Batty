## Description

#0478's VM UI tests found five places where a Projects surface does not appear in the accessibility tree the way the view code and `docs/ui-features.md` say it should. In three of them, a parent's identifier overrides its children's, or a child is merged into its parent, so neither VoiceOver nor automation can reach that child on its own. In the other two, state the user can see (a menu check mark, the trust sheet's command text) is not exposed where an accessibility client would look for it. #0478 worked around all five in its tests by matching either of two identifiers, matching by title, or sampling screenshot pixels. Those workarounds are recorded on branch `issue/0478` in `docs/ui-features.md`, section "Projects UI tests (#0478)" → "Identifiers the accessibility tree does not honor".

This is first an accessibility bug: a VoiceOver user cannot land on the picker's filter field as a separate control, or hear which Sidebar Session comes from a Project. The pixel checks are a secondary cost. They are fragile across appearance and Session color, and they stop working once #0482 changes the glyph.

## The five findings

Verified on `main` at `d0feadc1` (paths under `BattyKit/Sources/BattyKit/`):

1. **Open Project picker: the filter field and the hint line surface as `project-picker.root`.** The sheet's root `VStack` sets `.accessibilityIdentifier("project-picker.root")` (`Views/ProjectPickerView.swift:75`) with no `.accessibilityElement(...)`, and the identifier ends up on its un-buttoned descendants. These include the filter `TextField` (`:82-99`, which sets its own `project-picker.filter` at `:99`) and the footer hint `Text` (`project-picker.hint`, `:163`). The cards keep their own identifiers (`project-picker.card.<name>`, `:246-249`), and so does the empty state (`:155-156`). Both of those set `.accessibilityElement(children: .contain)` before their identifier, which points at the likely fix (unverified).
2. **Project Editor: every Pane card surfaces as `project-editor.preview`, and Pane 1's frame is the whole preview.** `PanePreview` (`Views/ProjectEditorView.swift:445-487`) sets `.accessibilityIdentifier("project-editor.preview")` at `:485`, again with no `.accessibilityElement(...)`. Each `PaneCard` (`:504-566`) is a `Button` with its own label `"Pane <n>: <kind>"` (`:561`) and identifier `project-editor.pane.<n>` (`:563`), and the preview's identifier replaces that identifier. #0478 also saw Pane 1's card report the preview's frame as its own, so its tests click every card near its top-left corner.
3. **Sidebar: the Project glyph is not an element, and nothing in the row says the Session is Project-backed.** `SessionRow`'s `Label` icon (`Views/SessionSidebarView.swift:257-269`) puts `.accessibilityIdentifier("session-row.project-glyph")` and `.accessibilityLabel("Project")` on the `folder.fill` image (`:264-265`). The row is a single accessibility element, `session-row.<title>` (`:98`), and its value comes from `rowAccessibilityValue(for:isSelected:)` (`:22-26`: `"selected"`/`"unselected"` plus `", N unseen"`). The icon is merged into that element, so both the glyph's identifier and its "Project" label are lost. A VoiceOver user hears a Project-backed Session exactly like a plain one. `rowAccessibilityValue` already exists to carry the unseen-bell badge, which the same merge hides, and it is the natural place for this state too.
4. **File ▸ Open Project: the check marks on open Projects are not readable.** Each Project item is a SwiftUI `Toggle` bound to "has an open Session" (`Commands/BattyCommands.swift:118-125`, from `ProjectFileMenuModel`). XCUITest sees neither `isSelected` nor a `value` on the item, so #0478 reads the check mark from pixels (`assertCheckMarks` in `BattyUITests/Support/ProjectsHarness.swift` on `issue/0478`). This may be how XCUITest maps the `NSMenuItem` state of a native menu, rather than something Batty sets wrong. Investigate before changing anything: check with Accessibility Inspector whether VoiceOver announces the item as checked.
5. **Startup-command trust sheet: text is in `value`, not `label`, and the root identifier can override its controls'.** In `Views/ProjectStartupTrustSheet.swift`, each command row is two bare `Text`s, the Pane/Tab label and `"$ <command>"` (`:17-23`). The root sets `.accessibilityIdentifier("project-startup-trust")` (`:49`) without `.accessibilityElement(...)`. The tests match command text through `label CONTAINS … OR value CONTAINS …` and match the buttons and toggle by title as well as by identifier (`BattyUITests/ProjectsStartupTests.swift:14-25` on `issue/0478`). A static text's string is in `AXValue` by macOS convention, and VoiceOver reads it. The real gaps are the root identifier overriding the controls' identifiers (`project-startup-trust.remember`, `.open-without-running`, `.run`, `:34-41`) and the fact that each command's Pane/Tab label and its command are read as two unrelated texts.

## Expected behavior

- VoiceOver can move to the picker's filter field and hint line as their own elements, each Project Editor Pane card as its own button ("Pane 2: Git Status, selected"), and the trust sheet's buttons and toggle. Each one carries the identifier `docs/ui-features.md` documents for it.
- A Project-backed Sidebar row tells an accessibility client that it is one. For example, `rowAccessibilityValue` gains a Project part (exact wording is the implementer's call, kept stable, documented in `docs/ui-features.md`, and unit-tested next to the existing unseen-bell value). Alternatively, the glyph becomes a separate child element that keeps `session-row.project-glyph`. Either way, `session-row.<title>` stays the row's identifier, and its existing `selected`/`unselected` and `N unseen` value parts keep their meaning. `SidebarTests` and `CLIBackgroundSessionTests.swift:162-177` depend on them.
- Each trust-sheet command reads as one unit (Pane/Tab plus command), for example a combined element.
- The File-menu check mark is either readable through accessibility, or the resolution documents (with Accessibility Inspector evidence) that it is AppKit/XCUITest behavior Batty cannot change. In that case the pixel check stays, its comment cites this issue, and the unit tests on `ProjectFileMenuModel` remain the primary coverage of check state.
- No visual change. All of this is accessibility modifiers only.

## Resolution notes

> 🟢 Resolved 2026-10-13. Projects controls are now addressable through Accessibility:
> - The picker filter field, the editor's Pane cards, and the trust sheet's buttons, toggle and command rows each keep their own identifiers.
> - A Project-backed Sidebar row's value carries ", Project, <Name> symbol".
> - The Symbol field is a single labelled stop.
>
> The UI tests read these by identifier instead of pixels, except for the File-menu check mark.

Owed to the user, using VoiceOver and Accessibility Inspector in Batty Beta:
- The picker's filter field and hint are separate elements.
- The Pane cards are buttons.
- The trust sheet's command rows read as one element each.
- A Project row reads "…, Project, Folder symbol".
- The Symbol field is one stop, with no unlabelled group.
- With Full Keyboard Access on, the Symbol field takes a single Tab stop.
- Whether VoiceOver announces the File ▸ Open Project check mark (finding 4).

## Root cause

- Three container roots set `.accessibilityIdentifier` on a view that wasn't an accessibility element, so SwiftUI pushed the identifier down onto the children and overwrote theirs: the picker sheet, the editor's `PanePreview`, and the trust sheet.
- The Sidebar row merges its icon into the row element, so the Project symbol wasn't exposed at all.
- The Symbol field's container could appear as an unlabelled group, and its inner Button took a second Tab stop.

## Fix

- **Containers:** `.accessibilityElement(children: .contain)` was added before the identifier on the picker root, `PanePreview` and the trust sheet root. This is the same pattern as the existing `pane-row` and `tab-chip`.
- **Trust sheet:** each command row is one combined element, `project-startup-trust.command.<n>` (one-based), labelled with its Pane/Tab and the command.
- **Sidebar row value:**
  - `SessionSidebarView.rowAccessibilityValue` gains a `, Project, <Name> symbol` part.
  - The part is supplied by the pure `rowProjectSymbol(flagOn:projectID:symbol:)`. It is added only with the flag on and a `projectID`.
  - Plain and flag-off values are byte-identical to before.
  - The test-only `, icon <sf-symbol>` part, gated by `BATTY_UI_TEST_SIDEBAR_ICONS`, is kept and still comes last.
- **Symbol field:** the container is `.contain` with the label "Symbol", and the inner Button is `.focusable(false)`.
- **UI-test helpers:** `pickerFilterField`, `paneCard`/`clickPaneCard`, `assertProjectGlyph` (which reads the Project part and keeps the `folder.fill` icon check), `listsCommand`, `sheetButton` and the remember toggle all use identifier queries. `assertCheckMarks` stays a pixel check (finding 4).
- **Docs:** `docs/ui-features.md` has a new accessibility-structure section. A comment above `SessionRow` that was no longer accurate has been corrected.
