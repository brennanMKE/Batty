# 0593 — `./build.sh unit` spends ~13 s in xcodebuild after the last test finishes, keeping the full unit run near 36 s

| | |
|---|---|
| **Status** | open |
| **Module** | Testing / Build |
| **Platform** | macOS |
| **First seen** | 2026-11-12 |

## Description

After the last test finishes, `./build.sh unit` waits another ~12.5–13.4 s in xcodebuild before it reports. `swift test` takes ~2 s for the same step. This tail is now the biggest cost outside test execution. Once #0592's test fixes land, execution takes ~18 s, but the full warm run still lands near 36 s. The target is well under 30 s.

Follow-up to #0592 (`issue/0592`, `## Plan` finding 5 and "Target"). #0587 moved `./build.sh unit` onto xcodebuild through the `BattyKit Unit Tests` scheme. #0588 is related.

## Measurements (from #0592's plan)

- In every full xcodebuild run, "Testing started completed" lands 12.5–13.4 s after the last test line. One run went from 02:52:03.7 to 02:52:16.3.
- `swift test` has a gap of ~2 s.
- A filtered run of 20 tests takes 3.6 s in total. The tail seems to grow with the number of results.
- xcodebuild used ~10 s more CPU than `swift test` for the same tests.
- `-quiet` saved only 2.4 s.
- For the same work, `swift test` takes ~19.9 s wall and `./build.sh unit` takes ~36 s.

## Ask

1. Find out where the tail goes. Candidates:
   - writing the xcresult bundle
   - streaming results per test
   - code coverage
   - test-plan or scheme settings
   - the cost of `-resultBundlePath`
   - `-parallel-testing-enabled`
   - `-collect-test-diagnostics`
2. If xcodebuild can't be made fast, reconsider `swift test` for unfiltered runs. #0587 rejected it because it writes no xcresult, filters would need translating, and it adds a second build directory. Any change must keep the current output contract of `./build.sh unit`: the `CHECK UNIT:` and `==> unit:` lines, the `tools/check-report.py` classification and exit codes, and filter arguments.

## Expected behavior

A warm, full `./build.sh unit` finishes well under 30 s.

## Actual behavior

It takes ~36 s. About 13 s of that comes after the last test result.
