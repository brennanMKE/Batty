## Description

The XPC port plan's transferable guidance lives in a sibling throwaway checkout, `/Users/brennan/Developer/brennanMKE/RemoteControl`, which could move or be deleted at any time — it was throwaway by design. Copy the experiment's reference docs into this repo at `docs/xpc/` so every later child of the #0265 umbrella can cite stable in-repo paths.

Files to copy (verified present at time of filing; line counts from `wc -l`):

- `docs/xpc-cli-architecture.md` (429 lines) — the broker pattern, endpoint handoff, protocol trio, four-string rule, `SMAppService` repair path
- `docs/cli-embedding-and-install.md` (543 lines) — CLI in a Swift package, embedding, signing, install action
- `docs/swift-concurrency-and-xpc.md` (268 lines) — the `@Sendable` trap in full, `nonisolated` helpers, moving non-`Sendable` connections across isolation
- `docs/build-and-release.md` (284 lines) — local install without notarization, the certificate-revocation hazard
- `docs/README.md` (89 lines) — the index; also carries "Decide this before you build anything" and the three process lessons
- `FINDINGS.md` (177 lines) — the decision evidence, effort data, and recommendation

Destination: `docs/xpc/` in this repo (e.g. `docs/xpc/xpc-cli-architecture.md`, …, `docs/xpc/FINDINGS.md`). Add a short entry for the new folder to Batty's own `docs/README.md` index.

The rationale (from #0265's "Vendoring recommendation"): the experiment's own hardest-won process lesson — "read the reference project's docs before implementing, not after"; it cost RemoteControl three divergences from Batty's already-solved CLI install — is precisely the failure mode a vendored copy inside this repo guards against.

## Resolution notes

> 🟢 Resolved 2026-07-24 — the six RemoteControl reference docs are vendored at `docs/xpc/`, byte-identical to source apart from a provenance header on each.

Later children of #0265 now cite stable in-repo paths; none of them depend on the sibling checkout still existing.

## Root cause

Not a defect — a durability gap. The XPC port plan's transferable guidance lived only in `/Users/brennan/Developer/brennanMKE/RemoteControl`, a checkout that was throwaway by design and could move or be deleted at any time, while #0269–#0274 were all written to depend on it.

## Fix

Copied all six documents verbatim into `docs/xpc/` (flat layout) and added an index entry to `docs/README.md`. Each vendored file carries a blockquote provenance header immediately after its H1 naming the source repo and path, the copy date, and — the load-bearing part — that bare `#NNNN` references in the body are **RemoteControl** issue numbers (that repo's `issues/0001`–`0031`), not Batty's, since both trackers use identical notation. `FINDINGS.md` names `#0249` as the single genuine Batty reference in the set.

Broken cross-links were annotated rather than rewritten, per the issue's binding "copy, don't rewrite" scope. Two links did not survive the flatten: `README.md`'s `../FINDINGS.md` (now dead) and its `../README.md`, which **silently resolves to Batty's own `docs/README.md`** instead of erroring. Both are called out by name in the provenance header.

## Review

Reviewed by `claude-opus-5`, two rounds.

Round 1 requested changes on one blocking finding: `FINDINGS.md`'s provenance header claimed "Batty" in the body was the experiment's stand-in name for another app. It is not — RemoteControl was a prototype built specifically to decide Batty's CLI transport, so the body's references to the 372-test build-graph gate, `#0249`, and the `BattyKit` target split are genuine. Left uncorrected, it would have told #0269–#0274's implementers to discount exactly the porting guidance the doc was vendored to deliver. The header also contradicted itself by separately flagging `#0249` as genuinely Batty's.

Round 2 approved. The reviewer independently re-diffed all six files against their live sources in both rounds rather than trusting the implementer's report, enumerated every `#NNNN` in the bodies to confirm the collision hazard is confined to `FINDINGS.md`, checked the round-2 header for over-correction (it claims only that body "Batty" strings are genuine, not that the doc is Batty-authoritative), and upheld annotate-don't-fix as the correct call on the silent misresolution.

## Gotchas

- **`#NNNN` means RemoteControl inside `docs/xpc/`.** Both trackers use identical notation and RemoteControl's numbering (`0001`–`0031`) overlaps Batty's real issues. Following "#0016" into Batty's `issues/0016.md` lands somewhere entirely unrelated. The provenance headers say so, but the hazard is worth knowing before reading.
- **`docs/xpc/README.md`'s `../README.md` link resolves to the wrong real document.** It points at Batty's own `docs/README.md` rather than 404-ing, because that file exists. Annotated, deliberately not rewritten.
- These are **snapshots, not living documents**. `FINDINGS.md` describes Batty's state as of 2026-07-24, before any of #0265's children landed — its "Batty currently does X" statements go stale as the track progresses. #0265 remains the current decision record.
- A reviewer nit left unfixed as not worth a round: `FINDINGS.md`'s header says RemoteControl "had no app of its own," which is loose — it built a prototype app, just not a product one. Drop the clause if that header is ever edited for another reason.

## Scope details

- **Copy, don't rewrite.** The docs were written explicitly for someone building a *different* app; they mark what must be renamed and what can be copied verbatim. Preserve them as-is.
- Add a brief provenance note at the top of each vendored file (or a single `docs/xpc/README` preamble) naming the source repo and copy date, so a future reader knows these are snapshots, not living documents.
- **Known dangling links, acceptable:** `FINDINGS.md` links to the experiment's `issues/` files and repo-root `README.md`, which are not vendored. Note this in the provenance preamble rather than editing the link targets.
- The internal cross-links between the four docs and their `README.md` are relative within the same folder, so copying the files into one flat `docs/xpc/` folder keeps them working. `FINDINGS.md`'s link `[docs/](docs/README.md)` will need the provenance note too (the vendored layout is flat, not nested).
