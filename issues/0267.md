## Description

The XPC port plan's transferable guidance lives in a sibling throwaway checkout, `/Users/brennan/Developer/brennanMKE/RemoteControl`, which could move or be deleted at any time — it was throwaway by design. Copy the experiment's reference docs into this repo at `docs/xpc/` so every later child of the #0265 umbrella can cite stable in-repo paths.

Files to copy (verified present at time of filing; line counts from `wc -l`):

- `docs/xpc-cli-architecture.md` (429 lines) — the broker pattern, endpoint handoff, protocol trio, four-string rule, `SMAppService` repair path
- `docs/cli-embedding-and-install.md` (543 lines) — CLI in a Swift package, embedding, signing, install action
- `docs/swift-concurrency-and-xpc.md` (268 lines) — the `@Sendable` trap in full, `nonisolated` helpers, moving non-`Sendable` connections across isolation

- `docs/README.md` (89 lines) — the index; also carries "Decide this before you build anything" and the three process lessons
- `FINDINGS.md` (177 lines) — the decision evidence, effort data, and recommendation

Destination: `docs/xpc/` in this repo (e.g. `docs/xpc/xpc-cli-architecture.md`, …, `docs/xpc/FINDINGS.md`). Add a short entry for the new folder to Batty's own `docs/README.md` index.

The rationale (from #0265's "Vendoring recommendation"): the experiment's own hardest-won process lesson — "read the reference project's docs before implementing, not after"; it cost RemoteControl three divergences from Batty's already-solved CLI install — is precisely the failure mode a vendored copy inside this repo guards against.

## Scope details

- **Copy, don't rewrite.** The docs were written explicitly for someone building a *different* app; they mark what must be renamed and what can be copied verbatim. Preserve them as-is.
- Add a brief provenance note at the top of each vendored file (or a single `docs/xpc/README` preamble) naming the source repo and copy date, so a future reader knows these are snapshots, not living documents.
- **Known dangling links, acceptable:** `FINDINGS.md` links to the experiment's `issues/` files and repo-root `README.md`, which are not vendored. Note this in the provenance preamble rather than editing the link targets.
- The internal cross-links between the four docs and their `README.md` are relative within the same folder, so copying the files into one flat `docs/xpc/` folder keeps them working. `FINDINGS.md`'s link `[docs/](docs/README.md)` will need the provenance note too (the vendored layout is flat, not nested).
