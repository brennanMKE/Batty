## Description

`AGENTS.md` "Release branches" requires Projects to stay behind a feature flag until 1.3.0: on in Batty Beta, off in Prod, and with it off the feature must be invisible and inert. No feature-flag code exists today (`grep -rn "FeatureFlag" BattyKit/Sources` finds nothing). This issue adds the flag, the test seam, and the vocabulary and PRD changes every later Projects child depends on. It ships no user-visible behavior.

## Expected behavior

**1. One flag type, one grep-able symbol, usable from the app, the CLI, and tests.**

- Add `FeatureFlags` to **`BattyXPCCore`**, the Foundation-only target that both `BattyKit` and the `batty` CLI link (`BattyKit/Package.swift:59-61`, `:81-87`). `BattyKit` has no route into the CLI, so the type cannot live there. It is a `Sendable, Equatable` value with one property, `projects: Bool`.
- **App and BattyKit, runtime resolution.** `FeatureFlags.resolved(bundleIdentifier: String? = Bundle.main.bundleIdentifier)` returns `projects == true` only when `ServiceNames.Variant(bundleIdentifier:)` (`BattyXPCCore/ServiceNames.swift:93-100`) is `.beta`. An unknown or nil identifier fails closed to off and logs an error, matching the three existing fail-closed callers (`SessionNameCache.resolvedDirectoryName`, `CLIInstaller`, `BrokerAgentController`). The flag never reads `UserDefaults` and has no "enable in Prod" switch, because the policy is off in Prod, not off by default.
- **CLI, compile-time resolution.** The `batty` binary has no `Info.plist`. It resolves its variant from `ServiceNames.current`, which the "Embed CLI" build phase sets via `-DBATTY_VARIANT_BETA` (`ServiceNames.swift:131-156`). Provide `FeatureFlags.current` (for bare Mach-Os only) derived from `ServiceNames.current`, documented like `current` is today.
- **Injected, not global.** `AppStateStore.init` (`Runtime/AppStateStore.swift:970-975`) gains `featureFlags: FeatureFlags = .resolved()` next to `preferences:`, stored `@ObservationIgnored public let featureFlags`. `AppStateStore.shared` (`:12`) keeps its zero-argument construction. Views, commands, the palette and XPC read `store.featureFlags.projects`. Unit tests pass an explicit value and never depend on the test host's bundle identifier.
- **Removal is mechanical.** Every gate site in every later child reads `featureFlags.projects` (or `FeatureFlags.current.projects` in the CLI). Add a short "Feature flags" section to `docs/source-layout.md`, or a new `docs/feature-flags.md` linked from `docs/README.md`. It states the policy, the two resolution paths, and a **gate-site list** that each later Projects child appends to. Removing the flag means deleting `FeatureFlags.projects`, fixing the compile errors, and checking the list.

**2. UI-test seam to force the flag off.** UI tests run against the Beta bundle (`Testing/UITestDriver.swift:14`), so the flag is always on there. #0478 needs to prove flag-off inertness at the UI level. Add a test-only override that can only *force the flag off*, never on. It is read only when the existing UI-test driver environment is present (`UITestDriver.scriptEnvVar`, `BATTY_UI_TEST_SCRIPT`, `:17`), or through an equivalent env var gated the same way. Prod must have no way to turn the flag on.

**3. Vocabulary: `Concepts.md` gains a `## Project` entry** under "# Containers", placed before `## Session` because a Project is what a Session is opened *from*. It must:

- define a Project as a saved, user-authored record: name, root folder, Session color, Layout (a `PaneLayout` preset or a captured topology), per-Pane kind, Terminal Tabs (optional title, working directory relative to the root, optional startup command), the Git Status repository folder, and the "run startup commands on open" toggle;
- say that **opening** a Project creates a new Session (title and color pinned), and that a Session opened from a Project is "Project-backed" for its lifetime. The association is in-memory only, shown by a folder glyph in the Sidebar, and the shell can `cd` anywhere;
- state the storage (`~/Library/Application Support/<Batty|Batty Beta>/projects.json`). Records are written only on explicit user action. Nothing is auto-saved, nothing is captured on quit or on a timer, and nothing is restored at launch. That is **why it is not a revival of #0172**, and the entry says so in the same way #0371 asked for its Workspace entry;
- say Pane sizes are not stored (equal splits per #0255);
- say that startup commands are typed into the Tab's shell, run only after a trust confirmation, and are re-confirmed when they change;
- note that Projects are Beta-only until 1.3.0 ships;
- update the "At a glance" block only if it stays accurate (a Project is not part of the Window→Session containment chain, so a one-line "Saved definitions: **Project**" line is enough), and bump the document version line at the bottom.

**4. `PRD.md`: put per-Project startup commands explicitly in scope.**

- §3 Non-goals currently lists "A scripting/config language à la tmux's `.tmux.conf`." Keep that line. Add a clarifying note: a Project's startup commands (literal lines typed into a Tab's shell when a Project opens, behind a trust prompt) are **in scope** as of 1.3.0 (user decision, 2026-10-12, #0469), and are not a scripting or config language.
- §10 "Session presets. Save named layouts (e.g. "frontend dev" = three panes with specific cwds) and launch them from a menu." is what Projects delivers. Mark it as delivered by Projects (1.3.0, #0469) rather than leaving it under "not committed".
- Bump the document version line at the bottom.

**5. `issues/Issues.md`'s module table already has a `Projects` row** (added when #0469 was filed). Nothing to do here beyond confirming it.

## Acceptance criteria

- `FeatureFlags` exists in `BattyXPCCore` with `resolved(bundleIdentifier:)` and `current`. Unit tests cover: the Beta identifier → on; the Prod identifier → off; nil → off; an unknown identifier → off.
- `AppStateStore` takes and stores an injected `FeatureFlags`. A unit test constructs it with each value and reads it back.
- The UI-test override can force the flag off and cannot force it on. A unit test proves that the override is ignored when the UI-test environment is absent, and that it cannot turn the flag on under a Prod identifier.
- The docs section with the gate-site list exists (empty list plus the instruction to append).
- `Concepts.md` and `PRD.md` are edited as above.
- No user-visible change in either variant.
- `./build.sh` and `./build.sh unit` pass, and the new tests appear in the run output.

## Notes

- The two resolution paths are deliberate and already documented in `projects-proposals.md` §1.7 (attached to #0469). There is no `SWIFT_ACTIVE_COMPILATION_CONDITIONS` for Beta in the app target, and an xcconfig condition would not reach the SPM package anyway, so `#if BETA` inside BattyKit is not an option.
- `BattyKitTests` builds via `swift test` without `-DBATTY_VARIANT_BETA`, so `FeatureFlags.current` is always off under unit tests. Code that branches on the CLI flag (#0477) must take the flag as a parameter so tests can exercise both branches. Do not test `current` itself beyond its Prod default.
- Follow `docs/isolate-userdefaults-in-tests.md`. The flag never touches `UserDefaults`, so this is mostly a reminder for the UI-test override, if it is implemented through launch arguments that land in the argument domain.
- No sleeps or polling in tests (`AGENTS.md` "Asynchronous tests"). Nothing here is asynchronous.

## Resolution notes

> 🟢 Resolved 2026-10-12 — `FeatureFlags.projects` exists, on only in Batty Beta, injected into `AppStateStore`; Concepts.md defines Project and PRD.md puts startup commands in scope.

## Root cause

No feature-flag mechanism existed, and the docs had no Project concept; the PRD's "no scripting/config language" non-goal excluded startup commands.

## Fix

- `FeatureFlags` (BattyXPCCore, shared by BattyKit and the CLI): `resolved(bundleIdentifier:environment:)` turns `projects` on only for the Beta bundle id and fails closed (with an error log) for nil/unknown ids; `current` serves bare Mach-Os from `ServiceNames.current`.
- UI-test override `BATTY_UI_TEST_FORCE_PROJECTS_OFF=1`, honored only alongside `BATTY_UI_TEST_SCRIPT`, can only turn the flag off. `UITestDriver.scriptEnvVar` now aliases `FeatureFlags.uiTestEnvironmentVar`.
- `AppStateStore.init(featureFlags: = .resolved())`, stored `@ObservationIgnored`.
- `docs/feature-flags.md` (policy, resolution paths, override, gate-site table), linked from `docs/README.md`; `Concepts.md` `## Project` (v0.5); `PRD.md` startup-command scope note and Session presets delivered by Projects (v0.4).
