## Audit: turn-bounded `awaitTerminalStatePublish`

`TerminalStatePublishing.swift:44-63` waits up to 20 main-queue turns (`DispatchQueue.main.async` hops) for `TerminalViewState`'s deferred publish. It has 74 call sites in 13 files. It's bounded by turns, not time, and it waits on a known `DispatchQueue.main.async` publish, so it's closer to allowed than the rows above. It's still a poll. Decide whether the publish can signal completion directly (e.g. await the one hop the publish is known to take, or a publish event from `TerminalViewState`). Then either migrate the helper, or keep it and **write the decision and its justification into `AGENTS.md` "Asynchronous tests (binding)"** so later audits don't reopen it. This audit uses no #0428 piece and can start now. Migrating 74 call sites, if the decision is to migrate, may warrant its own follow-up issue. Say so in the resolution rather than folding it in silently.

## Work notes (implementer, round 4 — review round 2 findings)

Review round 2 (Opus, `84e7fdea`) held round 1's approval on the four earlier files and found two problems specific to the new summarization seam:

1. **The bounded wait didn't belong in production.** `AppStateStore.awaitSummarizationForTesting` inlined an `NSLock`/`Task.sleep` race that duplicated the test target's own `ResumeOnce`. Removed it entirely. Production now exposes only a plain synchronous read accessor, `func summarizationTaskForTesting(entryID: UUID) -> Task<Void, Never>?` — no `async`, no bound, no lock, nothing but a dictionary lookup. This also removes the leaked `waiterTask` the reviewer flagged (a `Task` created to bridge `task.value` into the continuation race, cancelled only after the fact).
2. **One `false` was doing two jobs.** "Never scheduled" and "scheduled but timed out" both collapsed to `false`. Split them: skip tests (`summarizationSkippedWhenToggleOff`) now assert `store.summarizationTaskForTesting(entryID:) == nil` synchronously, no `await` at all — "skipped" really is a synchronous fact. Positive tests (`summarizationRunsWhenToggleOn`, `nilSummaryFromSummarizerLeavesEntryUnchanged`, `junkSummaryFromSummarizerIsDropped`, `summaryUpdatesCorrectEntry` — both entries, `bellTickSummarizationAlsoRuns`) now `try #require` the task first, then await it through a new test-target-only helper, `awaitSummarizationTask(_:bound:) -> SummarizationAwaitResult` (`.completed` / `.timedOut`, a distinct enum, not `Bool`), built on the shared `ResumeOnce` (`ResumeOnce.swift`) with the same `DispatchWorkItem`/`asyncAfter` timeout-race shape `ChildProcessReadiness.waitForReadableData` already uses.

**A second real bug found and fixed while building the moved helper:** the first draft of `awaitSummarizationTask` crashed the test process (`EXC_BREAKPOINT`/`SIGTRAP`, `dispatch_assert_queue_fail` inside `swift_task_checkIsolatedSwift`) the instant its timeout fired. Cause: `AppStateStoreSummarizationTests` is `@MainActor`, and a `DispatchWorkItem` closure formed inside a MainActor-isolated method infers MainActor isolation by default — but `asyncAfter` runs that closure on `DispatchQueue.global(qos: .utility)`, a thread with no MainActor affinity. The Swift 6 runtime's isolation check catches the mismatch and traps. `ChildProcessReadiness` never hits this because it's a top-level `nonisolated enum`, not nested in a `@MainActor` type. Fixed by marking `awaitSummarizationTask` `nonisolated` explicitly — reproduced with a temporary hanging-summarizer test before the fix (crashed, deterministically, 3/3 tries) and after (resolved `.timedOut` in ~0.1s, 1/1 try then re-confirmed); the temporary test was deleted, not kept.

**Mutations re-run against the new shape**, precise `Edit`s reverted the same way, never `git checkout --`:
1. Removed the toggle-off guard → `summarizationSkippedWhenToggleOff` failed (0.031s).
2. Dropped the `bellFeed.updateSummary` write → `summarizationRunsWhenToggleOn` failed (~0.1s).
3. Hanging summarizer (never returns) → `awaitSummarizationTask` reported `.timedOut` in ~0.1s, not a hang (this is the mutation that caught the isolation-crash bug above, before the `nonisolated` fix).

## Resolution notes

> 🟢 Resolved 2026-09-24 — the app-level unit tests no longer wait on sleeps, run-loop spins or `Task.yield` counts, with two documented exceptions: the Atlas first-frame wait (#0435) and the turn-bounded `awaitTerminalStatePublish`, an exception the user approved and recorded in AGENTS.md.

## Fix

- **Deferred terminate:** awaits a continuation from a `DispatchQueue.main.async` that is enqueued after `removeWindow`. The main queue is FIFO, so by the time it resumes, the deferred check has already run.
- **`PaneViewRenderTests.pump`:** the frame-callback continuation replaces the 20 ms run-loop poll.
- **`SidebarRestorationTests`:** synchronous delivery with `queue: nil`.
- **`BellNotificationSummaryTests`:** production now exposes only `summarizationTaskForTesting(entryID:) -> Task?`.
  - Tests await it through a test-target `awaitSummarizationTask`, built on `ResumeOnce` and a cancellable `DispatchWorkItem`, which returns `.completed` or `.timedOut`.
  - Skip tests check for `nil` synchronously; positive tests `#require` the task first.
  - Stale task entries are pruned by bell-feed membership.
- **Atlas:** flagged, not migrated. GhosttyTerminal has no public first-frame signal. Tracked in #0435.
- **`awaitTerminalStatePublish`:** kept. The decision and its justification are in AGENTS.md "Asynchronous tests (binding)".

## Gotchas

- **Timeout closures inside `@MainActor` suites crash.** A `DispatchWorkItem` timeout closure formed in a `@MainActor` test suite inherits MainActor isolation, and it traps (`dispatch_assert_queue_fail`) when `asyncAfter` runs it on a global queue. Mark such helpers `nonisolated`.
- **A timed-out wait leaves a parked task.** After a timeout, the inner task awaiting `task.value` stays parked until the production task finishes. This happens only in tests.
