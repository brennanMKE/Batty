## Description

Every quick way to set a Reminder sets it with no text. The **Remind Me** presets (In 5/15/30 Minutes, In 1 Hour, Tomorrow at …) fire at once from the Session menu, the Sidebar row's context menu and the Command Palette, with no prompt. The Reminder that later fires says only "Time to come back to <Session>". A note field does exist, but only behind **Custom…** / **Edit Reminder…**, where nothing points the user to it. User report, verbatim:

> "It does not let me set any text? What is the point of a reminder in 5 mins without any text?"

This was a deliberate choice in #0514. Open question 3 there recommended "the menu presets set the Reminder at once with no note, and Custom… opens the sheet for durations, Tomorrow time and notes" (`issues/0514.md:298`, `:312`). The report shows the choice is wrong for the common case: a short Reminder is mostly useful for *why* you want to come back.

## Root cause

Every quick entry point called `ReminderActions.set(_:on:store:)`, which set the Reminder with `note: nil` and no prompt (`Views/ReminderMenu.swift:28-32`); the note field existed only in `ReminderSheet`, behind Custom… and Edit Reminder…, and was never focused. The notification put the Session in the title ("Batty — Reminder: <Session>") and the note, or "Time to come back to <Session>", in the body, so a preset Reminder showed only the Session's name. This was the deliberate #0514 choice (open question 3), not a regression.

## Fix

Design B, the Quick Reminder bar, replaces the sheet and every textless preset.

- **Model** (`Model/SessionReminder.swift`): `ReminderSpec.at(Date)` (1 minute to 7 days ahead, resolved to `.instant`), `ReminderSpec.todayAt` and `isInstantInRange`, `SessionReminder.displayText` ("Come back to <Session>" when there is no note), and `ReminderFormat.relativeLine`, `dueLine`, `notificationBody` and `lateAfter` (moved from `BellFeedView`). The Reminder value types are now `nonisolated` so the nonisolated notification builders can use them.
- **Bar**: pure `ReminderBarModel` (rows, highlight, ⌘-digit map, Keep/Remove in edit mode, picker validity, 500-character clamp in the `text` setter, the "437 / 500" count past 400) and `ReminderBarView`, a `.sheet` on the Window through `WindowRuntime.reminderBarSessionID` (renamed from `reminderSheetSessionID`). Time rows are `Button`s with `.keyboardShortcut(⌘1…⌘6)`. `ReminderSheet.swift` is deleted.
- **Store** (`AppStateStore+Reminders.swift`): `commitReminderBar` (`.set` / `.keep` / `.remove`), `updateReminderNote` (same id, creation time and due instant; the system request is replaced under the same identifier), `remindAgain`, and an action switch at the top of `handleNotificationTap`. `commitReminderSheet` and `editReminder` are gone. A Pick Date & Time… instant on the next calendar day becomes the remembered Tomorrow time (premise 6). `remindSessionForXPC` handles `.today(time)`.
- **Entry points**: `ShortcutAction.remindMe` (⇧⌘R, appended), wired in `BattyShortcuts.run` and the palette's `dispatch`. `ReminderMenuItems` replaces the `ReminderMenu` submenu in the Session menu and the Sidebar context menu: Remind Me…, or Edit Reminder… and Cancel Reminder. The palette keeps only `action:remindMe` (it closes the palette and opens the bar's own sheet through the palette's after-dismiss hook; see the focus deviation below) and `extra:remind:cancel`.
- **Sidebar**: `ReminderLines` (text line and a `TimelineView(.everyMinute)` caption, a tap gesture that opens edit mode, tooltip "Reminder <phrase> — <text>") mounts only on pending or due rows. The outline answers `heightOfRowByItem` from a per-apply snapshot and calls `noteHeightOfRows` for rows whose state flipped; the medium height is measured from `outline.rowHeight` after `rowSizeStyle = .medium` (32 pt on this host).
- **Notifications**: `ReminderNotification` (two categories, three action ids, `content(...)`), registered in `BellNotifier.init`. The in-app post (`BellNotifier.reminderContent`, a pure builder) carries the in-app category plus the Session id and note in userInfo; the scheduled request carries the open-only category. `NotificationTapPayload` gains `sessionID`, `note` and `action`; the delegate skips `NSApp.activate` for Remind Again.
- **CLI**: positional text (`--note` kept; both is an error; text with `--cancel` is an error), `--at` alone means later today (`SessionRemindAction.today`, appended, so existing JSON encodings are unchanged), capabilities updated.
- **Docs**: `Concepts.md` 0.32, Help `05-shortcuts.md` and a new Reminders section in `06-notifications.md`, `docs/shortcuts.md`, `docs/ui-features.md`, `docs/notifications.md`, the CLI docs and the batty-cli skill.

Deviations from the plan:

- **Focus: both forms shipped.** `ReminderBarSheetHost` declares `.defaultFocus($focus, .text)` as planned, and `ReminderBarView` also has the palette's `.onAppear { focus.wrappedValue = .text }` precedent (a write of view-local `@FocusState`, no AppKit call, no Task hop). The palette's Remind Me… row no longer swaps the palette into the bar (VM round 2): it closes the palette and opens the bar's own sheet, because in place the bar's field never took focus (see Review notes); it also covers `.defaultFocus` not taking in a sheet, which I could not check without the VM. The VM's `testShiftCommandROpensTheBarReadyToType` and `testPaletteRemindMeSwapsIntoTheBar` decide whether either can go.
- **Picker Return and Escape.** Besides the `onKeyPress` handlers on the `DatePicker`, the picker row has Set (`.defaultAction`) and Back (`.cancelAction`) buttons, because I could not confirm that `onKeyPress` sees Return from an `NSDatePicker`'s field editor.
- **⌘-digits while picking.** The picker replaces the rows that carry ⌘1–⌘6, so zero-size, accessibility-hidden buttons keep those chords in the sheet in picking mode (premise 3). Without them ⌘1–⌘5 there would reach the Session menu's "Session N" items.
- **The Remind Me menus no longer show the pending Reminder's detail row.** The plan's `ReminderMenuItems` lists only the two items; the detail stays on the badge tooltip, the Sidebar lines and the row's accessibility value.
- **Extra tests** beyond the plan's list: `thePaletteRemindMeRowOpensTheBarSheetForTheSelectedSession` (replaces the plan's `thePaletteRemindMeRowKeepsThePaletteOpen`), `removingFromTheBarCancelsTheReminder`, `onTimeDeliveryBodySaysSetAt`, `thePickedDateDefaultsToAnHourAheadRoundedUpToFiveMinutes`, `todayAtResolvesInTheCalendarsZone`.

## Design

### The bar

- 560 pt wide, with the same chrome, material and selection colours as the Command Palette, reusing its component pattern. (The spec said "centred in the upper third of the Window". The palette is really a SwiftUI `.sheet`, so the bar uses the same sheet presentation. See Plan, premise 2.)
- **Top row:** alarm glyph, a single-line text field with the placeholder "Remind me to…", and a trailing secondary label with the Session title.
- **Time list** (each row: label, resolved clock time, ⌘-digit hint): In 5 Minutes ⌘1 · In 15 Minutes ⌘2 (default highlight) · In 30 Minutes ⌘3 · In 1 Hour ⌘4 · Tomorrow (at the remembered Tomorrow time from #0568, 9:00 AM until one is chosen) ⌘5 · Pick Date & Time… ⌘6.
- **Footer hints:** "↩ Remind Me   ↑↓ Time   esc Cancel".
- **Keyboard:** focus never leaves the text field. ↑/↓ move the highlight. ⌘1–⌘5 commit their row at once with the current text, and ⌘6 opens the picker. Return commits the text with the highlighted time. Escape closes. Clicking a row commits it.
- **Pick Date & Time…** replaces the list with one row: a date-and-time field plus "Reminds you Thu, Nov 19 at 2:00 PM". Return commits and Escape returns to the list. An invalid time (in the past, or more than 7 days ahead) turns the summary red with "Choose a time between 1 minute and 7 days from now.", and Return does nothing.
- **Edit mode** (any entry point, on a Session with a pending Reminder): the text is prefilled. The first row, "Keep 3:45 PM", is highlighted; choosing it commits a text-only change without moving the due instant. The last row is "Remove Reminder" in the destructive colour.
- The text is capped at 500 characters (the existing cap). A count shows only past 400 ("437 / 500").

### Entry points

- ⇧⌘R.
- Session ▸ **Remind Me…**, one item replacing the submenu. While a Reminder is pending it becomes **Edit Reminder…** plus **Cancel Reminder**.
- The Sidebar context menu, with the same items.
- The Command Palette: **Remind Me…**, which swaps the palette into the bar in place, and **Cancel Reminder** while one is pending. Eight rows become two.
- Clicking the Sidebar row's Reminder lines opens the bar in edit mode.
- No toolbar button.

### Common fixes (in scope)

- **Delivered notification:** title = the text, subtitle = the Session title, body "Set at <time>" or "Due at <time>". It has three actions: Open Session (foreground), Remind Again in 15 Minutes and Remind Again in 1 Hour. There are two categories. The in-app post carries all three actions; the request scheduled with macOS (which arrives after a quit) carries only Open Session. Remind Again creates a new pending Reminder with the same text.
- **Sidebar row while pending:** a second line with the text (secondary, 1 line, truncated) and a third caption line with the relative time ("in 18 min"; beyond 60 minutes, "at 9:00 AM tomorrow"). Both are drawn with self-updating `Text`/`TimelineView`, so no timer writes observed state.
- **Sidebar row when due:** `alarm.fill` in the accent colour, the text in primary, and "due 2 min ago". The tooltip is "Reminder at 3:45 PM — <full text>". Semantic colours only (vibrant Sidebar material, light and dark).
- **Never silently replace:** every entry point on a pending Reminder opens edit mode, and a text-only edit keeps the original due instant.
- Remove the old `ReminderSheet` and the `ReminderMenu` preset items.

### State ownership and observation rules (binding for the implementer)

- **Which Session's bar is open:** `WindowRuntime.reminderBarSessionID: UUID?`, renamed from `reminderSheetSessionID` (`Runtime/WindowRuntime.swift:142`, cleared in `removeSession` at `:427`). Its only writers are:
  - `ReminderActions.openBar(for:in:)`, called from event handlers only (menu item action, `BattyShortcuts.run`, palette dispatch, Sidebar button);
  - the sheet binding's setter in `SessionDetailView` (kept as at `:326-331`, with its `!=` guard);
  - the bar's `onClose`.
  No `body`, `init`, `onChange` or representable update writes it.
- **What is typed and highlighted:** a pure value `ReminderBarModel`, held as `@State private var model` by `ReminderBarView`. It is seeded once through `State(initialValue:)` in the view's `init`, the same pattern as `ReminderSheet.init` (`ReminderSheet.swift:78-85`): a read of the store, not a write. The view mutates it only from key and click handlers. The 500-character cap goes into the model's `text` setter (a pure clamp), not into an `onChange` that writes back.
- **Store writes** happen only when a commit runs, from the handler of the Return press, ⌘-digit or click: `ReminderActions.commit(_:session:store:)`.
- **Focus:** no `makeFirstResponder` anywhere in this change.
  - **Bar in its own sheet** (⇧⌘R, menus, Sidebar): the host wrapper `ReminderBarSheetHost` owns `@FocusState var focus: ReminderBarField?` and declares `.defaultFocus($focus, .text)`. That is declarative and needs no write.
  - **Palette swapping into the bar in place:** the palette's own event handler for the "Remind Me…" row writes both its `@State reminderBarTarget` and its `@FocusState barFocus = .text`, in the same handler. Focus is set by the event that opens the bar.
  - `ReminderBarView` takes `focus: FocusState<ReminderBarField?>.Binding` from its host.
  - **Fallback** if `.defaultFocus` does not take in a sheet on macOS 15.6 (checked by `testShiftCommandROpensTheBarReadyToType` in the VM): the palette's existing precedent, `.onAppear { focus = .text }` (`CommandPaletteView.swift:331`). That writes view-local `@FocusState`, not `@Observable` model state, and makes no AppKit call. Never use a `Task` hop or `DispatchQueue.main.async`. The implementer records in `## Fix` which form shipped.
  - **The suggestion is "selected"** because an `NSTextField` selects all its text when it becomes first responder through the key-view or focus machinery. Nothing programmatic is needed. `testSuggestionIsSelectedSoTypingReplacesIt` checks it.
- **Relative time on the Sidebar:** `TimelineView(.everyMinute)` renders the pure `ReminderFormat.relativeLine(due:now:)` / `dueLine(dueAt:now:)` from `context.date`. Nothing writes state per tick. The accessibility value keeps `ReminderActions.detail` (scheduler clock), so the UI tests still read the frozen manual clock.

## Current behavior (verified against `ad1ff1da`)

**The note already exists everywhere downstream. Only the entry points skip it.**

- **The model carries an optional note.** `SessionReminder.note: String?`, trimmed, `nil` when empty, capped at `maxNoteLength = 500` (`BattyKit/Sources/BattyKit/Model/SessionReminder.swift:18-38`). `ReminderSpec.makeReminder(now:calendar:note:)` threads it through (`SessionReminder.swift:97-118`).
- **Presets pass `note: nil`, with no prompt.** `ReminderActions.set(_:on:store:)` calls `store.setReminder(spec, note: nil, forSessionID:)`. Its doc comment says "A preset sets the Reminder at once, with no note. It replaces any Reminder the Session already had, note included" (`Views/ReminderMenu.swift:28-32`). So a preset chosen while a Reminder with a note is pending also **throws that note away**.
- **Every menu preset goes through that path.** `ReminderMenu` builds the four `presetMinutes` items and the Tomorrow item, each calling `ReminderActions.set` (`ReminderMenu.swift:69-78`). Only **Custom…** and **Edit Reminder…** call `presentSheet` (`ReminderMenu.swift:79-82`, `89-92`). The same `ReminderMenu` is the **Session ▸ Remind Me** submenu (`Commands/BattyCommands.swift:236-239`) and the Sidebar row's context-menu **Remind Me** submenu (`Views/SessionSidebarView.swift:539-540`).
- **The Command Palette does the same.** `extra:remind:5|15|30|60` and `extra:remind:tomorrow` call `ReminderActions.set` directly (`Views/CommandPaletteView.swift:202-217`). Only `extra:remind:sheet` ("Remind Me About This Session…") and `extra:remind:edit` open the sheet (`CommandPaletteView.swift:196-201`, `219-224`).
- **The sheet has a note field, but it isn't focused and isn't first.** `ReminderSheet` shows the preset row, Custom row and Tomorrow row, then "Note (optional)" with a vertical `TextField` (`Views/ReminderSheet.swift:94-112`). `@FocusState noteFocused` is declared and bound (`ReminderSheet.swift:74`, `105`), but nothing ever sets it to `true`, so the sheet opens without focus in the note. A new draft defaults to `.preset(15)` (`ReminderSheet.swift:16`), and the sheet has no way to open with a given preset chosen. Set is the `.defaultAction` button (`ReminderSheet.swift:131-134`). Whether Return in the `axis: .vertical` note field commits the sheet or inserts a newline has not been checked.
- **The notification body already shows the note.** `BellNotifier.reminderText(note:sessionTitle:)` returns the title "Batty — Reminder: <Session>" and, as the body, the note, or "Time to come back to <Session>" when there is none (`Runtime/BellNotifier.swift:233-238`). Both the in-app post (`BellNotifier.swift:173-178`) and the macOS-scheduled request (`Runtime/ScheduledReminderNotification.swift:35`, #0566) use it. So with no note, a user sees only the Session title, twice.
- **The note already persists with the macOS-scheduled notification.** `ScheduledReminderNotification.make` bakes the note into the request's `body` (`ScheduledReminderNotification.swift:29-58`). The pending `UNNotificationRequest` therefore still shows it after Batty quits or relaunches (#0566). The in-app `SessionReminder` itself does not survive a relaunch, because Sessions don't.
- **The Bell Feed and Sidebar already show the note.** The fired `.reminder` entry's `message` is the note (`Runtime/AppStateStore+Reminders.swift:273`), and the feed row falls back to "Time to come back to <path>" (`Views/BellFeedView.swift:223`). The Sidebar's pending-clock badge tooltip and the Remind Me menu's status row use `ReminderActions.detail`, which appends " — <note>" (`ReminderMenu.swift:44-51`, `SessionSidebarView.swift:441`). The due alarm's tooltip is the entry's message (`SessionSidebarView.swift:459-460`). The note shows only in tooltips and menus, never as text on the row.
- **The CLI already takes a note.** `batty session remind` has `--note <text>` ("Note shown when the Reminder fires (trimmed, up to 500 characters)"), rejected with `--cancel` (`BattyKit/Sources/batty/SessionRemindCommand.swift:47-48`, `58`). It is listed in capabilities (`SessionRemindCommand.swift:149`, `155`) and sent as `SessionRemindRequest.note` (`BattyXPCCore/SessionRemindPayload.swift:51-56`), which `remindSessionForXPC` passes to `setReminder` (`AppStateStore+Reminders.swift:235`).

## Expected behavior

1. Choosing a Remind Me preset (In 5/15/30 Minutes, In 1 Hour, Tomorrow at …) from the Session menu, the Sidebar context menu or the Command Palette **gives the user a place to type why** before the Reminder is set. It no longer fires silently.
2. Typing a note and pressing Return sets the Reminder with that note. Escape sets nothing.
3. When the Reminder fires, the macOS notification and the Bell Feed row show the note.
4. A pending Reminder's note is visible from the Session's Sidebar Reminder indicator.
5. Choosing a preset never silently throws away a note on a pending Reminder.

## Proposed direction (choices recorded for the planner, not a full design)

- **A Reminder has an optional note.** It already does (`SessionReminder.note`); keep the model as is.
- **The Reminder sheet has a note field.** It already does; keep it.
- **A preset opens the sheet instead of firing.** Choosing a preset from the menu or palette opens `ReminderSheet` with that time already chosen (a preset, or Tomorrow at the remembered time, #0568) and **the note field focused**, so the user can type at once and press Return to confirm. That needs a way to open the sheet seeded with a choice (today `WindowRuntime.reminderSheetSessionID` carries only the Session id), focus set when the sheet appears, and Return in the note field to commit, not insert a newline. Focus must follow `docs/swiftui-observation-rules.md`: set the `@FocusState` from the sheet's own appearance, not by writing observed state from `body`. When the Session already has a Reminder, the sheet should keep its note.
- **The notification body shows the note.** It already does (`BellNotifier.reminderText`); add tests if the preset path changes how the note gets there.
- **The Sidebar/Reminder indicator shows the note.** Today only the badge tooltip shows it. The planner decides whether that's enough or whether the row should show the note.
- **`batty session remind --note`** already exists (`SessionRemindCommand.swift:47`) in the CLI's `--long` option style. No CLI change is needed unless the planner finds a gap.
- **The note persists with the macOS-scheduled notification**, so it survives a relaunch (#0566). That already holds, because the note is baked into the request body. Keep it true for the new preset path, and cover it with a test.

## Open question for the user

- **Should presets keep a one-click path with no note?** For example, the sheet's Set/Return with an empty note still sets the Reminder (one extra keystroke), or an Option-click / modifier on the menu item keeps today's instant behaviour. The proposed direction above drops the instant path. Confirm that before the plan is written.
