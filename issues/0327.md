# 0327 — PRD.md says the Split divider ratio "is persisted" while Concepts.md says ratios are in-memory only

## Description

Two canonical documents directly contradict each other on Split ratio persistence, one line away from #0325's own subject. Surfaced by #0325's review; all claims re-verified against source on 2026-08-08.

- `PRD.md:161` (the #0325 review cited line 162; the persistence claim is actually on 161 — the mouse-resize bullet, directly above the keyboard-resize bullet at 162): "**Mouse resize:** drag the split divider to resize. Live preview while dragging; **the ratio is persisted**."
- `Concepts.md:128` (corrected by #0324): "**Resized by:** dragging the divider, or Cmd-Ctrl-arrows. Updates to `ratio` are **in-memory only; they do not survive a relaunch**."

Concepts.md is the one that matches the code. Verified there is no persistence mechanism: #0172 removed workspace persistence entirely; grepping the app and BattyKit sources finds no `WorkspaceManager`, no `workspace.json` reference, and no encode of `SplitTree`/`SplitNode`/session layout anywhere (the only JSON encoding in the tree is shortcuts, bell feed, session-name cache, theme, and XPC message payloads). `Concepts.md:53` states it flatly: "**Persisted:** nothing — the ordered Session list, each Session's Split tree, and everything inside are in-memory only." The one loose end in source is a stale doc comment in `BattyKit/Sources/BattyKit/Model/LayoutModel.swift:11` ("Mirrors `PaneRuntime` fields that must survive workspace persistence") — descriptive rot, not a mechanism.

## Expected behavior

`PRD.md` and `Concepts.md` agree on whether the Split ratio survives a relaunch.

## Actual behavior

`PRD.md:161` asserts the ratio is persisted; `Concepts.md:128` (and the code) say nothing persists it.

## Notes

`PRD.md` is a *requirements* document, so there are two defensible readings — this issue deliberately does not pick one; that call is the user's:

1. **PRD is stale**, the same way `Concepts.md` was before #0324: workspace persistence was deliberately removed by #0172 and the PRD sentence should be corrected to match reality (drop "the ratio is persisted" or say in-memory only).
2. **PRD states an intended-but-unbuilt requirement.** #0172 removed the implementation, but if ratio persistence is still wanted for some future milestone, the honest fix is marking the sentence as planned/not-yet-implemented rather than deleting it. Precedent: #0325 itself began as "docs describe an unimplemented feature" and resolved in favour of *the docs were right, the code was missing* — the requirement was built, not deleted.

Note for reading 2: #0172's title is "Remove workspace persistence: source, docs, **and spec**" — the removal was framed as a spec change too, which leans toward reading 1, but PRD.md:161 evidently survived that sweep, so intent should be confirmed rather than inferred.
