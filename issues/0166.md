## Description

The Settings window ([[0034]]) gates user preferences for font, cursor, default shell, notifications, multi-line paste confirmation, and customizable hotkeys ([[0070]]). Several preferences either claim behavior they don't have ([[0068]]) or default to a state the user has explicitly complained about ([[0105]] paste confirmation on by default). The Settings flow is not currently tested.

## Regressions this suite would have caught

- [[0034]] — Initial Settings wiring. Baseline tests for the window opening and each pane being visible.
- [[0068]] — Settings claimed per-session mute exists in sidebar context menu, but it didn't. A test asserting the documented setting maps to a real toggle would have caught the doc/implementation drift.
- [[0070]] — Customizable hotkeys. Tests that a rebind persists and takes effect.
- [[0105]] — Multi-line paste confirmation default. A test asserting the default toggle state would have caught the default flip.

## Test cases

All tests use [[0158]] driver intents.

### Settings window — would catch [[0034]] regressions

- **Cmd-, opens Settings.** Type `Cmd-,`. Assert `settings.window` exists.
- **Each pane is reachable.** Click each toolbar item in the Settings window (`settings.tab.general`, `settings.tab.shortcuts`, etc.). Assert the matching content view (`settings.content.<name>`) becomes visible.

### Toggles persist — would catch [[0105]] and similar

- **Toggle paste confirmation off, restart, assert it stays off.** Driver: open Settings, flip the toggle, terminate, relaunch. Assert the toggle state on relaunch.
- **Default values match the user-expected defaults.** For each toggle in the Settings UI, write a test asserting the default on a fresh launch (no prior `UserDefaults`). [[0105]] is exactly this kind of catch: "default should be off, not on."

### Hotkey customization — would catch [[0070]] regressions

- **Rebind a shortcut and verify it fires the new binding.** Driver: in Settings → Shortcuts, rebind `Cmd-T` to `Cmd-Shift-T` (intent: `rebindShortcut(action:, to:)`). Close Settings. Type `Cmd-T` — assert no new tab. Type `Cmd-Shift-T` — assert new tab.
- **Reset a rebinding returns the default.** Same flow, then reset, assert `Cmd-T` works again.

### Defaults documentation match — would catch [[0068]]

- **Every Settings → Shortcuts row maps to an actually-implemented action.** Iterate Settings rows; assert the action's accessibility identifier is reachable via the documented shortcut. Document/implementation parity check.
- **Every Settings → Behavior toggle maps to a real preference.** Same shape, less mechanizable; consider a curated list per Settings pane.

## Accessibility identifiers needed

- `settings.window` on the Settings window root.
- `settings.tab.<name>` on each toolbar item.
- `settings.content.<name>` on each content pane.
- `settings.toggle.<key>` on each `Toggle`. `accessibilityValue` is "on" / "off".
- `settings.shortcut-row.<action>` on each row in the Shortcuts pane.
- `settings.shortcut-recorder.<action>` on the recorder field.

## Driver intents needed (from [[0158]])

- `openSettings` / `closeSettings`.
- `setPreference(key:, value:)` — for tests that don't need to exercise the UI, just the underlying state.
- `rebindShortcut(action:, to:)` — for the hotkey tests.
- `resetShortcut(action:)`.

## Out of scope

- The shortcut recorder's gesture handling (third-party-ish surface; manual review).
- Font picker integration with the system font panel (cross-process; not testable from XCUITest).
- Validation of shortcut conflicts (separate issue if pursued).

## Acceptance criteria

- All test cases pass under `xcodebuild -scheme 'Batty (Beta)' -destination 'platform=macOS' test`.
- Default-value tests run with a clean `UserDefaults` (`BATTY_UI_TEST_TEMP_HOME` should redirect or the harness should reset).
- The doc/implementation parity test fails loudly when a Settings row references an unknown action — this is the catch for [[0068]]-shaped drift.

## Notes

- Depends on [[0158]].
- The hotkey test pair is the highest-value subset: it exercises the rebind → persist → fire-the-new-binding loop, which is exactly the surface that [[0070]] introduced and hasn't been re-verified end-to-end.
