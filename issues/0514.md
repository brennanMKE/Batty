# 0514 — Session reminders: set a Session aside and get pulled back to it later

| | |
|---|---|
| **Status** | open |
| **Module** | Session / BellFeed / Sidebar |
| **Platform** | macOS |
| **First seen** | 2026-10-14 |

## Description

Batty can't remind you to come back to a Session. You can set a Session aside, but nothing brings you back to it later. This feature adds a **Reminder**: a per-Session timer you set from the Session menu, the Sidebar row's context menu or the Command Palette. You can pick a preset (5, 15, 30 or 60 minutes), a custom number of hours and minutes, or Tomorrow at a set time, and you can attach a note. When the timer fires, Batty posts a special Bell Feed entry, styled differently from a terminal bell and carrying the note, along with a macOS notification. Clicking either one brings that Session forward in its Window.

A pending Reminder shows as a small clock badge on the Session's Sidebar row. You can view, edit or cancel it. A Session has at most one Reminder.

## User request (2026-10-14), verbatim

> Add a new feature. I want to add a sort of alert to bring me back to a session after a period of time. The presets can be 5, 15, 30 and 60 but also allow me to add minutes and hours plus a tomorrow option. I may want to set a session aside and come back to it later. This can show up with the Bell Feed as a special notification. We could optionally include text with it.

## Verified facts (main `1a9006e1`)

- **Sessions do not survive a relaunch.** `Concepts.md`, Session → Persisted: "nothing — the ordered Session list, each Session's Split tree, and everything inside are in-memory only." Window restoration is disabled (#0444), and every launch opens one Window with a fresh Session 1. Workspace persistence was removed in #0172.
- **The Bell Feed is app-wide.** `AppStateStore.bellFeed: BellFeedStore` (`BattyKit/Sources/BattyKit/Runtime/BellFeedStore.swift`) holds at most 200 entries, newest first, in memory only.
- **`BellFeedEntry` has no kind field.** Each entry is tied to a `windowID/sessionID/paneID/tabID/surfaceID`. A non-terminal entry already exists: the memory-footprint warning (#0290, `AppStateStore.recordFootprintWarning`), which sets every id to the sentinel `BellFeedEntry.systemID`. `BellFeedView.pathLabel` and `jumpToBellEntry` special-case that sentinel. `batty notify` (#0284) entries also have no kind and differ from bell entries only in their message text.
- **Click-to-jump runs in two steps.** `AppStateStore.jumpToBellEntry(_:)` finds the owning Window by `entry.windowID`, then calls `makeKeyAndOrderFront`. `WindowRuntime.jumpToBellEntry(_:)` then sets `selectedSessionID`, `focusedPaneID` and `activeTabID`, and it no-ops unless the entry's pane *and* tab still exist.
- **System notifications go through `BellNotifier`** (`Runtime/BellNotifier.swift`). It honors Settings → Notifications "Show system notifications" (`SettingsPreference.resolvedSystemNotifications()`) and "Play sound" (`resolvedBellSound()`). For terminal bells it also suppresses the banner when Batty is active and the entry is already seen (`evaluateShouldPost`). A tap reads `userInfo[BellNotifier.entryIdUserInfoKey]` and routes the entry id through `onTapEntry`. `postFootprintWarning(title:body:identifier:)` is the precedent for a notification that is not a bell.
- **Per-Session mute** (`SessionRuntime.notificationsMuted`, #0068) gates only the banner, in `AppStateStore.postNotification`.
- **Closing a Session purges its feed entries.** `AppStateStore.removeSession(id:)` calls `cleanUpBellState(forTabIDs:)` for every Tab in the Session (#0071).
- **Feed entries can collapse and get summaries.** `BellFeedStore.recordOrCollapse` merges repeats (#0298), and `scheduleSummarization` runs a Foundation Models summary on recorded entries.
- **Multi-window exists in code.** Children #0235–#0239 of #0234 are resolved: `WindowRuntime` exists and Shift-Cmd-N opens a new Window. `Concepts.md`'s Window entry still says "planned". `WindowRuntime.moveSessions(fromOffsets:toOffset:)` only reorders Sessions within a Window, and no path moves a Session to another Window.
- **Entry points exist for each place this feature needs one:**
  - The Session menu: `CommandMenu("Session")` in `Commands/BattyCommands.swift`.
  - The Sidebar row context menu in `Views/SessionSidebarView.swift`, which has Rename, Set Color…, Set Session Theme…, Mute Notifications, the Save as Project items and Close. Rename, Set Color and Theme each present a `.sheet(item:)`.
  - The Command Palette, which builds its entries in `Views/CommandPaletteView.swift`. Entries like "Duplicate Session" and "Mark All Bells Seen" are not `ShortcutAction` cases.
- **Every `ShortcutAction` needs a default chord.** `ShortcutAction.defaultBinding` is non-optional, so adding a `ShortcutAction` case means picking a default chord.
- **The injected clock seam already exists.** `SchedulingClock` (`Runtime/SchedulingClock.swift`) provides `now: Date` and `sleep(for: Duration)`. `SystemClock` is the production clock and `TestClock` (`BattyKitTests/TestClock.swift`) the test one, with `advance(by:)` and `waitForSleepers(_:)`. See `docs/async-test-seams.md` §1.
- **UI tests drive the app through env-var hooks.** `UITestDriver` (`BattyKit/Sources/BattyKit/Testing/UITestDriver.swift`) runs a JSON intent script from `BATTY_UI_TEST_SCRIPT` at launch. Other test-only overrides are honored only when that variable is present (`BATTY_UI_TEST_PROJECTS_FILE`, `BATTY_UI_TEST_SIDEBAR_ICONS`).
- **Release state.** 1.3.0 is tagged and `release/1.3` exists. 1.3.x patches are built from `release/1.3`, so nothing on `main` ships until 1.4.0. `docs/feature-flags.md` notes there are no flags today and gives the recipe for adding one. The `projects` flag was retired in #0504.

## Vocabulary

**Reminder**, formally a *Session Reminder*: a one-shot, user-set timer attached to one Session. When it fires, it brings that Session back to the user's attention. Use "Reminder" in UI copy and code (`SessionReminder`, `ReminderScheduler`), and "Session Reminder" in prose where "Reminder" alone would be ambiguous. Avoid "alarm", "snooze" and "come back later" as nouns. "Remind Me" is the verb in menu labels.

The implementation, not this filing, adds the term to `Concepts.md`:
- a new **Reminder** entry under "Events & feedback";
- a note in the Session entry that it can carry one Reminder;
- a note in the Bell Feed entry that the Feed holds two entry kinds, bell and Reminder;
- a note in the Sidebar entry that a row can show a Reminder badge.

## Spec

### Model

- `SessionReminder` is a value type: `Sendable` and `Equatable`, with no view or AppKit types. Its fields:
  - `id: UUID`
  - `createdAt: Date`
  - `target`: either `.instant(Date)` for presets and custom durations, or `.wallClock(DateComponents)` for Tomorrow (year, month, day, hour and minute in the user's calendar)
  - `note: String?`, trimmed, `nil` when empty, capped at 500 characters
- `SessionRuntime.reminder: SessionReminder?` holds at most **one Reminder per Session**. Setting a Reminder on a Session that has one replaces it.
- The app has one `ReminderScheduler`, owned by `AppStateStore` because the Bell Feed and the notifier are app-wide. It covers every Window's Sessions.
- **Presets and custom durations** resolve once, when set, to `fireDate = clock.now + duration`. That is an absolute instant, so a time-zone or DST change doesn't move it.
- **Tomorrow** keeps wall-clock components. It is resolved against `Calendar.current` and the current time zone each time the scheduler evaluates, so "9:00 AM tomorrow" stays 9:00 AM local even if the user changes time zone or a DST transition falls in between.

### Setting a Reminder

**Entry points.** Each one acts on a specific Session. The Sidebar row's Session is the target from the context menu. Elsewhere, the target is the key Window's selected Session.

- **Session menu.** Add a **Remind Me** submenu, between "Choose Layout…" and the Cmd-1..9 list, containing:
  - In 5 Minutes, In 15 Minutes, In 30 Minutes, In 1 Hour
  - Tomorrow at 9:00 AM. The label shows the time currently set for Tomorrow.
  - Custom…, which opens the Reminder sheet.

  While the target Session has a Reminder pending, the submenu also shows:
  - a disabled status line ("Reminder at 3:45 PM")
  - Edit Reminder…
  - Cancel Reminder
- **Sidebar row context menu.** Add the same **Remind Me** submenu, next to Mute Notifications.
- **Command Palette.** Add these entries:
  - "Remind Me About This Session…", which opens the sheet.
  - "Remind Me in 5 / 15 / 30 Minutes" and "Remind Me in 1 Hour", which set the Reminder directly.
  - "Remind Me Tomorrow at 9:00 AM".
  - When a Reminder is pending: "Edit Reminder…" and "Cancel Reminder".
- **Keyboard shortcut.** None in this issue. Adding one means a new `ShortcutAction` case, which needs a default chord, so the user picks the chord. Leave the palette entry as the keyboard path.

**Sheet, not popover.** The Reminder sheet is a `.sheet` on the Window, like Rename, Set Color and Set Session Theme already are. A popover needs an anchor view. That breaks down for the Session menu and the Command Palette, and when the Sidebar is collapsed, because the row isn't on screen.

Contents of the Reminder sheet, top to bottom:

1. A title: **Remind Me About “<Session title>”**.
2. Preset buttons: **5 min**, **15 min**, **30 min**, **1 hour**. Clicking one selects it; it doesn't commit.
3. **Custom**: an Hours field (0–168) and a Minutes field (0–59). Typing in either one selects Custom. The total must be between 1 minute and 7 days, and Set is disabled outside that range.
4. **Tomorrow**, with a time picker that defaults to **9:00 AM local**. The user can change the time for this Reminder. The change is not remembered (see Open questions).
5. **Note**, optional: a multi-line text field (1–4 visible lines, 500-character cap).
6. A live summary line with the absolute time it resolves to, for example "Reminds you Thu Oct 15 at 9:00 AM". This removes any doubt about what "Tomorrow" means near midnight.
7. Buttons: **Cancel**, and **Set Reminder** as the default button, which Return triggers. In edit mode the sheet opens prefilled from the existing Reminder, shows a destructive **Remove Reminder** button, and the default button reads **Update Reminder**.

**Defaults.**
- Opening the sheet for a new Reminder selects 15 min.
- "Tomorrow" means the next calendar day in `Calendar.current`, at the chosen time.
- Setting a Reminder records no Bell Feed entry and posts no notification.

### When it fires

The scheduler calls `AppStateStore.fireReminder(sessionID:)`. That method finds the owning Window and Session at fire time, clears `session.reminder`, and then does two things.

**1. It records a Reminder Bell Feed entry.**
- Add `kind: BellFeedEntry.Kind` (`.bell`, the default, or `.reminder`) to `BellFeedEntry`. Decode it with `decodeIfPresent ?? .bell`, following the existing `repeatCount` / `firstOccurrenceAt` forward-compatibility pattern.
- The entry carries:
  - the real `windowID` and `sessionID`
  - `paneID` and `tabID` set to the Session's focused Pane and its active Tab at fire time. These satisfy the current schema; the jump does not navigate by them.
  - `message`: the note, or `nil`
- The entry is recorded **unseen**, even if the Session is selected and Batty is frontmost. The user asked to be interrupted.
- It is recorded with `record(_:)`, never `recordOrCollapse`, so two Reminders never merge. It gets no Foundation Models summarization.
- It does **not** bump the tab, pane or session `unseenBellCount`. Those counts mean unseen bells, and the Reminder has its own Sidebar state (see Visible state).
- **Feed row styling.** Reminder rows look different from bell rows:
  - an `alarm` SF Symbol leading icon, tinted with the accent color
  - the title "Reminder" followed by the Session title as the path label, with no Pane or Tab
  - the note as the body, or "Time to come back to <Session title>" when there is none
  - a secondary line "Set <relative time> ago". When the Reminder fired more than a minute after its target (see Sleep and wake), the line reads "Due <time>".
  - unseen and seen highlighting that works the same as for bell rows
- "Clear All" (`markAllBellsSeen`) marks Reminder entries seen too.

**2. It posts a macOS notification.**
- Add `BellNotifying.postReminder(entry:sessionTitle:)`, following the `postFootprintWarning` precedent. Give it a no-op default in the protocol extension so test doubles don't break.
- **Title:** "Batty — Reminder: <Session title>". **Body:** the note, or "Time to come back to <Session title>". **Identifier and `userInfo`:** the entry id, so a tap goes through the existing `onTapEntry` path.
- **Gating:**
  - The app-wide "Show system notifications" setting applies.
  - "Play sound" applies.
  - Per-Session mute does **not** apply. Mute is for ambient bell noise; a Reminder is something the user set on purpose. If the user disagrees, see the Open questions.
  - The "active and already seen" suppression in `evaluateShouldPost` does not apply either, because the entry is always unseen at post time.
- **Decision history (#0297).** If `BellDecisionHistory` logs every post, add a `.reminder` trigger. Otherwise state in a code comment why Reminders are not logged. Either way, keep that log's outcome cases in lockstep with any new gate, as `BellNotifier.post`'s doc comment requires.

**3. Clicking the feed entry or the notification** routes through `AppStateStore.jumpToBellEntry`. For `.reminder` entries, the jump runs a *Session-level* path:
1. It makes the owning Window key and front. This is the same event-origin `makeKeyAndOrderFront` the bell path uses.
2. It sets that Window's `selectedSessionID` to the Session. It does **not** change `focusedPaneID` or the active Tab: the user returns to the Session as they left it, not to whichever Tab happened to be focused at fire time.
3. It marks the entry seen.

If the Session or Window no longer exists, the jump only marks the entry seen. That can't normally happen, because closing a Session purges its entries.

### Visible state

**Pending.** The Session's Sidebar row shows a small `clock` SF Symbol badge, secondary-tinted, before the unseen-bell count.
- Its tooltip (`.help`) shows the absolute time and the note: "Reminder at 3:45 PM — <note>". For Tomorrow it reads "Reminder tomorrow at 9:00 AM".
- Don't drive a ticking countdown through observed state. Any relative-time text is computed at render time, for example with `TimelineView(.periodic(from:by: 60))` or `Text(date, style: .relative)`. No timer writes `@Observable` properties once a minute (`docs/swiftui-observation-rules.md`).

**Due.** From fire until the Reminder entry is seen, the row shows an accent-tinted `alarm.fill` badge in place of the clock. The entry counts as seen when any of these happens:
- the user selects that Session, by any path that runs `markActiveTabSeen()`, extended to also mark that Session's unseen `.reminder` entries seen
- the user clicks the entry or the notification
- the user runs Clear All

Because the entry is unseen, the toolbar bell shows `bell.badge` until the entry is seen.

**View, edit and cancel.**
- Hovering the badge shows the details.
- Clicking the pending badge opens the sheet in edit mode. It is a plain button with a `.help` tooltip. Clicking the due badge does nothing beyond the row's normal selection.
- **Edit Reminder…** and **Cancel Reminder** appear in the Session menu's and the context menu's Remind Me submenu, and in the Command Palette. Cancel removes the Reminder at once, with no confirmation.
- Editing replaces the Reminder in place and reschedules it.

### Edge cases

- **Closing the Session cancels its Reminder.** `removeSession(id:)` clears `session.reminder` and tells the scheduler, and it purges that Session's `.reminder` feed entries along with its tab-keyed entries. This applies to all close paths: the Sidebar's Close item, closing the last Tab, `batty session close` and closing the Window. A Reminder that has already fired is not resurrected. Nothing is posted about the cancellation, because closing the Session was the user's own action. If a close confirmation is already shown for that Session, for example because processes are running, it adds a line: "Its reminder for 3:45 PM will be cancelled." No new confirmation is introduced just for the Reminder.
- **Quitting Batty.** Reminders do not survive a quit, because Sessions don't (#0172, #0444). There is nothing to restore a Reminder into, and a Reminder pointing at a Session that no longer exists would be meaningless. No `UNNotificationRequest` is scheduled ahead of time with a calendar or interval trigger: that notification would fire after quit for a Session that is gone. If any Reminders are pending and the existing "Quit Batty?" confirmation (`QuitConfirmation`) is shown, it adds a line: "N pending reminder(s) will be cancelled." Quitting does not add a confirmation of its own.
- **Sleep, wake and a missed fire time.** A Reminder whose fire time passed while the Mac slept **fires once, immediately on wake**. It records its feed entry and posts its notification, with a "Due <time>" secondary line on the row. When several are overdue, each fires and gets its own entry, ordered by due time. The scheduler re-evaluates on:
  - `NSWorkspace.didWakeNotification`
  - `NSNotification.Name.NSSystemClockDidChange`
  - `NSNotification.Name.NSSystemTimeZoneDidChange`
  - `.NSCalendarDayChanged`

  It does not rely on a pending `Task.sleep` resuming promptly after wake.
- **Multiple Windows.**
  - There is one app-wide scheduler.
  - Each Window's Sidebar shows badges for its own Sessions.
  - At fire time the owning Window is resolved from the Session, never cached when the Reminder is set.
  - A click makes that Window key, even if a different Window is key at the time.
  - Sessions cannot move between Windows today. If that ever becomes possible, resolving at fire time already handles it.
- **Duplicate Session and Save as Project** do not copy the Reminder.
- **Renaming a Session** while a Reminder is pending: the entry and the notification use the title at fire time.
- **Wall-clock time versus duration.** Presets and custom durations are instants (`clock.now + d`), and Tomorrow is wall-clock components. Example across the 2026-11-01 DST fall-back in America/Los_Angeles: Tomorrow at 9:00 AM set on 2026-10-31 at 20:00 PDT fires on 2026-11-01 at 09:00 PST, which is 14 elapsed hours later, not 13.

### Scheduler and clock seam

The design follows `AGENTS.md` "Asynchronous tests" and `docs/async-test-seams.md` §1.

- `ReminderScheduler` takes three injected dependencies:
  - `clock: SchedulingClock = SystemClock()`
  - `calendar: Calendar = .current` and `timeZone` (or a `() -> Calendar` provider, so tests can pin the zone)
  - `onFire: (UUID /* sessionID */) -> Void`
- **It runs a single loop task.** The loop takes the earliest resolved fire date and awaits `clock.sleep(for: max(0, fireDate - clock.now))`. It then fires every Reminder with `fireDate <= clock.now`, ordered by due time, and loops again.
- **`set`, `edit`, `cancel` and `reevaluate()` all cancel the loop task and restart it.** `reevaluate()` is the one entry point the wake and clock-change observers call. A test calls the same method directly to simulate wake, so tests need no `NSWorkspace` notification.
- **Firing is observable without waiting.** Tests await the `onFire` callback (through a continuation or an `AsyncStream`), or a `Task` handle the scheduler exposes for testing. Use `TestClock.waitForSleepers(1)` before `advance(by:)`. No `Task.sleep`, no polling, and no wall-clock assertions.
- **UI-test clock hook.** When `BATTY_UI_TEST_SCRIPT` is present and `BATTY_UI_TEST_REMINDER_CLOCK=manual` is set, the app builds its scheduler with a frozen manual clock (a `ManualSchedulingClock` in `BattyKit/Sources/BattyKit/Testing/`). Under that clock, time never passes on its own.
- **Advancing the manual clock** goes through a test-only Command Palette entry, "UI Test: Advance Reminder Clock…", with a minutes field. It exists only under both env vars. Alternatively, it can be a `UITestDriver` intent `advanceReminderClock(minutes:)`. The implementer picks whichever fits the harness, as long as a running test can trigger it after setting a Reminder through the real UI.
- **The hook can't run outside tests.** It is inert without `BATTY_UI_TEST_SCRIPT` and can't change Prod behavior. A unit test covers that gating, following the pattern of `UITestDriver.exposesSidebarIcons(environment:)`.

## Expected behavior / Acceptance criteria

1. The Session menu, the Sidebar row context menu and the Command Palette each offer Remind Me with In 5 / 15 / 30 Minutes, In 1 Hour, Tomorrow at 9:00 AM and Custom…. Each one acts on the right Session: the clicked row for the context menu, the key Window's selected Session otherwise.
2. The Reminder sheet:
   - offers the four presets, a custom Hours and Minutes duration (1 minute to 7 days, with Set disabled outside that range), Tomorrow with a time picker that defaults to 9:00 AM, and an optional note of up to 500 characters
   - shows the absolute fire time it resolves to
   - sets the Reminder on Return
3. A Session has at most one Reminder. Setting a new one replaces the pending one.
4. While a Reminder is pending, the Session's Sidebar row shows a clock badge. Its tooltip gives the absolute fire time and the note.
5. Edit Reminder… reopens the sheet prefilled, and saving reschedules the Reminder. Cancel Reminder removes it and its badge at once. Both are available from the Session menu, the context menu and the Command Palette.
6. At fire time:
   - exactly one Bell Feed entry of kind `.reminder` is recorded, unseen, with the note as its body and the Session as its path
   - the entry is styled differently from bell entries, with an `alarm` icon and "Reminder" title
   - no tab, pane or session `unseenBellCount` changes
   - the Session row's badge becomes the due badge
   - the toolbar bell shows `bell.badge`
7. At fire time a macOS notification titled "Batty — Reminder: <Session>" is posted, with the note or a default line as its body. It honors "Show system notifications" and "Play sound", and ignores per-Session mute.
8. Clicking the Reminder entry, or tapping its notification, makes the owning Window key, selects the Session without changing its focused Pane or active Tab, and marks the entry seen. Selecting the Session by any other route also marks it seen and clears the due badge.
9. Closing a Session with a pending Reminder cancels the Reminder, and it never fires. Closing a Session purges its Reminder entries from the feed.
10. A Reminder whose fire time passed while the Mac slept fires once on wake, and its row says "Due <time>".
11. Tomorrow resolves to the next calendar day at the chosen local time and stays correct across a DST transition. Presets are absolute instants.
12. With several Windows open, each Reminder fires for its own Session, and the click brings forward the Window that owns it.
13. Reminder entries never collapse into other entries and are never summarized.
14. Pending Reminders do not survive a quit, and nothing fires after a relaunch. An existing quit confirmation mentions pending Reminders.
15. No unit test or UI test waits in real time for a Reminder to fire.
16. The docs are updated:
    - `Concepts.md`: Reminder, plus the Session, Bell Feed and Sidebar notes, and a version bump.
    - `docs/notifications.md`: a new source in §2, the fire path, and the gating and mute exception.
    - `docs/ui-features.md`: the Bell feed section, plus a new Reminders section with accessibility identifiers.
    - `PRD.md` §6.13: one line.

## Tests

**Unit tests** go in `BattyKit/Tests/BattyKitTests/`, use `TestClock`, and use no real time. They cover:
- **Preset resolution.** Setting a 15-minute Reminder fires after `advance(by: .minutes(15))`. Advancing 14:59 fires nothing.
- **Custom duration bounds.** 0 minutes and more than 7 days are rejected, while 1 minute and exactly 7 days are accepted.
- **Tomorrow resolution** with a pinned calendar and time zone: the next calendar day at the chosen time. This includes the DST case above (14 elapsed hours) and a time set at 00:30, which still resolves to the *next* calendar day's 9:00 AM.
- **One per Session.** Setting a second Reminder replaces the first, and only the second fires.
- **Edit reschedules.** Moving a Reminder earlier fires it at the new time. Moving it later means it does not fire at the old time.
- **Cancel.** A cancelled Reminder never fires, and the scheduler has no pending sleepers (`clock.pendingCount == 0`).
- **Closing the Session cancels.** `removeSession` with a pending Reminder never fires, and a fired Reminder's feed entries are purged.
- **Missed fire on wake.** Advance past several Reminders' due times, call `reevaluate()`, and each fires exactly once in due-time order. Each carries its due time for the "Due" line.
- **Fire effects on `AppStateStore`.** Use a fake `BellNotifying` and check that:
  - one `.reminder` entry is recorded, unseen
  - no `unseenBellCount` changes
  - `postReminder` is called with the note
  - a muted Session still posts
  - the "Show system notifications" off setting suppresses the post. Isolate `UserDefaults` per `docs/isolate-userdefaults-in-tests.md`.
- **Jump.** `jumpToBellEntry` on a `.reminder` entry selects the Session and leaves `focusedPaneID` and `activeTabID` **unchanged**. Use a non-default fixture: focus a Pane or Tab other than the defaults first, so the "unchanged" assertion isn't vacuous. Then check it marks the entry seen.
- **Seen on selection.** Selecting the Session marks its unseen `.reminder` entries seen.
- **No collapse.** Two Reminders on the same Session fire as two entries.
- **Forward-compatible decoding.** `BellFeedEntry` JSON without `kind` decodes as `.bell`.
- **UI-test clock gating.** The manual clock is used only when both env vars are present.

**VM UI tests** go in `BattyUITests/SessionReminderTests`. They run only through `tools/run-ui-tests-vm.sh`, launched with `BATTY_UI_TEST_REMINDER_CLOCK=manual`:
- **Set from the context menu.** Remind Me → In 15 Minutes, then the clock badge appears on the row.
- **Set from the sheet with a note.** Custom… → 1 h 30 m, enter a note, Set. The badge appears, and its tooltip or accessibility value contains the note.
- **Cancel.** Cancel Reminder, and the badge disappears. Advancing the test clock 2 hours adds no Reminder entry to the Bell Feed.
- **Fire and jump.** Set a 5-minute Reminder on Session A, select Session B and focus a non-default Pane in A beforehand. Advance the test clock 5 minutes. Check the following:
  - the Bell Feed shows one Reminder entry with the note
  - A's row shows the due badge
  - clicking the entry selects Session A with its previously focused Pane unchanged
  - the due badge clears
- **Close cancels.** Set a Reminder, close the Session, advance the clock, and the feed has no Reminder entry.

## Open questions for the user

1. **Name.** Should it be "Reminder" (menu verb "Remind Me"), or something like "Set Aside" or "Come Back Later"? *Recommendation:* Reminder / Remind Me. It's the plainest word and reads naturally in the Bell Feed ("Reminder: api-server").
2. **Tomorrow's time.** Should it be fixed at 9:00 AM, editable per Reminder in the sheet, or a Settings preference? *Recommendation:* 9:00 AM by default, editable per Reminder in the sheet, not remembered, and no Settings row. Add a Settings default later if 9:00 AM keeps getting changed.
3. **One-click presets or always the sheet.** *Recommendation:* the menu presets set the Reminder at once with no note, and Custom… opens the sheet for durations, Tomorrow time and notes. It's fast in the common case, and the note is one more click away.
4. **Per-Session mute.** Should a muted Session's Reminder still post a banner? *Recommendation:* yes. Mute silences ambient bells, and a Reminder is an explicit request. The global "Show system notifications" toggle still applies.
5. **Banner when the Session is already in front.** *Recommendation:* still post it and record the entry unseen. The user set an alarm, and the note may be the point.
6. **One Reminder per Session.** *Recommendation:* exactly one, and setting another replaces it. Multiple Reminders would need a list UI on the row, which this feature doesn't need.
7. **Keyboard shortcut.** *Recommendation:* none in this issue. Adding one needs a new `ShortcutAction` with a default chord. If you want one, name the chord. Cmd-Shift-R is not bound by any `ShortcutAction` today, but confirm it doesn't clash with the menus.
8. **Feature flag.** *Recommendation:* none, provided this lands as one issue (see Feature flag). Add `sessionReminders` only if it gets split across issues.
9. **CLI verb `batty session remind`.** *Recommendation:* a follow-up issue after the GUI lands.
10. **Snooze.** Should the notification or the feed entry offer "Remind Again in 15 Minutes"? *Recommendation:* a follow-up. A `UNNotificationAction` category is a small addition once the scheduler exists.
11. **Telling the user when a Session close cancels a pending Reminder.** *Recommendation:* only mention it in a close or quit confirmation that is already being shown. Don't add a new prompt, and don't add a feed entry.
