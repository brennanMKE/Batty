## Description

Child of #0680. Before the skill is published on the site (#0687), it should be thin enough to rarely go stale, and the CLI should point people at the right install route. The source of truth stays the `SKILL.md` bundled in the app and installed by `batty agent install`, so its version always matches the installed CLI.

### Current state (checked against `main` at `3a7c12ec`)

- `.claude/skills/batty-cli/SKILL.md` is 381 lines. It already says `batty capabilities --json` outranks its prose (lines 15-20) and states minimum versions per section (lines 8-13), but §1-§10 still carry verb-level detail that duplicates `capabilities` and `batty agent context`, and §10 is headed "Dev servers (Beta only)" (line 325).
- The app bundles only `SKILL.md` (Run Script phase in `Batty.xcodeproj/project.pbxproj:363-373` copies it to `AgentGuidance/skills/batty-cli/`); `install.sh` (next to it in the repo) is not bundled.
- `CapabilitiesCommand.skillInstallLines` (`BattyKit/Sources/batty/CapabilitiesCommand.swift:302-339`): with `agentIntegration` on it points at `batty agent install`; with it off it prints a `git clone --branch v<cliVersion>` recipe that runs `install.sh` (lines 316-337). Once #0669 removes the flag, the git-clone branch is dead, and there is no site URL to fall back on.

## Expected behavior

1. **Thin skill.** `SKILL.md` keeps only what a schema can't carry (sequencing, which id to keep, what an exit code means to do next, cleanup duty) and defers parameters and per-verb detail to `batty capabilities --json` and `batty agent context`. It states one minimum Batty version in its first lines (and keeps per-section minimums only where they differ). Target: well under the current 381 lines; the plan names what moves out and confirms each removed fact is in `capabilities` or `agent context`.
2. **Pointer.** Plain-text `batty capabilities` names `batty agent install` first and the site's skill URL (`https://batty.sstools.co/docs/skill/batty-cli-skill-latest.zip`, #0687) second. The `git clone` recipe, `skillRepositoryURL` and `skillRepositoryRelativePath` are removed, with the tests that pinned them updated. `--json` output is unchanged (#0384).
3. Decide what happens to `.claude/skills/batty-cli/install.sh`: recommended, delete it, since `agent install` and the zip replace it; the plan checks every reference first (`git grep -n install.sh` finds 53 lines outside `issues/` today).

## Acceptance criteria

1. `./build.sh` and `./build.sh unit` pass.
2. `batty capabilities` (plain text, Beta build) prints no `git clone` and names `agent install` and the site URL; `batty capabilities --json` is byte-identical before and after except `cliVersion`.
3. Every verb or flag `SKILL.md` names exists in `batty capabilities --json` from a Beta build.
4. The bundled copy matches `.claude/skills/batty-cli/SKILL.md` (whatever check #0647 established).
