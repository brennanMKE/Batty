# 0104 — Website: add apple-touch-icon and sized favicon

| | |
|---|---|
| **Status** | open |
| **Module** | Website |
| **Platform** | All |
| **First seen** | 2026-05-13 |

## Description

The Batty website ships a single icon link on every page:

```
<link rel="icon" href="assets/batty-icon.png" type="image/png">
```

`assets/batty-icon.png` is 1024×1024 — the hero image. Browsers downscale it to render a 16/32-px favicon, which is wasteful and produces a soft favicon in tab chrome. And nothing serves an `apple-touch-icon`, so when a user pins the page in Safari or adds it to their iOS home screen, Safari either screenshots the page or scales the favicon awkwardly.

The fix is small and ships two new PNGs from the existing `batty-icon.png` source.

## Scope

In:

- `assets/favicon-32.png` (32×32) — wired as `<link rel="icon" type="image/png" sizes="32x32" href="assets/favicon-32.png">`.
- `assets/apple-touch-icon.png` (180×180, the modern Safari size) — wired as `<link rel="apple-touch-icon" href="assets/apple-touch-icon.png">`.
- Update `index.html`, `changelog.html`, and `privacy.html` head sections — keep the existing `assets/batty-icon.png` link as a generic fallback for browsers that don't pick the sized icon.
- All paths stay **relative** (`assets/...`) so the site continues to load locally per #0096.

Out:

- `icon-192.png` and a PWA manifest. Batty's site isn't a PWA; the 192 is mostly a manifest concern. Skip until that changes.
- Favicons in `.ico` format. Modern browsers handle PNG `rel="icon"` fine.
- Dark-mode-aware favicons. The current icon is on a transparent background and reads on both light and dark tab chrome.

## Acceptance criteria

- `website/assets/favicon-32.png` exists, is 32×32, exactly square.
- `website/assets/apple-touch-icon.png` exists, is 180×180, exactly square.
- All three website HTML pages have both new `<link>` tags in `<head>`, in addition to the existing generic icon link.
- All paths in the link tags are relative (no leading `/`).
- The site still loads locally (open `website/index.html` directly in a browser; favicon and icons resolve).

## Notes

- The source for both is `website/assets/batty-icon.png` (1024×1024). Use `sips` to downscale.
- Apple's current Safari guidance prefers 180×180 for `apple-touch-icon`; older guidance specified 152/167/180. A single 180 is fine — Safari downscales as needed.
