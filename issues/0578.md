## Description

Add a page to batty.sstools.co, `website/backgrounds.html`, that shows every hosted Background Set as a grid of thumbnails grouped by set, each linking to its full-size image, and that teaches people to build their own Background Catalog so they make and share sets. Child of [#0574](0574.md). Ships with 1.4.0 and its website deploy.

User request (2026-11-11, verbatim):

> "For the Batty website we will need a new web page dedicated to background images which feature the thumbnails which would be organized by set. It should also explain how to create your own set of images to encourage others to create their own sets to share."

## What exists today

- **Site.** Static HTML with one stylesheet, `website/css/style.css`, and no build step (`website/README.md`). House rules: "No tracking. No analytics. No external JS." No page has a `<script>` tag today. Subpages (`privacy.html`, `changelog.html`, `demo.html`) use `<body class="page">`, a `page-header` with a `← Batty` back link, and a `<footer>`. `demo.html` adds page-specific CSS in an inline `<style>` block, so there's precedent for that, even though the README says to keep the CSS in one file.
- **Navigation.** `index.html`'s footer `<nav>` links Demo, Changelog, Privacy and Report an issue. `demo.html`'s footer nav links Changelog, Privacy and Report an issue. `privacy.html`'s footer has no nav.
- **Catalog.** `website/backgrounds/catalog.json`, tracked in git: `schemaVersion` 1, name "Batty Backgrounds", three sets (`future-cities` "Future Cities", `cool-vehicles` "Cool Vehicles", `beautiful-landscapes` "Beautiful Landscapes"), five images each. No set has a `description` and no image has a `credit`. The format is in #0574 "Catalog format".
- **Images.** All 30 files exist in the local `website/backgrounds/<set>/` folders and are gitignored (`.gitignore:22`, `website/backgrounds/**/*.png`). Thumbnails are 480 × 300 (about 2 MB for all 15). Full-size images are currently **1586 × 992** (about 23 MB for all 15), not the 3840 × 2400 that `docs/background-image-prompts.md` asks for. The committed `catalog.json` still says 3840 × 2400. The working tree has an uncommitted edit to 1586 × 992, and the `sha256`/`bytes` fields aren't filled in yet. That is #0575's follow-through, not this issue, but this page shows whatever the catalog says.
- **Check script.** `tools/check-backgrounds.py` validates `catalog.json` against the files before a deploy. Its orphan check reports **every** file under `website/backgrounds/` that isn't `catalog.json`, isn't hidden and isn't named by a catalog `url` (`tools/check-backgrounds.py:285`–`290`). So an example catalog or any page asset saved inside `website/backgrounds/` fails the check.
- **Deploy.** `rsync -avz` without `--delete` to `photon:/var/www/vhosts/batty.sstools.co/`, after a `-n` dry run, with the user's go-ahead each time (`website/README.md` "Background images").
- **Repository.** `github.com/brennanMKE/Batty` has Issues on, Discussions **off** (`gh api repos/brennanMKE/Batty`, `has_discussions: false`), and an MIT license.

## The page

1. **File and style.** `website/backgrounds.html`, `<body class="page">`, the same `<head>` (favicons, `css/style.css`, plus `description` and Open Graph tags like `demo.html`, with a thumbnail as `og:image`), the `page-header` with `← Batty`, and the same footer. Any new CSS is small and follows the existing tokens (`--bg-card`, `--border`, `--accent`, `--max-width`). Put it in `css/style.css` (preferred, per the README) or an inline block like `demo.html`; the plan picks one.
2. **Linked from the site.** Add "Backgrounds" to the footer nav of `index.html` and `demo.html`, and a short mention on the landing page (for example a sentence or link in the features or download section) so it can be found without scrolling to the footer. Add `/backgrounds.html` to the "Pages to spot-check" list in `website/README.md`.
3. **Intro.** One short paragraph: what Background Sets are, that Batty 1.4.0 can browse them in the Background Images window and use one as a terminal background, and that anyone can publish their own.
4. **Sets.** One section per set, in catalog order, headed by the set `title` (with its `description` when present). Each section is a responsive grid of thumbnails at 16:10. Each thumbnail:
   - is an `<img>` with `src` = the thumbnail `url`, `width` and `height` from the catalog (so the layout doesn't shift), `loading="lazy"` and `decoding="async"`, and `alt` = the image `title`;
   - is wrapped in a link to the full-size `url`, so a click opens the full image in the browser;
   - has a caption with the `title`, the full-size dimensions, the size when `bytes` is known (for example "1586 × 992 · 1.6 MB"), and the `credit` when present.
   Paths are relative to the page (`backgrounds/future-cities/01-skyline-fog-thumb.png`), the catalog's own URLs joined to `backgrounds/`.
5. **Get them in Batty.** A short how-to: File → Background Images… → Browse, then pick an image. Describe it exactly as #0576 and #0577 ship it (see "Dependencies"), including that only thumbnails download while browsing.
6. **Make your own set.** See the next section.
7. **Share your set.** See open question 1.

## "Make your own set" section

Written for someone outside the project, in this order:

1. **What you need.** A folder of images, a `catalog.json` that lists them, and any `https` web host that serves static files (your own site, GitHub Pages, an S3 bucket and so on).
2. **The catalog format.** A short, friendly version of #0574 "Catalog format", `schemaVersion` 1:
   - top level: `schemaVersion` (1), `name`, optional `updated` (`YYYY-MM-DD`) and `homepage` (`https`), and `sets`;
   - set: `id` (lowercase letters, digits and hyphens, up to 64 characters, starting with a letter or digit), `title`, optional `description`, `images`;
   - image: `id` (same pattern, unique across the whole catalog, and never reused for a different picture), `title`, optional `credit`, `full`, `thumbnail`;
   - file (`full` and `thumbnail`): `url`, `width`, `height`, and the recommended `sha256` and `bytes`.
   - `url` may be relative and resolves against the catalog's own URL (`future-cities/01-skyline-fog.png` next to `.../backgrounds/catalog.json`), or absolute. Either way it must end up `https`. Images may be on another host.
   - PNG or JPEG, and the real type must match the extension (`.png`, `.jpg`, `.jpeg`).
   - Limits: catalog file 1 MB; 50 sets, 100 images per set, 1,000 per catalog; titles up to 100 characters, descriptions up to 300, credits up to 200; thumbnail up to 2 MB and 1024 px on its longest side; full size up to 50 MB and 8192 px on its longest side (#0577 "Limits"). Batty keeps its own copy scaled to at most 4096 px on the longest side, so larger than that gains nothing.
   - Unknown fields are ignored, so leave out anything Batty doesn't need.
   Show a short annotated example: one set with two images.
3. **Downloadable example catalog.** A complete, valid example file the reader can copy and edit, linked from the page with `download`. Put it **outside** `website/backgrounds/` (for example `website/examples/background-catalog.json`), because the check script reports any extra file in that folder as an orphan. Its URLs point at example names, not the real Batty images, and it says nothing that suggests it is a live catalog. The plan decides how it is kept valid (for example, a self-test case that parses it with the same schema checks).
4. **Designing images for behind terminal text.** Borrow from `docs/background-image-prompts.md` "Rules for every image": 16:10 landscape; dark overall with only small, soft highlights; low contrast and muted, one or two hues; keep the upper-left two-thirds calm because that's where text sits, and put the subject toward the right and the bottom third; avoid fine, busy detail; no text, logos or watermarks. Suggest checking each image at Batty's default 15% Image Opacity (`BattyKit/Sources/BattyKit/Help/11-backgrounds.md`) over a dark theme.
5. **Sizing.** Recommend 16:10, for example 2560 × 1600 or 3840 × 2400, and say why the 4096 px cap makes anything bigger pointless.
6. **Thumbnails with `sips`** (built into macOS): `sips -z 300 480 full.png --out full-thumb.png` for a 16:10 image; `sips -Z 480 full.png --out full-thumb.png` to keep any other aspect ratio; add `-s format jpeg` for a JPEG thumbnail. Make thumbnails from the full image, never separately.
7. **Filling in the fields.** `sips -g pixelWidth -g pixelHeight <file>` for the size, `shasum -a 256 <file>` for `sha256`, `stat -f %z <file>` for `bytes`. Mention that `tools/check-backgrounds.py --write` in the Batty repo fills `sha256` and `bytes` and checks everything, for a catalog whose image URLs are relative files in the catalog's folder.
8. **Hosting.** `https` with a valid certificate (Batty offers no override), at most 5 redirects and all `https`. Serve `catalog.json` with an `ETag` or `Last-Modified` header so Batty's regular checks are cheap (#0577 "Regular refresh"). CORS headers are **not** needed for Batty, which isn't a browser; they matter only if someone wants to show your catalog on a web page from another site. Keep image ids stable: ship a changed picture under a new id.
9. **Add it in Batty.** Settings → Appearance → Background Catalogs, paste the URL, Add. Batty fetches it once to validate it and shows any error beside the URL, then lists its sets in Background Images → Browse and checks it regularly. Use the wording and labels as shipped (see "Dependencies").
10. **Licensing.** Only share images you have the right to share, and say how others may use them (see open question 2).

## Static HTML or fetched in the browser

**Recommended: static HTML generated from `catalog.json` by a tool,** not a client-side `fetch`.

- **No JavaScript.** The site has none today and the README forbids external JS. Static markup works with scripts off, in reader modes and for crawlers and link previews.
- **Can't drift.** A generator writes the set grid between marker comments in `backgrounds.html` (for example `<!-- BEGIN SETS -->` … `<!-- END SETS -->`), so the hand-written prose around it stays editable. A `--check` mode exits 1 when the page doesn't match the catalog. Run it next to `tools/check-backgrounds.py` before every deploy, and document both in `website/README.md` "Background images". The plan decides whether this is a new `tools/` script with its own self-test, in the style of `tools/check-backgrounds-selftest.py`, or a mode of `tools/check-backgrounds.py`. It goes in `tools/`, not `scripts/` (restricted, AGENTS.md).
- **Caching.** A static page caches like every other page, with no second request for the JSON and no layout jump while it loads. `catalog.json` is the file the app revalidates (#0577), and the page doesn't add to that traffic.
- **Validated input.** The generator reads only a catalog that `tools/check-backgrounds.py` already passes, so the page never shows a missing file or a wrong size.
- **Cost:** someone must re-run the generator after editing `catalog.json`. The `--check` step catches a forgotten run.

The rejected option, a small inline script that fetches `backgrounds/catalog.json`, always matches the live catalog but shows nothing without JavaScript, adds the site's first script, and needs its own escaping of catalog text.

## Dependencies

Write that copy from what actually landed, not from the issue text. If either isn't on `main` when this is planned, write those steps last and keep the rest.
- **#0575.** The images, real `width`/`height`, and filled-in `sha256`/`bytes` in `catalog.json` must be settled before the page is generated for release. The page itself can be built and reviewed against today's catalog.
- **Release.** Ship the page with 1.4.0, in the same website deploy that publishes the images and the catalog, so the page never links to images that aren't on the server and never describes features users can't get yet. The deploy is the user's step, with their go-ahead each time.

## Out of scope

- Uploading or submitting a set through the website. The site stays static.
- Listing other people's catalogs on the page (it can come later, once sharing works; see open question 1).
- Changes to the app, the catalog format or the check script's catalog rules.
- Server configuration such as cache headers (#0575 open question 2).

## Open questions

1. **Where do people share sets?** GitHub Discussions is off on the repo. Options: (a) a GitHub issue template or label such as "Background set" on `brennanMKE/Batty`; (b) turn on Discussions with a "Background Sets" category, which is the user's change in GitHub settings; (c) an email address. Proposed: (a), since it needs no new service and the footer already links to issues. Until the user decides, the page can say "open an issue on GitHub with a link to your catalog.json".
2. **Image credits and licensing for shared sets.** What license are Batty's own 15 images under: the repo's MIT, CC BY, CC0, or "for use in Batty only"? They're AI-generated (`docs/background-image-prompts.md`), which may affect what can be claimed. What should the page ask of people who share: state a license in `credit` or on their `homepage`? Would the catalog benefit from an optional `license` field (unknown fields are already ignored, so it wouldn't need a new `schemaVersion`)? Proposed: the page asks sharers to name a license and use `credit`, and adds no format change in 1.4.0.
3. **Should the page link straight to `backgrounds/catalog.json`** as "the built-in catalog" so people can read a real one? Proposed: yes, beside the example.

## Acceptance criteria

1. Opening `https://batty.sstools.co/backgrounds.html` (or `/backgrounds.html` from `python3 -m http.server` in `website/`) shows Future Cities, Cool Vehicles and Beautiful Landscapes, in that order, with five thumbnails each and their titles.
2. Clicking any thumbnail opens that image's full-size file, and it is the same picture.
3. The page works and shows every thumbnail with JavaScript turned off in Safari.
4. In Safari's Web Inspector Network tab, opening the page doesn't load any full-size image, and thumbnails further down load as you scroll.
5. VoiceOver reads each thumbnail by its title.
6. The page looks like the other subpages (header, back link, fonts, colours, footer) on a wide window and on a phone-width window, with no sideways scrolling.
7. The site's index page and footer have a visible link to the page.
8. "Make your own set" covers the catalog format, image design tips, thumbnails with `sips`, hosting, and adding the URL in Batty Settings, and the example catalog downloads from a link on the page.
9. Following the page's steps, adding the downloaded example's structure with real images on your own `https` host, and pasting its URL into Batty Settings works, with the steps matching Batty's actual labels.
10. Changing an image title in `catalog.json` without regenerating makes the page check fail; regenerating fixes it. `tools/check-backgrounds.py website/backgrounds/catalog.json` still passes with the example catalog in place.
11. `tidy -e -q website/backgrounds.html` reports no new warnings.
