## "Make your own set" section

Written for someone outside the project, in this order:

1. **What you need.** A folder of images, a `catalog.json` that lists them, and any `https` web host that serves static files (your own site, GitHub Pages, an S3 bucket and so on).
2. **The catalog format.** A short, friendly version of #0574 "Catalog format", `schemaVersion` 1:
   - top level: `schemaVersion` (1), `name`, optional `updated` (`YYYY-MM-DD`) and `homepage` (`https`), and `sets`;
   - set: `id` (lowercase letters, digits and hyphens, up to 64 characters, starting with a letter or digit), `title`, optional `description`, `images`;
   - image: `id` (same pattern, unique across the whole catalog, and never reused for a different picture), `title`, optional `credit`, `full`, `thumbnail`;
   - file (`full` and `thumbnail`): `url`, `width`, `height`, and the recommended `sha256` and `bytes`.
   - `url` may be relative and resolves against the catalog's own URL (`future-cities/01-skyline-fog.png` next to `.../backgrounds/catalog.json`), or absolute. Either way it must end up `https`. Images may be on another host.
   - PNG or JPEG, and the real type must match the extension (`.png`, `.jpg`, `.jpeg`).
   - Limits: catalog file 1 MB; 50 sets, 100 images per set, 1,000 per catalog; titles up to 100 characters, descriptions up to 300, credits up to 200; thumbnail up to 2 MB and 1024 px on its longest side; full size up to 50 MB and 8192 px on its longest side (#0577 "Limits"). Batty keeps its own copy scaled to at most 4096 px on the longest side, so larger than that gains nothing.
   - Unknown fields are ignored, so leave out anything Batty doesn't need.
   Show a short annotated example: one set with two images.
3. **Downloadable example catalog.** A complete, valid example file the reader can copy and edit, linked from the page with `download`. Put it **outside** `website/backgrounds/` (for example `website/examples/background-catalog.json`), because the check script reports any extra file in that folder as an orphan. Its URLs point at example names, not the real Batty images, and it says nothing that suggests it is a live catalog. The plan decides how it is kept valid (for example, a self-test case that parses it with the same schema checks).
4. **Designing images for behind terminal text.** Borrow from `docs/background-image-prompts.md` "Rules for every image": 16:10 landscape; dark overall with only small, soft highlights; low contrast and muted, one or two hues; keep the upper-left two-thirds calm because that's where text sits, and put the subject toward the right and the bottom third; avoid fine, busy detail; no text, logos or watermarks. Suggest checking each image at Batty's default 15% Image Opacity (`BattyKit/Sources/BattyKit/Help/11-backgrounds.md`) over a dark theme.
5. **Sizing.** Recommend 16:10, for example 2560 × 1600 or 3840 × 2400, and say why the 4096 px cap makes anything bigger pointless.
6. **Thumbnails with `sips`** (built into macOS): `sips -z 300 480 full.png --out full-thumb.png` for a 16:10 image; `sips -Z 480 full.png --out full-thumb.png` to keep any other aspect ratio; add `-s format jpeg` for a JPEG thumbnail. Make thumbnails from the full image, never separately.
7. **Filling in the fields.** `sips -g pixelWidth -g pixelHeight <file>` for the size, `shasum -a 256 <file>` for `sha256`, `stat -f %z <file>` for `bytes`. Mention that `tools/check-backgrounds.py --write` in the Batty repo fills `sha256` and `bytes` and checks everything, for a catalog whose image URLs are relative files in the catalog's folder.
8. **Hosting.** `https` with a valid certificate (Batty offers no override), at most 5 redirects and all `https`. Serve `catalog.json` with an `ETag` or `Last-Modified` header so Batty's regular checks are cheap (#0577 "Regular refresh"). CORS headers are **not** needed for Batty, which isn't a browser; they matter only if someone wants to show your catalog on a web page from another site. Keep image ids stable: ship a changed picture under a new id.
9. **Add it in Batty.** Settings → Appearance → Background Catalogs, paste the URL, Add. Batty fetches it once to validate it and shows any error beside the URL, then lists its sets in Background Images → Browse and checks it regularly. Use the wording and labels as shipped (see "Dependencies").
10. **Licensing.** Only share images you have the right to share, and say how others may use them (see open question 2).

## Static HTML or fetched in the browser

**Recommended: static HTML generated from `catalog.json` by a tool,** not a client-side `fetch`.

- **No JavaScript.** The site has none today and the README forbids external JS. Static markup works with scripts off, in reader modes and for crawlers and link previews.
- **Can't drift.** A generator writes the set grid between marker comments in `backgrounds.html` (for example `<!-- BEGIN SETS -->` … `<!-- END SETS -->`), so the hand-written prose around it stays editable. A `--check` mode exits 1 when the page doesn't match the catalog. Run it next to `tools/check-backgrounds.py` before every deploy, and document both in `website/README.md` "Background images". The plan decides whether this is a new `tools/` script with its own self-test, in the style of `tools/check-backgrounds-selftest.py`, or a mode of `tools/check-backgrounds.py`. It goes in `tools/`, not `scripts/` (restricted, AGENTS.md).
- **Caching.** A static page caches like every other page, with no second request for the JSON and no layout jump while it loads. `catalog.json` is the file the app revalidates (#0577), and the page doesn't add to that traffic.
- **Validated input.** The generator reads only a catalog that `tools/check-backgrounds.py` already passes, so the page never shows a missing file or a wrong size.
- **Cost:** someone must re-run the generator after editing `catalog.json`. The `--check` step catches a forgotten run.

The rejected option, a small inline script that fetches `backgrounds/catalog.json`, always matches the live catalog but shows nothing without JavaScript, adds the site's first script, and needs its own escaping of catalog text.

### Generator: a new tool, not a mode of `check-backgrounds.py`

`check-backgrounds.py` checks a catalog against image files and edits the catalog. Rendering a page is a different job with different inputs (page, example). A mode would mix the two and grow its argument rules. So add a new script that **imports** the checker's schema functions instead of copying them, the same `importlib.util.spec_from_file_location` load the checker's self-test uses.

**`tools/build-backgrounds-page.py`** (new, standard library only, Python 3, shebang and module docstring in the checker's style):

```
python3 -I tools/build-backgrounds-page.py [--check] [--catalog PATH] [--page PATH] [--example PATH]
```
- Defaults, relative to the repo root (`Path(__file__).resolve().parent.parent`): `website/backgrounds/catalog.json`, `website/backgrounds.html`, `website/examples/background-catalog.json`. Optional `--checker PATH` (default `tools/check-backgrounds.py` beside the script) so the self-test can point at the in-tree copy explicitly.
- **Validate the catalog** with `_schema` + `_unique`, and `_url_problem(url, catalog_dir)` for every file `url` (relative only, as for the built-in catalog). Print each problem as the checker does and exit 1, writing nothing. It never opens image files: missing files, real dimensions and hashes stay `check-backgrounds.py`'s job, and the deploy runs both.
- **Validate the example catalog** the same way: `_schema` + `_unique`, and `_url_problem` against the example's own folder, which accepts the relative URLs the example uses without the files existing. Problems are printed with the prefix `example: ` and exit 1. Both modes do this, which is how the example stays valid.
- **Render** two blocks (below) and replace the text between each marker pair in the page.
- **Default mode** writes the page (temp file in the same folder + `os.replace`, as `write()` does), only when the text changed, then prints `OK: wrote <page> (N sets, M images)` or `OK: <page> already up to date`. Exit 0.
- **`--check`** never writes. If either rendered block differs from the page, print `<page>: sets block is out of date; run python3 -I tools/build-backgrounds-page.py` (or `example block`) and exit 1. Also exit 1 when `og:image` in the page doesn't end with `backgrounds/` + one of the catalog's thumbnail URLs (`<page>: og:image is not a catalog thumbnail`), so a renamed thumbnail can't break link previews. Otherwise `OK: <page> matches <catalog>`, exit 0.
- **Markers:** each pair must occur exactly once, BEGIN before END, each alone on its line. Otherwise print `<page>: missing or duplicate marker <marker>` and exit 1, page untouched. Exit 2 is reserved for argparse usage errors.
  - `<!-- BEGIN BACKGROUND SETS (generated by tools/build-backgrounds-page.py; do not edit) -->` … `<!-- END BACKGROUND SETS -->`
  - `<!-- BEGIN EXAMPLE CATALOG (generated by tools/build-backgrounds-page.py; do not edit) -->` … `<!-- END EXAMPLE CATALOG -->`
  - Replace everything strictly between BEGIN's line end and END's line start. Keep the marker lines and their indentation. Indent the generated lines to the BEGIN marker's indentation.
- **Sets block**, deterministic (same input, byte-identical output, `\n` line ends), per set in catalog order:
  ```html
  <section class="bg-set" id="set-<set id>" aria-labelledby="set-<set id>-title">
      <h2 id="set-<set id>-title"><title></h2>
      <p class="bg-set-description"><description></p>          <!-- only when present -->
      <ul class="bg-grid">
          <li>
              <figure class="bg-image">
                  <a href="backgrounds/<full url>"><img src="backgrounds/<thumb url>" width="<thumb w>" height="<thumb h>" alt="<image title>" loading="lazy" decoding="async"></a>
                  <figcaption><span class="bg-title"><image title></span> <span class="bg-meta"><W> × <H>[ · <size>]</span>[ <span class="bg-credit"><credit></span>]</figcaption>
              </figure>
          </li>
          …
  ```
  - Image order is the catalog's. `W × H` is the **full** size, with U+00D7 and spaces. `<size>` only when the full file's `bytes` is present: under 1,000,000 bytes `"<round(bytes/1000)> KB"`, otherwise `"<bytes/1_000_000:.1f> MB"` (decimal, as Finder shows sizes). The separator is ` · ` (U+00B7).
  - Every text and attribute value goes through `html.escape(s, quote=True)`. URLs are `"backgrounds/" + urllib.parse.quote(url, safe="/")`. The `alt` is the image title. The link has no `target`, so the full image opens in the same tab, as the issue asks.
- **Example block:** the example file's text, HTML-escaped, inside `<pre class="bg-example"><code>…</code></pre>`, so the snippet on the page can't drift from the download.

**`tools/build-backgrounds-page-selftest.py`** (new). Same shape as `check-backgrounds-selftest.py`: loads the generator by path (optional argv[1]), builds every fixture in a `tempfile.TemporaryDirectory`, runs `main(args)` with stdout captured, a crash is a failure, prints `ok`/`FAIL` per case and `N/M passed`, exits 0 or 1. **No image files are created**, which itself proves the generator never reads them. The fixture: a catalog with two sets (`alpha` with a `description`, `beta` without), two images each; one image has `credit` and full `bytes` 1,600,000, one has `bytes` 640,000, the others have no `bytes`; one title is `Café <Racer> & "Co"`. A minimal page with `<meta property="og:image" content="https://batty.sstools.co/backgrounds/alpha/01-pic-thumb.png">`, prose before, between and after two empty marker pairs. A small valid example catalog file. Cases:
1. `writes the sets block between the markers`
2. `prose outside the markers is unchanged` (byte-compare everything outside the blocks)
3. `sets and images in catalog order`
4. `thumbnail img has src width height alt lazy async`
5. `thumbnail links to the full-size url`
6. `no full-size url is an img src`
7. `caption shows full dimensions and MB size` (`160 × 100 · 1.6 MB`)
8. `caption shows KB size under one MB` (`640 KB`)
9. `caption has no size without bytes`
10. `credit shown when present, absent otherwise`
11. `description shown when present, absent otherwise`
12. `titles and credits are escaped` (`&lt;Racer&gt; &amp; &quot;Co&quot;` in text and `alt`, `é` kept as UTF-8, not an entity)
13. `url with a space is percent-encoded` (`a b.png` → `a%20b.png`)
14. `second run changes nothing` (byte-identical, prints "already up to date")
15. `check passes right after generating`
16. `check fails after a title changes and leaves the page alone` (acceptance 10)
17. `check fails after an edit inside the markers`
18. `check fails when the example file changes`
19. `check fails when og:image is not a catalog thumbnail`
20. `missing marker exits 1 and leaves the page alone`
21. `duplicate marker exits 1`
22. `END before BEGIN exits 1`
23. `invalid catalog exits 1 and writes nothing` (`schemaVersion` 2)
24. `absolute image url is refused` (`https://example.com/a.png`)
25. `dotdot image url is refused`
26. `invalid example catalog exits 1` (duplicate image id)
27. `repo example catalog passes the schema`: the real `website/examples/background-catalog.json` through `_schema`/`_unique`/`_url_problem` (our own file, so a real path is fine)

The self-test deliberately does **not** check that the real page matches the real catalog. That's `--check`'s job at deploy time, and the catalog changes independently.
