## Description

A VS Code / Xcode-style command palette: press Cmd-Shift-P, type a few characters, see a fuzzy-filtered list of in-app actions, hit Return to run the focused one. Examples of commands the palette should surface:

- *Split Right*, *Split Down*, *Close Pane*, *Zoom Pane*
- *Switch Theme…* (with theme names as sub-results)
- *New Session*, *Rename Session…*, *Duplicate Session*
- *Toggle Bell Feed*, *Mute Session*, *Mute All Sessions*
- *Open Settings*, *Check for Updates…*
- *Clear Scrollback*, *Reset Terminal*

A palette serves three purposes simultaneously: discoverability for users who don't know the shortcuts; speed for users who don't want to reach for the mouse; and living documentation for the project. `BattyShortcuts.swift` and `BattyCommands.swift` already enumerate most of the action surface, so the palette can largely be a view on top of that registry.

**Details TBD** — the broad shape above is committed; the specifics (registry shape, filter algorithm, what a "command" looks like, whether it accepts arguments, theming) need a design pass before implementation. This issue exists as a scope anchor; expect a follow-up before work begins.

## Acceptance criteria (provisional)

- Cmd-Shift-P from anywhere in the app opens a centered translucent sheet with a text field and a results list.
- Typing filters the list by case-insensitive fuzzy match against the command name.
- Up / Down arrow keys move selection; Return runs the focused command; Esc dismisses without action.
- Every command currently bound to a menu item or shortcut is reachable from the palette.
- The palette dismisses when a command runs; the affected pane / session regains focus.

## Out of scope

- Recently-used / frequently-used reordering. Worth doing later for ergonomics; not required for v1 of the palette.
- Arbitrary command arguments (e.g. "Open Session…" with a session-name argument). Two-step interaction (palette → sub-prompt) is fine; arg-parsing inside the palette text field is over-design.
- Surfacing shell commands, files, or terminal content. The palette covers *Batty actions*, not the terminal buffer.
- macOS Spotlight integration / system-wide commands.

## Notes

- This needs more design before implementation. Key questions to answer before estimating:
  - What's the registry data model? A `CommandDescriptor` with `title`, `subtitle`, `keyEquivalent?`, `category?`, `action: () -> Void`?
  - Do menu items and palette commands share a single source-of-truth registry, or does the palette mirror menu items?
  - How does the palette interact with the focused pane / session context? (e.g. "Split Right" needs to know which pane to split.)
  - Theme: bg/blur consistent with the bell feed popover, or its own visual?
- The Sessions sidebar and tabs strip already give navigation by clicking; the palette overlaps with that for navigation actions but adds reach to everything else.
- Related: `#0128` (Open Quickly) and this issue both surface fuzzy-search UI. Worth deciding whether they share infrastructure (one fuzzy-find component, two entry points) or are independent.
- `BattyShortcuts.swift` already centralizes shortcut keys; extending it to expose human-readable titles + actions is the natural seed for the registry.

## Root cause

No command palette existed.

## Fix

- Added `commandPalette` to `ShortcutAction` with default binding Cmd-Shift-P. `BattyShortcuts.run` dispatches it by posting `battyToggleCommandPalette`.
- `CommandPaletteView` (new) builds a `[PaletteCommand]` list from all `ShortcutAction` cases (with key hint from `ShortcutsStore`) plus additional commands: Duplicate Session, Mark All Bells Seen, Check for Updates, About Batty, and one entry per theme. Fuzzy filtering via `FuzzyMatcher` (new shared utility). Up/Down/Return/Esc keyboard navigation via `.onKeyPress`.
- `SessionDetailView` listens for `battyToggleCommandPalette` and presents the sheet.
- `openQuickly` action (`#0128`) is listed in the palette with its Cmd-Shift-O hint.

## Files changed

- `BattyKit/Sources/BattyKit/Shortcuts/ShortcutAction.swift` — added `commandPalette` and `openQuickly` cases (both for this issue and `#0128`)
- `BattyKit/Sources/BattyKit/Commands/BattyShortcuts.swift` — dispatch `commandPalette` → notification
- `BattyKit/Sources/BattyKit/Views/CommandPaletteView.swift` — new file; defines `PaletteCommand` and `CommandPaletteView`
- `BattyKit/Sources/BattyKit/Util/FuzzyMatcher.swift` — new shared fuzzy-match utility (used by this and `#0128`)
- `BattyKit/Sources/BattyKit/Views/SessionDetailView.swift` — wires notification → `commandPaletteShown` state → `.sheet`

## Gotchas

- The palette is presented as a macOS sheet (slides from title bar) rather than a VS Code-style centered overlay. This is SwiftUI's native modal path and steals keyboard focus correctly. A floating NSPanel would give a more VS Code-like feel but adds AppKit complexity; deferred.
- The dispatch in `CommandPaletteView` duplicates some logic from `BattyShortcuts.run`. Both implement the same action dispatch; a future refactor could centralize into a shared dispatch function on `AppStateStore` or a free function.

## Re-opened

**Reported by user 2026-05-18:** the command palette opens with Cmd-Shift-P, but typing in the search field does not filter the visible commands. Example: typing `Theme: Re` should narrow to entries like `Theme: Rebecca`, but the full list keeps showing.

The user also flagged that the issue's framing as "VS Code-style" is misleading without working filtering — in VS Code you can type `Tasks:` and the list collapses to matching entries; that's the core of the UX, not an extra. The acceptance criterion "Typing filters the list by case-insensitive fuzzy match against the command name" is not met.

**Likely cause (high-confidence guess):** the same family of bug just fixed in `#0128`. `FuzzyMatcher` itself was verified correct during the `#0128` work; the bug was in how `OpenQuicklyView` called it (composite-string scoring; unstable result IDs causing SwiftUI to render the wrong rows for the right filter, which can manifest as "no visible filtering" depending on how the view recycles). `CommandPaletteView` shares the matcher and was written in the same style — check it against the same failure modes:

1. Is `PaletteCommand.id` stable across re-renders, or is it a fresh `UUID()` on every access? Unstable IDs in a `LazyVStack`/`ForEach` will make filtered output render the unfiltered row labels.
2. Is `body` reading the filtered list multiple times per render? If so, snapshot it into a local `let` once and thread that through `ForEach`, key handlers, and Return-activation.
3. Is the match being run against the right field? Each `PaletteCommand` likely has a `title` (and maybe `subtitle`/`category`). Confirm the matcher input matches what the user sees in the row.

The `#0128` fix in commit `7ebdb09` (`OpenQuicklyView.swift` + the new `OpenQuicklyFilter.apply(query:to:)` pure function) is the reference pattern. The palette should get the same shape: an extracted `CommandPaletteFilter.apply(query:to:)` pure function, stable `id` on `PaletteCommand`, snapshot-the-list-once in `body`.

**How to reproduce:**

1. Open Batty.
2. Press **Cmd-Shift-P**.
3. Type `Theme:` (or any other substring matching multiple command titles).
4. Observe: the list does not narrow.

**Acceptance criteria for the fix:**

- Typing in the palette filters the visible command list in real time, case-insensitive, with the same fuzzy-match semantics used by `#0128` (subsequence + contiguity beats scatter).
- Selection state and Up/Down keyboard navigation operate on the filtered list, not the full list.
- Return activates the highlighted *filtered* command, not the same-indexed unfiltered one.
- Add unit tests against the new pure filter function covering: substring match (`Theme: Re` → `Theme: Rebecca`, not `Theme: Mocha`), case insensitivity, subsequence match, no-match returns empty, empty-query returns all.

**Out of scope for this fix:** the framing concern about VS Code parity. The fix here is the filter behavior; if the framing in `## Description` still feels misleading after the fix, that can be a documentation-only follow-up.
