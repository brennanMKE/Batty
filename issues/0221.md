## Description

The workspace persistence layer — pure value types `Tab`, `Pane`, `Session`, `SplitNode`, `Workspace`, `WindowState`, `WindowFrame`, and `WorkspaceStore` — is not implemented in BattyKit. `~/Library/Application Support/Batty/workspace.json` exists on disk and is written at quit, but no code reads it at launch. The app always starts with a default "Session 1" regardless of prior state.

## Closed 2026-08-27 — the premise was deleted, not deferred

> 🔴 Closed 2026-08-27 — the workspace persistence layer this issue asks for was
> removed from the project by #0172; there is nothing left to implement. The live
> successor carrying the useful part of the intent is [#0371](0371.md).

The user's decision, 2026-08-27. This issue describes a workspace model layer
(`Tab`, `Pane`, `Session`, `SplitNode`, `Workspace`, `WindowState`,
`WindowFrame`, `WorkspaceStore`) plus reading
`~/Library/Application Support/Batty/workspace.json` at launch to restore the
previous layout. **[#0172](0172.md) deleted that machinery entirely** — verified
against the repo on 2026-08-27:

- `#0172` (resolved 2026-05-20, commit `5628db1`) deleted `Workspace.swift`,
  `WorkspaceConversion.swift`, `WorkspaceManager.swift`, and
  `WorkspaceStore.swift`, and removed every `workspace.json` mention from
  `PRD.md`, `Concepts.md`, and `docs/`. Its stated rationale: *"Workspace
  persistence was never a planned feature and will never be one."*
- None of those files exists under `BattyKit/Sources/BattyKit/Model/` or
  `Runtime/` today, and `grep` for `workspace.json` across the Swift sources
  returns nothing.
- `CLAUDE.md` records the deletion as a standing architectural fact: the Codable
  `Session`/`Tab`/`SplitNode` snapshot types "were deleted along with workspace
  persistence in #0172, not merely renamed."

So both halves of this issue are moot: the file it wants read at launch is no
longer written, and the types it wants restored were removed on purpose. Closed
rather than `wontfix` — the premise ceased to exist; the request was not
declined on its merits.

**Live successor: [#0371](0371.md).** The one fragment of intent that survives —
saved, reusable Pane arrangements a user explicitly invokes — is carried there
under the term **Workspace** (decided 2026-08-27). #0371 is *not* a revival of
the deleted persistence layer: it stores split topology and a `PaneContentKind`
per slot, with no ratios, cwds, Tabs, window frames, or process state, and
nothing auto-saves or auto-restores.

The `## Relation` note below about #0256 goes with the premise: `Pane.isHidden`
still does not survive relaunch, because nothing persists Pane state at all —
and #0371 deliberately does not persist it either.

## Long Description

Four `BattyKitTests` test files (`LayoutModelTests.swift`, `WorkspaceTests.swift`, `WorkspaceStoreTests.swift`, `WorkspaceConversionTests.swift`) were written against these planned types. Because the source types don't exist, these tests are compile errors and block the entire `BattyKitTests` target from building (see #0220). They were removed as part of fixing #0220 and should be restored when this layer is implemented.

The CLAUDE.md spec says: "Layout model is pure value types (Session, Pane, Tab, SplitNode) — Codable, Sendable, no view or libghostty types embedded. This is what Workspace persistence serializes." This layer is the planned design but hasn't been built yet.

`workspace.json` content (last modified 2026-05-21, 1 session with a Claude Code bell entry) is readable and serves as a target for the restore format.

## Expected behavior

On launch, Batty reads `workspace.json` and restores the previous session layout (sessions, panes, tabs, names, sidebar state).

## Actual behavior

On every launch, Batty creates a single default "Session 1" and ignores `workspace.json`.
