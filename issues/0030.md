# 0030 — WorkspaceStore: save on quit, on structural changes, and every 30s

| | |
|---|---|
| **Status** | open |

| **Platform** | macOS |
| **First seen** | 2026-05-08 |

## Description

The runtime side of Workspace persistence: collect the current app state into a `Workspace` value (#0029) and write it to `~/Library/Application Support/Batty/workspace.json` on the cadence specified in `Concepts.md` → Workspace.

**Acceptance criteria:**
- `WorkspaceStore` writes the Workspace JSON:
  - Once on `applicationWillTerminate`.
  - Once after every structural mutation (Session add/remove/reorder, Pane split/collapse, Tab add/close/reorder), debounced ~250ms to coalesce rapid edits.
  - On a 30-second timer while the app is running.
- Writes are atomic (write to a `.tmp` sibling, fsync, rename) so a crash during write doesn't leave a half-written file.
- The directory `~/Library/Application Support/Batty/` is created if missing.
- A small log line (or os_log signpost) is emitted on each save so we can audit cadence during development.

## Notes

- Use `JSONEncoder` with `.prettyPrinted, .sortedKeys` (matches #0029).
- Don't block the main thread on disk IO — wrap writes in a detached `Task` or a serial dispatch queue.
- Loading is #0031.

### Phase 1 landed in `e2fa162` — IO layer only

Added `Batty/WorkspaceStore.swift`:

- `WorkspaceStore` — `@MainActor` final class. Holds the destination `URL`, defaulting to `~/Library/Application Support/Batty/workspace.json` resolved via `FileManager.urls(for: .applicationSupportDirectory, in: .userDomainMask)`.
- `save(_:)` — creates the parent directory if missing, encodes via `Workspace.prettyEncoder`, writes atomically (sibling `.tmp-<uuid>` then `FileManager.replaceItemAt`). A crash mid-write can't leave `workspace.json` half-written.
- `canonicalFileURL(fileManager:)` static — exposes the default URL computation.
- Logs each save (bytes + path) via `os.Logger` under subsystem `co.sstools.Batty`, category `WorkspaceStore`.

Tests in `BattyTests/WorkspaceStoreTests.swift` cover save round-trip, missing-directory creation, overwrite of an existing file, and canonical URL shape. 4 new tests passing.

### Why this is still `open`

The issue's acceptance criteria call for cadence:

- Save on `applicationWillTerminate`.
- Save after every structural mutation, debounced ~250ms.
- Save on a 30-second timer.

None of the three is wired. Each requires a running app with an observable workspace state to listen to, and that state lives downstream of M2 (sidebar) / M3 (tabs) / M4 (splits). The IO primitive is in place and unit-tested; the wiring is mechanical once there's a `Workspace` value being held by a live app.

### What's left — when M2–M4 lands

1. Hold the live `Workspace` value in an `@Observable` app-level store.
2. Subscribe to that store; on each change, kick a 250ms-debounced `Task` that calls `WorkspaceStore.save(_:)`.
3. Start a 30-second `Timer` that also calls `save`.
4. In `BattyApp`'s scene phase / `applicationWillTerminate`, force a synchronous final save.
5. Add an integration test that mutates the model and asserts the file lands within ~300ms.

Atomic-write rationale captured for posterity: `replaceItemAt` over `data.write(to:options:.atomic)` because the former preserves filesystem extended attributes (quarantine, finder tags) across the swap; `.atomic` does not. No `fsync` — power-loss within seconds is acceptable for v1.
