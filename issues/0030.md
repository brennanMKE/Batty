## Description

The runtime side of Workspace persistence: collect the current app state into a `Workspace` value (#0029) and write it to `~/Library/Application Support/Batty/workspace.json` on the cadence specified in `Concepts.md` → Workspace.

**Acceptance criteria:**
- `WorkspaceStore` writes the Workspace JSON:
  - Once on `applicationWillTerminate`.
  - Once after every structural mutation (Session add/remove/reorder, Pane split/collapse, Tab add/close/reorder), debounced ~250ms to coalesce rapid edits.
  - On a 30-second timer while the app is running.
- Writes are atomic (write to a `.tmp` sibling, fsync, rename) so a crash during write doesn't leave a half-written file.
- The directory `~/Library/Application Support/Batty/` is created if missing.
- A small log line (or os_log signpost) is emitted on each save so we can audit cadence during development.

## Notes

- Use `JSONEncoder` with `.prettyPrinted, .sortedKeys` (matches #0029).
- Don't block the main thread on disk IO — wrap writes in a detached `Task` or a serial dispatch queue.
- Loading is #0031.

### Phase 1 landed in `e2fa162` — IO layer only

Added `Batty/WorkspaceStore.swift`:

- `WorkspaceStore` — `@MainActor` final class. Holds the destination `URL`, defaulting to `~/Library/Application Support/Batty/workspace.json` resolved via `FileManager.urls(for: .applicationSupportDirectory, in: .userDomainMask)`.
- `save(_:)` — creates the parent directory if missing, encodes via `Workspace.prettyEncoder`, writes atomically (sibling `.tmp-<uuid>` then `FileManager.replaceItemAt`). A crash mid-write can't leave `workspace.json` half-written.
- `canonicalFileURL(fileManager:)` static — exposes the default URL computation.
- Logs each save (bytes + path) via `os.Logger` under subsystem `co.sstools.Batty`, category `WorkspaceStore`.

Tests in `BattyTests/WorkspaceStoreTests.swift` cover save round-trip, missing-directory creation, overwrite of an existing file, and canonical URL shape. 4 new tests passing.

### Why this is still `open`

The issue's acceptance criteria call for cadence:

- Save on `applicationWillTerminate`.
- Save after every structural mutation, debounced ~250ms.
- Save on a 30-second timer.

None of the three is wired. Each requires a running app with an observable workspace state to listen to, and that state lives downstream of M2 (sidebar) / M3 (tabs) / M4 (splits). The IO primitive is in place and unit-tested; the wiring is mechanical once there's a `Workspace` value being held by a live app.

### What's left — when M2–M4 lands

1. Hold the live `Workspace` value in an `@Observable` app-level store.
2. Subscribe to that store; on each change, kick a 250ms-debounced `Task` that calls `WorkspaceStore.save(_:)`.
3. Start a 30-second `Timer` that also calls `save`.
4. In `BattyApp`'s scene phase / `applicationWillTerminate`, force a synchronous final save.
5. Add an integration test that mutates the model and asserts the file lands within ~300ms.

Atomic-write rationale captured for posterity: `replaceItemAt` over `data.write(to:options:.atomic)` because the former preserves filesystem extended attributes (quarantine, finder tags) across the swap; `.atomic` does not. No `fsync` — power-loss within seconds is acceptable for v1.

## Phase 2 fix — `7beddf3`

`AppStateStore` (M2 from #0010) is the live state. Wired the cadence on top:

- New `WorkspaceManager` singleton (`BattyKit/Sources/BattyKit/WorkspaceManager.swift`) holds the loaded `AppStateStore`. Construction:
  1. Resolves the `WorkspaceStore` (URL → `~/Library/Application Support/Batty/workspace.json`).
  2. Calls `workspaceStore.load()` and switches on the three-case result. `.loaded` / `.recovered` populate the store via `AppStateStore(from: WindowState)`. `.missing` falls back to a fresh empty store.
  3. Starts a 30-second timer `Task` that calls `saveNow()`.
  4. Subscribes to `NSApplication.willTerminateNotification` (queue: `.main`); on fire, performs a synchronous final save.
- `RootWindowView` defaults to `WorkspaceManager.shared.store` so the loaded state is the default for new windows.
- New `WorkspaceConversion.swift` provides bidirectional model ↔ runtime converters: `Tab ↔ TabRuntime`, `Pane ↔ PaneRuntime`, `SplitNode ↔ SplitTreeNode`, `Session ↔ SessionRuntime`, plus `WindowState(from: AppStateStore, sidebarHidden:)` and `AppStateStore(from: WindowState)`.
- Save reads `SidebarPreference.hiddenKey` from `UserDefaults` so quit-while-sidebar-hidden restores hidden on relaunch.

Five new tests in `BattyKitTests/WorkspaceConversionTests`:
- `SessionRuntime` round-trip preserves id / title / focused pane / pane count.
- A 3-leaf tree built via `splitFocusedPane` preserves shape through persistence.
- `AppStateStore → WindowState → AppStateStore` preserves session count, titles in order, selected session.
- Full JSON round-trip via `Workspace.prettyEncoder` / `decoder`.
- `Tab.titleOverride` survives the round-trip.

44 tests pass via `swift test --package-path BattyKit`. `xcodebuild build` passes.

## Gotchas

- **No structural-mutation debounce.** The 30-second timer + on-quit pair guarantees no more than 30 seconds of state loss. Adding fine-grained save-on-mutation (debounced ~250ms) would require explicit calls from every `addSession`, `removeSession`, `splitFocusedPane`, `addTab`, `removeTab`, etc., or a `withObservationTracking` re-arm pattern. Either is doable; the timer is good enough for v1.
- **Single-window persistence.** Only `windows[0]` is read on load and only one `WindowState` is written on save. PRD §6.6 calls for per-window persistence; with `WorkspaceManager.shared` being a singleton, all `RootWindowView` instances share the same `AppStateStore`. Multi-window means multiple windows showing the same data. Genuine per-window persistence is a follow-up.
- **`willTerminateNotification` runs synchronously on the main queue.** The save needs to complete before the process exits. For a small `workspace.json` (typically <50KB) this is sub-millisecond. If the file ever balloons we may need to look at this again.
- **Live shell state, scrollback, running processes are NOT restored.** Per PRD §6.7 we explicitly start fresh shells. The persisted Tab has `lastKnownCWD` and `lastSetTitle` fields, but cwd is currently always nil at save time because pwd-tracking depends on `TerminalSurfacePwdDelegate` (delegate-plumbing-blocked). Once that's plumbed, new shells can spawn in the saved cwd.
- **Bell feed history is in the schema but always empty.** `#0024`/`#0025` are delegate-plumbing-blocked; once they land, the manager will need to extend its save snapshot to include `bellFeedStore.entries`.
- **Surface ids regenerate on load.** The `Tab` model has a `surfaceID: UUID` that's unused at runtime currently; the conversion regenerates it each save. Once `surfaceID` becomes meaningful (e.g., for click-to-jump in the bell feed), persistence will need to keep it stable across launches.
