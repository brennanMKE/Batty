# 0030 — WorkspaceStore: save on quit, on structural changes, and every 30s

## Description

The runtime side of Workspace persistence: collect the current app state into a `Workspace` value (#0029) and write it to `~/Library/Application Support/Batty/workspace.json` on the cadence specified in `Concepts.md` → Workspace.

**Acceptance criteria:**
- `WorkspaceStore` writes the Workspace JSON:
  - Once on `applicationWillTerminate`.
  - Once after every structural mutation (Session add/remove/reorder, Pane split/collapse, Tab add/close/reorder), debounced ~250ms to coalesce rapid edits.
  - On a 30-second timer while the app is running.
- Writes are atomic (write to a `.tmp` sibling, fsync, rename) so a crash during write doesn't leave a half-written file.
- The directory `~/Library/Application Support/Batty/` is created if missing.
- A small log line (or os_log signpost) is emitted on each save so we can audit cadence during development.

## Notes

- Use `JSONEncoder` with `.prettyPrinted, .sortedKeys` (matches #0029).
- Don't block the main thread on disk IO — wrap writes in a detached `Task` or a serial dispatch queue.
- Loading is #0031.
