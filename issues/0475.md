# 0475 — There is no way to pick and open a saved Project from the app: no Open Project picker, no File menu items, no Command Palette entries

## Description

With Projects stored (#0471), openable (#0472, #0473) and editable (#0474), the user still needs in-app ways to open one. This issue adds the **Open Project picker** sheet (artboard 2, `issues/0469/OpenProject.dc.html`), the **File ▸ Open Project ›** submenu, and **Open Project: <name>** entries in the Command Palette (artboard 4). Every one of them is absent while the flag is off.

## Expected behavior

**1. Open Project picker sheet**, modeled on the Layout picker (`Views/LayoutPickerView.swift`, a `.sheet` over a `LazyVGrid` with arrow, Return and Escape handling via `.onKeyPress` at `:76-81`). The sheet is presented from `SessionDetailView` like the Layout picker (`Views/SessionDetailView.swift:49-52`, `:78-80`), toggled by a notification guarded on `isKeyWindow` (the #0242 fan-out guard):

- Title "Open a Project", plus "Esc to dismiss".
- A **filter field**, focused on appear through `@FocusState`. It does a fuzzy or substring match on name and path. Reuse `CommandPaletteFilter` if its semantics fit.
- A **grid of Project cards**. Each card has a pane thumbnail with each slot colored and badged by kind, with geometry derived from the Project's topology (see #0474 on deriving thumbnail geometry). Then the color dot and name, the path (abbreviated with `~`), and the summary "N panes · N tabs · N startup commands" from #0471's helpers, with correct singular and plural forms ("1 pane", "no startup commands"). An **OPEN** badge appears when #0472's helper reports an open Session for that Project.
- **Keys.** Arrows move the selection. **Return** opens with `.focusExistingOrOpen`. **Option-Return** opens with `.openNew` ("Open another copy"). **⌘E** dismisses and opens the Project Editor on the selected Project (#0474). **⌘N** dismisses and opens the editor on a new Project. **Escape** dismisses. The footer shows these hints, and the hint line reads "↩ Open <name> in a new Session" or "↩ Switch to the open <name> Session", depending on the OPEN state.
- **⌘N conflict, verify it.** ⌘N is the global New Session chord (`ShortcutAction.newSession`; the File menu item at `Commands/BattyCommands.swift:71-76`), and the `BattyShortcuts` NSEvent monitor guards only on `keyWindowIsContentWindow()` (`Commands/BattyShortcuts.swift:34`). A `.sheet` is attached to the content window. Establish which handler sees ⌘N first while the picker is up, and make ⌘N in the picker mean New Project… only. A UI test or a documented manual check must show that pressing ⌘N in the picker creates no Session. If that can't be made reliable, drop the ⌘N hint and tell the user.
- **Empty state.** With no Projects, show "No Projects yet" plus a New Project… button that opens the editor.
- Opening routes through #0472's `openProject`, and therefore through #0473's trust check.

**2. File menu**, inside the existing `CommandGroup(replacing: .newItem)` (`Commands/BattyCommands.swift:66-87`), after Open Quickly, in a `Divider`-separated group with #0474's Edit Projects…:

- **Open Project ›** is a submenu. It lists every Project by name in store order, with a **check mark** on Projects that have an open Session (#0472's helper). Selecting one opens it with `.focusExistingOrOpen`. Then a `Divider`, **Choose Project…** (presents the picker), and **New Project…** (opens the editor on a new Project).
- **Save Session as Project…** is #0476's item. Leave its slot for that issue.
- No `.keyboardShortcut` on any of these and **no new `ShortcutAction` case** (#0469). Disable the items when `keyWindow == nil`, matching New Session's `.disabled(keyWindow == nil)`.
- The menu's Project list must be driven from `ProjectStore`, never retyped, because the hand-copied-list hazard is recorded in `docs/issue-work-obstacles.md`.

**3. Command Palette** (`Views/CommandPaletteView.swift:52-114`, `allCommands`). One `PaletteCommand` per Project with `id: "project:<uuid>"` and title **"Open Project: <name>"** (opens with `.focusExistingOrOpen`), plus `id: "extra:openProjectPicker"` ("Open Project…"). Follow the existing conditional-entry pattern (`UpdaterController.shared.isConfigured` at `:86`, the `theme:` loop at `:100`). The palette's "Save Session as Project…" entry is #0476's.

**4. Flag gate, per entry point.** With `featureFlags.projects == false`:

- the File menu has **no** Open Project submenu, Choose Project… or New Project…. The items are absent, not merely disabled;
- `allCommands` contains **no** `project:` or `extra:openProjectPicker` ids;
- the picker's toggle notification is never posted, and `SessionDetailView` does not install the sheet;
- `ProjectStore` is never constructed, because no menu or palette code path touches it.

Append each site to #0470's gate-site list.

## Acceptance criteria

- `CommandPaletteView.allCommands` unit tests (the `CommandPaletteViewActionTests` pattern): with the flag on and two seeded Projects, it contains both `project:` entries with the right titles, and invoking one opens or focuses through a seam. With the flag off, it contains none, and `ProjectStore` was never constructed.
- The picker's selection, filter and summary-pluralization logic is a pure type with unit tests. That covers moving the selection over the grid, Return vs. Option-Return mode, the empty state, and filter matches by name and by path.
- The File-menu model (the list of items and their check states) is a testable function of `(flags, projects, open-project ids)`, unit-tested for flag on, flag off, zero Projects, and a check mark on an open Project.
- No sleeps or polling in tests (`AGENTS.md` "Asynchronous tests").
- Accessibility identifiers for the picker (sheet, filter field, cards keyed by Project name, OPEN badge) and the menu items, documented in `docs/ui-features.md` for #0478.
- `./build.sh unit` passes. The picker is a new visual surface, so the user's visual sign-off is required. Mark `resolved`, not `closed`.

## Notes

- **Binding:** `docs/swiftui-observation-rules.md`. The sheet's `isPresented` flips only from the notification handler (an event). Selection and filter changes are event-origin. `.onAppear` may focus the filter field through `@FocusState`, but must not write app state or call `makeFirstResponder`. `docs/view-hierarchy.md`: the sheet attaches to `SessionDetailView` like the other pickers, and opening a Project goes through the model only.
- **Layout picker leak, don't copy it.** #0371 found that two of the Layout picker's four entry points don't gate. Here the gate is the flag, and every entry point must check it. The palette and the NSEvent monitor are the paths reviewers have caught missing before (`docs/issue-work-obstacles.md:131-148`). Projects adds no `ShortcutAction`, so the monitor has nothing to gate. Say so in the resolution.
