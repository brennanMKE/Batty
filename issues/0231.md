## Description

When a session moves to a new working directory and the auto-naming chain finds no match — no cached user name for the path and no project marker recognized by `ProjectNameResolver` — the session falls back to the generic "Session N". Add an AI fallback step between rules-based derivation and the generic default: use Apple's FoundationModels framework (on-device local model, `LanguageModelSession`) to prompt for a reasonable session name from the path. If the model is unavailable or cannot produce a good name, keep the default.

## Long Description

The existing auto-naming priority chain in `AppStateStore.resolveAutoTitle(forCWD:sessionIndex:cache:resolver:)` is:

1. `SessionNameCache` hit (user's previous rename at this path)
2. `ProjectNameResolver` project-name extraction (Xcode, SPM, Cargo, npm, Deno, Go, Python, Ruby, Dart, Julia, Elixir, CMake — rules in `project-name-rules.json`)
3. Default `"Session N"`

This issue inserts a new step 3 (pushing the default to step 4): an on-device LLM prompt that looks at the directory path — which may be a meaningful set name (`~/Projects/batty-website`) or an anonymous path (`~/Documents/untitled folder 3`) — and optionally a shallow listing of file names in the folder, and asks for a short, human-friendly session name (2–4 words, no punctuation).

**Reference implementation:** the `ChatGPT` project (sibling repo, `foundation-models` branch) demonstrates the full pattern:

- `ChatGPT/Models/TabNaming.swift` — `generateTabName(userMessage:assistantMessage:)`: a dedicated `LanguageModelSession` with naming-only instructions ("Reply with only 2–5 words, no punctuation, no quotes"), one `respond(to:)` call, trim the result.
- `ChatGPT/Models/ChatViewModel.swift` — session lifecycle, cancellation, error handling (including context-window-exceeded reset and retry).

Design constraints:

- **Fallback only.** The AI step never runs when the cache or the project rules already produced a name, and never when `session.titleOverride == true`.
- **AI names are not user names.** A model-suggested name must not be written to `SessionNameCache` (`record(path:name:)`) and must not set `titleOverride = true`. It is a transient auto-title with the same standing as a rules-derived project name: a later `cd` re-resolves it, and a user rename still pins over it. Only an explicit user rename enters the cache.
- **"No good name" is a valid outcome.** The prompt should let the model decline (e.g., instruct it to reply `NONE` when the path/contents carry no meaningful signal — `untitled folder`, `tmp`, random hashes). On `NONE`, empty output, junk output (too long, punctuation-heavy), any thrown error, or model unavailability, leave the default "Session N". Never surface a raw model failure to the user.
- **Availability.** FoundationModels requires macOS 26+, which is the base requirement for this feature; Batty's deployment target stays macOS 15.6. Gate on `#available(macOS 26.0, *)` plus `SystemLanguageModel.default.availability` (Apple Intelligence may be off, model not downloaded, or device unsupported). When unavailable, the existing chain behaves exactly as today.
- **Ephemeral across launches.** An AI-suggested name must not survive into future sessions as a stored name. It must not be serialized by Workspace persistence as if it were a real title — on restore, the session re-resolves its name from the normal chain (cache → project rules → AI → default) rather than restoring the previously suggested AI name from disk.
- **Async and non-blocking.** Model inference takes real time. The cwd-change handler must not block; resolve the deterministic chain synchronously (so the title settles immediately to the project name or default), then kick off the AI suggestion and apply it only if, when it returns, the session's anchor cwd is still the same path, `titleOverride` is still false, and no newer resolution has run. Mind `docs/swiftui-observation-rules.md` — the eventual title write happens from event/task-origin code, not view-update code.
- **One in-flight request per session**, cancel on cwd change (see `currentTask` cancellation pattern in `ChatViewModel`).
- Consider a small in-memory memo (path → suggested name or NONE) so repeated `cd`s into the same unnamed folder don't re-prompt the model every time. This memo is distinct from `SessionNameCache` and is not persisted.

## Steps to reproduce

1. Open Batty (single-pane session, no user-defined name).
2. `cd` into a folder with no recognized project marker, e.g. `~/Documents/meeting notes 2026` or a path like `~/Downloads/archive-7f3a2`.
3. Observe the session title in the sidebar.

## Expected behavior

For a folder whose path or contents carry meaning, the session gets a short, readable AI-suggested name (e.g. "Meeting Notes"). For a folder with no signal, the title stays "Session N". A user rename always wins and is the only thing stored in the per-path name cache. On macOS < 26 or when Apple Intelligence is unavailable, behavior is unchanged from today.

## Actual behavior

The title falls straight to the generic "Session N" whenever the path has no cache entry and no project-rule match, even when the folder name or contents would make an obvious good name.

## Resolution notes

> Added an injectable AI naming step (FoundationModels, macOS 26+, weak-linked) between the project rules and the `Session N` default; suggestions are ephemeral, staleness-guarded, and never touch `SessionNameCache`.

## Root cause

Feature gap, not a bug: the auto-naming chain in `AppStateStore.handleWorkingDirectoryChange` had no step between `ProjectNameResolver` and the generic default, so any folder without a cache entry or project marker fell straight to `Session N` even when the path itself carried obvious meaning.

## Fix

- New `SessionNameSuggester.swift` (ProjectName module folder):
  - `SessionNameSuggesting` protocol — the injectable seam (`func suggestName(forPath:) async -> String?`, nil = "no good name").
  - `SessionNameSuggestion.sanitize(_:)` — centralized junk filter: trims whitespace/quotes, rejects `NONE` (case-insensitive), empty, >40 chars, >4 words, and anything outside alphanumerics/space/hyphen/underscore.
  - `FoundationModelsNameSuggester` — gated behind `#if canImport(FoundationModels)` + `#available(macOS 26.0, *)` + a per-call `SystemLanguageModel.default.availability` check. Builds a tight, dedicated `LanguageModelSession` per request (instructions: "2-4 words, no punctuation, reply NONE if no signal"), prompts with the path plus up to 20 non-hidden top-level entry names, single `respond(to:)`, returns trimmed content; all errors (incl. cancellation) collapse to nil. `makeIfAvailable()` returns nil below macOS 26.
- `AppStateStore`:
  - `@ObservationIgnored public var nameSuggester: SessionNameSuggesting?` — nil (the default, and the unit-test state) disables the feature entirely.
  - `handleWorkingDirectoryChange` still resolves the deterministic chain synchronously (title settles to project name / cached name / `Session N` immediately). Only when the result is a default `Session N` title does it consult the in-memory memo (path → suggestion-or-NONE, never persisted, capped at 256) or schedule the async suggestion.
  - One in-flight request per session, tagged with the cwd it was issued for: a repeat report of the same cwd does not restart it; a different cwd, a user rename, or session removal cancels it.
  - `applySuggestedName` re-validates everything when the model answers: session still exists, `titleOverride` still false, still single-pane, anchor cwd unchanged, and title still default (no newer resolution superseded). It never writes `nameCache` and never sets `titleOverride`.
- `BattyApp.applicationDidFinishLaunching` wires `FoundationModelsNameSuggester.makeIfAvailable()` into `AppStateStore.shared`.
- Observation rules: the title write happens from event-origin code only — the libghostty pwd delegate (synchronous deterministic write, unchanged) and a store-owned `Task` with explicit ownership, cancellation, and stale-result checks, exactly the sanctioned async shape in `docs/swiftui-observation-rules.md`. No view-update-path writes, no Task-hop of an illegal write.

## Gotchas

- **The live FoundationModels path needs manual sign-off.** Unit tests exercise the gating/staleness/sanitizer logic through a mock; the real on-device model call (`FoundationModelsNameSuggester`) cannot run in tests. This machine runs macOS 26.4, so a manual check is possible: cd a fresh session into a markerless folder (e.g. `~/Documents/meeting notes 2026`) and confirm a sensible 2-4 word title appears, and that a junk path stays `Session N`. Whether Apple Intelligence is enabled/downloaded on a given machine determines if the step activates at all — when unavailable it logs "system language model unavailable" and behaves exactly as before. Marked `resolved`, not `closed`, pending that visual verification.
- There is no workspace.json persistence of session titles today — the only persisted name store is `SessionNameCache`, so "AI names must not survive relaunch" reduces to never writing that cache (tested: `persistenceRoundTripReResolvesInsteadOfRestoringAITitle`). If Workspace persistence later serializes `SessionRuntime.title`, it must re-resolve on restore rather than trusting the stored title, or AI names will start sticking.
- `nameSuggestionMemo` is `[String: String?]`; plain subscript assignment of `nil` would delete the key instead of memoizing NONE — `updateValue(_:forKey:)` is load-bearing there.
- ld's automatic weak linking (driven by the SDK's availability info vs the deployment target) is what makes `import FoundationModels` safe in a `.macOS(.v15)` SwiftPM target — no `unsafeFlags`/`-weak_framework` needed, but keep every use behind `#available(macOS 26.0, *)` and avoid stored properties of FoundationModels types.
