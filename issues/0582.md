# 0582 — A downloading Background Sets image shows a busy row and a Cancel button under its thumbnail, where the user wants only a spinner on the thumbnail, cancelled by clicking it again

| | |
|---|---|
| **Status** | open |
| **Module** | Settings / Theme |
| **Platform** | macOS |
| **First seen** | 2026-11-11 |

## Description

When you click a Background Sets image in a **Choose…** sheet, its cell adds a row under the title with a small spinner and a **Cancel** button while the full-size image downloads. The user doesn't want that row. Show the spinner centered over the downloading thumbnail instead, and drop the Cancel button. Clicking that thumbnail again cancels the download. Clicking a different thumbnail cancels the one in flight and starts the new one. Follow-up to [#0576](0576.md).

User report (2026-11-11, verbatim):

> "When I select a background image it shows a busy indicator and cancel button. I don't like that. Just put the busy indicator over the center of the thumbnail. And clicking the thumbnail while it is loading can cancel it. And if the user taps a different background that also cancels it."

## Steps to reproduce

1. Open **Settings → Appearance → Background** and click **Choose…**. A Session's, Pane's or Project's **Choose…** works too.
2. Switch to **Background Sets**.
3. Click an image that isn't downloaded yet.

## Expected behavior

- No status row with a spinner and **Cancel** under the cell while it downloads.
- A spinner centered over the downloading thumbnail. The thumbnail stays visible under it, perhaps dimmed.
- Clicking the downloading thumbnail again cancels the download. The spinner goes, nothing is applied, and the sheet stays open with the current background unchanged.
- Clicking a different thumbnail while one downloads cancels that download and starts the new one. Only the new image is applied when it finishes. This already works today (see Notes); keep it.
- The other status lines stay as they are: "In use", "Available offline" and a failure's reason.

## Actual behavior

Checked on `main` at `3b78562`:

- `BattyKit/Sources/BattyKit/Views/BackgroundSetsView.swift:166-176`: `HostedBackgroundCell.status`, for `hosted.fetches[key] == .fetching`, shows an `HStack` holding `ProgressView().controlSize(.small)` and `Button("Cancel") { hosted.cancelFetch(key) }`. The HStack's identifier is `background-sets.cell.<stem>.progress` and the button's is `background-sets.cell.<stem>.cancel`. It sits under the title (line 153), not on the thumbnail.
- The thumbnail's overlay (`picture`, lines 198-211) shows a spinner only while the *thumbnail* loads (`thumbnail == nil`, line 204). It shows nothing while the full-size image downloads.
- A click (`BackgroundSetsView.click`, lines 118-122) sets `selected` and calls `hosted.pick(image) { onPick($0) }`. Clicking the same downloading image again goes through `HostedBackgroundsModel.pick` (`BattyKit/Sources/BattyKit/Model/HostedBackgroundsModel.swift:253-273`). Its key matches `pendingPick`, so it joins the running fetch and doesn't cancel it (`select`, line 181, returns the running task). Today a second click does nothing you can see.

## Notes

**Premise check: downloads happen only in Choose… sheets.** The report says "select", and the Background Images window (**File → Background Images…**) also shows Background Sets. There, `onPick` is nil (`BackgroundSetsView.swift:12-13`, and `pickHandler` in `BackgroundImagesView.swift:199-200` returns nil outside `.pick` mode). A click only highlights the cell and fetches nothing. So the busy row appears only in a **Choose…** sheet (`TerminalBackgroundControls.swift:65-77` presents `BackgroundImagesView` in `.pick` mode). Clicking a thumbnail to cancel only matters there. In the window, a click goes on only selecting.

**Cancellation is already supported.**
- `HostedBackgroundsModel.cancelFetch(_:)` (lines 234-239) cancels the key's running `Task`. If the fetch is still queued for one of the two slots (`maxConcurrentFetches`, line 56), it also takes it out of `fetchWaiters`.
- The cancel reaches the network: `URLSessionBackgroundCatalogFetcher` wraps the data task in `withTaskCancellationHandler` (lines 61-69) and cancels it.
- `runSelect` (lines 218-231) treats `.fetch(.cancelled)` as a quiet cancel, clearing the cell's state with no failure message.
- `HostedImageStore.fetch` downloads into a per-fetch temporary folder that a `defer` removes (`HostedImageStore.swift:113-115`), so a cancelled download leaves no partial file.
- Unit tests cover all this: `cancelledSelectClearsTheStateAndKeepsNothing`, `cancellingAQueuedFetchLeavesTheQueueAndClearsItsCell` and `repickingAnImageRightAfterItsFetchWasCancelledFetchesItAgain` in `BattyKit/Tests/BattyKitTests/HostedBackgroundsModelTests.swift`.

**A pick that supersedes another is already handled.** Picking a different image calls `releasePendingPick()` (line 259). That cancels the earlier pick's fetch when the pick started it (`ownsFetch`), and bumps `pickGeneration`, so the earlier pick's `onPicked` never runs. If the pick joined a fetch something else started, that fetch keeps running, but its result still isn't applied. Tests: `aLaterHostedPickWinsOverAnEarlierOneThatFinishesAfterIt`, `aCachedHostedPickSupersedesAnEarlierDownload`, `aPickOfADifferentImageStillCancelsTheFetchItStarted` and `aPickJoiningAnotherFetchOfTheSameImageNeverCancelsIt`. A **My Images** pick, **Add from File…**, the sheet's **Cancel** and dismissing the sheet call `supersedePicks()` (`BackgroundImagesView.swift:87, 218, 291, 300`). So the third expected behavior needs no model change, only a check that it still holds.

**What's new is the same-image click.**
- Today a second `pick` of the downloading key joins the fetch. Now a click on a cell whose key is `.fetching` should cancel it: something like `cancelFetch(key)` plus `supersedePicks()`, so the pending pick never delivers. A click on a cell that isn't fetching picks as before.
- The view can tell from `hosted.fetches[key]`, which it already reads.
- Decide what happens to the `selected` highlight on a cancelling click.
- Keep the joined-fetch rule: cancelling a fetch this sheet didn't start, such as one in another open sheet, would stop it for both. `releasePendingPick`'s `ownsFetch` guard already encodes that. A click that cancels probably goes through a model method that respects it, not a raw `cancelFetch`.
- Make sure a third click (pick, cancel, pick) starts a fresh fetch. `select`'s cancelled-task path (lines 180-187) already waits for the cancelled task to unwind.

**View rules.** The new click path writes observed state (`fetches`) from a tap, an event origin, so it's routine under `docs/swiftui-observation-rules.md`. The spinner overlay must not take the cell's tap (`.onTapGesture`, `BackgroundSetsView.swift:110`). Give it `.allowsHitTesting(false)` or put it inside the same tappable shape.

**Accessibility identifiers.** No UI test uses `background-sets.cell.<stem>.progress` or `.cancel` (grepped `BattyUITests` and `BattyKit/Tests` on 2026-11-11). Keep `.progress` on the new overlay spinner so a test can find it, and drop `.cancel`. A UI test for click-to-cancel would need the fixture fetcher to hold a download.
