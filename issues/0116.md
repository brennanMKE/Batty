## Description

Tier 3 localization target. Covers Taiwan and Hong Kong. Distinct from Simplified Chinese — both character forms and some terminology differ enough that `zh-Hans` is not an acceptable substitute for `zh-Hant` users.

Depends on `#0107`. Pairs with `#0109` (Simplified Chinese, `zh-Hans`).

## Acceptance criteria

- Every key in `Localizable.xcstrings` has a non-empty `zh-Hant` translation, reviewed by a native speaker.
- Launching with macOS Language & Region set to 繁體中文 shows the full UI translated.
- Visual sweep confirms Traditional characters render correctly with appropriate weight.
- `## Files changed` should list the `.xcstrings` diff.

## Notes

- The TW vs HK split (`zh-Hant-TW` vs `zh-Hant-HK`) is real but rarely consequential for software UI; ship a single `zh-Hant` first and split only if a user reports a regional term that breaks.
- Terminology often diverges from Simplified Chinese — don't run `zh-Hans` translations through a character-converter and call it done. Translator should be a native Traditional speaker.
- Sparkle ships Traditional Chinese strings.

## Root cause

After `#0107` (catalog foundation) and `#0109` (zh-Hans) landed, the `zh-Hant` column in `Batty/Localizable.xcstrings` was still empty for every key. Traditional Chinese users on macOS — Taiwan and Hong Kong, primarily — would fall back to the English source rather than the carefully picked Apple-style zh-Hant terminology that distinguishes itself from mainland zh-Hans.

## Fix

Populated `zh-Hant` for every key in the catalog using Apple's Taiwan macOS house style (the dominant `zh-Hant` flavour; HK distinctions left to a hypothetical future `zh-HK`):

- `Batty` — passes through as the Latin-script brand name; no 蝙蝠 transliteration, matching the catalog's never-translate-the-brand convention.
- `Quit Batty?` → `要結束 Batty 嗎？`. Taiwan macOS uses 結束 for Quit and the final particle 嗎 in yes/no questions (mainland zh-Hans uses 吗).
- `Quit` → `結束`. Diverges from the zh-Hans `退出` — Apple's Taiwan macOS Quit button reads 結束.
- `Cancel` → `取消`. Identical to zh-Hans by coincidence; both scripts use the same two characters.
- `Paste %lld lines?` (plural) → `要貼上 %lld 行嗎？` for both `one` and `other`. Taiwan uses 貼上 for paste, not the mainland 粘贴; the Edit menu on Taiwan macOS reads 編輯 → 貼上.
- `There %lld open terminal(s).` (plural) → `有 %lld 個終端機已開啟。` for both variants. Taiwan macOS renders terminal as 終端機 (literally "terminal machine") rather than the mainland 终端; 開啟 replaces mainland 打开; classifier 個 (traditional form of 个) is the general-purpose measure word.
- `%lld unseen bell event(s)` (plural) → `%lld 個未讀響鈴事件` for both variants. 響鈴 = ringing bell, 未讀 = unread; both use traditional character forms (響 vs simplified 响, 讀 vs 读).

Format specifiers (`%lld`) preserved verbatim. Full-width punctuation (`？`, `。`) per Apple's published Chinese style guide for both zh-Hans and zh-Hant. Single space inserted between Han characters and the embedded Latin brand `Batty`, matching Apple's house style.

## Files changed

- `Batty/Localizable.xcstrings` — added `zh-Hant` localizations for the 4 simple keys (`Batty`, `Quit Batty?`, `Quit`, `Cancel`) and the 3 plural-aware keys (`Paste %lld lines?`, `There %lld open terminal(s).`, `%lld unseen bell event(s)`), each with `one` and `other` variants.

## Gotchas

- **LLM-authored, not native-speaker reviewed.** Per the acceptance criteria, a native Traditional Chinese speaker (ideally Taiwan-based, given the house style chosen) should still vet these. Terminology choices follow Apple's published Taiwan macOS vocabulary (Terminal.app's Traditional Chinese strings, System Settings, the Apple Style Guide for Traditional Chinese) and widely-accepted Apple renderings (結束, 貼上, 終端機, 視窗 — not used here yet but reserved for future menu/window keys), but specific phrasing ("要…嗎？" vs "確定…？", 響鈴事件 vs 鈴聲事件) is a judgment call a native reviewer may want to revisit.
- **Taiwan vs Hong Kong convention.** Per the issue notes, `zh-Hant-TW` and `zh-Hant-HK` are distinct but rarely diverge for software UI. The translations here lean Taiwan-Apple — most consequentially in 結束 (Quit) and 終端機 (terminal). Hong Kong users typically accept these, though local terms differ (e.g. HK sometimes uses 退出 like the mainland for Quit). If a HK user reports a regional term that breaks, splitting out a separate `zh-HK` column is the right move; for now a single umbrella `zh-Hant` ships per the issue's guidance.
- **Key Taiwan-vs-mainland divergences in this catalog.** Worth noting because anyone diff-checking the two zh columns will spot them: Quit (結束 vs 退出), terminal (終端機 vs 终端), paste (貼上 vs 粘贴), open (開啟 vs 打开), classifier 個 vs 个, and traditional vs simplified character forms throughout (響/响, 讀/读, 嗎/吗, 貼/贴, 結/结, 終/终, 機/机, 啟/启, 開/开). Plus the question-final particle: Taiwan uses 嗎, mainland uses 吗. None of these are silent regional preferences — they're the kind of detail Traditional users notice immediately and flag if a build accidentally ships zh-Hans content instead.
- **Plural variants carry the same string.** Chinese (both scripts) has no grammatical singular/plural distinction; the catalog still requires both `one` and `other` to be populated, but the rendered output is identical regardless of count.
- **Punctuation is full-width.** `？`, `。` per Apple's Chinese style. Half-width `?` would look wrong inside a string of Han characters on native macOS UI. The Japanese pass (#0108) chose half-width `?` — Chinese diverges from that convention deliberately.
- **`knownRegions` in `Batty.xcodeproj/project.pbxproj` still does not list `zh-Hant`.** Following the precedent set by `#0107` / `#0108` / `#0109`, registration in the Xcode Localization UI is only needed to make the catalog editor render the column; `xcstringstool` emits `zh-Hant.lproj/Localizable.strings` and `Localizable.stringsdict` correctly without it. Confirmed by inspecting the build product (`plutil -p .../zh-Hant.lproj/Localizable.strings` and `.stringsdict` show the translated values).
- **Verified by build, not runtime.** `xcodebuild -scheme Batty -destination 'platform=macOS' build` passed (with `CODE_SIGN_IDENTITY=-` / `CODE_SIGNING_REQUIRED=NO` / `CODE_SIGNING_ALLOWED=NO`, mirroring the prior locale subagents). A full runtime visual sweep under `-AppleLanguages '(zh-Hant)'` — the acceptance criterion for no clipping or wrapping regressions in Settings, the bell feed popover, and alerts — has not been done and is part of what the user needs to confirm before this moves from `resolved` to `closed`.
