## Description

A fired Reminder records a `.reminder` `BellFeedEntry` (`Runtime/AppStateStore+Reminders.swift:313-348`). It shows in the Bell Feed and counts toward `bellFeed.unseenCount`, which turns on `bell.badge`. The user chose **Design D** (`0637/spec.md`, Part 2; `0637/option-D.html`): Reminders get their own toolbar button and popover, and fired Reminders leave the Bell Feed entirely. This issue is the **model and store move** that D needs. The popover is #0640.

This is **step 3 of 4** (sequence table in #0637). It depends on #0637, whose fixed Sidebar glyph this issue rewires, and on #0638, which defines the unread / read / Clear Read concept that fired Reminders now follow.

**Ship constraint:** between this issue and #0640, a fired Reminder is visible in the app only as the Sidebar glyph and the row's accessibility value, plus its System notification. That is acceptable on `main`, but **no release may be cut with #0639 and without #0640**. #0640 is the next issue worked.

## Goal

Fired Reminders live in a list of their own on the store, with the unread / read state from #0638. They record no Bell Feed entry and never light the bell. The System notification looks and behaves exactly as it does today.

## Acceptance criteria

### The fired-Reminder list

- New in-memory, observable store state, for example `firedReminders: [FiredReminder]`, owned by `AppStateStore` (or a small `@Observable` store beside `bellFeed`, following `BellFeedStore`'s aggregate pattern). Each item holds: the Reminder id, Session id, Window id, text (`note`), set time (`createdAt`), due time, fired time, and `read: Bool`. It does not survive a relaunch, like the Feed. Pending Reminders stay on `SessionRuntime.reminder` and are not in this list.
- Stored aggregates, written only when they change: `unreadFiredCount` (or `hasUnreadFired`), and `unreadFiredSessionIDs`, which replaces `bellFeed.dueReminderSessionIDs`.
- A Session has at most one fired item. A new firing on the same Session replaces the older item, so each Session has at most one pending Reminder and one fired Reminder. If the user would rather keep every fired item, see Open question 1.

### Unread / read (the #0638 concept applied)

- A Reminder fires as **unread**, whether or not the Session is selected or muted, as today.
- It becomes **read** on: **Mark All Read** in the list (store API here, button in #0640); selection falling back onto its Session (today's `markSelectedSessionReminderEntriesSeen()`, `Runtime/WindowRuntime.swift:1388-1393`, called from `markActiveTabSeen()` at `:1360`); and a notification Remind Again that is ignored because the Session has a newer pending Reminder (#0633's rule, `AppStateStore+Reminders.swift:81-84`; today that path marks the entry seen through the `defer` at `:76-80`).
- It **leaves the list**, read or unread, on: a visit to its Session (`visitFocusedTab()`, `Runtime/WindowRuntime.swift:1346-1348`; any click, ⌘1–9 or Open Session); **Remind Again** that sets a new Reminder, replacing today's "marks the entry seen and kept" (`AppStateStore+Reminders.swift:67-86`), since the new pending Reminder now shows in Upcoming; **Done** (store API here, buttons in #0640); its Session closing (`Runtime/WindowRuntime.swift:426`); its Window closing (`Runtime/AppStateStore.swift:530`).
- **Clear Read** (store API) removes every read fired Reminder and nothing else. It never touches pending Reminders or the Bell Feed.
- Opening any list marks nothing read.

## Open questions (defaults in place)

1. **More than one fired item per Session?** Default: no. A newer firing on the same Session replaces the older fired item. One pending and one fired per Session keeps the Due list short. The alternative keeps every fired item until visited or cleared.
2. **Does a read fired Reminder keep the Sidebar glyph?** Default: no. Only unread fired Reminders show `alarm.fill`, matching today's `dueReminderSessionIDs` (unseen only). A Session with a read fired Reminder and a pending one shows the `clock`.
3. **Remind Again ignored for a newer pending Reminder: read or untouched?** Default: read, because the user acted on the banner. That keeps today's `defer` behaviour.

## What needs the user's eye

- A fired Reminder no longer badges the bell or adds a Bell Feed row. The notification (title, subtitle, body, Open Session, Remind Again) looks unchanged.
- Clicking a fired Reminder's notification selects its Session and leaves the focused Pane and Tab as they were.
