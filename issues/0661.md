## Description

Child of #0660. An agent has no single, quiet way to learn "you are in Batty, in this Session, Tab and Pane, and here is how to drive it". Add `batty agent context`: it reads `BATTY_SESSION_ID`, `BATTY_TAB_ID` and `BATTY_PANE_ID` and prints a short note for an agent. It prints nothing and exits 0 outside Batty. The same text builder is reused by the MCP `instructions` (#0662) and the Claude Code SessionStart hook (#0663), so the three never drift.

### Current state

- `batty id` (`BattyKit/Sources/batty/IDCommand.swift:24-35`) prints `session …`/`pane …`/`tab …` or JSON, and outside Batty writes an error to stderr and exits 1. That is right for a script and wrong for a hook, which runs in every session and must stay silent outside Batty.
- The parsing already exists: `BattyContextEnvironment.lookup` returns `.absent`, `.malformed` or `.value(UUID)` per variable (`BattyKit/Sources/BattyCLICore/BattyContextEnvironment.swift:29-40`), and `BattyIdentityContext.resolve()` builds the triple.
- The only agent-facing prose is the project snippet (`ProjectAgentSnippet.block`, `BattyKit/Sources/BattyCLICore/ProjectAgentSnippet.swift:11-22`) and the static MCP instructions (`BattyKit/Sources/batty/MCPServer.swift:72-77`).
- `agent` has one verb, `install` (`BattyKit/Sources/batty/AgentCommand.swift:13`), behind `agentIntegration`.

## Plan

Planned 2026-11-18 against `main` at `b9911b66`. Premises checked: `IDCommand.run` exits 1 outside Batty (`IDCommand.swift:24-35`); `BattyContextEnvironment.lookup` treats an empty string as `.absent` (`BattyContextEnvironment.swift:37-38`); `BattyIdentityContext.resolve(from:)` reports malformed before missing; `ProjectAgentSnippet.block` holds the four rule lines (`ProjectAgentSnippet.swift:11-22`); `agent` has only `install`, and `AgentNounCommand` is in the tree only with `agentIntegration` (`BattyCLI.swift:31-34`); `MCPToolCatalog.excludedVerbPaths == ["mcp", "agent install"]` (`MCPToolCatalog.swift:49`). `BattyCLICore` has no dependencies, so it cannot read `ServiceNames`; the CLI name is passed in. The Claude Code plugin's MCP server key is `identity.pluginName` (`batty` / `batty-beta`, `AgentGuidanceInstaller.swift:381`), the same string as `ServiceNames.current.cliCommandName`.

### Decisions

1. **Env only, no live details** (open question 1). No XPC: instant, works when the app is not answering, and safe for a hook that runs at every session start. `session_info` gives the title and cwd when an agent wants them.
2. **One pure builder in `BattyCLICore`**, `AgentContextNote`, which owns both the note and the shared rule lines. `ProjectAgentSnippet.block` is built from the same rule lines (with `cliName: "batty"`), so the rules exist once. #0662 composes `AgentContextNote.header(context:cliName:)` + its tool map + `ruleLines(cliName:)`; #0663's hook runs the command; #0664's prompt embeds `ruleLines`. No outside-Batty prose here: #0662 owns that text.
3. **Three outcomes** from `BattyIdentityContext.resolve(from:)`: success → in Batty; `.missing` of all three keys (including all three set to `""`) → silent; anything else (some missing, any malformed) → incomplete: nothing on stdout, one stderr line, exit 0.
4. **`--json` always prints a JSON object on stdout**, even when incomplete (`{"inBatty": false}`), so a JSON consumer always gets something parseable; the incomplete stderr line is printed in that case too. The plain-text outside-Batty case stays fully silent.
5. **The command never throws or exits non-zero from `run()`.** (ArgumentParser still exits 64 on an unknown flag, before `run()`; the hook passes none.)
6. **Annotations archetype `id`** (read-only, idempotent): it is the same kind of env read as `batty id`.
7. **No `--prompt` flag here.** #0664 decides whether it adds one.
8. **"Close what you open" joins the shared rules**, so the project snippet gains that line. `ProjectAgentSnippet.apply` replaces the marked block in place, so existing project files update cleanly on the next `agent install --project`.

### Files

- **Add `BattyKit/Sources/BattyCLICore/AgentContextNote.swift`** — `public nonisolated enum AgentContextNote` (same `nonisolated` discipline as `BattyContextEnvironment`):
  - `static func ruleLines(cliName: String) -> [String]`: the four existing `ProjectAgentSnippet` bullets, with `batty` replaced by `cliName` in commands, plus `- Close the Panes and Sessions you open when you are done with them.` Each line starts `- `.
  - `static func header(context: BattyIdentityContext, cliName: String) -> String`: for example

    ```
    You are running in a terminal Pane of Batty, a macOS terminal multiplexer.
    Session: <uuid>
    Tab: <uuid>
    Pane: <uuid>
    Drive Batty with the `<cliName>` MCP tools when they are available, otherwise the `<cliName>` CLI (run `<cliName> capabilities` first). Tools and commands given no Session, Tab or Pane act on this Pane.
    ```

  - `static func text(context:cliName:) -> String`: `header` + blank line + `ruleLines` joined by `\n`, no trailing newline. Keep it under 1,200 characters with `batty-beta` (#0662 must fit its tool map under ~1,500).
  - `public enum Resolution: Equatable, Sendable { case inBatty(BattyIdentityContext), notInBatty, incomplete(String) }` and `static func resolve(environment: [String: String]) -> Resolution` (no default argument, so tests can never read the runner's environment by accident; the command passes `ProcessInfo.processInfo.environment`). `incomplete` carries `ResolutionError.description`.

## Expected behavior

- `batty agent context` with all three variables valid prints a few lines, for example: you are in a terminal Pane of Batty; Session, Tab and Pane ids; the CLI name for this variant (`batty` or `batty-beta`); that the `batty` MCP tools (or the CLI) default to this Pane; the short rules already in `ProjectAgentSnippet` (status views in Panes, dev servers through `server start`/`attach`, no browser, `notify` for attention, close what you open).
- With no `BATTY_*` variables: prints nothing, exits 0.
- With some missing or malformed: prints nothing to stdout, one line to stderr, exits 0 (a hook must never fail the agent's session start).
- `--json` prints `{"inBatty": true, "sessionID": …, "tabID": …, "paneID": …, "cli": "batty-beta", "note": "…"}`, or `{"inBatty": false}`.
- The text comes from one `BattyCLICore` builder (for example `AgentContextNote.text(context:cliName:)`), pure and unit-tested; `ProjectAgentSnippet`'s rule lines move into or are shared with it so the rules exist once.
- It reads the environment only: no XPC, so it is instant and works even when the app is not answering.
- Listed in `batty capabilities` with an `inputSchema`; excluded from MCP tools like `agent install` (`MCPToolCatalog.excludedVerbPaths`), since #0662 carries the same text in `instructions`.

Capabilities archetype `id`; excluded from MCP tools. Docs updated per the plan. No deviations from the plan.
