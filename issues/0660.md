## Description

**Umbrella, 1.5.0 milestone ("Batty knows it's Batty").** An AI agent started in a Batty Pane should find out, with no manual steps (or one clear prompt the first time), that it is running inside Batty, which Session, Tab and Pane it is in, and that it can drive Batty through the `batty` MCP tools, which default to its own Pane. With that it can use Batty's existing views (status Panes, Server Pane, Web Preview Pane) and open terminal Panes and Tabs that run commands, and learn how those commands ended. No code ships on this issue; the work lands in the children below.

User's direction, 2026-11-18: "Work on a plan to streamline using an MCP that runs the CLI too automatically once the agent can detect it is running in the Batty app. It has the 3 variables which can place it as well. That should be sufficient to leverage the existing views and even run terminal windows which run commands. File new issues into a new milestone. This will become the 1.5.0 release. Other changes we are making will become 1.4.1."

This builds on #0646 (resolved: `batty mcp`, `batty agent install`, Server Pane, `server serve`/`preview`), which is Beta-only today and is retargeted to 1.5.0 with #0647, #0648, #0649, #0657 and #0658.

### Where things stand (checked against `main` at `ae801921`)

- **The three variables exist.** Every Tab's process gets `BATTY_TAB_ID`, `BATTY_PANE_ID` and `BATTY_SESSION_ID` through libghostty's `env` config directive (`BattyKit/Sources/BattyKit/Runtime/TabRuntime.swift:471-476`). `batty id` prints them from the environment alone (#0281).
- **MCP targets already default to the caller.** `batty mcp` runs each tool by re-executing the `batty` binary, and "the child inherits the server's environment (the Pane's `BATTY_*`) and cwd" (`BattyKit/Sources/batty/MCPToolRunner.swift:16-18`), so the CLI's flag → env → focused-element resolution (`BattyTargetResolver`) applies. This holds only if the agent host passes its own environment to the MCP server it spawns (see #0665 for Codex).
- **The MCP server is registered only by hand.** It exists after the user runs `batty agent install` or Settings → Advanced → AI Agents (`AgentGuidanceInstaller.plan`, `BattyKit/Sources/BattyCLICore/AgentGuidanceInstaller.swift:231-297`; `AgentIntegrationModel.beginInstall`/`confirmInstall`, `BattyKit/Sources/BattyKit/Settings/AgentIntegrationModel.swift:58-76`). Nothing offers it, and nothing refreshes it after an app update.
- **Everything agent-related is Beta-only.** `agentIntegration` gates `mcp`, `agent` and the AI Agents Settings section; `serverPane` gates the `server` noun and both new Pane kinds (`BattyKit/Sources/BattyXPCCore/FeatureFlags.swift:40,51`; `BattyKit/Sources/batty/BattyCLI.swift:29-35`; `docs/feature-flags.md`).
- **The agent is told "may be".** `MCPServer.instructions` (`BattyKit/Sources/batty/MCPServer.swift:72-77`) says "You may be running inside Batty", whatever the environment holds.
- **No global note.** `agent install` writes a marked Batty block only into a project file with `--project` (`ProjectAgentSnippet`, `BattyKit/Sources/BattyCLICore/ProjectAgentSnippet.swift`). The user wrote global `## Batty` sections by hand on 2026-11-18 in `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md` and `~/.config/opencode/AGENTS.md`, without markers.
- **No SessionStart hook.** The staged Claude Code plugin has `plugin.json`, `.mcp.json` and the skill, and no `hooks/` (`AgentGuidanceInstaller.stageMarketplace`, `AgentGuidanceInstaller.swift:358-386`).
- **Commands in Panes.** `pane split -c <cmd>` runs a command in a new terminal Pane in place of the shell and holds the Pane open after it exits (`wait-after-command`, `TabRuntime.swift:429-458`). It prints only the new Pane id (`BattyKit/Sources/batty/PaneCommand.swift:193`). There is no `tab new` (`TabCommand.swift:17` has only `focus`), no exit status, and no way to wait.

### Existing views are already covered

The MCP tool list is built from `batty capabilities` (`MCPToolCatalog`), so `pane_split` with `view` (git-status, process-status, system-metrics, lm-studio-dashboard), `server_start`/`attach`/`serve`/`preview`/`stop`/`restart`, `notify`, `session_remind`, `project_open` and the rest are tools already. No child adds view coverage; #0662 makes the instructions name which tool shows which view, and #0669/#0670 make them reach Prod.

### Decision: reading a terminal Pane's output is out of scope for 1.5.0

`docs/batty-cli-design.md` lists `batty read` under "Advanced / automation (adopt only if the workflow demands)", not under "Deliberately skip". It is still not filed here. An agent that needs a command's output runs that command in its own shell. Panes it opens are for the user to watch. The completion signal an agent does need, the exit status, is #0668. Revisit `read` only if real use shows agents need the scrollback of a Pane the user is watching. #0671 records this decision in `docs/batty-cli-design.md` and the agent docs.

## Acceptance criteria

This umbrella can be resolved only when every child is resolved, and:

1. In **Prod** Batty 1.5.0, after one prompt (or one `batty agent install`), a fresh Claude Code, Codex or OpenCode session started in a Batty Pane, in a project that has never mentioned Batty, states that it is in Batty with the right Session, Tab and Pane ids, without running `env` itself, and can call the `batty` MCP tools.
2. An MCP tool call with no target arguments acts on the caller's own Pane in all three hosts.
3. The same agent outside Batty gets no Batty note (the hook and the instructions say nothing, or say it is not in Batty), and the global note tells it to ignore the section.
4. Through MCP the agent can open a terminal Pane or Tab that runs a command, get its Pane and Tab ids back, and, when it asks to wait, the command's exit status.
5. Re-running the installer (or the app updating) replaces Batty's marked blocks and entries in place, never duplicating them, and keeps every byte outside the markers.
6. `docs/feature-flags.md` lists neither `agentIntegration` nor `serverPane` under "Current flags".

## Open questions for the user

Each child lists its own with a recommended default. The ones that shape the milestone:

1. **Automatic means one prompt, not silent writes.** Recommended: Batty offers setup once (first launch of 1.5.0, or when it first sees an agent host), and after an update silently refreshes only what the user already installed (#0666). It never edits an agent's config without that first yes.
2. **New grammar.** `agent context` (#0661), `tab new` (#0667) and `--wait` on `pane split -c` / `tab new -c` (#0668) extend the noun set approved in `docs/batty-cli-design.md` §1.1. Recommended: approve all three; none adds a noun.
3. **`batty read` stays deferred** (decision above). Recommended: agree.
