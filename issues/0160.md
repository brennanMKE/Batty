# 0160 — UI test suite: tab and session rename / reset / title override

|---|---|
| **Status** | open |

## Description

Title-override paths (tab rename, session rename, Reset Title, Reset Name) have regressed repeatedly and are *currently broken* on the tab side — [[0157]] reports that the Rename Tab sheet accepts input, dismisses, and the chip silently keeps showing the shell title. This is exactly the class of bug a UI test would have caught in seconds. This suite locks in title-override semantics for both tabs and sessions.

## Regressions this suite would have caught

- [[0157]] (currently open) — Rename Tab no longer updates the chip title. A test typing into the rename sheet and asserting the chip identifier becomes `tab-chip.<new-name>` would have failed on the first run after the regression landed.
- [[0153]] — No way to clear a session's manually-set name (Reset Name was disabled in the wrong context). A test invoking Reset Name from the sidebar context menu and asserting the session title returns to the resolver-derived name would have caught it.
- [[0142]] — Tab at home directory always shows "~", ignoring any set name. A test renaming a home-dir tab and asserting the override wins would have failed.
- [[0089]] — Auto-naming sessions and tabs from project artifacts. Tests around resolver + override interaction would document the expected precedence and catch ordering bugs.
- [[0058]] — Remember session names per working directory. A test creating a session in a known cwd, renaming it, closing it, reopening at the same cwd, and asserting the saved name auto-applies would catch cache regressions.
- [[0043]] — Sidebar session row overwriting user-set name with live terminal title. A test setting a session name and then sending a long shell title via OSC 1 would catch overwrite-on-update regressions.
- [[0050]] — Tab chips all showed the same shell `user@host` string. A test creating three tabs with different `cd` cwds and asserting unique chip identifiers would have caught it.

## Test cases

All tests use the driver from [[0158]] for setup; assertions read accessibility identifiers and values.

### Tab rename — would catch [[0157]]

- **Context-menu Rename → chip title updates immediately.** Use `renameActiveTab(to: "MyTab")` driver intent (mirrors the sheet's `onCommit`). Assert `tab-chip.MyTab` exists within 1 second; assert prior `tab-chip.<shell-title>` no longer exists.
- **Override survives shell title changes.** After rename, send an OSC 1 title change via the terminal. Assert chip identifier stays `tab-chip.MyTab`.
- **Reset Title clears the override.** Use `resetActiveTabTitle` intent. Assert chip identifier returns to `tab-chip.<shell-title>`.
- **Empty rename collapses to no-op (or clears, depending on spec).** Document the chosen behavior in the test name; test it.

### Session rename — would catch [[0043]], [[0153]]

- **Sidebar rename updates the row identifier.** `renameSession(from: "Session 1", to: "Work")` intent. Assert `session-row.Work` exists; `session-row.Session 1` does not.
- **Reset Name returns to resolver-derived title.** Open a session in a directory with a `project.json` or git remote (driver can stage a temp directory). Rename, then Reset Name. Assert the title returns to the resolver output (not the original "Session N").
- **Reset Name in home directory falls back to dir basename.** [[0153]]'s landed fix. Open a session in `$HOME`. Rename and Reset Name. Assert it falls back to basename (`brennan` for `/Users/brennan`), not the literal "~".
- **Shell title cannot overwrite user-set name.** Set a session name. Send a long OSC 1 title from the shell. Assert the sidebar still shows the user-set name. Regression test for [[0043]].

### Per-tab title independence — would catch [[0050]]

- **Three tabs with three different cwds get three different chip titles.** Driver: create tab 1, `cd /tmp`, create tab 2, `cd /var`, create tab 3, `cd ~`. Assert three unique chip identifiers exist (none collide).

### Home-directory tab override — would catch [[0142]]

- **Rename a home-dir tab beats the "~" formatter.** Create a tab at `$HOME`. Rename to "Home". Assert `tab-chip.Home` exists; `tab-chip.~` does not.

### Name cache — would catch [[0058]]

- **Name auto-applies after session close + reopen in same cwd.** Open session in `$TMPDIR/proj-test/`, rename to "Proj", close session. Open a new session in `$TMPDIR/proj-test/`. Assert the new session's title is "Proj" (cache hit), not "Session N".

## Accessibility identifiers / values needed

Most already exist. To add:

- `tab-chip-title-source` accessibility value on `tab-chip.<title>` set to `"override"` / `"shell"` / `"resolver"` so tests can assert *why* a given title is displayed (not just that it matches). Useful for the override-vs-fallback assertions.
- `session-row-title-source` analogous accessibility value on `session-row.<title>`.

These are diagnostic-grade identifiers — they add no production behavior, only test-readability.

## Driver intents needed (from [[0158]])

- `renameActiveTab(to:)`
- `resetActiveTabTitle`
- `renameSession(from:, to:)`
- `resetSessionName(name:)`
- `setSessionCWD(name:, path:)` — for the cwd-based resolver tests (or use a shell `cd` via the terminal if the resolver only watches the live shell).

## Out of scope

- The fix for [[0157]] itself. This suite includes the test that would have caught it; the fix is a separate issue.
- Localization of titles (covered by the [[0107]]+ localization series).
- Performance of the resolver (no specific regression history).

## Acceptance criteria

- All test cases pass under `xcodebuild -scheme 'Batty (Beta)' -destination 'platform=macOS' test`.
- Each test comment names the regression it covers.
- The currently-failing [[0157]] case is documented as `XCTSkip("blocked on #0157")` or similar so the suite green-lights while [[0157]] is open, and the skip is removed when the fix lands.

## Notes

- Depends on [[0158]] for the driver intents and the cwd setup helpers.
- The OSC 1 send for the override-survival test can use the existing sentinel pattern; the terminal accepts `printf '\033]1;newtitle\007'` from the shell.
