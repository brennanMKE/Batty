## Description

Phase 5 of the #0234 multi-window umbrella: restore the **window set** across relaunch, per `docs/multi-window-design.md` §6. Important scope correction recorded there: workspace persistence was removed in #0172 ("never a planned feature") — there is no `workspace.json` and no `WorkspaceManager`, so this phase restores windows, not session contents. There are no single-window workspace files in the field to migrate.

Scope:

- Window count, frames, displays, and zoom restore via macOS window restoration through the `WindowGroup` scene (#0237); each restored window's presented `WindowID` re-materializes its `WindowRuntime` through the same lazy `windowRuntime(for:)` path New Window uses. No Batty code stores frames.
- Sidebar visibility becomes per-window: `@SceneStorage` replaces the single `SidebarPreference.hiddenKey` read in `Views/RootWindowView.swift`; the first window seeds from the legacy global key so existing users keep their hidden/shown state; the `toggleSidebar` shortcut flips the key window's state.
- Restored windows open with one fresh session each (cwd `$HOME`), matching launch behavior today — sessions/panes/tabs/shells are deliberately not restored (#0172 stands).
- A restored window whose display is gone lands wherever macOS places it (system behavior, not overridden).

## Acceptance criteria

- Quit with N windows on multiple displays → relaunch reopens N windows at their frames (on the original displays when present), each with its own sidebar state and a fresh session.
- Single-window users see today's exact behavior: one window, old frame, fresh `Session 1`, sidebar state preserved (legacy-key seed verified).
- `scripts/build.sh unit` passes; UI suite (including relaunch-shaped tests) passes.

## Resolution notes

> 🟢 Resolved 2026-06-15 — Sidebar visibility is now per-window (`@SceneStorage`, with a one-time legacy-key seed so existing users keep their hidden/shown state); window count/frames/displays restore via macOS window restoration through the #0237 `WindowGroup` scene; restored windows open one fresh session each. The per-window sidebar isolation is verified at runtime by `WindowRestorationTests` (passing).

Frame-level restoration (N windows reopening at exact coordinates) is a macOS window-restoration behavior that only commits on a clean quit, not on the XCTest `terminate()`/SIGKILL cycle — it is verified manually, not by the UI suite. The full UI suite runs in #0240.

## Root cause

Not a bug — Phase 5 of the #0234 umbrella. Per the #0172 scope correction (workspace persistence was removed as "never a planned feature"), there is no `workspace.json`/`WorkspaceManager` and nothing to migrate; this phase restores the *window set* (count/frames/sidebar state), not session contents.

## Fix

Window count/frames/displays/zoom restore for free via the #0237 `WindowGroup(for: WindowID.self)` scene — macOS encodes each window's `WindowID` in restoration state and re-presents it on relaunch, re-materializing the `WindowRuntime` through the same lazy `windowRuntime(for:)` path New Window uses; no Batty frame code. Per-window sidebar visibility: `RootWindowView` replaced its global `@AppStorage(SidebarPreference.hiddenKey)` with `@SceneStorage`, so each window persists and restores its own sidebar state. A one-time migration (`@AppStorage` `migratedKey` flag) seeds the first window's `@SceneStorage` from the legacy global key on first launch after update, preserving existing users' hidden/shown preference; windows 2+ skip the seed. The `toggleSidebar` shortcut/menu/palette now post a `.battyToggleSidebar` notification that every `RootWindowView` receives but only the key window acts on (gated by `keyWindowRuntime()?.id == windowID`), replacing the old global `UserDefaults` write that would have flipped all windows at once. Restored windows open one fresh `Session 1` (cwd `$HOME`); sessions/panes/tabs are deliberately not restored (#0172 stands).

## Gotchas

- **Per-window sidebar test had to fight XCUI quirks (not a product bug):** the product isolates sidebar state per window correctly. The first UI test failed only because it used a global `app.outlines["session-sidebar"].firstMatch` (resolves to the frontmost window, which after the toggle was the collapsed one) and assumed `app.windows` is z-ordered — it is **creation-ordered** (`boundBy:0` = original, `boundBy:1` = the new/frontmost window). The reliable pattern is a two-step sequential check: assert the frontmost (key) window's sidebar collapsed after Cmd-B, then click the original window forward and assert its sidebar is still expanded. A newly-opened window's sidebar can take several seconds to become accessible to per-window XCUI element queries.
- **Frame restoration isn't UI-testable** via XCUI: `app.terminate()` is SIGKILL, so macOS never writes restoration state. Verify N-windows-reopen-at-frames manually.
- **Menu label regressed to static "Toggle Sidebar"** (was dynamic Show/Hide) because the old dynamic label read the global key; correct per-key-window labeling (via a `FocusedValue`) is carried into #0239's Notes.
