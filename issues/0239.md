## Description

Phase 6 of the #0234 multi-window umbrella: the behaviors that only exist once two windows can be open, per `docs/multi-window-design.md` §8.

Scope:

- **Termination:** the app terminates when the last *content* window closes (Help/Settings don't count) — today's "terminate when the last session closes" generalized. Closing the last session in a window closes that window (`WindowRuntime.onAllSessionsClosed` → close window; the app delegate's terminate hook moves to last-content-window-closed). With one window this composes to exactly the current behavior.
- **Window close with live sessions:** confirm-then-teardown via `NSWindowDelegate.windowShouldClose`, prompting iff any tab in the window reports `terminal.needsConfirmClose`, honoring the existing "Confirm on close with running processes" setting (same contract as `QuitConfirmation`). `QuitConfirmation.shouldQuitOrPrompt` widens to all windows' sessions for Cmd-Q.
- **Bell-feed routing:** `BellFeedEntry.windowID` carries the real owning window's ID (retiring the throwaway `UUID()` defaults in `AppStateStore.recordBellTick`/`recordDesktopNotification`). `jumpToBellEntry` makes the owning window key and front, then runs the existing selection flow on that window's runtime — the canonical flow already specified in `Concepts.md` § Bell Feed. Dead-window entries no-op and are marked seen; bell-state cleanup on window close reuses `cleanUpBellState(forTabIDs:)`.
- `markActiveTabSeen` / `locate(tabID:)`'s `isFocused` gain the key-window term so a bell in a non-key window counts as unseen.

`makeKeyAndOrderFront` is responder-changing AppKit: legal only from event-origin handlers (feed click, notification tap), never from view-update code — `docs/swiftui-observation-rules.md` is binding here.

## Root cause

Not a bug — Phase 6 of the #0234 umbrella, the behaviors that only exist once two windows can coexist. Starting state (#0237/#0238): the app terminated when the last *session* closed in any window (would kill the app on closing window 2's last tab), bell entries used throwaway `UUID()` window IDs, and `releaseHost`/`unregisterNSWindow` (added in #0236/#0237) had no caller.

## Fix

**Termination:** each `WindowRuntime` gets a `closeWindowCallback`; its `onAllSessionsClosed` closes the window rather than terminating the app. `windowWillClose` calls `terminateIfLastContentWindowGone`, guarded by `nsWindowMap.isEmpty && windows.allSatisfy { sessions.isEmpty }`. With one window this composes to exactly today's quit-on-last-session behavior. **Window close:** `NSWindowDelegate.windowShouldClose` prompts via `QuitConfirmation.windowNeedsConfirmClose(window:)` iff a tab in *that* window reports `needsConfirmClose` (honoring the running-process setting); `windowWillClose` tears down in order — bell cleanup → `releaseTerminalView` per tab → `releaseHost(forWindowID:)` (gate now sees all tabs released) → `unregisterNSWindow` → `removeWindow`. `QuitConfirmation.shouldQuitOrPrompt` widens to all windows for Cmd-Q. **Bell routing:** `recordBellTick`/`recordDesktopNotification` drop the throwaway `windowID` and stamp the real owning `window.id`; `jumpToBellEntry` resolves the owner and `makeKeyAndOrderFront`s it (event-origin only) before running the existing selection flow; dead-window entries no-op + mark seen. A bell's `seen` gains a key-window term (`isFocused && isOwnerKey`) so non-key-window bells count unseen, reducing to single-window semantics when no window is registered. **Carried-over #0237 dispatch:** `BattyCommands` and `CommandPaletteView` now route per-window commands through `keyWindowRuntime() ?? windows[0]`.

## Gotchas

- **The termination guard is two-part for a reason.** `nsWindowMap.isEmpty` alone would quit prematurely during a New Window / close-original interleaving where the new NSWindow hasn't registered yet. The second clause `windows.allSatisfy { sessions.isEmpty }` holds because `WindowRuntime.init` seeds `Session 1` when constructed empty — so an appended-but-not-yet-onscreen window already carries a session and blocks termination. Don't "simplify" either clause away.
- **`releaseHost` ordering is load-bearing:** it must run after every `releaseTerminalView` for the window (its #0236 gate waits for zero orphan tab views) and before `unregisterNSWindow` (so the terminate check fires only after full teardown).
- **`makeKeyAndOrderFront` stays event-origin:** it lives in `jumpToBellEntry`, reached only from the bell-feed tap and the system-notification tap. Never call it from `body`/`onChange`/`onAppear`/`updateNSView` — `docs/swiftui-observation-rules.md`.
