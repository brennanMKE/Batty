## Description

`AtlasOwnershipExperimentTests.attachSurface` (`BattyKit/Tests/BattyKitTests/AtlasOwnershipExperimentTests.swift:100`) waits with `RunLoop.main.run(until: Date().addingTimeInterval(0.3))`. It needs the new surface to draw its first frame, which allocates the glyph atlas, before the test counts 1040K `IOAccelerator` regions. `AGENTS.md` "Asynchronous tests" forbids this: a test must await a signal the code emits, not let time pass. Nothing Batty can see today says "this surface has drawn". The signal exists inside libghostty-spm but is internal. The fix needs a small public addition to the GhosttyTerminal Swift wrapper, then a re-pin of `BattyKit/Package.swift`.

#0433 found this site (child of umbrella #0427). #0433's instruction for this row was: "If no such signal exists without libghostty changes, record the finding and file a follow-up rather than inventing one." This is that follow-up.

## Where the frame is drawn

Paths are under `BattyKit/.build/checkouts/libghostty-spm/Sources/GhosttyTerminal/`, at the current pin (`Lakr233/libghostty-spm` @ `a2565ccf`).

- `Surface/TerminalSurfaceCoordinator.swift:473` `tick(context:)` is the only macOS path that calls `surface?.draw()` (`:491`), which is where the atlas gets allocated. `onPostRender?()` runs on the very next line (`:492`).
- `tick` is driven by the display link. `requestImmediateTick()` (`:125`) sets `pendingImmediateTick` and calls `ensureDisplayLink()` (`:590`). That acquires a `DisplayLink`, and its vsync callback calls `tick`. On AppKit, `AppTerminalView+Lifecycle.swift` calls `requestImmediateTick()` from the attach and layout paths (`:72`, `:136`, `:164`, `:170`, `:177`).
- `var onPostRender: (() -> Void)?` (`TerminalSurfaceCoordinator.swift:70`) is internal, like the whole `final class TerminalSurfaceCoordinator` (`:18`). Its only macOS consumer is `Platform/AppKit/AppTerminalView.swift:107`, which uses it to call `enforceMetalLayerScale()`. The UIKit view uses it the same way (`UITerminalView.swift:172`).
- The public `TerminalSurfaceLifecycleDelegate` (`Surface/TerminalSurfaceViewDelegate.swift:257`) reports attach (`terminalDidAttachSurface`, sent from `TerminalSurfaceCoordinator.swift:228`). Attach comes before the first draw, so it does not work as a "drawn" signal. None of the other 17 public `TerminalSurface*Delegate` protocols reports rendering. `TerminalController.tick()` (`Controller/TerminalController.swift:308`) is public but only calls `ghostty_app_tick`. It never draws a surface.

So a test cannot wait on the first draw today, and it cannot trigger one synchronously either.

## Proposal

1. **Add a public first-frame signal to GhosttyTerminal.** Keep it narrow and easy to upstream. One option is a `TerminalSurfaceRenderDelegate` sub-protocol, e.g. `terminalDidDrawFirstFrame()`, sent once per attached surface from `tick(context:)` right after `surface?.draw()`, next to `onPostRender`. `TerminalViewState` would conform and publish it (a counter or flag). Another option is a one-shot `AsyncStream`/callback on the view. It must not change production behaviour, and the per-frame cost must be one boolean check. Do not add a per-frame delegate call.
2. **Land it where `Package.swift` can consume it.** Note: the pin is **not** the `brennanMKE/libghostty-spm` fork that `docs/delegate-plumbing.md` recommends. #0212 moved it to upstream `Lakr233/libghostty-spm`, and #0389/#0397 re-pinned it to `a2565ccf` (`BattyKit/Package.swift:31-32`; `docs/themes.md` also says the package is pinned to upstream, not the fork). So there are two routes. (a) Upstream PR to `Lakr233/libghostty-spm`, then re-pin once a release with a matching xcframework ships. (b) Revive the fork for this change, which brings back the fork-maintenance and binary-asset concerns recorded in #0210/#0212. Choosing between them is a user decision. A re-pin also means re-checking the #0397 lesson: delegate writes to `TerminalViewState` are deferred through `DispatchQueue.main.async`, so the test must await the published value, not read it synchronously after the call.
3. **Migrate `attachSurface`** to await the new signal, bounded as a failure guard only (e.g. a continuation with a timeout that fails the test). Then delete the `RunLoop.main.run(until:)` line.
4. **Fix the helper's doc comment while there.** It says the first tick is scheduled by `TerminalSurfaceCoordinator.scheduleTickIfNeeded` via `DispatchQueue.main.async`. No `scheduleTickIfNeeded` exists at the current pin (grep finds nothing under `Sources/GhosttyTerminal`). The real path is `requestImmediateTick` → `ensureDisplayLink` → display-link vsync → `tick`.

## Expected behavior

`AtlasOwnershipExperimentTests` waits for each surface's first draw through a signal the wrapper emits. No run-loop spin or timed wait remains in the file.

## Actual behavior

Each `attachSurface` call spins the main run loop for a fixed 0.3 s (three calls per test). It hopes the display link fires and `draw()` runs within that window. It adds about 0.9 s per run, and under load it can sample the region count before the atlas exists.

## Notes

- A display-link-driven first draw also needs a window on a real display. The test's borderless, deferred `NSWindow` gets one today (the spin evidently works). The implementer should confirm the new signal actually fires in the headless `./build.sh unit` environment before relying on it. If it does not, record that rather than bringing back a wait.
- Not a candidate for "remove the test": it pins #0287's atlas-ownership finding (see the file's header comment).
