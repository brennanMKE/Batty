# 0549 — Dragging a Session row to reorder the Sidebar has no routine UI test, because the only test that does it runs in demo mode

| | |
|---|---|
| **Status** | open |
| **Module** | Testing / Sidebar |
| **Platform** | macOS |
| **First seen** | 2026-11-04 |

## Description

No UI test in the daily run or the Release-tier suite drags a Session row to reorder the Sidebar. A regression in the drag would ship unnoticed.

The only UI test that does it is `DemoSceneTests/testClip02SessionsAndSidebar`, and `DemoSceneTests` skips unless `BATTY_UI_DEMO=1`. It runs only on request, through demo mode on `tools/run-ui-tests-vm.sh`.

Low severity, and not a 1.3.5 blocker. Nothing is broken today: #0547's review ran that test in demo mode (VM run `20261104-002928-77218`) and the drag worked.

## Expected behavior

A UI test that runs without demo mode, and so in the daily run and the Release-tier suite, drags one Session row onto another's position and checks the resulting Session order.

## Actual behavior

- `BattyUITests/DemoSceneTests.swift:43` skips the class unless `BATTY_UI_DEMO` is `1`. Line 47 also skips it outside the Tart VM.
- `BattyUITests/DemoSceneTests.swift:369-376` is the only drag of a Session row in `BattyUITests`. The other `press(forDuration:thenDragTo:)` calls drag Pane handles and dividers.
- That test asserts only that the order changed (`XCTAssertNotEqual(before, after, ...)`), not that the row landed where it was dropped.

## Notes

- **What is covered:** unit tests call `WindowRuntime.moveSessions(fromOffsets:toOffset:)` directly (for example `SessionColorOverrideTests.explicitColorSurvivesReorder`), so the model's move is exercised. What's uncovered is the path from the drag to that call: the `.onMove` at `BattyKit/Sources/BattyKit/Views/SessionSidebarView.swift:163`, and whether the row can be dragged at all.
- **Why this can regress unnoticed:** #0547 changed the row's accessibility and added a content shape to it. Its plan and draft assumed the Release-tier suite covered drag reorder, and the review found it doesn't. See `## Gotchas` in `issues/0547.md`.
- `BattyCLI.topology()?.sessions.map(\.name)` is how the demo test reads the order, and a new test could do the same.
