# 0558 — Bells from a muted Session still add unread Bell Feed rows and bump the unseen counters, so muting quiets the banner but not the list

## Description

Muting a Session (Sidebar context menu > Mute Notifications, `SessionRuntime.notificationsMuted`, #0068) suppresses only the macOS banner. Its bells still add unread Bell Feed rows and bump the Tab, Pane and Session unseen counters. `AppStateStore.postNotification` (`BattyKit/Sources/BattyKit/Runtime/AppStateStore.swift:2690`) returns early on `notificationsMuted`, but by then `recordBellTick`, `recordDesktopNotification` or `recordCLINotification` has already called `recordOrCollapse` and `propagateUnseenForced`. This is deliberate and documented. `Help/06-notifications.md` says: "The chip dot, sidebar badge, and bell feed still update — mute affects delivery, not capture." `AppStateStoreNotifyTests.mutedSessionSuppressesTheNotifierPostButStillRecordsTheFeedEntry` locks it in.

The goal, from the user (2026-11-05):

> We should make it our goal to declutter the notification list as much as possible so only what is useful remains.

Split out of [#0555](0555.md), "Further decluttering". The question is whether a muted Session's bells count as "ignored" notifications that shouldn't be listed.

## What the data shows

In the exported decision log (`~/Downloads/batty-bell-decisions-2026-11-05-142840.txt`, 188 records), none has `sessionMuted=true`, so there's no evidence either way of how much clutter mute would remove.

## Recommended default

**Keep today's behavior,** and change it only if the user asks. Mute is the per-Session way to silence banners, and the row and the badge are what's left to show that something happened. Help promises this.

If the user wants muted Sessions out of the list, the plan to follow:

- No Feed row and no counter bump for a muted Session's bells.
- #0297 and #0523 still record them (`suppressed:sessionMuted`).
- Help's mute paragraph, the Settings help row and the test above are updated.
- Unmuting doesn't bring back past bells.

Decide also whether the Sidebar shows any sign of activity from a muted Session. The recommended answer is no.

## Notes

- A muted Session's bell from the focused Tab while Batty is active is already dropped by [#0555](0555.md), which doesn't depend on mute.
- Session Reminders ([#0514](0514.md)) ignore mute by design ("a Reminder is something the user set on purpose"). Whatever this issue decides must leave Reminder rows alone.
