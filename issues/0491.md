## Description

In Batty Beta (Projects flag on), **Open Quickly** (⇧⌘O) is the user's go-to typing path: press the chord, type a few letters, press Return. It lists the Sessions and Tabs of the key Window and nothing else, so typing a saved Project's name offers nothing unless that Project already has a Session in this Window. To open a Project by typing its name today the user must switch to the Command Palette (⇧⌘P) and find its "Open Project: <name>" row (#0475), or go through File ▸ Open Project ▸ Choose Project… and the picker's filter field.

The user's words (2026-10-12): "We have an Open Quickly feature. This should include project names so someone can use Open Quickly to type their project name to open one that way as well."

This issue adds **Project rows** to Open Quickly, behind the Projects flag. The user types a Project name, presses Return, and the Project opens as a Session (or its open Session is focused), through the same path the picker uses. It ships with Projects in 1.3.0 on `main`; nothing here exists on `release/1.2`.

## Current code (verified on `main` at `dd9f875b`)

**Open Quickly.** `BattyKit/Sources/BattyKit/Views/OpenQuicklyView.swift`:

- `QuickOpenResult` (`:12-20`) is a `(sessionID, sessionTitle, tabID, tabTitle)` row whose `id` is the Tab id. `OpenQuicklyFilter.allResults(for:)` (`:49-62`) walks **only `windowRuntime.sessions`** (`:50`), so a Session in another Window is never listed, and lists one row per Tab of every `.terminal`-kind Pane (a non-terminal Pane's placeholder Tab is skipped, #0315).
- `OpenQuicklyFilter.apply(query:to:)` (`:27-38`) scores each row as `max(FuzzyMatcher.score(query, sessionTitle), FuzzyMatcher.score(query, tabTitle))`, drops zeros, and sorts by score descending. `FuzzyMatcher.score` (`Util/FuzzyMatcher.swift:24-32`) is 3 for a case-insensitive prefix, 2 for a contiguous interior match, 1 for a scattered subsequence, 0 for no match. An empty query returns every row in its original order (`:28`). Equal scores have no tie-break beyond `sorted`'s behavior.
- `OpenQuicklyView` (`:65-151`) is a 540×380 sheet with a `TextField("Jump to session or tab…")` (`:87`) focused in `onAppear` (`:135`), ↑/↓ wrapping through the list (`moveSelection`, `:138-142`), Return calling `activate` (`:92`), Escape dismissing (`:93`), and a tap on a row activating it (`:114-117`). `activate` (`:144-150`) sets `isPresented = false` and then **immediately** calls `windowRuntime.jumpToTab(sessionID:tabID:)` (`Runtime/WindowRuntime.swift:956-988`), which selects the Session, focuses the Pane and activates the Tab in this Window. Rows are `QuickOpenRow` (`:153-176`), text only: `Session › Tab` with a `chevron.right`.
- Accessibility identifiers in code: `open-quickly.root` (`:134`) and `open-quickly.row` on every row (`:119`). The `TextField` has none. `docs/ui-features.md:535-536` claims `open-quickly.filter-field` and `open-quickly.row.<target>`; neither exists in the code, and `BattyUITests/FuzzyFinderTests.swift:164-169` counts rows by the real identifier `open-quickly.row` with a floor of 3.

**How it is presented.** It is a `.sheet` on `SessionDetailView` (`Views/SessionDetailView.swift:86-88`), toggled by `.battyToggleOpenQuickly` (declared `OpenQuicklyView.swift:7`) in an `onReceive` guarded by `isKeyWindow` (`:48-51`, `:299-301`, the #0242 fan-out guard). **How it differs from the Command Palette.** The palette (`CommandPaletteView.swift`) lists app *actions* by title; `CommandPaletteFilter` (`:24-38`) scores titles only. ## Steps to reproduce

1. Launch Batty Beta with a Project named "Beta Duo" in `projects.json` and no Session opened from it.
2. Press ⇧⌘O and type `beta`.
3. Observe "No Results" (or only unrelated Sessions). Press Return: nothing opens.
4. Press ⇧⌘P and type `beta`: the palette lists "Open Project: Beta Duo". That is the only typed path to the Project today.

## Expected behavior

### 1. Project rows

With the flag on, Open Quickly lists **one row per saved Project**, in addition to the Session/Tab rows it lists today. A Project row shows:

- the Project's **symbol**, tinted in the Project's `SessionColor`: `ProjectSymbol.resolvedSystemName` once #0482 has landed, otherwise `folder.fill`. Route the lookup through one small function so #0482 (or this issue, whichever lands second) swaps it in one place;
- the Project **name** as the primary text, with a secondary "Project" caption or the same `Session › Tab` typography the existing rows use, so a Project row and a Session row with the same name are told apart at a glance;
- the **root path**, abbreviated with `~` through `ProjectPickerModel.abbreviate(path:homeDirectory:)` (`ProjectPicker.swift:165-171`), as secondary text with middle truncation;
- an **OPEN** marker, drawn like the picker's badge, when `openProjectIDs` contains the Project (a Session in *any* Window), consistent with the picker card and the File-menu check mark.

Session/Tab rows are unchanged. When a Project row is selected, a one-line footer shows the picker's hint text (`ProjectPickerModel.hint` wording: "↩ Open <name> in a new Session" / "↩ Switch to the open <name> Session") followed by "⌥↩ Open another copy". The footer is absent while a Session/Tab row is selected, so the existing layout is untouched for users without Projects. The sheet's data is read live from the store on every render, the way the picker does it (`ProjectPickerView.swift:25-26`, `:42-45`), so the OPEN marker follows opens and closes while the sheet is up.

### 2. Choosing a row

- **Return or a click on a Project row** opens it with `.focusExistingOrOpen`. **Option-Return on a Project row** opens it with `.openNew` ("Open another copy"), exactly as the picker does (`ProjectPickerModel.openAction(optionHeld:)`, `ProjectPicker.swift:131-134`). Open Quickly's Return handler changes from `.onKeyPress(.return)` (`OpenQuicklyView.swift:92`) to the `keys:phases:` form the picker uses (`ProjectPickerView.swift:92-97`) so it can read the Option modifier. Option-Return on a Session/Tab row behaves like Return (there is no second copy of a Tab). Verify in the VM that Option-Return in the filter field inserts no newline, as `docs/ui-features.md:788-789` has the picker verify.
- **The open goes through the picker's path and runs after the sheet has closed.** `OpenQuicklyView` only *reports* the choice: it hands an `OpenQuicklyAction` value (`.openProject(UUID, AppStateStore.ProjectOpenMode)`) to its host through a closure and sets `isPresented = false`. `SessionDetailView` stores it in `@State` (as `afterProjectPicker` is stored at `SessionDetailView.swift:18`), adds `onDismiss:` to the Open Quickly sheet (`:86-88`), and in that `onDismiss` calls `ProjectOpenPresenter.open(id:mode:in: store)` (`ProjectOpenPresenter.swift:18-29`). This is the binding onDismiss rule (`docs/swiftui-observation-rules.md:179-186`): a sheet's `onDismiss` is the completion signal, so the startup-command trust sheet, which presents from the same `SessionDetailView` (`startupTrustBinding`, `:329-339`), never competes with a sheet that is still closing. **It is routed to this Window directly, as a value**, never by posting a notification that a key-window-gated `onReceive` must accept: #0483 is the record of what that costs (the palette's "Open Project…" post is dropped from inside `onDismiss`). No `Task`, `DispatchQueue.main.async` or `asyncAfter` hop anywhere on this path.
- Consequences that follow from the shared path and need no new code, but must be asserted: an already-open Project (in this or another Window) has its Session selected and its Window activated (`openProject`'s focus-existing branch, `AppStateStore.swift:1296-1304`); a Project with an unapproved command set shows the trust sheet on this Window after Open Quickly has closed (`requestOpenProject`, `AppStateStore+ProjectStartup.swift:71-92`); a failed open shows `ProjectOpenPresenter`'s alert except for `.cancelled`.
- The existing **Session/Tab jump is unchanged**: `activate` still calls `windowRuntime.jumpToTab` as today. Do not move it into `onDismiss`; nothing follows it that needs the sheet closed, and moving it would change `#0405`'s verified behavior for no reason.

### 3. Matching, ranking and de-duplication

Put the rule in a pure type beside `OpenQuicklyFilter` (for example `OpenQuicklyEntry`, an enum of `.tab(QuickOpenResult)` and `.project(OpenQuicklyProjectRow)`, and `OpenQuicklyFilter.apply(query:tabs:projects:)` returning `[OpenQuicklyEntry]`), so it is unit-tested without a view, like `OpenQuicklyFilterTests` (`BattyKit/Tests/BattyKitTests/FuzzyMatcherTests.swift:74` on) and `ProjectPickerModelTests`.

- **Tab rows** score exactly as today (`max` of the Session and Tab scores, `OpenQuicklyView.swift:29-33`).
- **Project rows** match on `FuzzyMatcher.score(query, in: project.name)` (3 / 2 / 1). If the name does not match at all, a case-insensitive substring hit on `rootPath` or its `~` form scores **1**, the same tier as a scattered name match. This is the picker's rule (`ProjectPicker.swift:176-183`) mapped onto Open Quickly's three tiers: a name match always outranks a path-only match, and the path lets `~/Developer/x` reach a Project whose name the user forgot. Project rows never match against the Project's Tab titles or startup commands.
- **Among Project rows, recency orders them, not store order** (user guidance, 2026-10-12: Projects rank by recency of use, adjusted for which are already open). Within one match tier, Project rows are ordered by the **shared recency model that #0492 defines** for the Open Project picker; this issue consumes that model and does not define its own. What this issue fixes about it:
  - the model is a pure function of the Projects, their recency data and `openProjectIDs`, that returns the Projects in rank order (for example `ProjectRecency.ranked(_:openProjectIDs:now:)`), so both surfaces call one function and their unit tests share fixtures;
  - a Project used more recently ranks above one used longer ago, and a Project never opened ranks last among those with the same match tier, in store order;
  - **an already-open Project ranks according to #0492's model, not by a rule of this issue.** Open Quickly passes `openProjectIDs` in and takes the order out. The exact weighting (whether an open Project is pulled to the top because the user is working in it, or pushed below the recently used but closed ones because "open" is already reachable through its Session/Tab rows) is #0492's decision, and this issue's tests pin only that the order Open Quickly shows equals the order the shared function returns for the same inputs;
  - the recency *data* is `Project.lastOpenedAt` (`Model/Project.swift:203`, already decoded and encoded, `:274`, `:295`, and carried through the editor's drafts, `Model/ProjectDraft.swift:39`, `:115`, `Model/ProjectEditorViewModel.swift:716`). **Nothing on `main` writes it**: `openProject` (`AppStateStore.swift:1282-1321`) and `finishOpen` (`AppStateStore+ProjectStartup.swift:137-163`) never touch it. #0492 owns the write (on a successful open, in the store, from the event-origin open path) and its `ProjectsFile` implications; if #0492 has not landed when this issue is worked, this issue uses the shared function as #0492 specifies it and, if the write is still missing, lands it as #0492 describes and says so in the Work log, rather than inventing a second timestamp.
- **Match tier before recency.** Recency orders Projects *within* a tier; it never lifts a path-only match (1) above a name-prefix match (3). Typing the start of a name must reach that Project before a Project whose path merely contains the letters, however recently the latter was used.
- **One ranked list**, not two sections: sort by score descending, so the best match is row 1 whatever its kind, which is the point of "type a name, press Return". **Ties between kinds break Tab rows first, then Project rows**; within Tab rows the existing order, within Project rows the recency order above. Use an explicit tie-break (`ProjectPicker.swift:185`), not `sorted`'s stability.
- **Empty query**: every Tab row in today's order, then every Project row in recency order, so ⇧⌘O followed by ↓ reaches the most recently used Project without typing.
- **De-duplication rule: one row per Project id, always; one row per Tab id, always; neither kind ever suppresses the other.** A Project with an open Session still has its Project row, marked OPEN, next to that Session's Tab rows. Justification:
  1. They are different targets. A Tab row jumps to one Tab in *this* Window (`allResults` lists only `windowRuntime.sessions`, `OpenQuicklyView.swift:50`). The Project row is the only row that can reach a Project's Session in *another* Window (through `openProject`'s focus-existing branch) and the only row that can open another copy (Option-Return). Hiding it when the Project is "open" would silently drop both.
  2. The visible text differs (a Project row carries the symbol, the path and the OPEN marker), so the pair does not read as a duplicate.
  3. The list stays stable as Sessions open and close. A row that disappears because something else happened elsewhere breaks the muscle memory Open Quickly exists for.
  4. The Return outcome is the same either way when the Project is open in this Window: its Session's title is pinned to the Project name (`WindowRuntime.swift:231-233`), so a query that reaches the Project row by name reaches that Session's Tab rows with the same score, the tie puts the Tab row first, and Return lands in that Session. The only difference is that the Tab row also activates the matching Tab, which is the more precise target.
- **Why Tab rows win ties.** Open Quickly's contract is navigation with no side effects. A Project row can create a Session and, through the trust flow, type commands into shells. When a live target and a Project match equally well, the no-side-effect row is the safer default for a user who types two letters and hits Return. The Project row is then row 2, one ↓ away, and its symbol and path make it obvious which is which. When no Session carries the name (the common case for a Project that is not open here), the Project row is row 1 and Return opens it, which is what the user asked for.

## Actual behavior

Open Quickly lists only this Window's Sessions and Tabs. A Project name matches nothing unless a Session with that name is open here. Traced from `OpenQuicklyFilter.allResults(for:)` (`OpenQuicklyView.swift:49-62`), which reads `windowRuntime.sessions` and nothing else; nothing in `OpenQuicklyView` or `SessionDetailView`'s sheet (`SessionDetailView.swift:86-88`) touches `projectStore`, `openProjectIDs` or `ProjectOpenPresenter`.
