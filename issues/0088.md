## Description

Write the **Drag and Drop** section of Batty's user Help: `Batty/Help/08-drag-and-drop.md`. Covers dropping file URLs onto a terminal — a feature called out as required in `PRD.md`.

Depends on `#0080` (Help window bootstrap).

## What `08-drag-and-drop.md` covers

### What you can drop

Files and folders from the Finder, the Open dialog, or any source that produces a file URL.

Drop a single file: its path is shell-quoted (escaping spaces and special characters) and typed into the focused terminal at the cursor position.

Drop multiple files: each path is shell-quoted and joined with spaces, then typed into the terminal as one combined string. The cursor is left after the last path so you can press Return or compose the rest of a command around them.

### How the visual feedback works

When you drag over a terminal pane, the pane's border highlights to confirm it'll accept the drop. Letting go drops the paths. The drag only takes effect on the **active tab in the focused pane**; dropping on a chip or on a non-active tab area doesn't do anything special.

### What it looks like in practice

If you drag `/Users/you/Pictures/My Photo.png` onto the terminal, the inserted text looks like:

```
'/Users/you/Pictures/My Photo.png'
```

If you drag three files at once, you'll see:

```
'/Users/you/file one.txt' '/Users/you/file two.txt' '/Users/you/file three.txt'
```

You can now type a command in front and submit — `cp `, `mv `, `ls -l ` — without typing the paths by hand.

### What doesn't work yet (v1)

- Dropping into a non-active tab's area to bring it to focus before dropping. Switch tabs first.
- Dropping plain text content (only file URLs work).
- Dropping to start a new tab / new pane at the dropped folder's path.
- Inter-tab drag (drag a tab between panes / sessions).

These may land later but are not part of v1.

## Notes

- The feature is implemented in `PaneView.handleFileDrop`. Don't mention that file name — users don't care.
- Reference `ShellQuote.joinPaths` only as "Batty quotes the paths automatically so spaces and special characters work."

## Root cause

Not a bug — a documentation gap. Drag-and-drop was implemented in
`PaneView.handleFileDrop` / `ShellQuote.joinPaths` but the corresponding
user help page was a one-line placeholder stub from `#0080`.

## Fix

Rewrote `Batty/Help/08-drag-and-drop.md` as a user-facing page that
matches the tone of the other help sections. Covers:

- What a user can drop: files and folders from any file-URL source.
- Single-file behavior: path is POSIX-quoted, inserted at the cursor,
  with a trailing space.
- Multi-file behavior: each path is quoted and the set is joined with
  spaces into a single inserted string.
- Visual feedback: an accent-colored border lights up around the
  receiving terminal area as you drag over it.
- Targeting rule: the drop only takes on the active tab in the
  focused pane; other tabs and panes ignore the drag.
- A worked example showing the inserted text for a single file and
  for three files at once.
- The v1 limits (no non-active drop, no plain text, no
  cd-into-folder shortcut, no inter-pane tab drag).

Avoids internal type names per the issue's "Notes" guidance — uses
"Batty quotes the paths automatically" rather than referencing
`ShellQuote.joinPaths`, and never names `PaneView.handleFileDrop`.

- The `~250 words` target in the issue was treated as approximate.
  Sibling help pages (`02-sessions.md`, `03-panes.md`, etc.) all run
  longer (380–540 words); the final draft lands at ~350 to match

  (bootstrapped in `#0080`). No Xcode project changes were needed —
  the `Batty/` group is a `PBXFileSystemSynchronizedRootGroup`, so
  the new content is picked up automatically.
- `xcodebuild -scheme Batty -destination 'platform=macOS' build`
  passes; the change is markdown-only.
