## Description

The user chose **Design D**: "I like design D. It is simple and easy to read. We should have a clear concept for Remdiners and Bell Feed notifications. There are unread, read and then the option to clear all read items." Design D adds a **Reminders** toolbar button, just left of the bell, that opens a popover listing **Due** (fired) and **Upcoming** (pending) Reminders. It also offers New Reminder… and per-row actions. Spec: `0637/spec.md`, Part 2, "What D, E and F share" and "Option D". Mockup: `0637/option-D.html`.

This is **step 4 of 4** (sequence table in #0637). It depends on:

- **#0639**: the fired-Reminder list with unread / read state, and its store API (Mark All Read, Clear Read, Done, Remind Again);
- **#0635**: the Quick Reminder bar must not open over another sheet, because Edit and New Reminder… present the bar from this popover;
- **#0636**: tooltips built from the live binding, a pattern this button copies.

The user has accepted one new toolbar button for this, which relaxes the standing "no new toolbar buttons" rule for this button only.

**Override of the spec.** The spec says fired Reminders have "no seen / unseen state … and there is no Clear All". The user replaced that with the shared concept in #0638: fired Reminders are **unread** or **read**, and the list offers **Clear Read**. Where this issue and the spec disagree, this issue wins.

## Goal

A visible home for Reminders. At a glance the user can see what is due and what is coming, act on either, and set a new one. Fired Reminders follow the same unread / read / Clear Read rules as the Bell Feed.

## Acceptance criteria

### Toolbar button

- `RemindersToolbarButton` gets its own view struct, like `BellFeedToolbarButton` (`Views/SessionDetailView.swift:404-432`), so a Reminder change re-renders only this button. It sits in the same `ToolbarItemGroup` (`:203-233`), immediately left of the bell. The order is Split Horizontally, Split Vertically, Reminders, Bell Feed.
- Glyph, rendered hierarchically. The names are in `Resources/SFSymbolNames.txt:401-412`:

  | State | Symbol | Colour |
  |---|---|---|
  | No pending and no unread fired Reminder | `alarm` | toolbar tint |
  | At least one pending, or only read fired ones | `alarm.fill` | toolbar tint |
  | At least one **unread** fired Reminder | `alarm.waves.left.and.right.fill` | accent |

  An unread fired Reminder wins over pending. No count is drawn on the button. A fired Reminder never changes the bell (#0639).
- Tooltip, built from the live binding (#0636's pattern): "Reminders (⌥⌘R)", followed by the state, for example "· 2 upcoming, next at 3:45 PM" or "· 1 due, 2 upcoming".
- Accessibility: identifier `toolbar.reminders`, label "Reminders", and a value of `none`, `2 upcoming`, `1 due, 2 upcoming` or `1 unread due, …`. The label stays "Reminders" whatever the state.

### Shortcut and entry points

- New `ShortcutAction.toggleReminders` ("Show Reminders"), **appended after `remindMe`** (`Shortcuts/ShortcutAction.swift:56`; the catalog is append-only). Default **⌥⌘R**, rebindable. No default in `ShortcutAction.swift:100-186` uses ⌥⌘R, and neither does any hard-coded `keyboardShortcut` in `Commands/BattyCommands.swift`. The only hard-coded ⌥ chords are the ⌘⌥1–9 Session and Tab selectors at `:249-252` and `:688-691`. It is not in `ShortcutsStore.reservedShortcuts` either (`Shortcuts/ShortcutsStore.swift:25-31`). It pairs with ⇧⌘R (Remind Me…).
- A notification such as `.battyToggleReminders`, guarded by `isKeyWindow` like `.battyToggleBellFeed` (`Views/SessionDetailView.swift:41-44`), toggles the popover. It is wired:
  - in `Commands/BattyShortcuts.swift`, next to `.toggleBellFeed` (`:184`);
  - as a menu item "Show Reminders" beside Toggle Bell Feed (`Commands/BattyCommands.swift:323-329`);
  - as a Command Palette case next to `:418`.
- Docs that `ShortcutDocsSyncTests` checks: add the row to `BattyKit/Sources/BattyKit/Help/05-shortcuts.md` (near `:62-67`) and `docs/shortcuts.md` (near `:83` and `:133`).

### Popover (360 x 420, the Bell Feed's size)

```
Reminders                              + New Reminder…
------------------------------------------------------
Due  1                        Mark All Read  Clear Read
 ● (alarm) Check the deploy finished…        2 min ago
           api · due 3:31 PM
           [Remind Again in 15 Minutes] [In 1 Hour] [Done]
Upcoming  2
 (clock) Check on ./build.sh unit            in 12 min
         Session 1 · 3:45 PM              (pencil) (x)
 (clock) Review the release notes…            tomorrow
         Batty · tomorrow at 9:00 AM
```

- **Sections.** **Due** comes first: fired Reminders, newest fired first. **Upcoming** follows: every `SessionRuntime.reminder` across `store.windows`, soonest first (`SessionReminder.fireDate(calendar:)`, `Model/SessionReminder.swift:53`). A section with no rows is not shown. Upcoming is a computed list with no new stored state.
- **Due rows.** An accent `alarm` glyph. An **unread dot** (accent) when unread, none when read, the same dot the Bell Feed uses (`Views/BellFeedView.swift:250-255`). Line 1 is the text (`displayText(sessionTitle:)`), up to 3 lines, with the relative time trailing. Line 2 is `<Session> · due <time>` (`ReminderFormat.dueLine`).
- **Upcoming rows.** A `.secondary` `clock` glyph. Line 1 is the text, one line, tail-truncated, with the relative time trailing (`ReminderFormat.relativeLine(due:now:)`, `Model/SessionReminder.swift:205`). Line 2 is `<Session> · <clock phrase>`. They have no unread dot and never count as unread.
- Relative times are drawn inside `TimelineView(.everyMinute)`, so nothing writes observed state per minute.
- **Due section header:** **Mark All Read**, shown while an unread Due row exists, and **Clear Read**, shown while a read Due row exists. They call #0639's store API. Neither touches Upcoming or the Bell Feed.
- **Row actions:**

  | Action | Due row | Upcoming row |
  |---|---|---|
  | Open Session (visits it: selects the Session, keeps its focused Pane and active Tab) | click, Return; the row leaves the list | click, Return |
  | Remind Again in 15 Minutes / 1 Hour | inline buttons on hover or selection, context menu, `R` = 15 min; the row leaves and the new Reminder shows in Upcoming | — |
  | Done | inline button, context menu, Delete; removes the row | — |
  | Edit Reminder… | — | pencil on hover, context menu, `E` |
  | Cancel Reminder | — | x on hover, context menu, Delete |

  - Remind Again is disabled when the Session has a newer pending Reminder (#0633's rule).
  - Edit closes the popover, makes the Session's Window key, then calls `ReminderActions.openBar(for:in:)` (`Views/ReminderMenu.swift:31`) without changing the selected Session. Cancel calls `store.cancelReminder(forSessionID:)` with no confirmation, as the menu does.
- **Header: New Reminder…** closes the popover and opens the Quick Reminder bar for the Window's selected Session (`ReminderActions.openBar(in:)`, `Views/ReminderMenu.swift:37`). The bar opens in edit mode when that Session already has a pending Reminder. Disabled with no selected Session.
- **Empty state:** `ContentUnavailableView` with the `alarm` glyph, "No Reminders", "Set one on a Session to be brought back to it later.", and a "New Reminder for <Session>…" button showing ⇧⌘R.
- **Keyboard:** Up and Down move across Due, then Upcoming, as one selection. Return, Escape, `E`, `R` and Delete work as in the table. Initial selection: the first unread Due row, else the first Due row, else the first Upcoming row. The List's type-select must not swallow `E` and `R`; verify in the VM.
- **Opening the popover marks nothing read.**
- **Popover writes are event-origin only** (clicks and key presses), per `docs/swiftui-observation-rules.md`. The popover is dismissed before the bar's sheet is presented.
- **Toolbar overflow:** not verified by the spec. Check what the bell's popover does today when the toolbar overflows in a narrow Window, and make Reminders match it.

### Accessibility identifiers (for UI tests)

`reminders.list`, `reminders.new`, `reminders.empty`, `reminders.mark-all-read`, `reminders.clear-read`, and `reminders-due.<Session title>` with value `reminder due, unread` or `reminder due, read`. Also `reminders-upcoming.<Session title>`, valued `reminder pending: <phrase> — <text>` from `ReminderActions.detail` so the manual-clock UI tests can assert on it. Row buttons insert the action after the prefix: `reminders-due.again15.<title>`, `.again60.`, `.done.`, `reminders-upcoming.edit.<title>`, `.cancel.`. Session-title keys follow the Sidebar's `session-row.<title>` (`Views/SessionSidebarView.swift:392`). VoiceOver reads a row as "Reminder, <text>, <Session>, <phrase>[, unread]". Edit, Cancel, Remind Again and Done are also exposed as custom actions.

## Open questions (defaults in place)

1. **Keep Done now that Clear Read exists?** Default: keep it. Design D shows it, and it removes one row without visiting the Session. The alternative is a per-row Mark as Read, with Clear Read doing the removal.
2. **Where do Mark All Read and Clear Read sit?** Default: in the Due section header, because only Due rows take part. The alternative puts them in the popover header beside New Reminder…, as in the Bell Feed.
3. **Glyph for "only read fired Reminders":** default `alarm.fill`, the same as pending. The alternative is plain `alarm`.
4. **Click on an upcoming row: Open Session or Edit?** Default: Open Session, consistent with every other row. Edit is the pencil, the context menu and `E`.
5. **Popover keys `E`, `R`, Delete.** Default: as specified, if a VM check shows type-select does not take them.
6. **Toolbar overflow.** Default: match whatever the bell does today, after checking in the VM.
7. **Shortcut.** Default: ⌥⌘R, rebindable.

## What needs the user's eye

- The three button states in light and dark, on a see-through Window and with a themed accent. The ringing glyph must read as "something needs you" next to the bell.
- The popover against `0637/option-D.html`: spacing, the three-line Due text, and the hover buttons at 360 pt.
- That opening the popover leaves unread rows unread, and that Clear Read matches "clear all read items".
- Toolbar overflow in a narrow Window.
