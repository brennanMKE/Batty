## Description

Batty's keyboard-driven pickers each show their keyboard hints in a different place and style. Some put "Esc to dismiss" in the header next to the title or filter field. Others put a footer bar of key hints under the list. One has a plain caption at the bottom of the content, and the Command Palette shows no hint at all. Each picker should show its hints in the same place and the same style, built from one shared view.

This is the follow-up carved out of #0654 (parent), which sets one macOS button convention for Batty's sheets. Its rule 8 says the keyboard pickers keep hint captions instead of buttons, "but put them in one place and one style". The #0654 plan left that half out of its scope because these pickers have no buttons, and moving their captions touches six more views and their UI tests.

This is UI work. The review resolves it, and the user signs off visually and closes it.

So there are four header captions, one bare bottom caption, two footer bars that are copies of each other with different vertical padding, and one picker with no hint. Two different type sizes (`.caption` and `.callout`) are used, and two different words for Escape ("dismiss", "cancel").

## Target

- One shared view in BattyKit, for example `PickerHintBar` in `Views/PickerHintBar.swift`, that every picker above uses for its hints. The plan phase picks the name and shape.
- One placement: a footer bar under the list, styled like the existing Open Project / Open Quickly footer (`.callout`, `.secondary`, `controlBackgroundColor`, top `Divider`, one padding value). The header keeps only the title or filter field.
- The Escape hint lives in that footer, with one wording for "close without choosing" across every picker ("Esc to dismiss", or the plan's choice). "Esc to clear" stays wherever Escape clears a filter first.
- Pickers with context hints (the Open Project selection hint, ⌥↩, ⌘E, ⌘N, the Open Quickly row hints) put them in the same bar. Leading is the hint for the selection, trailing is the key list.
- The Command Palette gets the same footer with at least the Escape hint.
- The Session color picker is a small sheet, not a list. The plan decides if it uses the same bar or the same caption style without the bar, and records why. #0654 decided it stays a click-to-pick picker with no Cancel / Set buttons; this issue doesn't change that.

## Acceptance criteria

- [ ] A shared hint view exists in BattyKit, and every picker in the inventory uses it: Layout, Theme, Session Theme, Session color, Open Project, Open Quickly and Command Palette. No picker builds its own hint `HStack`.
- [ ] No picker shows a hint in its header.
- [ ] Every picker shows an Escape hint, worded the same way for the same behavior.
- [ ] Open Project and Open Quickly keep their context hints and key lists, with the same padding.
- [ ] Accessibility identifiers `project-picker.hint`, `open-quickly.hint` and `open-quickly.tab-hint` are kept. The UI tests that use them (`ProjectsSharingTests`, `ProjectsPickerTierTests`, `ProjectsOpenTests`, `Support/ProjectsHarness.swift`) still compile with `./build.sh ui-typecheck`, and the affected classes re-run in the VM.
- [ ] Any new user-facing strings go through `LocalizedStringKey` / `String(localized:)` like the existing ones.
- [ ] `./build.sh` and `./build.sh unit` pass.
- [ ] Gotchas records what the user still has to check visually (each picker in light and dark mode, the footer at each picker's width).

## Notes

- Depends on #0654 landing first. Its plan doesn't change these pickers, but it adds `DialogButtonRow` with a `.bar` style (padding 20 / 12 under a `Divider`). The plan here should decide if the hint bar's padding matches that bar so the sheets look alike.
- The Open Project picker's footer and Open Quickly's two footers are already near-copies (`ProjectPickerView.swift:314-334`, `OpenQuicklyView.swift:318-349`). Those are the natural starting point for the shared view.
