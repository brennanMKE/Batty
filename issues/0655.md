## Description

Batty's keyboard-driven pickers each show their keyboard hints in a different place and style. Some put "Esc to dismiss" in the header next to the title or filter field. Others put a footer bar of key hints under the list. One has a plain caption at the bottom of the content, and the Command Palette shows no hint at all. Each picker should show its hints in the same place and the same style, built from one shared view.

This is the follow-up carved out of #0654 (parent), which sets one macOS button convention for Batty's sheets. Its rule 8 says the keyboard pickers keep hint captions instead of buttons, "but put them in one place and one style". The #0654 plan left that half out of its scope because these pickers have no buttons, and moving their captions touches six more views and their UI tests.

This is UI work. The review resolves it, and the user signs off visually and closes it.

### Decisions

1. **One shared view: `PickerHintBar`** in `BattyKit/Sources/BattyKit/Views/PickerHintBar.swift`, plus a pure `PickerEscapeHint` enum in the same file. Not an extension of `DialogButtonRow`: that type is about buttons and shortcut placement; a hint bar has no buttons and no shortcuts (the pickers handle keys in `onKeyPress`).
2. **Esc wording:** "Esc to dismiss" for close-without-choosing, everywhere (it is already the phrase in five of six places and its key exists). "Esc to clear" only in the Open Project picker while filtering. The Session color picker's "Esc to cancel" becomes "Esc to dismiss" — same behaviour, so same phrase.
3. **Placement:** a footer bar at the bottom of every picker, always shown (Open Quickly's footer is shown for every selection now, not only Project / Project-backed Tab rows). Layout: leading = the selection's context hint (optional), spacer, trailing = key list, with the Esc hint always last. Headers keep only the title / filter field.
4. **Style and padding:** `.callout`, `.secondary`, `Color(nsColor: .controlBackgroundColor)` background, top `Divider()` overlay, item spacing 18, **padding 16 horizontal / 10 vertical** (Open Project's value; Open Quickly moves from 8 to 10). Not `DialogButtonRow.bar`'s 20 / 12: every picker insets its header and list by 16, so 16 lines the hint text up with the filter field and rows above it, and the bar holds one line of callout text, not regular-size buttons, so 12 vertical would make it visibly taller than the content warrants. The two bars look alike in material and divider; only their insets follow their own sheet's content inset.
5. **Session color picker gets the full bar**, not just the caption style. Reasons: the acceptance criteria want every picker on the shared view, and one look is the point of the issue; the bar fits — at 260 pt wide less 32 pt padding, "↩ Set" + "Esc to dismiss" at callout needs roughly 130 pt. Keep it click-to-pick with no buttons (#0654). Its trailing keys: "↩ Set" then "Esc to dismiss" (keeps the Return hint the caption had). Structure: the existing padded `VStack` content stays as is (minus the caption `HStack`), wrapped in an outer `VStack(spacing: 0)` with the bar under it; `.frame(width: 260)` and the focus / `onKeyPress` modifiers move to the outer stack so key handling is unchanged.
6. **Return hints:** only where a picker already showed one (Open Project selection hint, Open Quickly hints, Session color). Layout, Theme, Session Theme and Command Palette show only the Esc hint. Adding "↩ Choose" everywhere is scope creep and not asked for.

### `PickerHintBar` shape

- `nonisolated enum PickerEscapeHint: Equatable, Sendable { case dismiss, clear }` with `var title: String` → `String(localized: "Esc to dismiss", comment: "Keyboard picker footer: Escape closes without choosing")` / `String(localized: "Esc to clear", comment: "Keyboard picker footer: Escape clears the filter")`.
- `struct PickerHintBar<Leading: View, Keys: View>: View`, `init(escape: PickerEscapeHint = .dismiss, @ViewBuilder leading: () -> Leading, @ViewBuilder keys: () -> Keys)`, with convenience inits for no leading (`Leading == EmptyView`), no keys (`Keys == EmptyView`), and neither.
- Body: `HStack(spacing: 18) { leading.lineLimit(1).truncationMode(.tail); Spacer(minLength: 12); HStack(spacing: 18) { keys; Text(escape.title).accessibilityIdentifier("picker-hint.escape") }.fixedSize() }` then the style above. The key list is `fixedSize()` so the context hint truncates before any key does (Open Quickly at 540 pt with a long Project name is the tight case).
- Do **not** add `.accessibilityElement(children: .combine)` (or `.ignore`) to the bar or its leading content: UI tests find `project-picker.hint`, `open-quickly.hint`, `open-quickly.tab-hint` as their own elements and read `label`/`value`.
- Pure view: no state, no writes, so `docs/swiftui-observation-rules.md` is not engaged. Don't move any key handling into the bar.

## Resolution notes

> 🟢 Resolved 2026-11-18 — every keyboard picker shows its hints in one shared `PickerHintBar` footer with one Escape phrase per behaviour.

## Root cause

Starting state: each keyboard picker built its own hint `HStack`. Four put "Esc to dismiss" in the header (`.caption`), the Session color picker had a bare bottom caption ("Esc to cancel · Return to set"), Open Project and Open Quickly had near-copy footer bars (padding 10 vs 8, Open Quickly's only for Project rows and with no Esc hint), and the Command Palette showed no hint.

## Fix

New `Views/PickerHintBar.swift`: `PickerEscapeHint` (`.dismiss` "Esc to dismiss", `.clear` "Esc to clear") and `PickerHintBar` (leading context hint that truncates, fixed trailing key list ending in the Escape hint `picker-hint.escape`; `.callout`, `.secondary`, `controlBackgroundColor`, top `Divider`, padding 16 / 10). `ProjectPickerModel.escapeHint` added. All seven pickers use it as their last child and no header carries a hint; Open Quickly's footer is always shown with `open-quickly.hint` / `open-quickly.tab-hint` on the same conditions as before. Session color picker: content moved into `content`, wrapped in an outer `VStack` with the bar ("↩ Set", "Esc to dismiss"); width, focus and `onKeyPress` modifiers moved to the outer stack. Command Palette root gained `.accessibilityElement(children: .contain)`. `docs/ui-features.md` gained "Picker hint bars" and updated Open Project / Open Quickly notes. Followed the plan; no deviations.

Round 2: the tests read the Escape hint as `value` when `label` is empty, because a macOS SwiftUI `Text` exposes its string as the static text's `value`. Adding `.accessibilityLabel(Text(escape.title))` to the hint (as the review preferred) was tried and still left `label` empty in VM run `20261118-230003-76041` (4 of 4 failed), so it was reverted; the existing Projects tests already read `[label, value]` for `project-picker.hint` for the same reason. `ProjectsPickerTierTests.testFilteringCollapsesToOneGridAndEscapeIsTwoStep` reads the hint through `waitFor` after typing and after Escape, since it re-renders with the filter. VM run `20261118-230454-93271`: `CHECK UI: PASSED (4 tests)` for the four footer tests; host `./build.sh`, `./build.sh ui-typecheck` and `./build.sh unit` (4838 tests) pass.
