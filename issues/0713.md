## Description

User report (2026-11-21), verbatim: "I think I am running the latest .dmg but this is what I see as the version. That looks totally wrong. Version 1.4.0 (1)" and then "No, this build should not show this version number. The 1 should at least be the normal time stamp."

Every Batty Beta built by `./build.sh package` (unsigned, `--sign`, `--sign --notarize`, `--sign --notarize --no-submit`) shows `CFBundleVersion` `1`, because `scripts/build-beta.sh` never overrides `CURRENT_PROJECT_VERSION` the way `scripts/release.sh` does. And a Beta built from `main` shows `MARKETING_VERSION` `1.4.0`, because `main` was not moved to the next minor after `release/1.4` was cut, while 1.4.1 and 1.4.2 shipped from `release/1.4`. The result, `1.4.0 (1)` in the About panel, looks like an old release and doesn't identify the build.

The user directed the outcome on 2026-11-21 (quoted above): Beta packages carry the normal timestamp build number, and Betas from `main` don't claim to be 1.4.0.
