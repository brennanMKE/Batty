# 0350 — The system metrics pane runs its full ~6.5 ms sampling sweep synchronously on the MainActor every second

| | |
|---|---|
| **Status** | open |
| **Module** | Pane |
| **Platform** | macOS |
| **First seen** | 2026-08-21 |

## Description

`SystemMetricsPaneContent` is `@MainActor`, and its `startActive()` creates the 1 Hz sampling loop with a plain `Task { … }` — which inherits main-actor isolation. Every tick therefore runs `SystemMetricsSampler.sampleOnce()` synchronously on the main thread: `proc_listallpids` plus ~800 `proc_pidinfo`/`proc_pid_rusage` calls (one pair per process on this machine), a `host_processor_info` sweep, and a synchronous IOKit round trip to the AppleSMC driver. Measured on this machine the full sweep is ~6.5 ms — a dropped frame every second while a system-metrics pane is visible, and a main-thread hang risk if the SMC call ever blocks (SMC access goes through the kernel driver; a wedged sensor read has nowhere to time out).

All the readers are stateless (`SMCThermalReader`, `SystemCPUReader`, `SystemLoadReader`, `SystemMemoryReader`, `ProcessMetricsReader` are enums/structs with static or pure functions) and `SystemMetricsSnapshot` is `Sendable`, so moving `sampleOnce()` off-actor is mechanical: sample on a background executor, hop back to the main actor only to assign `snapshot`.

## Expected behavior

The per-tick sweep runs off the main actor; only the `snapshot` assignment (and any `@Observable` notification) happens on the MainActor. No per-second main-thread stall attributable to sampling.

## Actual behavior

The entire sweep — syscall storm plus the IOKit/SMC round trip — executes on the main thread once per second for every active system-metrics pane.

## Notes

Verified code locations (branch `issue/0314-2`, pending merge at filing time):

- `BattyKit/Sources/BattyKit/Runtime/SystemMetricsPaneContent.swift` — `@MainActor` class; `startActive()` builds `task = Task { [weak self] in while !Task.isCancelled { … refresh() … Task.sleep(for: Self.sampleInterval) } }`; `refresh()` calls `sampler.sampleOnce()` directly.
- `BattyKit/Sources/BattyKit/Runtime/SystemMetricsSampler.swift` — `sampleOnce() -> SystemMetricsSnapshot`, the synchronous sweep.

Watch the `docs/swiftui-observation-rules.md` constraints when restructuring: the off-actor hop must not turn into a mutate-during-update or an unowned write race — the pattern is "background sample, main-actor assign", not `Task.detached` writes into observed state.
