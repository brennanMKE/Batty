# 0659 — Background Images picker: a single click should show the image and keep the picker open, and a double click should pick it and close, as the Theme selector does

|---|---|
| **Status** | open |
| **Module** | Settings / Pane / Projects / Testing |
| **Platform** | macOS |
| **First seen** | 2026-11-18 |
| **Priority** | medium |

## Description

The user wants the Background Images picker to work like the Theme selector. A single click on an image loads it and shows it on the target, as it does now. A double click on an image picks it and closes the picker. The user's words (2026-11-18): "When I am selecting a background image I can tap it and it will load and show it. I want it to also work like themes where I can just double tap and that also closes that selection window."

**Premise check.** On `main` today a single click doesn't leave the picker open. In both tabs, from every caller, a single click picks the image, applies it and closes the picker sheet once the image is ready. For a Background Sets image that isn't downloaded yet, the picker closes after the download finishes. There is no double-click handler (see Current state). "Load and show it" is what the user sees after the picker closes: in a gear sheet the new image shows behind the still-open gear sheet. To make a double click the "pick and close" gesture, the single click has to stop closing the picker. So the change is:

- **single click** applies the image live and keeps the picker open;
- **double click** applies it and closes the picker;
- **Return** applies the selected image and closes the picker;
- **Escape and Cancel** close the picker. Open question 1 decides whether they also undo the live single-click change.

The plan should confirm this reading with the user if there is any doubt. The other reading, keeping single click as pick-and-close and adding a double click, would change nothing anyone can see.

This is UI work. Visual sign-off is the user's.

## Current state (checked on `main` at `c6f385fd`)

All paths below are under `BattyKit/Sources/BattyKit/`.

### The picker

`BackgroundImagesView` (`Views/BackgroundImagesView.swift`) is the "Choose an Image" sheet. It has two tabs, My Images and Background Sets (`:48-56`), and opens on the tab that holds the current image (#0650, `:88-96`).

**My Images tab**
- A single click (`.onTapGesture { click(entry) }`, `:163`) runs `click` (`:294-298`). That selects the cell, focuses the grid and calls `pick` (`:308-315`). `pick` waits for the thumbnailer's usability check, then calls `onPick(entry.path)`. Every caller's `onPick` closes the sheet (see Callers). An unusable image does nothing.
- There is no `onTapGesture(count: 2)`.
- The arrow keys move the selection (`:184-187`, `move` at `:285-292`) without applying anything. Return calls `activateSelection` (`:188`, `:300-303`), which picks the selected image and closes. Delete removes the selected image (`:189-195`). The grid has no Escape handler; the sheet's Cancel button carries `.cancelAction`.
- Add from File… picks the added image straight away and closes (`add`, `:317-324`).

**Background Sets tab** (`Views/BackgroundSetsView.swift`)
- A single click on a cell (`.onTapGesture(perform: activate)`, `:284`) runs `click` (`:179-182`), which calls `hosted.pickOrCancel(image) { onPick($0) }` (`Model/HostedBackgroundsModel.swift:480-489`). An image that isn't downloaded yet downloads first, with a spinner over its thumbnail (`:248-259`). When the download finishes, `onPick` runs and the sheet closes. A second click on a cell that is still downloading cancels its download (#0582). A click on a different cell supersedes the earlier pick.
- There is no double-click handler and no keyboard handling at all: no arrow keys, no Return. The filter field takes the focus.

**Bottom row** (after #0654): `bottomBar` (`Views/BackgroundImagesView.swift:228-249`) is a `DialogButtonRow` with `confirm: nil` and only **Cancel** (`background-images.picker.cancel`, `.cancelAction`). Cancel calls `model.hosted.supersedePicks()` and then `onCancel()`. On the My Images tab the leading side holds Add from File…, Remove…, a status message and the image total. #0654 ("Background Images keeps pick-on-click with Cancel only") left the picker without a Choose or Done button on purpose, because the click itself was the commit. `.onDisappear` also calls `supersedePicks()` (`:81`), so a download still in flight never delivers after the sheet closes.

### Callers (every place the picker opens)

`BackgroundImagesView` is built in exactly two places.

1. **`TerminalBackgroundControls`, the Choose… sheet** (`Views/TerminalBackgroundControls.swift:51`, sheet at `:65-75`). `onPick` calls `onPickedLibraryImage(path)` and then sets `isChoosingImage = false`, which closes the picker. Used by:
   - **Settings → Appearance → Background**, the app-wide default (`Views/SettingsView.swift:320-329`). Its `startAdopt` (`:358-374`) copies the image and calls `editor.pickImage(path:)`, which writes the app-wide setting straight away. Settings has no Cancel.
   - **`BackgroundOverrideSettingsView`, the gear sheet** (`Views/BackgroundOverrideSettingsView.swift:294-301`, `startAdopt` at `:374-389`). Its `editor.update { $0.pickingImage(path:) }` is a live preview that the gear sheet's own Cancel reverts and Done keeps (#0654 inventory). The gear sheet is opened by:
     - the Pane gear (`Views/PaneView.swift:156`);
     - Tab Background… and Set Session Background… in the sidebar (`Views/SessionSidebarView.swift:169`, `:179`);
     - the Project Editor's Project background (`Views/ProjectEditorView.swift:491`), Pane background (`:992`) and Tab background (`:1137`).
2. **Pane → Background Images…** (`PaneBackgroundImagePickerSheet`, `Views/PaneBackgroundImagePicker.swift:38-65`). `pick` calls `PaneBackgroundImagePicker.apply` (`:22-34`), which writes the Pane's override straight away with no gear-sheet Cancel behind it, and then sets `isPresented = false`.

So the picker closes on a single click from every caller. What a pick writes differs by caller: the Settings app-wide default and Pane → Background Images… are written at once, while gear-sheet callers only preview until the gear sheet's Done.

### The Theme selector, the model to copy

`ThemeSelectorView` (`Views/ThemeSelectorView.swift`, opened from `Views/SessionDetailView.swift:138`) and `SessionThemeSelectorView` (`:293`, opened from `Views/SessionSidebarView.swift:153`):

- **Single click** (`.onTapGesture`, `:246-249` / `:470-473`) moves the cursor and **commits** the Theme (`store.setGlobalTheme` / `setSessionTheme`). The selector stays open.
- **Double click** (`.onTapGesture(count: 2)`, `:241-245` / `:465-469`) commits and sets `isPresented = false`. The double-click modifier comes before the single-click one, so a double click also fires the single click first. That is harmless here, because both commit the same Theme.
- **Arrow keys** only preview (`previewGlobalTheme` / `previewSessionTheme`, `:274-279`).
- **Return** commits the cursor's Theme and closes (`confirmSelection`, `:128`, `:261-268`).
- **Escape** just closes (`cancelSelection`, `:129`, `:270-272`). A Theme that a click already committed stays. An arrow-key preview that was never committed is dropped. The header shows the caption "Esc to dismiss".

## Expected behavior

- **Single click, both tabs.** The clicked image becomes the selection (outlined) and is applied to the target live, so the user sees it on the Pane, Tab, Session, Project or app-wide background. The picker **stays open**. For a Background Sets image that isn't downloaded, the click starts the download with the spinner as now. The image is applied when the download finishes, and the picker stays open. A second click on a cell that is still downloading still cancels it. A click on another image still supersedes it.
- **Double click, both tabs.** Applies the image and closes the picker, matching the Theme selector. For a Background Sets image that isn't downloaded, a double click starts the download and closes the picker once the image is applied. Open question 3 covers whether it waits for the download. Two clicks on a not-yet-downloaded image must not count as "click, then click again to cancel".
- **Return.** In My Images, Return applies the selected image and closes, as it does today. Background Sets gets the same Return (and arrow-key selection if the plan finds it cheap), so both tabs behave alike. If Background Sets keyboard navigation is out of scope, say so in the plan and in Gotchas.
- **Escape and Cancel** close the picker. What happens to an image that a single click already applied is open question 1.
- **Add from File…** behaves like a single click on the added image: it is added, selected and applied, and the picker stays open. Or the plan keeps it as pick-and-close and says why.
- **Every caller** behaves the same: Settings → Appearance, the Pane gear, Tab Background…, Set Session Background…, the three Project Editor background sheets, and Pane → Background Images….
- No writes to observed state from `body`, and no `Task` hop to work around a mutate-during-update (`docs/swiftui-observation-rules.md`). The single-click handler must not cause the grid jumps that `GridSelection` and the scroll monitor guard against (#0624, `BackgroundSetsScrollStabilityTests`).

## Acceptance criteria

1. In **My Images**, from each caller, a single click on a usable image applies it to the target and leaves `background-images.picker.root` on screen with that cell selected. A double click applies it and closes the picker. Return on the selected cell applies it and closes.
2. In **Background Sets**, from each caller, a single click on a downloaded image applies it and leaves the picker open. A single click on an image that isn't downloaded downloads it, applies it and leaves the picker open. A double click applies the image and closes the picker. The existing click-again-to-cancel and click-another-supersedes download behaviour still holds.
3. Escape and Cancel follow the rule decided in open question 1, the same way for every caller. In particular, Cancel in a gear sheet behind the picker still reverts everything the gear sheet changed.
4. Settings → Appearance and Pane → Background Images…, whose picks are written at once, behave as decided in open question 2.
5. A single click on an unusable My Images image ("Can't be used") applies nothing and keeps the picker open. A double click on it also applies nothing.
6. Clicking several images in turn leaves the last one clicked applied. A download superseded by a later click never delivers after it, as `supersedePicks` ensures today.
7. Reopening the picker after a single-click apply opens on that image's tab with it selected and in view (#0650 still holds).

## Notes

### Open questions for the plan

1. **Cancel and Escape after a live single click.** The Theme selector keeps a clicked Theme on Escape. The gear-sheet callers already have their own Cancel that reverts. Option A, Theme parity: Cancel and Escape just close and the last clicked image stays applied. In a gear sheet it can still be undone with the gear sheet's Cancel. Option B: Cancel and Escape restore the image that was current when the picker opened. Option B needs a revert path for the two immediate-write callers. A matches the request ("like themes"). B matches the #0654 meaning of Cancel. Pick one and use it for every caller.
2. **Immediate-write callers.** Settings → Appearance and Pane → Background Images… write a pick straight away, and each pick copies the image into the target's folder (`adoptImage`). Several single clicks therefore copy several images. Check that each new pick releases the copy it replaces (Settings passes `retaining:`; the Pane path goes through `BackgroundOverrideEditor`). Otherwise single-clicking around leaves orphaned copies.
3. **Double click on a Background Sets image that isn't downloaded.** Either close at once and let the download deliver after the sheet is gone, or keep the picker open with the spinner until the download finishes and then close. `.onDisappear` calls `supersedePicks()` today, which cancels an in-flight pick, so closing first needs that changed. Waiting for the download and then closing is the smaller change.
4. **A double click fires the single click first** (SwiftUI runs `onTapGesture` on the first click). In Background Sets the second click of a double click hits `pickOrCancel` on a key that is now fetching, and that would cancel the download. The plan must keep a double click from reading as "click again to cancel", for example by handling the double click before the single click, or by routing both through one handler that knows the click count.
5. **Bottom row.** With a single click no longer committing, the picker might want a default **Choose** or **Done** button beside Cancel (`DialogButtonRow` supports `confirm:`), revisiting #0654's "Cancel only". The Theme selector has no buttons, only the caption "Esc to dismiss". The request doesn't ask for a button. Decide, and record the reason in the Resolution.
