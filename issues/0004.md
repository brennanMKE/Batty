## Description

`CLAUDE.md` exists at the repo root but is empty. Populate it so future Claude sessions and subagents pick up canonical project conventions without having to reverse-engineer them.

**Acceptance criteria:**
- `CLAUDE.md` documents:
  - One-paragraph what-this-is, with pointers to `PRD.md` and `Concepts.md`.
  - Build / verify commands (`xcodebuild -scheme Batty -destination 'platform=macOS' build` and the `test` variant).
  - Swift conventions: Swift 6.0, MainActor default isolation, no comments unless the why is non-obvious.
  - Module / file layout guidance (where new files go).
  - Pointer to `issues/Issues.md` for issue-tracker workflow.
  - Restricted areas (e.g., do not modify `Configuration/Build.xcconfig` without confirmation).

## Notes

- Keep it terse — agents should read it in <30 seconds.
- Mirror `Issues.md`'s style: bullets and tables over prose where possible.
- Don't duplicate the PRD; reference it.

## Root cause

`CLAUDE.md` existed at the repo root but was an empty file — every Claude session was starting cold without canonical guidance, having to reverse-engineer conventions from `PRD.md` / `Concepts.md` / `issues/Issues.md` each time.

## Fix

Populated `CLAUDE.md` with binding guidance covering:

- Reading order (PRD → Concepts → Issues.md → specific issue).
- Build / verify commands (`xcodebuild -scheme Batty -destination 'platform=macOS' build`, plus the `test` variant) and the `open Batty.xcodeproj` Xcode entry point.
- Release pipeline (`scripts/release.sh`, `verify-dmg.sh`, `setup-keys.sh`) plus the explicit "do not run autonomously" rule for notarization.
- Project layout including the `PBXFileSystemSynchronizedRootGroup` note (new Swift files in `Batty/` don't require pbxproj edits).
- Code conventions (Swift 6, MainActor default, no comments unless the *why* is non-obvious, minimal headers, no emojis).
- Architectural rules (surface registry as single source of truth; value-type layout model; **unsandboxed app** with hardened runtime).
- Restricted areas (Build.xcconfig, scripts/, app icon assets).
- Issue tracker workflow rules (resolved-vs-closed, two-commit resolve flow, never close on inference).

The "Authoring rules" section explicitly warns against shared-state actions (running `release.sh`, `git push`, GitHub releases) without confirmation, and against marking UI work `closed` without user verification.

## Files changed

- `CLAUDE.md` — populated from empty to ~100 lines of binding guidance.

## Gotchas

- The architectural rule "App is unsandboxed" pre-states a finding from the project audit: `Configuration/Build.xcconfig` and `project.pbxproj` currently have `ENABLE_APP_SANDBOX = YES` from the Xcode template. This is incompatible with terminal use (PRD §11). The flip from YES to NO will land as part of #0001's work alongside the libghostty SPM addition.
- Build verification: `xcodebuild -scheme Batty -destination 'platform=macOS' build` passed before and after this change (no code touched).
