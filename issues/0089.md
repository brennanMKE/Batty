## Description

When a session's anchor tab (or a tab's terminal) sits in a directory that contains a recognizable project manifest, derive the project's display name from the manifest and use it as the title. As the user `cd`s through directories, the title updates to whatever the current folder calls itself. When the user manually renames a session or tab, the override **wins permanently** — no further auto-changes.

The catalog of ecosystems and extraction rules is comprehensive — see `docs/project-name-extraction.md` (already in the repo). The rules should live in a bundled JSON resource so the catalog can be edited and extended without touching Swift code.

This is additive to:

- `#0050` — `TabTitleFormatter` precedence (override → TUI display name → live OSC → cwd basename → fallback). A new "project name" step slots between live OSC and cwd basename.
- `#0058` — Session name cache (directory → name from previous manual rename). Still wins over derived names because the user already named it.
- `#0073` — TUI display-name registry. TUI name still wins over project name when a TUI is running.

## User-facing behavior

### Tabs

The chip title resolution chain becomes:

1. **`tab.titleOverride`** — user-set Rename. Absolute.
2. **`tab.runningCommandDisplayName`** — a known TUI is running (per `#0073`).
3. **Live OSC title** stripped + prettified (the existing path).
4. **NEW: project name** extracted from the tab's current cwd.
5. **cwd basename** (the existing fallback for non-project directories).
6. **`Tab N`**.

When the user `cd`s into `~/Developer/Batty`, the chip shows `Batty` (from `Batty/Package.swift` or `Batty.xcodeproj`). `cd ..` and the chip becomes the basename of that directory, unless THAT directory is also a project root.

### Sessions

Session titles have always been mutable (the user can rename via the sidebar context menu, and `#0058` autoapplies cached names when a previously-seen directory comes back). The new derivation slots into the chain similarly:

1. **`session.titleOverride`** (NEW — see below) — explicit user-set rename. Absolute.
2. **`SessionNameCache` hit** for the anchor tab's CWD — the user has previously renamed a session in this directory.
3. **NEW: project name** extracted from the anchor tab's CWD.
4. **`Session N`**.

Today `SessionRuntime.title` is just a `String` that gets mutated by `renameSession`. We need a way to distinguish "user explicitly set this" from "auto-derived." Add `SessionRuntime.titleOverride: Bool`. Set to `true` whenever the user calls `renameSession`. When the title is set by the auto-derivation path, leave it `false` so future auto-changes can replace it.

### Behavior on `cd`

- The anchor tab's `terminal.workingDirectory` change drives session re-derivation via the existing observer (`AppStateStore.handleWorkingDirectoryChange(forTabID:)` from `#0058` Phase 2). Extend this to also try project-name derivation if the name cache misses.
- Per-tab cwd changes (any tab) drive tab chip re-derivation. The `TabTitleFormatter` reads project name on demand each time it's called — caching is optional.
- Manual renames stop the cascade for that specific session/tab. `titleOverride` (the boolean for sessions; the existing `titleOverride: String?` for tabs) pins the title.

## JSON ruleset

Bundle `project-name-rules.json` as a resource in BattyKit. Loaded once at app launch.

Schema (proposal — adjust if needed during implementation):

```json
{
  "rules": [
    {
      "id": "node",
      "label": "Node.js / npm / pnpm / Yarn / Bun",
      "detect": ["package.json"],
      "extract": {
        "kind": "json",
        "file": "package.json",
        "path": "name"
      },
      "fallback": "directory"
    },
    {
      "id": "rust",
      "label": "Rust / Cargo",
      "detect": ["Cargo.toml"],
      "extract": {
        "kind": "toml-regex",
        "file": "Cargo.toml",
        "pattern": "(?ms)^\\[package\\][^\\[]*?\\bname\\s*=\\s*\"([^\"]+)\""
      },
      "fallback": "directory"
    },
    {
      "id": "swift-spm",
      "label": "Swift Package Manager",
      "detect": ["Package.swift"],
      "extract": {
        "kind": "regex",
        "file": "Package.swift",
        "pattern": "Package\\s*\\(\\s*name:\\s*\"([^\"]+)\""
      },
      "fallback": "directory"
    },
    {
      "id": "swift-xcode",
      "label": "Xcode project",
      "detect": ["*.xcodeproj", "*.xcworkspace"],
      "extract": {
        "kind": "directory-basename-of-match",
        "stripExtension": true
      },
      "fallback": "directory"
    },
    {
      "id": "go",
      "label": "Go module",
      "detect": ["go.mod"],
      "extract": {
        "kind": "regex",
        "file": "go.mod",
        "pattern": "^module\\s+([^\\s]+)",
        "transform": "last-path-segment"
      },
      "fallback": "directory"
    }
  ],
  "priority": ["swift-xcode", "swift-spm", "rust", "node", "go"]
}
```

`extract.kind` options to support (v1):

- `"json"` — parse the file as JSON, extract at `path` (simple dotted path is enough).
- `"regex"` — apply the regex to the file's text, take capture group 1.
- `"toml-regex"` — regex applied with a `(?ms)^\[<section>\]...name\s*=\s*"..."` shape (TOML is regex-friendly enough for the common case; we don't pull in a TOML parser).
- `"directory-basename-of-match"` — when the detect pattern is a glob like `*.xcodeproj`, take the first matching filename's basename minus extension.

`transform` options:

- `"last-path-segment"` — useful for Go's module path → project name.

`priority` lists rule IDs in resolution order. When a directory matches multiple rules, take the first by priority. If the chosen rule's extract fails, try the next match in priority order; if all fail, use the directory basename.

The bundled JSON should cover the catalog in `docs/project-name-extraction.md` — about 30 ecosystems. Start with the top 10–15 most common (Node, Rust, Python, Go, Swift SPM, Xcode, JVM Gradle/Maven, Ruby, .NET, CMake) and add the rest over time.

## Implementation guidance

### New files

- `BattyKit/Sources/BattyKit/ProjectName/ProjectNameRules.swift` — Codable structs for the JSON schema, loader from bundle.
- `BattyKit/Sources/BattyKit/ProjectName/ProjectNameResolver.swift` — given a directory path, walks the rule set and returns `String?`. Pure (file I/O only; no SwiftUI / observation).
- `BattyKit/Resources/project-name-rules.json` — the catalog. Add to the BattyKit bundle.
- `BattyKit/Tests/BattyKitTests/ProjectNameResolverTests.swift` — tests against fixture directories under `BattyKit/Tests/BattyKitTests/Fixtures/projects/<ecosystem>/`. Each fixture contains the bare minimum manifest needed to trigger the rule.

### Model changes

- `SessionRuntime.titleOverride: Bool = false` (default false). `AppStateStore.renameSession(id:to:)` sets it to `true`. The new auto-derivation skips sessions with `titleOverride == true`.
- `TabRuntime.titleOverride` already exists as `String?` — no change needed.
- `ProjectNameCache: actor` (or `@MainActor` final class) — process-wide cache keyed by absolute path, holds last derived name + a timestamp. Invalidate after ~30s or on explicit calls. Helps avoid hammering disk on rapid cd-back-and-forth.

### Wire-up

- In `AppStateStore.handleWorkingDirectoryChange(forTabID:)` (from `#0058` Phase 2), after the existing cache lookup, fall through to `ProjectNameResolver.resolve(at: cwd)`. If a name is returned and the session has no `titleOverride`, set `session.title = name`. Don't write to the SessionNameCache from this path — the cache is for **user-chosen** names only.
- In `TabTitleFormatter.chipTitle(for:fallback:)`, insert the project-name step. Call `ProjectNameResolver.resolve(at: tab.terminal.workingDirectory)` between the live-OSC step and the cwd-basename step.
- Both resolutions are synchronous reads of a small file — generally < 1ms. If profiling shows them on a hot path, add the cache above.

### Failure modes

- File missing → rule doesn't match, try next.
- File present but malformed → extraction returns nil, try next.
- Permission denied → catch and fall through silently.
- Rule has a typo in `path` or `pattern` → extraction returns nil, log a debug message.

### Tests

Fixture directories under `BattyKit/Tests/BattyKitTests/Fixtures/projects/`:

- `node/` containing `package.json` with `{"name": "test-node-project"}`.
- `rust/` containing `Cargo.toml` with `[package]\nname = "test-rust-project"`.
- `swift-spm/` containing `Package.swift` with `Package(name: "TestSwiftPkg", ...)`.
- `swift-xcode/` containing an empty `MyApp.xcodeproj/` directory.
- `go/` containing `go.mod` with `module github.com/example/test-go-project`.
- `no-manifest/` empty directory.

Tests:

- Each fixture resolves to its expected name.
- A directory with multiple manifests resolves to the highest-priority one.
- A malformed `package.json` falls back to the next match or to directory basename.
- A missing directory returns nil (not a crash).
- Glob patterns (`*.xcodeproj`) match correctly.

## Acceptance criteria

- `cd ~/Developer/Batty` makes the chip show `Batty` (from `Package.swift`'s name) and the session show `Batty` if it wasn't already named.
- Renaming the session to "Frontend" pins it — subsequent `cd`s into other project roots don't change the session title.
- Renaming a tab to "Logs" pins the chip — subsequent OSC titles and cwd changes don't override.
- `cd ~/Music` (no manifest) → chip shows `Music` via the existing cwd-basename fallback. Session title (if not overridden) shows `Music` too, OR falls back to "Session N" if the cwd-basename path is session-scoped only — decide during implementation.
- Adding a new rule to `project-name-rules.json` and rebuilding extends coverage. No Swift recompile of the resolver needed for content changes.
- 10+ ecosystems shipped in v1 (Node, Rust, Python, Go, Swift SPM, Xcode, Gradle, Maven, Ruby, .NET, plus more from `docs/project-name-extraction.md` as time permits).
- Unit tests cover every shipped rule via fixtures.

## Out of scope

- Reading display names that differ from identifiers (e.g. Maven `<name>` vs `<artifactId>`). v1 picks identifier; display name is a future polish.
- Monorepo subdirectory handling. v1 derives from the directory the tab is in; if the user cds into a subpackage with its own manifest, the subpackage's name wins (correctly).
- Custom user rules. The JSON is read-only at app launch.
- Editing the JSON via Settings.
- Network-based name resolution (e.g. resolving git remotes to repo names).

## Notes

- The catalog reference doc (`docs/project-name-extraction.md`) is authoritative for rule semantics. Keep the JSON aligned.
- Help section `02-sessions.md` and `04-tabs.md` (`#0082`, `#0084`) will need a one-paragraph note about the new auto-naming once this lands. The user-override-pins-forever rule is the key thing to communicate.
- The `SessionRuntime.titleOverride` field needs to persist through the Codable schema (`LayoutModel.Session`) so that even if workspace restore comes back (off by default per `#0055`), the override stays pinned. Add with `decodeIfPresent` for legacy compatibility.
- Performance: resolving a project name reads up to ~5 files from disk per directory check. With debouncing + caching, this should be invisible. If it ever becomes a hot path, switch the resolver to be async with cancellable lookups.
- This issue's design intentionally mirrors `#0058` (the existing session-name cache for user-renames-by-CWD). The two should coexist cleanly: cache > resolver, both gated by titleOverride.
