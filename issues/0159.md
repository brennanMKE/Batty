# 0159 — UI test suite: drag-and-drop (file drop, pane swap, cross-session)

|---|---|

## Description

The drag-and-drop code path has the worst regression history in the project — [[0022]], [[0023]], [[0102]], [[0127]], [[0143]], [[0144]], [[0145]], [[0156]] — and zero of it is covered by UI tests. Every fix has been verified by manual smoke testing only, and several of the bugs were *introduced* by fixes for neighboring drag-related features. This issue adds the test suite that locks in the current behavior so the next change to overlays, gestures, or AppKit z-order trips a test instead of shipping.

## Regressions this suite would have caught

- [[0102]] — File drag-and-drop onto the terminal stopped working after the persistent-host migration. A Mode-B test would have failed the moment `TerminalHostView` lost its `NSDraggingDestination` registration.
- [[0127]] re-opening — Pane drag never initiated because `SlidingTabBar` child gestures won the priority race against the container `.onDrag`. A test asserting "drag from `pane-drag-handle.<id>` produces a swap" would have failed.
- [[0143]] — Drop zone highlight unreliable because `.onDrop` sat below the terminal NSView in AppKit z-order. A Mode-B drag-targeted test would have failed.
- [[0144]] — File drop broken by an overlay attempting to fix [[0143]]. The test for [[0102]] would have caught this immediately.
- [[0156]] — Cross-session drop silently no-ops because drop zones mount on every pane in every session. A test running a script with two sessions would have failed by observing "no swap happened" or by counting drop-zone mounts (the [[0154]] logs make this assertable).

## Test cases

All tests use the foundation from [[0158]] — driver intents for setup, Mode A for model-state assertions, Mode B for AppKit-level drag fidelity.

### Pane swap (Mode A — fast, runs every CI build)

- **Single-session swap.** Script: 4 panes via `twoByTwoGrid`. Swap pane 0 ↔ pane 2 via the intent. Assert `tab-bar.<id>` order in the visible tree matches the expected post-swap layout.
- **Self-drop is a no-op.** Swap pane 1 ↔ pane 1. Assert no model change.
- **Swap focused pane keeps focus.** Focus pane 1, swap 1 ↔ 3, assert focused pane's `accessibilityValue == "focused"` is still on the originally-focused pane (now in the new position).

### Pane swap (Mode B — real drag, slower, runs nightly or on DnD-touching PRs)

- **Drag handle initiates a real swap.** `press(forDuration: 0.1, thenDragTo:)` from `pane-drag-handle.<sourceID>` to `pane-terminal.<targetID>`. Assert the swap happened. This is the [[0127]]-reopening regression test.
- **Drop zone highlight visible mid-drag.** Same drag as above; mid-drag, assert the target pane carries an overlay (use a new `pane-drop-zone.<id>` accessibility identifier on `PaneSwapDropZone`). This is the [[0143]] regression test.

### Cross-session no-mount (Mode A — would have caught [[0156]])

- **Two sessions, drag in Session A doesn't expose Session B drop zones.** Script: create two sessions, each with `twoByTwoGrid`. Select Session A. Start a drag intent (a new `beginPaneSwapDrag(from:)` driver intent that sets `PaneSwapDragState` without consuming it). Assert exactly N-1 drop zones exist for Session A's tree and zero exist for Session B's tree. Cancel the drag via an `endPaneSwapDrag` intent.

### File drop onto terminal (Mode B — real `NSDraggingDestination` dispatch)

- **File URL drop inserts shell-quoted path.** Use an in-process `NSDraggingSource` (or scripted Finder drag via `osascript` if the in-process route is too brittle — see [[0158]]). Drop a known file URL on `pane-terminal.<id>`. Use the sentinel pattern: pre-type `cat > /tmp/sentinel; ` into the prompt, drop, type close-stdin sequence, assert the sentinel contains the dropped path.
- **Drop on no-terminal area is a no-op.** Drop on the `session-sidebar` area; assert no shell input was sent.
- **Drop hover highlight transitions between adjacent panes.** Two panes side-by-side; drag a file URL across the boundary; assert the `pane-terminal.<id>` accessibility value transitions from `"drag-hover"` to `"unfocused"` and the other one becomes `"drag-hover"` (add the accessibility value to `TerminalPlaceholderView` keyed off `tab.isDragHovering`).

## Accessibility identifiers to add

- `pane-drop-zone.<paneID>` on `PaneSwapDropZone` so Mode-B drag tests can wait for the highlight.
- `accessibilityValue("drag-hover" / "unfocused")` on `pane-terminal.<id>` driven by `TabRuntime.isDragHovering`.

## Out of scope

- Cross-window drag (multi-window is gated on [[0027]]; no fix for cross-window DnD exists yet).
- Drag-to-detach a pane out of a window.
- Image / sixel drops (libghostty handles those internally; no Batty-side logic).
- Visual verification of the drag preview's appearance (rendering, not behavior).

## Acceptance criteria

- All test cases above pass under `xcodebuild -scheme 'Batty (Beta)' -destination 'platform=macOS' test`.
- Each test names the issue number it would have caught in a comment.
- The Mode-B tests are tagged or grouped so they can be excluded from a fast PR-time run if their flake rate proves intolerable on CI; nightly run always includes them.
- The cross-session test confirms drop-zone-mount count = `N - 1` for the active session and 0 for non-active sessions — the [[0154]] logging already exposes this; the test reads it via the new `pane-drop-zone.<id>` identifier rather than parsing log output.

## Notes

- Depends on [[0158]] for the driver intents and Mode-B harness.
- Keep the Mode-B suite small. Every Mode-B test is a maintenance liability; only keep ones that genuinely cover an AppKit-routing bug that Mode A can't.
- The [[0154]] logging is the diagnostic backstop when tests fail — `pane-swap:` and `file-drop:` lines in the captured test logs will show what AppKit and SwiftUI actually did.
