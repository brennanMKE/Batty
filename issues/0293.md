# 0293 — No way to release a surface's GPU resources without destroying the surface and its PTY

| | |
|---|---|
| **Status** | open |
| **Module** | GhosttyKit |
| **Platform** | macOS |
| **First seen** | 2026-07-31 |

## Description

libghostty offers no API between "pause rendering" and "destroy everything". The #0285 source investigation dumped every `_ghostty_surface_*` export in the vendored binary: the list contains `set_occlusion` and `free`, and **nothing in between**; `.SwapChain.deinit` appears only alongside renderer teardown. So an embedder with 100+ mostly-invisible surfaces has no way to bound its graphics memory — occlusion (see #0288) stops redraw-driven growth but does not free the swap chain, leaving roughly **48 MB per hidden Terminal Session unreclaimable from Batty's side** without killing the PTY. This is the genuinely upstream defect in the #0285 umbrella, and the ceiling on everything else: even with #0287 and #0288 done, steady-state footprint still scales with total open Terminal Sessions rather than visible ones.

**The upstream asks, cheapest first** (to be filed against ghostty and/or libghostty-spm — github.com/Lakr233/libghostty-spm; this Batty issue tracks them):

1. **Drop `CAMetalLayer.maximumDrawableCount` from 3 to 2 for non-visible surfaces.** The live instrumentation confirmed the default of 3 is in effect by measurement: 93 `'Batty'` IOSurfaces / 31 layers = exactly 3.00, with exactly 1/3 held by WindowServer as front buffers, stable across samples. Dropping to 2 for occluded surfaces would cut drawable memory by a third — ~125 MB of the 377 MB on the measured 26-session instance — and is a far smaller upstream change than freeing the whole swap chain.
2. **Free the swap chain when a surface is occluded** (reallocating on re-display), or add an explicit release/reacquire API for a surface's GPU resources — the full fix, and the larger change.

**Corroborating report from another libghostty-based multiplexer:** github.com/manaflow-ai/cmux issue #1435 — 67 panes, 8.4 GB footprint, ~90% GPU memory, IOSurface 5 GB / IOAccelerator 1.3 GB / owned-graphics 1.3 GB. Nearly identical proportions to Batty's measurements; still open. Caveat carried over from the investigation: cmux almost certainly makes the same app-per-pane integration choice (the path of least resistance through this wrapper's API), so the shared signature is not by itself proof the defect is in the renderer — but the *absence of any GPU-release API* is upstream fact regardless, confirmed by the symbol dump.

## Relation

- Child of umbrella #0285.
- Complements #0288: occlusion signalling stops growth; this issue is about reclaiming footprint occlusion cannot touch.
- #0291 experiment (b) (`setSurfaceVisible(false)` vs IOSurface region count) determines urgency: if occlusion already frees the swap chain in this Ghostty revision (unverifiable from the stripped static library), this issue is unnecessary. The investigation's confidence that the swap chain survives occlusion is **medium** — verify by measurement before filing upstream.

## Expected behavior

An occluded/hidden surface's GPU resources (swap-chain IOSurfaces at minimum) can be released and later reacquired without destroying the surface or its PTY, so graphics footprint scales with *visible* Terminal Sessions.

## Actual behavior

The only lever that frees GPU memory is `ghostty_surface_free`, which also destroys the terminal state and kills the PTY. Hidden surfaces hold full-size swap chains indefinitely (`updatePlacements` only writes `view.frame` when `placement.isVisible` — `TerminalHostStore.swift:209-212` — so a hidden Tab's chain stays at its last visible size).

## Notes

Two minor related upstream nits, recorded here rather than as their own tickets:

- `AppTerminalView` orphans the `CAMetalLayer` it creates in `commonInit` (`AppTerminalView.swift:15, 55-63`): Ghostty replaces `self.layer` with an `IOSurfaceLayer`, but the ivar keeps the original alive with a live `MTLDevice`, and `updateMetalLayerMetrics` keeps writing `drawableSize` to it (`AppTerminalView+Lifecycle.swift:188-192`). Small (a `CAMetalLayer` allocates no drawables until `nextDrawable`), but plainly unintended. Confidence it matters for footprint: low.
- `synchronizeMetrics` calls `ghostty_surface_set_size` unconditionally (`TerminalSurfaceCoordinator.swift:173`) ahead of its own change guard at `:184`, and both `layout()` and `setFrameSize` invoke it on every AppKit layout pass (`AppTerminalView+Lifecycle.swift:144-154`). Harmless if Ghostty short-circuits an unchanged size; a per-layout renderer resize if it doesn't. Confidence: low.

Both are worth a mention in the upstream filing. The orphaned-`CAMetalLayer` nit is also cross-referenced by #0294 (the 2×-content-area drawable anomaly), since `updateMetalLayerMetrics` writing `drawableSize` to the orphaned layer is a plausible mechanism there.
