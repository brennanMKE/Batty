# 0290 — Batty has no memory footprint monitoring or soft-limit warning

| | |
|---|---|
| **Status** | open |
| **Module** | App / Settings / BellFeed |
| **Platform** | macOS |
| **First seen** | 2026-07-31 |

## Description

Batty has no awareness of its own memory use. The #0285 report documents a footprint that grew to 8.4 GB over 42 days — ~38% of all memory in use on the system, pushing the kernel to memory pressure level 2 — without any signal to the user, and RSS-based observation (`ps`) missed it entirely for weeks. Batty should monitor its own footprint and warn the user before the system starts swapping.

This is a mitigation/observability feature: it ships whether or not the underlying graphics-memory growth turns out to be fixable in Batty or upstream in libghostty. It is independent of the other #0285 children — it ships regardless of what the fixes achieve.

## Relation

- Child of umbrella #0285 (this spec was originally the umbrella's "Expected behavior" section, moved here).
- Independent of the other children.

## Expected behavior

Batty monitors its own memory footprint and warns the user when it crosses a soft limit:

- Batty periodically samples its own `phys_footprint` (e.g. `task_info` with `TASK_VM_INFO` — not RSS, per the measurement trap below). Per-Terminal-Session attribution is a bonus if feasible; a process-level number is the requirement.
- A **configurable soft limit** with a sane default (given ~65 MB of graphics memory per open Terminal Session on the reporting machine, something in the low single-digit GB is a reasonable starting point). Configuration belongs with the app's existing preferences (Settings window).
- Crossing the limit **warns the user** through an existing app affordance — the Bell Feed is the app's notification surface and a natural fit, optionally paired with a System notification when Batty is not frontmost. The implementer picks the exact surface; the requirement is that the warning is visible without the user going looking for it.
- The warning is **actionable**: it states the current footprint and how many Terminal Sessions are open, so the user can decide what to close.
- The warning does **not nag**: once acknowledged, it does not repeat until the situation meaningfully changes (e.g. footprint crosses the next threshold step, or drops below the limit and crosses it again).

**Measurement trap (binding):** `ps -o rss` reported 287 MB while the real `phys_footprint` was 8,546 MB — a **29× under-report**, because RSS excludes compressed and swapped pages (1.9 GB of Batty's footprint was in the compressor). The monitoring feature must read `phys_footprint` via `task_info` with `TASK_VM_INFO`, never RSS.

## Actual behavior

No monitoring, no limit, no warning of any kind.
