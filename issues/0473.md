## Description

In the approved design (#0469, artboards 3 and 4), opening a Project types each Terminal Tab's startup command into that Tab's shell **once the shell is ready**, as if the user typed it and pressed Return. When the command exits, the Tab stays open at the prompt. Before Batty runs a Project's commands for the first time, and again whenever any command changes, a confirmation sheet lists the commands and lets the user open without running them. #0472 builds the Tabs. This issue makes them run their commands, safely.

## Expected behavior

**1. Typed input, not a replaced shell.** Each command is delivered to the Tab's running shell as input followed by Return. Do not use the per-Tab `command` override (`Runtime/TabRuntime.swift:28-33`, `:247-283`, #0282's `pane split -c`), which replaces the shell with the command. Typed input has to handle the following:

- `TerminalViewState.send(_:)` is a **paste** (`libghostty-spm` `State/TerminalViewState.swift:124-139`). Its own doc comment warns that `send("ls\r")` "a shell with bracketed paste on does not run". Deliver the command text, then a real Return key press (`sendKey(.enter)`; `TerminalKey.enter` exists in `Surface/TerminalKey.swift:79`), or another mechanism verified to execute under zsh's and bash's bracketed-paste mode.
- Both calls return `false`/no-op while the Tab has no surface ("view state paste ignored: missing surface"). A surface exists only after the Tab's placeholder first mounts and AppKit moves the view into a window (`docs/view-hierarchy.md`, "First mount of TerminalPlaceholderView" timeline). So the command must wait for the surface **and** the shell.
- Multi-line commands: either reject newlines in the editor (#0474) or send each line with its own Return. Pick one, test it, and say which in the Concepts.md entry.

**2. Readiness is an event, never a delay.** No `asyncAfter`, `Task.sleep` or polling, in production or in tests (`AGENTS.md` "Asynchronous tests"). Signals found while filing:

- **The first OSC 7 working-directory report.** Batty's bundled shell integration emits OSC 7 from the prompt hooks (`shell-integration/zsh/ghostty-integration:64`, `bash/ghostty.bash:151` in the vendored `libghostty-spm`). It reaches `TerminalDelegateProxy.terminalDidChangeWorkingDirectory` (`Runtime/TerminalDelegateProxy.swift:94-97`) and from there the per-Tab `onWorkingDirectoryChange` closure. `AppStateStore.wireWorkingDirectoryReporting(for:)` (`Runtime/AppStateStore.swift:1911-1916`) installs that closure from `PaneView`'s per-Tab `.task` (`Views/PaneView.swift:283-305`). It is a **single closure slot**, so the startup-command hook must compose with the auto-naming handler, not replace it.
- **Surface attach.** `TerminalSurfaceLifecycleDelegate.terminalDidAttachSurface` (`TerminalDelegateProxy.swift:103-105`) says the surface exists but not that the shell has drawn a prompt. Typed-ahead input is buffered by the pty, so it may be acceptable as a fallback for shells without OSC 7 integration (fish, nushell, or a user shell where integration doesn't load). Verify this rather than assume it.
- **Command-finished (OSC 133 D)** is wired too (`TerminalDelegateProxy.swift:99-101`), but it fires after a command, not at the first prompt.

Pick the signal and document the fallback. Then cover the ordering hazard: the pwd closure is installed from `.task` after mount, so the first OSC 7 can race the installation. A Tab whose first report arrived before the hook was installed must still run its command exactly once, for example because the hook checks whether a pwd has already been reported. Exactly once means once per Tab per open. Re-mounting a placeholder, switching Sessions, moving a Tab, or a later `cd` (a second OSC 7) must never re-send.

**3. Trust confirmation.** This is artboard 4, "First open: confirm startup commands".

- The sheet appears when a Project with at least one startup command is opened with "Run startup commands when the Project opens" on, and its current command set's hash differs from the Project's stored `approvedCommandsHash` (#0471).
- The title is "Run N startup commands for "<name>"?". Each command is listed with its position ("Pane 1 · build", then `$ ./build.sh`). Buttons: **Open Without Running** (opens the Session, runs nothing) and **Run Commands** (default). The checkbox reads **"Don't ask again until the commands change"**. When it is checked, Run Commands stores the hash through `ProjectStore`. The footer copy reads "Startup commands run like typed input. Batty asks the first time, and again if a command is edited."
- **The hash** is over the ordered list of (Pane index, Tab index, working directory, command) for every non-empty command. A change to any command, its directory, or its position re-prompts. A title-only change does not. Use a stable digest (SHA-256 over a canonical encoding), not `hashValue`, because that is seeded per process.
- With the run toggle **off**, the Project opens with no sheet and no commands. With it on and the hash matching, the commands run with no sheet.
- **Where the sheet is presented.** The Session does not exist until the user chooses, because the choice decides whether commands run, so attach the sheet to the target content window (`defaultTargetWindow()`). It works the same whether the open came from the picker, the File menu, the palette, the editor's Save & Open, or the CLI. **CLI-initiated opens:** `batty project open` must not hang waiting on an unattended sheet. The app shows the sheet, and the CLI reply returns once the Session exists (#0477). #0477 decides the CLI's exit status and output wording.
- Present the sheet from an event-origin write (the open request), never from `body`/`onAppear` (`docs/swiftui-observation-rules.md`). If AppKit presentation is needed, don't call `makeFirstResponder`/`addSubview` from inside a SwiftUI update.

**4. Flag gate.** The startup-command hook installs only for Tabs created by `openProject`, which can't happen with the flag off. The hook and the sheet still read `featureFlags.projects`, so the gate-site list (#0470) stays complete. Append the sites.

## Acceptance criteria

- A unit test drives the real hook through `TerminalDelegateProxy`/`TerminalViewState`, the same pattern `wireWorkingDirectoryReporting` was built for (its doc comment, `AppStateStore.swift:1903-1909`). Injecting a pwd report causes exactly one delivery of the command text plus Return to a test seam standing in for the surface. A second pwd report and a re-wire deliver nothing.
- A report that arrived **before** the hook was wired still yields exactly one delivery.
- Auto-naming still receives every pwd report when the hook is present (composed, not replaced).
- Hash: identical command sets give identical hashes across process launches (fixed expected digest in the test). Editing a command, its directory, or its order changes the hash. Editing a Tab title does not.
- Trust decision logic is a pure function, unit-tested over these cases: toggle off → run nothing, no prompt; toggle on and hash matches → run, no prompt; toggle on and hash differs → prompt; "Open Without Running" → Session opens, nothing runs, hash unchanged; "Run Commands" with the checkbox → hash stored; without the checkbox → runs, hash unchanged.
- No sleeps, deadline polls, or elapsed-time assertions (`AGENTS.md` "Asynchronous tests"). If a test needs to await delivery, the production code exposes a completion signal (`docs/async-test-seams.md`).
- Manual verification in Batty Beta (in addition to #0478's UI tests). In zsh and in bash, a Project with `./build.sh`-style and `claude`-style commands opens, each command runs in the right directory, and the Tab returns to the prompt after exit. Record the result in the issue. The trust sheet and the "commands ran" behavior get the user's visual sign-off, so mark `resolved`, not `closed`.
- `./build.sh unit` passes and the new tests appear in the output.

## Notes

- **Binding:** `docs/terminal-pane-requirements.md`. Typing into a Tab must not disturb focus, IME marked text, or the pointer/keyboard path. Don't move first responder to deliver input; deliver through the surface API. `docs/view-hierarchy.md`: never reach into `TerminalHostStore` to find a view. Go through the Tab's `terminal` state.
- **Security posture.** #0247 (open) drew the line that a per-project file must never run anything without consent. The trust sheet is that consent. Commands live only in the user's own `projects.json` (per-variant Application Support), never in a repo-committed file. Keep it that way. Reading `.batty/config` or any repo file for commands is out of scope.
- `PasteConfirmation` (`Views/PasteConfirmation.swift`) guards the user's Cmd-V path. It is not involved here. The trust sheet replaces it for this path, so don't route startup commands through it.

## Resolution notes

> 🟢 Resolved 2026-10-12 — Opening a Project types each approved startup command into its Tab's shell once the shell first reports its working directory, behind a trust sheet that asks again whenever the commands, their directories or the root change.

Shells that never report their working directory run nothing; follow-up: [#0479](0479.md). Manual zsh/bash runs, the IME check and visual sign-off on the sheet are owed (#0478 in the Tart VM, then the user).

## Root cause

Starting state: Project Tabs opened as plain shells (#0472). The per-Tab `command:` override replaces the shell, `TerminalViewState.send` is a bracketed paste (a trailing `\r` doesn't execute), and surfaces exist only after a Tab's view mounts — so there was no safe way or moment to run a command.

## Fix

- **Delivery** (`Runtime/StartupCommandDelivery.swift`): each non-blank line, with control and Unicode format (Cf) characters dropped, is pasted and followed by a real Return via the Tab's `TerminalViewState` (`paste(text:)` + `sendKey(.enter)`), exactly once. The view-state path leaves an open IME composition as preedit (`AppTerminalView.sendKey` would commit it onto the executed line).
- **Readiness** (`TerminalDelegateProxy.armStartupCommand`): the first OSC 7 working-directory report, in a slot separate from auto-naming's `onWorkingDirectoryChange`; a report that arrived before arming delivers on arming. The input runs on the next main-queue turn, never inside libghostty's action callback (`ghostty_app_tick`).
- **Trust** (`Model/ProjectStartupTrust.swift`): `Project.startupCommandsHash` — SHA-256 over a length-prefixed encoding of the standardized root and each (pane, tab, directory, command); titles excluded. `decide` → skip / run without prompt / prompt.
- **Flow** (`Runtime/AppStateStore+ProjectStartup.swift`): `requestOpenProject(id:mode:contentFactory:completion:)` is the entry point for every user-facing open. On prompt, a `ProjectStartupTrustRequest` is queued on `defaultTargetWindow()` (`WindowRuntime.pendingStartupTrusts`); no Session exists until answered. `resolveStartupTrust` re-checks the hash and the run toggle (re-asking if either changed), stores the approval when "Don't ask again" is checked, opens, and arms commands only for a newly created Session. Esc/dismiss and window removal complete with `ProjectOpenError.cancelled`. Focusing an already-open Project never prompts or runs.
- **Sheet** (`Views/ProjectStartupTrustSheet.swift`, presented from `SessionDetailView`): per artboard 4 — pluralized title, sanitized rows, "Don't ask again" (on by default), Open Without Running, Run Commands; cancels by the displayed request's id.
- `Concepts.md` (v0.6) documents delivery, readiness, IME and the approval scope; two gate-site rows in `docs/feature-flags.md`.

## Gotchas

- Every user-facing open (#0474 Save & Open, #0475 picker/palette/menu, #0477 CLI) must call `requestOpenProject(..., completion:)`, not `openProject`. Pass `completion:` by label — a trailing closure binds to `contentFactory`. `UITestDriver`'s `openProject` intent still calls `openProject` directly; #0478 needs an intent through `requestOpenProject`.
- The trust sheet shares `SessionDetailView` with the palette, picker and paste sheets: an entry point that starts from a sheet must dismiss it before calling `requestOpenProject`, or the trust sheet may not present.
- Keep startup input on `TerminalViewState`, never `AppTerminalView.sendKey` (it commits IME marked text onto the line Return runs). No unit test pins this; the sink seam stands in for the terminal.
- Only zsh and bash report OSC 7 at runtime: Batty loads shell integration from libghostty-spm's bundle, which ships only those two; the five-shell tree in `Resources/ghostty-runtime/` is copied but never loaded (#0400). See #0479.
- Subagent transcripts in this harness record stream-start `output_tokens`, so Work log output counts and costs are understated.
