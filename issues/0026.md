## Description

The user-facing UI for the Bell Feed (Concepts → Bell Feed). A toolbar button using SF Symbols `bell.badge` (when unseen) / `bell` (when clean) opens a popover listing recent events newest-first. Cmd-Shift-N is the keyboard alternative.

**Acceptance criteria:**
- Toolbar button toggles the popover. Icon switches based on `BellFeedStore.hasUnseen`.
- Cmd-Shift-N also toggles the popover.
- The popover renders a scrollable list of events newest-first.
- Each row shows:
  - Timestamp (relative: "2m ago"; absolute on hover).
  - Path: `<Session> › <Pane› › <Tab>`.
  - Message body (OSC 9) or short preview if available.
  - Unseen indicator if not yet clicked.
- A "Clear all" button at the top of the popover marks every entry seen.
- Click-to-jump on an entry is wired to #0027's flow.

## Notes

- The popover should be keyboard-navigable (up/down through entries, Enter to jump). Accessibility matters here — bell feed is a recovery tool.
- Keep row visuals dense — 200 entries should remain navigable.
- Use `MenuBarExtra` only if we want a menu-bar status item; stick with the in-app toolbar button for v1.

## Root cause

After #0025 the BellFeedStore was populated and the unseen counters propagated, but there was no UI surface — no toolbar button, no popover, no keyboard shortcut. Users had no way to see what bells had fired or to clear them.

## Fix

A standard SwiftUI `.popover` anchored to a toolbar `Button`, plus a Cmd-Shift-N keyboard alternative.

- New `BellFeedView` is the popover content. List + ContentUnavailableView for the empty state. Each row is `BellFeedRow` showing an unseen-dot circle, the resolved `Session › Pane N › Tab` path, the relative timestamp (with the absolute date/time on hover), and the OSC 9 message body if present. The list supports keyboard selection and Return-to-jump via `.onKeyPress(.return)`.
- A "Clear All" button in the popover header calls `AppStateStore.markAllBellsSeen()` which decrements all the unseen counters in one shot.
- New toolbar item in `SessionDetailView` uses SF Symbols `bell.badge` (when `bellFeed.unseenCount > 0`) or `bell` (clean), with `.symbolRenderingMode(.hierarchical)` for a subtle two-tone look. The popover binds to a local `@State` and the Cmd-Shift-N command toggles it via a Notification.
- New "Toggle Bell Feed" command in the `windowArrangement` group of `BattyCommands` with the Cmd-Shift-N shortcut. Posts `Notification.Name.battyToggleBellFeed`; `SessionDetailView.onReceive` flips the popover state. Notification round-trip avoids tying the command to the toolbar's `@State` (commands live outside the view tree).
- A "Mark All Bells Seen" command alongside, disabled when `unseenCount == 0`.
- `AppStateStore.jumpToBellEntry(_:)` implements the click-to-jump flow (also covers #0027): updates `selectedSessionID`, `session.tree.focusedPaneID`, and `pane.activeTabID` to the entry's recorded triple. The popover calls this on row-tap or Return after `markBellSeen(id:)`.

## Gotchas

- **The popover keyboard nav is single-row Return,** not arrow-key traversal. SwiftUI's `List(selection:)` handles up/down arrow movement automatically when focused, but the focus has to be on the list — which only happens after the user clicks a row once. If users complain that they want to "open feed → arrows → enter" without an initial click, look at `.focusable()` on the list or `.defaultFocus(_:_:)` to seed the selection on appear.
- **Path resolution falls through to `"(closed)"`** when the entry refers to a Session/Pane/Tab that no longer exists (e.g. user closed it after a bell fired). The entry stays in the feed for visibility but jumping to it is a no-op (`jumpToBellEntry` early-returns). Consider purging entries on tab/pane/session removal as a follow-up if the dead-entry pile-up becomes annoying.
- **Cmd-Shift-N via NotificationCenter** is a small piece of glue that exists because SwiftUI commands and view-local `@State` don't share a memory space. The Notification name is namespaced (`co.sstools.Batty.toggleBellFeed`) so it doesn't collide. If we add a second view-local action driven by a command, this pattern generalizes; if it's the only one, the cost is one Notification.
- **Window-bringing-forward is a no-op for v1.** PRD §6.1 specifies single-window default, and #0009 builds that path. Multi-window (PRD §6.2 mentions "additional new windows allowed but rare") would need `NSApp.activate` and `window.makeKeyAndOrderFront` plumbing. Out of scope here; revisit if multi-window lands.
- **The bell symbol is hierarchical-rendered** which gives a subtle accent on the badge component — visible on Sequoia and later. On earlier macOS (we target 15+, so we're fine) the renderer falls back gracefully.
