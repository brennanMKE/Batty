# 0005 — Define core data models (Session, Pane, Tab, SplitNode)

|---|---|

## Description

Implement the layout containers from `Concepts.md` as Codable Swift types so every later module has a stable vocabulary. These are the model layer — no view code, no libghostty calls.

**Acceptance criteria:**
- `Session`, `Pane`, `Tab`, and `SplitNode` exist as Swift types matching the shapes described in `Concepts.md` and `PRD.md` §6.2.
- `SplitNode` is an `indirect enum` with `.leaf(Pane)` and `.split(direction:, ratio:, left:, right:)` cases.
- Each container has a stable `id: UUID`, and Tab references its surface via `surfaceID: UUID`.
- All four types are `Codable` and round-trip cleanly through JSONEncoder/JSONDecoder. Verify with a test in `BattyTests`.
- All four types are `Sendable`-compatible (Swift 6 / MainActor default; explicit `Sendable` conformance where it makes sense).

## Notes

- Don't bake in any UI or libghostty types here — these models must be pure value types so persistence (#0029+) can serialize them safely.
- Tab title resolution (focused-surface process → cwd → user override) lives at the view layer; the model just stores an optional override.
- Keep `bellCount` / `lastBellAt` / `unseenBellCount` on the model — they're persisted state, not view state.
