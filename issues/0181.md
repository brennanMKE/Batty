## Description

UI test `BattyUITests.LayoutTests.testThreeColumnProducesThreePanes` (`BattyUITests/LayoutTests.swift:84`) fails with:

```
XCTAssertTrue failed - threeColumn must produce exactly 3 panes; got 1
```

This test was created by [[0162]] as part of the UI test automation suite. The test was previously masked by the `Thread.sleep` runloop-blocking bug fixed in [[0170]] — the failure is now visible on every test run.

## What to investigate

Open `BattyUITests/LayoutTests.swift:84` and trace what state the assertion is checking. Cross-reference [[0162]] for the test's design and acceptance criteria.

The failure is one of:

- **App bug** — the behavior the test asserts on is genuinely broken; fix the app.
- **Test bug** — the test's assertion, setup, or accessibility-identifier expectation is wrong; fix the test.
- **Test infra gap** — a required driver intent or accessibility identifier referenced by the test doesn't exist yet; add it.

Look at the lines around `:84` and at the driver script (if any) in the test's launch call to determine which.

## Root cause

The test passed a layout name to the `applyLayout` driver intent that
does not exist in the `PaneLayout` enum. The enum cases are
`horizontalSplit` (2 panes), `verticalSplit` (2 panes), and
`threeColumns` (3 panes) — but the three failing tests were passing
`twoColumn` / `twoRow` / `threeColumn`. The driver
(`UITestDriver.applyLayout`) calls `PaneLayout(rawValue:)` and returns
silently on `nil`, so the script logged an `unknown layout` notice,
did nothing, and the test saw the default single pane.

## Fix

Resolved by code commit `25aa000`. Updated the layout names passed to
`applyLayout` in the three affected tests to use the actual enum case
names. Verified locally with `scripts/run-ui-tests.sh
BattyUITests/LayoutTests` — all six LayoutTests pass.
