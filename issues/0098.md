# 0098 — Pin BattyKit at the pushed libghostty-spm fork SHA

| | |
|---|---|
| **Status** | open |
| **Module** | Build / GhosttyKit |
| **Platform** | macOS |
| **First seen** | 2026-05-12 |

## Description

`BattyKit/Package.swift` currently depends on `libghostty-spm` via `.package(path: "../../libghostty-spm")`. That works on the developer's machine but means a fresh checkout — or a CI runner, or a notarization VM — can't resolve the dependency without a sibling clone at the right path. For v1.0.0 ship, swap to a `url:` + `revision:` form against the published fork SHA so the build is reproducible from any clean checkout.

Fork commit `8915065` (on `brennanMKE/libghostty-spm` branch `batty-delegates`) carries the `needsConfirmClose` / `processExited` accessors that `#0054` depends on. As of filing, `git ls-remote https://github.com/brennanMKE/libghostty-spm refs/heads/batty-delegates` should show `8915065...`; if it doesn't yet, the prerequisite is to push that commit.

## Acceptance criteria

- `BattyKit/Package.swift`'s `libghostty-spm` dependency is `.package(url: "https://github.com/brennanMKE/libghostty-spm", revision: "<full SHA>")`.
- The revision SHA matches the head of `origin/batty-delegates` on the fork as of the v1.0.0 release.
- `BattyKit/Package.resolved` and `Batty.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` reflect the new pin.
- `xcodebuild -scheme Batty -destination 'platform=macOS' build` succeeds against a fresh derived-data state (no cached local-path checkout).
- `swift test --package-path BattyKit` passes.
- The sibling `../../libghostty-spm` clone is no longer required for a build to succeed.

## Steps

1. Verify the fork is pushed: `git ls-remote https://github.com/brennanMKE/libghostty-spm refs/heads/batty-delegates` — capture the full SHA.
2. Edit `BattyKit/Package.swift`:
   ```swift
   .package(
       url: "https://github.com/brennanMKE/libghostty-spm",
       revision: "<full SHA from step 1>"
   ),
   ```
3. `rm -rf ~/Library/Developer/Xcode/DerivedData/Batty-*` (optional — forces a fresh package resolve).
4. `xcodebuild -scheme Batty -destination 'platform=macOS' -resolvePackageDependencies` — should show `GhosttyKit: https://github.com/brennanMKE/libghostty-spm @ <sha>` instead of `@ local`.
5. `xcodebuild build` + `swift test --package-path BattyKit`.
6. Commit `BattyKit/Package.swift` + both `Package.resolved` files.

## Prerequisites

- **Fork is pushed.** The local libghostty-spm working copy at `/Users/brennan/Developer/brennanMKE/libghostty-spm` is one commit ahead of `origin/batty-delegates` (commit `8915065`). Push that to GitHub before swapping the pin.

## Out of scope

- Tagging the fork with a stable release tag (e.g. `batty-v1.0.0`). Could pin via tag instead of SHA for nicer-looking metadata; not required.
- Upstreaming the delegate additions to `Lakr233/libghostty-spm`. Optional polish; not blocking v1.0.0.

## Notes

- This is the same swap pattern as `#0044`'s second-half resolution. After the swap, the sibling clone is dispensable on developer machines; it's still useful for iterating on the fork itself.
- If a future need adds another fork commit, this becomes "bump the pin to the new SHA" — small, easily-tracked diffs.
