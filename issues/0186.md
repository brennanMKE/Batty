## Description

UI test `BattyUITests.LifecycleTests.testSplitThenCmdWCollapsesPane` (`BattyUITests/LifecycleTests.swift:55`) fails with:

```
XCTAssertTrue failed - Expected pane to collapse after closing its last tab
```

This test was created by [[0094]] as part of the UI test automation suite. The test was previously masked by the `Thread.sleep` runloop-blocking bug fixed in [[0170]] — the failure is now visible on every test run.

## Root cause

The test dispatches `Cmd-D` to split the active pane and polls until
the tab-bar count reaches 2, then dispatches `Cmd-W` and polls until
the tab-bar count returns to 1 (closing the only tab on the new pane
should cascade into removing the pane itself). Both `XCTAssertTrue`
calls (`LifecycleTests.swift:53` and `:57`) are the post-keystroke
`waitFor` polls.

Pre-[[0170]], each test file's duplicated `waitFor` helper used
`Thread.sleep(forTimeInterval: 0.1)` from a `@MainActor` test method,
starving the test process's main runloop and preventing XCUITest's XPC
bridge from delivering the post-keystroke accessibility-tree snapshots
inside the 5s budget. The predicate kept reading the stale tab-bar
count and the assertion failed before the split / collapse was
meaningfully verified.

The app-side Cmd-D split and Cmd-W close-and-collapse routing is
correct; the new tab-bar appears after the split and is removed after
the cascade well inside 5s now that the centralized `waitFor`
(commit `eb00412`) pumps the runloop via `RunLoop.run(until:)` between
predicate evaluations.

## Fix

No code change. The fix landed transitively with [[0170]]
(commit `eb00412`'s `waitFor` overhaul). This matches the resolution
pattern for sibling issues [[0174]], [[0175]], [[0178]], [[0179]],

## Gotchas

- The test's collapse assertion depends on the app's cascade rule
  "closing the last tab on a non-root pane removes the pane" — verified
  indirectly via `tabBarCount == 1` rather than a dedicated pane-count
  identifier. If a future refactor adds tab-bars that aren't pane-scoped
  (e.g. a window-level tab bar) the predicate would need tightening to
  match a pane-scoped identifier prefix.
- Both `Cmd-D` and `Cmd-W` rely on XCUITest's `typeKey` awaiting
  `Wait for co.sstools.Batty.beta to idle` plus the `waitFor` runloop
  pump to surface the updated accessibility-tree state. If a future
  refactor switches to a non-idling key dispatch path, the 5s `waitFor`
  budget should remain generous enough — but the dependency is real.
