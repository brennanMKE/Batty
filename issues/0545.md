# 0545 — Help and Concepts.md say the Sidebar's right-click menu has Duplicate, which it doesn't

| | |
|---|---|
| **Status** | open |
| **Module** | Docs / Sidebar |
| **Platform** | macOS |
| **First seen** | 2026-11-03 |

## Description

The in-app Help tells users to right-click a Session and choose **Duplicate**, but the Sidebar row's context menu has had no such item since #0153 removed it (39e9298f). A user following Help finds nothing to click. The only way to duplicate a Session is the Command Palette's **Duplicate Session** row, and Help doesn't mention it.

Documentation only. Low severity, not a 1.3.5 blocker. The wrong text has already shipped: at tag `v1.3.4` both Help pages and `Concepts.md` make the claim, and `SessionSidebarView.swift` has no Duplicate item.

## Steps to reproduce

1. Open Help and read **Sessions > Duplicating a session**.
2. Right-click a Session row in the Sidebar.

## Expected behavior

Help and `Concepts.md` name the entry point that exists: Command Palette (`Cmd-Shift-P`) > **Duplicate Session**, which acts on the selected Session.

## Actual behavior

The menu has Rename, Reset Name, Set Color, Reset Color, Set Session Theme, Clear Session Theme, Set Session Background, Clear Session Background, Mute/Unmute Notifications, the Project save items and Close, some of them conditional. None of them duplicates the Session.

## Notes

Confirmed against the code on `main` (c7f75339):

- `BattyKit/Sources/BattyKit/Views/SessionSidebarView.swift:456-508`: the row's `.contextMenu`, with no Duplicate item.
- `BattyKit/Sources/BattyKit/Views/CommandPaletteView.swift:82-93`: `extra:duplicateSession`, titled "Duplicate Session". A grep of `BattyKit/Sources` and `Batty` for `duplicateSession` finds no other caller in a view or menu; `AppStateStore.duplicateSession` forwards to `WindowRuntime.duplicateSession`.
- `issues/0153.md`: its fix notes record removing the "unintentional" Duplicate action from the Sidebar. The menu item itself dates from #0011.

Lines that make the wrong claim:

- `BattyKit/Sources/BattyKit/Help/02-sessions.md:24`: "Right-click and choose **Duplicate**." The rest of the paragraph still holds: the title gets a `Copy` suffix and the new Session starts with one empty shell (`WindowRuntime.duplicateSession`).
- `BattyKit/Sources/BattyKit/Help/01-overview.md:18`: "Right-click a row for Rename, Duplicate, Mute, or Close."
- `Concepts.md:64`: "right-click to Rename / Duplicate / Set Color / Set Session Background / Close". Line 65 ("Duplicate doesn't copy it") is about the behavior and is still accurate.
- `PRD.md:148`: "Context menu on each session: Rename, Duplicate, Close." This is the original product spec, so whoever plans this should decide whether to update it. The report didn't name this line.

Checked and not affected:

- `Help/04-tabs.md:48` and `PaneView.swift:670`: Duplicate Tab is a separate action and does exist on the tab chip menu.
- `docs/multi-window-design.md:240` and `docs/pane-view-lifecycle.md:512` name the `duplicateSession` method, not a menu item.
- `README.md`, `tools/demo` and the `website/` pages have no claim about Duplicate Session. The changelog's "Duplicate Tab" is about Tabs.

Help ships in the app through `.copy("Help")` in `BattyKit/Package.swift`, so a Help fix reaches users only with a new release.

`Concepts.md:64` is also incomplete apart from this: it leaves out Mute Notifications, Set Session Theme and the Project save items. Whoever edits the line can list them at the same time.

The opposite fix, putting Duplicate back on the Sidebar menu, would reverse #0153's decision, so it needs a user decision. This report only asks for the docs to match the app.
