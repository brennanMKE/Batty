|---|---|

## Description

Set up code signing with a Developer ID Application certificate and Apple's notary service so direct downloads of Batty don't get blocked by Gatekeeper. Required because terminal apps don't fit App Store sandbox rules (PRD §11).

**Acceptance criteria:**
- A signed `.app` and `.dmg` can be produced from a clean checkout via a single command (e.g. `make release` or a `Scripts/release.sh`).
- The signed `.app` passes `spctl --assess --verbose=4 Batty.app`.
- Notarization succeeds: `xcrun notarytool submit ... --wait` returns Accepted.
- The `.dmg` is stapled (`xcrun stapler staple`).
- Hardened runtime is enabled in build settings.
- The release script is documented in CLAUDE.md or a Scripts/README so future me remembers how to use it.

## Notes

- Team ID is already set in `Configuration/Build.xcconfig` (`DEVELOPMENT_TEAM = XV8BAAVZ6V`).
- Notarization credentials should be stored in a notarytool keychain profile, not committed.
- If terminal apps require additional entitlements (e.g. `com.apple.security.cs.disable-library-validation` for libghostty's loaded resources), add them in this issue.
