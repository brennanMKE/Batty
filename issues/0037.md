## Description

Set up code signing with a Developer ID Application certificate and Apple's notary service so direct downloads of Batty don't get blocked by Gatekeeper. Required because terminal apps don't fit App Store sandbox rules (PRD §11).

**Acceptance criteria:**
- A signed `.app` and `.dmg` can be produced from a clean checkout via a single command (e.g. `make release` or a `Scripts/release.sh`).
- The signed `.app` passes `spctl --assess --verbose=4 Batty.app`.
- Notarization succeeds: `xcrun notarytool submit ... --wait` returns Accepted.
- The `.dmg` is stapled (`xcrun stapler staple`).
- Hardened runtime is enabled in build settings.
- The release script is documented in CLAUDE.md or a Scripts/README so future me remembers how to use it.

## Notes

- Team ID is already set in `Configuration/Build.xcconfig` (`DEVELOPMENT_TEAM = XV8BAAVZ6V`).
- Notarization credentials should be stored in a notarytool keychain profile, not committed.
- If terminal apps require additional entitlements (e.g. `com.apple.security.cs.disable-library-validation` for libghostty's loaded resources), add them in this issue.

## Root cause

Standalone-distribution Mac apps need a signed bundle and a notarization round-trip. Without the scripted pipeline, this is a multi-step manual workflow (archive → export → sign → notarize → wait → staple → DMG → verify) that's easy to get wrong.

## Fix

The pipeline is in place:

- **`scripts/release.sh`** — full pipeline (archive → export → sign → notarize → wait → staple → DMG → verify). Preflight checks the `Developer ID Application` certificate is in the keychain and the `Batty-notary` keychain profile exists; emits an actionable error otherwise. Output: `dist/Batty-<sha>.dmg`.
- **`scripts/verify-dmg.sh <path>`** — verifies signing, notarization, stapling, and Gatekeeper acceptance under quarantine.
- **`scripts/setup-keys.sh`** — one-time setup of the `Batty-notary` keychain profile via `xcrun notarytool store-credentials`.
- **`Configuration/Build.xcconfig`** — `DEVELOPMENT_TEAM = XV8BAAVZ6V`, `CODE_SIGN_STYLE = Automatic`, hardened runtime is set on the Batty target via `ENABLE_HARDENED_RUNTIME = YES` in `project.pbxproj` (both Debug and Release).
- **`scripts/RELEASE.md`** (added in #0039) — end-to-end checklist for cutting a release.
- **`Ship-v1.md`** (added in #0039) — the success-criteria gate.

## Gotchas

- **The actual notary round-trip is user-gated** per CLAUDE.md ("Do not run `scripts/release.sh` autonomously. Notarization submits the binary to Apple, which counts as modifying a shared system."). The script's preflight already covers the failure modes (missing cert, missing keychain profile), so the user gets clear errors instead of a half-built bundle if they invoke it before setup.
- **Notarytool sometimes takes 2–10 minutes** for a small bundle. The script uses `--wait` so the round-trip blocks; that's intentional. If the apple server queue is long, the agent shouldn't autonomously retry.
- **`#0003`'s Run Script build phase adds the terminfo/shell-integration resources** into the bundle before signing. Make sure the resources are vendored (`Resources/ghostty-runtime/`) before running the release script — otherwise the bundle ships without shell-integration. The preflight doesn't currently check this; `scripts/verify-dmg.sh` could be extended to assert the sentinel file is present in the stapled bundle.
- **Custom entitlements (`com.apple.security.cs.disable-library-validation` etc.) are NOT set.** libghostty is statically linked into the app binary via the xcframework, so library-validation should hold. If a future libghostty version starts dynamically loading additional dylibs, add the entitlement and re-test signing.
- **`Build.xcconfig` carries the team ID and bundle id;** any rotation lands there. The release script reads the team ID from a constant at the top — keep them in sync.
