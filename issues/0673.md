## Description

Four UI tests that #0650 added or changed fail in the VM at the check that the Background Images picker opened on the expected tab. Each reads `app.radioButtons["<tab name>"].firstMatch.isSelected` on the picker's segmented tab control and gets `false`. These checks came in with #0650 (`11a7ceb1`) and had never run in a VM before. They first ran in VM run `20261118-194744-92434`, on branch `issue/0659` rebased onto `main` (#0659 does not change these lines).

Failure messages from that run (`build/ui-tests/20261118-194744-92434/xcodebuild.log` in the `issue-0659` worktree):

- `BackgroundSetsTests.swift:76` `testPickerOpensOnBackgroundSetsWithNoImage`: "the picker did not open on Background Sets"
- `BackgroundSetsTests.swift:103` `testReopeningAfterPickingASetImageShowsItSelectedAndInView`: "the picker did not open on Background Sets"
- `BackgroundCatalogSettingsTests.swift:124` `testRemovingACatalogKeepsTheBackgroundInUse`: "the picker did not open on Background Sets"
- `BackgroundImagesWindowTests.swift:484` `testReopeningShowsTheCurrentMyImagesImageSelectedAndInView`: "the picker did not open on My Images"

In each case the log shows the `"<tab>" RadioButton` was found (the `waitForExistence` passed). Only `isSelected` was false.

The fifth failure in that run, `BackgroundSetsTests/testReturnAfterASingleClickClosesThePickerWithThatImage` ("Return did not close the picker"), is #0659's own work and is not part of this issue.

### Likely cause: the test is wrong, not the app

- **The check fails for both tabs.** It fails on "Background Sets" (three tests) and on "My Images" (one test). That includes the simplest case: no current image, where `BackgroundPickerOpening` picks Background Sets and `BackgroundPickerOpeningTests` covers that decision at unit level. If the app opened on the wrong tab, at least one of the two directions would pass.
- **The tab control is a segmented `Picker`.** In `BattyKit/Sources/BattyKit/Views/BackgroundImagesView.swift:48-56` on `main` (`:52-60` on `issue/0659`): `Picker("", selection: tabBinding) { … }.pickerStyle(.segmented).labelsHidden()`, with `.accessibilityIdentifier("background-images.tab")` on the control. On macOS this is an `NSSegmentedControl`. Accessibility shows each segment as an `AXRadioButton`, and the chosen segment is reported through `AXValue` (1 or 0), not `AXSelected`. XCUITest's `isSelected` reads `AXSelected`, so it is `false` for every segment. Clicking a segment (`BackgroundSetsTests.swift:24`, `:523`; `BackgroundImagesWindowTests.swift:107`) works, which is why the query itself is fine. None of the existing UI tests read a segment's selected state.
- **The app's tab state is set before the sheet shows.** `onAppear` (`BackgroundImagesView.swift:88-97` on `main`) sets `tab` from `model.opening(forCurrent:)`. The binding's getter falls back to `.backgroundSets` while `tab` is nil (`:199-203`).
- **Unconfirmed.** Because `ProjectsUITestCase` sets `continueAfterFailure = false` (`BattyUITests/Support/ProjectsHarness.swift:145`), each test stopped at the tab check. The assertions after it (Background Sets root shown, current cell selected and in view) never ran. So the run does not prove that the picker opened on the right tab. The planner should confirm the AX value with a debug dump of the segment (`value`, `isSelected`) in a filtered VM run before relying on it.

The same check also appears at `BattyUITests/BackgroundCatalogSettingsTests.swift:100` (`testAddedCatalogsSetsAppearInBackgroundSets`). That test was not in this filtered run but will fail the same way.

### Fix direction

Replace the `isSelected` checks with a check that matches how a segment reports its state. Either read the segment's `value` (selected is `1`, as an `NSNumber`), or check for content that only the chosen tab shows: `background-sets.root` for Background Sets, and the My Images grid or `background-images.empty` for My Images. Put the check in one shared helper rather than in each test. Do not change the app unless the debug dump shows it really opens on the wrong tab.

## Plan

Planned 2026-11-18 against `issue/0673` at `c1f7be6e` (#0659 merged). The premises hold:

- The tab control is `Picker("", selection: tabBinding) { Text("My Images")…; Text("Background Sets")… }.pickerStyle(.segmented).labelsHidden()` with `.accessibilityIdentifier("background-images.tab")` (`BattyKit/Sources/BattyKit/Views/BackgroundImagesView.swift:52-60`).
- The tab is decided once in `.onAppear` (`:89-97`) and only changes after that through `tabBinding.set` (`:204-212`), which a segment click calls.
- The tab is reported by content that only one tab builds:
  - `switch tab` (`:62-75`) builds `BackgroundSetsView` only on Background Sets. Its scroll area always carries `background-sets.root` (`BackgroundSetsView.swift:88`), whether the catalog is empty, loading or loaded.
  - The bottom bar shows `background-images.add` and `background-images.total` only when `tab == .myImages` (`BackgroundImagesView.swift:243-253`, `:262-263`). This holds whether My Images is empty or has a grid.
- The checks to replace (grep `isSelected` and the tab names across `BattyUITests`):
  - `BackgroundSetsTests.swift:76` (`tab.isSelected`) and `:103`.
  - `BackgroundCatalogSettingsTests.swift:100` and `:124`.
  - `BackgroundImagesWindowTests.swift:484` (in `testReopeningShowsTheCurrentMyImagesImageSelectedAndInView`).
  - The other `isSelected` reads (`BackgroundImagesWindowTests.swift:485/510/556`, `BackgroundSetsTests.swift:105/278`, `RemindersPopoverTests`, `ProjectsHarness.swift:240`) are on grid cells, rows or menu items, not segments. They stay. The cells get `.isSelected` from `accessibilityAddTraits`, and `:510`/`:556`/`:278` passed in VM run `20261118-203728-69975`.

### Decision: read the tab from its content, in one shared helper. No app change.

- **Content, not the segment.** `background-sets.root` and `background-images.add` exist only on their own tab, by the `switch`/`if` above. That is exactly what "the picker opened on tab X" means to a user. The check does not depend on how AppKit encodes a segment's state (`AXValue` versus `AXSelected`), which is the very thing that broke here.
- **Rejected: the segment's `value`.** It is probably `1`/`0`, but that is unconfirmed, and its type (`NSNumber` or `String`) varies by OS. It is still worth recording, so the helper's failure message includes it and the VM dump below confirms it.
- **Rejected: an app-side accessibility value for tests.** It is not needed, since the content markers already exist in the app.
- **It cannot pass by accident.** The helper requires the expected marker present **and** the other tab's marker absent. The two markers come from exclusive branches of one `tab` value, so a picker on the wrong tab shows the other marker and fails. A picker that never decided (`tab == nil`, `Color.clear`) shows neither and fails too. The test below proves it by switching tabs and watching the reading follow.

### Files

**`BattyUITests/Support/ProjectsHarness.swift`.** Add next to `openPaneBackgroundPicker` (`:400-412`), in the same `ProjectsUITestCase` extension:

```swift
enum BackgroundPickerTab: String { case myImages = "My Images", backgroundSets = "Background Sets" }

/// The tab the Background Images picker shows, read from content only that tab builds:
/// a segment reports its state through AXValue, not AXSelected, so `isSelected` is false for both.
/// nil when neither or both show.
@MainActor func backgroundPickerTab(in app: XCUIApplication) -> BackgroundPickerTab?

/// Waits up to `timeout` for `backgroundPickerTab == tab`; the failure message names what was seen
/// and each segment's `value` and `isSelected`.
@MainActor func assertBackgroundPickerTab(_ tab: BackgroundPickerTab, in app: XCUIApplication,
    timeout: TimeInterval = 5, file: StaticString = #filePath, line: UInt = #line)
```

- `backgroundPickerTab` reads `element("background-sets.root", in: app).exists` and `element("background-images.add", in: app).exists`. It returns `.backgroundSets` or `.myImages` when exactly one exists, and nil otherwise.
- `assertBackgroundPickerTab` uses `waitFor({ self.backgroundPickerTab(in: app) == tab }, timeout:)`. On failure it builds a message from a private `segmentState(in:)`, for each segment: `"\(label): value=\(String(describing: rb.value)) isSelected=\(rb.isSelected)"`. The message reads "the picker did not open on \(tab.rawValue); saw \(seen) [segments]".
