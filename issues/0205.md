## Description

UI test `BattyUITests.TabRenameTests.testResetActiveTabTitleClearsOverride` (`BattyUITests/TabRenameTests.swift:115`) fails with:

```
XCTAssertTrue failed - A chip with the default title should appear after reset
```

This test was created by [[0160]] as part of the UI test automation suite. The test was previously masked by the `Thread.sleep` runloop-blocking bug fixed in [[0170]] — the failure is now visible on every test run.

## Root cause

Two compounding problems, both unrelated to the rename logic the test was nominally exercising:

1. **Tab-chip accessibility identifiers were being swallowed by the parent tab-bar.** `PaneView.swift` applied `.accessibilityIdentifier("tab-bar.<uuid>")` to the `SlidingTabBar`. SwiftUI on macOS folds a container that has an identifier into a leaf and propagates that identifier down to every child Button. Dumping the accessibility tree confirmed every chip showed `identifier: 'tab-bar.<uuid>'` and the inner `.accessibilityIdentifier("tab-chip.<title>")` was dropped — so `NSPredicate(format: "identifier BEGINSWITH 'tab-chip.'")` returned zero matches. All four `TabRenameTests` plus all four `TabChipRenderingTests` failed on the same root cause; the rename / reset / home-dir specifics in each test were irrelevant.

2. **The UI test runner could not even launch on this machine.** Xcode builds `BattyUITests-Runner.app` by copying Apple's stock XCTRunner template (Apple-signed) and dropping our xctest bundle into `PlugIns/` without re-signing the outer app, leaving a signature that no longer matches its on-disk resources. `spctl` reports "code has no resources but signature indicates they must be present"; AppleSystemPolicy treats that as a tampered Apple binary and translocates the runner to `~/.Trash` before xcodebuild can bootstrap the test session. The "move runner to Trash" prompt blocked all UI test work until the runner was re-signed ad-hoc.

## Fix

1. Added `.accessibilityElement(children: .contain)` to the `SlidingTabBar` parent in `PaneView.swift` so the tab bar is declared as a container rather than a leaf. Children stay as discrete accessibility elements with their own identifiers; the bar keeps its own `tab-bar.<uuid>` identifier (still used by `DragDropTests`, `KeyboardShortcutTests`, `LifecycleTests`, `TabChipRenderingTests`); and the chip's `tab-chip.<title>` identifier survives.

2. Added `scripts/run-ui-tests.sh` to repair the runner signature after every build. It runs `build-for-testing`, re-signs `BattyUITests-Runner.app` and `Batty Beta.app` ad-hoc with `codesign --force --deep --sign -`, then runs `test-without-building`. Documented in `CLAUDE.md` so subagents and the user invoke `scripts/run-ui-tests.sh ...` instead of raw `xcodebuild test` for UI tests.

Verified all six `TabRenameTests` pass and all four `TabChipRenderingTests` pass after the fix. `KeyboardShortcutTests` (5/5) also pass. The one failing test in adjacent runs (`LifecycleTests.testCmdOptionNCreatesSession`) is unrelated — it asserts on session-row creation via Cmd-Option-N, not on chip identifiers.

The same code change resolves the three sibling issues that shared this root cause: [[0202]] (`testEmptyRenameIsNoOp`), [[0203]] (`testRenameActiveTabUpdatesChipTitle`), [[0204]] (`testRenameWinsOverHomeDirTilde`).

## Files changed

- `BattyKit/Sources/BattyKit/Views/PaneView.swift` — added `.accessibilityElement(children: .contain)` to the `SlidingTabBar` parent so chip identifiers are not swallowed.
- `scripts/run-ui-tests.sh` — new wrapper that re-signs the test runner ad-hoc after `build-for-testing` to keep Gatekeeper / AppleSystemPolicy from trashing it. Committed separately from the code fix because it's test infra, not a #0205 fix per se.
- `CLAUDE.md` — added a note pointing future contributors at `scripts/run-ui-tests.sh` for UI tests.

## Gotchas

- The `com.apple.provenance` xattr macOS attaches to ad-hoc-signed binaries cannot be removed via `xattr -d` even with `-r`. Removing the broken signature with `codesign --force --deep --sign -` and replacing it with a valid ad-hoc signature is what actually stops the trash-prompt.
- `.accessibilityElement(children: .contain)` is the SwiftUI macOS escape hatch for "this view has an identifier of its own AND nested children with their own identifiers". `.combine` (the more commonly recommended modifier) merges children into the parent and would have eaten the chip elements. `.contain` is what's needed when both the parent and children are individually queryable.
- The test runner re-sign trick is local-build-only. Release builds via `scripts/release.sh` use a Developer ID identity and don't hit this.
