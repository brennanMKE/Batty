## Description

Child of #0689. User decision D (2026-11-19): "Tailnet: detect automatically — `tailscale` in PATH and `tailscale status --json` with `.BackendState == "Running"` (parse the JSON; jq not required). Serve a port to the tailnet with `tailscale serve --bg <port>`; the resulting URL comes from the status JSON (Self.DNSName). `tailscale serve` changes the tailnet serve config; it runs only when the user/agent asks to share on the tailnet, and Batty offers turning it off."

### Facts checked 2026-11-19

- `tailscale serve --help` (this host's `/usr/local/bin/tailscale`): `tailscale serve --bg 3000` exposes `127.0.0.1:3000`; `--https <port>` is "the default mode"; subcommands `status [--json]`, `reset`, `clear`; flags `--http`, `--https`, `--set-path`, `--bg`.
- Tailscale docs (`tailscale.com/kb/1242/tailscale-serve`): "To turn off a `tailscale serve` command, you can add `off` to the end of the command you used to turn it on" (e.g. `tailscale serve --https=443 … off`); the target is optional in `off` commands but all original flags are required; `tailscale serve reset` clears the whole config. HTTPS uses an automatically provisioned certificate.
- So `tailscale serve --bg 3000` serves `https://<Self.DNSName without trailing dot>/` on **443**, and a second server shared the same way would replace that mapping. The docs page did not show the exact URL output; the plan confirms it on this host with `tailscale serve status --json` (read-only).

### Tailscale CLI facts (verified 2026-11-19, read-only)

Verified on this host (Tailscale 1.102.4). Only `--help`, `status --json` and `serve status --json` were run.

- **CLI location.** `/usr/local/bin/tailscale` is a 2-line `sh` wrapper that execs `/Applications/Tailscale.app/Contents/MacOS/Tailscale "$@"`. The app binary is the CLI.
- **PATH.** A Finder-launched app's `PATH` lacks `/usr/local/bin` and `/opt/homebrew/bin`, so the locator checks those paths explicitly.
- **`tailscale status --json`.** Top-level keys include `BackendState`, `Self`, `CertDomains`, `MagicDNSSuffix` and `CurrentTailnet`. Here `BackendState == "Running"` and `Self.DNSName == "<host>.<tailnet>.ts.net."` (trailing dot). `CertDomains == ["<host>.<tailnet>.ts.net"]` and is absent or empty when HTTPS certificates are off. A logged-out node reports `"NeedsLogin"`; others are `"Stopped"`, `"Starting"` and `"NoState"`.
- **`tailscale serve status --json`.** It prints `{}` here: no mappings, and none may be created by any agent.
  - Shape, from Tailscale's `ipn.ServeConfig` (Go field names as JSON keys): `{"TCP":{"3000":{"HTTPS":true}},"Web":{"<host>.<tailnet>.ts.net:3000":{"Handlers":{"/":{"Proxy":"http://127.0.0.1:3000"}}}}}`.
  - Unknown keys (`AllowFunnel`, `Services`, `Foreground`) are ignored. The user checklist confirms the shape on a real share.
- **Turning a mapping on.** `serve --bg` persists until disabled; `--https=<port>` is the default mode.
  - Per `serve_v2.go`, the printed URL is `https://<host>:<port>/`, with no `:443` on 443.
  - `--yes` only skips the confirmation for deleting **several** handlers on one port. It does not gate overwrites, and no check stops a new mapping from replacing an existing one on the same port. So Batty checks `serve status` first.
- **Turning a mapping off.** The docs say: "add `off` to the end of the command you used to turn it on"; "the `<target>` argument is optional, but all original flags are required". `serve_v2.go` accepts `--bg` together with `off`.
  - Without `--set-path`, `off` removes **every** handler on that port. With more than one handler it prompts, and its default answer is yes.
  - So Batty runs `off` only when the port holds exactly our single `/` handler, never passes `--yes`, and gives the child `/dev/null` stdin.
- **HTTPS not enabled.** The CLI runs an interactive "enable HTTPS" flow (`enableFeatureInteractive`) that can wait on the user. So Batty refuses up front when `CertDomains` lacks the node's name, and bounds every call with a timeout.

**Commands Batty runs (exact argv; nothing else ever):**
```
tailscale status --json
tailscale serve status --json
tailscale serve --bg --https=<N> http://127.0.0.1:<N>        # on
tailscale serve --bg --https=<N> http://127.0.0.1:<N> off    # off: the on argv + "off"
```
The tailnet port is always the local port. Because `127.0.0.1` is explicit, the stored `Proxy` is exactly `http://127.0.0.1:<N>`, and that value is what identifies Batty's mapping. Batty never runs `reset`, `clear`, `funnel` or `--yes`.

### Grammar (decided; amends "Expected behavior")

```
batty server tailnet (<id> | --port N) [--off] [--json]   share on the tailnet / stop sharing
batty server share   --port N … [--tailnet]               share, then share on the tailnet
```
- **One verb with `--off`, not `tailnet on|off <id>`.** ArgumentParser handles an optional `<id>` positional plus an `on|off` positional poorly. One verb is one MCP tool (`server_tailnet`), and it reuses `controlRequest(id:port:pane:)`.
- **`--tailnet` goes on `share` only.** `start` doesn't take it: an agent runs `server start … && server tailnet --port N`. `start` can gain it later through a plain optional field.
- Any server kind can be shared (terminal, external, static), because all of them listen on `127.0.0.1`. `server tailnet` doesn't require the server to be listening yet; until it is, Tailscale answers 502.
- `server tailnet` with no `--off` on an already shared server is a no-op success, so the verb is idempotent. `--off` on a server Batty isn't sharing:
  - when no mapping exists on that port, it is a no-op success;
  - when a mapping exists that Batty didn't make, it fails with `notOurs`, and nothing runs.
- **Output.** Plain output is the server id, then the tailnet URL on a second line when it is set. `--json` prints `ServerReply`, which now includes `tailnetURL`.
- **`share --tailnet` when the tailnet step fails.** The share itself stands, and the reply carries `tailnetError`. The CLI prints the reply, then `batty: tailnet: <message>` on stderr, and exits `XPCExitCode.requestFailed`.

### Behavior

**`TailnetSharing`** (new, `@MainActor @Observable`, one per `AppStateStore`, `store.tailnet`)
- **Observed state:** `public private(set) var status: TailnetStatus?`. Ownership state is `@ObservationIgnored`:
  - `owned: Set<UInt16>`, the ports whose mapping Batty created;
  - `pending: [UInt16: Task<Void, Never>]`, which serializes the operations on each port, each one awaiting the previous one;
  - `lastRefresh: Date?`, `now: () -> Date`, `runner: TailscaleCommandRunning` and `locate: () -> URL?`.
- **`TailnetStatus`:**
  - `.unavailable`: no CLI was found, or the runner failed or timed out on `status --json`.
  - `.notRunning(backendState: String)`.
  - `.running(dnsName: String, httpsEnabled: Bool)`. `dnsName` has the trailing dot stripped. `httpsEnabled` is `CertDomains` containing `dnsName`. `Running` with a missing `Self` or an empty `DNSName` is `.notRunning("NoDNSName")`.
- `var offersSharing: Bool` is true only for `.running`. The row menu reads it.
- **Detection:** `refreshStatusIfStale() -> Task<Void, Never>?`.
  - It runs `status --json` off the main actor through the runner and writes `status` when the task completes.
  - Results are cached for 10 s.
  - It does nothing while `ServerRegistry.entries` is empty.
  - Callers, both event or tick origin: `registerServer`, and the Servers toolbar button's action when it opens the popover. Never `body`, `onAppear` or `onChange`.
  - Tests await the returned Task.
- **`share(entry:) -> Task<Result<URL, TailnetError>, Never>`** (chained on `pending[port]`):
  1. Locate the CLI, then a fresh `status --json` (writes `status`). The status must be running with HTTPS enabled, or the share fails with the matching error.
  2. `serve status --json` → `TailscaleServeConfig`. Then check port `N`:
     - `isOurs(port:N, dnsName:)`: `TCP["N"].HTTPS == true` and `Web["<dns>:N"].Handlers` is exactly `["/": Proxy "http://127.0.0.1:N"]` (trailing `/` tolerated). The mapping is already there: if `N ∈ owned`, keep it owned; otherwise **adopt** it. Set the URL, don't add `N` to `owned`, and don't run serve.
     - The port has any other TCP or Web entry: fail with `portTaken(N)`.
  3. Run the on argv, with a 20 s timeout. A nonzero exit fails with `commandFailed(message)`, using stderr, else stdout, trimmed to 400 chars. A timeout fails with `timedOut(output)`.
  4. Read `serve status --json` again and require `isOurs`. If it doesn't hold, fail with `notApplied`. If it does, insert `N` into `owned`.
  5. On success, set `entry.tailnetURL = TailnetURL.make(dnsName:port:)` and clear `entry.tailnetError`. On failure, set `entry.tailnetError = error.message` and leave `tailnetURL` unchanged. `entry.isTailnetBusy` is true while the operation is in flight.
- **`unshare(port:entry:) -> Task<Result<Void, TailnetError>, Never>`** (chained):
  - If `N ∉ owned`, clear `entry?.tailnetURL`, which covers an adopted mapping. Without `--off` semantics there is nothing more to do. The CLI `--off` path runs `serve status` and returns `notOurs` if a foreign mapping sits on `N`.
  - If `N ∈ owned`: run `serve status --json`. If `isOurs`, run the off argv (20 s timeout). Otherwise log "mapping on N changed; leaving it" and run nothing. Then remove `N` from `owned`, whether or not the off argv ran, and clear the URL. A failed off records `entry?.tailnetError` and keeps `N` owned, so quit retries it.
- **Registry hook.** `ServerRegistry` gains `@ObservationIgnored public var onRemove: ((ServerEntry) -> Void)?`. `remove(id:)` calls it after removing the entry and before `tearDown()`. `AppStateStore.init` sets it to `{ [weak self] e in self?.tailnet.entryRemoved(port: e.port) }`, which calls `unshare(port:entry:nil)` when `port ∈ owned`.
  - This covers stop and finish, `unshare` (CLI and Remove from List), crash and teardown.
  - The hook runs from a tick or an event, never from view code. Starting the subprocess Task is not an observed-state write hopped into a Task: the only observed writes (`entry.tailnetURL`/`tailnetError`) land at task completion, on an entry that is already out of the list.
- **Quit.** `removeOwnedMappingsForQuit() async` holds the core logic and is unit-tested. `removeOwnedMappingsSynchronouslyForQuit(timeout: 5)` wraps it, running it on a detached task and waiting on a semaphore. It is called from `applicationWillTerminate` after `tearDownAllPaneContentSynchronouslyForQuit`, and does nothing when `owned` is empty.
  - Blocking here is acceptable for the same reason as the pane teardown (the app is quitting; see the existing comment there).
  - It logs every port it turns off, and every port it leaves because the mapping changed.
  - **Default, per the Decisions block: removal at quit happens without a dialog.** See Open question 1.
- **`ProcessTailscaleCommandRunner`** (production, `nonisolated`, `Sendable`): `run(executable:arguments:timeout:) async -> TailscaleCommandResult { exitCode, stdout, stderr, timedOut }`.
  - It runs the `Process` inside `Task.detached` with stdin `FileHandle.nullDevice`.
  - It drains stdout and stderr concurrently through two `readDataToEndOfFile` calls on separate detached tasks, so a full pipe can't wedge the child (the hazard `LMStudioCLI.runPs` documents).
  - A timeout fires `ProcessSignal.send(SIGTERM, to:)`, then `SIGKILL` 1 s later, and sets `timedOut`.
  - No main-actor waits.
- **`TailscaleExecutableLocator.locate(environmentPATH:isExecutable:) -> URL?`** checks, in order:
  1. each `PATH` entry + `/tailscale`;
  2. `/usr/local/bin/tailscale`;
  3. `/opt/homebrew/bin/tailscale`;
  4. `/Applications/Tailscale.app/Contents/MacOS/Tailscale`.
- **UI-test runner.** With `BATTY_UI_TEST_FAKE_TAILSCALE=running|absent` in the environment, `AppStateStore` builds `TailnetSharing` with `UITestTailscaleRunner` (in `BattyKit/Testing`) and a locator returning `/fake/tailscale`, or nil for `absent`.
  - The runner answers `status --json` with a canned Running status (`batty-vm.example.ts.net.`, CertDomains set).
  - It keeps an in-memory serve config that the on/off argvs mutate, and it never spawns a process.
  - With the variable unset, it is the production runner.
- **Errors** (`ServerXPCError.tailnet(String)`, message passed through; `TailnetError.message`):
  - absent: "Tailscale isn't installed (no tailscale command found)"
  - `NeedsLogin`: "Tailscale is logged out; log in, then try again"
  - any other non-Running state: "Tailscale isn't running (state: <BackendState>)"
  - `NoDNSName`: "Tailscale reports no MagicDNS name for this Mac; turn on MagicDNS in the admin console"
  - HTTPS off: "HTTPS certificates aren't enabled for this tailnet; turn them on in the Tailscale admin console (DNS › HTTPS Certificates), then try again"
  - `portTaken`: "tailnet port N is already served by a mapping Batty didn't make; Batty won't replace it (see tailscale serve status)"
  - `notOurs`: "the tailnet mapping on port N wasn't made by Batty; remove it with tailscale serve yourself"
  - `commandFailed`: "tailscale serve failed: <tool message>"
  - `timedOut`: "tailscale serve didn't finish within 20 s: <output>"
  - `notApplied`: "tailscale serve exited 0 but serve status doesn't show the mapping"
- **Servers row.** Every action here is an event-origin button action.
  - The "…" menu gets a tailnet item only when `store.tailnet.offersSharing`. With `tailnetURL == nil` it is **Share on Tailnet** (`servers.row.tailnet-share`, calling `store.shareServerOnTailnet(entry)`); otherwise **Stop Sharing on Tailnet** (`servers.row.tailnet-unshare`, calling `store.stopSharingServerOnTailnet(entry)`).
  - The item is disabled while `entry.isTailnetBusy`.
  - When `entry.tailnetError` is set, the row's `VStack` shows it as a red caption line (`servers.tailnet-error`, `lineLimit(2)`). The next attempt clears it.
  - Copy Tailnet URL is unchanged. With Tailscale absent or not running, nothing new appears (AC 2). An adopted or still-shared URL keeps showing even if `status` later goes stale.
- **Popover open.** In `ServersToolbarButton`, the action becomes `isShown.toggle(); if isShown { store.tailnet.refreshStatusIfStale() }`.

## Expected behavior

> **Amended by `## Plan` (2026-11-19):** the verb is `server tailnet (<id>|--port N) [--off]` plus `share --tailnet`; argv is `serve --bg --https=N http://127.0.0.1:N` (+ `off`). The Plan's Grammar block is authoritative.

- **Detection** (no user action, read-only): `tailscale` found in `PATH` (also the App Store/standalone CLI locations the plan confirms), `tailscale status --json` parsed with `JSONDecoder`: `BackendState == "Running"` and `Self.DNSName`. Run off the main actor, only while the Servers list has entries or on a share request, cached briefly. Not running or absent → no tailnet UI at all.
- **Share on tailnet** is opt-in **per server**, never automatic: `batty server share … --tailnet` / `batty server tailnet <id> on|off` (grammar per plan, consistent with #0692), and a "Share on Tailnet" / "Stop Sharing on Tailnet" item in the Servers list row's menu. Runs `tailscale serve --bg --https=<port> <port>` so each local port keeps its own tailnet port (URL `https://<dnsname>:<port>/`; 443 only if the user picks it), and turning off runs the same command with `off`.
- Batty records which mappings it added and removes only those: on `stop`/`unshare`, and offers to remove them (never silently) at quit. Never runs `tailscale serve reset` or touches mappings it didn't make. If `tailscale serve` fails (HTTPS certificates not enabled in the tailnet, permissions), the CLI and the row show the tool's message.
- **Copy Tailnet URL** on the row when shared; `server list --json` includes `tailnetURL`.

## Decisions (orchestrator defaults, 2026-11-19; the user may override)

- **Tailnet port per server:** each server is shared on its own tailnet HTTPS port with `tailscale serve --bg --https=<port> <localport>` so several can be shared at once. The plan verifies the exact current CLI form against Tailscale's docs.
- **Turning off:** Batty turns off the tailnet mappings it created on Unshare and when it quits, and never touches mappings it didn't create (no `tailscale serve reset`).

## Facts from PhotonHTTP llms.txt (2026-11-19)

From `https://photon-http.sstools.co/llms.txt` and its linked `docs/running-on-a-mac.md` ("Serve a folder", "Binding to all interfaces and the firewall prompt"):

- `batty server serve` runs `photon serve <dir> --host 127.0.0.1 --port <N>` (#0693), a cleartext HTTP/1.1 server on loopback. Sharing it on the tailnet is the same as for any other server: `tailscale serve --bg --https=<N> <N>` proxies to `127.0.0.1:<N>`, and the tailnet HTTPS certificate comes from Tailscale, not from photon (photon's own TLS needs a config file and is not used).
- photon's docs say a server reached only through a tunnel (Tailscale named) "can stay on loopback". Batty never passes `--host 0.0.0.0` for tailnet sharing; loopback also never triggers the macOS firewall prompt that a newly built `photon` gets on a non-loopback bind.
- Nothing tailnet-specific is needed from photon: no health endpoint exists, so the tailnet row reuses the local listener state. Related future: #0695.
