# 0157 — Rename Tab no longer changes the tab title; no logs on the rename path

| | |
|---|---|
| **Status** | open |
| **Module** | Tab / Pane |
| **Platform** | macOS |
| **First seen** | 2026-05-20 |

## Description

Renaming a tab via the chip's context menu no longer updates the tab title. The **Rename…** sheet accepts input and dismisses, but the chip continues to display the shell-emitted title. There are no log lines anywhere along the rename path, so the cause can't be diagnosed from Console.app — logging needs to be added first, then the underlying bug investigated.

## Steps to reproduce

1. Open a session with at least one tab.
2. Right-click the tab chip → **Rename…**.
3. Type a new name and press Return (or click **Rename**).

## Expected behavior

The chip immediately displays the typed name, and the override persists regardless of what the shell emits afterward (per `Help/04-tabs.md`).

## Actual behavior

The sheet dismisses but the chip keeps showing the shell title. The typed name appears to be lost. Console.app shows nothing for the rename path.

## Notes

Plan of attack:

1. **Add logs first.** Instrument the rename path so we can see, from Console.app, what the user typed, what `titleOverride` got set to before/after, and whether `TabTitleFormatter` is actually consulted afterward. Relevant sites:
   - `BattyKit/Sources/BattyKit/Views/PaneView.swift` around line 265 — the `RenameTabSheet` `onCommit` closure that writes `tab.titleOverride`. Log the trimmed value, the prior `titleOverride`, and the tab id.
   - `BattyKit/Sources/BattyKit/Views/PaneView.swift` around line 337 — the **Reset Title** menu item that clears `titleOverride`. Log the clear.
   - `BattyKit/Sources/BattyKit/Util/TabTitleFormatter.swift` — where the displayed title is composed; log which branch wins (override vs `terminal.title`).
   - `BattyKit/Sources/BattyKit/Runtime/TabRuntime.swift:11` — the `titleOverride` property itself. Verify it's `@Observable` so SwiftUI rebuilds the chip when it changes.

   Follow the project logging convention (file-scoped `nonisolated private let logger = Logger(subsystem: Logging.subsystem, category: "<Filename>")`). Use a distinct tag prefix like `tab-rename:` so the lines group cleanly in Console.

2. **Then diagnose.** Likely suspects, in order:
   - `TabRuntime.titleOverride` may not be observable (missing `@Observable` macro / not `@Published`), so the write succeeds but no view invalidation fires.
   - The tab chip view may bind to `terminal.title` directly and bypass `TabTitleFormatter`.
   - The `RenameTabSheet` may be writing to a local copy of `tab` rather than the source-of-truth `TabRuntime`.

3. Related context: [[0153]] fixed an analogous problem on **sessions** (Reset Name fallback / cache clear). The tab path was not touched by that change but may have the same shape of bug.
