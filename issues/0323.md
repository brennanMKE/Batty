## Description

Batty's bundle includes three GPLv3-licensed files, but the full GPLv3 license text ships nowhere — the attribution document links it at a URL instead. GPLv3 §4 requires giving "all recipients a copy of this License along with the Program", and a URL is arguably not "a copy". This is a compliance-completeness gap, not a licensing conflict: nothing about the current state threatens the product, but "we link the license" versus "we ship the license" is a real distinction and it is cheap to close.

The three GPLv3 files (verified by reading their headers directly; each states it is based on Kitty's shell integration and "so this file is also distributed under GPLv3"):

- `Resources/ghostty-runtime/ghostty/shell-integration/bash/ghostty.bash`
- `Resources/ghostty-runtime/ghostty/shell-integration/zsh/.zshenv`
- `Resources/ghostty-runtime/ghostty/shell-integration/zsh/ghostty-integration`

They are copied into `Batty.app/Contents/Resources/ghostty/shell-integration/` by `scripts/bundle-ghostty-resources.sh`.

`THIRD-PARTY-LICENSES.md` as landed by #0318 (currently on branch `issue/0318`; read via `git show issue/0318:THIRD-PARTY-LICENSES.md`) correctly identifies the three files as GPLv3, reproduces their short header notice verbatim, and links the full text at `https://www.gnu.org/licenses/gpl-3.0.txt` with an explicit rationale for not inlining its 674 lines. The gap is in its "Why this doesn't currently obligate more than the notice above" paragraph: it quotes GPLv3 §4's first two requirements — "conspicuously and appropriately publish[ing] on each copy an appropriate copyright notice" and keeping "intact all notices" — but elides §4's third requirement, "and give all recipients a copy of this License along with the Program." (Verified against the branch copy: the paragraph really does stop at the notices clauses.) The files ship unmodified in source form, so §4 verbatim copying is the operative clause, and its third requirement is the one Batty does not currently satisfy beyond a link.

## Resolution notes

> 🟢 Resolved 2026-08-08 — the verbatim GPLv3 text now ships at `Contents/Resources/ghostty/shell-integration/gpl-3.0.txt`, beside the three files it governs, and the §4 paraphrase no longer elides the "give all recipients a copy" requirement.

No script change was needed. `scripts/bundle-ghostty-resources.sh` rsyncs the whole `shell-integration/` subtree, so a file placed at that root ships automatically — the restricted area was never touched.

## Root cause

#0318 identified the three Kitty-derived shell-integration scripts as GPLv3 correctly, but linked the license text rather than shipping it, and its §4 paraphrase quoted the first two requirements while eliding the third. A URL is arguably not "a copy of this License along with the Program".

## Fix

- **`Resources/ghostty-runtime/ghostty/shell-integration/gpl-3.0.txt`** — the canonical FSF text, vendored verbatim, placed in the directory shared by all three GPLv3 files. Chosen over the `ghostty-runtime/` root specifically because the bundling script rsyncs `shell-integration/` but only `cp`s the single terminfo file; a file at the root would not have shipped and closing that would have meant editing a restricted script.
- **`THIRD-PARTY-LICENSES.md`** — the §4 paragraph now quotes all three requirements, names the third as the gap this issue closed, states the built-bundle path rather than only the repo path, and is explicit that it groups GPLv3's four semicolon-separated clauses into three (the two "keep intact" clauses collapsed).
- **`Resources/ghostty-runtime/ATTRIBUTION.md`** — `gpl-3.0.txt` added to the Contents list, summary updated from "verbatim/linked" to "verbatim", and a maintenance note added for version bumps.
- The byte-identical Help copy was regenerated so `ThirdPartyLicensesSyncTests` stays green.

The "8 shell-integration files" label that enumerated 7 was corrected to 7, with the terminfo entry accounting for the 8th.

## Gotchas

- **`gpl-3.0.txt` is Batty's own addition, not upstream.** Any Ghostty version bump that *replaces* `shell-integration/` (an `rm -rf` and copy, or an `rsync --delete` sourced from upstream) will drop it. Re-fetch and confirm 674 lines after any bump. The documented `cp -R` recipe *merges* and will not drop it.
- **`ATTRIBUTION.md`'s `cp -R` refresh recipe has a pre-existing bug**, found while reviewing this issue and deliberately left alone: run as written against a checkout it produces a nested `shell-integration/shell-integration/` instead of refreshing the tree, because `cp -R src dst` copies *into* an existing `dst`. It predates this issue (#0318) and nothing here depends on it.
- **File placement was forced by the bundling script's shape**, not chosen for tidiness — `shell-integration/` is rsynced wholesale, the `ghostty-runtime/` root is not.

## Expected behavior

The full GPLv3 text (`gpl-3.0.txt`) ships in the app bundle alongside the files it governs, and `THIRD-PARTY-LICENSES.md`'s §4 paragraph accurately reflects all three of §4's requirements — including where the shipped copy of the license lives.

Also fold in a cosmetic fix to the same document: its sweep paragraph says "8 shell-integration files (…)" but the parenthetical enumerates 7 (`bash/ghostty.bash`, `bash/bash-preexec.sh`, `zsh/.zshenv`, `zsh/ghostty-integration`, plus the `fish`, `elvish`, and `nushell` files), then adds "plus the one `terminfo` entry". The list is complete and the downstream 3 + 1 + 4 = 8 arithmetic is correct only because the `terminfo` entry is counted inside the "remaining 4" — the "8 shell-integration files" label is off by one and should say 7 (or "8 files" without "shell-integration"). Verified against the branch copy.

Remember the in-app Help topic `BattyKit/Sources/BattyKit/Help/09-third-party-licenses.md` is a byte-identical copy of the root document per #0318 — any edit must update both.

## Actual behavior

The GPLv3 files ship; the GPLv3 text does not. The document's §4 quotation is incomplete in exactly the direction that makes the current state look fully compliant. The "8 shell-integration files" label miscounts its own enumeration.

## Notes

**Cheapest fix identified during #0318 review round 3:** drop a copy of `gpl-3.0.txt` into `Resources/ghostty-runtime/` so it ships with the files it governs via the existing copy step.

**Placement matters — read-only check of `scripts/bundle-ghostty-resources.sh` already done while filing this issue:** the script does *not* copy `Resources/ghostty-runtime/` wholesale. It copies exactly two things — `terminfo/78/xterm-ghostty` as a single named `cp`, and `rsync -a --delete "$SRC/ghostty/shell-integration/" "$DEST/ghostty/shell-integration/"`. So:

- `Resources/ghostty-runtime/ghostty/shell-integration/gpl-3.0.txt` (or a subdirectory of it) ships automatically with **no script change**.
- `Resources/ghostty-runtime/gpl-3.0.txt` at the vendored root would **not** ship without editing the script — and `scripts/` is a restricted area under `CLAUDE.md`, so that path requires explicit user go-ahead first.

Placing the license text inside `shell-integration/` is also the semantically right spot: that is the directory containing all three GPLv3 files. Note the `--delete` flag means the bundle-side copy tracks the vendored tree exactly, so the vendored location is the single source of truth. Also note `Resources/ghostty-runtime/ATTRIBUTION.md` documents this vendoring (updated by #0318) and should mention the shipped license copy so the two don't drift.

Fetch `gpl-3.0.txt` from the canonical URL the file headers themselves point to (`https://www.gnu.org/licenses/gpl-3.0.txt`) and vendor it verbatim — do not retype or reformat it.

This issue depends on #0318's `THIRD-PARTY-LICENSES.md` (and its Help-topic twin) being on `main` first; the document edits here amend that file.

All factual claims above were re-verified against source while filing: the three file headers in `Resources/ghostty-runtime/`, the branch copy of `THIRD-PARTY-LICENSES.md` (§4 elision, URL-link-not-copy, off-by-one label), and the copy behavior of `scripts/bundle-ghostty-resources.sh`.
