## Description

`Lakr233/libghostty-spm` PR #22 ("Fix XCFramework bundle format validation") has been merged (merge commit `d5af462`). It fixes the upstream packaging bug that caused Xcode's embed-frameworks validation to reject the macOS slice of `libghostty.framework` — the same bug that forced the `scripts/fix-libghostty-framework.sh` workaround introduced in [[0212]].

Once a new upstream release is cut that includes this fix, re-pin `BattyKit/Package.swift` to that release and retire the workaround machinery.

## Acceptance criteria

- `BattyKit/Package.swift` `revision:` is updated to a commit at or after `d5af462` on `Lakr233/libghostty-spm` (or to a new release tag that includes it).
- `scripts/build.sh` — `** BUILD SUCCEEDED **` without needing to reshape the framework.
- Direct Xcode builds (`open Batty.xcodeproj` → Product → Build) succeed without `fix-libghostty-framework.sh` having been run first.
- `scripts/fix-libghostty-framework.sh` is removed.
- `scripts/build.sh` and `scripts/run-ui-tests.sh` are simplified to remove the fixup step and its comment.
- `CLAUDE.md` and `issues/Issues.md` are updated to remove the wrapper-necessity note and restore the direct-Xcode-build guidance.

## Root cause

`Lakr233/libghostty-spm` 1.1.9 shipped the macOS slice of `GhosttyKit.xcframework` as a shallow `.framework` bundle, which Xcode's embed-frameworks validation rejects. PR #22 switched the xcframework to the static-library format (`libghostty.a` + `Headers/`), eliminating the `.framework` bundle entirely and with it the validation error.

## Fix

Re-pinned `BattyKit/Package.swift` to `c69c34354e511af7a3e6d7e5e2a4fa2fed4b90ff` (tag `1.2.2`). Both `Package.resolved` files updated automatically by SPM. Removed `scripts/fix-libghostty-framework.sh` and the resolve+fixup preamble from `scripts/build.sh` and `scripts/run-ui-tests.sh`. Updated `CLAUDE.md` and `issues/Issues.md` to remove the wrapper-necessity notes.

## Files changed

- `BattyKit/Package.swift` — revision bumped to `c69c343` (tag `1.2.2`).
- `BattyKit/Package.resolved` — SPM-regenerated.
- `Batty.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` — SPM-regenerated.
- `scripts/fix-libghostty-framework.sh` — deleted.
- `scripts/build.sh` — stripped to a thin `xcodebuild` wrapper; resolve and fixup steps removed.
- `scripts/run-ui-tests.sh` — resolve and fixup preamble removed.
- `CLAUDE.md` — wrapper-necessity note replaced with a simple description of the script as a convenience wrapper.
- `issues/Issues.md` — same update to the build/verify section.

## Gotchas

- The 1.2.2 xcframework uses `libghostty.a` (static library) rather than `libghostty.framework`. Static libraries are linked at build time, not embedded, so there is no embed-frameworks step to validate. This is why Xcode direct builds now work without any preprocessing.
- `scripts/build.sh` still exists and is still the canonical command — it ensures the correct scheme (`Batty (Prod)`) and destination are used consistently.
