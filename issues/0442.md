# 0442 — A Swift 6 compile error in `BattyUITests` is caught only by a full Tart VM run, and `docs/async-test-seams.md` omits the `@MainActor` timeout-closure trap

## Description

This issue covers two test-tooling gaps. The same incidents exposed both of them:

**(a) Nothing on the host type-checks `BattyUITests` code.** The target has a #0412 build-phase guard that refuses to build outside a VM, so a Swift 6 strict-concurrency error in UI-test code first shows up inside the Tart VM, after a full export, clone and boot. #0417 lost a whole VM run this way (run 3, `20260924-004217-60112`): a `private static let` `NSPredicate` was flagged as `#MutableGlobalVariable`. The #0437 reviewer found a host-side check that works: `swiftc -typecheck -swift-version 6 -default-isolation MainActor` over the test files plus `BattyUITests/Support/*.swift`, against the real `XCTest` module. Add it as `./build.sh ui-typecheck` and document it in `docs/ui-testing-vm.md`.

**(b) `docs/async-test-seams.md` doesn't warn about a trap that three #0427 children hit.** Under this package's `.defaultIsolation(MainActor.self)`, a `DispatchWorkItem` timeout closure formed inside a `@MainActor` test suite or method inherits MainActor isolation. `asyncAfter` then runs it on a `DispatchQueue.global` queue, and the Swift 6 runtime traps: `EXC_BREAKPOINT`/`SIGTRAP` in `dispatch_assert_queue_fail`, via `swift_task_checkIsolatedSwift`. The test process crashes at the moment a hang-guard bound expires, instead of failing cleanly. #0429 also saw this crash orphan live `sleep 60` children. The fix is to mark the helper (or its type) `nonisolated`. A related lost-wakeup also belongs in the doc. A `nonisolated` async wait really does hop off MainActor, so a MainActor-side `signal()` can run before the wait registers its continuation. The wait must check a flag both before registering and inside its registration closure.

## Premise check (read-only, on `main` at `3e8e7236`)

**(a)**

- **The guard exists.** `Batty.xcodeproj/project.pbxproj:285` has a shell-script build phase that exits 1 unless `sysctl -n kern.hv_vmm_present` is `1`.
- **No such action exists yet.** `build.sh` has no `ui-typecheck` case. Its `case "$ACTION"` (`:79`) has `ui|test`, `package`, `unit`, `release`, `run`, `terminate` and a `*)` passthrough to `xcodebuild`. So today `./build.sh ui-typecheck` would hand `ui-typecheck` to `xcodebuild` as an action. `build.sh` is at the repo root, which isn't restricted. `scripts/` is restricted, so the new action goes in `build.sh` or `tools/`, not `scripts/`.
- **The lost run is recorded.** `issues/0417.md:76` has the run and says only `swiftc -parse` was possible on the host. `issues/0437.md:86` and `:134` record the working `-typecheck` form.
- **The check works on current `main` (trial run).** I ran this from a scratchpad directory:
  ```
  P=$(xcrun --sdk macosx --show-sdk-platform-path)
  xcrun swiftc -typecheck -swift-version 6 -default-isolation MainActor \
    -sdk "$(xcrun --sdk macosx --show-sdk-path)" \
    -F "$P/Developer/Library/Frameworks" -I "$P/Developer/usr/lib" \
    BattyUITests/*.swift BattyUITests/Support/*.swift
  ```
  It finished in about 3 s with exit 0, **0 errors and 7 warnings**: 6 in `LifecycleTests.swift`, whose class is `nonisolated`, and 1 in `Support/BattyUITestHarness.swift`. It wrote no files to the working directory. `-I $P/Developer/usr/lib` is where `XCTest.swiftmodule` lives. It sits next to `libXCTestBundleInject.dylib`, but `-typecheck` only reads the module interface and links or loads nothing.
- **The flags don't yet match the target exactly.** `BattyUITests` (`TEST_TARGET_NAME = Batty`) has no `baseConfigurationReference` of its own, so it inherits the project-level `Configuration/Build.xcconfig`: `SWIFT_VERSION = 6.0`, `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, `SWIFT_STRICT_CONCURRENCY = complete`, `SWIFT_UPCOMING_FEATURE_MEMBER_IMPORT_VISIBILITY = YES`, `MACOSX_DEPLOYMENT_TARGET = 15.6`. The target overrides `SWIFT_APPROACHABLE_CONCURRENCY = NO` (pbxproj `:593`, `:606`). The trial didn't pass `-enable-upcoming-feature MemberImportVisibility` or `-target …-apple-macos15.6`. The action should mirror the target's settings, so it doesn't pass code that the VM build would reject, and doesn't reject code the VM would accept.

**(b)**

- **Not in the doc.** `grep -n 'dispatch_assert\|nonisolated\|lost.wakeup\|isSignaled' docs/async-test-seams.md` finds `nonisolated` only in the `SchedulingClock`/`TeardownReapGate` declarations and in `TestClock`'s description (`:17-18`, `:55`, `:156`). It has no note on the timeout-closure trap and none on the lost wakeup. §4's "hang-guard bound" bullet tells readers to build a `ResumeOnce` plus `DispatchWorkItem` timeout, which is the exact pattern that traps inside a `@MainActor` suite, and doesn't warn them.
- **Documented only locally today:**
  - In doc comments on each helper: `BellNotificationSummaryTests.swift:174-182` (`awaitSummarizationTask`, #0433), `LMStudioDashboardPaneContentTests.swift:1170-1180` (`EventCounter`, #0429), and `GitStatusPaneContentTests.swift:205-260` (`ScanHandledSignal`'s trap and lost wakeup, #0430).
  - In issue files: #0433's Gotchas (`issues/0433.md:127`), #0429's Notes (`issues/0429.md:95`), and #0430's Gotchas "Default isolation" (`issues/0430.md:424`).
- **The XPC twin is documented elsewhere.** `docs/xpc/swift-concurrency-and-xpc.md:36-44` and `:277` and `docs/xpc/FINDINGS.md:122` cover the same inherited-isolation `SIGTRAP` for XPC handler closures. The new gotcha should link there rather than repeat it.

## Expected behavior

- **(a)** `./build.sh ui-typecheck` type-checks every `BattyUITests` source on the host, with flags matching the target's Swift settings, and exits non-zero on any error. It produces no `.xctest` bundle and no runnable product, and nothing is loaded into another process. It doesn't touch `Configuration/Active.xcconfig` (`swiftc` doesn't read it), and it leaves no residue in `project.pbxproj` or `.xcscheme`. `docs/ui-testing-vm.md` lists it in "What runs where" under "On the host (fine)". It also says to run it before committing UI-test changes and before starting a VM run.
- **(b)** `docs/async-test-seams.md` gains a gotcha, in §4 or a new short section, covering:
  - the trap: symptom, cause and the `nonisolated` fix
  - the lost-wakeup rule: check the flag before registering and again inside the registration closure
  - pointers to the three in-code examples and to the XPC doc

## Direction

- **(a)** Add a `ui-typecheck)` case to `build.sh` and document it in the usage header. It should:
  - glob the target's sources with `BattyUITests/**/*.swift`, so new subfolders aren't missed
  - resolve the platform path with `xcrun`
  - pass `-swift-version 6 -default-isolation MainActor -strict-concurrency=complete -enable-upcoming-feature MemberImportVisibility -target $(uname -m)-apple-macos15.6`
  - pass the `-sdk`, `-F` and `-I` paths above
  - run `-typecheck` only, never `-emit-*` or `-o`

  Before hard-coding the flags, check them once against `xcodebuild -project Batty.xcodeproj -target BattyUITests -showBuildSettings`. That command resolves settings and runs no build phases. Discard any `project.pbxproj`/`.xcscheme` residue, per `AGENTS.md`.
- **Prove it catches what the VM would catch.** Re-introduce #0417's `private static let` `NSPredicate` in a scratch copy, or on the branch and then revert, and confirm the action fails with `#MutableGlobalVariable`.
- **Prove it's inert.** Run it from a clean tree. Confirm `git status --porcelain` is unchanged, that nothing new is written under the working directory, and that no `xctest` or `testmanagerd` process starts (`pgrep -l 'xctest|testmanagerd'` before and after).
- **(b)** Documentation only. No code changes.
