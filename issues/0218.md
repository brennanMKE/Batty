# 0218 — Beta scheme BuildableName oscillates between "Batty Beta.app" and "Batty.app" after every build

| | |
|---|---|
| **Status** | open |
| **Module** | Build |
| **Platform** | macOS |
| **First seen** | 2026-05-28 |

## Description

Every time a Prod build runs, the Beta scheme file gets `BuildableName` silently rewritten from `"Batty Beta.app"` to `"Batty.app"`. Every time a Beta build runs, Prod's file gets rewritten the other way. The oscillation shows up as an uncommitted diff after almost every build, and has been manually "fixed" four times in git history — always undone by the next build.

## Root cause

`xcodebuild` rewrites `BuildableName` in **all** shared scheme files after a build to match the product name it just resolved. The resolution uses the build configuration of the scheme that was just run, and stamps that value across every scheme that references the same target. So:

- Running `Batty (Prod)` resolves `PRODUCT_NAME = Batty` → rewrites every scheme's `BuildableName = "Batty.app"`, including `Batty (Beta)`.
- Running `Batty (Beta)` resolves `PRODUCT_NAME = Batty Beta` (from `Beta.xcconfig`) → rewrites every scheme's `BuildableName = "Batty Beta.app"`, including `Batty (Prod)`.

The mismatch exists because `Beta.xcconfig` sets `PRODUCT_NAME = Batty Beta`. That is the only reason the two schemes disagree. Commit history documenting the oscillation:

| Commit | What it did |
|---|---|
| `ca58407` | Set Beta scheme to `"Batty Beta.app"` to match `Beta.xcconfig` |
| `f7d4e52` | Changed it back to `"Batty.app"` |
| `b46f489` | Fixed Prod scheme (contaminated by a Beta build) back to `"Batty.app"`; noted the xcodebuild cross-write in the commit message |
| (working tree, 2026-05-28) | Prod build via `scripts/build.sh test` reset Beta back to `"Batty.app"` again |

## Fix

Remove `PRODUCT_NAME = Batty Beta` from `Beta.xcconfig`. Both variants produce `Batty.app` — they are already distinguished by bundle identifier (`co.sstools.Batty.beta` vs `co.sstools.Batty`) and Sparkle feed configuration. There is no need for the binary filename to differ. Once both schemes agree on `"Batty.app"`, xcodebuild's cross-write is a no-op and the oscillation stops.

## Files changed

- `Configuration/Beta.xcconfig` — remove `PRODUCT_NAME = Batty Beta` line
- `Batty.xcodeproj/xcshareddata/xcschemes/Batty (Beta).xcscheme` — commit `BuildableName = "Batty.app"` as the stable canonical value (already correct in working tree after the xconfig change)
