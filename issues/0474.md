## Description

The Project Editor (artboard 1, `issues/0469/Main.dc.html`; rendered at https://claude.ai/artifact/WoKFESyWFnQFkM64TF2P5o) is where a user defines Projects. It is a window, not a sheet. It has a Projects list on the left, the selected Project's settings in the middle, and an inspector for the selected Pane on the right. This issue builds the editor and its own entry point, File ▸ Edit Projects…. The Open Project picker and its menu items are #0475. Save Session as Project and the editor's "Copy from current Session" button are #0476.

## Expected behavior

**Layout of the window** (follow artboard 1):

- **Left column: Projects list.** Every Project in `ProjectStore` order (#0471), with name, path, and a color dot. "+ New Project…" at the bottom creates an untitled Project with the root defaulting to the focused Tab's cwd, the `singlePane` layout, and one Terminal Pane with one Tab at root. Support reordering and Delete (with confirmation), using a context menu or the Delete key.
- **Header.** **Name** (text field). **Root folder** (path display plus **Choose…**, which opens an `NSOpenPanel` for directories; the name field pre-fills from `ProjectNameResolver` (`BattyKit/Sources/BattyKit/ProjectName/`), falling back to the folder's basename, only when the name is still empty or untitled). **Session color** (swatches for the ten `SessionColor` cases; see #0469 "Design vs. code" 1; reuse `SessionColorPickerView`'s palette and its keyboard cursor `SessionColorGridCursor` if they fit).
- **Layout strip.** Thumbnails for all ten `PaneLayout.allCases` (#0469 "Design vs. code" 2, reusing `LayoutThumbnailView` from `Views/LayoutThumbnailView.swift`). The selected one is highlighted. If the Project's topology is a captured one and not a preset (#0476), show it as a "Custom" thumbnail with geometry **derived from the topology**. `LayoutThumbnailView` takes a `PaneLayout` and reads its hand-written `layoutPanes` (`Model/PaneLayout.swift:56-125`), and a captured topology has none, which #0371 flagged too. **Changing the preset** keeps slot i's configuration for slots that still exist and drops the rest. Warn before dropping a slot that has Tabs or commands. The "Copy from current Session" button sits beside the strip. It is **built by #0476**, so leave the space or omit it here.
- **Pane preview.** One card per slot, positioned by the layout geometry. Each card shows its number, a kind badge (glyph plus color per artboard 1), and either its Tabs (title, plus `$ command` or `shell in root/…`) or the view's one-line blurb. Clicking a card selects it. Arrow keys move the selection. Caption: "Click a pane to set it up. Panes open at equal sizes; resize them freely afterwards."
- **Right inspector for the selected Pane.** "Pane N" plus where it sits ("Top", "Bottom left", …). **Shows:** a kind picker over `PaneContentKind.allCases` using `displayName` (#0469 "Design vs. code" 3). For **Terminal:** the Tabs editor. Each Tab has a **title** (optional), a **working directory** (`root/` prefix plus a relative field, with an optional folder chooser that is constrained to the root), and a **startup command** (`$` prefix field). Each Tab has a remove ×, disabled on the last Tab. "+ Add Tab" sits below. Help text: "Each command is typed into its Tab's shell once the shell is ready. When it exits, the Tab stays open at the prompt." For **Git Status:** the **Repository folder** (`root/` plus relative). For the other kinds: the kind's blurb plus "Nothing to set up for this view."
- **Footer.** The **"Run startup commands when the Project opens"** checkbox, then **Cancel**, **Save**, and **Save & Open** (the default button). Save & Open saves, then calls #0472's `openProject(id:, mode: .focusExistingOrOpen)`, which goes through #0473's trust check.

**Behavior:**

- **Edits are a draft.** Nothing is written to `ProjectStore` until Save or Save & Open. Cancel discards the draft. Switching Projects in the list with unsaved changes asks Save / Discard / Cancel.
- **Validation before Save is enabled.** The name is non-empty and unique among Projects, case-insensitively (#0471). The root exists and is a directory. Relative paths don't escape the root (#0471's resolver). Each Terminal Pane has at least one Tab. Commands follow #0473's newline decision. Show invalid fields inline. Never fail silently.
- **Editing commands invalidates trust.** Saving a command change does not touch `approvedCommandsHash`. #0473's hash comparison makes the next open prompt again. Do not clear the hash on save, because a revert to the approved commands should not re-prompt.
- **Opening the editor.** Add File ▸ **Edit Projects…** to the existing `CommandGroup(replacing: .newItem)` (`Commands/BattyCommands.swift:66-87`), after Open Quickly (#0475 adds the other two Projects items next to it). No keyboard shortcut and no `ShortcutAction` case (#0469). Opening the editor brings the existing window forward if it is already open. Provide an entry point that opens it with a given Project selected, which #0475 (⌘E) and #0476 (Save as Project) use.
- **The window and the flag.** Today the app's only non-content window is the Help `Window` scene (`Batty/BattyApp.swift:55-68`). A SwiftUI `Window` scene is listed in the Window menu automatically, which would leak Projects in Prod. With the flag off, the editor must have **no menu item, no Window-menu entry, and no way to be opened**. Use a conditional scene if `SceneBuilder` supports it on macOS 15.6 (verify it, don't assume), or an AppKit-managed `NSWindow`/`NSHostingController` that is created only on demand. Also decline external URL events the way the Help scene does (`.handlesExternalEvents(matching: Set())`, #0251). Otherwise a `batty://` URL could open the editor.
- **Not a content window.** The editor must not register in the `NSWindow`↔`WindowID` registry (`AppStateStore.registerNSWindow`, `Runtime/AppStateStore.swift:816`). Content-window shortcuts must stay off while it is key, because `BattyShortcuts` checks `keyWindowIsContentWindow()` at `Commands/BattyShortcuts.swift:34`. Actions the editor triggers (Save & Open, the default root from the "focused Tab") must target `defaultTargetWindow()`'s content window (#0439), not the editor window.

## Acceptance criteria

- The editor model (draft, validation, preset change that keeps or drops slots, add/remove Tab, kind change) is a pure or `@Observable` type with unit tests. Kind change from Terminal to Git Status and back preserves the Terminal Tabs in the draft until Save. Pick this behavior or document the alternative.
- Save writes exactly the edited Project to the store (round-trip through a temp `fileURL`). Cancel writes nothing. Use a non-default fixture so "unchanged" is not vacuous.
- Save & Open opens the Project via #0472/#0473. Unit-test the call through a seam, without mounting UI.
- With `FeatureFlags(projects: false)`, the File menu has no Edit Projects… item, no editor window can be created, and nothing constructs `ProjectStore`. Unit-test the menu-model/gate function, and #0478 checks it in UI.
- Accessibility identifiers on the list, the fields, the layout thumbnails, the pane cards, the inspector controls and the footer buttons, for #0478. Document them in `docs/ui-features.md`.
- No sleeps or polling in tests (`AGENTS.md` "Asynchronous tests").
- `./build.sh unit` passes. This is a new visual surface, so the user's visual sign-off is required. Mark `resolved`, not `closed`, and note in Gotchas what couldn't be verified.

## Notes

- **Binding:** `docs/swiftui-observation-rules.md`. The draft lives in its own `@Observable` model. `body`, view inits and `onAppear` never write `ProjectStore` or app state. Writes happen in button actions. Selection in the list and the pane preview are event-origin writes. Focus moves between fields go through `@FocusState`, never `makeFirstResponder` from a SwiftUI callback.
- `docs/view-hierarchy.md`: the editor never touches terminal views. `docs/multi-window-design.md`: the editor is process-global, like Settings and Help, and is not per-Window.
- `NSOpenPanel` is presented from a button action. Don't present it from inside a SwiftUI update.
- Localization: user-facing strings use `String(localized:)`, following the surrounding code (`docs/localization.md`).
