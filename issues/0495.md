# 0495 — On `main`, a terminal split from a Git Status or other non-terminal Pane still starts in `$HOME` because #0487's working-directory inheritance exists only on `release/1.2`

## Description

#0487 made every split from a non-terminal Pane inherit a working directory: a Git Status Pane gives its `directoryPath`, a Process Status Pane following a Tab gives that Tab's directory, anything else gives the most recently focused terminal Pane's directory, and the typed views (⌘G, ⌘J) resolve the same way. It was developed on `issue/0487` from `release/1.2` under a user-authorized exception and landed there as `174f06bb`, for 1.2.1. Its Release section names the port to `main` as the one follow-up, with the extra path `main` has that `release/1.2` does not: `ProjectTreeBuilder`. This is that port, plus one improvement #0487's round-2 review recorded in its Gotchas.

The source issue is not on `main`; read it with `git show release/1.2:issues/0487.md`.

## Current code (verified 2026-10-13 on `main` at `673c6530` and `release/1.2` at `174f06bb`)

**The bug on `main`.** `SplitTree.makePane` (`BattyKit/Sources/BattyKit/Model/SplitTree.swift:363-411`) still reads only the source's active Tab: the terminal branch at `:405-410` (`guard let sourceTab = source?.activeTab`, then `terminal.workingDirectory ?? terminal.configuration.workingDirectory`), the Git Status branch at `:391-394` (`source?.activeTab?.terminal.workingDirectory …`), and the Process Status branch at `:385-386` (`.followingTab($0.activeTabID)`, the placeholder Tab for a non-terminal source). `inheritedSource` does not exist on `main` (`git grep inheritedSource BattyKit/Sources` is empty). `docs/pane-kinds.md:137-142` still says "a Git Status pane has no cwd to inherit in the same sense", the false premise #0487 corrected, and `Concepts.md` Pane › Splitting (`:80`) lacks the sentence #0487 added.

**What `174f06bb` touched** (`git show --stat 174f06bb`): `SplitTree.swift` (+150), `BattyKit/Tests/BattyKitTests/SplitTreeNonTerminalCWDTests.swift` (new, 23 `@Test` declarations), `BattyUITests/CLIViewPaneTests.swift` (+92: `testSplitTerminalFromGitStatusPaneInheritsRepositoryDirectory`, `testGitStatusFromGitStatusPaneMonitorsTheSameRepository`), `BattyUITests/Support/BattyCLIHarness.swift` (+12, `CLITopology.Pane` decodes Tab working directories), `Concepts.md`, `docs/design/git-status-view.md`, `docs/pane-kinds.md`, `issues/0487.md`. On `release/1.2` the resolver is `SplitTree.inheritedSource(from:in:tabLookup:)` (`:408-456`, returning `InheritedSource` `:376`, with `Step` cases `none`/`terminal`/`gitStatusDirectory`/`followedTab`/`recentTerminal`), `mostRecentTerminalPane(in:)` (`:458-466`), and `makePane(inheritingFrom:in:…)` (`:332-375`) calls it for every kind.

**What differs on `main` and must be adapted** (not mechanical):

- `makePane` has a `tabs: [TabRuntime]?` parameter (`:369`) with the short-circuit `if let tabs, !tabs.isEmpty { return PaneRuntime(tabs: tabs) }` at `:402-404`, before any inheritance. Explicit Tabs must keep winning.
- `SplitTree.withFirstPane(kind:path:tabs:contentFactory:isSessionSelected:)` (`:187-205`) calls `makePane(inheritingFrom: nil, …)` at `:196-204` **before** the tree exists (`let tree = SplitTree(root: .leaf(pane))` follows). `release/1.2`'s `makePane` takes `in tree: SplitTree`, so the port needs the tree parameter optional (or the resolver skipped for a nil source, which already yields `.none`).
- `splitPane(id:…)` (`:455-479`) passes `tabs:` through; `WindowRuntime.createPane` and `AppStateStore.splitPane` are unchanged call sites.
- **`ProjectTreeBuilder`** (`BattyKit/Sources/BattyKit/Model/ProjectTreeBuilder.swift`): `build` (`:47-53`) opens a Project with `withFirstPane` and then `splitPane(id: previous.id, …, path: spec.path, tabs: spec.tabs)` for each later slot (`:127-146`), where `previous` is the slot before. `slot(for:)` maps a Terminal Pane to `Slot(kind: .terminal, tabs: tabs.isEmpty ? nil : tabs, path: nil)` (`:95`). A `nil` `tabs` falls into `makePane`'s inheriting branch, and when `previous` is a Git Status slot that is this bug.
- **Corrected premise.** #0487 described the no-Tabs terminal slot as a reachable Project path. On `main` it is not reachable through the model: `ProjectPane.init` (`Model/Project.swift:32-36`) and `ProjectPane.init(from:)` (`:48-54`) both normalize an empty Terminal `tabs` to `[ProjectTab()]` (working directory `"."`, the root), and `ProjectDraft.swift:97` does the same for the editor. So every Project-opened terminal slot carries explicit Tabs and never inherits. The branch is reachable only by assigning `[]` to the `public var tabs` after init. The `[git-status, terminal-with-no-tabs]` test is still required, as the guard for that branch and for any future `Slot` with `tabs: nil`, but the issue must not claim a user-visible Project reproduction.

**The ⌘J improvement** (#0487 Gotchas, from its round-2 review). On `release/1.2`, `inheritedSource`'s non-terminal branch (`:427-449`) reads a Process Status source only when its target is `.followingTab` (`:433-441`). A source in `.pinned` (or, once #0494 lands, `.followingName`) falls to step 4, so ⌘J from such a Pane creates a Process Status Pane following the most recently focused terminal Tab instead of watching what the source watches. The review's suggestion: carry the source's `Target` through for a Process Status destination.

## Expected behavior

1. **The port.** Never `git cherry-pick` from `release/1.2` into `main` (`AGENTS.md` "Release branches"). Branch `issue/0495` from `main` and reapply `174f06bb` there (for example `git diff 174f06bb^ 174f06bb -- <every path except issues/0487.md> | git apply --3way`, then adapt), with `#0495` commit messages and no `(cherry picked from …)` trailer. The precedence rule, the typed-view behavior, the `.info` log line, the docs changes (`docs/pane-kinds.md`, `docs/design/git-status-view.md` §1, `Concepts.md` Splitting) and the UI harness change are #0487's, unchanged. Explicit `tabs` keep winning in `makePane`; `withFirstPane` keeps building the first Pane with no source.
2. **The Project path.** `ProjectTreeBuilder` needs no code change beyond what `makePane` gains, but the unit test below proves the `tabs: nil` slot inherits from a Git Status `previous`. Keep #0487's decision for a Project-backed Session: step 4 stays "most recently focused terminal in the Session", not `Project.rootPath`; the Project's own Tab directories are explicit and do the work.
3. **⌘J carries the source's target.** `InheritedSource` gains the source Process Status Pane's target (for example `processTarget: ProcessStatusPaneContent.Target?`, set when the source is a `.processStatus` Pane whose target is `.pinned(pid)` or `.followingName(name)`; `.followingTab` keeps flowing through `followedTabID` as today). `makePane`'s Process Status branch resolves `processStatusPid.map { .pinned($0) } ?? inherited.processTarget ?? inherited.followedTabID.map { .followingTab($0) }`. The terminal split from such a source still takes step 4 for its directory, and `--pid` still wins. This matches the rule #0487 set for ⌘G from a Git Status Pane: a view opened from a view inherits what that view shows. **The `.followingName` case depends on #0494**; this issue is worked after it (ascending order). If #0494 has somehow not landed, carry `.pinned` only and say so in the summary.

## Notes

- `docs/swiftui-observation-rules.md` is binding and barely touched: every write happens inside `makePane` at creation, from an event-origin call. Do not resolve the directory lazily from a view, and do not hop it into a `Task`. Read `terminal.workingDirectory` (live), not the `TabRuntime.workingDirectory` mirror, as #0487's Notes explain.
- `InheritedSource` and `inheritedSource` stay `internal` on `release/1.2` as the seam for this port; keep them `internal` on `main` too.
- The `issue/0487` worktree under `.claude/worktrees/` is not to be touched; read `174f06bb` from `release/1.2`.
- ⌘N (`addSession`) from a non-terminal Pane still starts in `$HOME`, deliberately (#0332 B3); #0487 left it alone and so does this issue.
