# 0260 — Tab chip title does not live-update when the terminal's working directory changes

| | |
|---|---|
| **Status** | open |
| **Module** | Tabs |
| **Platform** | macOS |
| **First seen** | 2026-07-08 |

## Description

A tab chip's title goes stale when the shell's working directory changes: `cd`-ing in the terminal does not update the chip. `TabTitleFormatter.chipTitle` reads `tab.terminal.workingDirectory`, but that value is backed by Combine, not Observation, so SwiftUI does not re-render the chip when it changes. This was surfaced while resolving **#0259** (sidebar pane rows), which sidestepped the problem for the *sidebar* by switching that label to a tree-derived position — but the tab chips themselves still show the stale directory.

## Steps to reproduce

1. Open a session with at least one tab whose chip shows the working directory.
2. In that tab's terminal, `cd` into a different directory.
3. Observe the tab chip.

## Expected behavior

The chip title reflects the current working directory (or updates on whatever OSC title / cwd signal it derives from) shortly after the directory changes.

## Actual behavior

The chip keeps showing the directory from when the chip was last rendered; it does not update on `cd`.

## Notes

- Root cause (from #0259 review): `workingDirectory` is Combine-backed and not tracked by Observation, so SwiftUI view updates aren't triggered on change. The fix likely bridges the Combine publisher into observed state (or exposes the cwd via an `@Observable` property the chip reads) so the chip re-renders.
- Relevant code: `TabTitleFormatter.chipTitle`, the terminal's `workingDirectory` source, and the tab chip view.
- See `docs/swiftui-observation-rules.md` before changing observed-state wiring.

## Relation

- Discovered during **#0259** (sidebar pane rows replaced the stale path label with a tree-derived `column/row` position). #0259 fixed the sidebar rows only; this ticket covers the same staleness for the tab chips.
