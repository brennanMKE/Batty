# 0260 — Auto-name tab chips and sidebar pane rows via Apple Intelligence, with per-tab chips and persistent user overrides

| | |
|---|---|
| **Status** | open |
| **Module** | Tabs / Sidebar |
| **Platform** | macOS |
| **First seen** | 2026-07-08 |

## Description

Originally filed as a staleness bug: a tab chip's title goes stale when the shell's working directory changes, because `TabTitleFormatter.chipTitle` reads `tab.terminal.workingDirectory`, which is Combine-backed and not Observation-tracked, so SwiftUI never re-renders the chip on `cd`. That bug still stands, but the scope has expanded — the user now wants intelligent auto-naming for both tab chips and the sidebar pane rows, which subsumes the staleness fix (the new naming path must be live / Observation-tracked). The user's request, verbatim:

> "For #0260 we want to make improvements for the tab chips but also the newly added list under the session on the left column. Both should have the same value, but the left column only describes the pane not individual tabs. We can use Apple Intelligence and the project files to automatically name both as we do the session name and it should use the setting which toggles support for Apple Intelligence.
>
> For the title set under the session just use the first tab in a pane. Then tab chips for each tab can be specific to each tab. Ensure that if the user sets the title it remains unless the user resets it."

## Desired behavior

- **Auto-naming via Apple Intelligence.** Both tab chips and the sidebar pane rows (the per-pane list under each Session in the left column, added in #0259) get automatically generated names, derived from the project files / working directory using the same mechanism that already auto-names Sessions (`FoundationModelsNameSuggester` and the `SessionNameSuggesting` chain — see Notes). Gated by the existing Apple Intelligence setting (`SettingsPreference.autoNameWithAIKey`, the "Use Apple Intelligence to suggest names" toggle in Settings → General → Session Naming). When the toggle is off (or the model is unavailable — the toggle is disabled below macOS 26), fall back to non-AI naming: the existing `TabTitleFormatter.chipTitle` chain for chips, and the #0259 `column/row` position label for sidebar pane rows.
- **Tab chips are per-tab.** Each Tab's chip gets a name specific to that tab (its own working directory / project context), not a shared pane-level name.
- **Sidebar pane row uses the pane's first tab.** The left-column row describes the *Pane*, not individual tabs, so it shows the name derived from the **first tab in that pane**. "Both should have the same value": the sidebar pane row displays exactly the value the first tab's chip displays. (Today `PaneRow.paneLabel` reads `pane.activeTab?.titleOverride` — the active tab, not the first — appended to the position; that changes.)
- **User override persists.** If the user sets a title (the `tab.titleOverride` path via the Rename… sheet), it stays and is never overwritten by auto-naming, until the user resets it — at which point auto-naming resumes for that tab. An explicit reset affordance is required; the tab context menu's existing "Reset Title" (sets `titleOverride = nil`) is the model to follow or extend.
- **Live-updating (subsumes the original bug).** Displayed names must update when the underlying signal changes (working directory / project context) — i.e. the naming inputs must be Observation-tracked, not Combine-only. This fixes the original staleness: `cd` in a terminal must refresh that tab's chip (and, if it's the pane's first tab, the sidebar pane row) shortly after.

## Steps to reproduce (original staleness bug)

1. Open a session with at least one tab whose chip shows the working directory.
2. In that tab's terminal, `cd` into a different directory.
3. Observe the tab chip — it keeps showing the directory from the last render.

## Notes

- **Session-name auto-naming (the mechanism to reuse):** `BattyKit/Sources/BattyKit/ProjectName/SessionNameSuggester.swift` — protocol `SessionNameSuggesting`, implementation `FoundationModelsNameSuggester` (Apple's on-device FoundationModels framework, `makeIfAvailable()` factory), validation in `SessionNameSuggestion.sanitize`, file-reading tool support in `SessionNameToolSupport` (reads top-level project entries + file excerpts). The trigger/orchestration lives in `AppStateStore.handleWorkingDirectoryChange(forTabID:)` (`BattyKit/Sources/BattyKit/Runtime/AppStateStore.swift`): deterministic chain first (`SessionNameCache`, `ProjectNameResolver`), then the AI fallback with per-cwd memoization (`nameSuggestionMemo`) and debounced scheduling (`scheduleNameSuggestion` / `cancelNameSuggestion`). Note it currently only names the *anchor tab* (first leaf pane's first tab) of *single-pane* sessions — per-tab naming is a real extension, not a rewire.
- **Apple Intelligence toggle:** `SettingsPreference.autoNameWithAIKey` (`"co.sstools.Batty.autoNameWithAI"`) in `BattyKit/Sources/BattyKit/Settings/SettingsPreferences.swift`, resolved via `SettingsPreference.resolvedAutoNameWithAI()`; UI is the "Use Apple Intelligence to suggest names" toggle in `SettingsView.swift`, Settings → General → "Session Naming" section (disabled when the model is unsupported, "Requires macOS 26"). The companion "Name sessions from project files" toggle (`autoNameFromFiles`) gates the deterministic chain.
- **Tab chip path:** `TabTitleFormatter.chipTitle(for:fallback:)` (`BattyKit/Sources/BattyKit/Util/TabTitleFormatter.swift`) — priority today: `titleOverride` → home-dir `~` → running command → stripped OSC title → `ProjectNameResolver` / prettified cwd → fallback. Rendered in `PaneView.swift` (chip row, drag preview, `tab-chip.*` accessibility ids) and reused by `BattyCommands` and `OpenQuicklyView`.
- **Sidebar pane row path (#0259):** `SplitTree.panePositions` / `PanePosition.label` (`BattyKit/Sources/BattyKit/Model/SplitTree.swift`) feed `PaneRow.paneLabel` in `BattyKit/Sources/BattyKit/Views/SessionSidebarView.swift` — currently `column/row` position, with the active tab's `titleOverride` appended when set.
- **User-set titles:** `TabRuntime.titleOverride: String?` (`BattyKit/Sources/BattyKit/Runtime/TabRuntime.swift`), written by the Rename… sheet in `PaneView.swift` (empty commit clears to `nil`) and cleared by the context menu's "Reset Title". Sessions have the analogous `SessionRuntime.titleOverride: Bool` pin that auto-naming already respects — tab auto-naming must respect `tab.titleOverride` the same way.
- **Root cause of the original staleness** (from #0259 review): `workingDirectory` is Combine-backed and not tracked by Observation, so SwiftUI view updates aren't triggered on change. Whatever naming path lands here must bridge that signal into observed state.
- See `docs/swiftui-observation-rules.md` (binding) before changing observed-state wiring.

## Open questions

- **When is auto-naming (re)triggered?** On every cwd change? Debounced / on idle? It's an on-device model call, so per-keystroke or rapid-`cd` retriggering needs the same memoization + debounce discipline `AppStateStore` already applies for sessions. Does a per-tab memo share the session memo (`nameSuggestionMemo` is keyed by cwd)?
- **What is the reset UI?** Extend the existing tab context-menu "Reset Title", add a matching affordance on the sidebar pane row, or both?
- **Does the sidebar row follow the first tab even when a different tab is active?** The requirement says first tab; today's `PaneRow` reads the active tab's override. Confirm the first-tab rule holds regardless of tab selection, and what "first" means after tab reorder.
- **Does the sidebar pane row keep the `column/row` position** alongside the AI name (as it does today for overrides), or replace it?
- **Background / throttled sessions:** behavior when Apple Intelligence is throttled or unavailable mid-session — silently keep the fallback name, or retry later?
- **Multi-pane sessions:** session-level auto-naming deliberately skips multi-pane sessions (#0213). Per-pane naming presumably lifts that restriction for pane rows — confirm session titles remain governed by the existing anchor-tab rule.

## Relation

- Builds on **#0259** (sidebar pane rows: replaced the stale path label with a tree-derived `column/row` position via `SplitTree.panePositions`). Those rows are the "list under the session on the left column" this issue extends. #0259 fixed the sidebar staleness only; the tab-chip staleness it left behind is folded into this issue's live-update requirement.
