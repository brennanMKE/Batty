# 0127 — Pane swap by drag-and-drop with animation

| | |
|---|---|
| **Status** | open |
| **Module** | Pane / Split |
| **Platform** | macOS |
| **First seen** | 2026-05-14 |

## Description

Swap two panes' positions in the split tree by dragging one over the other. Pick up a pane from its title strip (or a dedicated drag handle), drag it over another pane in the same window, drop — the two panes exchange positions and the layout animates into place. Mirrors tmux's `prefix-{` / `prefix-}` swap, but with direct manipulation instead of a keybinding.

The implementation can borrow from the existing tab-reorder behavior in SlidingTabs, which already handles a similar pattern — chip drag, drop-target highlight, animated reposition. Translating that to panes-in-a-split-tree is the work.

## Acceptance criteria

- A pane's title strip (or another deliberate handle — not the terminal body) initiates a drag when long-pressed or dragged with enough threshold to distinguish from a normal click.
- During the drag, the dragged pane's chrome follows the cursor as a translucent preview.
- Every other pane in the same window highlights as a drop target when the cursor enters its bounds.
- Dropping over a target pane swaps the two panes in the underlying `SplitNode` tree. The split structure (which splits are horizontal / vertical, the ratios) is preserved — only the leaf contents (terminal sessions) trade places.
- The post-drop transition animates smoothly — both panes' frames interpolate to their new positions, not a hard cut. Reuse SwiftUI's `.animation(.spring, value: …)` against the layout model so the renderer's existing layout pass handles the tweening.
- The dragged pane's keyboard focus follows the swap (the originally-dragged pane stays focused, now in its new position).
- Drop on the originally-dragged pane (no-op location) cancels cleanly with a snap-back animation; no state change.
- Drop outside any pane cancels cleanly.

## Out of scope

- Dragging a pane *into a split position* (e.g. drop on the right half of a target pane to convert it into a new split with the dragged pane on the right). That's "rearrange the tree by drag," a strictly larger feature. Pure swap is a clean v1; the split-creation variant can land as a follow-up.
- Dragging a pane out of the window to detach it. Multi-window support is gated on `#0027`; until that lands, drag-to-detach has nowhere to go.
- Dragging a tab between panes. That's a different shape and tracked separately if needed.
- Cross-session pane drag. Pane swap stays within the current session for v1.

## Notes

- The existing tab-chip drag in SlidingTabs is the prior art — read it first. The pane drag will sit one level up in the view hierarchy (`PaneView` rather than tab chip) but the gesture, the translucent preview, and the drop-target highlight should feel consistent.
- The split-tree mutation is a swap on two `SplitNode.leaf(...)` cases (or wherever leaf panes live) — find the two paths to the swapped leaves, exchange them. Make sure focus state, bell counters, and any per-pane runtime state (`PaneRuntime`) travel with the pane, not with the tree position.
- Animation: SwiftUI's implicit layout animation on a `.spring(response: 0.32, dampingFraction: 0.78)` (roughly tmux-fast, not iOS-bouncy) tends to feel right for terminal-app UI. Worth a quick A/B with the existing split-divider drag for consistency.
- Cursor: standard "grabbing hand" during the drag, "no" cursor over invalid drop zones (everywhere except inside the window's other panes).
- File-drop UX (`#0022`) lives on the terminal *body*; pane-drag UX should live on the title strip / handle, so the two don't conflict. Verify by reproducing: drag a file from Finder onto a pane vs. drag the pane handle of one pane onto another.
