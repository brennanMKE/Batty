## Description

**HIGH. Related to #0601 and #0604.** `BellFeedStore.unseenCount` and `unseenReminderEntries(forSessionID:)` are computed by scanning `entries`, and they are read in view bodies: the window toolbar's bell icon (inside `SessionDetailView.body`'s `.toolbar` closure), the main-menu `BattyCommands` body, and every sidebar Session row (its accessibility value and its Reminder badge). `entries` is rewritten on every bell, repeat-count collapse, seen mark, removal and AI-summary arrival, most of which change neither the unseen count nor the reminder-due state. Each write re-runs every window's `SessionDetailView.body` (including the `ForEach` over every Session, #0604), every window's sidebar body (every row), and the `Commands` body. Since #0602, `markActiveTabSeen` runs from `selectedSessionID`'s `didSet`, so a Session switch's Feed write lands in the same flush as the switch.

### Files and approach

1. **`BattyKit/Sources/BattyKit/Runtime/BellFeedStore.swift`**
   - Add two stored aggregates, both `Equatable` and written only as whole values:
     ```swift
     public private(set) var unseenCount: Int = 0
     public private(set) var dueReminderSessionIDs: Set<UUID> = []
     ```
     Delete the computed `unseenCount` (`:334-336`). Callers keep the same name and type, so `BattyCommands`, `SessionDetailView` and the existing tests compile unchanged.
   - Keep them in sync from one place: give `entries` a `didSet { refreshAggregates() }`. `@Observable` keeps property observers (`WindowRuntime.selectedSessionID` and `PaneRuntime` already use `didSet` in `@Observable` classes). `didSet` covers every mutator (`record`, `recordOrCollapse`, `markSeen`, `markAllSeen`, `updateSummary`, `removeReminderEntries`, `removeEntries`, cap eviction) and the `internal(set)` writes tests make directly (`AppStateStoreReminderTests.swift:272`, `store.bellFeed.entries[0] = entry`). A new mutator cannot forget it. The cost is one O(n) scan per write, with n ≤ `cap` (200). That is the same scan the old computed property ran for every reader on every body.
   - `refreshAggregates()` is private. It computes both values in one pass and assigns each **only when it differs**:
     ```swift
     private func refreshAggregates() {
         var unseen = 0
         var due: Set<UUID> = []
         for entry in entries where !entry.seen {
             unseen += 1
             if entry.kind == .reminder { due.insert(entry.sessionID) }
         }
         if unseen != unseenCount { unseenCount = unseen }
         if due != dueReminderSessionIDs { dueReminderSessionIDs = due }
     }
     ```
     A whole-value equal write to an `Equatable` property would not notify anyway (AGENTS.md / `ObservationEqualWriteSemanticsTests`). The explicit guard documents intent and doesn't depend on that toolchain behavior. Never mutate the set in place (`insert`/`remove` on the stored property): an in-place mutation always notifies.
   - `init(entries:)`: `didSet` does not fire for writes in `init`, so call `refreshAggregates()` at the end of `init`, after the sort and cap. All stored properties have defaults, so calling a method there is legal.
   - `dueReminderSessionIDs` must match exactly what `!unseenReminderEntries(forSessionID:).isEmpty` returned: `kind == .reminder && !seen`, keyed by `sessionID`. Keep `unseenReminderEntries(forSessionID:)` for `WindowRuntime` and for the alarm leaf below.
   - Write a short doc comment on the two properties giving the *why*: views read these instead of scanning `entries`, so a Feed write that changes neither aggregate doesn't invalidate them. No issue numbers.
   - Leave `unseenCount(forTabID:/forPaneID:/forSessionID:)` alone. They have no view readers today (check with grep; if one appears after the merge, note it in Gotchas rather than widening scope).

2. **`BattyKit/Sources/BattyKit/Views/SessionDetailView.swift`**: extract the toolbar bell button (`:220-240`, the `Button { bellFeedShown.toggle() } … .popover { BellFeedView … }`) into a new `private struct BellFeedToolbarButton: View` in the same file, with `let store: AppStateStore` and `@Binding var isShown: Bool`. Its body is the current code, with `bellFeedShown` replaced by `isShown`, and it reads `store.bellFeed.unseenCount > 0`. In `toolbarItems`, use `BellFeedToolbarButton(store: store, isShown: $bellFeedShown)`. Then `SessionDetailView.body` no longer reads any Bell Feed state; only the leaf does. Keep `.help`, `.symbolRenderingMode`, the popover's `arrowEdge`, and the `onJump`/`onDismiss` closures exactly as they are. `bellFeedShown` stays `@State` on `SessionDetailView`, because the `.battyToggleBellFeed` notification handler there toggles it. Check the accessibility identifier and the label text don't change: UI tests find the button by its label.

3. **`BattyKit/Sources/BattyKit/Commands/BattyCommands.swift:326`**: no source change. It now reads the stored `Int`, so the `Commands` body re-runs only when the count changes. (Extracting a leaf there isn't worth it: the `Commands` body is cheap and the stored read already removes the per-bell invalidation.)

4. **`BattyKit/Sources/BattyKit/Views/SessionSidebarView.swift`** (in #0604's shape after the merge):
   - `reminderState`: replace `!store.bellFeed.unseenReminderEntries(forSessionID: session.id).isEmpty` with `store.bellFeed.dueReminderSessionIDs.contains(session.id)`.
   - `ReminderBadge`: replace the `else if let due = store.bellFeed.unseenReminderEntries(…).first` branch with `else if store.bellFeed.dueReminderSessionIDs.contains(session.id) { DueReminderAlarm(store: store, sessionID: session.id, accent: accent) }`. Add `private struct DueReminderAlarm: View`. Its body reads `store.bellFeed.unseenReminderEntries(forSessionID:).first?.message` for the `.help` text, with the same `"Reminder is due"` fallback, `alarm.fill`, `.imageScale(.small)`, accent foreground and `.accessibilityHidden(true)`. Only rows that actually have a due Reminder mount this leaf, so only they track `entries`, and the row body never does.
   - Result: a sidebar row's body depends on `dueReminderSessionIDs` (changes only when a Reminder fires, is seen, or is removed) and never on `entries`.

5. **`docs/notifications.md`**: one sentence where the Feed store is described: views read `unseenCount` / `dueReminderSessionIDs` (stored, refreshed when `entries` changes, written only when the value changes), never scan `entries`. Only `BellFeedView` reads `entries`.

## Resolution

`BellFeedStore.unseenCount` and the new `dueReminderSessionIDs: Set<UUID>` are stored properties, recomputed in one pass from `entries`' `didSet` (and once at the end of `init`) and assigned only when the value differs. Views read them instead of scanning `entries`:

- `SessionDetailView`: the toolbar bell moved into `private struct BellFeedToolbarButton` (same label, help, popover and closures), so `SessionDetailView.body` reads no Bell Feed state.
- `SessionSidebarView`: `SessionSidebarRow.reminderState` and `ReminderBadge` read `dueReminderSessionIDs.contains(session.id)`; the due alarm is a new `DueReminderAlarm` leaf that alone reads `unseenReminderEntries` for its tooltip, mounted only on due rows.
- `recordOrCollapse` now builds the reordered array locally and assigns `entries` once; the old remove-then-insert passed through a state without the row and flipped `unseenCount` 1 to 0 to 1 (caught by the collapse test after the first fix).
- `BattyCommands` unchanged; it now reads the stored `Int`.
- `docs/notifications.md`: one bullet on the aggregates.
