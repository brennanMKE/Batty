# 0609 — Bell Feed counts are scanned from entries in view bodies, so every Feed write re-renders the toolbar, the menu and every sidebar row

| | |
|---|---|
| **Status** | open |
| **Module** | BellFeed / Sidebar |
| **Platform** | macOS |
| **First seen** | 2026-11-12 |
| **Priority** | high |

## Description

**HIGH. Related to #0601 and #0604.** `BellFeedStore.unseenCount` and `unseenReminderEntries(forSessionID:)` are computed by scanning `entries`, and they are read in view bodies: the window toolbar's bell icon (inside `SessionDetailView.body`'s `.toolbar` closure), the main-menu `BattyCommands` body, and every sidebar Session row (its accessibility value and its Reminder badge). `entries` is rewritten on every bell, repeat-count collapse, seen mark, removal and AI-summary arrival, most of which change neither the unseen count nor the reminder-due state. Each write re-runs every window's `SessionDetailView.body` (including the `ForEach` over every Session, #0604), every window's sidebar body (every row), and the `Commands` body. Since #0602, `markActiveTabSeen` runs from `selectedSessionID`'s `didSet`, so a Session switch's Feed write lands in the same flush as the switch.

## Current state (verified 2026-11-12 on `main` `ce66ca6a`)

- `BattyKit/Sources/BattyKit/Runtime/BellFeedStore.swift:198`: `public internal(set) var entries: [BellFeedEntry]`.
- `BellFeedStore.swift:334-336`: `unseenCount` = `entries.lazy.filter { !$0.seen }.count`.
- `BellFeedStore.swift:359-361`: `unseenReminderEntries(forSessionID:)` filters `entries`.
- Readers:
  - `Views/SessionDetailView.swift:227`: `systemImage: store.bellFeed.unseenCount > 0 ? "bell.badge" : "bell"`, in `toolbarItems`.
  - `Commands/BattyCommands.swift:326`: `.disabled(store.bellFeed.unseenCount == 0)`.
  - `Views/SessionSidebarView.swift:75-84` (`reminderState(for:)`, called at `:179` for every row's `accessibilityValue` inside the sidebar body's `ForEach`) and `:469` (`ReminderBadge`). Both read `unseenReminderEntries` only when `session.reminder` is nil, the common case.

## Rule violated

- `docs/swiftui-observation-rules.md`, "Observation semantics and dependency granularity": pass narrow values; computed helpers broaden dependencies.
- swift-guidance `swiftui-observation.md`: a view should depend on the one fact it shows, not a hot array.

## Evidence

- **Proven:** the reads and the writes.
- **Inferred:** that `.toolbar`'s content closure is attributed to `SessionDetailView.body` (likely, it is non-escaping), and the per-bell cost. A BEL flood from an unfocused Tab does this per bell.

## Fix direction

- Keep `entries` for `BellFeedView` only. Add stored, `Equatable` aggregates maintained by the store's mutators (`record`, `recordOrCollapse`, `markSeen`, `markAllSeen`, removals, reminder adds): `private(set) var unseenCount: Int` and `private(set) var dueReminderSessionIDs: Set<UUID>`, written only when they change. Views read those.
- Extract the toolbar bell button into its own `View` (e.g. `BellFeedToolbarButton`) so it is the only toolbar reader.
- In the sidebar, have each row read only its own membership in `dueReminderSessionIDs`, ideally from inside the row view rather than the sidebar body.

## Tests

- New in `BellFeedStoreTests`: `collapsingARepeatedBellDoesNotNotifyUnseenCountReaders()`, `aiSummaryArrivalDoesNotNotifyUnseenCountReaders()`, `markingSeenUpdatesUnseenCount()` (non-default fixture with several unseen entries), `dueReminderSessionIDsTracksReminderEntries()`, and a consistency test that `unseenCount` equals the scan after every mutator. The two "does not notify" tests use `withObservationTracking` on the aggregate; they fail before (the computed property tracks `entries`) and pass after.
- Keep passing: `BellFeedStoreTests`, `BellFeedVisitTests`, `ReminderEntryPointTests`.
- UI, at the daily VM run: `BattyUITests/BellFeedTests`, `BattyUITests/SessionReminderTests`, `SidebarTests`.
