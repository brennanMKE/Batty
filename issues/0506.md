# 0506 — There is no way to produce a notarized Batty Beta DMG for installing on a second Mac

| | |
|---|---|
| **Status** | open |
| **Module** | Build |
| **Platform** | macOS |
| **First seen** | 2026-10-14 |

## Description

No command in the repo produces a Batty Beta that another Mac will open. `./build.sh package --sign` builds a Developer ID signed `Batty Beta.app`, but the notary service would reject it, and nothing packages it as a DMG or notarizes it. `scripts/release.sh` notarizes, but only the Prod scheme. A Beta copied to a second Mac without notarization gets the Gatekeeper "unidentified developer" block.

The fix is an opt-in mode, `./build.sh package --sign --notarize`. It extends the existing sanctioned `package --sign` Developer ID site in `scripts/build-beta.sh`. It is not a new Developer ID site.

## User request (2026-10-14)

The user wants to confirm that iCloud sync of Shared Projects (#0503) works between their Mac mini and their MacBook. That needs a Beta `.dmg` to install on the MacBook. The user approved notarizing the Beta for this: "You can notarize the beta app for my MacBook install."

## Verified facts (main `2c630f08`)

- `./build.sh package` runs `exec scripts/build-beta.sh "$@"`, so new flags reach `build-beta.sh` unchanged. `build-beta.sh` currently rejects any flag other than `--sign`, `--teardown` and `-h/--help`.
- `build-beta.sh` hardcodes `CONFIGURATION="Debug"` and runs `xcodebuild build` (not `archive`). `--sign` passes `BATTY_SIGNING=developerid` after `scripts/install-profiles.sh --quiet`. Output is `beta-build/Products/Batty Beta.app`. The script never creates a DMG.
- The `--sign` result is Developer ID signed with hardened runtime, but the notary service would reject it. It needs a secure timestamp on every binary and no `get-task-allow`, and this build has neither:
  - Xcode signs a `build`-action product with `--timestamp=none`. The app's main executable, `Batty Beta.debug.dylib` and `__preview.dylib` show a local `Signed Time=`, not a secure `Timestamp=`.
  - The Debug signature's entitlements include `com.apple.security.get-task-allow`.
  - The "Embed CLI" and "Embed Broker" phases (`project.pbxproj`) sign `Contents/Resources/bin/batty` and `BattyBroker` with `--timestamp` only when `ACTION = install` (Archive). Any other action uses `--timestamp=none`, so both show `Signed Time=` only. A plain `xcodebuild build -configuration Release` still has `ACTION = build`, so switching the configuration alone does not fix this.
  - Sparkle's nested code (`Sparkle.framework/Versions/B/Autoupdate`, `Updater.app`, `XPCServices/Downloader.xpc`, `XPCServices/Installer.xpc`) showed no `Timestamp=` line on the same build. The notary service checks nested code inside frameworks too. `release.sh` avoids this because `-exportArchive` (method `developer-id`) re-signs nested code with a timestamp.
- `release.sh`'s pipeline is: install profiles, then `preflight.sh --credentials-only`, then `xcodebuild archive` (Release, `BATTY_SIGNING=developerid`), then `-exportArchive` (manual, `developer-id`, profile map). Next it re-signs `bin/BattyBroker` and `bin/batty` with `--options runtime --timestamp` and re-signs the app with its extracted entitlements (#0273). It then runs `codesign --verify --deep --strict` and `verify-profile.sh`, and checks each embedded binary's Authority, team, runtime flag and timestamp. Last come `create-dmg` (work file named to match `--volname`), `codesign --timestamp` on the DMG, `notarytool submit --keychain-profile Batty-notary --wait`, `stapler staple` and `validate`, and `spctl -a -t open`.
- The Beta profile is committed: `Configuration/Profiles/Batty_Beta.provisionprofile`, name `Batty Beta Developer ID`, App ID `XV8BAAVZ6V.co.sstools.Batty.beta`. `Configuration/Beta.xcconfig` selects it through `BATTY_DEVELOPER_ID_PROFILE` when `BATTY_SIGNING=developerid`.

## Decision

Add `--notarize` to `scripts/build-beta.sh`, valid only together with `--sign` (`--notarize` alone exits non-zero with a usage message). With it, the script:

1. Builds a configuration the notary service accepts: Release, or whatever `release.sh` archives with, which has no `get-task-allow`. It uses `BATTY_SIGNING=developerid`, the Beta profile and `Batty/Batty.entitlements`, with Manual signing via the committed profiles. Recommended: `xcodebuild archive` of the `Batty (Beta)` scheme plus `-exportArchive` with `method = developer-id`, `signingStyle = manual` and `provisioningProfiles = { co.sstools.Batty.beta = Batty Beta Developer ID }`, mirroring `release.sh`. That gives Sparkle's nested code a timestamp and makes the Embed phases run with `ACTION = install`. If the implementer uses `build` instead, every nested Mach-O, Sparkle's included, must be re-signed with a timestamp, inside-out.
2. Re-signs `Contents/Resources/bin/BattyBroker` and `Contents/Resources/bin/batty` with the Developer ID identity and `--options runtime --timestamp`, then re-signs the app with its extracted entitlements, the same way `release.sh` does (#0273).
3. Verifies the result the way `release.sh` does: `codesign --verify --deep --strict`, `scripts/verify-profile.sh` on the app, and a direct per-binary check (Developer ID Authority equal to the app's, same team, hardened runtime, secure `Timestamp=`) before spending the notarization round trip. It also asserts that the app's entitlements carry no `get-task-allow`.
4. Creates a DMG with `create-dmg`, volume name "Batty Beta". The work file's name matches the volume name (`Batty Beta.dmg`), as in `release.sh`. It then signs the DMG with `codesign --timestamp`.
5. Runs `xcrun notarytool submit --keychain-profile Batty-notary --wait`, then `xcrun stapler staple` and `xcrun stapler validate`.
6. Runs `scripts/verify-dmg.sh` on the stapled DMG. `verify-dmg.sh` runs `verify-profile.sh` on the inner app, and the step-3 call covers the app before submission. Exits non-zero if either fails.
7. Renames the result to `dist/Batty-Beta-<short sha>.dmg` and prints that path.

Constraints:

- **Never** touches the Keychain or the developer account. **Never** uses Automatic signing for this build. **Never** passes `-allowProvisioningUpdates` or `-allowProvisioningDeviceRegistration`. If a signing or notarization step fails, it stops and reports. It never works around a failure (AGENTS.md, "Developer ID certificate").
- The mode installs nothing. It does not copy into `/Applications`, does not launch the app and does not register the broker. Like the current script, it prints the next step instead.
- Like the rest of the script, it snapshots and restores `Configuration/Active.xcconfig` on every exit path.
- It leaves no stray `Batty Beta.app` that LaunchServices would index, apart from the one copy the script already keeps in `beta-build/Products` (#0026). Archive and export intermediates go under `beta-build/` and are removed on success.
- It checks for `create-dmg` and the `Batty-notary` profile before building, as `release.sh` does. It may reuse `preflight.sh --credentials-only` if that check does not require Prod-only items.
- **Notarization is a shared-state action.** It uploads the binary to Apple, so it runs only with the user's go-ahead, each time. **The user gave that go-ahead for this Beta on 2026-10-14** (quote above). That approval covers the run that verifies this issue. It is not a standing authorization for future `--notarize` runs.

Docs to update in the same change:

- `docs/code-signing.md`: add a `./build.sh package --sign --notarize` row to "Which build signs with what", and update the Developer ID row of the Identities table.
- `AGENTS.md`, "Developer ID certificate" section: extend the `./build.sh package --sign` bullet to mention `--notarize`. It produces a notarized Beta DMG for installing on another Mac, and it notarizes only with the user's go-ahead each time. The section still names exactly two Developer ID sites.
- `build.sh`'s usage line (`./build.sh package [--sign]`) and the `build-beta.sh` header/`--help` text.

## Acceptance criteria

- [ ] `./build.sh package --sign --notarize` produces `dist/Batty-Beta-<sha>.dmg`. The DMG is signed with the Developer ID identity, notarized and stapled (`xcrun stapler validate` passes).
- [ ] `scripts/verify-dmg.sh dist/Batty-Beta-<sha>.dmg` passes every check: stapled ticket, `source=Notarized Developer ID`, DMG signature, the quarantined copy accepted by Gatekeeper, deep verify of the inner app, and the profile and entitlement assertions (`XV8BAAVZ6V.co.sstools.Batty.beta` kvstore key, Beta profile embedded).
- [ ] The inner `Batty Beta.app` has no `get-task-allow`. The app, `bin/batty`, `bin/BattyBroker` and Sparkle's nested code each carry a secure `Timestamp=`, hardened runtime and the Developer ID Authority.
- [ ] `--notarize` without `--sign` is rejected with a usage message and does nothing.
- [ ] Plain `./build.sh package --sign` is unchanged: Debug, `xcodebuild build`, output at `beta-build/Products/Batty Beta.app`, no DMG, no notarization. Show this with a diff of the code path, or one run before and after.
- [ ] Routine builds are unchanged: `./build.sh`, `./build.sh unit`, `./build.sh package` (unsigned), `./build.sh release …` and the VM runner. They never use the Developer ID identity and never call `notarytool`. `./build.sh` and `./build.sh unit` pass.
- [ ] No `xcodebuild` call in the repo passes `-allowProvisioningUpdates` (`grep -rn allowProvisioning scripts build.sh tools` finds only comments and docs).
- [ ] `docs/code-signing.md`, AGENTS.md's Developer ID section, `build.sh`'s usage text and `build-beta.sh --help` describe `--notarize`.
- [ ] `Configuration/Active.xcconfig` is identical before and after a `--notarize` run, including after a failed run.

## Notes

- **Restricted area.** `scripts/` is restricted (AGENTS.md, "Restricted areas"), and so is the Developer ID signing path. This change was approved through the user's notarization request on 2026-10-14, **pending their confirmation** that the approval extends to editing `scripts/build-beta.sh`. The orchestrator should confirm with the user before dispatching the implementer.
- **Running the verification.** The acceptance run submits to Apple. The implementer runs it once, under the 2026-10-14 go-ahead, and records the notarytool submission ID and the `verify-dmg.sh` output in the Work log. If notarization is rejected, fetch the log (`xcrun notarytool log <id> --keychain-profile Batty-notary`), record it, and stop. Do not retry blindly.
- **Universal binary.** Release builds `arm64 x86_64`. The Embed phases already split `ARCHS` correctly (#0273), so no change is expected there.
- **Installing on the MacBook** stays manual. The user mounts the DMG and drags `Batty Beta.app` to Applications. The Beta teardown steps (`scripts/build-beta.sh --teardown`, `docs/beta-teardown.md`) apply on that Mac too.
- Related: #0265 (certificate revocation, why signing is fenced), #0273 (embedded binaries sealed as resources, timestamp keyed on `ACTION`), #0279 (Beta alongside Prod), #0503 (iCloud sync, the Beta profile and the two Developer ID sites).
