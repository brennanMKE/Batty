# 0022 — File-URL drag-and-drop on TerminalSurfaceNSView with shell-quoted text injection

| | |
|---|---|
| **Status** | open |
| **Module** | DragDrop / TerminalSurface |
| **Platform** | macOS |
| **First seen** | 2026-05-08 |

## Description

Make `TerminalSurfaceNSView` a drag destination for file URLs. When the user drops one or more files from Finder (or any source producing file URLs), insert their POSIX-quoted paths at the cursor, space-separated, with a trailing space (PRD §6.12). This is a hard-required v1 feature — it's how the user shares screenshots/videos with Claude Code.

**Acceptance criteria:**
- `TerminalSurfaceNSView.registerForDraggedTypes([.fileURL])` is called.
- `draggingEntered`, `draggingUpdated`, `prepareForDragOperation`, `performDragOperation`, `draggingExited` are implemented.
- On a successful drop, file URLs are extracted from the pasteboard and converted to POSIX-quoted shell paths via a small `shellQuote(_ path: String) -> String` helper.
- The resulting string (paths space-separated with trailing space) is fed into the surface via `ghostty_surface_text(...)` — same entry point as paste.
- Confirmed manually: dropping a screenshot named like `Screenshot 2026-05-08 at 12.34.56.png` (with U+202F) inserts a single-quoted path that, when Enter'd, the shell can `cat`/`open`/etc. successfully.

## Notes

- POSIX shell quoting: prefer single-quotes and escape internal single-quotes via `'\''`. Don't try to be clever about backslashes — single-quoting handles everything.
- libghostty has no concept of drag-and-drop; this is entirely AppKit-level.
- Browser-dragged URLs (Safari) are **out of scope** for v1 (PRD §6.12) — only `.fileURL` types.
- Drag-over highlight is #0023.

## Revised approach — 2026-05-08

With `GhosttyTerminal` providing `TerminalView` (an `NSView` typealias) and `TerminalSurfaceView` (the SwiftUI wrapper), there's no longer "our own NSView" to register drag-drop on. Two viable paths:

1. **Subclass `TerminalView` (`AppTerminalView`)** in `BattyKit` and add `NSDraggingDestination` conformance there. Override `registerForDraggedTypes`, `draggingEntered`, `performDragOperation`, and emit text via `terminalView.surface?` or whatever GhosttyTerminal exposes for sending text. Use the subclass instead of the bare `TerminalView` in our SwiftUI hierarchy.
2. **Wrap `TerminalSurfaceView` in a SwiftUI overlay** that uses `.onDrop(of: [.fileURL], …)` modifier. Simpler, but the drop target sits *over* the terminal and intercepts events; need to check it doesn't block keyboard focus.

Path 2 is cleaner and aligns with "use what's available." Try it first; fall back to subclassing if the overlay interferes with focus / mouse events.

For text injection, `GhosttyTerminal` likely exposes a `send(_:)` or similar on its surface controller. If not, drop down to `BattyKit`'s re-exported `GhosttyKit` and call `ghostty_surface_text(surface, ...)` against the underlying `ghostty_surface_t` if the wrapper exposes it.

**Revised acceptance criteria:**
- File-URL drop on a terminal pane inserts POSIX-quoted paths via whatever `send-text` API `GhosttyTerminal` exposes (or `ghostty_surface_text` directly if needed).
- Implementation lives in `BattyKit` so it composes with `TerminalSurfaceView` cleanly.
- Verified manually with a screenshot drop from Finder containing `Screenshot 2026-05-08 at 12.34.56.png` (U+202F narrow no-break space test).
