## Description

UI test `BattyUITests.SidebarTests.testSidebarVisibleOnColdLaunch` (`BattyUITests/SidebarTests.swift:30`) fails with:

```
XCTAssertTrue failed - Sidebar must be visible on launch
```

This test was created by [[0167]] as part of the UI test automation suite. The test was previously masked by the `Thread.sleep` runloop-blocking bug fixed in [[0170]] — the failure is now visible on every test run.

## What to investigate

Open `BattyUITests/SidebarTests.swift:30` and trace what state the assertion is checking. Cross-reference [[0167]] for the test's design and acceptance criteria.

The failure is one of:

- **App bug** — the behavior the test asserts on is genuinely broken; fix the app.
- **Test bug** — the test's assertion, setup, or accessibility-identifier expectation is wrong; fix the test.
- **Test infra gap** — a required driver intent or accessibility identifier referenced by the test doesn't exist yet; add it.

Look at the lines around `:30` and at the driver script (if any) in the test's launch call to determine which.

## Root cause

`BattyUITestHarness.sidebar(in:)` hard-coded
`app.collectionViews["session-sidebar"].firstMatch`. The
`session-sidebar` accessibility identifier lives on a SwiftUI
`List(selection:).listStyle(.sidebar)` in
`BattyKit/Sources/BattyKit/Views/SessionSidebarView.swift:46`, which
on macOS renders as an `NSOutlineView`, not an `NSCollectionView`. The
`collectionViews[…]` query therefore never matched, the
`waitForExistence(timeout: 5)` always timed out, and `sidebar.frame.width`
on the resulting non-existent element returned zero — so this test
failed at line 30 before getting anywhere near the visibility logic.

Latent for as long as the helper has existed; surfaced by [[0170]]'s
`Thread.sleep` removal, then masked by the runner-trash problem until
that was unblocked by [[0210]] / `scripts/run-ui-tests.sh`.

## Fix

Updated `sidebar(in:)` to mirror the pattern already used by
`sessionRow(named:in:)`: try the expected element type, fall back to
the type-agnostic descendant identifier query. Verified locally with
`scripts/run-ui-tests.sh BattyUITests/SidebarTests` — all three
SidebarTests pass.

## Files changed

- `BattyUITests/Support/BattyUITestHarness.swift` — `sidebar(in:)`
  now tries `collectionViews` → `outlines` → `descendants(...)`.
