## Description

Set the project's logging convention now while the codebase has only one logger to migrate. Per Apple's unified logging guidance and the `swift-guidance` skill's `references/logging.md`:

- Loggers should be **file-scoped**, declared as `nonisolated private let logger = Logger(subsystem: ..., category: ...)` at the top of each file.
- A shared `Logging` enum exposes the subsystem constant so every file uses the same identifier (sourced from `Bundle.main.bundleIdentifier` with a fallback).
- No `print()` or `NSLog()` for diagnostics — those are debug ergonomics that disappear in release.

Currently `BattyKit/Sources/BattyKit/WorkspaceStore.swift:29` declares an **instance member** `private let logger`, not a file-scoped `nonisolated private let`. That's the only "bad logging" in the project today — but the convention needs to be set before M3+ adds more.

**Acceptance criteria:**

- A new `BattyKit/Sources/BattyKit/Logging.swift` file exists with:
  ```swift
  import Foundation

  public enum Logging {
      public static let subsystem = Bundle.main.bundleIdentifier ?? "co.sstools.Batty"
  }
  ```
- `WorkspaceStore.swift`'s instance-member `logger` is replaced with a file-scoped `nonisolated private let logger = Logger(subsystem: Logging.subsystem, category: "WorkspaceStore")` declared above the class. The class no longer holds the logger as a stored property; methods reference the file-scoped identifier directly.
- Verify with `grep -rn "private let logger" BattyKit/Sources Batty/` that any remaining loggers are at file scope, not instance scope.
- Verify with `grep -rEn "(print\(|NSLog\()" BattyKit/Sources Batty/` that no `print()` or `NSLog()` calls exist (excluding test helpers if any). Currently zero hits — keep it that way.
- `CLAUDE.md` gains a one-paragraph "Logging" subsection under the Code conventions section pointing future code at this pattern. The guidance: "Each `.swift` file that needs to log declares `nonisolated private let logger = Logger(subsystem: Logging.subsystem, category: \"<Filename>\")` at top scope. No `print()` / `NSLog()` for diagnostics."
- `xcodebuild -scheme Batty -destination 'platform=macOS' build` passes.
- `swift test --package-path BattyKit` passes (39 tests).

## Notes

- **Why `nonisolated`:** `Logger` is a value type and safe to construct from any thread. Marking the file-scoped `let` `nonisolated` avoids spurious `@MainActor` warnings under the package's `defaultIsolation(MainActor.self)` setting.
- **Why `private`:** prevents the logger leaking across files / modules and ensures each file has its own categorized logger.
- **Why `public enum Logging`:** the subsystem constant is referenced from every file, including app-target files in `Batty/`. Public access is required for that boundary crossing.
- **Privacy in release:** the existing `WorkspaceStore` log line uses `\(self.fileURL.path, privacy: .public)` which is correct — file paths are not sensitive in our context. Future logs follow the same pattern: redacted by default; `.public` for non-sensitive values needed in production debugging.
- **Reference:** the swift-guidance skill's `references/logging.md` is the canonical source for this pattern.

## Out of scope

- Adding loggers to files that don't currently log. The point is to establish the convention; add loggers in those files when they have something worth logging.
- OSLog signposts for performance tracing — useful when we get to performance work, not now.
- Setting up `log stream` / `log show` filter helpers as scripts. Document on demand later.

## Root cause

No logging convention had been written down. The single existing logger in `WorkspaceStore.swift` was an instance-member stored property using a hard-coded subsystem string, which would have multiplied across files as more loggers were added.

## Fix

Introduced a shared `public enum Logging` with a `nonisolated` `subsystem` constant sourced from `Bundle.main.bundleIdentifier`. Migrated the existing `WorkspaceStore` logger to the file-scoped `nonisolated private let logger = Logger(subsystem: Logging.subsystem, category: "WorkspaceStore")` pattern declared above the type. Added a "Logging" subsection to `CLAUDE.md` so future code follows the same pattern.

## Files changed

- `BattyKit/Sources/BattyKit/Logging.swift` — new file; declares `public enum Logging` with the shared subsystem constant.
- `BattyKit/Sources/BattyKit/WorkspaceStore.swift` — removed the instance-member logger; added a file-scoped `nonisolated private let logger` above the type declarations.
- `CLAUDE.md` — added a "Logging" subsection under "Code conventions" describing the file-scoped logger pattern and the no-`print()`/`NSLog()` rule.

## Gotchas

- `Logging.subsystem` needs `nonisolated` on the static `let` itself, not just on the enclosing enum. Under the BattyKit package's `defaultIsolation(MainActor.self)` setting, a plain `public static let subsystem = ...` becomes `@MainActor`-isolated, which then prevents the file-scoped `nonisolated private let logger` from referencing it as a default value (Swift 6 reports "main actor-isolated default value in a nonisolated context"). Marking the constant `public nonisolated static let` keeps it usable from any isolation domain.
