## Description

UI test `BattyUITests.FuzzyFinderTests.testOpenQuicklyListsSessionsAndTabs` (`BattyUITests/FuzzyFinderTests.swift:165`) fails with:

```
XCTAssertTrue failed - Open Quickly must list at least one result per session
```

This test was created by [[0168]] as part of the UI test automation suite. The test was previously masked by the `Thread.sleep` runloop-blocking bug fixed in [[0170]] — the failure is now visible on every test run.

## What to investigate

Open `BattyUITests/FuzzyFinderTests.swift:165` and trace what state the assertion is checking. Cross-reference [[0168]] for the test's design and acceptance criteria.

The failure is one of:

- **App bug** — the behavior the test asserts on is genuinely broken; fix the app.
- **Test bug** — the test's assertion, setup, or accessibility-identifier expectation is wrong; fix the test.
- **Test infra gap** — a required driver intent or accessibility identifier referenced by the test doesn't exist yet; add it.

Look at the lines around `:165` and at the driver script (if any) in the test's launch call to determine which.

## Root cause

The Open Quickly picker (`OpenQuicklyView`) renders results in a
`LazyVStack { QuickOpenRow }`. The test asserted
`picker.descendants(matching: .cell).count >= 3`, but SwiftUI's
`LazyVStack` does not render as `NSTableViewCell` / `NSCollectionViewItem`
on macOS, so the `.cell` element-type query never matched anything.
`QuickOpenRow` also had no accessibility identifier, so even a
correctly-typed query couldn't have found the rows.

## Fix

Resolved by code commit `a3698cf`. Two pieces:

1. `OpenQuicklyView`: each `QuickOpenRow` is now
   `.accessibilityElement(children: .combine)` with identifier
   `open-quickly.row`, making each row a single accessibility element
   with a stable identifier.
2. `FuzzyFinderTests.testOpenQuicklyListsSessionsAndTabs`: query by
   identifier (`matching(identifier: "open-quickly.row")`) rooted at
   `app` rather than the picker. The picker overlay sits inside a
   `.regularMaterial` sheet whose accessibility relationship to the
   `open-quickly.root` element isn't always a strict `descendants`
   match.
