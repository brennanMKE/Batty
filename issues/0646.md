## Description

**Umbrella.** Make Batty a better partner for AI agents. An agent such as Claude Code running in a Batty Pane should know it is inside Batty, know how to drive it, and have a Batty view for what it starts (dev servers, static previews) instead of opening a browser or leaving the user to find the process. No code ships on this issue; the work lands in the children below.

Feature request from the user (Brennan), 2026-11-17, for the release after 1.4.0.

### Where things stand (checked against `main` at `3b5735c3`)

- The CLI is already machine-describable. `batty capabilities --json` emits, for every verb, an MCP-shaped `inputSchema` (`CapabilitiesInputSchemaPayload`, #0402), built by hand per command and kept honest by `CapabilitiesInputSchemaTests`' drift oracle. #0402's own framing was that the CLI "essentially acts like an MCP server with tool calling". There is no MCP server yet.
- The agent skill lives only in this repo, at `.claude/skills/batty-cli/` (`SKILL.md` plus a multi-host `install.sh` from #0404). `SKILL.md` says "Authored against Batty CLI `1.1.0`"; `MARKETING_VERSION` is `1.4.0` (`Configuration/App.xcconfig:49`). The only install path for anyone outside the repo is the recipe plain-text `batty capabilities` prints (`CapabilitiesCommand.skillInstallLines`): `git clone --branch v<version>` of the GitHub repo, then run `install.sh`. Nothing is in the app bundle.
- Pane kinds today (`PaneContentKind`, `BattyKit/Sources/BattyXPCCore/PaneContentKind.swift`): `terminal`, `git-status`, `process-status`, `lm-studio-dashboard`, `system-metrics`. There is no kind for a server or a web page. A Markdown Viewer (#0527) and a Scratch Pad (#0571) are filed, open, not built.
- `batty pane split --view <kind> --unique` exists (#0383): it finds an existing visible Pane of that kind and creates nothing. It matches on kind only; `viewOptions` differences (`--path`, `--pid`) do not defeat the match.

## Acceptance criteria

This umbrella can be resolved only when every child above is resolved, and:

1. A fresh agent session in a project the user has never opened in the Batty repo learns it is running inside Batty and how to drive it, with no manual skill copying.
2. When that agent starts a Go dev server, it does so through Batty (or attaches it), and the user sees a Server Pane placed where their Settings say, without the agent opening a browser.
3. `Concepts.md` and `PRD.md` name the new terms (Server Pane, web preview Pane) the children introduce.

## Resolution notes

> 🟢 Resolved 2026-11-18 — all three children and both follow-ups are merged on `main`; the acceptance criteria are met in code and docs, with live confirmation left to the user.

Merged commits:

- `4dd2ebd7` #0647 `batty mcp` server and bundled agent guidance with `batty agent install`
- `7043365b` #0648 Server Pane: `batty server start|attach|stop|restart`

- `fc1370ba` #0657 `batty mcp` frames stdin messages on LF only

Criteria, checked against `main`:

1. **Agents learn about Batty without manual copying.** `batty agent install` (`AgentCommand.swift`, `AgentGuidanceInstaller.swift`) and Settings → Advanced → AI Agents (`SettingsView.swift`, `AgentIntegrationModel.swift`) install the skill bundled in the app and register `batty mcp` for Claude Code (plugin), Cursor and OpenCode, and print the Codex entry. `batty capabilities` prints the `agent install` line (`CapabilitiesCommand.skillInstallLines`). `--project DIR` adds the `ProjectAgentSnippet` block telling an agent it is in Batty when `BATTY_PANE_ID` is set.
2. **Dev servers go through Batty.** The skill's §10 (`.claude/skills/batty-cli/SKILL.md`), `docs/batty-cli-agent-workflows.md` ("Dev servers: `server start` and `server attach`") and `ProjectAgentSnippet.block` all state the rule: start with `server start` or `server attach`, let Settings place the Server Pane, pass `--split` only on request, and do not open a browser. The server rule #0647's Gotchas said was missing (#0648 had not merged then) is now in all three.
3. **Concepts.md and PRD.md name the new terms.** `Concepts.md` has Server Pane, Web Preview Pane, MCP server (`batty mcp`) and Plugin. `PRD.md` §10 had Server Pane and the Web Preview Pane; this review added an entry for `batty mcp` and `batty agent install`.

All of it is Beta-only: `mcp` and `agent` are behind the `agentIntegration` flag, and `server` and both Pane kinds are behind `serverPane` (`FeatureFlags.swift`; on for Beta, off for Prod) until 1.5.0.

## Gotchas

Only the user can verify these:

- **A real fresh agent session** (criteria 1 and 2): run `batty-beta agent install` (or Settings → Advanced → AI Agents), open an agent in a project outside the Batty repo, and check that it finds Batty, drives it, and starts a Go dev server with `server start` so the Server Pane appears where Settings say, with no browser opened. No session or subagent ran `agent install` against the real agent configs.
- **Design docs** awaiting approval: `docs/design/server-pane-view.md` and `docs/design/web-preview-pane.md`.
- **Three #0647 decisions**: `agent` as a new noun with one verb `install` and `mcp` as a top-level verb; the plugin manifests generated at install time instead of shipped in the bundle; the Codex MCP entry printed, never written into `config.toml`. Also look over `~/.config/opencode/opencode.json`, which a #0647 host check reformatted (see #0647 Gotchas).
- **Restart for the in-app static server** (#0649 Decision 8) was added although the issue said it wasn't needed.
- **`a.click()` residual** in the Web Preview Pane: a page script can still open an external link in the browser through a scripted `<a>` click, because WebKit reports it as `.linkActivated` and exposes no public user-gesture flag on macOS.
- **The `docs/terminal-pane-requirements.md` §6 checklist** with Server and Web Preview Panes beside terminal Panes (clicks, selection, scroll, file and text drop, typing, IME, focus moving between the page and a terminal).
