## Description

UI test `BattyUITests.LifecycleTests.testCmdOptionNCreatesSession` (`BattyUITests/LifecycleTests.swift:22`) fails with:

```
XCTAssertTrue failed - Expected a new session row after Cmd-Option-N
```

This test was created by [[0094]] as part of the UI test automation suite. The test was previously masked by the `Thread.sleep` runloop-blocking bug fixed in [[0170]] — the failure is now visible on every test run.

## What to investigate

Open `BattyUITests/LifecycleTests.swift:22` and trace what state the assertion is checking. Cross-reference [[0094]] for the test's design and acceptance criteria.

The failure is one of:

- **App bug** — the behavior the test asserts on is genuinely broken; fix the app.
- **Test bug** — the test's assertion, setup, or accessibility-identifier expectation is wrong; fix the test.
- **Test infra gap** — a required driver intent or accessibility identifier referenced by the test doesn't exist yet; add it.

Look at the lines around `:22` and at the driver script (if any) in the test's launch call to determine which.

## Root cause

Test bug. The test typed Cmd-Option-N to trigger session creation,
but the `newSession` shortcut defaults to Cmd-N (see
`ShortcutAction.defaultBinding` in
`BattyKit/Sources/BattyKit/Shortcuts/ShortcutAction.swift`). The
mismatched modifiers meant the keystroke did nothing, no new session
row appeared, and the assertion failed.

The test name "testCmdOptionN…" appears to predate the default
binding being settled at Cmd-N.

## Fix

Resolved by code commit `d6085ae`. The test now types Cmd-N. Test
function name kept for git/PR continuity. Verified locally with
`scripts/run-ui-tests.sh
BattyUITests/LifecycleTests/testCmdOptionNCreatesSession` — passes.
