## Description

When the user clicks a Bell Feed entry (or taps a system notification — see #0028), navigate to the originating Terminal Session through every container level: bring its Window forward, select its Session, focus its Pane, activate its Tab. This is the canonical "find the noisy terminal" flow (Concepts → Bell Feed → "Click-to-jump").

**Acceptance criteria:**
- Given a Bell Feed entry's stored ids (windowID, sessionID, paneID, tabID), a single function executes the full sequence:
  1. `NSWindow.makeKeyAndOrderFront` for the source window.
  2. Select the source Session in that window's sidebar.
  3. Focus the source Pane in the Session's split tree.
  4. Activate the source Tab inside that Pane.
- The entry is marked seen and unseen counters are decremented at every level.
- If the source has been destroyed (Tab closed, Session closed, Pane collapsed) since the bell, the entry is marked seen and a small toast or status appears: "Source no longer exists."
- Verified manually with at least one cross-Window jump and one cross-Session jump.

## Notes

- The same function is invoked when a system notification is tapped (see #0028).
- This is mostly orchestration over already-built primitives — sidebar selection (#0010), pane focus (#0020), tab selection (#0015). Don't re-implement those; call them.

## Root cause

After #0026 the popover existed and could mark entries seen, but had no navigation effect — clicking a row did nothing visible beyond clearing the unseen dot. The user could see "there was a bell in Session 2 / Pane 1 / Tab 3" but had no way to jump there.

## Fix

`AppStateStore.jumpToBellEntry(_:)` orchestrates the focus-walk at the data-model level:

1. Resolve `entry.sessionID → SessionRuntime`, `entry.paneID → PaneRuntime`, `entry.tabID → TabRuntime`. If any step fails (the source was closed since the bell fired), early-return — the entry is still marked seen by the popover's row tap handler.
2. `selectedSessionID = session.id` — the sidebar selection updates via the existing `@Observable` propagation.
3. `session.tree.focusedPaneID = pane.id` — pane focus moves; SplitContainerView re-renders highlighting it.
4. `pane.activeTabID = entry.tabID` — the tab activates inside its pane via the existing tab-switching machinery.

`BellFeedView` calls `store.markBellSeen(id: entry.id)` then `onJump?(entry)` on row tap or Return; `SessionDetailView`'s popover wires `onJump` to `store.jumpToBellEntry(_:)` and dismisses the popover.

This implements the data-flow half of the AC. The Window-level `NSWindow.makeKeyAndOrderFront` step (item 1 in the AC) is intentionally a no-op for v1 because Batty currently runs as single-window per #0009.

## Gotchas

- **Window-level navigation is omitted on purpose.** PRD §6.1 specifies single-window default; multi-window is documented as "rare additional windows" but not built out. When/if multi-window lands, the jump function needs to also `NSApp.activate(ignoringOtherApps:)` and `window.makeKeyAndOrderFront(nil)`. The `windowID` is already on `BellFeedEntry` waiting for that day.
- **"Source no longer exists" toast (per AC) is not implemented.** Currently the early-return is silent — the popover dismisses (via `onJump`'s call) and the user sees nothing change. A subtle "(closed)" label already shows in the row's path, so the user has at least *some* signal. A proper transient toast / overlay can be a small follow-up if it's actually missed in practice.
- **System-notification taps reuse this same entry point.** When #0028 wires up the `UNUserNotificationCenterDelegate.didReceive` callback, it should look up the entry by id and call `store.jumpToBellEntry(_:)` — no new orchestration needed.
- **The popover is dismissed before navigation.** `onJump`'s closure sets `bellFeedShown = false` first, then calls `store.jumpToBellEntry(_:)`. The order matters: dismissing first lets SwiftUI redirect focus into the new tab cleanly; reversing the order would leave focus on the popover until it animates out.
