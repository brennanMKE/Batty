## Description

This is the UI-test child of umbrella [#0427](0427.md). It is **independent**: it uses none of [#0428](0428.md)'s BattyKit pieces and can start at any time. `BattyUITestHarness.pause(_ seconds:)` (`BattyUITests/Support/BattyUITestHarness.swift:76-78`) spins the run loop for a fixed time. It is an unconditional wait, and the harness's own doc comment says to use it "only when no observable signal exists". It is called four times:

| File:line | Pause |
|---|---|
| `BattyUITests/PaneSidebarTests.swift:72` | 0.5s |
| `…:130` | 1s |
| `…:149` | 0.5s |
| `BattyUITests/SessionCwdRenameTests.swift:77` | 0.5s |

Replace each one with an element or predicate wait (`waitForExistence`, or the harness's `waitFor(_:timeout:description:)`) on the state it is really waiting for. Read the surrounding test to find that state. Then delete `pause`.

Out of scope: whether the `waitFor` predicate poll itself (`:55-70`, a 50ms `RunLoop` spin to a deadline, 98 call sites, kept because `XCTNSPredicateExpectation` polls at a fixed ~1Hz) should change. #0427 leaves that question open, and this issue does not settle it. UI tests are XCTest and may use expectations.

## Verification

**VM-only.** Per `AGENTS.md` "UI test automation (binding)" and [#0412](0412.md), UI tests never run on the host. Commit first, then run `PaneSidebarTests` and `SessionCwdRenameTests` through the Tart VM runner (`docs/ui-testing-vm.md`). The orchestrator serializes VM runs, so the implementer must not start one in parallel with another agent. `./build.sh` (build) and `./build.sh unit` stay on the host.

## Done when

- `grep -rn 'pause(' BattyUITests/` returns nothing, and `pause` is removed from the harness.
- Each replaced wait is on a named element or predicate that says what it waits for.
- `PaneSidebarTests` and `SessionCwdRenameTests` pass in the VM.
- `./build.sh` passes on the host.
