## Description

> **Rescoped 2026-11-19 (user decision below).** This issue first said "add PhotonHTTP as an SPM dependency in `BattyKit/Package.swift`". It now says: Batty adds **no** package dependency; `batty server serve <dir>` runs the PhotonHTTP command-line tool when the user has installed it separately, in a terminal Pane, tracked in the Servers list like `server start`. The SPM, tools-version 6.4 bump and tag-pinning items are dropped.

Child of #0689 (decision E, as amended 2026-11-19).

### Current state (checked against `main` at `94b038c1`)

- `BattyKit/Sources/BattyKit/Runtime/StaticServer/` — 10 files (~860 lines): `StaticFileServer` (`NWListener`, `127.0.0.1` only, `StaticServing` protocol with `start(port:)`, `stop()`, `waitUntilStopped()`, `broadcastReload()`, `stats` = request and reload-client counts), path resolver, MIME types, byte ranges, directory listing, `ReloadScriptInjector` + `StaticReloadBroadcaster` (server-sent events for reload on change), `DirectoryChangeWatcher`. Wrapped by `InAppStaticServerBackend`; `AppStateStore+StaticServer.swift`; tests `StaticFileServerTests`, `InAppStaticServerTests`.

### PhotonHTTP CLI (`github.com/brennanMKE/PhotonHTTP`, read 2026-11-19 at `2d01f282`)

- The package is renamed (`name: "PhotonHTTP"`, commit `a333f2bf`), MIT licensed (`2d01f282`), no tags or releases, no Homebrew formula found.
- **Executable name: unconfirmed.** The executable product is still `SwiftWebServer` (README and `docs/guide/running-on-a-mac.md` still say `SwiftWebServer`). The rename of the executable has not landed; the expected new name (e.g. `photonhttp` or `PhotonHTTP`) must be confirmed with the user or the repo before implementing. Detection should look for the confirmed name (and may accept `SwiftWebServer` until the rename lands, if the user agrees).
- Install today: build from source (`swift build -c release --product SwiftWebServer`, needs a Swift 6.4 toolchain) and copy the binary to a directory on `PATH` (the guide suggests `/usr/local/bin` or `~/bin`).
- Usage: `SwiftWebServer [--config FILE] [--root DIR] [--host HOST] [--port PORT]`; binds `127.0.0.1` by default; `--port 0` picks a free port; prints `listening 127.0.0.1:PORT` on stdout once bound; SIGINT/SIGTERM drain and exit 0; exit 1 on startup error (port in use, missing root), 2 on usage error.
- Status: there is **no HTTP status endpoint by default**. Control commands (`status [--json]`, `reload`, `restart`) work through a status file (`run/status.json` next to the config), written **only when the server runs with a config file**. Prometheus metrics at `/metrics` exist only when the config sets `accessLog.metrics`. No reload-on-change script injection is documented (only config reload via SIGHUP/watch).

## Expected behavior

- **No dependency.** `BattyKit/Package.swift` is unchanged; nothing from PhotonHTTP is linked into the app.
- **Detection** (read-only, off the main actor, only when `serve` runs or Settings is shown): the PhotonHTTP executable on the login-shell `PATH`, plus common install locations (`/opt/homebrew/bin`, `/usr/local/bin`, `~/bin`, `~/.local/bin`).
- **`batty server serve <dir> [--port N] [--open]`** runs `<photonhttp> --root <dir> --port <N or 0>` in a new terminal Pane (as `server start` does, #0692), so the process and its output are visible; registers it in the Servers list (#0691) once it listens (the `listening HOST:PORT` line or the port scan), with Copy URL; `server stop`/`restart` (#0692) stop or restart it with the same terminal-job ownership rules as `server start`. `--open` opens the URL in the default browser.
- **Status in the list:** minimal — name, port, state from the process and listener. If PhotonHTTP exposes a status source Batty can read cheaply (its `status --json` with a config file Batty writes, or a future status endpoint), the plan may use it; Batty serves no `/_batty/status` of its own.
- **Not installed:** `serve` fails with a clear message naming the tool and how to install it (link to the PhotonHTTP README), and opens nothing. Settings (Advanced, near the CLI install) and Docs mention PhotonHTTP as an optional, separately installed tool; no prompt or banner.
- **Remove the in-app server** (orchestrator default, open question below): delete `Runtime/StaticServer/`, `InAppStaticServerBackend`, the in-app parts of `AppStateStore+StaticServer.swift` and their tests.
- Starts only on request; nothing listens at launch.

## Acceptance criteria

1. Unit tests with an injected executable locator and command runner (no sleeps): detection finds the tool on `PATH` and in the fallback locations, and reports absent otherwise; `serve` builds the exact argv; `serve` without the tool fails with the install-guidance message and creates no Pane; the server registers on the `listening` line / listener and leaves the list on exit.
2. `BattyKit/Package.swift` and `Package.resolved` gain no PhotonHTTP entry; `git grep -n NWListener BattyKit/Sources` finds no static-server use (if the open question is decided as remove).
3. UI test (typecheck only per issue): with a stub executable on `PATH`, `server serve <dir>` opens a terminal Pane and a `toolbar.servers` row.
4. A fresh install shows nothing new and opens no listening socket until `server serve` runs; without PhotonHTTP installed nothing about it appears except the optional mention in Settings and Docs.
5. `./build.sh`, `./build.sh unit`, `./build.sh ui-typecheck` pass.

## Open questions

1. **Remove the in-app `NWListener` server (#0649) or keep it as a fallback when PhotonHTTP isn't installed?** Orchestrator default (the user may override): **remove** it, to keep the app small; `serve` then needs PhotonHTTP. Keeping it would also keep its reload-on-change behavior, which the PhotonHTTP CLI does not provide.
2. **Executable name** after the rename (see above).

## Decisions (user, 2026-11-19)

- **License:** PhotonHTTP (`github.com/brennanMKE/PhotonHTTP`) now has an MIT license (GitHub reports spdx `MIT`, pushed 2026-11-19). Kept as context; Batty no longer bundles it.
- **Rename:** the user is renaming the package from `SwiftWebServer` to `PhotonHTTP`. The package rename landed (`a333f2bf`); the executable product is still `SwiftWebServer` as of `2d01f282`.
- "We may not need to install PhotonHTTP directly in Batty. Instead we can simply offer to use it if the user installs it separately as a CLI tool."
- Superseded by the line above: the earlier SPM-dependency scope, its tools-version bump and the tag-pinning rule.
