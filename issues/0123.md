## Description

`Batty/Localizable.xcstrings` currently reports **38% complete** in Xcode. Investigation: the catalog has 18 keys but only 7 of them carry any translations — the original set that the per-language issues `#0108`–`#0121` translated. The other 11 keys were added to the catalog *after* those issues resolved (Help-section titles and a couple of error strings) and have no `localizations` block at all.

Goal: populate all 14 non-English locales (plus `en` for parity with the existing entries) for the 11 missing keys, so the catalog reports 100% complete.

## Missing keys

```
Batty Help
Couldn't load %@
Drag and Drop
Keyboard Shortcuts
Notifications
Overview
Panes and Splits
Sessions
Tabs
The bundled file %@.md is missing from the app's Help resources.
Themes
```

Mostly Help section titles (from `#0081`–`#0088`), plus two error messages. None of these keys are plural-aware, so no plural variants needed in the catalog entries.

## Acceptance criteria

- Every one of the 11 listed keys has a `localizations` block in `Batty/Localizable.xcstrings` populated for all 15 locales: `de`, `en`, `es`, `es-419`, `fr`, `it`, `ja`, `ko`, `nl`, `pl`, `pt-BR`, `ru`, `tr`, `zh-Hans`, `zh-Hant`.
- Each entry uses the same `stringUnit { state: "translated", value: "…" }` shape as the existing entries — no new entries left in `extractionState: "manual"` without a translation.
- `xcodebuild -scheme Batty -destination 'platform=macOS' build` passes after the change.
- The catalog reports 100% in Xcode's String Catalog editor for every listed locale.

## Out of scope

- Native-speaker review of the LLM-authored translations (existing acceptance criterion across `#0108`–`#0121`; not addressed here).
- Adding any new keys to the catalog. This issue is purely about filling in the 11 already-present keys.
- Adjusting the source style guide / terminology decisions made by the prior pass — match what each locale already established for its existing 7 keys (e.g. zh-Hant uses 結束 / 終端機; ko uses noun-phrase buttons; etc.).

## Notes

- Translations will be LLM-authored, same approach used for the original 7 keys. Same caveat applies: native-speaker review remains aspirational.
- For each locale, terminology should match the choices made by the existing entries to keep the catalog internally consistent — e.g. Taiwan-style zh-Hant for the new keys, since `#0116` chose Taiwan macOS house style.
- Help section titles correspond to in-app section headings that users navigate via the Help menu (`#0080`–`#0088`). Translations should be terse navigation labels, not full sentences.
- `Couldn't load %@` and `The bundled file %@.md is missing…` are error strings shown when a Help bundle resource is missing; treat them as error-dialog copy and keep them concise.
