# 0129 — Cmd-B should toggle the sidebar, and the binding must appear in Settings → Shortcuts

| | |
|---|---|
| **Status** | open |
| **Module** | Sidebar / Settings |
| **Platform** | macOS |
| **First seen** | 2026-05-18 |

## Description

The system-wide macOS idiom for "show/hide sidebar" is **Cmd-B** — Finder, Mail, Notes, Reminders, Messages, and Xcode all bind it. Batty currently defaults `toggleSidebar` to **Cmd-Control-S**, which is non-standard and harder to reach one-handed. Change the default to **Cmd-B** and confirm the action is listed in Settings → Shortcuts so users who want something different can rebind it.

The `toggleSidebar` case already exists in `ShortcutAction` (`BattyKit/Sources/BattyKit/Shortcuts/ShortcutAction.swift:24`) with a `displayName` of "Toggle Sidebar", so the rebinding row should already render in the Shortcuts pane. This issue is to (a) change the default binding and (b) verify that the row is actually visible and works end-to-end in Settings.

## Acceptance criteria

- `ShortcutAction.toggleSidebar.defaultBinding` returns Cmd-B (`key: "b", modifiers: [.command]`).
- Pressing Cmd-B from anywhere in the app toggles the session sidebar (collapse / expand) on the focused window.
- The Settings window's Shortcuts pane shows a "Toggle Sidebar" row with the current binding, and the recorder accepts a new chord and persists it.
- "Reset to Defaults" in the Shortcuts pane restores the binding to Cmd-B.
- Existing users with a previously-saved custom binding for `toggleSidebar` keep their override — only the unset / default value changes.

## Notes

- Cmd-B is unbound elsewhere in Batty today (no terminal emulator typically claims it; the terminal doesn't need the chord). Worth a grep across `BattyShortcuts` / `BattyCommands` to double-check no other action defaults to Cmd-B before the swap.
- The current default (Cmd-Control-S) was chosen to avoid collisions, but Cmd-B is the right call now that the shortcut catalog is user-editable — users who genuinely need Cmd-B for something else can rebind in two clicks.
- Related: `#0070` documents which shortcuts are *fixed* (Cmd-1..9, Cmd-C, Cmd-V); `toggleSidebar` is in the customizable set, so changing its default is a pure default-value change, not a policy change.
- No migration needed: `ShortcutsStore` reads `UserDefaults` and falls back to `defaultBinding` only when no override is stored, so the new default applies to fresh installs and to users who never touched the row.
