## Description

`website/assets/screenshots/` is empty. The marketing page in `website/index.html` references the feature set but doesn't show any of it. A single hero shot plus a few feature snippets would carry the landing page from "competent placeholder" to "obvious what this is."

Required only because v1.0.0 is the public face — for internal builds we can ship without. Tracked separately from `#0096` (which built the scaffolding) so the screenshot pass can happen on the eve of the release without revisiting the whole site issue.

## Shot list

Capture against a real Batty window. Cmd-Shift-4 (with Space for a window-bound shot) for the cropped versions; Cmd-Shift-5 → "Capture Selected Portion" for the others.

| File | What it shows |
|---|---|
| `website/assets/screenshots/hero.png` | Wide screenshot at ~1600×1000. Three sessions in the sidebar, a 2×2 grid of split panes, a couple of tab chips, the bell-feed badge subtly visible. |
| `website/assets/screenshots/splits.png` | Tight shot of a split layout — left/right + top/bottom recursion, dividers visible. ~1200×800. |
| `website/assets/screenshots/tabs.png` | Close shot of the tab strip, including the `+` button and a chip with the unseen-bell dot. ~1200×500. |
| `website/assets/screenshots/bell-feed.png` | Bell-feed popover open, two-three entries visible. ~1000×800. |
| `website/assets/screenshots/settings.png` | (optional) Settings → Appearance pane, showing theme picker + font size. ~900×700. |

## Capture guidance

- Use the **Mocha** or **Tokyo Night** theme (or whichever the developer prefers — anything but Default looks more like a real product).
- Pretty the prompts. Avoid showing the developer's home directory in absolute paths; use a project under `~/Developer/` so the auto-derived names (`#0089`) display nicely.
- Take screenshots on a Retina display for crisp images, but downsample to ~2x DPI to keep file sizes under 600KB each (`sips -Z 1600 hero.png` to cap the long edge).
- No window chrome over the terminal area — close any popovers/sheets unless the shot is specifically of one.
- Pasteable text in the terminal: don't show real credentials, ssh hosts, etc.

## Page wiring

After files land, edit `website/index.html`:

- Add an `<img>` to the hero section above (or below) the icon: `<img src="/assets/screenshots/hero.png" alt="Batty showing multiple sessions, split panes, and the bell feed">`.
- In the features grid, swap the per-card icon/description for a small `<img>` of the matching shot.

Validate by previewing locally:

```bash
cd website && python3 -m http.server 8000 && open http://localhost:8000/
```

## Acceptance criteria

- `website/assets/screenshots/{hero,splits,tabs,bell-feed}.png` exist.
- Each file is ≤ 600KB.
- `website/index.html` references at least the hero image; ideally one image per feature card.
- Site preview at `http://localhost:8000/` renders the images without 404s.
- HTML validates (no broken `<img>` references, `alt` text on every image).

## Out of scope

- Screen recordings / animated GIFs — possible follow-up, not v1.0.0.
- Localized screenshots (only English shipped).
- A press kit (logos at multiple sizes, color/dark variants) — separate task if anyone asks.

## Notes

- The `#0096` `index.html` already styles for screenshots if you drop `<img>` tags in. CSS targets `.features img` and `.hero img` with sane defaults.
- If a shot isn't ready in time, the page degrades gracefully — there are no required `<img>` references blocking the landing page from rendering.
