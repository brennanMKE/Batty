## Description

Sidebar collapse/expand uses NavigationSplitView's standard toggle button (View → Hide Sidebar, Cmd-Ctrl-S, or the toolbar control). Per `Concepts.md` → Sidebar, the collapsed state is persisted per Window so restarting the app puts the sidebar back where the user left it.

**Acceptance criteria:**
- The user can collapse and expand the sidebar via View menu, keyboard (Cmd-Ctrl-S), and the toolbar toggle button.
- Collapsed/expanded state survives quit and relaunch (per Window).
- View menu reflects the current state ("Hide Sidebar" vs "Show Sidebar").

## Notes

- Persistence here can use `UserDefaults` or piggyback on the Workspace document (#0029). Decide based on which lands first; if Workspace lands first, prefer that for consistency.
- This is the smallest persistence-related issue and is a good candidate to land before the full Workspace serializer (#0029).

## Root cause

Feature gap. M2 polish: collapsed-sidebar preference should outlive the app session.

## Fix

`@AppStorage("co.sstools.Batty.sidebarHidden") private var sidebarHidden: Bool` in both `RootWindowView` and `BattyCommands`. The two read the same UserDefaults key and stay in sync via SwiftUI's observation.

`RootWindowView` exposes a `Binding<NavigationSplitViewVisibility>` derived from the Bool (`.all` when not hidden, `.detailOnly` when hidden), and passes that to `NavigationSplitView(columnVisibility:)`. The toolbar toggle that NavigationSplitView provides automatically writes through the binding, so user-initiated drags and toolbar clicks also persist.

`BattyCommands` adds a `CommandGroup(after: .sidebar)` button labelled "Hide Sidebar" or "Show Sidebar" depending on state, with Cmd-Ctrl-S as the keyboard shortcut.

A `SidebarPreference` namespace enum exposes the UserDefaults key publicly so future code (Settings UI, per-window persistence migration) can refer to the same key.

## Files changed

- `BattyKit/Sources/BattyKit/RootWindowView.swift` — added `@AppStorage`, `columnVisibilityBinding`, and `SidebarPreference` enum; passed the binding to `NavigationSplitView`.
- `BattyKit/Sources/BattyKit/BattyCommands.swift` — added `@AppStorage` for the same key plus the toggle button in `CommandGroup(after: .sidebar)`.

## Gotchas

- **Visual verification:** sidebar toggles via Cmd-Ctrl-S, View menu shows correct label, state survives quit and relaunch. `xcodebuild build` passes.
- **Persistence is global, not per-window.** PRD §6.6 / Concepts → Workspace call for per-window persistence. With #0030 cadence still deferred, the simplest correct-enough behavior is one shared bool. When `WindowState` is being persisted to `workspace.json`, this will hoist there and become genuinely per-window. Adding the `SidebarPreference` namespace makes that migration straightforward — the key is exposed and easy to grep for.
- **The default "View > Toggle Sidebar" menu item** (provided automatically by NavigationSplitView) and our explicit `CommandGroup(after: .sidebar)` button both drive the same `@AppStorage` value through the binding. They don't conflict; users get whichever shortcut they reach for first. The standard Cmd-Option-S NavigationSplitView shortcut and our Cmd-Ctrl-S coexist.
- **`@AppStorage` Bool default is `false`** (sidebar visible) — first launch shows the sidebar, matching the reasonable default.
