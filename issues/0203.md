## Description

UI test `BattyUITests.TabRenameTests.testRenameActiveTabUpdatesChipTitle` (`BattyUITests/TabRenameTests.swift:42`) fails with:

```
XCTAssertTrue failed - tab-chip.MyCustomTab must appear after renameActiveTab ([[0157]] regression)
```

This test was created by [[0160]] as part of the UI test automation suite. The test was previously masked by the `Thread.sleep` runloop-blocking bug fixed in [[0170]] — the failure is now visible on every test run.

## Root cause

Same as [[0204]] / [[0205]]: the parent SlidingTabBar's
`.accessibilityIdentifier("tab-bar.\(pane.id…)")` propagated to its
children, replacing every chip's `tab-chip.<title>` identifier. The
chip element was present in the accessibility tree but couldn't be
matched by its own identifier, so `matching(identifier:
"tab-chip.MyCustomTab")` found nothing even though `chipTitle` was
correctly returning `"MyCustomTab"`.

Latent since `a5d71c7` ([[0122]] BattyKit reorg) — masked by [[0170]]'s
`Thread.sleep` runloop block until that was fixed, and then by the
UI test runner being killed by AppleSystemPolicy until that was
unblocked by `scripts/run-ui-tests.sh` (commit `51acf65`).

## Fix

Resolved by commit `e7beeb5` (see [[0205]]). One-line change in
`BattyKit/Sources/BattyKit/Views/PaneView.swift`:
`.accessibilityElement(children: .contain)` on the tab bar so the
parent identifier no longer overwrites children's identifiers.

Verified locally with `scripts/run-ui-tests.sh
BattyUITests/TabRenameTests/testRenameActiveTabUpdatesChipTitle` —
test passes.
