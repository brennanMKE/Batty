## Description

Feature request, **depends on #0523** (Bell Feed capture log). The capture log will record what each Bell event sent and what Batty showed. To turn that into something we can improve against, the user also needs to say, entry by entry, whether the shown text was good. Add a context menu to each Bell Feed row with three items, "Good Summary", "Bad Summary" and "Suggest Better Text…". Each one appends a `rating` record to the #0523 capture file, joined to the event by entry id. Ratings are available only while capture is on.

**Release target: 1.3.2.** This is new work on `main`, cherry-picked to `release/1.3` with `git cherry-pick -x` after #0523. The user approved this as an exception to the AGENTS.md "Release branches" rule that keeps feature work off release branches. Record the release-branch commit in the Work log. It ships without a feature flag; the capture toggle (off by default) is the gate.

## Current state (verified on main `7ed271e7`)

- `BellFeedView` (`BattyKit/Sources/BattyKit/Views/BellFeedView.swift`) is a `List(selection: $selectedEntryID)` over `store.bellFeed.entries`. Each `BellFeedRow` has `.onTapGesture { handleJump(to: entry) }` (click-to-jump) and the accessibility identifier `bell-feed-entry.<uuid>`. The body text has `bell-feed-message.<uuid>`. Return, Escape and the arrow keys are handled with `onKeyPress`. There is **no context menu** today.
- The row's body text is `entry.summary ?? entry.message`, omitted when both are nil or empty. That is the text being rated. It changes when the async summary lands, so a rating must record what was on screen at the moment it was given.
- The Bell Feed is a popover attached to the toolbar bell button (Cmd-Shift-B), sized 360×420. `BellFeedStore` is in-memory and doesn't survive a relaunch. Every entry visible in the feed comes from the current launch.
- Existing UI coverage is `BattyUITests/BellFeedTests.swift`. It triggers bells by typing `printf '\a'` into a terminal.

## Expected behavior

1. **Context menu** on every Bell Feed row, except footprint-warning entries (`BellFeedEntry.systemID`), with these items:
   - **Good Summary** and **Bad Summary.** One verdict per entry. The current verdict shows a checkmark, and picking the other one replaces it.
   - **Suggest Better Text…** opens a small sheet or popover with a multi-line text field. It is prefilled with the current row text, has the field focused on open, and has Save (Return / Cmd-Return) and Cancel (Escape) buttons. Saving empty or whitespace-only text is disabled. The suggestion is independent of the verdict, so an entry can be both "Bad Summary" and have a suggestion. Saving again replaces the earlier suggestion.
   - **Clear Rating** (recommended) records a `cleared` verdict, so a mis-click can be undone.

   Opening the menu must not trigger click-to-jump or mark the entry seen.
2. **Availability.**
   - **Capture off:** the rating items are hidden.
   - **Capture on, but no #0523 `event` record for this entry** (it arrived before capture was turned on, or before a "Clear Capture"): the items appear disabled, with help text saying the entry wasn't captured.

   The capture layer from #0523 owns the "has an event record" fact, for example as an in-memory set of captured entry ids that is reset by Clear Capture.
3. **Rating record**, appended to the #0523 capture file through the same off-main serial writer:
   - `schema` (the #0523 schema version), `type: "rating"`, `recordID` (fresh UUID), `entryID`, `ratedAt` (ISO 8601 UTC);
   - `kind: "verdict" | "suggestion"`;
   - `verdict: "good" | "bad" | "cleared"` (for verdicts) or `suggestedText` (for suggestions, untruncated up to the same cap #0523 uses for `message`);
   - `shownText` (the row text at the moment of rating), `summaryAtRating` and `messageAtRating`.

   Processing rule: for each `entryID`, the latest verdict wins and the latest suggestion wins. Document this in `docs/bell-feed-capture.md` (created by #0523), and add the `rating` record to its schema section.
4. **In-app state.** The checkmark reflects the latest verdict given in this launch. Keep it in memory, owned by the capture layer or `AppStateStore`, keyed by entry id. Write it only from the menu and sheet action handlers. Don't read the file back. Entries removed from the feed (cap, Tab close cleanup) can drop their rating state.
5. **No new entry points elsewhere.** There is no toolbar button, no Command Palette item and no keyboard shortcut. Only the row context menu.

## Constraints

- `docs/swiftui-observation-rules.md` is binding:
  - The presented-sheet entry id and the draft suggestion text are view-local `@State`.
  - Rating writes happen only in button and menu action closures. Never write from `body`, `onChange` or `onAppear`.
  - When the user re-picks the current verdict, skip the `@Observable` write, because `@Observable` notifies even on equal writes. Whether a re-pick still appends a record is the implementer's choice; document it in `docs/bell-feed-capture.md`.
  - Presenting the sheet is state-driven. Don't call `makeFirstResponder` or other AppKit responder APIs synchronously from SwiftUI callbacks.
- The Bell Feed lives in a popover, and the existing `onKeyPress` handlers on the `List` must keep working. While the suggestion field has focus, Return, Escape and the arrow keys go to the field and its buttons, not to `BellFeedView`'s row navigation and dismiss handlers.
- No file I/O on the main actor; the record is enqueued to #0523's writer. Capture off means no record and no state change.
- New strings go in the string catalog (`docs/localization.md`).

## Acceptance criteria

- [ ] With capture on, right-clicking a captured row shows Good Summary, Bad Summary, Suggest Better Text… (and Clear Rating if implemented). Each appends one correct `rating` record joined by `entryID`, with `shownText` equal to the row's visible text at that moment.
- [ ] Changing a verdict appends a new record and moves the checkmark. The file keeps both records.
- [ ] A suggestion saved twice appends two records. Cancel appends nothing.
- [ ] With capture off the rating items are hidden. For an uncaptured entry they're disabled.
- [ ] Right-click doesn't jump or mark the entry seen. Left-click and keyboard navigation behave as before.
- [ ] `docs/bell-feed-capture.md` documents the `rating` record and the latest-wins rule.

## Resolution notes

> 🟢 Resolved 2026-10-18 — Right-clicking a Bell Feed entry offers Good Summary, Bad Summary, Suggest Better Text… and Clear Rating; each choice writes a `rating` record to the #0523 capture file, joined by `entryID`.

The items appear only when capture is on, are disabled with a "Not captured…" line for entries without an `event` record, and never mark an entry seen. Ships in 1.3.2 via cherry-pick to `release/1.3` (user-approved exception).

## Root cause

Starting state: the #0523 capture log recorded what each Bell event showed but had no signal for whether the summary was any good.

## Fix

- `BellCaptureRating` record (schema 1; adding a record type is non-breaking) with verdict or suggested text plus the shown text, summary and message at rating time. Latest verdict and latest suggestion per `entryID` win in processing; documented in `docs/bell-feed-capture.md`.
- `BellFeedStore` tracks `capturedEntryIDs` and `ratingVerdicts`, pruned with the feed; `AppStateStore.clearBellCapture()` clears the files and both sets, and Settings' Clear uses it. Ratings are only accepted for captured entries, so Clear can't leave an orphan rating.
- Per-row `.contextMenu` with Toggle items; the suggestion editor replaces the list inside the same popover (no nested sheet). Its field handles plain Return (save) and Escape (cancel) itself, focuses on open, and uses the snapshot taken when the editor opened.
- State is exposed to UI tests through identifiers: `bell-feed-unseen.<id>` / `bell-feed-seen.<id>` (with a Seen/Unseen VoiceOver label) and a `.selected` suffix on the current verdict item.
- `launchBatty` / `launchConnected` take optional `extraArguments` (default empty).
