## Description

Add the user-facing controls that split the focused Pane: SF Symbol toolbar buttons and keyboard shortcuts. Per `Concepts.md` → Split, `rectangle.split.2x1` splits horizontally (side-by-side) and `rectangle.split.1x2` splits vertically (stacked). New panes are born with one Tab containing one fresh Terminal Session in the parent's cwd.

**Acceptance criteria:**
- Two SF Symbol buttons appear in the session toolbar:
  - `rectangle.split.2x1` → split focused Pane horizontally; new Pane to the right.
  - `rectangle.split.1x2` → split focused Pane vertically; new Pane below.
- Keybindings:
  - **Cmd-D** — split horizontally (matches the toolbar button).
  - **Cmd-Shift-D** — split vertically.
- Both controls operate on the **focused Pane** in the active Session.
- The split inserts a new `.split(...)` node in place of the focused leaf, with the original leaf and a new leaf as children. Default ratio is 0.5.
- New leaf: one Pane, one Tab, one Terminal Session in the focused Pane's cwd.

## Notes

- Toolbar buttons may live in the window toolbar, the session toolbar, or a per-pane hover overlay (TBD per PRD §6.4 — decide during implementation).
- The new Pane should take focus immediately so the user can start typing.
- Does not include divider drag (#0019), focus movement (#0020), or last-tab collapse (#0021).

## Root cause

Feature gap. M4's first user-visible action: insert a split. #0017 built the renderer; this issue adds the user controls that grow the tree.

## Fix

`SplitTree` got `splitFocusedPane(direction:ratio:)` which:
- Constructs a fresh `PaneRuntime` (one tab, one fresh shell).
- Recursively walks the tree finding the leaf at `focusedPaneID`.
- Replaces it with a `.split` containing the original pane on the left, the new pane on the right.
- Updates `focusedPaneID` so typing immediately goes to the new pane.

The recursion lives on `SplitTreeNode.inserting(newPane:adjacentTo:direction:ratio:into:)` — left subtree first, then right; returns `nil` if the pane id isn't found.

User-facing controls in two places:
- `SessionDetailView`'s `.toolbar` gains a `ToolbarItemGroup` with the two SF Symbol buttons (`rectangle.split.2x1`, `rectangle.split.1x2`). Tooltips show the keyboard equivalents.
- `BattyCommands` gains a `CommandMenu("Pane")` with two buttons mapping Cmd-D and Cmd-Shift-D.

Both paths call the same `splitFocusedPane(...)` so toolbar and keyboard exercise the same model code.

## Files changed

- `BattyKit/Sources/BattyKit/SplitTree.swift` — `splitFocusedPane(...)` and the recursive `SplitTreeNode.inserting(...)` helper (~50 lines added).

## Gotchas

- **Visual verification needed.** Clicking either toolbar button or pressing the shortcut splits the focused pane; HSplitView/VSplitView places a draggable divider between the two; new pane gets a fresh shell and accepts keystrokes; clicking the original pane restores focus. `xcodebuild build` passes; resolved-not-closed.
- **Ratio default 0.5** is intentional. `HSplitView`/`VSplitView` doesn't accept a programmatic position, so the `ratio:` associated value is recorded in the model but the actual divider always renders at the SwiftUI default (50%-ish, depending on minimum widths). Persistent ratio is #0019's work.
- **Hit-testing across nested splits.** With multiple panes alive, clicking on a pane's terminal should set focus to that pane. Today we don't have explicit click-to-focus wiring at the pane level — `focusedPaneID` only updates via `splitFocusedPane(...)` (and will update via #0020's keyboard movement). Clicking a non-focused pane to focus it is a follow-up; for now the typing-focus follows the GhosttyTerminal `TerminalSurfaceView`'s own focus handling, but the model's `focusedPaneID` may stay stale until #0020 lands. Worth eyeballing.
- **Focused pane tracking under nested splits.** When the user splits pane A into A+B, then splits B into B+C, then splits C into C+D, the model correctly tracks `focusedPaneID = D.id` (always the most recently created). Walks happen depth-first so the recursion is O(n) in tree size; performance is fine for any reasonable split count.
