## Description

UI test `BattyUITests.WorkspacePersistenceTests.testTabTitleOverridePersistsAcrossRelaunch` (`BattyUITests/WorkspacePersistenceTests.swift:105`) fails with:

```
XCTAssertTrue failed - Renamed chip must appear in launch 1
```

This test was created by [[0165]] as part of the UI test automation suite. The test was previously masked by the `Thread.sleep` runloop-blocking bug fixed in [[0170]] — the failure is now visible on every test run.

## What to investigate

Open `BattyUITests/WorkspacePersistenceTests.swift:105` and trace what state the assertion is checking. Cross-reference [[0165]] for the test's design and acceptance criteria.

The failure is one of:

- **App bug** — the behavior the test asserts on is genuinely broken; fix the app.
- **Test bug** — the test's assertion, setup, or accessibility-identifier expectation is wrong; fix the test.
- **Test infra gap** — a required driver intent or accessibility identifier referenced by the test doesn't exist yet; add it.

Look at the lines around `:105` and at the driver script (if any) in the test's launch call to determine which.

## Root cause

The test was asserting on a feature that no longer exists. Workspace persistence (the `workspace.json` save-on-structural-change / load-on-launch path) was removed in its entirety by [[0172]] — the four source files (`Workspace.swift`, `WorkspaceConversion.swift`, `WorkspaceManager.swift`, `WorkspaceStore.swift`) were deleted and every doc/spec mention was scrubbed. With no save and no load, tab title overrides cannot round-trip across a relaunch.

## Fix

Deleted `BattyUITests/WorkspacePersistenceTests.swift` entirely. The same fix resolves [[0206]] and [[0207]] (the other two tests in the same file).
