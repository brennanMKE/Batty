# Issue #0144: Add Optional Dimensions to Pane JSON Output

**Status:** open  
**Created:** 2026-08-10  
**Components:** CLI (batty), BattyKit  

---

## Summary

Add optional dimension information (height and width) to pane objects in the JSON output from `batty list --json` and other commands that return pane topology.

## Motivation

Agents controlling Batty through the CLI need to know whether a session/pane is still large enough to split further. Without dimensions, an agent cannot determine if adding another pane will result in a layout that's too cramped.

## Proposed Behavior

### 1. New Flag: `--include-dimensions`

Add an optional flag to CLI commands that return pane topology:

```bash
batty list --json --include-dimensions
batty session info --session <id> --json --include-dimensions
```

When this flag is present, each pane object includes additional fields:

### 2. Added Fields in Pane Objects

```json
{
  "id": "...",
  "kind": "shell | command",
  "path": "/Users/brennan/Developer/Batty",
  "focusedPaneID": "...",
  
  // NEW FIELDS (only when --include-dimensions is set):
  "frame": {
    "x": 0,
    "y": 0, 
    "width": 1280,
    "height": 720
  },
  "visibleRect": {
    "x": 100,
    "y": 50,
    "width": 640,
    "height": 670
  }
}
```

### 3. Default Behavior (Backward Compatible)

- **Without `--include-dimensions`**: JSON output is unchanged - no dimensions are included
- **With `--include-dimensions`**: Each pane includes `frame` and `visibleRect` objects

## Use Cases

### Agent Decision-Making
```bash
# Get topology with dimensions for an agent evaluating layout decisions
topology=$(batty list --json --include-dimensions)

# Agent logic to decide whether to split:
if [[ $(echo "$topology" | jq '.size < 3') ]]; then
    # Only one pane, safe to split
    batty pane split --horizontal --pane "$pane_id" -c "command"
else
    # Check if panes are too small (< 400px width) to split further
    min_width=$(echo "$topology" | jq '[.windows[].sessions[] | 
        select(.focusedPaneID == .id) | 
        .visibleRect.width] | min')
    
    if [[ "$min_width" -lt 400 ]]; then
        echo "Panes are too small to split further"
        exit 1
    else
        batty pane split --horizontal --pane "$current_pane" -c "command"  
    fi
fi
```

### Manual Layout Inspection
```bash
# For power users who want to monitor their layout dimensions in real-time
watch 'batty list --json --include-dimensions | jq ".windows[].sessions[]"'
```

## Implementation Considerations

### Data Source for Dimensions
- Read from the active session/tab window's `frame` and available `visibleRect` in its owning terminal surface
- Use a fresh snapshot (not cached) when the flag is present, since these are derived state
- Include the flag in any topology request and have the broker apply it at snapshot time

### Performance Impact
- Dimensions are derived state that's cheap to compute (just rectangle math on an existing property)
- A fresh snapshot on each request with the flag is acceptable - this isn't a high-frequency path

### Backward Compatibility
- The `--include-dimensions` flag is opt-in, so existing scripts and agents are unaffected
- JSON schema remains the same when the flag is not present

## Acceptance Criteria

1. `batty list --json` works identically to today (no dimensions by default)
2. `batty list --json --include-dimensions` returns pane objects with `frame` and `visibleRect`
3. The flag works across all commands that return pane topology (`list`, `session info`, etc.)
4. The dimensions are accurate and reflect the current layout at snapshot time
5. No breaking changes to existing CLI interfaces or JSON schema
