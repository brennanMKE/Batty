# 0687 — The batty-cli skill and Claude Code plugin cannot be installed from the website without the app's installer

## Description

Child of #0680. `batty agent install` is the primary route and stays so. A person who wants the skill on a machine where `agent install` isn't convenient, or an agent host it doesn't detect, has no download, and Claude Code users can't `/plugin marketplace add` Batty. At release, package the bundled skill as a versioned zip plus a stable `latest` URL, and publish a Claude Code plugin marketplace with the same plugin `agent install` stages. Everything is generated from the release's sources, never hand-edited.

### Current state (checked against `main` at `3a7c12ec`)

- The app bundles `SKILL.md` into `AgentGuidance/skills/batty-cli/` (`Batty.xcodeproj/project.pbxproj:363-373`); `agent install` copies it into `~/.agents/skills`, Codex, Cursor and OpenCode skill folders (`BattyKit/Sources/BattyCLICore/AgentGuidanceInstaller.swift:255, 271, 285, 294`), renaming it `batty-beta-cli` in Beta (`AgentGuidanceIdentity.swift:28`, `AgentGuidanceInstaller.swift:348-357`).
- For Claude Code it stages a local marketplace (`stageMarketplace`, `AgentGuidanceInstaller.swift:360-398`): `.claude-plugin/marketplace.json`, the plugin's `.claude-plugin/plugin.json`, `.mcp.json`, `hooks/hooks.json` (SessionStart → `<cli> agent context`, line 402) and `skills/batty-cli/SKILL.md`. All paths in it are the app-bundle CLI path.
- `website/downloads/` holds only DMGs and a README.

## Expected behavior

1. **Shared staging code.** The plugin tree `stageMarketplace` writes is produced by a function that a release tool can call with the bare command name `batty` instead of the app-bundle path, and with a public plugin `source`. The installer's own output is unchanged byte for byte.
2. **Release tool.** `tools/build-agent-downloads.sh` (or a Python tool calling a Swift generator, plan's choice; no `scripts/` change without the user's confirmation) runs at release from the release tag's sources and writes:
   - `website/docs/skill/batty-cli-skill-<X.Y.Z>.zip`, in the Agent Skills folder layout (`batty-cli/SKILL.md` plus any files the bundled skill folder carries), usable from `~/.agents/skills`, Codex, Cursor and OpenCode;
   - `website/docs/skill/batty-cli-skill-latest.zip`, a copy of the newest (a copy, not a symlink: rsync and the web server must serve it plainly);
   - the Claude Code marketplace: `website/docs/claude-plugins/.claude-plugin/marketplace.json` and the plugin tree (skill + `.mcp.json` + SessionStart hook) beside it, version `X.Y.Z`, at a stable URL.
   Zips are reproducible (fixed mtimes, sorted entries), so a re-run on the same tag gives identical bytes and `--check` can compare.
3. **Hosting choice (open question for the user).** Recommended: serve the marketplace from the site (`https://batty.sstools.co/docs/claude-plugins/.claude-plugin/marketplace.json`). The plan must first confirm against current Claude Code docs whether a URL-added marketplace can use relative plugin `source` paths; if it can't, the marketplace entry points its `source` at the published plugin by URL or the user picks the alternative, a public GitHub repo (or this repo's path) added with `/plugin marketplace add brennanMKE/…`. Record the finding on the issue before implementing.
4. `website/README.md` "Per-release workflow" gets the step that runs the tool and commits its output. The agent page (#0683) and `llms.txt` (#0685) link the `latest` zip and the marketplace command.
5. Held: `docs/skill/batty-cli-skill-*` and `docs/claude-plugins/` are in `website/.deploy-hold` until #0688.

## Acceptance criteria

1. `./build.sh unit` passes, including a test that the public plugin tree (with `batty`) and the installer's staged tree (with the app path) differ only in the CLI path.
2. Running the tool twice on one commit gives byte-identical zips; `--check` exits 0.
3. Unzipping `batty-cli-skill-<X.Y.Z>.zip` into an empty `~/.agents/skills`-style folder gives `batty-cli/SKILL.md` identical to the bundled one.
4. In a scratch `HOME` (never the user's real `~/.claude`), `claude plugin marketplace add <local path or file URL of the generated marketplace>` and `claude plugin install batty@<marketplace>` succeed, if the `claude` CLI is available; otherwise the Gotchas say so.

## Notes

- Verification tier: build + unit tests, plus the scratch-`HOME` marketplace check.
- The SessionStart hook and `.mcp.json` call bare `batty`, so they work only when the CLI is on `PATH` (Settings → Install CLI). The agent page says so.
