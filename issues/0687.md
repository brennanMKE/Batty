## Description

Child of #0680. `batty agent install` is the primary route and stays so. A person who wants the skill on a machine where `agent install` isn't convenient, or an agent host it doesn't detect, has no download, and Claude Code users can't `/plugin marketplace add` Batty. At release, package the bundled skill as a versioned zip plus a stable `latest` URL, and publish a Claude Code plugin marketplace with the same plugin `agent install` stages. Everything is generated from the release's sources, never hand-edited.

Round 2 (review notes): `tools/sync-claude-marketplace.sh` can no longer empty a Batty checkout or another repo.
- Refuses (exit 2, nothing written) a target that is not a git repo or not its top level, any checkout or worktree of this repo (`git rev-parse --path-format=absolute --git-common-dir` equal to `$ROOT`'s), a symlinked managed path, a `marketplace.json` whose `name` isn't `batty-plugins`, and a non-empty folder with no `.claude-plugin/marketplace.json` (ignoring `.git`, `LICENSE`, `README.md`, `.gitignore`, `.gitattributes`).
- Dropped the whole-tree `rsync --delete`. It now writes only the managed paths: `rsync -a --delete` into `.claude-plugin/` and `batty/` separately, plus a plain copy of `README.md`. Chosen over an explicit file list because a file list can't remove a file a later plugin version drops (a renamed skill would linger in the repo), while per-subtree `--delete` keeps that cleanup and caps the blast radius at those two folders. Nothing outside them (`.git`, `LICENSE`, hand-written files) is ever deleted, even in a valid clone.
- Added `--dry-run` (checks only, writes nothing) and `--from DIR` (sync an already generated tree; the selftest's seam, also usable on release day).
- New `tools/sync-claude-marketplace-selftest.py`: copies the script into a scratch git repo standing in for Batty, so the main-checkout and worktree cases never touch a real checkout. `tools/README.md` updated.

**Claude Code marketplace format.** Source: <https://code.claude.com/docs/en/plugin-marketplaces>, <https://code.claude.com/docs/en/plugins/marketplace-reference.md> and <https://code.claude.com/docs/en/plugins/host-marketplace.md>, read 2026-11-19.
- `.claude-plugin/marketplace.json` sits at the repo root and needs `name`, `owner.name` and `plugins`. `description` is optional, but `validate` warns when it's missing.
- A relative `source` resolves from the marketplace root (the folder that holds `.claude-plugin/`), must start with `./`, and must not contain `..`. `./batty` is valid.
- The entry name must equal the `plugin.json` name.
- Names may use letters, digits, `.`, `_` and `-`. Reserved names include `claude-code-plugins`, `claude-plugins-official`, `anthropic-*`, `agent-skills` and `claudeai-*`. `batty-plugins` is allowed.
- **Set `version` in `plugin.json` only.** The docs say not to set it in both places: `plugin.json` wins, and `validate` warns on a mismatch. Users get an update only when the version changes, so every release bumps it.
- Users run `/plugin marketplace add owner/repo` (or `claude plugin marketplace add`), then `/plugin install <plugin>@<marketplace-name>`. Local testing uses `claude plugin marketplace add <dir>` and `claude plugin validate <dir>`.
- Keep plugin files out of Git LFS. That's fine here: the files are JSON and Markdown, and the repo is separate.

### Decisions in this plan (user can override)

- **Repo `brennanMKE/batty-plugins`, marketplace name `batty-plugins`, plugin `batty`.** Install is `/plugin install batty@batty-plugins`. The names live in one place, `AgentPluginTree` (below), so changing them is a one-line edit. **The user confirms the repo name before #0688.** The plan doesn't block on it.
- **Prod only.** The public marketplace publishes only the `batty` plugin. Beta keeps `agent install` only.
- **The marketplace contents are generated, gitignored output in `build/claude-marketplace/`**, already ignored by `build/`. They are not a checked-in template. The tree is a pure function of `SKILL.md`, the version and constants in Swift, so a checked-in copy would be a third copy to drift. The public repo's own git history is the record of what shipped. Drift is guarded by unit tests (public tree vs installer tree) and by the sync script, which always regenerates before copying.
- **The zips use `ZIP_STORED`, not deflate.** A stored zip's bytes depend only on content, names, the fixed timestamp and attributes, not on the zlib version, so `--check` holds across machines. The file is about 8 KB.
