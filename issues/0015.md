## Description

Wire keyboard navigation for the focused Pane's Tab strip per `Concepts.md` → Tab and PRD §6.5.

**Acceptance criteria:**
- **Cmd-T** — adds a new Tab to the focused Pane (with a fresh Terminal Session).
- **Cmd-W** — closes the focused Tab. If it was the last Tab in the Pane, it triggers the Pane collapse logic owned by #0021. (For this issue, the Tab simply closes; pane-collapse behavior is verified end-to-end in #0021.)
- **Cmd-1..9** — selects the Nth Tab in the focused Pane. No-op if fewer than N Tabs.
- **Cmd-Shift-[** — cycle to previous Tab; **Cmd-Shift-]** — cycle to next Tab. Wrap at the ends.
- All keybindings are exposed in the menu bar (Tab menu) for discoverability and VoiceOver.

## Notes

- Cmd-W must target the focused Pane's focused Tab, not the focused Window. SwiftUI's default Cmd-W maps to "close window" — override with a custom `.keyboardShortcut`.
- Cmd-1..9 may conflict with system shortcuts in some apps; these are window-scoped here, so it's fine.

## Root cause

Feature gap. M3's tab navigation needed keyboard affordances on top of the SlidingTabs UI from #0014.

## Fix

Two parts:

`PaneRuntime` gained four convenience methods on top of the register/remove primitives from #0014:
- `closeActiveTab()` — closes whatever tab is active via `removeTab(id:)`. Last-tab guard from #0014 still applies (no-op when 1 tab).
- `selectTab(at:)` — index-based selection.
- `selectNextTab()` / `selectPreviousTab()` — cycle with wrap-around (modulo `tabs.count`).

`BattyCommands` got a `CommandMenu("Tab")` with seven kinds of buttons: New Tab (Cmd-T), Close Tab (Cmd-W), Show Previous/Next Tab (Cmd-Shift-[ / Cmd-Shift-]), and nine "Show Tab N" buttons (Cmd-1..9). Each wires to the focused session's pane via the existing `@FocusedValue(\.appStateStore)`. Tab menu titles use the same fallback chain as `PaneView`'s chip titles: `titleOverride` → live terminal title → "Tab N".

A private `focusedPane` computed property in `BattyCommands` centralizes the `store?.selectedSession?.pane` lookup so the disabled-state checks stay readable.

## Files changed

- `BattyKit/Sources/BattyKit/PaneRuntime.swift` — added 4 navigation methods (~25 lines).
- `BattyKit/Sources/BattyKit/BattyCommands.swift` — added Tab menu (~50 lines) plus `focusedPane`, `tabMenuTitle`, `tabExists`.

## Gotchas

- **Cmd-W routing.** Our "Close Tab" with Cmd-W is **disabled when only one tab exists**, so the system File > Close Window (also Cmd-W) is the only enabled handler in the single-tab case. With multiple tabs, our Tab > Close Tab takes the keystroke. This is the simplest interaction for M3; once #0021 lands the "last-tab close → pane collapse" semantics, Close Tab can stay enabled at all counts and Cmd-W can route to Close Window via Cmd-Shift-W (iTerm2 convention).
- **`focusedPane` reads `store?.selectedSession?.pane`.** For M3 with one pane per session this is unambiguous. M4's focus-movement (#0020) introduces per-pane focus within a session via Cmd-Option-arrows; that work will need to switch the per-tab commands to use that focus marker rather than the session's only pane.
- **No surface registry interaction.** Tab close goes through `PaneRuntime.removeTab` which mutates `tabs` and re-routes `activeTabID`. The underlying `TerminalViewState` is the SwiftUI runtime's responsibility to deinit when the SwiftUI subtree dismounts; libghostty surface lifetime follows from there. The `SurfaceRegistry` from #0006 is currently not in the call path — left in place per #0006's resolution as a likely-vestigial component pending verification.
