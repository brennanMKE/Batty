# 0581 — A background catalog image's title is optional, so an untitled image shows its file name (such as `02-lanterns`) as its caption; the user wants every image to have a title

## Description

The simplified catalog format (#0574's "Catalog format", recorded as decision 12 on branch `issue/0576`; website side converted by #0580) makes an image's `title` optional. A missing, `null` or blank title falls back to the full-size file's name without its extension, so the page and the Background Sets browser show captions like `02-lanterns`. The user wants a title on every image. Make `title` **required** everywhere: a string that is non-empty after trimming and at most 100 characters. A catalog with a missing, `null`, non-string, blank or over-long title is rejected, with the error naming its path (`sets[0].images[1].title`), like every other required field. Child of [#0574](0574.md).

User decision (2026-11-11, verbatim):

> "I'd prefer to require a title so it looks better."

This applies to user-added catalogs (#0577) as well as the built-in one, since they share the parser. The live catalog at batty.sstools.co already has titles on all 24 images, and so does `website/backgrounds/catalog.json` on `main` (checked 2026-11-11: 24 `"title"` keys for 24 images, none blank). So no image or catalog redeploy is needed. The page and the example catalog change, and they go out with the 1.4.0 website deploy.
