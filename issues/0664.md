# 0664 — `agent install` does not write the global Batty note to Claude Code's, Codex's and OpenCode's instruction files

| | |
|---|---|
| **Status** | open |

| **Platform** | macOS |
| **First seen** | 2026-11-18 |
| **Target** | 1.5.0 |

## Description

Child of #0660. Every agent session should carry a short note: check for `BATTY_*`; if set, you are in Batty, prefer the `batty` MCP tools or the CLI. The user wrote that note by hand on 2026-11-18 into `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md` and `~/.config/opencode/AGENTS.md`, each as an unmarked `## Batty` section. `agent install` should write and refresh it as a marked block, exactly as it already does for a project file.

### Current state

- `agent install --project DIR` writes `ProjectAgentSnippet.block` between `<!-- batty:begin -->` and `<!-- batty:end -->`, replacing an existing marked block and keeping everything outside it byte for byte (`BattyKit/Sources/BattyCLICore/ProjectAgentSnippet.swift:8-9, 56-70`). It asks first on a TTY and refuses without `--yes` otherwise (`confirmationRequired`, `ProjectAgentSnippet.swift:72-76`).
- `AgentGuidanceInstaller.plan` (`BattyKit/Sources/BattyCLICore/AgentGuidanceInstaller.swift:231-297`) has no action for a global instruction file. `AgentInstallAction` (`:25-35`) has no case for one.
- Claude Code reads `~/.claude/CLAUDE.md` (not a global `AGENTS.md`); Codex reads `~/.codex/AGENTS.md`; OpenCode reads `~/.config/opencode/AGENTS.md`. Cursor's user rules live in its settings, not a file, so Cursor is out of scope.
- The hand-written sections start `## Batty` / "At the start of a session, run `env | grep '^BATTY'`…" and end "If those variables are not set, you are not in Batty; ignore this section." They are not wrapped in markers, so a naive append would add a second Batty section.

## Expected behavior

- A new `AgentInstallAction` case, for example `.mergeInstructionBlock(host:file:)`, planned for each detected host: Claude Code → `~/.claude/CLAUDE.md`, Codex → `~/.codex/AGENTS.md`, OpenCode → `~/.config/opencode/AGENTS.md`. It creates the file if missing.
- The block is variant-aware global text (not the project snippet, which is variant-neutral for git): it uses the same marker pair and the shared rules from #0661's builder, and names `batty`/`batty-beta`. It starts with the `BATTY_*` check and ends with "If those variables are not set, you are not in Batty; ignore this section."
- With both Prod and Beta installed, the two installs must not fight over one block. Recommended: one block that names both CLIs, so whichever installs last writes the same text.
- **Hand-written section:** if the file has no markers but has a `## Batty` heading, the installer reports it as `manual` ("an unmarked ## Batty section exists; replace it with Batty's block? Re-run with --replace-unmarked, or confirm in Settings"), and does not write. With confirmation it replaces that section (from the heading to the next heading of the same or higher level, or end of file) with the marked block.
- `--dry-run` shows the diff; the report lists each file as `ok`, `unchanged` or `manual`.
- Settings → AI Agents shows the same plan and confirmation.

## Acceptance criteria

1. `AgentGuidanceInstallerTests`: planned for each detected host and not for undetected ones; creates a missing file; replaces a marked block in place; keeps surrounding text byte for byte; an unmatched marker is `failed` with the existing message; an unmarked `## Batty` section yields `manual` and no write, and with the replace option is replaced with nothing else changed (fixture copied from the user's current wording).
2. All tests use a temporary home directory, never the real `~`.

## Open questions

1. **Replace the user's hand-written sections automatically?** Recommended: no; ask once (`manual` outcome, confirmation in Settings or `--replace-unmarked`).
2. **Write global files by default, or only on request?** Recommended: by default as part of `agent install`, since it is shown in the plan and confirmed (#0666 adds the prompt).
