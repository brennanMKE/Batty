# 0664 — Batty has no documented prompt that has an agent add or update the Batty note in its own global instructions file

| | |
|---|---|
| **Status** | open |
| **Module** | App / Settings / Docs |
| **Platform** | macOS |
| **First seen** | 2026-11-18 |
| **Target** | 1.5.0 |

## Description

Child of #0660. Every agent session should carry a short note: check for `BATTY_*`; if set, you are in Batty, prefer the `batty` MCP tools or the CLI. The user wrote that note by hand on 2026-11-18 into `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md` and `~/.config/opencode/AGENTS.md`, each as an unmarked `## Batty` section. Other users have no way to get it except writing it themselves.

Batty does not write these files. Instead it documents a ready-to-paste prompt the user gives their agent, asking the agent to add or update a "Batty" section in that agent's own global instructions file, with Batty's canonical note text.

### Current state

- `agent install --project DIR` writes `ProjectAgentSnippet.block` between `<!-- batty:begin -->` and `<!-- batty:end -->` in a project file (`BattyKit/Sources/BattyCLICore/ProjectAgentSnippet.swift`). Nothing covers global instruction files, and per the decision below `agent install` will not.
- Global instruction files per agent: Claude Code `~/.claude/CLAUDE.md` (not a global `AGENTS.md`); Codex `~/.codex/AGENTS.md`; OpenCode `~/.config/opencode/AGENTS.md`. Cursor's user rules live in its settings, not a file; the prompt can tell Cursor users to paste the note into User Rules.
- The user's current wording (from `~/.claude/CLAUDE.md`, the canonical text to start from):

```markdown
## Batty

At the start of a session, run `env | grep '^BATTY'`. If `BATTY_SESSION_ID`,
`BATTY_TAB_ID` and `BATTY_PANE_ID` are set, you are running in a terminal Pane of
Batty, a macOS terminal multiplexer, and can drive it:

- Prefer the `batty` MCP tools when they are available (`batty mcp`, installed by
  `batty agent install`). Otherwise use the CLI: `batty` (or `batty-beta` in Batty
  Beta). Run `batty capabilities` to see the available commands.
- Use Batty to split Panes, show status views (git status, processes, system
  metrics), set reminders, and notify the user when a long task finishes or needs
  their attention.
- Start dev servers with `batty server start` (or adopt a running one with
  `batty server attach`) so the user sees them in a Server Pane, instead of opening
  a browser or leaving processes running untracked.
- Close Panes and Sessions you created when you are done with them.

If those variables are not set, you are not in Batty; ignore this section.
```

## Expected behavior

- One canonical prompt text, kept in a single source (shared with #0661's rule text where it overlaps), that says: add a `## Batty` section to your global instructions file, or update it in place if one exists, with exactly this text; it names the file per agent (the three paths above, and Cursor's User Rules) and embeds the note. The note names both `batty` and `batty-beta`, so it is the same for Prod and Beta.
- The prompt is shown where users find it:
  - the Help (the AI Agents page from #0671);
  - the `batty-cli` skill and CLI docs (`docs/batty-cli-agent-workflows.md`);
  - Settings → AI Agents, with a Copy button.
  - Optionally a CLI form such as `batty agent context --prompt`; the plan decides whether to add it.
- `agent install` does not read or write any global instruction file. Hand-written or agent-written `## Batty` sections are left to the user and their agent.

## Acceptance criteria

1. A unit test pins the prompt: it names all three file paths, embeds the canonical note, and starts the note with the `BATTY_*` check and ends with "If those variables are not set, you are not in Batty; ignore this section."
2. Settings → AI Agents shows the prompt with a working Copy button; Help and the skill/CLI docs carry the same text (a drift test or a single generated source).
3. `AgentGuidanceInstaller` plans no action touching `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md` or `~/.config/opencode/AGENTS.md` (test with a temporary home directory).

## Decisions (user, 2026-11-18)

- "Document a prompt to give to agents": Batty provides a ready-to-paste prompt for the agent to add or update its own global Batty section, rather than `agent install` writing marked blocks into global instruction files. This replaces the earlier plan for a `.mergeInstructionBlock` installer action and the `--replace-unmarked` option; the former open questions (replacing hand-written sections, writing global files by default) no longer apply.
