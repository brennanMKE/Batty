## Description

Batty never tells libghostty that a surface is invisible — not once, for any surface, ever. `AppTerminalView.setSurfaceVisible(_:)` (`AppTerminalView.swift:34-36` in libghostty-spm) is the wrapper's occlusion entry point and it has **zero callers in either repository** (Batty and libghostty-spm, both grepped). Every surface is created with `setOcclusion(true)` (`TerminalSurfaceCoordinator.swift:128`) and stays there for the process lifetime, so every background Tab renders a full frame each time its PTY produces output.

**This is now evidence-backed by live measurement, and it is the biggest Batty-side lever in the #0285 umbrella.** The instrumentation (`issues/0285/investigation-live.md`) measured **31 live `CAMetalLayer`s for 26 Terminal Sessions, and 22 of them share one identical 820×962 geometry that at most 2 panes can occupy on screen at once** — layers are demonstrably retained for Terminal Sessions that are not visible; layer count tracks *existing* sessions, not visible ones. The costs that scale with layer count are the dominant ones: **377 MB of drawables plus 326 MB of Metal render textures, ~700 MB of the 1090 MB graphics footprint** on the measured instance. The measured per-Terminal-Session cost model (at 820×962): 3 × drawable 9.19 MB + 3 × grayscale atlas 3.05 MB + 3 × color atlas 0.80 MB + ~10.5 MB render textures + ~8.0 MB unmapped ≈ **35 MB per layer / 42 MB per Terminal Session** — every line of which multiplies by the live layer count.

Why hiding a view doesn't help: the render gate is `shouldRenderFrame` (`TerminalSurfaceCoordinator.swift:305-310`), which is `isDisplayVisible && isAttached()`, and `isAttached` is `self?.window != nil` (`AppTerminalView.swift:69`) — **true for hidden views**, because Batty deliberately keeps background Tabs in the host with `isHidden = true` (`TerminalHostStore.swift:136, 216-218, 240-242`) precisely so they never detach. `AppTerminalView` overrides no visibility hook (no `viewDidHide` / `viewDidUnhide` / `isHiddenOrHasHiddenAncestor` check), and nothing anywhere observes `NSWindowOcclusionState`.

Hidden panes (#0256) are the same story with an extra twist: `hidePane` sets an invisible placement (`WindowRuntime.swift:426-431`) which only sets `view.isHidden = true`, and `updatePlacements` only writes `view.frame` when `placement.isVisible` (`TerminalHostStore.swift:209-212`) — so a hidden Tab keeps a **full-size swap chain at its last visible size** indefinitely.

**Fix:** call `AppTerminalView.setSurfaceVisible(_:)` from the same places that set `isHidden` (`TerminalHostStore.swift:216-218, 240-242`), and additionally observe `NSWindowOcclusionState` so fully occluded windows stop rendering too. Its only downstream effect is `setDisplayVisible(_:)` (`TerminalSurfaceCoordinator.swift:212-228`), the sole mutator of `isDisplayVisible` (default `true`, `:66`).

## Resolution notes

> 🟢 Resolved 2026-08-01 — non-visible Terminal Sessions no longer render, and a Batty-side ticker keeps their bells, titles, and child-exit events flowing.

Four implementation rounds and four reviews. The issue was parked twice as unfixable-from-Batty before a public API turned out to make it fixable.

## Root cause

`AppTerminalView.setSurfaceVisible(_:)` had **zero callers in either repository**. Every surface was created with `setOcclusion(true)` and stayed that way for the process lifetime. Because Batty deliberately keeps background Tabs in the host with `isHidden = true` so they never detach, the render gate `canRenderFrame` (`isDisplayVisible && isAttached()`, where `isAttached` is just `window != nil`) stayed true — so every background Tab rendered a full frame on every PTY wakeup, and hidden Tabs held a full-size swap chain at their last visible size.

Measured: **31 live `CAMetalLayer`s for 26 Terminal Sessions, 22 of them at one 820×962 geometry that at most 2 panes can occupy on screen.** Layer-count-scaled costs are ~700 MB of the 1090 MB graphics total.

## Fix

Two halves, and the second is why this took four rounds.

**Occlusion signalling.** `setSurfaceVisible(_:)` is now called from `TerminalHostStore.updatePlacements` / `setPlacement` as `effectiveSurfaceVisible(placementVisible:windowVisible:)`, plus a new `setWindowOcclusionVisible(_:forWindowID:)` driven by a real `windowDidChangeOcclusionState` delegate callback — covering full occlusion, minimize, and Cmd-H. Effective visibility is always recomputed from both inputs, never a blanket "show everything," so restoring a window cannot un-hide an already-hidden background Tab.

**The ticker.** `setSurfaceVisible(false)` also sets `isDisplayVisible`, which libghostty-spm installs as the package-internal `TerminalController.shouldProcessWakeup`; `handleWakeup()` guards on it and skips `ghostty_app_tick` **entirely**, suppressing `RING_BELL`, `SET_TITLE`, `CELL_SIZE`, `PROGRESS_REPORT`, child-exit, and desktop notifications. `OccludedSurfaceTicker` drains occluded Tabs on a 500 ms poll via the **public** `TerminalController.tick()`. Rendering stays gated independently: a drained `GHOSTTY_ACTION_RENDER` routes to `requestImmediateTick()` → `scheduleTickIfNeeded()`, which returns at `guard canRenderFrame`.

## Review

Reviewed by claude-opus-5 across four rounds.

Round 1 verified the observation-rules compliance and traced re-display through every path, then **blocked**: `setSurfaceVisible(false)` suppresses far more than rendering, and because the change also drives window occlusion, a covered or locked window would silence the Bell Feed — whose entire purpose is sessions the user is not watching.

Rounds 2 and 3 were parked twice for want of a measurement the locked screen made impossible. The unblock came from re-checking an access-level assumption: `shouldProcessWakeup` is indeed internal, but `TerminalController.tick()` three lines above it is `public`, and `ghostty_app_tick` has exactly one caller in the package.

Round 3's review then answered the load-bearing question **by enumeration**: `surface.draw()`/`refresh()` occur exactly once in the package, inside `TerminalSurfaceCoordinator.tick(context:)`, whose only two callers both open with `guard canRenderFrame`, and which re-guards itself. Triple-gated. It also found a real defect — the tick set went stale when a surface was created while already invisible, so a Tab mounting into an already-covered window stayed untracked and its bells stayed queued.

Round 4 approved, having personally re-run the mutation in both directions.

## Expected behavior

Surfaces belonging to hidden Tabs, hidden panes, and fully occluded windows stop rendering: `setSurfaceVisible(false)` on hide/occlude, `setSurfaceVisible(true)` on reveal.

**Set expectations correctly:** this should slow or stop redraw-driven growth for non-visible sessions, but it is **not** expected to reclaim existing footprint. The C API exposes no "release GPU resources" call short of `ghostty_surface_free` — occlusion pauses the render loop, it does not free the swap chain (roughly 48 MB per hidden Terminal Session stays put; see #0293). Whether Ghostty's occlusion path additionally releases anything could not be determined from source alone; #0291 experiment (b) settles it by live measurement.

## Actual behavior

Every background/hidden Tab renders a full frame per PTY wakeup: `bridge.onRenderRequest` → `requestImmediateTick()` (`TerminalSurfaceCoordinator.swift:76-78`) → `tick()` → `surface.refresh(); surface.draw()` (`:238-241`). Hidden panes keep a full-size swap chain.

## Notes

This work touches the pane/visibility path, so the binding docs apply: read `docs/terminal-pane-requirements.md` and `docs/swiftui-observation-rules.md` before starting. In particular, occlusion-state observation must not write observed state from layout/focus/geometry-origin callbacks.

**Runtime verification can use the Beta build** rather than the user's running release instance: scheme `Batty (Beta)`, bundle id `co.sstools.Batty.beta` (`Configuration/Beta.xcconfig:4`), built with `SCHEME="Batty (Beta)" scripts/build.sh`. The distinct bundle id gives it its own UserDefaults domain and workspace persistence, so it can be launched, driven, and killed freely. Run the before/after layer census (#0291) against it to verify the occlusion signalling and settle whether `setSurfaceVisible(false)` drops the IOSurface region count.

One useful non-finding from the investigation: despite its name, `startDisplayLink()` (`TerminalSurfaceCoordinator.swift:86-88`) starts no display link — the real mechanism is a one-shot `DispatchQueue.main.async` re-armed per wakeup (`:312-334`). There is **no per-Tab timer** burning frames on idle Tabs; growth requires actual PTY output. So this fix helps exactly the sessions that produce output while invisible.

A nuance the live data adds to the caveat above: the measured instance's footprint was flat over 20 idle minutes, so occlusion signalling alone will not shrink the ~700 MB of layer-scaled cost — it targets the growth path for sessions producing output while invisible. Actually *reclaiming* the retained-layer cost requires either dropping layers for non-visible Tabs (a Batty design question against the #0256 keep-attached decision) or an upstream release API (#0293). Record which of those this issue's implementation does and does not attempt.

## Gotchas

**What this change does.** Non-visible Terminal Sessions (background Tabs,
hidden panes, and every Tab in a fully occluded / minimized / Cmd-H'd window)
now receive `setSurfaceVisible(false)`, which stops libghostty's render loop
for them. That removes the redraw-driven growth path for sessions producing
output while nobody is watching.

**What it does not do.** It does not reclaim any existing footprint. The C API
exposes no "release GPU resources" call short of `ghostty_surface_free`, so an
occluded surface keeps its swap chain, drawables, and glyph atlases — roughly
48 MB per hidden Terminal Session stays resident. Reclaiming that is #0293
(upstream), not this issue.

**The memory census was never run by an agent.** No before/after IOSurface or
layer-count measurement was taken on a live process at any point across four
implementation rounds and four reviews — the screen was at loginwindow and GUI
automation was unavailable. Whether `setSurfaceVisible(false)` additionally
drops any IOSurface regions inside the Zig core is still unknown from source
alone; #0291 experiment (b) is the measurement that settles it. Treat the
memory benefit as "growth stopped, footprint unchanged" until measured.

**Bell delivery for occluded Tabs is now poll-driven, not event-driven.**
`setSurfaceVisible(false)` sets `isDisplayVisible`, which libghostty-spm
installs as the package-internal `TerminalController.shouldProcessWakeup`;
`handleWakeup()` guards on it and skips `ghostty_app_tick` entirely, which
would otherwise suppress not just rendering but `RING_BELL`, `SET_TITLE`,
`CELL_SIZE`, `PROGRESS_REPORT`, child-exit, and desktop notifications for that
Tab. Batty cannot override that gate (it is internal, and the two closures
that could observe a wakeup are both internal *and* overwritten on every
surface build). The public `TerminalController.tick()` is the only remaining
hook, so `OccludedSurfaceTicker` drains occluded Tabs on a 500 ms poll.
Consequence: a bell from an occluded Tab can be up to 500 ms late. Suppression
without the ticker was proven real (3/3 in a live in-process harness with a
real PTY: occluded, the bell never auto-delivered across a 3 s window; the
first manual `tick()` drained it immediately), so the poll is load-bearing,
not belt-and-braces. If `startOccludedSurfaceTicking()` is ever dropped from
`BattyAppDelegate`, occluded-Tab bells go silent rather than merely late.

**User verification still outstanding** (this is `resolved`, not `closed`):
run the bell check on the Beta build — `sleep 10; printf '\a'` in a Tab, then
switch away so it is (a) a background Tab, (b) in a hidden pane, (c) in a

`tools/memsample.sh sample --target beta --tag before` with Tabs visible,
drive them occluded, `--tag after`, `diff before after`. Expect the surface
count NOT to drop; the signal is that growth stops.
