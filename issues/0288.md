# 0288 — Occlusion is never signalled, so background and hidden Tabs keep rendering on every PTY wakeup

| | |
|---|---|
| **Status** | open |
| **Module** | TerminalSurface |
| **Platform** | macOS |
| **First seen** | 2026-07-31 |

## Description

Batty never tells libghostty that a surface is invisible — not once, for any surface, ever. `AppTerminalView.setSurfaceVisible(_:)` (`AppTerminalView.swift:34-36` in libghostty-spm) is the wrapper's occlusion entry point and it has **zero callers in either repository** (Batty and libghostty-spm, both grepped). Every surface is created with `setOcclusion(true)` (`TerminalSurfaceCoordinator.swift:128`) and stays there for the process lifetime, so every background Tab renders a full frame each time its PTY produces output.

Why hiding a view doesn't help: the render gate is `shouldRenderFrame` (`TerminalSurfaceCoordinator.swift:305-310`), which is `isDisplayVisible && isAttached()`, and `isAttached` is `self?.window != nil` (`AppTerminalView.swift:69`) — **true for hidden views**, because Batty deliberately keeps background Tabs in the host with `isHidden = true` (`TerminalHostStore.swift:136, 216-218, 240-242`) precisely so they never detach. `AppTerminalView` overrides no visibility hook (no `viewDidHide` / `viewDidUnhide` / `isHiddenOrHasHiddenAncestor` check), and nothing anywhere observes `NSWindowOcclusionState`.

Hidden panes (#0256) are the same story with an extra twist: `hidePane` sets an invisible placement (`WindowRuntime.swift:426-431`) which only sets `view.isHidden = true`, and `updatePlacements` only writes `view.frame` when `placement.isVisible` (`TerminalHostStore.swift:209-212`) — so a hidden Tab keeps a **full-size swap chain at its last visible size** indefinitely.

**Fix:** call `AppTerminalView.setSurfaceVisible(_:)` from the same places that set `isHidden` (`TerminalHostStore.swift:216-218, 240-242`), and additionally observe `NSWindowOcclusionState` so fully occluded windows stop rendering too. Its only downstream effect is `setDisplayVisible(_:)` (`TerminalSurfaceCoordinator.swift:212-228`), the sole mutator of `isDisplayVisible` (default `true`, `:66`).

## Expected behavior

Surfaces belonging to hidden Tabs, hidden panes, and fully occluded windows stop rendering: `setSurfaceVisible(false)` on hide/occlude, `setSurfaceVisible(true)` on reveal.

**Set expectations correctly:** this should slow or stop redraw-driven growth for non-visible sessions, but it is **not** expected to reclaim existing footprint. The C API exposes no "release GPU resources" call short of `ghostty_surface_free` — occlusion pauses the render loop, it does not free the swap chain (roughly 48 MB per hidden Terminal Session stays put; see #0293). Whether Ghostty's occlusion path additionally releases anything could not be determined from source alone; #0291 experiment (b) settles it by live measurement.

## Actual behavior

Every background/hidden Tab renders a full frame per PTY wakeup: `bridge.onRenderRequest` → `requestImmediateTick()` (`TerminalSurfaceCoordinator.swift:76-78`) → `tick()` → `surface.refresh(); surface.draw()` (`:238-241`). Hidden panes keep a full-size swap chain.

## Notes

This work touches the pane/visibility path, so the binding docs apply: read `docs/terminal-pane-requirements.md` and `docs/swiftui-observation-rules.md` before starting. In particular, occlusion-state observation must not write observed state from layout/focus/geometry-origin callbacks.

One useful non-finding from the investigation: despite its name, `startDisplayLink()` (`TerminalSurfaceCoordinator.swift:86-88`) starts no display link — the real mechanism is a one-shot `DispatchQueue.main.async` re-armed per wakeup (`:312-334`). There is **no per-Tab timer** burning frames on idle Tabs; growth requires actual PTY output. So this fix helps exactly the sessions that produce output while invisible.
