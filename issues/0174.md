## Root cause

The original failure was caused by the same main-runloop-blocking
`Thread.sleep` bug fixed in [[0170]]. XCUITest's XPC bridge needs the
host process's main runloop to be live in order to observe accessibility
mutations after a real `NSDraggingSession`. The pre-[[0170]] `waitFor`
helper spun a `Thread.sleep` loop on `@MainActor`, starving the
runloop and preventing post-drag accessibility-tree updates
(swapped tab-bar identifiers at positions 0/1) from reaching the test
process before the timeout. The Mode-B `press(forDuration:thenDragTo:)`
drag itself was — and is — being routed correctly through the
pane-drag-handle and producing a real swap; the test simply couldn't
see it.

[[0170]]'s centralized `RunLoop.run(until:)`-based `waitFor` keeps the
runloop pumping during polls, so the post-drag tab-bar identifiers are
now observed within the 5s window and both swap assertions
(`tabBars[0].identifier == targetID` and
`tabBars[1].identifier == sourceID`) pass cleanly.

The test itself is also structurally sound, unlike the
`testIntentSwapChangesTabBarOrder` rewrite in [[0173]]: it captures
`sourceID` / `targetID` and performs the swap inside a single launch
(so per-launch UUIDs are not a problem), and its assertions verify
the actual structural mutation rather than a tautology.

## Gotchas

- Mode-B drag tests depend on a live main runloop in the host app
  process for the entire duration of the synthesized
  `NSDraggingSession` plus the post-drag accessibility-tree
  reconciliation. Any future "let's just sleep for a second to wait
  for X" added to `@MainActor` test code will re-break this test
  (and likely the other Mode-B test, `testModeBDropZoneVisibleMidDrag`)
  in exactly the way [[0170]] just fixed. Always use the centralized
  `waitFor` helper from `BattyUITestHarness`.
- This test, unlike the one rewritten in [[0173]], is a clean example
  of how a single-launch drag-drop test should be written: capture
  identifiers from a known-good baseline, perform the mutation in the
  same process, then assert against the post-mutation identifiers.
  Worth using as a template if more drag-drop tests are added.
