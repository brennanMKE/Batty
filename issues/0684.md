# 0684 — The site has no CLI reference and no published `capabilities.json`

|---|---|

## Description

Child of #0680. `batty capabilities --json` is the source of truth for every verb and its `inputSchema` (`.claude/skills/batty-cli/SKILL.md:15-20`), but an agent without Batty installed, or a person reading ahead, can't see it. Publish it as `docs/cli/capabilities.json` and render a human and agent-readable reference from it at `docs/cli/index.html` and `docs/cli/index.md`.

### Current state (checked against `main` at `3a7c12ec`)

- `CapabilitiesCommand.buildPayload(flags:)` (`BattyKit/Sources/batty/CapabilitiesCommand.swift:75`) builds a `CapabilitiesPayload` (`BattyKit/Sources/BattyXPCCore/CapabilitiesPayload.swift:49-57`: `cliVersion`, `verbs`, `exitCodes`, `jsonSchemaDialect`); each verb has `name`, `abstract`, `aliases`, `inputSchema`, `annotations` (lines 11-21).
- The verb list depends on `FeatureFlags` (`agentIntegration`, `serverPane`) until #0669/#0670 remove them, so a Beta and a Prod build list different verbs today.
- No `website/docs/cli/` exists.

## Expected behavior

1. `website/docs/cli/capabilities.json` is committed: the `--json` output, pretty-printed with sorted keys. It is regenerated at each release from that release's Prod build (step added to `website/README.md` "Per-release workflow" by this issue).
2. `tools/build-cli-reference.py` (stdlib Python, `python3 -I`, with `--check` and a self-test) renders `website/docs/cli/index.md` and `website/docs/cli/index.html` from the JSON: grouped by noun, each verb with its abstract, aliases, parameters (name, type, enum values, default, required) from `inputSchema`, its annotations, and the exit-code table. The pages state the `cliVersion` they were generated from.
3. **Drift test.** A BattyKit unit test builds the payload in-process with all flags on (or with no flags, once #0669/#0670 land) and compares it with the committed JSON, ignoring `cliVersion`. It fails, naming the regenerate command, when a verb is added, removed or changed without regenerating. The plan picks the module that can see `buildPayload` (the `batty` executable target is not importable; move the builder or the test accordingly, without changing `--json` output, #0384).
4. `docs/cli/` stays in `website/.deploy-hold` (#0681) until #0688.

## Acceptance criteria

1. `./build.sh unit` passes, and editing any verb's abstract or schema without regenerating fails the drift test.
2. `python3 -I tools/build-cli-reference.py --check` exits 0; `tidy -e -q website/docs/cli/index.html` reports no errors.
3. The reference pages list every verb in `capabilities.json`, and nothing else.
4. `batty capabilities --json` output is unchanged by this issue (diff before and after on a Beta build).
