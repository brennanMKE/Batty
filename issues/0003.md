# 0003 — Bundle Ghostty terminfo and shell-integration resources

| | |
|---|---|
| **Status** | open |
| **Module** | Build / GhosttyKit |
| **Platform** | macOS |
| **First seen** | 2026-05-08 |

## Description

Copy Ghostty's terminfo database and shell-integration scripts into `Batty.app/Contents/Resources/` so libghostty's runtime can find them. Without these resources, shell integration silently degrades (Kytos's writeup flags this as a common gotcha — `batty-getting-started.md` §4).

**Acceptance criteria:**
- After a build, `Batty.app/Contents/Resources/terminfo/78/xterm-ghostty` exists (the sentinel file libghostty looks for).
- `Batty.app/Contents/Resources/ghostty/shell-integration/...` exists with bash/zsh/fish helpers.
- The app can launch a shell and the `$TERM` value resolves cleanly inside that shell (verify by typing `echo $TERM` after M1 is in).

## Notes

- Implement as an Xcode Run Script build phase that copies from the GhosttyKit xcframework (or the Ghostty source tree if Path B). The script must be deterministic and idempotent.
- Add a smoke test or build-time check that the sentinel file is present in the bundle output — silent absence is the failure mode we're protecting against.
- Source: `batty-getting-started.md` §4 step 4 ("Copy Ghostty's resource tree into your app bundle").
