# 0699 — No keyboard shortcut jumps to the Pane of the latest unread Bell Feed entry

## Description

Getting to the Pane that just rang takes three steps: open the Bell Feed (`Cmd-Shift-B`), find the row, and click it. Add one rebindable shortcut, **Jump to Latest Unread Bell**, default **`Cmd-Option-J`**. It goes straight to the Pane of the newest unread Bell Feed entry in any Window. It brings that Window forward and selects the entry's Session, Pane and Tab, exactly as clicking the row does. Pressing it again goes to the next-newest unread entry. With nothing unread it beeps and does nothing else.

**Relation:** #0704 (`batty bell jump`, 1.5.0) runs the same "jump to newest unread" action. Whichever lands first adds `BellFeedStore.latestUnreadEntry` and `AppStateStore.jumpToLatestUnreadBell()`, and the other reuses them unchanged.

## Current state (checked against `main` at `77eaadcc`)

- **No existing command does this.** Bell commands today are Toggle Bell Feed (`ShortcutAction.toggleBellFeed`, `BattyKit/Sources/BattyKit/Shortcuts/ShortcutAction.swift:45, 85, 159`), plus Mark All Bells Read and Clear Read Bells. The last two appear only in the menu (`BattyKit/Sources/BattyKit/Commands/BattyCommands.swift:329-342`) and the Command Palette (`BattyKit/Sources/BattyKit/Views/CommandPaletteView.swift:111-121`), with no shortcut. The only routes to an entry's Pane are a feed row click and a notification tap.
- **How a row click navigates.** `BellFeedView.handleJump` (`BattyKit/Sources/BattyKit/Views/BellFeedView.swift:158-161`) calls `store.markBellSeen(id:)` and then `onJump`. `onJump` closes the popover and calls `AppStateStore.jumpToBellEntry` (`BattyKit/Sources/BattyKit/Views/SessionDetailView.swift:432-436`). A notification tap does the same (`BattyKit/Sources/BattyKit/Runtime/AppStateStore+Reminders.swift:258-261`).
  - `AppStateStore.jumpToBellEntry` (`BattyKit/Sources/BattyKit/Runtime/AppStateStore.swift:2606-2626`) resolves the owning Window by `entry.windowID`. If that Window is gone, or the entry is a system entry (`BellFeedEntry.systemID`), it marks the entry seen and stops. Otherwise it calls `makeKeyAndOrderFront` on that Window's `NSWindow`. That call changes the responder, which is legal only from an event-origin path, and a shortcut is one. Then it calls `WindowRuntime.jumpToBellEntry`.
  - `WindowRuntime.jumpToBellEntry` (`BattyKit/Sources/BattyKit/Runtime/WindowRuntime.swift:1308-1323`) checks that the Session, Pane and Tab still exist. It un-hides a hidden Pane (#0256), sets `focusedPaneID`, `activeTabID` and `selectedSessionID`, then calls `visitFocusedTab()`.
  - `visitFocusedTab()` (`WindowRuntime.swift:1344-1350`) marks the Tab's rows seen through `markActiveTabSeen()` and then **removes every Feed row for that Tab** (`bellFeed.removeEntries(matchingTabIDs:)`, #0556). A jump therefore takes every row for that Tab out of the Feed, not just the one that was clicked.
- **What "latest" means in the model.** `BellFeedStore.entries` (`BattyKit/Sources/BattyKit/Runtime/BellFeedStore.swift`) is kept newest-first. `record` inserts at index 0, `recordOrCollapse` moves a collapsed repeat to index 0 with its `timestamp` refreshed, and `init` sorts by `timestamp` in descending order. So "latest unread" is `entries.first { !$0.seen && $0.windowID != BellFeedEntry.systemID }`.
  - Entries that are already read stay in the Feed until Clear Read. They are recorded `seen: true` when the bell rang in the focused Tab (`AppStateStore.swift:2381, 2409, 2465`), or marked seen by a passive focus move. Skipping them fits the Bell Feed declutter goal, where the Feed is "things the user missed".
  - Bells from muted Sessions, and bells `BellNotifier.evaluateShouldPost` declines, never enter the Feed (`AppStateStore.swift:3074-3078`), so they need no filter here.
  - The system entry (the memory-footprint warning, `systemID`) has no Pane to jump to and must be skipped, not consumed.
- **How shortcuts dispatch.** `BattyShortcuts.handle` (`BattyKit/Sources/BattyKit/Commands/BattyShortcuts.swift:34-44`) runs only while a Batty content Window is key. It matches the event against every `ShortcutAction` binding and calls `run(_:appStore:)`. The Command Palette lists every catalog action except `commandPalette` (`CommandPaletteView.swift:71`) and runs each through its own `switch` (`CommandPaletteView.swift:363`). Settings → Shortcuts lists the whole catalog. A new case therefore appears in all three once it is added and handled in both switches.

## Expected behavior

1. With a Batty content Window key, pressing `Cmd-Option-J` (or choosing the menu item or the Command Palette entry) finds the newest Bell Feed entry that is unread and is not a system entry, in any Window. It then does exactly what clicking that row does: `markBellSeen(id:)`, then `AppStateStore.jumpToBellEntry`. That brings the owning Window forward, selects the Session, un-hides the Pane if it is hidden, focuses the Pane, selects the Tab, and visits it. The visit removes that Tab's rows from the Feed.
2. **Repeated presses walk the unread entries, newest to oldest.** Nothing needs to remember a cursor: the visit removes the Tab's rows, so the next press picks the next-newest unread entry, which is always in a different Tab. The implementation must not keep a separate cursor.
3. **Unresolvable entries are skipped in the same press.** If the newest unread entry's Window has closed, or its Session, Pane or Tab is gone, mark that entry seen (as `jumpToBellEntry` already does on a closed Window) and try the next one. A single press then lands on a live Pane whenever one exists, instead of quietly using up a press on a dead entry. Never loop more than `entries.count` times.
4. **Nothing unread: `NSSound.beep()` and nothing else.** No popover, no focus change, no state write. A beep is the standard macOS "no next item" signal and confirms that the key was received. The menu item is disabled when `bellFeed.unseenCount == 0`, the same as Mark All Bells Read. The shortcut still reaches the handler through the event monitor and beeps.
5. If the Bell Feed popover is open in the Window that becomes key, it closes, the same as after a row click.
6. Jumping is not reading. Other unread entries keep their unread state and counts. Only the visited Tab's rows change, through the existing `visitFocusedTab()` path.

## Implementation notes

- Add `case jumpToLatestBell` to the end of `ShortcutAction`, which is append-only (rawValue `jumpToLatestBell`). Give it a `displayName` of "Jump to Latest Unread Bell" and a `defaultBinding` of `j` with `[.command, .option]`.
- Put the logic on `AppStateStore`, for example `@discardableResult public func jumpToLatestUnreadBell() -> Bool`. It returns `false` when there was nothing to jump to, and the caller beeps. Keep the beep in the dispatch layer (`BattyShortcuts.run`, the menu action, the palette action) so the store stays testable without sound. Separately, expose a pure lookup `BellFeedStore.latestUnreadEntry` (newest unread, not `systemID`), so the selection rule can be unit-tested on its own.
- Handle the case in `BattyShortcuts.run` (`BattyShortcuts.swift`, beside `.toggleBellFeed` at line 184) and in `CommandPaletteView`'s `switch`. The palette path has to run after the palette dismisses (`runAfterDismiss`), the same as other navigation actions.
- Docs that the sync tests enforce: add the row to `docs/shortcuts.md` §2 (and update its case count), and add it to the Help catalog `BattyKit/Sources/BattyKit/Help/05-shortcuts.md`. `ShortcutDocsSyncTests.helpCatalogListsEveryShortcutAction` and `docsCatalogListsEveryShortcutAction` fail until both are updated. Optionally add it to the §1 "frequently used" table.
- Read `docs/swiftui-observation-rules.md` before writing this. Every write happens on the event path (key event, menu click, palette selection), so no `Task` hop is needed or allowed.

## Acceptance criteria

- [ ] `ShortcutAction.jumpToLatestBell` exists with default `Cmd-Option-J`, and no other default collides with it.
- [ ] With unread entries in two Windows, the shortcut brings the Window holding the newest unread entry forward and focuses that entry's Session, Pane and Tab. It works the same from either Window.
- [ ] Repeated presses visit unread entries newest to oldest, one Tab per press, until none remain. Then the next press beeps and changes nothing.
- [ ] Read entries, the system footprint entry, and entries whose Window or Tab is gone are never jump targets. Dead entries are marked seen and skipped within the same press.
- [ ] An entry whose Pane is hidden: the jump un-hides it (same as a row click, #0256).
- [ ] The menu item appears under Window after Toggle Bell Feed, shows the current binding, and is disabled when nothing is unread.
- [ ] The action is listed in the Command Palette and Settings → Shortcuts. Rebinding it in Settings changes the menu item, the palette chord and the key that fires.
- [ ] `docs/shortcuts.md` and `Help/05-shortcuts.md` list it, and `ShortcutDocsSyncTests` passes.
- [ ] `./build.sh` and `./build.sh unit` pass. `./build.sh ui-typecheck` passes for the new UI test.
