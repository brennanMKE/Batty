## Description

Phase (a) (#0501) shipped the Shared flag, the checkbox on every picker card and in the editor, the `ProjectSyncRecord` definition / device-state split, the `~`-portable root, the pure last-writer-wins merge and the `ProjectSyncBackend` protocol, with `LocalOnlyProjectSyncBackend` as its only implementation. Production passes no backend (`AppStateStore.projectStore`, `BattyKit/Sources/BattyKit/Runtime/AppStateStore.swift:95-101`), so a Project marked Shared still never leaves the Mac, and `Concepts.md:51` and `docs/design/projects-sharing.md` say so.

This issue is **phase (b)**: the iCloud key-value-storage backend behind that protocol, and the entitlement, provisioning-profile, signing and release-pipeline changes without which the entitlement either does nothing (no profile embedded) or stops the app launching (a restricted entitlement in an unauthorized signature). The user created both Developer ID provisioning profiles on 2026-10-13 (see "Verified facts"), which unblocks the account-side items of #0501 readiness §4.

Ships on `main` for 1.3.0 behind the Projects flag. With the flag off nothing here runs: no backend is built, `NSUbiquitousKeyValueStore` is never touched.

### D1. Mechanism: `NSUbiquitousKeyValueStore`

As #0501 recommended. Batty requests exactly one entitlement, `com.apple.developer.ubiquity-kvstore-identifier` = `$(TeamIdentifierPrefix)$(CFBundleIdentifier)`, which resolves to `XV8BAAVZ6V.co.sstools.Batty` and `XV8BAAVZ6V.co.sstools.Batty.beta`, both inside the profiles' `XV8BAAVZ6V.*`. Prod and Beta therefore have separate stores and Beta testing never touches Prod data. No `icloud-services`, container or CloudKit key is requested, even though the profiles would allow them.

### D2. Profiles in the repo; manual Developer ID signing

- Copy the two profiles to `Configuration/Profiles/Batty.provisionprofile` and `Configuration/Profiles/Batty_Beta.provisionprofile`. They hold no secrets (certificates and entitlements only). Nothing in `.gitignore` excludes `*.provisionprofile`.
- Signing becomes **manual** with the **Developer ID Application** identity for Prod and Beta: `CODE_SIGN_STYLE = Manual`, `CODE_SIGN_IDENTITY = Developer ID Application` (`Build.xcconfig`), the profile selected per variant. Manual signing never contacts Apple; `-allowProvisioningUpdates` stays forbidden (`docs/code-signing.md`, Rules). Every signed Beta build, including `./build.sh`, then signs with Developer ID; the #0265 revocation came from Automatic signing managing certificates, which manual signing does not do.
- **Selection: by specifier, recommended.** `PROVISIONING_PROFILE_SPECIFIER = Batty` (Prod) / `Batty Beta` (Beta), applied to the **app target only**. Because `BattyTests` shares `App.xcconfig`, the variant xcconfigs set a variable (`APP_PROVISIONING_PROFILE_SPECIFIER`, the `APP_PRODUCT_NAME` precedent) and the app target's build settings map it to `PROVISIONING_PROFILE_SPECIFIER`; a test bundle with the app's profile fails to sign. `xcodebuild` finds a specifier only among installed profiles, so an idempotent install step copies the repo copies to the local profiles directory (`~/Library/MobileDevice/Provisioning Profiles/<UUID>.provisionprofile`, or the directory this Xcode uses; the implementer verifies) from `build.sh` and `scripts/release.sh`. Copying a file into that directory is a local operation, not a certificate or profile action in the sense of the signing rules.
- **Fallback: by embedding.** If the specifier route cannot work without provisioning updates, a Copy Files phase places the variant's profile at `Contents/embedded.provisionprofile` and no specifier is set. Decide by building; record the choice in `docs/code-signing.md`.
- With the specifier in place Xcode embeds the profile at `Contents/embedded.provisionprofile` and checks the entitlements file against it.

### D3. Builds without a profile drop the entitlement

A restricted entitlement in a signature with no authorizing profile gets the app killed at launch (AMFI "restricted entitlements"; #0501 readiness §4.6). It must not appear in unsigned or ad-hoc builds, the UI-test VM build, or `./build.sh unit`.

- Two entitlements files: `Batty/Batty.entitlements` gains the kvstore key; a new `Batty/Batty-local.entitlements` holds only the two hardened-runtime keys. `Build.xcconfig` sets `CODE_SIGN_ENTITLEMENTS = $(BATTY_ENTITLEMENTS)` with `BATTY_ENTITLEMENTS = Batty/Batty.entitlements` as the default.
- Builds without a profile override on the command line: `BATTY_ENTITLEMENTS=Batty/Batty-local.entitlements PROVISIONING_PROFILE_SPECIFIER=` in `build.sh unit`, `tools/run-ui-tests-vm.sh` (both `xcodebuild` calls, next to the ad-hoc flags) and `scripts/run-ui-tests.sh`. `scripts/build-beta.sh` needs nothing for its unsigned default (no signature, no entitlements); `--sign` keeps the full file and the Beta profile.
- Runtime: the backend is wired in only when the running binary carries the entitlement (`SecTaskCopyValueForEntitlement` on `SecTaskCreateFromSelf`, wrapped in a small `ProjectSyncEntitlement` helper). Without it `AppStateStore.projectStore` passes **no backend** (`nil`), which is what "fall back to `LocalOnlyProjectSyncBackend`" amounts to: `isAvailable == false`, nothing published, nothing merged, minus a `calls` log that would otherwise grow for the life of the process. `ProjectStore` is unchanged by that choice.
- **D3a, decided 2026-10-13 by the orchestrator (user may overrule): ship the kvstore key only.** Prod has run without `allow-jit` and `allow-dyld-environment-variables` since 1.0, so adding them loosens the hardened runtime for no observed need (`allow-dyld-environment-variables` in particular widens injection). The entitlements file that gets wired holds only `com.apple.developer.ubiquity-kvstore-identifier`; remove the two unused keys from `Batty/Batty.entitlements` (or wire a new file and delete the old one), and correct `docs/code-signing.md`, which wrongly says they are granted.

### D4. `ICloudKeyValueProjectSyncBackend`

`BattyKit/Sources/BattyKit/Model/ICloudKeyValueProjectSyncBackend.swift`, `@MainActor`, conforming to `ProjectSyncBackend`.

- **Store seam.** It takes a `KeyValueStoring` protocol (`dictionaryRepresentation`, `data(forKey:)`, `set(_:forKey:)`, `removeObject(forKey:)`, `synchronize()`) and a change-notification source (a `NotificationCenter` instance, default `.default`). `NSUbiquitousKeyValueStore` conforms in an extension. Unit tests pass a fake and post notifications on their own center; no test reaches iCloud.
- **Keys.** One key per shared Project, `project.<uuid>` (44 bytes, under the 64-byte key limit), value = `ProjectSyncRecord` as compact JSON (no pretty printing; ISO 8601 dates with fractional seconds, matching `projects.json`). A tombstone is the same key holding `{ "deletedAt": "<ISO 8601>" }`. `withdraw` removes the key. `snapshot()` decodes every `project.` key; an undecodable value is logged and skipped, never deleted.
- **Changes.** Observes `NSUbiquitousKeyValueStore.didChangeExternallyNotification`. Reasons `ServerChange` and `InitialSyncChange` yield `changes` (the store then runs the merge); `AccountChange` yields too, after re-reading, since the new account's snapshot is the new truth; `QuotaViolationChange` never yields: it is logged and surfaced through `lastError` (below). Keys outside the `project.` prefix are ignored.
- **The merge-rule-4 hazard** (#0501 Gotchas; `docs/design/projects-sharing.md`, "Backend protocol"): an empty snapshot means "everything withdrawn", so `changes` must never yield before the store has synced. The backend yields only after it has received a `ServerChange`, `InitialSyncChange` or `AccountChange` notification in this process; `init` calls `synchronize()` and sets nothing else. `isAvailable` is `ubiquityIdentityToken != nil` and the entitlement present; the store's `mergeRemote` already ignores an unavailable backend.
- **Limits, enforced before writing.** 1 MB total per app per user, 1,024 keys, 1 MB per value (Apple's iCloud Design Guide; recorded in `docs/design/projects-sharing.md`). `publish` computes the encoded size and the store's current total (sum of all `project.` values plus the new one) and key count; above any limit it **throws** `ProjectSyncError.quotaExceeded(reason:)` and writes nothing. This changes the protocol: `publish(_:) throws`. `ProjectStore.upsert` and `setShared` call `publish` **before** `commit`, so a refused share leaves `isShared` false and the file untouched; the error propagates to the caller. `LocalOnlyProjectSyncBackend` never throws. Nothing is ever dropped silently.
- **Visible error.** `ProjectStore` gains an observable `syncError: String?` set by a failed `publish` or a `QuotaViolationChange` and cleared on the next successful publish. The picker shows it as a caption under the cards (`project-picker.sync-error`) and the checkbox stays unchecked; the editor shows it through `saveError` and Save fails as for `duplicateName`. The `onSetShared` closure in `SessionDetailView` keeps the `do`/`catch` and no longer swallows: the store's `syncError` carries the message.
- **Tombstone pruning.** On every `snapshot()` the backend removes tombstones older than 30 days (store clock injected). Pruning is the only write not caused by a user action, and it only removes keys that no Mac still needs.
- **Wiring.** `AppStateStore.projectStore` builds the backend only when `featureFlags.projects` is on **and** the entitlement is present; otherwise `backend: nil`. No new gate site: amend the #0471 row in `docs/feature-flags.md`.
- The locally suffixed name from merge rule 5 (`Name 2`) is published on the next `upsert` of that Project and then propagates (`docs/design/projects-sharing.md`, "Phase (b) must also"). Decided: that is wanted; the suffix is the resolution of a real collision and the user sees it in the editor.

## Notes

- **Order of work.** Nothing in D4 can be verified end to end until D2/D3 are in, and D2/D3/D5 touch restricted areas. The implementer starts with the user's go-ahead on D2, D3 (including D3a) and D5 in hand; absent that, the backend and its unit tests can land first with the production wiring left reading the entitlement (which is absent until D3 ships), so the branch stays inert.
- **Why the Beta profile is a Developer ID profile.** `./build.sh` signs Beta with Apple Development today (`docs/code-signing.md`, Identities). A Developer ID profile does not authorize that certificate, so under D2 Beta moves to Developer ID too. The alternative, a Mac development profile for Beta regenerated by automatic signing, is exactly the provisioning-update path the signing rules forbid.
- **Why no `icloud-services` key.** `NSUbiquitousKeyValueStore` needs only the kvstore identifier. Requesting `icloud-services` would advertise CloudKit/documents the app does not use, and every extra restricted key is another thing a profile must authorize.
- **KVS semantics the merge already handles.** The server keeps the latest value per key and rejects a write that races a recent remote change, then posts the external-change notification; the app re-reads and the store's merge (last writer wins on `modifiedAt`) decides. A rejected write is therefore not an error to surface, only a reason to merge.
