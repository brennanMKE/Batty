# 0006 — Implement SurfaceRegistry for libghostty surface lifecycle

## Description

Build the `[UUID: ghostty_surface_t]` registry described in `Concepts.md` → Surface registry. This is the single source of truth for live Terminal Sessions. The SwiftUI tree only ever stores `surfaceID: UUID`; SwiftUI rebuilding views must not kill the underlying surface.

**Acceptance criteria:**
- A `SurfaceRegistry` (likely `@MainActor`-isolated) exposes:
  - `create(in: ghostty_app_t, config:) -> UUID`
  - `surface(for id: UUID) -> ghostty_surface_t?`
  - `destroy(_ id: UUID)` — kills PTY, frees Metal resources, removes from map.
- Lifetime is decoupled from any SwiftUI view identity — destroying a `TerminalSurfaceView` (when triggered by `dismantleNSView`) is what triggers `destroy`, not view-tree churn.
- Thread-safety: callbacks from libghostty's IO/render threads marshal to the main actor before mutating the registry.

## Notes

- Use `Unmanaged<T>.passUnretained(self).toOpaque()` for round-tripping Swift objects through C `void*` userdata (PRD §5).
- Watch C-string ownership: some `const char*` returns from libghostty are owned by it and must not be freed by us.
- No views or NSViews in this issue — pure registry plumbing. The NSView consumer comes in #0007.
