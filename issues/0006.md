## Description

Build the `[UUID: ghostty_surface_t]` registry described in `Concepts.md` → Surface registry. This is the single source of truth for live Terminal Sessions. The SwiftUI tree only ever stores `surfaceID: UUID`; SwiftUI rebuilding views must not kill the underlying surface.

**Acceptance criteria:**
- A `SurfaceRegistry` (likely `@MainActor`-isolated) exposes:
  - `create(in: ghostty_app_t, config:) -> UUID`
  - `surface(for id: UUID) -> ghostty_surface_t?`
  - `destroy(_ id: UUID)` — kills PTY, frees Metal resources, removes from map.
- Lifetime is decoupled from any SwiftUI view identity — destroying a `TerminalSurfaceView` (when triggered by `dismantleNSView`) is what triggers `destroy`, not view-tree churn.
- Thread-safety: callbacks from libghostty's IO/render threads marshal to the main actor before mutating the registry.

## Notes

- Use `Unmanaged<T>.passUnretained(self).toOpaque()` for round-tripping Swift objects through C `void*` userdata (PRD §5).
- Watch C-string ownership: some `const char*` returns from libghostty are owned by it and must not be freed by us.
- No views or NSViews in this issue — pure registry plumbing. The NSView consumer comes in #0007.

## Root cause

Concepts → Surface registry calls for a process-wide `[UUID: ghostty_surface_t]` map so the SwiftUI tree can store stable `surfaceID: UUID` values while libghostty handles live elsewhere. Without it, every `TerminalSurfaceView` rebuild would risk killing the underlying terminal.

## Fix

Added `BattyKit/Sources/BattyKit/SurfaceRegistry.swift`:

- Final class, implicitly `MainActor`-isolated under BattyKit's `defaultIsolation(MainActor.self)` setting.
- `register(_:) -> UUID` — assigns a fresh UUID, stores the handle, returns the id.
- `surface(for: UUID) -> ghostty_surface_t?` — lookup; nil for unknown ids.
- `unregister(_: UUID) -> ghostty_surface_t?` — removes from the map and returns the handle so the caller can `ghostty_surface_free` it.
- `contains(_:)`, `count`, `ids` — convenience accessors.

Tests in `BattyKit/Tests/BattyKitTests/SurfaceRegistryTests.swift` cover register / lookup / unregister / contains / ids / count plus retention across unrelated removals. 8 tests, all passing alongside the existing 31 (39 total).

The registry deliberately **does not** call `ghostty_surface_new` or `ghostty_surface_free` itself. Surface creation requires an `ghostty_app_t` plus a `ghostty_surface_config_s` that needs Metal layer pointers and per-surface event callbacks — too coupled for the registry to own. The "create a surface in this view" entrypoint lives in #0007 where there's an NSView with a Metal layer to bind to.

## Gotchas

- **`ghostty_surface_t` imports as `UnsafeMutableRawPointer`, not `OpaquePointer`.** The C typedef is `typedef void* ghostty_surface_t`, but Swift's importer chose `UnsafeMutableRawPointer` for this version of libghostty-spm (1.0.1777879537). Test helpers fabricating fake handles must use `UnsafeMutableRawPointer(bitPattern:)`, not `OpaquePointer(bitPattern:)`. If the typedef changes upstream, the registry's stored type is `ghostty_surface_t` directly so it'll track automatically; only the test fakes need updating.
- **Sendable.** `UnsafeMutableRawPointer` is not `Sendable`. The registry is `@MainActor`-isolated by default (BattyKit's `defaultIsolation(MainActor.self)`), so all access happens on one actor and we never need to `Sendable`-cross. Do not add `Sendable` conformance to the registry — it would require unsafe escape hatches and lose the protection.
- **Register, then store the id.** Callers should hold the returned `UUID` in their model (e.g. `Tab.surfaceID`). Don't try to look up surfaces by reverse-mapping the pointer; that's not supported and the pointer can't be a stable identity (libghostty may move surfaces in some configurations).
- **Lifecycle responsibility.** When a Tab closes, the caller must `unregister(id)` and then call `ghostty_surface_free(handle)`. Forgetting either leaks libghostty resources or leaves a dangling registry entry.
