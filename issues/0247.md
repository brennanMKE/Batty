# 0247 — Support an opt-in .batty/config (TOML) for per-project session name and settings

| | |
|---|---|
| **Status** | open |
| **Module** | Session / Settings |
| **Platform** | macOS |
| **First seen** | 2026-06-17 |

## Description

Add support for a project-local `.batty/config` file (TOML) that can declare a session name and, in time, other per-project settings. It is a fourth naming signal alongside the file-derivation, Foundation Models, and manual-rename paths — but the strongest one, because it is explicit, deterministic, and committable so a team shares it. **Off by default**: Batty does not read `.batty/config` until the user enables it in Settings, and Batty never writes the file into a project folder unless the user explicitly asks — a project folder stays free of Batty files until the user opts in.

## Long Description

### What it is

A `.batty/config` file at a project's working directory, in TOML, that Batty reads to resolve that session's name (and later other per-project settings). The first and only v1 field:

```toml
title = "Payments API"
```

`.batty/config` (a `config` file inside a `.batty/` directory, mirroring `.git/config`) leaves room for the directory to grow later (themes, layouts, default splits) while keeping a single entry at the project root. A flat `.batty.toml` is the lighter alternative; pick one in the design and state why.

### Off by default — two distinct gates

1. **Reading is opt-in.** A new Settings toggle (e.g. "Read `.batty/config` from project folders"), default **off**, in the existing "Session Naming" section (#0233). When off, the naming chain behaves exactly as today and the file is never opened. When on, the chain consults it.
2. **Batty never dirties the folder.** Batty must not auto-create `.batty/` or `.batty/config` on `cd`, on rename, or on enabling the toggle. The file exists only if the user (or a future explicit "Save settings to project" command — out of scope here) creates it. Reading a file that the user placed is the whole v1 feature.

### Precedence

Insert `.batty/config` into the auto-naming chain in `AppStateStore.resolveAutoTitle` above the derived/AI signals but below the user's own explicit rename:

1. User manual rename (`SessionNameCache`) — explicit *local* intent, always wins.
2. **`.batty/config` `title`** — explicit *repo-author* intent.
3. `ProjectNameResolver` (derived from `Package.swift`, `package.json`, etc.).
4. Foundation Models AI fallback (#0231/#0232).
5. "Session N" default.

Decide #1 vs #2 deliberately and document it: the user's manual rename stays on top (their machine, their most recent explicit choice), and a `.batty/config` name does not overwrite a cached user rename.

Interaction with the #0233 toggles: a `.batty/config` `title` is authored config, not "automatic" derivation, so it should apply independent of the `autoNameFromFiles` / `autoNameWithAI` toggles — gated only by its own read-config toggle. A user who turned off automatic naming still gets a name a repo explicitly declares. State this in the design.

### Security — declarative and non-executable only

`.batty/config` is read from a directory the user may have cloned from anywhere, so it is untrusted input:

- **v1 is name-only / strictly declarative.** No field may set the shell, inject env vars, run startup commands, or otherwise execute anything. The worst a malicious repo can do is propose a label. If executable behavior is ever wanted, it must come with a direnv-style per-repo trust prompt — a separate, later issue, not this one.
- **Sanitize the `title` value through `SessionNameSuggestion.sanitize`** — the same path the AI suggestion uses (control-character stripping, length cap, word/character rules). Never trust the raw bytes. A value that fails sanitization is treated as absent (fall through to the next signal), not surfaced.
- Read a bounded prefix of the file; ignore unknown keys forward-compatibly.

### Implementation notes

- TOML has no Swift standard-library parser. Two options: (a) a minimal hand-rolled parser for the tiny surface (`key = "value"` lines, comments, whitespace) which keeps BattyKit dependency-free; (b) add a TOML SPM dependency (e.g. TOMLKit / TOMLDecoder) to `BattyKit/Package.swift`. Given v1 is a handful of string keys, lean toward (a) and revisit if the schema grows. Adding an SPM dependency to the package is allowed but flag it in review; `Configuration/Build.xcconfig` stays untouched.
- The `.batty/config` value is ephemeral-by-the-same-logic as derived/AI names: it is not written into `SessionNameCache` and does not set `titleOverride`. Re-reading the file on the next cwd resolution keeps it live; a user rename still pins over it.
- Watch file existence at resolve time (on the cwd-change path), not via a persistent file watcher in v1 — re-read on each working-directory change, consistent with how the rest of the chain resolves.

## Steps to reproduce

1. Add `.batty/config` with `title = "Payments API"` to a project folder.
2. `cd` into it in a Batty session.
3. Observe the session title with the feature both off (default) and on (Settings).

## Expected behavior

With the toggle off (default), `.batty/config` is ignored and naming is unchanged; no `.batty` files are ever created by Batty. With the toggle on, a session entering a folder that contains `.batty/config` takes its declared `title` (sanitized), overriding the file-derived and AI names but not a manual rename.

## Actual behavior

No project-local config is supported; per-project naming relies entirely on derived names, the AI fallback, or a manual rename, and nothing is shareable through the repo.

## Notes

Key code locations:

- `BattyKit/Sources/BattyKit/Runtime/AppStateStore.swift` — `resolveAutoTitle` (insert the `.batty/config` step) and `handleWorkingDirectoryChange` (resolve the read-config toggle and pass it in).
- `BattyKit/Sources/BattyKit/ProjectName/` — natural home for a `BattyProjectConfig` parser/loader next to `ProjectNameResolver`.
- `BattyKit/Sources/BattyKit/ProjectName/SessionNameSuggester.swift` — `SessionNameSuggestion.sanitize`, reused for the `title` value.
- `BattyKit/Sources/BattyKit/Settings/SettingsPreferences.swift` — new `co.sstools.Batty.readProjectConfig` key/default/resolved accessor (default `false`), following the #0233 pattern.
- `BattyKit/Sources/BattyKit/Views/SettingsView.swift` — add the toggle to the "Session Naming" section from #0233.
- `BattyKit/Package.swift` — only if a TOML dependency is chosen over a hand-rolled parser.

Testing: unit tests for the parser (valid `title`, comments/whitespace, missing file, malformed TOML, unknown keys ignored), sanitization of a hostile `title`, precedence (config beats derived/AI, loses to manual rename), and the off-by-default gate (no read, no file creation). The live behavior is unit-testable end to end since no model call is involved.
