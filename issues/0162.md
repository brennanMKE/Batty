# 0162 — UI test suite: layout picker (presets, CWD inheritance, gating)

| | |
|---|---|
| **Status** | open |
| **Module** | Tests / Layout / Session |
| **Platform** | macOS |
| **First seen** | 2026-05-20 |

## Description

The layout picker ([[0136]]) creates multi-pane sessions in one shot. Each subsequent change has shipped a bug — [[0148]] (panes created at home directory instead of cwd), [[0152]] (picker should be disabled for multi-pane sessions). The picker is invoked frequently and its bugs corrupt the user's working state directly (lost cwd, lost panes). This suite asserts that each preset produces the right tree, inherits the right cwd, and is gated correctly.

## Regressions this suite would have caught

- [[0148]] — Layout picker created panes at `$HOME` instead of the focused pane's cwd. A test using the [[0058]] resolver-style assertion (sentinel-file `pwd`) on each newly created pane would have caught it.
- [[0152]] — Picker should be disabled for multi-pane sessions and surfaced in the Session menu. A test asserting the picker accessibility identifier's `isEnabled` flips with pane count would have caught it.
- [[0136]] — Initial picker wiring. The "applies the chosen layout" assertions are the regression baseline.

## Test cases

All tests use [[0158]] driver intents.

### Layout structure — would catch [[0136]] regressions

- **Each preset produces the expected pane count.** Run `applyLayout(layout: X)` for each known layout (`twoByTwoGrid`, `mainLeftTwoRight`, `mainTopTwoBottom`, `threeColumn`, `twoColumn`, `twoRow`, etc.). Assert `pane-terminal.<id>` count matches the documented shape per preset.
- **Each preset produces the expected split structure.** Use a new `dumpSplitTree` driver intent that writes the tree shape (as a string like `H(V(L,L),L)`) to a sentinel file. Assert it matches the preset's spec.

### CWD inheritance — would catch [[0148]]

- **All panes inherit focused pane's cwd at picker time.** Driver: focus a pane, `cd /tmp/picker-test` in its terminal, wait for prompt, apply layout, then in each new pane send `pwd > /tmp/sentinel-N` and assert all sentinels contain `/tmp/picker-test`. This is the regression test for [[0148]].

### Gating — would catch [[0152]]

- **Picker is enabled for single-pane sessions.** Fresh session. Assert layout-picker accessibility element's `isEnabled == true`.
- **Picker is disabled when the session has > 1 pane.** Apply layout, assert `isEnabled == false`. (Or, if the picker is hidden rather than disabled, assert it's no longer present.)
- **Picker is exposed in the Session menu (not just toolbar).** Assert the menu item with identifier `menu.session.layout-picker` exists.

### Focus after layout — covers an unstated but obvious requirement

- **After applying a layout, focus lands somewhere reasonable.** Assert exactly one pane has `accessibilityValue == "focused"`.

## Accessibility identifiers needed

- `layout-picker.button` on the toolbar button.
- `layout-picker.row.<layoutName>` on each row in the picker popover.
- `menu.session.layout-picker` on the Session menu item.

## Driver intents needed (from [[0158]])

- `applyLayout(layout:)` — already in the foundation vocabulary.
- `openLayoutPicker` — opens the popover so a test can assert against its rows.
- `dumpSplitTree(toPath:)` — writes the tree shape as a string for structural assertions.

## Out of scope

- The visual preview shown in each picker row (covered by manual review per [[0151]]'s SF Symbols pass).
- Custom user-defined layouts (not yet a feature).

## Acceptance criteria

- All test cases pass under `xcodebuild -scheme 'Batty (Beta)' -destination 'platform=macOS' test`.
- Every preset listed in the codebase has at least one structure test.
- The cwd-inheritance test runs against at least two distinct presets (a horizontal-heavy one and a vertical-heavy one) to catch tree-walk bugs that only fire on one orientation.

## Notes

- Depends on [[0158]].
- `dumpSplitTree` is a diagnostic-only driver intent. Keep its output format stable (a simple S-expression-ish string is fine); changing it would force test churn.
