## Description

Write the **Overview** section of Batty's user Help, bundled as `Batty/Help/01-overview.md`. This is the first section users see when they open Help and should give them a working mental model of the app in ~300 words.

Depends on `#0080` (Help window bootstrap).

## What `01-overview.md` covers

- What Batty is: a native macOS terminal multiplexer built on libghostty.
- The single-window default: Batty opens one window. Multi-window support is not part of v1.
- The four-level hierarchy a user navigates:
  1. **Sessions** — appear in the sidebar. Each is a separate workspace with its own panes and tabs.
  2. **Panes** — splits within a session. `Cmd-D` / `Cmd-Shift-D` to create.
  3. **Tabs** — strips of terminals within a pane. `Cmd-T` to create.
  4. **Terminals** — the actual shell prompt you type into.
- Brief tour of the main UI surfaces:
  - **Sidebar** — session list. `+` button at the bottom to add a new session. Right-click for Rename / Duplicate / Mute / Close.
  - **Tab bar** — at the top of each pane. Drag to reorder, `×` to close, right-click for Rename / Duplicate / Close.
  - **Bell feed** — `Cmd-Shift-N` or the bell button in the toolbar. Shows recent `\a` bells across all tabs.
  - **Settings** — `Cmd-,`. Shell, font, cursor, paste confirmation, theme picker, keyboard shortcuts (per `#0070`).
- Pointer to the other Help sections for deeper coverage.
- A short "Try this" block: open Batty, type something, `Cmd-D` to split, `Cmd-T` for a tab, sidebar `+` for a new session. Five seconds of doing, and the user gets the structure.

## Tone

- User-facing. Second person ("you"). No code paths, no source-file paths, no issue numbers.
- Concise. ~300 words target.
- Concrete. Reference real shortcuts and UI elements, not abstractions like "the input controller."

## Acceptance criteria

- `Batty/Help/01-overview.md` replaces the stub from `#0080`.
- Rendered in the Help window, the overview fits on one scroll-free screen at default font size.
- A user who has never seen Batty before can read the overview and immediately try the suggested actions.
- Cross-references to other Help sections use markdown links (`[Sessions](02-sessions.md)`, etc.) — the `StructuredText` renderer handles them via the `baseURL` set in `HelpSuccessPaneView`.

## Out of scope

- Installation / Build instructions (this is a Help system for users, not contributors).
- Multi-window support — single-window is the v1 design.
