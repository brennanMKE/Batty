## Description

Commit `ed1c261a` ("Add the San Francisco, Circuit Boards and World Cities background sets") appended three sets after Deep Space in the shipped `website/backgrounds/catalog.json`. The catalog now has 7 sets of 8 images each (56 images), in this order: Future Cities, Cool Vehicles, Beautiful Landscapes, Deep Space, San Francisco, Circuit Boards, World Cities. Deep Space is no longer last, and Distant Galaxy (`deep-space/08-distant-galaxy.png`) is no longer the last image.

Five UI tests in `BattyUITests/BackgroundSetsTests.swift` load the shipped catalog through `BackgroundCatalogFixture.writeShipped`. They scroll Background Sets to the bottom and assume the last row there is Deep Space's, with Distant Galaxy in it. They guard #0624 (selecting an image in the bottom rows made the grid jump), so their point is the *last* rows of the grid. With three sets now below Deep Space, they will either fail or stop testing the bottom of the grid.

**This failure is predicted from the code, not observed.** The daily VM UI run has not yet run against the 7-set catalog.

### Current state (checked against `main` at `ed1c261a`)

- **The fixture copies the shipped catalog as is.** `BackgroundCatalogFixture.writeShipped(in:)` (`BattyUITests/Support/BackgroundCatalogFixture.swift:45-63`) reads `website/backgrounds/catalog.json` from the repo and writes it, with a 480 x 300 placeholder thumbnail per image, so the tests see every set the website ships, in the website's order.
- **The shared helper hard-codes Deep Space and Distant Galaxy as the bottom.** `openShippedAtTheBottom` (`BattyUITests/BackgroundSetsTests.swift:400-452`, declared at `:402`):
  - Doc comment, `:393-394`: "Background Sets scrolled to the bottom so Deep Space's heading is above the view."
  - `:423` `let deepSpace = element("background-sets.set.Deep Space", in: app)` and `:424` `let galaxy = cell("08-distant-galaxy", in: app)`.
  - `:438-442` scroll by `-240` until `galaxy.exists && galaxy.isHittable`, then `for _ in 0..<5 { root.scroll(byDeltaX: 0, deltaY: -240) }`. Those five extra scrolls (about 1,200 pt) were meant to settle at the end of the grid. When Deep Space was last they did nothing past the end. Now three more sets (24 images, three headings; cells are at least 170 pt wide, `BattyKit/Sources/BattyKit/Views/BackgroundSetsView.swift:33`, `:158`) lie below Distant Galaxy, so the extra scrolls carry it off the top of the view.
  - `:449` `XCTAssertTrue(galaxy.exists && galaxy.isHittable, "Distant Galaxy never came on screen")`. This is where every test below is predicted to fail.
- **`assertBottomStill`** (`:474-492`) measures Distant Galaxy (`bottom.galaxy`), its row neighbours `05-engine-trail`, `06-ring-station`, `07-fleet-dust-lane` (`:473`), and the Deep Space heading. It asserts `XCTAssertLessThan(headerBefore.minY, bottom.root.frame.minY, "Deep Space's heading is still in view, so this isn't the reported layout")` (`:480`). If the scroll ever left Distant Galaxy on screen, the test would measure a mid-grid row, not the bottom one #0624 reported, and could pass without covering the bug.
- **`holdDeepSpace` / `releaseDeepSpace`** (`:456-466`) write `.hold` files under `deep-space/` to keep a click's download in flight. They depend on which set is clicked, not on the set being last.

## Expected behavior

The bottom-of-grid tests keep testing the actual last rows of Background Sets, whatever sets the website ships and in whatever order. Adding, removing or reordering a set in `website/backgrounds/catalog.json` must not break them or quietly turn them into mid-grid tests.

Possible approaches, for the plan to choose between:

- Find the last set and its last image (and that image's row neighbours) from the catalog `writeShipped` copies, and derive the element identifiers, the `.hold` paths and the seeded "uneven above" and "in view" paths from it. `writeShipped` could return the parsed sets for this.
- Or pin the catalog these tests use, e.g. a committed copy in the test bundle, or a `writeShipped` variant that writes the shipped sets up to and including Deep Space, so the layout #0624 was reported against stays fixed. This loses coverage of the real catalog's size.

## Acceptance criteria

- None of the five tests above names "Deep Space", "Distant Galaxy" or the `deep-space/` stems as the bottom of the grid, unless it pins a catalog in which that is the last set.
- `openShippedAtTheBottom` still checks that the last set's heading is above the view (the "reported layout" guard at `:480`), and that the last image is on screen and hittable after the scroll.
- Doc comments and test names describe what is tested ("the last image") without naming a specific shipped set as last.
- `./build.sh ui-typecheck` passes, and the five tests pass in the VM: `./build.sh ui` filtered to each of `BattyUITests/BackgroundSetsTests/<test>` above (`tools/run-ui-tests-vm.sh`).

## Root cause

`openShippedAtTheBottom` and `assertBottomStill` hard-coded Deep Space / Distant Galaxy (and its `deep-space/05…07` neighbours) as the bottom of the shipped catalog, and settled at the end of the grid with five unconditional extra `-240` scrolls. Since `ed1c261a` three sets follow Deep Space, so those scrolls would carry Distant Galaxy off screen (predicted failure at "Distant Galaxy never came on screen"). The failure was predicted from code, not observed before the fix.

## Fix

As planned: `BackgroundCatalogFixture.writeShipped(in:)` now returns `[ShippedSet]` (name + full paths) and gains `stem(ofFullPath:)`. `openShippedAtTheBottom(seed:environment:checkInFlight:)` derives the last set, last image, its up-to-three preceding neighbours, the first set's heading (catalog-loaded wait) and the seeded paths (`.unevenAbove`: images 1, 2, 5 of up to three sets above the last; `.neighboursInView`) from the catalog. Scrolling is phase A (until the last cell is hittable, 120-step guard) then phase B (scroll until the last cell's settled `minY` stops changing, 10-step guard, asserted). It also asserts the last set's heading is above the view. Hold helpers are `holdShipped`/`releaseShipped` keyed on full paths. `assertBottomStill` keeps only neighbours on the last cell's row. Test 2's second click goes to the first on-screen neighbour. No deviations from the plan.

Round 2: moved `writeShipped(in:)`'s doc comment back directly above it (it had ended up on `ShippedSet`) and added "Returns the sets in catalog order." Comment-only; no code changed.
