# 0518 — The VM UI-test runner's 40-minute guest bound is shorter than the full `BattyUITests` suite, so an unfiltered run is cut off before it finishes

| | |
|---|---|
| **Status** | open |
| **Module** | Testing / Docs |
| **Platform** | macOS |
| **First seen** | 2026-10-16 |

## Description

`tools/run-ui-tests-vm.sh` wraps the guest's `xcodebuild ... test-without-building` in `$GUEST_TMO $TEST_GUEST_SECS` (the `perl alarm` bound defined as `GUEST_TMO` at line 480). Outside demo mode the bounds are:

```
TEST_GUEST_SECS=2400   # line 119, 40 min
TEST_HOST_SECS=2700    # line 120, 45 min
```

(Demo mode, `BATTY_UI_DEMO=1`, raises them to 4500 / 4800.)

The full suite now takes about 51 minutes, so an unfiltered `./build.sh ui` / `tools/run-ui-tests-vm.sh` cannot complete.

Evidence from the #0240 multi-window regression pass (artifacts under the `Batty-0240` worktree's `build/ui-tests/`):

- **Run `20261016-181007-64163` (unfiltered).** `All tests` started at 01:12:15. The last suite to pass was `TabRenameTests` at 01:52:02. `xcodebuild.log` stops mid-`TerminalPersistenceTests` at 01:52:06, about 39.9 min in, with no `Executed N tests` summary and no `TEST EXECUTE` line. 193 test cases had started, out of about 209 `func test` methods in `BattyUITests/`.
- **Run `20261016-185336-94049` (the remainder, filtered).** `MultiWindowCLITests`, `TerminalPersistenceTests`, `ThemeTests`, `ViewGalleryTests`, `WindowRegistrationRaceTests` and `WindowRestorationTests` ran 20 tests in 609 s. `ViewGalleryTests` alone took about 498 s for 8 tests, 44–89 s each (`testGitStatusMergeConflict` 88.9 s, `testGitStatusNotARepository` 44.0 s).

Together that is about 40 + 10 = 50–51 minutes, which is more than the 40-minute guest bound. The host bound (45 min) would also be exceeded.

The documented figure is stale as well. `AGENTS.md` line 86 says "60+ tests, ~10 min", and `issues/Issues.md` line 282 says "~10 min". `docs/ui-testing-vm.md` line 368 records a 617.5 s test phase as matching that estimate. The suite has grown to about 209 tests.

## Steps to reproduce

Only inside the Tart VM, never on a host Mac (AGENTS.md, #0409).

1. On `main`, run `tools/run-ui-tests-vm.sh` with no filter.
2. Look at `build/ui-tests/<run-id>/xcodebuild.log`.

## Expected behavior

An unfiltered run executes every test and ends with an `Executed N tests` summary and `TEST EXECUTE SUCCEEDED` / `FAILED`. The bound only catches a genuine hang.

## Actual behavior

The guest `perl alarm` kills `xcodebuild` at 2400 s. The run ends mid-suite, and the suites after roughly `TabRenameTests` (alphabetically) never run.

## Notes

Options, for the implementer to choose from (not conclusions):

- **Raise the bounds.** Raise `TEST_GUEST_SECS` / `TEST_HOST_SECS` with real headroom over the current ~51 min (e.g. 90 / 95 min), and keep host > guest so the guest bound fires first. Add a comment explaining how the numbers were derived, so the next person knows to re-check them as the suite grows.
- **Split the suite.** Split it across sequential runs (e.g. alphabetical halves, or `ViewGalleryTests` on its own), each under the bound. The runner already takes `-only-testing` filters. Only one VM may run at a time (AGENTS.md), so the shards run one after another.
- **Make `ViewGalleryTests` cheaper.** It dominates the tail at about 8 minutes for 8 tests. Find out where its 45–90 s per test goes (fixture setup, launch, screenshot settling) before deciding whether it belongs in the default unfiltered run.

Whatever is chosen, update `AGENTS.md` ("60+ tests, ~10 min"), `issues/Issues.md` ("~10 min") and the `docs/ui-testing-vm.md` timing note with the measured count and wall clock.

## Acceptance criterion

An unfiltered `tools/run-ui-tests-vm.sh` on `main` runs every `BattyUITests` test to a final `Executed N tests` summary, or the documented sharded invocation covers the whole suite. `AGENTS.md`, `issues/Issues.md` and `docs/ui-testing-vm.md` state the current test count and duration.
