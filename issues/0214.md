# 0214 — Unify create-time and live-update auto-naming against resolveAutoTitle

| | |
|---|---|
| **Status** | open |
| **Module** | Session |
| **Platform** | macOS |
| **First seen** | 2026-05-25 |

## Description

After [[0213]]'s live-update naming work, `AppStateStore` has two auto-naming chains that don't quite agree:

- **Live-update path** (`handleWorkingDirectoryChange`) now goes through a pure helper `resolveAutoTitle(forCWD:sessionIndex:cache:resolver:)` that returns `cache-hit > project-name > Session N`.
- **Create-time path** (`addSession`) still uses its own chain: `title ?? cachedName ?? Session N` — with **no project-name step**.

Today this only "works" because the shell emits an OSC CWD update right after the surface spawns, which triggers the live-update path and lands the project name. It's a hidden race: if for any reason the post-spawn CWD signal is delayed or dropped, the session keeps its `Session N` default until the user `cd`s.

## Expected behavior

`addSession` should call `resolveAutoTitle` (or the same underlying chain) at create time, so a session spawned in a project directory gets the project name eagerly rather than depending on a post-spawn OSC race.
