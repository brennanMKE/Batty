## Description

#0675 took the worst offenders off the main actor and replaced `exec sleep 60` fixtures with `ChildLifetime.hold` (a child held by a stdin pipe until the test kills it). Its plan's "Follow-up" section left the shorter cases for this issue. They break two `AGENTS.md` "Asynchronous tests" rules:

- **A test that blocks on a child process must not do it on the main actor.** Each synchronous `waitUntilExit()` in a `@MainActor` suite (BattyKit's default isolation is `MainActor`, so an unannotated suite counts) stalls every other main-actor test in the parallel run. Under host load that queueing is what pushes unrelated `TestBounds.hangGuard` waits past 60 s (#0675, and probably #0678).
- **A test fixture's child lives until the test kills it, not for a wall-clock time.** A `sleep 30` or `sleep 2` child that must still be alive when the test inspects it is a timed assumption that load can break. A `sleep 0.05` child the test waits on to exit by itself is fine: its exit is the event.

## Expected behavior

- No BattyKitTests test calls `waitUntilExit()`, `waitpid`, or `ChildProcessFixture.killAndReap` while on the main actor. Each such test is `nonisolated` (as in `ProcessGitStatusScannerTests`' real-git tests and #0675's `ProcessFollowByNameTests` real-enumerator tests), with main-actor API calls in short `await MainActor.run { … }` blocks, or awaits exit as an event (a `terminationHandler` bridged through `ResumeOnce` with a `TestBounds.hangGuard` guard).
- No fixture child that must be alive at an assertion has a timed lifetime. Each uses `ChildLifetime.holdCommand`/`ChildLifetime.hold(_:)`, or the `TestChildSpawner` equivalent, and ends when the test kills it.
- Children that the test waits on to exit by themselves (`sleep 0.05`) may stay, as long as the wait is off the main actor.
- No sleeps, polling or elapsed-time assertions are added (`AGENTS.md`).
