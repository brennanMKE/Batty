## Description

**Umbrella, 1.5.0.** No code ships on this issue; the work lands in the children below.

On 2026-11-21 a Claude Code session in a Batty Pane (working in the OpenCircuitSF repo) had to run a deploy script whose last step is a `[y/N]` prompt guarding an irreversible database migration. Two attempts failed before it found the right move:

1. Piping `y` into the script. An earlier `ssh` in the script consumed stdin, so the prompt read nothing and the script aborted. Piping was also the wrong instinct: it answers a confirmation meant for the user.
2. Suggesting the user run it with Claude Code's `! <cmd>` prefix. That output is shown in the conversation, but the user can't type into it, so it aborted the same way.

It then ran `batty pane split --vertical --command "zsh -c 'cd <repo> && scripts/deploy.sh; echo exit \$?; exec zsh'"`, told the user what to answer, and the deploy succeeded. The user liked the result and asked for it to work this way for every Batty user.

What let it get there, and what was missing:

- **It only knew Batty existed because of a note in the user's private `~/.claude/CLAUDE.md`.** No `batty-cli` skill was installed and no `batty` MCP server was connected in that session. Most users won't have that note.
- **Nothing named the case.** The guidance it had covers status views, dev servers and notifications, not "a command needs a person to answer it". It worked that out after two failures.
- **The installed CLI was 1.4.2.** `batty capabilities` lists `pane split` in one line without mentioning `--command`; the agent found it only through `pane split --help`. 1.5.0 on `main` already has `pane split --wait` (exit status, the command typed into a shell that stays open), `tab new --cwd`, and an MCP instructions hint "A command in a new Pane: `pane_split` with `command`", so part of what the agent lacked already ships in 1.5.0.
- **After opening the Pane the agent was blind.** It could not see when the script finished or whether it succeeded, and verified production out of band once the user said to close the Pane.

## Decisions (user, 2026-11-21)

- Implement the recommendation for 1.5.0: name the interactive-input case in every place an agent learns about Batty, reach agents whose user never wrote a CLAUDE.md note, and add the MCP tools that let an agent follow a command it handed to the user.
- File it as this umbrella with child issues.

## Acceptance criteria

1. A fresh agent session in a Batty Pane, with no user-written CLAUDE.md note, is told by Batty itself to run commands that need the user's input in a Pane and never to answer a confirmation prompt for the user (#0706, #0708).
2. An agent can open such a Pane in a chosen directory with no shell-quoting workaround, and the Pane stays open with its output after the command exits (#0707, plus the existing `--wait` behaviour).
3. The user is notified when that command exits or needs input, and the agent can learn its exit status even after its own `--wait` call returned (#0709, #0710).
4. The decision on reading Pane output is recorded, and implemented or declined (#0711).
5. Nothing here lets an agent type into a Pane: a `send`/`send-key` verb stays out of scope (see #0711).
