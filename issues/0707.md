## Description

Child of #0705. `batty tab new` takes `--cwd` (#0667, #0668), but `batty pane split` does not: its only directory option, `--path`, is valid only with `--view git-status`. To run a command in a new Pane in a given directory an agent writes `--command "zsh -c 'cd /path && cmd; exec zsh'"`, nesting quotes it can easily get wrong.

## Expected behavior

- `batty pane split --cwd <dir>` for terminal Panes (the default view), resolved to an absolute path, combinable with `--command` and `--wait`. Rejected with `--view` other than terminal (those have `--path`/`--pid`).
- The MCP `pane_split` tool gains `cwd`.
- Without `--cwd`, behaviour is unchanged (inherits as today).

## Acceptance criteria

1. `--cwd` sets the new terminal Pane's working directory, with and without `--command`/`--wait`.
2. A missing directory fails before a Pane is created, with a clear error and the CLI's usual exit code.
3. Unit tests in BattyKitTests cover parsing, the validation matrix against `--view`, and the XPC payload.
4. `docs/batty-cli-design.md`, the skill and the CLI reference page list the flag.

## Relation

- Umbrella #0705. Mirrors `tab new --cwd`; reuse its resolution code.
