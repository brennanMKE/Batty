## Description

**Idea only; not 1.5.0.** User decision F (2026-11-19): "PhotonHTTP may later serve remote interactions with Batty from another Mac via SSH or Tailscale." Today the CLI reaches the app only through the local launchd broker and XPC (`docs/batty-cli-design.md` §1.3), so nothing outside this Mac can drive Batty.

Once #0693 has PhotonHTTP inside Batty, a later release could expose a small authenticated API (for example the `batty capabilities` verbs) on a loopback port, reached from another Mac by an SSH tunnel or `tailscale serve`. Questions for whoever picks this up: authentication (PhotonHTTP's `Auth` has bearer/JWT), which verbs are safe remotely, how it is turned on (Settings only, off by default, per `AGENTS.md` "Top design goal: progressive disclosure"), and whether `batty mcp` on the remote Mac can proxy to it.

No plan until the user schedules it.
