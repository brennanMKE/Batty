## Description

`BattyKitTests` — the unit test suite in the BattyKit Swift package — does not appear in Xcode's Test Navigator under any scheme. Xcode's Test Navigator does not surface SPM package tests when the package is opened as a dependency of a host project; it only works when the package is opened directly via `Package.swift`.

## Root cause

SPM package tests are architecturally invisible to Xcode's Test Navigator when the package is a dependency (not opened directly). `shouldAutocreateTestPlan = "YES"` in a package scheme makes `xcodebuild test` work from the CLI, but the Xcode IDE Test Navigator ignores it. No scheme XML format resolves this limitation for dependency packages.

A secondary blocker: four test files referenced types that don't yet exist. See #0221.

## Fix

Moved all 32 non-placeholder test files from `BattyKit/Tests/BattyKitTests/` to `BattyTests/`. The `BattyTests/` directory uses `PBXFileSystemSynchronizedRootGroup` so files are picked up automatically — no `project.pbxproj` change needed. Tests are now visible in Xcode's Test Navigator under `Batty (Prod)` and `Batty (Beta)`.

`ProjectNameResolverTests.swift` used `Bundle.module` (an SPM synthesized accessor). Replaced with `#filePath`-based navigation pointing to the Fixtures directory that stays in `BattyKit/Tests/BattyKitTests/Fixtures/`.

Updated `scripts/build.sh unit` to run `xcodebuild test -scheme "Batty (Prod)" -only-testing:BattyTests` (skips UI tests).

## Verification

`scripts/build.sh unit` — 246 tests in 35 suites, `** TEST SUCCEEDED **`.

- `BattyTests/*.swift` (32 files) — moved from `BattyKit/Tests/BattyKitTests/`
- `BattyTests/ProjectNameResolverTests.swift` — bundle access changed from `Bundle.module` to `#filePath` navigation
