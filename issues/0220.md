## Description

`BattyKitTests` — the 33-file unit test suite in the BattyKit Swift package — does not appear in Xcode's Test Navigator under any scheme. The `BattyKit` scheme is auto-discovered by `xcodebuild -list`, but running `xcodebuild test -scheme "BattyKit"` fails with "Scheme BattyKit is not currently configured for the test action." No shared `BattyKit.xcscheme` file exists with a `TestAction`.

## Root cause

No `BattyKit.xcscheme` file exists in `BattyKit/.swiftpm/xcode/xcshareddata/xcschemes/`. Xcode auto-generates a stub scheme from the package manifest (visible in `-list` output) but that stub has no `TestAction`. Without an explicit shared scheme file, neither `xcodebuild test` nor Xcode's Test Navigator can run BattyKitTests.

A secondary blocker: four test files (`LayoutModelTests.swift`, `WorkspaceTests.swift`, `WorkspaceStoreTests.swift`, `WorkspaceConversionTests.swift`) reference types that don't yet exist (`Tab`/`Pane`/`Session` as pure value types, `Workspace`, `WorkspaceStore`). These cause compile failures that prevent the entire `BattyKitTests` target from building. See #0221 for the missing model layer.

## Fix

1. Delete the four uncompilable test files (they test the unimplemented workspace model layer tracked in #0221).
2. Create `BattyKit/.swiftpm/xcode/xcshareddata/xcschemes/BattyKit.xcscheme` with a `TestAction` targeting `BattyKitTests`.
3. Update `scripts/build.sh` to run `xcodebuild test -scheme "BattyKit"` for unit tests (fast, no UI, runnable during development), separate from the UI test run.
