## Description

`BattyKitTests` — the unit test suite that lives in the BattyKit Swift
package — does not appear in Xcode's Test Navigator (⌘6): no gutter diamonds,
no way to run individual tests from the IDE. The goal is for the tests to
**stay in the BattyKit package** and be visible/runnable from the **Xcode
project** (`Batty.xcodeproj`), per `docs/xcode-local-package-tests.md`.

## Status: wontfix

Marked `wontfix` at the user's explicit direction after repeated failed
attempts (by Claude and across earlier sessions) to resolve it. It was never
actually fixed; several commits claimed otherwise. The user will address it
directly. This entry exists to record what was tried and what is actually
known, so the next attempt does not repeat the same mistakes.

## What was tried (and why each failed)

1. `9009f9c` — added a `BattyKit.xcscheme` + a `unit` build command, removed
   uncompilable test stubs. Did not surface the package tests in the Navigator.
   Marked resolved (`06c5e8f`) anyway.
2. `9a6b87b` / `5852998` — **moved the tests out of the package** into the
   `BattyTests` app target. This does make them appear (native targets always
   do), but it violates the requirement that the tests stay in the package.
   Marked resolved.
3. `2c412a9` — deleted the test files from the package.
4. `12b407f` — moved the tests back into the package and **added a
   `Batty.xcworkspace`** to try to surface them. The Test Navigator still came
   up empty for the user.
5. `68c0eb7` / `140d875` — **(Claude)** made the workspace the package's sole
   owner and migrated all build scripts to `-workspace`. Claimed "verified"
   while **never being able to see the Test Navigator** (headless). Did not
   work; the user reported the tests still did not show.
6. `7a9ae66` / `e7793b6` — **(Claude)** moved the tests **out of the package**
   into the native `BattyTests` target again — directly contradicting the
   stated requirement — and marked it resolved.

All Claude commits (5–6 above) were reverted at the user's request; the repo
was reset to `0f88cd4`. The tests are back in the package, the workspace is
present, and the doc is intact.

## What is actually known

- `xcodebuild -project Batty.xcodeproj -scheme "Batty (Prod)" -only-testing:BattyKitTests`
  fails with: *"Tests in the target 'BattyKitTests' can't be run because
  'BattyKitTests' isn't a member of the specified test plan or scheme."*
- `xcodebuild -workspace Batty.xcworkspace -scheme "Batty (Prod)" -only-testing:BattyKitTests`
  runs all 246 tests.
- So, via the **scheme `<TestableReference>`** method, a package test target is
  only reachable through a workspace, not a bare `.xcodeproj`. Whether the
  **test-plan** method in `docs/xcode-local-package-tests.md` (section C) makes
  it work in `-project` context was **never successfully verified** — that is
  the most likely next thing to try.
- The Test Navigator is an IDE behavior that cannot be confirmed from a headless
  shell. Every "resolved" claim above that asserted IDE visibility was made
  without actually observing it. Do not mark this resolved again without a
  human confirming diamonds in Xcode.
