# 0665 — `agent install` prints Codex's MCP entry instead of registering it, and Codex may not pass `BATTY_*` to `batty mcp`

## Description

Child of #0660. For Codex, `agent install` only prints a `[mcp_servers.batty]` table for the user to paste. So Codex has no Batty tools unless the user edits `config.toml` by hand, and the user's `~/.codex/config.toml` has no Batty entry today. Separately, Codex is believed to start stdio MCP servers with a filtered environment, which would drop `BATTY_SESSION_ID`, `BATTY_TAB_ID` and `BATTY_PANE_ID`, so tools without explicit ids would act on Batty's focused Pane, not the caller's.

### Current state

- `AgentGuidanceInstaller.plan` (`BattyKit/Sources/BattyCLICore/AgentGuidanceInstaller.swift:283-290`): "Foundation can't round-trip TOML, so Codex's config is never edited", then `.printMCPEntry(host: .codex, …)` with `command` and `args` only.
- `perform` treats `.printMCPEntry` as `manual` (`AgentGuidanceInstaller.swift:337`).
- Target defaulting relies on the server's environment reaching each tool's child process (`BattyKit/Sources/batty/MCPToolRunner.swift:16-18`).

## Expected behavior

- Register the entry without parsing TOML: append (or replace) a marked text block in `~/.codex/config.toml`, between comment markers such as `# batty:begin` / `# batty:end`, holding the `[mcp_servers.<plugin name>]` table. A TOML table appended at the end of the file is valid as long as the file has no table of the same name; if an unmarked `[mcp_servers.batty]` (or `batty-beta`) table exists, report `manual` and write nothing.
- The table forwards the three variables. Recommended: `env_vars = ["BATTY_SESSION_ID", "BATTY_TAB_ID", "BATTY_PANE_ID"]` if Codex supports that key at plan time; otherwise the planner records what Codex does support.
- Same `ok`/`unchanged`/`manual`/`failed` reporting and `--dry-run` preview as the other hosts.

## Acceptance criteria

1. The planner verifies, from Codex's current documentation or source, (a) whether Codex filters the environment of stdio MCP servers and (b) the key that forwards named variables, and writes both into the plan with the source.
2. `AgentGuidanceInstallerTests`: appends to a fixture `config.toml` with other tables and keeps them byte for byte; replaces its own marked block; a pre-existing unmarked table of the same name yields `manual` and no write; a missing file is created.
3. Manual (user checklist): a Codex session in a Batty Pane calls `id` through MCP and gets its own Pane id.

## Open questions

1. **Edit `config.toml` at all?** #0647 chose to print only. Recommended: edit with a marked text block, which needs no TOML parser and is reversible by deleting the block.
2. **Other hosts.** Claude Code and OpenCode are believed to pass the full environment to local MCP servers; the planner should confirm, and if either filters, file a follow-up rather than widen this issue. Cursor's MCP servers are started by the Cursor app, not a Batty Pane, so they never see `BATTY_*`; leave Cursor as is.
