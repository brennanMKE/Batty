## Description

Child of #0660. For Codex, `agent install` only prints a `[mcp_servers.batty]` table for the user to paste. So Codex has no Batty tools unless the user edits `config.toml` by hand, and the user's `~/.codex/config.toml` has no Batty entry today. Separately, Codex is believed to start stdio MCP servers with a filtered environment, which would drop `BATTY_SESSION_ID`, `BATTY_TAB_ID` and `BATTY_PANE_ID`, so tools without explicit ids would act on Batty's focused Pane, not the caller's.

### Current state

- `AgentGuidanceInstaller.plan` (`BattyKit/Sources/BattyCLICore/AgentGuidanceInstaller.swift:283-290`): "Foundation can't round-trip TOML, so Codex's config is never edited", then `.printMCPEntry(host: .codex, …)` with `command` and `args` only.
- `perform` treats `.printMCPEntry` as `manual` (`AgentGuidanceInstaller.swift:337`).
- Target defaulting relies on the server's environment reaching each tool's child process (`BattyKit/Sources/batty/MCPToolRunner.swift:16-18`).

## Root cause

`agent install` emitted `.printMCPEntry` for Codex (print-only, per #0647), so Codex had no Batty tools without a hand edit. Codex builds a stdio MCP server's environment from a fixed allow-list plus `env_vars` (confirmed in the plan from `codex-rs/rmcp-client/src/utils.rs`), so even a hand-added entry without `env_vars` dropped `BATTY_*` and tools fell back to the focused Pane.

## Fix

- New `BattyKit/Sources/BattyCLICore/CodexConfigBlock.swift`: pure string `block(identity:)` (marked `# <key>:begin` / `# <key>:end`, `command`, `args = ["mcp"]`, `env_vars = ["BATTY_SESSION_ID", "BATTY_TAB_ID", "BATTY_PANE_ID"]`, TOML-escaped command) and `merge(existing:block:key:)` returning `.write` / `.unchanged` / `.conflict`. Appends keeping existing bytes (adds a missing final line ending plus a blank line), replaces only its own marked lines, follows the file's CRLF/LF, and conflicts on unbalanced markers or an unmarked `[mcp_servers.<key>]` (quoted forms, sub-tables, dotted keys) outside the block.
- `AgentGuidanceInstaller`: `.printMCPEntry` replaced by `.writeCodexMCPBlock(file:key:block:)` targeting `$CODEX_HOME/config.toml` (else `<home>/.codex/config.toml`). `perform` resolves symlinks, backs up the original to `AgentGuidanceBackups/<stamp>/codex/config.toml`, writes atomically and restores POSIX permissions. Conflict or non-UTF-8 → `manual` with the block indented, nothing written.
- Docs: `.claude/skills/batty-cli/SKILL.md` and `docs/batty-cli-agent-workflows.md` describe the written block.
- No deviation from the plan. `CodexConfigBlock.lines(key:cliCommandName:command:)` is internal so the pure tests need no app-bundle fixture.

**Round 2 (after review).** `CodexConfigBlock.merge` now splits lines on the `\n` byte (`splitLines`, over `text.utf8`), keeping each line's own ending (`\n`, `\r\n`, or none at EOF), because Swift treats `"\r\n"` as one `Character`. Marker search, the conflict scan and the unchanged check compare line contents without endings; a replaced block takes the file's dominant ending (CRLF only when more lines end in CRLF than bare LF; LF for empty/new files) and its last line keeps the old end marker's ending; append adds a missing final ending and exactly one blank line in the dominant style. The installer splits off a UTF-8 BOM before decoding and writes it back, and gives the backup the original's POSIX permissions. Tests added: CRLF append (one blank line), CRLF stale-block replace, CRLF re-run `.unchanged`, CRLF unmarked table → conflict, mixed endings (append and replace), block at EOF without a newline, empty file; installer CRLF re-install (no duplicate table, then `.unchanged`), CRLF unmarked table → `manual`, BOM preserved (file and backup), backup 0600. Every merge test now asserts bytes outside the block are identical (`[UInt8]`/`Data` comparisons, not `String ==`).

## Review notes

Round 1, bounced 2026-11-18. Build (`CHECK BUILD: PASSED`) and `./build.sh unit` (`CHECK UNIT: PASSED (4637 tests)`) pass, but `CodexConfigBlock.merge` mishandles CRLF files, which the plan and Fix both claim are supported. Reproduced with a standalone copy of `merge`:

1. **CRLF re-run appends a second block (blocking).** Swift treats `"\r\n"` as one `Character`, so `text.split(separator: "\n")` in `merge` (`BattyKit/Sources/BattyCLICore/CodexConfigBlock.swift`) does not split a CRLF file at all: the whole file is one "line". The markers are never found, so the second `agent install` on a CRLF `config.toml` appends another `[mcp_servers.batty]` table. Codex then fails to load the file (duplicate table).
2. **CRLF bypasses the conflict scan (blocking).** For the same reason, a CRLF file that already has an unmarked `[mcp_servers.batty]` gets the block appended (`.write`), not `.conflict`, producing a duplicate table.
3. **Extra blank line on CRLF append.** `result.hasSuffix("\n")` is false for text ending in `"\r\n"` (grapheme), so an extra `\r\n` is added (file ending in CRLF gets two blank lines). Bytes outside the block stay intact, but it differs from the LF behaviour.
4. **UTF-8 BOM is dropped.** `String(data:encoding: .utf8)` strips a leading BOM, and the write re-encodes without it, so a BOM-prefixed file loses its first three bytes outside the block. Keep the BOM (e.g. detect `EF BB BF` on the `Data`, merge the rest, and prepend it on write), or treat a BOM file as `manual`.
5. **Backup permissions (should fix).** The backup is written with default permissions, so a 0600 `config.toml` (it can hold `env` secrets) is backed up world-readable. Give the backup the original's POSIX permissions.

What would satisfy it: split and compare on unicode scalars or bytes (e.g. `text.unicodeScalars` / `components(separatedBy: "\n")` on an `NSString`-free path, or operate on `[UInt8]`), keeping each line's own `\r`; fix the trailing-newline check the same way. Add tests in `CodexConfigBlockTests`: CRLF re-run with current block is `.unchanged`; CRLF re-run with a stale block replaces only the block, bytes outside identical; CRLF file with an unmarked `[mcp_servers.batty]` is `.conflict`; CRLF file ending in CRLF gets exactly one blank line before the block. In `AgentGuidanceInstallerTests`: a BOM file keeps its BOM (or yields `manual`), and the backup of a 0600 file is 0600.

Checked and fine: Prod/Beta markers do not cross-match; comment lines that mention the table do not conflict; unbalanced/duplicated markers conflict and write nothing; the TOML command string escapes `\\`, `"` and controls, and a path with spaces is a valid basic string; symlinks are resolved and kept; atomic write restores the config's permissions; every path derives from the injected home/`CODEX_HOME`; tests use `AgentInstallFixture` temp dirs only. Real home untouched during review: `~/.codex/config.toml` mtime `1794450373` before and after, no `AgentGuidanceBackups` or `~/.codex/skills/batty*`.

### Approach

**1. New file `BattyKit/Sources/BattyCLICore/CodexConfigBlock.swift`.** A `nonisolated enum CodexConfigBlock` holding pure string functions, so most tests need no file system.

- `static func block(identity:lineEnding:) -> String`, which returns:
  ```
  # <plugin>:begin — managed by `<cli> agent install`; edits inside this block are replaced
  [mcp_servers.<plugin>]
  command = "<cliExecutablePath, TOML basic-string escaped>"
  args = ["mcp"]
  env_vars = ["BATTY_SESSION_ID", "BATTY_TAB_ID", "BATTY_PANE_ID"]
  # <plugin>:end
  ```
  `<plugin>` is `identity.pluginName` (`batty` / `batty-beta`), which is a valid TOML bare key. The markers are per variant, so Prod and Beta blocks coexist. Escape `\` and `"`, plus control characters as `\uXXXX`, in a small `tomlBasicString` helper.
- `static func merge(existing: String?, block: String, key: String) -> Result`, where `Result` is `.write(String)`, `.unchanged` or `.conflict(String)`.
  - Markers are matched as **whole trimmed lines** that start with `# <key>:begin` or equal `# <key>:end`. So `# batty:begin` never matches `# batty-beta:begin`.
  - Zero markers: scan every line for a conflicting table. If none, append the block. Keep every existing byte, add the file's line ending first if the file doesn't end with one, and put a blank line before the block when the file isn't empty.
  - Exactly one begin followed by one end: if the text between them equals the new block, return `.unchanged`. Otherwise replace only the lines from begin to end inclusive. The bytes before and after stay identical.
  - Anything else (begin without end, end first, two begins) is `.conflict("unbalanced Batty markers")`.
  - **Conflict scan**, outside our block only. Strip whitespace and any trailing `# comment`. A line conflicts if it is a table header `[mcp_servers.<key>]`, `[mcp_servers."<key>"]` or `[mcp_servers.'<key>']`, with or without inner spaces, or a sub-table header that starts with one of those plus `.` (e.g. `[mcp_servers.batty.tools.id]`). A line that starts with the dotted key `mcp_servers.<key>` (=, or `.`) also conflicts. `[mcp_servers.batty-beta]` is **not** a conflict for `batty`, and `[mcp_servers.battyx]` isn't either. An inline `batty = {…}` inside a `[mcp_servers]` table is also not detected. That's an accepted gap, named in Gotchas; Codex would then report a duplicate key and the user would see it.
  - Line ending: use `"\r\n"` for the block if the existing text contains `"\r\n"`, else `"\n"`.

**2. `AgentGuidanceInstaller.swift`.**
- Replace `case printMCPEntry(host:text:)` with `case writeCodexMCPBlock(file: URL, key: String, block: String)`. Summary: `"Codex: add MCP server mcp_servers.<key> to <file> (marked block)"`. Remove the "Foundation can't round-trip TOML" comment. Update the type doc comment ("the skill plus MCP entry for Cursor, OpenCode and Codex" stays true).
- The Codex branch of `plan` uses `file = codexDirectory/config.toml` (so `CODEX_HOME` is honoured). The block comes from `CodexConfigBlock.block(identity:lineEnding:"\n")`; the line ending is re-derived at apply time.
- `perform` → `writeCodexMCPBlock(identity:file:key:stamp:)`:
  1. Resolve symlinks (`file.resolvingSymlinksInPath()`) so a dotfiles symlink stays a symlink and its target is edited.
  2. Read the data. Missing file means `existing = nil`. Data that isn't valid UTF-8 gives `.manual("config.toml is not UTF-8 …" + block)`.
  3. Run `merge`. `.unchanged` returns `.unchanged`, with no backup and no write. `.conflict(reason)` returns `.manual` with the reason and the block indented for pasting, the same shape as the JSON-merge manual path, and nothing is written.
  4. `.write`: if the file existed, first copy the original bytes to `appSupportDirectory/AgentGuidanceBackups/<stamp>/codex/config.toml`, as `mergeMCPEntry` does, and record its POSIX permissions. Create the parent directory, write `.atomic`, then restore the recorded permissions (a 0600 config stays 0600). Return `.done("previous file backed up to …")` or `.done("")` when created.
