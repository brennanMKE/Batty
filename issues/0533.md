## Verified facts (2026-10-20, `main` at `dab3c6df`)

### Why the Project clips look wrong

- **Every seeded Project is palette color 0 (Blue).** `ProjectFixture.project` hardcodes `"color": 0` (`BattyUITests/Support/ProjectsHarness.swift:49`). It has no parameter for the color, the custom color (`customColor`) or the custom symbol name (`symbolName`) (`:31-56`). The demo helper `project(_:slug:layout:startup:symbol:)` passes only `symbol` (`BattyUITests/DemoSceneTests.swift:229-231`).
- **Clip 01's one symbol is invalid.** The Batty Project is seeded with `symbol: "bolt.fill"` (`DemoSceneTests.swift:248`). The `symbol` key holds a `ProjectSymbol` raw value, not an SF Symbol name. `bolt.fill` is not a raw value, so it decodes to `.folder` and logs "unrecognized project symbol" (`BattyKit/Sources/BattyKit/Model/Project.swift:349-353`). An arbitrary SF Symbol goes in the `symbolName` key (`Project.swift:211-214`, `CodingKeys` at `:312`). So all four Projects in clip 01 (`:241-256`) and all three in clip 07 (`:552-556`) are identical blue folders.
- **A Project's palette color becomes its Session's color when the Project opens** (`BattyKit/Sources/BattyKit/Runtime/WindowRuntime.swift:239`, `:246`). A Session takes `project.color.rawValue` only. `customColorHex` is not carried to the Session row, so the demo should use palette colors so that the Sidebar matches the picker.
