## Description

#0481 made ⌘W and ⌘Q behave while the Project Editor has a sheet: ⌘W does nothing while a sheet is attached, and a ⌘Q that cannot show the editor's Save / Discard / Cancel question (because a sheet is attached) is cancelled at once. Its premise was that the Root folder chooser is such a sheet. It is not: `ProjectEditorPanels.chooseDirectory` runs the `NSOpenPanel` with `runModal()`, so the panel is an app-modal window with no `sheetParent`, and `attachedSheet` on the editor stays nil. #0481's Gotchas record that what ⌘W and ⌘Q do during that modal session is unverified. The work here is to examine it and decide.

Behind the Projects flag: the editor and its panel exist only with the flag on.

## Current code (verified 2026-10-13 on `main` at `673c6530`)

- **The panel.** `ProjectEditorPanels.chooseDirectory(startingAt:message:)` (`BattyKit/Sources/BattyKit/Views/ProjectEditorView.swift:42-53`): builds an `NSOpenPanel` and returns `panel.runModal() == .OK ? panel.url : nil` (`:52`). Three call sites, all from button actions: `chooseRoot()` (`:332-340`, the Root folder **Choose…** button, identifier `project-editor.root.choose`, `:311-312`), `chooseFolder(tab:)` (`:627-636`) and `chooseFolder()` (`:811-819`) for a Tab's working directory. The Git Status Pane's "Change Directory…" uses the non-modal `panel.begin { }` instead (`Views/GitStatusPaneView.swift:473-478`); Settings' bell-decision export uses `NSSavePanel.runModal()` (`Views/SettingsView.swift:383-387`).
- **What the chords would hit if the menu fires during the modal session.**
  - ⌘W: the Close item (`Commands/BattyCommands.swift:610-631`) calls `closeProjectEditor(from: NSApp.keyWindow)` (`Runtime/AppStateStore+Quit.swift:82-86`). `projectEditorWindow(from:)` (`Runtime/AppStateStore.swift:1004-1008`) walks `sheetParent` only, so a modal panel resolves to nil and the call returns false. The panel is titled and unregistered, so `auxiliaryWindowIsKey` is true (`AuxiliaryWindowGateTests.aStandaloneOpenPanelIsAuxiliary`, `:108`) and `key?.performClose(nil)` is sent to the panel (#0481 Gotchas). With #0496's rule the panel is its own top-level window, so that path would still close it.
  - ⌘Q: `handleTerminateRequest` (`AppStateStore+Quit.swift:29-58`) asks a dirty editor through `editor.requestQuit`, whose presenter `model.presentForQuit` (`Views/ProjectEditorWindowController.swift:88-94`) only refuses when `window.attachedSheet != nil`; a modal panel passes that guard, so the editor is brought to the front (`makeKeyAndOrderFront`, `NSApp.activate()`) and a `confirmationDialog` is raised **under a running modal session**, and `.terminateLater` is returned while the panel still owns the run loop.
  - Whether AppKit dispatches these key equivalents to Batty's SwiftUI menu items at all while `NSApp.modalWindow` is non-nil is the unknown. Do not assume either way.

## Expected behavior

1. **Examine first.** In the VM (or by a manual check recorded in the resolution if XCUITest cannot drive the panel reliably), with the Projects flag on: make the editor dirty, click `project-editor.root.choose`, and press ⌘W, then ⌘Q, then Escape. Record for each what happened to the panel, the editor, the edit, and the app. Repeat with a clean editor for ⌘Q.
2. **Decide and record**, in a `## Decision` section before implementation, one of:
   - **(a) Present the panel as a sheet on the editor** (`beginSheetModal(for:completionHandler:)`), so `attachedSheet` is non-nil and #0481's existing ⌘W ("nothing while a sheet is up") and ⌘Q ("cancel at once when the question cannot be shown") paths cover it with no new rule. `chooseDirectory` becomes completion-handler shaped at the three call sites, and the `onChosen` closure applies the URL to the model from the panel's completion, which is event-origin. **Recommended**, because both chords land in code #0481 already tests, the quit presenter's `attachedSheet` guard becomes true instead of accidentally false, and the Git Status precedent already avoids `runModal()`.
   - **(b) Keep `runModal()`** and make both chords explicitly safe: `closeProjectEditor` and the auxiliary branch do nothing while `NSApp.modalWindow != nil` (through an injectable seam), and `handleTerminateRequest` cancels at once while a modal session runs, as it does for an attached sheet. Choose this only if (1) shows the chords are already inert, in which case the change is a documented no-op plus tests.
3. Either way: no edit is lost, no dialog is raised under a modal panel, and a cancelled panel leaves the editor exactly as it was.
4. **Flag off:** nothing; the editor does not exist. No new gate site unless the implementation adds one; if so, append it to `docs/feature-flags.md`.

## Decision

Option (a): the folder chooser is an `NSOpenPanel` sheet on the editor window (`beginSheetModal(for:)`), presented from `ProjectEditorPanels` at all three call sites. #0481's existing rules then cover it with no new rule: Cmd-W does nothing while a sheet is attached, and Cmd-Q is cancelled at once because the editor cannot show its question. The "examine first" step is moot, since `runModal()` no longer exists to examine. The window is the editor's own (`ProjectEditorWindowController.shared.window`), never the key window.

## Resolution notes

> 🟢 Resolved 2026-10-13. The Project Editor's folder choosers (Root, Tab, and the Git Status repository) now open as a sheet on the editor window instead of as an app-modal `runModal()` panel. #0481's existing paths therefore cover them:
> - ⌘W does nothing while the panel is up.
> - ⌘Q with unsaved edits is cancelled immediately, with no dialog.
> - Escape or Cancel leaves the edit untouched.

Owed to the user (visual, so this issue is resolved rather than closed):
- The panel appears as a sheet on the editor from all three Choose… buttons.
- ⌘W and ⌘Q behave as described above with the sheet up.
- ⌘Q with a clean editor while the panel is up is unverified (see Gotchas).

## Root cause

`ProjectEditorPanels.chooseDirectory` used `NSOpenPanel.runModal()`. The panel therefore had no `sheetParent`, and the editor's quit and ⌘W handling (#0481) never saw it.

## Fix

- **Option (a), recorded in `## Decision`:** `chooseDirectory` is completion-shaped and presents with `beginSheetModal(for:)`.
- `chooseRoot(for:)` and `chooseFolder(for:tab:)` default the window to `ProjectEditorWindowController.shared.window`, never `NSApp.keyWindow`. An accessibility press while a terminal window is key would otherwise hang the panel there.
- The chosen folder is applied in the panel's completion, which is event-origin and needs no Task hop. Cancel never calls the completion.
- With no editor window, nothing is presented and an error is logged.
- A `Presenter` seam lets tests complete the panel without a real one.
