Do not plan-to-implement without that go-ahead, and never run a deploy (real or against the server) while working it.

## Description

The website is served from `photon:/var/www/vhosts/batty.sstools.co/` (`website/README.md:33`), deployed by a hand-run rsync that, since #0681, uses `--exclude-from=website/.deploy-hold --exclude=README.md --exclude=.deploy-hold` (`website/README.md:52-55`) after `python3 -I tools/check-website-hold.py` (`website/README.md:40`).

The scripts were never updated:

- `scripts/deploy-website.sh:2` says it pushes "to the EC2 host"; it requires `BATTY_EC2_HOST` / `BATTY_EC2_PATH` (lines 5-10, 41-42), optional `BATTY_EC2_KEY` / `BATTY_EC2_PORT` (44-56, 76-82), and rsyncs to `$BATTY_EC2_HOST:$BATTY_EC2_PATH/` (101-108).
- Its rsync (101-108) excludes only `.DS_Store`, `*.swp`, `*.bak`: no `--exclude-from=website/.deploy-hold`, no `README.md` / `.deploy-hold` exclusion, and it does not run `tools/check-website-hold.py`. Running it would publish held paths (`/docs/`, `/llms.txt`, `/llms-full.txt`, held until 1.5.0) early, plus `README.md`.
- `scripts/preflight.sh:15` (`--skip-ssh-check ... EC2 host`) and 682-709 check `BATTY_EC2_*` env vars and SSH to `$BATTY_EC2_HOST`, reporting "deploy-website.sh disabled" when unset.

## Expected

- `deploy-website.sh` targets `photon:/var/www/vhosts/batty.sstools.co/` (or reads host/path from one place shared with the docs), no EC2 env vars.
- Runs `python3 -I tools/check-website-hold.py` first and stops on failure.
- rsync uses `--exclude-from=website/.deploy-hold --exclude=README.md --exclude=.deploy-hold` (keep the existing junk excludes), never `--delete`.
- Supports `-n` for a dry run (rsync `-n`).
- `preflight.sh` checks the photon target (SSH reachability, skippable with `--skip-ssh-check`) instead of `BATTY_EC2_*`.
- `website/README.md` may then point at the script as the one deploy process.

## Verification

Read-only: `zsh -n` both scripts; run `deploy-website.sh -n` only with the user's go-ahead (it contacts photon). Never run a real deploy.
