# 0725 — Apple Intelligence never chooses a symbol for a Session in a project folder, so every plain Session shows the same dot until the user picks one

| | |
|---|---|
| **Status** | open |
| **Module** | Session / Sidebar / Settings |
| **Platform** | macOS |
| **First seen** | 2026-11-22 |
| **Target** | 1.5.0 |

## Description

User request (2026-11-22), verbatim: "We also let the user rename the session and set the color which are persisted. At least the name is persisted. Why not let them pick the symbol as well. File issues to let the user select the SF Symbol of a session and also make sure we persist the color change. We also want to use AFM to automatically select a symbol as long as we can get back a high confidence the symbol is a good match. This also makes it very easy to save as a project as we can take the name, color and symbol along with the path to use in the project."

When a Session settles in a folder that looks like a project, Batty should be able to choose a fitting SF Symbol for it with the on-device Foundation Models (Apple Intelligence) model, the same way it already suggests a Session name, and show it in place of the Sidebar dot — **only when the match is high-confidence**. Otherwise the dot stays. A symbol the user chose ([#0724](0724.md)) or a Project's symbol always wins. A Session that carries a suggested symbol then hands it to Save as Project ([#0724](0724.md)) like any other Session symbol.

## Expected behavior

1. **Trigger.** Alongside Session auto-naming, on an anchor-cwd change of a single-Pane Session, when the folder looks like a project: `nameCache.isProjectDirectory(cwd)` **and** a project signal — a `ProjectNameResolver` rule matches, or `.git` plus a README/build file is present (per `docs/project-name-extraction.md`).
2. **Closed vocabulary.** The model chooses from a `@Generable` enum mirroring the curated `ProjectSymbol` cases **plus an explicit `none`**, so it cannot invent an SF Symbol name and has a sanctioned way to decline. Same tool-limited folder access as the name suggester (`readFile` of top-level entries only, 4 KB cap, no TCC prompts). New `LanguageModelSession` per request.
3. **Apply only at high confidence** (see decision 1), otherwise keep the dot.
4. **Precedence**, highest first: Project's symbol → user-chosen Session symbol (#0724, live or remembered per folder) → AI suggestion → dot. The AI result never writes the per-folder store (#0723/#0724) and never marks the symbol as user-chosen — same standing as an AI name (`docs/foundation-models.md`, "An AI name never writes SessionNameCache"). Leaving the folder clears an AI symbol back to the dot; a `cd` into another project re-evaluates.
5. **Stale-result guard** as in `applySuggestedName`: apply only if the Session still exists, is single-Pane, has no user/Project symbol, and its anchor cwd is unchanged. Results (including `none`) memoized per cwd, in memory only.
6. Deterministic result first: the UI is correct if the model never answers (dot or the deterministic symbol, per decision 2).
7. Save as Project from a Session showing an AI symbol pre-fills that symbol (via #0724's draft path); the user can change it in the editor.

## Decisions for the user

1. **How "high confidence" is obtained.** Foundation Models returns no calibrated probability for a guided-generation choice, so any "confidence" is a proxy. Options:
   - **(A, recommended)** Agreement gate: a deterministic ecosystem→symbol table keyed by the matched `project-name-rules.json` rule `id` (the bundled rules today are `swift-xcode`, `swift-spm`, `rust`, `node`, `deno`, `go`, `python-pep621`, `ruby-gem`, `dart-flutter`, `julia`, `elixir`, `cmake`; e.g. `swift-xcode` → `macApp`, `swift-spm` → `package`, `rust` → `hammer`, `node`/`deno` → `web`, `dart-flutter` → `iPhoneApp`, `cmake` → `chip`; a folder with only `.git` + README has no table entry). Apply the AI pick only when it **agrees** with the table, or when the table has no opinion and the model's self-reported `confidence` field (a `@Guide`-constrained `high|medium|low`) is `high`. `none` or anything else keeps the dot.
   - **(B)** Model-only: a `@Generable` struct `{ symbol: SymbolChoice, confidence: high|medium|low }`, apply only on `high` with a non-`none` symbol. Cheaper; the self-report is uncalibrated and small models over-claim.
   - **(C)** Self-consistency: ask twice (or at two temperatures) and apply only when both answers agree and neither is `none`. Doubles inference cost per folder.
2. **Deterministic fallback without AI.** Should the ecosystem→symbol table alone set a symbol when Apple Intelligence is unavailable or off (macOS 15, AI disabled)? Recommended: **no** for this issue — keep the table as an agreement signal only, so a Mac without the model looks the same as today; it can become its own opt-in later.
3. **Setting and default (progressive disclosure).** The existing AI naming toggle defaults **on** (`SettingsPreferences.swift:50`). A symbol appearing on the row is a visible change an existing user didn't ask for. Recommended: a **new toggle under Session Naming**, "Use Apple Intelligence to choose session symbols", **off by default**, disabled with "Requires macOS 26" before macOS 26, checked on every call. Alternative: reuse the existing AI naming toggle (would turn the feature on for everyone who never touched it, which conflicts with `AGENTS.md`).

## Acceptance criteria

- With the new toggle off (default), nothing changes: no model call, the dot stays.
- With it on, a single-Pane Session that `cd`s into a recognized project gets a curated symbol only when the confidence rule (decision 1) passes; otherwise the dot.
- The model cannot produce a name outside the curated set (enforced by the `@Generable` enum); `none` is honored.
- Never overrides a Project's symbol or a user-chosen Session symbol (#0724), live or remembered.
- Stale results (Session closed, split, cwd changed, user picked a symbol meanwhile) are discarded.
- No unit test runs the model; the logic is tested against a fake `SessionSymbolSuggesting`.
- `docs/foundation-models.md` gets a "Session symbols" section and a row in its feature table; Help and changelog mention the toggle.
