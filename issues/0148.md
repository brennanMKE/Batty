# 0148 — Layout picker creates new panes at home directory instead of current working directory

| | |
|---|---|
| **Status** | open |
| **Module** | Layout / Session |
| **Platform** | macOS |
| **First seen** | 2026-05-19 |

## Description

When a layout is applied via the layout picker (Cmd-Shift-L), all new panes open at `~` (home directory) instead of inheriting the working directory of the currently-focused pane. Toolbar and menu splits (Cmd-D, Cmd-Shift-D) correctly inherit the CWD because they pass `inheritingFrom: tree.focusedPane` to `splitFocusedPane()`. The layout picker's `PaneLayout.apply(to:primaryPane:)` uses bare `splitFocusedPane(direction:)` calls that omit `inheritingFrom:`, so new panes get no working directory and fall back to `~`.

## Steps to reproduce

1. Open Batty and navigate to any directory (e.g. `cd /usr/local`).
2. Open the layout picker (Cmd-Shift-L) and apply any multi-pane layout (e.g. Horizontal Split).
3. Observe the new pane's shell prompt — it starts at `~` instead of `/usr/local`.

## Expected behavior

Every pane created by the layout picker should inherit the working directory of the focused pane at the time the layout is applied, matching the behavior of Cmd-D / Cmd-Shift-D splits.

## Actual behavior

New panes open at `~`. `PaneLayout.apply(to:primaryPane:)` (`PaneLayout.swift:136–208`) calls `tree.splitFocusedPane(direction:)` without `inheritingFrom:`, so `TabRuntime.init` receives `workingDirectory: nil` and the terminal starts in the default working directory.

## Notes

The `inheritingFrom` parameter on `splitFocusedPane(direction:ratio:inheritingFrom:)` (`SplitTree.swift:76`) reads the CWD from the source pane's active tab:

```swift
if let sourceTab = source?.activeTab {
    let cwd = sourceTab.terminal.workingDirectory
        ?? sourceTab.terminal.configuration.workingDirectory
    newPane = PaneRuntime(tabs: [TabRuntime(workingDirectory: cwd)])
}
```

The fix is to pass `inheritingFrom: primary` for every `splitFocusedPane` call inside `PaneLayout.apply(to:primaryPane:)` in `PaneLayout.swift`. The `primary` pane is already available as a parameter to the method. All layouts need the same change — `horizontalSplit`, `verticalSplit`, `threeColumns`, `threeRows`, `mainLeftTwoRight`, `mainRightTwoLeft`, `mainTopTwoBottom`, `mainBottomTwoTop`, and `twoByTwoGrid`.
