## Description

The Background Sets tab of the Background Images window can keep showing an old copy of the hosted catalog. On 2026-11-12 a new "Deep Space" set was deployed to `https://batty.sstools.co/backgrounds/catalog.json`. The user then opened the Background Images window and the set was not there. The tab has no Refresh control. The only manual fetch is the banner's Retry, which appears only after a failed check. There is also no way to narrow the grid as more sets are added.

User request (2026-11-12): "The window showing Background Images does not refresh. I think it could check each time the window appears or offer a refresh button. I think it would also be good to offer a filter text field to match set names and image titles."

This issue covers three changes to the Background Sets tab:

1. **Check when the window appears.** Each time the Background Images window is shown, or the Background Sets tab is selected, make a cheap conditional request (`If-None-Match` / `If-Modified-Since`, so an unchanged catalog costs a 304). Throttle it so that opening the window repeatedly doesn't hammer the server. The planner picks the throttle interval and the trigger. Bringing an already-open window to the front must count as "appears". Today it does not (see Notes).
2. **A Refresh button** in the Background Sets tab. It bypasses the throttle and is disabled while a check is running, with an in-progress indicator. A failure is shown through the existing problem banner. A successful check clears the banner.
3. **A filter text field** that matches set names and image titles. It is case- and diacritic-insensitive, and it matches the display text (`BackgroundCatalogParser.displayText`). When a set's name matches, the whole set shows. Otherwise the set shows only its matching images. Empty sets, and catalog sections left with no sets, are hidden. When nothing matches, the tab shows an empty-result state ("No backgrounds match …"). Clearing the field restores the full grid. The filter is view-local `@State` and is never written from `body`.

### Decisions

1. **Throttle interval: 5 minutes** (`HostedBackgroundsModel.refreshInterval` goes from `10 * 60` to `5 * 60`, same name). Opening or re-focusing the window repeatedly costs at most one conditional request per catalog per 5 minutes; Refresh covers "right now".
2. **The throttle uses the latest of the in-memory `lastRefresh[url]` and the persisted `HostedCatalogState.lastChecked`**, so a relaunch within 5 minutes of a check doesn't check again. A last check in the future (wall clock moved back) counts as due, so a clock change can't silence checks. All times come from the injected `clock` (`SchedulingClock`); `lastChecked` is written with `clock.now` already.
3. **Window trigger is `windowDidBecomeKey`**, which fires for the first `show`, a re-`show` of a window behind others, and a click or app switch that brings it to the front. It is an AppKit delegate callback, outside any SwiftUI update, so starting async work there is event-origin. It checks only `hosted.scheduledCatalogURLs` (the built-in catalog only after the first Browse), and does not mark Browse as opened. It runs whichever tab is showing: a 304 is cheap, and the controller doesn't know the view-local tab.
4. **Tab-selection trigger stays `BackgroundSetsView`'s `.task`** (the segment action makes the view appear; its writes all follow an `await`). It now goes through the same due-check helper as the window trigger.
5. **Refresh checks every catalog in `catalogURLs` one after another** (same order and shape as `BackgroundCatalogScheduler.runScheduledChecks`), bypassing the throttle, then reconciles availability. A new observed `private(set) var isRefreshingAll` is written only by `refreshAll()` (start/end, only on change) so the button doesn't flicker enabled between catalogs. The button and spinner key off `isCheckingAny` (`isRefreshingAll || catalogs.contains(where: \.isChecking)`), so a check started by the window, the scheduler or Retry also disables it.
6. **Banner:** no new banner path. `performRefresh` already sets `problem` on failure (including `.offlineShowingCache`, whose banner has no Retry; Refresh now covers it) and clears it on 200/304. Refresh reuses it.
7. **Filter is a pure enum, `BackgroundCatalogFilter`**, matching `displayText(set.name)` / `displayText(image.title)` with `range(of:options: [.caseInsensitive, .diacriticInsensitive])` against the trimmed query. Whitespace-only or empty input returns the input unchanged. While a query is active, sections whose catalog has not loaded or that have no matching sets are hidden (problem banners included); with no query every section shows as today. Catalog section headers keep using the full `hosted.catalogs` count, so they don't appear and disappear while typing.
8. **Filter field is a plain `TextField` with `.roundedBorder`** in a control row above the `ScrollView`, with a clear (`xmark.circle.fill`) button shown only when the field is non-empty. The query is view-local `@State private var query = ""`, written only by the field's binding and the clear button; never from `body`. No focus writes (the field is not auto-focused). `background-sets.root` stays on the `ScrollView` so `scrollToCell`'s hover/scroll targets the grid unchanged.
9. **Website/Concepts copy:** add one clause each that Batty also checks when Background Images comes to the front (at most every 5 minutes) and that Refresh in Background Sets checks right away. The deploy itself is not part of this issue.

## Notes

### How the catalog is refreshed on `main` today

- **Model:** `BattyKit/Sources/BattyKit/Model/HostedBackgroundsModel.swift`, `@MainActor @Observable`. It is owned by `BackgroundImagesModel` (`store.backgroundImages.hosted`) and built in `BattyKit/Sources/BattyKit/Runtime/AppStateStore+BackgroundImages.swift`, so it lives for the whole app process.
- **The only automatic trigger** is `BackgroundSetsView`'s `.task { await hosted.browseAppeared() }` (`BattyKit/Sources/BattyKit/Views/BackgroundSetsView.swift`). It runs when the Background Sets segment of `BackgroundImagesView` appears, and not on the My Images tab. `browseAppeared()` loads any cached copy, then calls `refresh(url)` for each catalog URL. It skips a URL whose in-memory `lastRefresh[url]` is less than `HostedBackgroundsModel.refreshInterval` (10 minutes) old. `lastRefresh` is not persisted, so it resets when the app relaunches.
- **Why the new set can be missed:** `.task` runs once per appearance of the view, not when the window comes to the front. `BackgroundImagesWindowController` (`BattyKit/Sources/BattyKit/Views/BackgroundImagesWindowController.swift`) keeps a window that is open but behind other windows. `show(store:)` only calls `makeKeyAndOrderFront`, and `windowDidBecomeKey` calls only `model?.refreshUses()`. An open window, or one reopened within 10 minutes of the last check, therefore shows the old copy. Closing the window releases it (`windowWillClose` nils `window`), and reopening it rebuilds the view, but the 10-minute throttle still applies.
- **Manual trigger:** only the problem banner's **Retry** (`hosted.refresh(url)`), which is hidden when there is no problem and for `.offlineShowingCache`.
- **No launch or periodic check on `main`.** The website (`website/backgrounds.html` line ~392) says Batty "checks it at launch and every 24 hours, and **Check Now** checks it right away". That describes the unmerged #0577 (`BackgroundCatalogScheduler`, a Check Now button in Settings), not shipped behavior.
- **Conditional GET:** `performRefresh` sends the cached `etag` / `lastModified` from `BackgroundCatalogCache.state(for:)`, but only when a parsed copy is already in memory. `URLSessionBackgroundCatalogFetcher` uses an ephemeral session with `urlCache = nil` and `.reloadIgnoringLocalCacheData`, so URLSession never serves a stale copy. A 304 calls `cache.markChecked` and keeps the copy. A 200 is parsed, then `cache.store(body:validators:…)` writes it. The server sends both validators (checked 2026-11-12: `ETag: "14b1-6600eaea32500"`, `Last-Modified: Thu, 12 Nov 2026 06:47:16 GMT`), so a check of an unchanged catalog is a cheap 304.
- **Disk cache:** `BattyKit/Sources/BattyKit/Settings/BackgroundCatalogCache.swift` (actor). It stores `~/Library/Caches/<bundle id>/BackgroundCatalogs/<sha of URL>/catalog.json` plus `state.json` (`etag`, `lastModified`, `lastChecked`, `lastError`), with thumbnails beside them. `lastChecked` is persisted but nothing uses it for throttling today. A persisted throttle could be based on it.
- `refresh(url)` already merges concurrent calls for the same URL (`refreshing[url]`), and `HostedCatalogState.isChecking` is already published, so a Refresh button's in-progress state can use it.

### Constraints for the planner

- `docs/swiftui-observation-rules.md` is binding. A refresh on window appearance must start from an event: the window controller's `show` / `windowDidBecomeKey`, or the tab-selection action. It must not come from layout or a focus flip that writes during an update. No Task-hop "fixes". The model already writes only on change. Keep it that way.
- The throttle must use the injected `SchedulingClock`, so unit tests advance it explicitly with no sleeps (AGENTS.md "Asynchronous tests").
- **Overlap with the unmerged `origin/issue/0577`** (catalog URLs in Settings). It rewrites `HostedBackgroundsModel.swift` heavily: `catalogURLs` becomes a computed property with `userCatalogURLs`, and it adds `lastChecked` / `failingSince`, `loadCatalogRows`, `addCatalog` / `removeCatalog` and `BackgroundCatalogScheduler`. It also touches `BackgroundSetsView.swift`, `BackgroundCatalogCache.swift` and `AppStateStore+BackgroundImages.swift`. Expect conflicts whichever lands second. The planner should keep the changes here small and localized: a throttle helper, a `refresh` entry point and a pure filter function. The filter must also work with several catalog sections, which is what #0577 adds.

## Root cause

The only automatic catalog check was `BackgroundSetsView`'s `.task`, which runs when the view appears, not when an already-open Background Images window comes to the front (`windowDidBecomeKey` only refreshed uses). The throttle (`lastRefresh`, 10 minutes) was in-memory only, there was no manual check besides the banner's Retry, and no filter.

## Fix

- `HostedBackgroundsModel`: `refreshInterval` is 5 minutes; a pure `isCheckDue(lastCheck:now:)` (a future last check counts as due) applied to the later of the in-memory and persisted `lastChecked`, through `refreshDue`, used by `browseAppeared` and the new `windowBecameKey()` (checks only `scheduledCatalogURLs`, never marks Browse). New `refreshAll()` (Refresh button, bypasses the throttle) with `isRefreshingAll` / `isCheckingAny`.
- `BackgroundImagesWindowController.windowDidBecomeKey` (AppKit event, outside SwiftUI updates) starts `hosted.windowBecameKey()` and exposes the task as `appearCheck` for tests.
- New pure `BackgroundCatalogFilter` (case/diacritic-insensitive match on display text; set-name match keeps all images; sections with no matches hidden while filtering).
- `BackgroundSetsView`: control row with Filter field (view-local `@State`), clear button, spinner and Refresh (disabled while any check runs); "No backgrounds match" empty state.
- Website and Concepts copy updated.

- Two sets can't share an image, by design: `BackgroundCatalogParser.parse` rejects a catalog in which the same resolved `full` URL appears twice (`BackgroundCatalog.swift`, `fullURLs.insert`; #0574 decision 12, "an image's identity is its resolved `full` URL, unique within a catalog", and `website/backgrounds.html` line 309).
