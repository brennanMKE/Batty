## Description

Found in #0694's review. When Batty shares a server on the tailnet and finds an identical `tailscale serve` mapping already there that it didn't create, it "adopts" it: shows the URL but never records the port in `owned`, so it will never turn the mapping off (safe by design: Batty never removes mappings it didn't make).

Stop Sharing (row menu, `batty server tailnet --off`, MCP `server_tailnet`) on that adopted row then reports success and clears the row's URL, but the mapping stays served on the tailnet. The docs promise the opposite: `--off` "refuses one it didn't [make]".

### Verified (2026-11-19, `main` at 46d4e0e2)

- `BattyKit/Sources/BattyKit/Runtime/TailnetSharing.swift:186-187` — identical existing mapping is adopted; log says "Batty won't turn it off"; `owned` is not set.
- `TailnetSharing.swift:208` — `unshare` passes `adopted: entry?.tailnetURL != nil`.
- `TailnetSharing.swift:222-223` — `performUnshare` with no `owned[port]` and `adopted == true` returns `.success(())` without running anything, so the `notOurs` refusal is skipped.
- `TailnetSharing.swift:210-211` — on success the row's `tailnetURL` is cleared, so the UI says "not shared" while the tailnet still serves the port.
- `docs/batty-cli-design.md:140` — "`--off` turns off a mapping Batty made and refuses one it didn't."

## Resolution notes

> 🟢 Resolved 2026-11-19 — Stop Sharing, `batty server tailnet --off` and MCP refuse an adopted tailnet mapping with the `tailscale serve … off` command and keep its URL, and quit cleanup now actually turns off owned mappings.

## Root cause

`TailnetSharing.performUnshare` treated an adopted port (URL shown, port not in `owned`) as a silent success, and `unshare` then cleared the row's URL, so Stop Sharing looked like it worked while the mapping stayed served. Adoption wasn't recorded anywhere except as "has a URL but isn't owned".

Second, found while writing the quit-bound test: `removeOwnedMappingsSynchronouslyForQuit` never removed anything. `turnOff` is `nonisolated` but read the main-actor `static let commandTimeout`, so the detached task hopped to the main actor, which the semaphore wait was blocking. Quit cleanup always ran out the 5 s and left every owned mapping served (confirmed: `quitCleanupReportsCompletion` failed with a 1 s and 5 s bound until the fix).

## Fix

As planned: `ServerEntry.isTailnetAdopted`, set from `performShare`'s result; `performUnshare` returns `.notOurs(port)` at once for an adopted entry regardless of `reportForeign` and runs no argv; `unshare` keeps the URL on failure; `notOurs` message names `tailscale serve --bg --https=N http://127.0.0.1:N off`; `ServerEntryDisplay.tailnetMenuAction` drives the row menu, which shows a disabled "Shared on Tailnet outside Batty" for adopted rows; Copy Tailnet URL help notes it; docs line 140 updated; `quitWait` seam and `Bool` return on the quit cleanup.

Divergence: `TailnetSharing.commandTimeout` is now `nonisolated static let`, fixing the quit-cleanup deadlock above.

## Review

Approved first pass. Checked the quit path: the detached task calls only `nonisolated` code (`turnOff`, `TailscaleArgs`, `TailscaleServeConfig`, `ProcessTailscaleCommandRunner`, `ProcessSignal`, file-scoped `nonisolated` loggers), and `commandTimeout` is an immutable `Duration`, so `nonisolated static let` is sound. `quitCleanupReportsCompletion` blocks the main actor on the real semaphore, so any remaining main-actor hop would time out and fail it; the timeout test injects `quitWait` and does no real waiting. Adopted refusal runs no argv and keeps the URL in all three entry points. No `tailscale serve` was run on the host.

## Plan

Planned 2026-11-19 against `main` at b97efef8. Every premise is confirmed (`TailnetSharing.swift:186-188, 208, 222-223, 210-211`; `docs/batty-cli-design.md:140`). One correction: no separate MCP `server_tailnet` handler exists. The CLI and MCP both reach `AppStateStore.tailnetServerForXPC` (`AppStateStore+Server.swift:290`), so fixing `TailnetSharing.unshare` covers all three entry points. The existing test `anIdenticalPreexistingMappingIsAdoptedButNeverTurnedOff` currently asserts the bug (`tailnetURL == nil` after unshare).

### Files and approach

1. **`BattyKit/Sources/BattyKit/Runtime/ServerEntry.swift`**: add `public internal(set) var isTailnetAdopted = false` next to `tailnetURL`, with a doc comment: the URL is served by a mapping Batty found and didn't make, so Batty never turns it off.
2. **`BattyKit/Sources/BattyKit/Runtime/TailnetSharing.swift`**
   - `performShare` returns whether it adopted the mapping, e.g. `Result<(url: URL, adopted: Bool), TailnetError>` or a small private struct. It reports `adopted: owned[port] == nil` on the `isOurs` early return and `false` after a successful `serveOn`. In `share`'s success branch, write `entry.isTailnetAdopted` with an equality guard, matching the existing guarded writes. The public return type `Task<Result<URL, TailnetError>, Never>` stays the same.
   - `unshare`: pass `adopted: entry?.isTailnetAdopted == true` instead of `entry?.tailnetURL != nil`. In the success branch, also clear `isTailnetAdopted` with a guard. On failure, keep `tailnetURL` as it is.
   - `performUnshare`: when `owned[port] == nil && adopted`, return `.failure(.notOurs(port))` at once, **regardless of `reportForeign`**, and run no argv. The `reportForeign && !adopted` path for a foreign mapping stays unchanged. `entryRemoved` passes `entry: nil`, so it is still a silent no-op for an adopted port. Quit only walks `owned`. Batty therefore never sends `off` for an adopted port.
   - `TailnetError.notOurs(port).message` becomes: `this tailnet mapping on port N wasn't created by Batty; remove it with tailscale serve --bg --https=N http://127.0.0.1:N off`. Build the command from `TailscaleArgs.serveOff(port:)` joined with spaces. Don't use the issue's shorter `--https=N off`: `TailscaleArgs.serveOff` documents that `off` is appended to the full `on` command.
   - Quit bound seam: add `@ObservationIgnored var quitWait: @Sendable (DispatchSemaphore, TimeInterval) -> DispatchTimeoutResult = { $0.wait(timeout: .now() + $1) }`. Make `removeOwnedMappingsSynchronouslyForQuit` `@discardableResult` and return `Bool` (true if it finished). Production behaviour is unchanged.
3. **`BattyKit/Sources/BattyKit/Views/ServersListView.swift`** (`rowMenu`): when `entry.isTailnetAdopted`, don't show "Stop Sharing on Tailnet". Show a disabled item instead, "Shared on Tailnet outside Batty" (`servers.row.tailnet-adopted`). Copy Tailnet URL stays. Its `.help` becomes "Copy Tailnet URL (this mapping wasn't created by Batty)" when adopted. Don't add a line of text to the row. Put the branch in a pure helper, `ServerEntryDisplay.tailnetMenuAction(hasURL:adopted:offersSharing:) -> .share | .stop | .adoptedNote | nil`, so it can be unit tested. The view reads only; it writes no observed state.
4. **`docs/batty-cli-design.md:140`**: "`--off` turns off a mapping Batty made. It refuses a mapping Batty didn't make, including an identical one Batty found already in place and showed (adopted): Batty never removes that one, not even on quit, and the error names the `tailscale serve … off` command to run."
5. **`Batty/BattyApp.swift:172`**: no change (it ignores the return value).

## Expected

Behaviour and docs agree. Recommended:

- `--off` / Stop Sharing / `server_tailnet` off on an adopted mapping is **refused** with a clear message, e.g. "this tailnet mapping wasn't created by Batty; remove it with `tailscale serve --https=N off`" (N the port), nonzero CLI exit, and the row's `tailnetURL` is kept.
- The row for an adopted mapping shows the tailnet URL (Copy Tailnet URL stays) with a short note that Batty didn't create it, and **no** Stop Sharing on Tailnet action.
- Batty never removes an adopted mapping (no `off` argv for a port not in `owned`, including quit cleanup).
- `docs/batty-cli-design.md:140` states the adopted case explicitly.
