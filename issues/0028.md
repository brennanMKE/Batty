## Description

Surface bell events outside the Bell Feed popover — both via macOS Notification Center and via inline visual indicators. Concepts → Bell event ("Visual feedback") and → System notification.

**Acceptance criteria:**
- **System notifications:** when the app is not frontmost OR when the source is in a non-active Session/Pane/Tab, post a `UNNotificationRequest`:
  - Title: `Batty — <Session> › <Pane› › <Tab>`.
  - Body: OSC 9 message if present, else `"Bell"`.
  - Tapping invokes #0027's click-to-jump flow.
- **Per-Tab dot:** SlidingTabs' `hasUnseen` is bound to `tab.unseenBellCount > 0`.
- **Per-Pane border:** subtle accent flash on bell, fading over ~1s; sustained dot/border tint when an inactive Tab in the Pane has unseen bells.
- **Per-Session sidebar badge:** small dot or count badge on the Session row when any descendant has unseen bells.
- Settings expose: notification sound on/off, system notifications on/off, per-Session mute toggle (lives in the Session context menu — see follow-up if needed).

## Notes

- `UserNotifications` framework requires a one-time prompt (`UNUserNotificationCenter.current().requestAuthorization`); handle a denied state gracefully (still show in-app indicators; just no NSC posts).
- Per-Session mute can be a UserDefault keyed by Session UUID for now; promote to Workspace persistence (#0029) if it should travel with the layout.

## Revised approach — 2026-05-08

System-notification posting can route through `GhosttyTerminal`'s `TerminalSurfaceDesktopNotificationDelegate` directly: when a surface fires OSC 9 with a body, post the system notification verbatim instead of synthesizing one from a generic "Bell" message. For BEL-only events (no body), fall back to "Bell" as the body.

Visual indicators are still our work:
- SlidingTabs `hasUnseen` dot — bind to `tab.unseenBellCount > 0` from the Concepts model.
- Pane border accent flash — a SwiftUI overlay on the `TerminalSurfaceView` driven by an `@Observable` flag in our pane wrapper, set on each bell and decayed on a 1s timer.
- Sidebar session-row badge — a SwiftUI badge driven by `session.unseenBellCount` from the model.

No changes to the acceptance criteria; just a note that the notification source path becomes simpler.

### Deferred — 2026-05-08

Depends on `#0024` for bell events (and OSC 9 desktop-notification events specifically) — same delegate-plumbing blocker. ## Root cause

After #0025/#0026/#0027 the bell pipeline was complete from event capture through popover and click-to-jump, but the user only noticed bells if they actively opened the popover. There was no system notification, no visual cue on the tab/pane/sidebar, so a bell in a background tab was silent until the user happened to look.

## Fix

Three independent surfaces, all reading the data populated by #0025:

**System notifications** via `UserNotifications.framework`:
- `BellNotifier` (new, @MainActor) wraps `UNUserNotificationCenter`. `ensureAuthorization` requests `[.alert, .sound]` once per process; results are remembered.
- `post(for: entry, sessionTitle:, paneIndex:, tabLabel:)` builds a `UNMutableNotificationContent` with title `"Batty — <Session> › Pane <N> › <Tab>"`, body = entry.message or `"Bell"`, and `userInfo = [entryIdUserInfoKey: entry.id.uuidString]`.
- `BellNotifierDelegate` (private NSObject conforming to `UNUserNotificationCenterDelegate`):
  - `willPresent` returns `[.banner, .sound]` so banners appear even while the app is foregrounded.
  - `didReceive` decodes `userInfo[entryIdUserInfoKey]` into a UUID and calls back to a stored `onTapEntry` closure on the main queue, then `NSApp.activate(ignoringOtherApps: true)`.
- `AppStateStore.notifier: BellNotifier?` (`@ObservationIgnored`); `recordBellTick` and `recordDesktopNotification` call `postNotification(for: entry, at: location)` after recording. Posting is gated on `!NSApp.isActive || !entry.seen` — if the app is foreground AND the source is the focused tab, no banner.
- `RootWindowView.task` constructs the notifier on first appear with a closure that calls `store.markBellSeen` then `store.jumpToBellEntry` on tap. `ensureAuthorization` is invoked from the same callback.

**Visual indicators**:
- `PaneView`'s `DefaultTabChip` `hasUnseen` parameter now binds to `tab.unseenBellCount > 0` so SlidingTabs renders its built-in unseen dot.
- `PaneView` gets a second 2pt accent-color `RoundedRectangle.strokeBorder` overlay (independent from the existing drag-hover one) whose opacity flashes to 1 on bell and animates back to 0 over 1s via `withAnimation(.easeOut(duration: 1.0))`. The trigger is `.onChange(of: pane.tabs.map(\.bellCount).reduce(0, +))` — any tab in the pane ringing causes the flash.
- `SessionRow` in `SessionSidebarView` adds a trailing capsule badge with the numeric `session.unseenBellCount` (in white-on-accent) whenever it's positive, with a help-text describing how many events.

## Gotchas

- **`UNUserNotificationCenter` authorization is asynchronous.** First-launch behavior: the user sees a one-shot system prompt; until they grant, banners don't post. The granted state is cached on `BellNotifier` for the session but not persisted — denied or restricted state means no banners but visual indicators still work, which is the documented graceful-degradation path.
- **`willPresent → [.banner, .sound]`** intentionally posts banners even when foregrounded. Without this, the user wouldn't see banners while looking at Batty — they'd only see them in other apps. With the focused-tab gate (`!entry.seen`), foreground banners only fire for non-focused-tab events, which is the desired behavior.
- **The bell-flash overlay watches the `bellCount` sum across all tabs in the pane,** not per-tab. A burst of three bells in the focused tab is one flash; a bell in tab A followed by a bell in tab B is two flashes. This matches "the pane is ringing" rather than "tab N is ringing", which is the right level given that the chip's hasUnseen dot already covers per-tab.
- **Session-row badge is a numeric count, not a dot.** PRD §6.13 says "small dot or count badge" — picked count for v1 because it conveys severity. If the count gets noisy at scale (10+), revisit a max-9-then-9+ truncation or fall back to a dot.
- **`BellNotifier` lives on `AppStateStore` as `@ObservationIgnored`** so SwiftUI doesn't try to observe it. The `notifier` reference itself doesn't change after `setUpNotifier` runs once; if it ever needs to swap (e.g., for tests), make it `weak` or rebuild the store.
- **System notification settings (sound on/off, per-session mute, system-on/off toggle)** from the AC are intentionally deferred to #0034 (Settings window). The UI surface to toggle them needs to exist before the toggle has any meaning. Until then the behavior is "always banner, always sound, no per-session mute".
- **`BellNotifierDelegate` is `@unchecked Sendable`** because `UNUserNotificationCenterDelegate` requires NSObject conformance and Swift 6 can't prove the closure-only state is safe across actors. The delegate only reads `onTapEntry` (immutable after init) from the notification center's callback and dispatches synchronously to the main queue, so the marking is correct.
