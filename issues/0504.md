## Description

Projects (#0469) is finished on `main` but still sits behind `FeatureFlags.projects`, so Prod has none of it: no File menu items, no Sidebar entries, no palette or Open Quickly rows, no `batty project`, and no `projects.json`. The user has authorized the 1.3.0 release, which ships Projects. `AGENTS.md` "Release branches" says to remove the flag in the release that ships the feature. This issue does that. Projects becomes always on in Prod and Beta, the flag-off tests go, a Help page for Projects lands, and the docs stop calling Projects Beta-only.

This is the flag-removal issue that #0469's Acceptance criteria require ("The flag-removal issue for the 1.3.0 release is filed when this umbrella's children resolve. That issue removes the flag, adds shortcuts if the user wants them, and adds the Help page"). #0469's open question 2 deferred all `Help/` content to this issue.

## Decisions

### 1. Delete the `FeatureFlags` type, not just its `projects` property

`projects` is the only flag. An empty `FeatureFlags` struct, an `AppStateStore.featureFlags` property and a `featureFlags:` init parameter that carry nothing would be dead code, and every test that constructs an `AppStateStore` would keep passing an empty value. Delete `BattyKit/Sources/BattyXPCCore/FeatureFlags.swift`. Remove `AppStateStore.featureFlags`, the init parameter, and every parameter that only carried the flag (`flagOn:`, `projectsEnabled:`, `featureEnabled:`, `featureFlags:`, `flags:`, `includingProjects:`). Also delete `ProjectOpenError.featureDisabled` and its `errorDescription` case, since nothing can produce it any more.

The next flagged feature re-adds a `FeatureFlags` struct from the recipe kept in `docs/feature-flags.md` (Docs, below). `ServiceNames.Variant` / `ServiceNames.current` stay. They have other users.

### 2. Every gate collapses to its flag-on branch

For each site below, keep exactly what the code does today with the flag on (Batty Beta) and delete the flag-off branch. No behaviour visible in Beta changes. Prod gains the Beta behaviour.

- **`AppStateStore.projectStore` becomes non-optional** (`ProjectStore`, still built lazily on first access from `projectsFileURL`). Lazy construction is what keeps `projects.json` from being touched until a Projects surface reads it. That remains the rule (`Concepts.md` `## Project`, "written only on explicit user action"). Remove the `let projectStore` unwraps that only existed for the flag-off nil. If a site's nil branch also covers some other condition, keep that condition and say so in the Work log.
- The XPC `projectList` / `projectOpen` verbs are always handled. The `unknown verb` replies at `AppXPCService.swift:411-414` and `:428-431` go away. A verb the app has never heard of still gets `unknownVerbResponse` (`ProjectXPCTests.aVerbTheAppNeverHeardOfStillGetsTheSameWording` keeps passing).
- The CLI tree always contains `ProjectNounCommand`. `batty capabilities` always lists `project list`, `project open` and exit code 8.
- The Sidebar row icon is always `circle.fill` for a plain Session and the Project's symbol for a Project-backed one. Delete `SessionRowIcon.legacySystemName` and the `rectangle.split.3x1` branch of `SessionRowIconView`, as `docs/feature-flags.md` already instructs. The `BATTY_UI_TEST_SIDEBAR_ICONS` value suffix is a test seam, not a gate, and stays.

### 3. Shortcuts stay unchanged

No `ShortcutAction` case is added. #0469's Acceptance criteria and its "Entry points" list ("No new keyboard shortcuts … while the feature is flagged", reasoning in `projects-proposals.md` §4.3) left shortcuts for this issue to add *if the user wants them*. The user has not asked for any, so this issue adds none. The in-sheet ⌘E / ⌘N / ⌥↩ handlers in the Open Project picker and Open Quickly are not `ShortcutAction`s and are unchanged. Record this in the resolution. Adding Projects shortcuts later is a separate issue.

### 4. The Help page is `Help/10-projects.md`, listed before the licenses page

Add `BattyKit/Sources/BattyKit/Help/10-projects.md` and a `HelpCatalog` entry `.init(id: "10-projects", title: String(localized: "Projects"), resourceName: "10-projects")`, inserted **before** the `09-third-party-licenses` entry so the licenses page stays last in the Help sidebar. Don't rename `09-third-party-licenses.md`, because three docs and a test name its path. The filename number then doesn't match the display order. That is deliberate, and the Work log says so.

## Help page

Create `BattyKit/Sources/BattyKit/Help/10-projects.md` (Decision 4) in the voice of the existing pages (second person, short sections, `Cmd-` / `Option-` key spelling as in `05-shortcuts.md`). It covers:

- **What a Project is:** a saved recipe for a Session: name, root folder, Session color and symbol, Pane layout and kinds, each Tab's directory and optional startup command. Opening one builds that Session. Nothing is saved automatically.
- **Creating one:** File ▸ Open Project ▸ New Project…, or File ▸ Save Session as Project… / the Sidebar row's **Save as Project…** to start from the current Session. Then the Project Editor (File ▸ Edit Projects…).
- **Opening one:** File ▸ Open Project ▸ <name>, Choose Project…, the briefcase button at the bottom of the Sidebar, the Command Palette's **Open Project: <name>** rows, and Open Quickly. Return opens it, or switches to its Session if one is open. Option-Return opens another copy.
- **Open Quickly** (#0491 and #0499's owed text, verbatim): "If you have saved Projects, Open Quickly also lists them: type a Project's name and press Return to open it as a Session (or switch to it if it is already open); Option-Return opens another copy, or press Option-Return on one of its Session's Tabs."
- **Startup commands and the trust prompt:** the "Run startup commands when the Project opens" toggle; the confirmation sheet shown the first time and whenever a command changes; "Don't ask again until the commands change"; the waiting indicator with Run Now / Dismiss when a shell never reports its directory.
- **Shared:** the checkbox marks a Project as one you intend to sync. Say plainly that today it is stored on this Mac only. Don't promise iCloud sync, because #0503 is parked.
- **CLI:** `batty project list` and `batty project open <name> [--new]`, pointing to the CLI docs.

Also add a line to `Help/02-sessions.md` beside "Click `+` at the bottom of the sidebar": the briefcase button next to it opens a Project (owed by #0490, `issues/0490.md:103`).
