## Description

Child of #0689. User decision C (2026-11-19): "The CLI tells Batty to share/track a localhost server (e.g. `batty server share --port N`), and it also opens a Process Status view to watch the server process. CLI can terminate or restart servers Batty manages." With the Server Pane gone (#0691), the `server` noun needs a grammar built around the Servers list.

### Current state (checked against `main` at `94b038c1`)

- `batty server start --port N -- <cmd>` (runs the command in a new terminal Pane, then shows a Server Pane), `attach --port N [--command C --cwd D]`, `serve <dir>`, `stop`, `restart` target a Server Pane id (`BattyKit/Sources/batty/ServerCommand.swift`; XPC in `AppStateStore+Server.swift`). After #0691 they register in the server registry instead.
- Process Status Pane: `batty pane split --view process-status --pid <pid>` (#0301/#0305), `PaneSplitRequest.viewOptions`.
- `ListeningPortScanner.listeners(port:)` finds the pid listening on a port (#0648).
- Stop safety (#0648, #0658): a terminal-backed server is stopped (SIGINT → SIGTERM → SIGKILL to the job's process group) only when the listener is provably a job of that terminal Pane's own shell.

## Resolution notes

> 🟢 Resolved 2026-11-19 — `server share/list/unshare` replace `attach`, servers get a Process Status Pane, and only Batty-started servers can be stopped or restarted.

## Root cause

Feature work. Starting state (`main` at `e74bce4a`): the `server` noun had `start`/`attach`/`serve`/`stop`/`restart`. `attach` registered an `ExternalProcessServerBackend` that Batty *could* stop (tree stop) and restart (with `--command`), there was no `list`/`unshare`, and no server opened a Process Status Pane.

## Fix

Followed the Plan's grammar and behavior:

- Wire: `ServerShareRequest` replaces `ServerAttachRequest`; `ServerStartRequest` drops `statsURL`, gains `name`/`processView`; new `ServerKind`, `ServerListItem`, `ServerListReply`; `ServerReply` gains optional `name`/`kind`/`processPaneID`. Verbs `serverShare`, `serverList`, `serverUnshare` (no `serverAttach`).
- `ExternalProcessServerBackend()` takes no parameters, can neither stop nor restart, `stopDecision` is `.nothing`. `ServerEntry.convert(to:)` deleted. `ServerEntry` gains `customName` (observed, read first by `ServerEntryDisplay.name`), `processStatusPaneID`, `wantsProcessStatus`, `onListenerChange` (fired from `performTick` when `listenerPid` changes to a found pid).
- Store: `shareServerForXPC` (async; one-shot scan via the new injectable `AppStateStore.serverPortScanner`, `.nothingListening` when empty), `unshareServerForXPC`, `listServersForXPC`, `unshareServer(_:)` (row menu), `ensureProcessStatusPane`, `serverListenerChanged` (wired in `registerServer`; retargets an open Pane, opens one below the terminal Pane only on a `start`'s first listener, never reopens a closed one). `stop`/`restart` refuse `external` with `.notManaged`; `start` on a still-listening shared port fails `.portShared`, otherwise takes it over with `replaceBackend`.
- CLI: `ServerShareCommand`, `ServerListCommand` (tab-separated lines or JSON), `ServerUnshareCommand`; `start` gains `--name`/`--no-process-view`, loses `--stats-url`. Capabilities archetypes `share` (idempotent) and `unshare` (not destructive, not idempotent); `server list` uses `list`. MCP hint names `server_share`.
- Servers list: Remove from List (`servers.row.unshare`) for external rows.
- Docs: `batty-cli-design.md` §1.1, `design/servers-list.md`, `batty-cli-agent-workflows.md`, `batty-cli-install.md`, `Concepts.md`, SKILL.md, and `AgentContextNote` (the shared agent prompt that the skill and workflows doc must carry verbatim) swap `attach` for `share`.

Deviations:
- `MCPToolCatalogTests.timeoutSchemaCarriesTheMaximum`: the Plan said to swap `server_attach` for `server_share`, but `share` has no `--timeout`, so `server_attach` was dropped from the arguments instead (`server_start` still covers the server noun). Added `noServerAttachTool`.
- `ServerRegistryTests.nameIsTheCommandsProgram` used `ExternalProcessServerBackend(command:)`; it now uses a `TerminalTabServerBackend` with that command.
- Code landed in one commit rather than the Plan's three.
- `ServerReply.pid` keeps its previous meaning (listener pid when known).

## Plan

Written 2026-11-19 against `main` at `e74bce4a` (#0691 merged). Premises checked: `ServerCommand.swift` has `start`/`attach`/`serve`/`stop`/`restart`. `AppStateStore+Server.swift` has `startServerForXPC`, `attachServerForXPC`, `stopServerForXPC` and `restartServerForXPC`. `ServerRegistry` is one app-wide registry, one entry per port. `ExternalProcessServerBackend` (attach) **can** be stopped today: `canStop` is true and it uses a tree stop through `ServerJobResolver.planTreeStop`. It can be restarted when `--command` was given. `pane split --view process-status --pid` pins a pid (`ProcessStatusPaneContent.Target.pinned`). `retarget(to:)` exists. `findUniquePane` matches any visible Pane of the kind in the Session and ignores the pid, so `share` can't reuse it as is. Entry ticks already stop when the registry is empty (AC 4 holds today).

### Grammar (decided; amends "Expected behavior")

```
batty server share   --port N [--name S] [--url U] [--split right|down] [--pane P] [--no-process-view] [--json]
batty server start   --port N [--name S] [--url U] [--split right|down] [--pane P] [--no-process-view] [--wait [--timeout S]] [--json] -- <command…>
batty server serve   [<dir>] …                       (unchanged here; #0693 reworks it)
batty server list    [--json]
batty server stop    (<id> | --port N) [--json]      managed servers only (terminal, static)
batty server restart (<id> | --port N) [--json]      managed servers only
batty server unshare (<id> | --port N) [--json]      shared servers only; signals nothing
```

Reasons:
- **`share` replaces `attach`, which is removed, with no hidden alias.** The `server` noun exists only in Beta, behind the `servers` flag, so no shipped user depends on `attach`. An alias would add a sixth verb to the capabilities list, the MCP tools and the tests for one release. `attach --command/--cwd` (Restart of a process Batty didn't start) is dropped: decision C says the CLI stops or restarts only servers Batty *manages*. To make a shared server managed, stop it yourself and run `server start` on the same port (below).
- **`unshare`, not `stop`, for shared servers.** It is the inverse of `share`, and it can't be confused with signalling.
- **`--no-process-view`**, not `--no-watch`. It names the thing it suppresses, and `--no-watch` would sit one letter away from `--wait` on `start`. `share` and `start` both take it.
- `--stats-url` is dropped from `start` and `share`. It has had no effect since #0691, and the `server` noun is Beta only. `start` keeps `--split`/`--pane`.
- `--name S` overrides the row name on `share` and `start` (`ServerEntry.customName`, read first by `ServerEntryDisplay.name`).
- Hook for #0694: `share` and `start` gain `--tailnet` later. The wire requests are plain Codable structs, so #0694 adds a `tailnet: Bool?` field with no migration. `ServerListItem.tailnetURL` ships now, nil until #0694. `ServerRegistry.remove(id:)` is the single exit point for entries (stop/finish, `unshare`, teardown). #0694 hooks its mapping removal there.

### Behavior

- **share**: the flag must be on. The store runs a one-shot scan, `serverPortScanner.listeners(port:)` (new `@ObservationIgnored var serverPortScanner: PortListenerScanning = SystemPortListenerScanner()` on `AppStateStore`, injected in tests). If the scan finds nothing, the request fails with `.nothingListening(port)`: "nothing of yours is listening on 127.0.0.1:N". Nothing is registered and no Pane opens. If an entry already holds the port, whatever its kind, `share` returns it with `created: false` and applies `--name` if given. Otherwise it registers an `external` entry (`ExternalProcessServerBackend()`). In both cases, unless `--no-process-view`, it calls `ensureProcessStatusPane(for:pid:anchor:direction:)` with the scanned pid.
- **ensureProcessStatusPane** (new, `AppStateStore+Server.swift`): the entry remembers `processStatusPaneID` (`@ObservationIgnored`).
  - If that Pane still exists: retarget it to `.pinned(pid)` when its target differs, then reuse it. A repeated share never opens a second Pane.
  - Otherwise: `splitPane(id: anchor, direction:, kind: .processStatus, processStatusPid: pid)`, then restore the Session's `focusedPaneID`, as `makeServerTerminal` does. The keyboard stays in the caller.
  - The anchor is `--pane` / `BATTY_PANE_ID` / the focused Pane. If no Pane resolves, the share still succeeds and `processPaneID` is nil. An explicit `share` after the user closed the Pane opens a new one.
- **start**: as today. In addition, `ServerStartRequest.processView != false` sets `entry.wantsProcessStatus`. A new entry callback, `onListenerChange: ((ServerEntry, pid_t) -> Void)?` (`@ObservationIgnored`, set in `registerServer`), fires from `performTick` when `listenerPid` changes to a non-nil pid. The store's handler acts as follows:
  - First listen with `wantsProcessStatus`: open the Process Status Pane split **down** from the server's terminal Pane, so the caller gets one new column, not two. Fall back to `anchorPaneID`. Clear `wantsProcessStatus`.
  - Later pid changes (Restart, a file watcher re-binding): retarget an existing `processStatusPaneID` Pane to the new pid. Never reopen a Pane the user closed.

  The same handler retargets the Pane for shared servers. This runs from the tick `Task`, not from view code, so it is a scheduled write that can't land inside a layout pass (`docs/swiftui-observation-rules.md`). Don't hop it into a further `Task`.
- **start on a shared port**: if the external entry is listening, fail with `.portShared(port)`: "port N is held by a shared server Batty didn't start; stop that process, then run server start". If it isn't listening, take it over with `entry.replaceBackend(terminalBackend)`. Delete `ServerEntry.convert(to:)`, whose only caller was this path, along with its stop-then-swap logic.
- **stop / restart**: `resolveServer` as today, then refuse `external` with `.notManaged`: "this server was shared, not started by Batty, so Batty won't signal it; use batty server unshare to remove it from the list". Terminal and in-app behavior is unchanged: the #0648/#0658 ownership proof, `stopRefusal` and the re-identification `check` before each signal.
- **ExternalProcessServerBackend**: `init()` takes no parameters. `command`/`workingDirectory` are nil, `canStop`/`canRestart` are false, and `stopDecision` returns `.nothing`. The ticks then no longer compute a tree-stop plan for a process Batty won't signal.
  - Leave `ServerJobResolver.planTreeStop`, `StopTarget.processTree` and `ProcessGroupStopper`'s tree handling in place. The in-app teardown test backend still uses them, and #0693 (which removes the in-app server) decides whether they go. Note this in `## Gotchas`.
- **unshare**: resolve as stop does. A managed entry is refused with `.managedServer`: "Batty started this server; use batty server stop". An external entry gets `servers.remove(id:)` and no signal. The Process Status Pane stays: it is the user's Pane now and tombstones when the process exits. The reply is the entry as it stood, with `state` unchanged.
- **list**: new verb `serverList`, no request payload. Reply `ServerListReply { servers: [ServerListItem] }`. `ServerListItem` fields: `serverID`, `name`, `port`, `kind` (`terminal | external | static`, a new `ServerKind` wire enum; `inApp` maps to `static`, the name #0693 keeps), `state`, `url`, `tailnetURL?`, `pid?`, `terminalPaneID?`, `processPaneID?`. Items are in registration order. Plain output has one line per server: `<id>\t<name>\t<port>\t<kind>\t<state>\t<url>`, plus `\t<tailnetURL>` when one is set. With no servers it prints nothing and exits 0.
- **Replies**: `ServerReply` gains `name`, `kind` and `processPaneID` (all optional, so older readers still decode it). The plain output is still the server id. The CLI's `share` no longer prints the "nothing is listening yet" stderr line, because share now fails instead.
- **Servers list row** (`ServersListView`): for `external` rows only, the "…" menu gets **Remove from List** (`servers.row.unshare`), calling a new `AppStateStore.unshareServer(_:)`. This is an event-origin button action. A shared server never leaves the list on its own (its process can re-bind under a watcher), so without this item the GUI has no way to clear a dead shared row. User sign-off item.

## Expected behavior

> **Amended by `## Plan` (2026-11-19):** `attach` is removed (no alias); the opt-out flag is `--no-process-view`; `unshare` is refused for managed servers; `start` on a still-listening shared port fails. The Plan's Grammar block is authoritative.

Proposed grammar (the plan confirms or amends it; any change is recorded here before implementation):

- `batty server share --port N [--name S] [--no-process-view]` — tracks a server already listening on `127.0.0.1:N` (fails clearly when nothing listens), adds it to the Servers list, and opens a Process Status Pane on the listener's pid beside the caller (`pane split --view process-status --pid`, reusing `--unique`-style matching so a second share of the same port opens no second Pane). Prints the server id. Replaces `attach` (kept as a hidden alias for one release, or removed; plan decides with the user if unsure).
- `batty server start --port N -- <cmd>` — as today it runs the command in a terminal Pane, then registers the server and opens the Process Status Pane once the port listens. Prints the server id.
- `batty server list [--json]` — id, name, port, kind, state, localhost URL, tailnet URL.
- `batty server stop <id|--port N>` / `restart <id|--port N>` — **managed** servers only: `terminal` kind (with #0658's ownership proof) and `static` kind (#0693: the user-installed PhotonHTTP CLI running in a terminal Pane, stopped under the same ownership proof). An `external` (shared) server can't be stopped or restarted; `stop` on it fails with a message, and `batty server unshare <id|--port N>` removes it from the list without signalling anything.
- Capabilities `inputSchema`/annotations for each verb (`destructiveHint` on `stop`/`restart`), so the MCP tools follow; `CapabilitiesInputSchemaTests` drift oracle updated.
