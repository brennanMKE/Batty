## Description

Regression cluster from the #0256 sidebar pane tree, observed live (see screenshot and log):

1. **The app reaches a "No Session Selected" state that should be impossible.** With one session ("Session 1", three panes) the detail area shows the No Session Selected placeholder while the sidebar still lists the session and its panes. The log shows the cause directly:

   ```
   selectedSessionID changed: 320B9A05-… → D861187E-…   ← D861187E is a PANE id
   applyActiveSessionTheme: no selected session
   allPanes.count changed → 0; re-applying theme
   focus skipped: tab 5B532DAA-… had no visible AppTerminalView after 5 retries
   ```

   `D861187E…` and `0C8011FD…` appear elsewhere in the same log as **pane** ids (`focusPane: 0C8011FD-… -> 96640D63-…`). Pane ids are being written into `selectedSessionID`.

2. **Duplicate hide/show indicators on each sidebar pane row.** A leading `eye`/`eye.slash` status icon *and* a trailing eye toggle button — two eyes per row.

3. **The session's pane list must be expandable/collapsible — even with a single pane.** #0256 intended this; what shipped shows pane rows only when a session has >1 pane, with no way to collapse them. Wanted: a chevron on the session row — pointing **right when collapsed, down when expanded** — that **animates** on tap, present for every session regardless of pane count.

4. **Requirement (re-stated from #0256): a session must always have ≥ 1 visible terminal.** The guard exists (`WindowRuntime.hidePane` refuses the last visible pane; both eye buttons disable) and is covered by `PaneHideTests` (`cannotHideLastVisiblePane`, `…WhenOthersAreHidden`, `windowRuntimeRefusesHidingLastVisiblePane`). The apparently-empty window in the screenshot is item 1, not a guard failure — but the invariant gains a second layer here: with selection validated, a window with sessions can never render the empty state at all.

## Root cause

*(Item 1, the selection leak — items 2/3 were design gaps, not defects.)*

`SessionSidebarView` binds `List(selection: $windowRuntime.selectedSessionID)` (a `UUID?`). The pane rows added by #0256 carry a code comment claiming they are "non-selectable — they carry no List tag", but on macOS **`List` derives an implicit selection value from each row's `ForEach` identity even without an explicit `.tag()`**. The pane `ForEach` is keyed by `pane.id` — a `UUID` that type-matches the selection binding — so clicking a pane row (including near its eye button) writes the *pane's* id into `selectedSessionID`. No layer validates the write; `selectedSession` finds no matching session → placeholder UI, `applyActiveSessionTheme: no selected session`, `allPanes.count → 0`, and focus retries that fail because the session content is unmounted. Clicking empty sidebar space (or Esc) can likewise write `nil`.

## Fix

- **Validated selection write path:** the sidebar `List` binds through `WindowRuntime.setSelectedSession(id:)` — rejects ids that aren't sessions of this window and rejects `nil` while sessions exist; idempotent on equal values (equal-value writes on `@Observable` still notify, #0229). Invariant: `selectedSessionID` is `nil` iff `sessions` is empty. SwiftUI re-reads the binding getter after a rejected write, so the List snaps back to the real selection. All writes remain event-origin per `docs/swiftui-observation-rules.md`.
- **Pane rows genuinely non-selectable:** `.selectionDisabled()` on each pane row.
- **Pane rows have a deliberate tap action** (event-origin): select the owning session, un-hide the pane if hidden (#0256's "selecting a hidden pane's row restores it"), focus the pane.
- **Single eye per row:** the leading status icon is gone; the trailing button is the one control and shows **state** (`eye` = visible, `eye.slash` = hidden), layers-panel style. Hidden rows keep the secondary text color.
- **Chevron expand/collapse:** `SessionRuntime.isPaneListExpanded` (collapsed by default, not persisted); a chevron button on every session row (`chevron.right`, rotating 90° when expanded, animated via `withAnimation(.easeInOut(0.18s))`); pane rows render only while expanded, for any pane count. `hidePane` auto-expands the owning session's list so a just-hidden pane's restore control is reachable; a refused hide (last visible pane) does not expand.
- **≥1 visible:** no code change needed — the `hidePane` guard was verified present and already covered by three `PaneHideTests`; selection validation closes the "empty window" presentation of the bug.

## Gotchas

- **macOS `List` selects rows by ForEach identity even without `.tag()`.** Any row whose identity type matches the selection binding's type is implicitly selectable; "I didn't add a tag" is not protection. Either `.selectionDisabled()` the row or validate at the binding — this fix does both.
- The chevron/expansion state is **not persisted** (resets to collapsed on relaunch); if #0221 workspace persistence wants it, serialize `SessionRuntime.isPaneListExpanded` alongside `Pane.isHidden`.
- Pane rows are now hidden by default for split sessions (previously always shown when >1 pane). The `hidePane` auto-expand keeps the restore path discoverable; if this default feels wrong in use, flip the `isPaneListExpanded` initial value.
