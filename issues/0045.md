## Description

`xcodebuild -scheme Batty -destination 'platform=macOS' build` fails with five errors, all in `BattyKit/Sources/BattyKit/TabRuntime.swift`:

```
TabRuntime.swift:62:33: error: value of type 'TerminalViewState' has no member 'bellCount'
TabRuntime.swift:67:31: error: value of type 'TerminalViewState' has no member 'lastBellAt'
TabRuntime.swift:74:33: error: value of type 'TerminalViewState' has no member 'lastDesktopNotificationAt'
TabRuntime.swift:80:29: error: value of type 'TerminalViewState' has no member 'lastDesktopNotificationTitle'
TabRuntime.swift:81:28: error: value of type 'TerminalViewState' has no member 'lastDesktopNotificationBody'
```

Bell-event observation in `TabRuntime` (added during the `#0024` / `#0028` work) reads these properties as the data source for bell counters, desktop-notification metadata, etc. The properties are part of `#0044`'s scope — extending `TerminalViewState` with the missing delegate conformances + published properties.

## Root cause

`#0044`'s fork-side work was never executed. The local fork at `/Users/brennan/Developer/brennanMKE/libghostty-spm` is still pristine upstream (latest commit `f10e02d chore: autopublish 2026-05-04T07:33:38Z`; only `main` exists; no `batty-delegates` branch). Meanwhile the Batty side has accumulated `#0024`, `#0025`, `#0026`, `#0027`, `#0028` (bell feed), `#0034` (Settings UI), `#0035` (paste confirm), `#0036` (close-confirm + About), and `#0039` (release docs) — all of which lean on properties that only exist post-#0044.

So this issue is the symptom; `#0044` is the fix. They resolve together.

Once the fork lands those properties, the Batty side compiles unchanged.
- There may be **additional build errors** that only surface after the first batch is fixed (e.g., `send(_:)`, `lastCommandExitCode`, etc.). This issue captures the state at `2026-05-11`; expand the criteria if more errors emerge after the first compile pass.
- Don't "fix" by mocking the missing properties on `TerminalViewState` in BattyKit (e.g., via a wrapper) — that would just shadow the eventual upstream additions. The right fix is to land `#0044`.

## Root cause

`#0044`'s initial fork-side work (resolved Batty-side via `c24aae8` on 2026-05-09) shipped public `sendText` and the first batch of delegate conformances. Between then and 2026-05-11, additional Batty-side code (`#0024` bell hook, `#0028` system notifications, `#0034` Settings, `#0035` paste confirm, `#0036` close-confirm + about, `#0039` ship docs) accumulated references to a wider set of published properties on `TerminalViewState`:

- `bellCount: Int`
- `lastBellAt: Date?`
- `lastDesktopNotificationAt: Date?`
- `lastDesktopNotificationTitle: String?`
- `lastDesktopNotificationBody: String?`
- (Plus pre-existing `workingDirectory` and `send(_:)`)

These weren't in the fork at `c24aae8`'s point in time, so the Batty side compiled before but broke as the references piled up.

## Fix

User extended the fork's `batty-delegates` branch with commit **`ef88eed` — "Expose surface text injection and additional delegate sub-protocols on TerminalViewState"** which adds the missing published properties and conforms `TerminalViewState` to `TerminalSurfaceBellDelegate`, `TerminalSurfaceDesktopNotificationDelegate`, `TerminalSurfacePwdDelegate`, `TerminalSurfaceCommandFinishedDelegate`, and the lifecycle delegates.

No Batty-side commit was required — `BattyKit/Package.swift` was already pinned at the local fork path (`.package(path: "../../libghostty-spm")`) via `#0044`'s resolution `c24aae8`. The fork repo update is what restored the build.

## Files changed

- **Fork side (`brennanMKE/libghostty-spm`, branch `batty-delegates`):** commit `ef88eed` — touched `Sources/GhosttyTerminal/State/TerminalViewState.swift` (new published properties), `Sources/GhosttyTerminal/State/TerminalViewState+Delegate.swift` (new conformances).
- **Batty side:** none. The path-based dependency pin in `BattyKit/Package.swift` already points at the fork; SwiftPM picks up the new commit on the next resolve.
