# 0065 — Sidebar toggle is jarring: no animation, + button disappears, chevron shifts position

| | |
|---|---|
| **Status** | open |
| **Module** | Sidebar / Window |
| **Platform** | macOS |
| **First seen** | 2026-05-11 |

## Description

The sidebar collapse/expand toggle (the `NavigationSplitView` chevron button in the window toolbar, bound to `Cmd-Control-S` per `BattyCommands.swift`) has three rough edges:

1. **No animation.** Toggling drops or restores the sidebar with no transition — it just snaps. SwiftUI's `NavigationSplitView` typically animates this; we're either fighting the animation or not letting it run.
2. **The "+" button disappears.** When the sidebar is open it shows a "New Session" `+` toolbar item (`SessionSidebarView.swift` lines 39–48 — a `.toolbar { ToolbarItem { ... } }` scoped to the sidebar column). When the sidebar is collapsed, that column's toolbar contents are gone. Re-expanding the sidebar should bring the `+` back, but the user reports it doesn't appear in the same position (or at all).
3. **The chevron / sidebar-toggle button shifts position.** When the sidebar is open, the chevron sits at the leading edge of the sidebar column. When collapsed, the chevron sits at the leading edge of the detail column. That's macOS-default `NavigationSplitView` behavior, but it makes the toggle feel like a different button each time, which is what makes the rest of the toolbar (the `+`) read as "missing" rather than "moved with the sidebar."

User-facing summary: opening / closing the sidebar should look like opening / closing a drawer, not a jarring rebuild.

## Steps to reproduce

1. Launch Batty. Sidebar is open with the session list, `+` button visible in the toolbar.
2. Click the sidebar toggle (chevron). Sidebar disappears instantly — no slide / fade.
3. Click the toggle again. Sidebar reappears — `+` button is missing from its original position (or shows up only after a delay / on hover).
4. The chevron itself has moved relative to where it was.

## Expected behavior

- Sidebar collapse/expand animates over ~200ms with a standard easing curve (matches Finder, Mail, Xcode behavior). SwiftUI typically applies this automatically when `columnVisibility` changes inside `withAnimation { ... }` or when SwiftUI's default transaction animates.
- The `+` button is consistently visible whenever the sidebar is visible. Position doesn't shift between open/close cycles.
- The sidebar toggle button stays in a consistent position. Acceptable: it's the leftmost item of the merged toolbar regardless of column visibility (which is what macOS does), but the user's other toolbar items shouldn't appear to "jump" relative to it.

## Actual behavior

`RootWindowView.columnVisibilityBinding` writes `sidebarHidden = (newValue == .detailOnly)` synchronously, with no `withAnimation` wrapper. `SessionSidebarView`'s `.toolbar { ToolbarItem { ... } }` is column-scoped — when the column collapses, that toolbar item vanishes; when the column comes back, the toolbar item must re-mount and SwiftUI doesn't reliably place it in the same position as before.

The `+` "disappearance" likely has two root causes:

- **Column-scoped toolbar.** A `ToolbarItem` placed inside `SessionSidebarView` is tied to the sidebar's existence. When the sidebar collapses, the item is unmounted. On re-expand, the item is re-mounted but SwiftUI doesn't always place it back where it was, particularly with `NavigationSplitView`'s automatic toolbar merging.
- **No `placement` hint.** `ToolbarItem` without an explicit `placement:` argument is positioned by SwiftUI's default rules, which can yield inconsistent slots across column-visibility changes.

## Implementation guidance

Two angles, both small:

### Animation

Wrap the column-visibility write in `withAnimation`:

```swift
private var columnVisibilityBinding: Binding<NavigationSplitViewVisibility> {
    Binding(
        get: { sidebarHidden ? .detailOnly : .all },
        set: { newValue in
            withAnimation(.easeInOut(duration: 0.2)) {
                sidebarHidden = (newValue == .detailOnly)
            }
        }
    )
}
```

The toggle from `BattyCommands` also writes `sidebarHidden.toggle()` directly — wrap that in `withAnimation` too (or move the persistence behind a helper that animates).

### "+" button stability

Move the "+" button out of `SessionSidebarView`'s column-scoped toolbar and into `RootWindowView`'s window-scoped toolbar, with an explicit `placement:`. For example:

```swift
// In RootWindowView.body, after NavigationSplitView:
.toolbar {
    ToolbarItem(placement: .navigation) {
        Button {
            store.addSession()
        } label: {
            Label("New Session", systemImage: "plus")
        }
        .help("New Session")
        // Disable when sidebar is collapsed if the visual signal it adds-a-session-to-the-hidden-list is too confusing.
        // Or: leave enabled, since adding a session and then revealing the sidebar to see it is fine.
    }
}
```

The `.navigation` placement sits next to the sidebar toggle, so the toolbar layout (chevron — "+" — detail toolbar) stays put across collapse/expand. Drop the existing `.toolbar { ToolbarItem { ... } }` block from `SessionSidebarView`.

### Sidebar toggle position

The chevron moving is macOS's default behavior. If we want it pinned regardless of column-visibility, we'd need to provide our own toolbar item and override the default toggle behavior. That's a bigger change; v1 should accept macOS's default position behavior. The fix above (move `+` to the window toolbar with `placement: .navigation`) already makes the toggle's left/right shift less perceptible because the `+` no longer disappears from view.

## Acceptance criteria

- Toggling the sidebar (chevron click or `Cmd-Control-S`) animates the collapse/expand over ~200ms.
- The `+` "New Session" button is visible in the same toolbar slot whenever the window is visible — collapsing/expanding the sidebar does not relocate or hide it.
- The sidebar toggle (chevron) sits in a predictable position; even if macOS's default behavior moves it slightly with column visibility, the rest of the toolbar layout remains stable around it.
- Hovering the `+` button still shows its help tooltip.
- `Cmd-Control-S` (toggle sidebar) animates the same way as the chevron click.

## Out of scope

- A custom-drawn replacement for the chevron that stays pinned. Too much surface area for the issue.
- Adjusting sidebar default width / min width. Separate sizing concern if needed.
- Persisting sidebar state across launches. Already handled via `@AppStorage(SidebarPreference.hiddenKey)`.
