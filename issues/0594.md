## Description

#0592 added an all-skipped guard to `classify()` in `tools/check-report.py` (line ~244 on `issue/0592`). The guard runs for both `--stage unit` and `--stage ui`. Its detail string always says `no tests ran (N skipped; slow tests need --full)`.

For UI runs that hint is wrong. Take a VM run filtered to only on-request UI tests, such as `BattyUITests/DemoSceneTests` without `BATTY_UI_DEMO=1`. It ends with `CHECK UI: ERROR (… slow tests need --full)`. `--full` is a unit-tier flag and does nothing for UI tests. Exit code 2 is still right, since zero tests ran. Only the hint misleads.

Found by the #0592 reviewer (`issue/0592`, `issues/0592.md` `## Review`). Fix this after #0592 merges.

## Resolution notes

> 🟢 Resolved 2026-11-12 — an all-skipped UI run now hints at the on-request opt-in env (`BATTY_UI_DEMO=1`) instead of the unit-only `--full`.

## Root cause

The all-skipped guard in `classify()` (`tools/check-report.py`) used one detail string for every stage, `no tests ran (N skipped; slow tests need --full)`. `--full` only opens the slow unit tier, so the hint was wrong for `--stage ui`.

## Fix

`classify()` picks the hint by stage: `ui` gets `on-request UI tests need their opt-in env, e.g. BATTY_UI_DEMO=1`; every other stage keeps `slow tests need --full`. Exit code stays 2. Two selftest cases added, as planned. No deviation.
