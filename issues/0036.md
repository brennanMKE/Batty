## Description

Two small polish items grouped because they're each tiny:

1. **Close-confirmation:** when closing a Tab, Pane (last tab), Session (last pane), or Window where the surface has a running foreground process (i.e. not just a shell prompt), present a confirm sheet. Toggleable in Settings.
2. **About panel:** wire a real About panel via `NSApplication.orderFrontStandardAboutPanel(_:)` with credits — Batty version, built on libghostty, SlidingTabs.

**Acceptance criteria:**
- Tab close / Pane collapse / Session close / Window close paths check whether their underlying Terminal Sessions have an active foreground process. If yes (and the Settings toggle is on), prompt: "There are running processes. Close anyway?"
- Quit (Cmd-Q) does the same check across all Windows.
- About panel shows: Batty version (from Info.plist `CFBundleShortVersionString`), build number, copyright, and a credits line linking to libghostty / Ghostty / SlidingTabs.

## Notes

- "Active foreground process" is detectable via the PTY's foreground process group ID being different from the shell's own PID. libghostty may already expose this; check its surface API.
- Don't prompt for plain shell prompts — that gets noisy fast.

## Revised approach — 2026-05-08

`GhosttyTerminal` exposes `TerminalSurfaceCloseDelegate.terminalDidClose(processAlive: Bool)` which fires when the underlying process exits. The inverse signal — "is the foreground process alive *right now*?" — is what close-confirmation needs to make a "running processes" decision.

We need a way to query liveness on demand. Options:

1. Track a per-`Tab` `processIsAlive: Bool` flag, initialized `true`, flipped to `false` on `terminalDidClose`. Confirm prompts when *any* doomed tab still has `processIsAlive == true`. This is approximate (the "shell with prompt" still counts as alive) but acceptable for v1.
2. If `GhosttyTerminal` exposes a `TerminalViewState` property for "foreground command running" (via shell integration's `OSC 133` markers), prefer that — it distinguishes "shell prompt" from "shell running `vim`" and lets us prompt only on the latter.

Pick option 2 if the API is present; otherwise ship option 1 with a Gotcha noting it'll prompt on plain prompts too. Manual verification: open a tab, hit Cmd-W → no prompt expected; run `sleep 30`, hit Cmd-W → prompt expected.

The About panel half is unchanged.

### Deferred — 2026-05-08 (close-confirmation half only)

`TerminalSurfaceCommandFinishedDelegate.terminalDidFinishCommand(...)` and the OSC 133 command-start signals aren't on `TerminalViewState` (only Title/GridResize/Focus/Close are). Same delegate-plumbing blocker as `#0024`/`#0035`. Without a "command running" signal, every Cmd-W would either always prompt (annoying) or never prompt (unsafe). Deferring until upstream exposes the necessary delegates.

The **About panel** half is independent. SwiftUI's default `.about` command group already produces a basic about panel populated from Info.plist (app name, version, copyright). For v1 the default is acceptable; a custom About with credits to libghostty / SlidingTabs / Sparkle is polish that can ship as a one-liner `CommandGroup(replacing: .appInfo) { ... }` in BattyCommands later. Not blocking anything; deferred as low-priority polish.

## Root cause

Two unrelated polish gaps:

1. No quit confirmation. Cmd-Q tore down the workspace silently — fine when nothing was running, dangerous when long-lived processes were attached.
2. The default About panel was the SwiftUI / AppKit minimum and didn't credit libghostty or SlidingTabs.

## Fix

**Quit confirmation**:

- `SettingsPreference.confirmQuitKey` + `resolvedConfirmQuit()` (default true). Settings General pane gains a `Toggle`.
- `QuitConfirmation.shouldQuitOrPrompt(store:)` counts open tabs across all sessions (`session.tree.allPanes.reduce(0) { $0 + $1.tabs.count }`). When > 0 and the toggle is on, runs an `NSAlert` with "Quit" and "Cancel" buttons, returning the user's choice.
- `BattyAppDelegate: NSApplicationDelegate` (new in `BattyApp.swift`, attached via `@NSApplicationDelegateAdaptor`) overrides `applicationShouldTerminate(_:)` to call `QuitConfirmation.shouldQuitOrPrompt` against `WorkspaceManager.shared.store`. Returns `.terminateNow` on confirm, `.terminateCancel` on dismiss.

**About panel**:

- `AboutPanel.show()` (new) reads `Bundle.main.infoDictionary` for the canonical app metadata (`CFBundleName`, `CFBundleShortVersionString`, `CFBundleVersion`, `NSHumanReadableCopyright`) and assembles an `NSApplication.AboutPanelOptionKey` dictionary plus an attributed credits string that names libghostty and SlidingTabs explicitly. Calls `NSApplication.shared.orderFrontStandardAboutPanel(options:)` and activates the app.
- `BattyCommands` replaces the `.appInfo` CommandGroup with a single "About Batty" `Button` that calls `AboutPanel.show()`.

## Gotchas

- **Per-tab / per-pane / per-session close-confirmation is deliberately NOT implemented.** `TerminalSurfaceCommandFinishedDelegate` was wired in #0044, but a "command currently running" signal would also need a CommandStart event from libghostty's shell-integration to be reliable, and that delegate doesn't exist yet. With only the "is the surface still alive?" signal (option 1 from the prior approach note), every Cmd-W on a tab with a live shell would prompt — including idle prompts. Quit-time confirmation is the most important safety case (the user is about to lose everything), so we ship that and document the limitation here. Per-action prompts can layer on later when the upstream signal exists.
- **`applicationShouldTerminate` is synchronous and runs on the main thread,** so the `NSAlert.runModal()` blocks until the user clicks. That's the standard pattern for quit confirmations in AppKit. SwiftUI doesn't have a direct equivalent, hence the AppDelegate.
- **The About panel's `copyright` AboutPanelOptionKey doesn't exist** — SwiftUI/AppKit handles copyright by reading `NSHumanReadableCopyright` from Info.plist directly. The attributed credits string is the right place to put a custom copyright line (currently just defaults to "© Batty contributors" if Info.plist lacks the key).
- **`NSApplicationDelegateAdaptor` lives in BattyApp (the executable target),** not BattyKit. The delegate calls into BattyKit (`QuitConfirmation`, `WorkspaceManager`), which keeps the actual logic testable; the executable target only owns the AppKit glue.
- **Per-Session bell mute (mentioned in the original `Settings` AC) still doesn't exist** — that's a Session-context-menu feature per the #0028 notes, not a global toggle. File a follow-up if it becomes load-bearing.
- **About panel includes only the text credits, not interactive links.** Adding `NSAttributedString` link attributes for github.com/ghostty-org/ghostty etc. is a one-line follow-up if it matters; left unimpl because the panel is rarely-used and the library names are searchable text on their own.
