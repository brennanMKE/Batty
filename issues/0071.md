# 0071 — Closing a pane should clear bell-feed entries and unseen counts that refer to it

| | |
|---|---|
| **Status** | open |
| **Module** | BellFeed / Pane |
| **Platform** | macOS |
| **First seen** | 2026-05-11 |

## Description

When a tab or pane is closed (via `Cmd-W`, shell-exit auto-close from `#0059`, last-pane-of-last-session cascade, or chip ×), any **bell-feed entries** that pointed at tabs inside that pane stay in the feed, and any `unseenBellCount` deltas they contributed remain on the surviving aggregates. The result is "ghost" badge counts the user can never clear because the originating tab/pane is gone — clicking the feed entry tries to `jumpToBellEntry` to a tab that no longer exists, which is a no-op (the guard `pane.tabs.contains { $0.id == entry.tabID }` fails silently). The badge stays lit forever until the user hits "Mark All Bells Seen" or the cap evicts the entry.

`#0069` clears unseen counts when the user *navigates to* a tab. This issue is the symmetric case: when the tab is *removed*, the unseen contribution from its remaining feed entries should be removed too.

## Steps to reproduce

1. Open two sessions. In Session 2, run `printf '\a'` in a tab — sidebar shows a badge on Session 2.
2. Without switching to Session 2, close it via right-click → Close.
3. **Observed:** the session is gone but the bell feed still has the old entry pointing at the dead tab id. If other sessions' badges were already showing, their counts are fine; but the feed shows an entry that can no longer be jumped to.
4. **Expected:** entries referring to the closed pane/session are removed from the feed, and unseen aggregates are recomputed. The feed never lists entries whose target tab no longer exists.

A more visible variant of the same bug:

1. Single session. Pane A. Ring a bell in a tab inside pane A while focus is elsewhere. `pane.unseenBellCount` and `session.unseenBellCount` increment.
2. Before navigating to the bell tab, close that tab via the chip × (or Cmd-W).
3. **Observed:** the chip's unseen dot is gone (the tab is gone), but `session.unseenBellCount` still shows the increment, and the feed still has the entry.
4. **Expected:** counts decrement, feed entry is removed.

## Expected behavior

When a tab is removed from a pane:

- Walk `bellFeed.entries`, find entries with the removed `tabID`, remove them from the feed.
- Decrement `tab.unseenBellCount` / `pane.unseenBellCount` / `session.unseenBellCount` for each removed entry that was unseen — same cascade as `markBellSeen` does, except the entry is dropped rather than flipped.

When a pane is removed (last tab closed, or the pane itself is dropped from the tree): same as above, but over the union of all `tabID`s that were in that pane.

When a session is removed: same, over the union of all `tabID`s under all its panes.

The Bell Feed popover should never list entries whose target tab no longer exists. The aggregate `unseenBellCount` on any surviving session/pane/tab should always equal the count of unseen feed entries pointing at it.

## Implementation guidance

### Add a helper on `BellFeedStore`

```swift
public func removeEntries(matchingTabIDs tabIDs: Set<UUID>) -> [BellFeedEntry] {
    let (kept, removed) = entries.stablePartition { !tabIDs.contains($0.tabID) }
    entries = kept
    return removed
}
```

The "return the removed entries" shape lets `AppStateStore` decrement the aggregates for any that were unseen, using the existing `decrementUnseen(for:)` private helper.

### Wire the cleanup into the cascade

In `AppStateStore.closeTab(id:)`, the cascade is:

```swift
pane.removeTab(id: tabID)
if pane.tabs.isEmpty {
    let treeEmptied = session.tree.removePane(id: pane.id)
    if treeEmptied {
        removeSession(id: session.id)
    }
}
```

Before each `removeTab` / `removePane` / `removeSession`, capture the set of tab IDs that are about to disappear. After the structural removal, call `bellFeed.removeEntries(matchingTabIDs: idsToClear)` and decrement `unseenBellCount` aggregates accordingly.

A clean approach is a single helper on `AppStateStore`:

```swift
private func cleanUpBellState(forTabIDs tabIDs: Set<UUID>) {
    let removed = bellFeed.removeEntries(matchingTabIDs: tabIDs)
    for entry in removed where !entry.seen {
        decrementUnseen(for: entry)
    }
}
```

Call sites:

- `closeTab(id:)` — pass `[tabID]` BEFORE the cascade.
- `pane.removeTab` (when called from cascade) — already handled by `closeTab`'s pre-capture.
- Pane teardown (the inner `tree.removePane` call) — pass all tab IDs that were under that pane.
- `removeSession(id:)` — pass all tab IDs under all panes of that session.

### Race / re-entrancy

The cascade is synchronous. No race. Calling `decrementUnseen` after removing the entry from `bellFeed.entries` works because the decrement reads `entry.sessionID` / `entry.paneID` / `entry.tabID` — the entry value is captured by the partition.

If an entry's session or pane is *also* about to be removed (i.e. cleaning up a whole session), decrementing the session's `unseenBellCount` is harmless because the session is removed seconds later. The decrement could be skipped, but doing it consistently keeps the invariant simpler.

### Tests

Add `BattyKit/Tests/BattyKitTests/BellFeedCleanupTests.swift` (or extend an existing bell-feed test file). Cases:

- Record a bell tick on a non-active tab; close that tab; assert the feed has no entries with that tabID and unseenBellCount aggregates dropped accordingly.
- Multi-tab pane: tab A and tab B both rang bells; close only tab A; assert A's entries are gone but B's remain.
- Pane cascade: pane with one tab that rang a bell, closed via Cmd-W; assert the entry is gone and the session's unseenBellCount dropped.
- Session cascade: session with one pane with one tab with bells, closed via removeSession; assert all entries cleared.

## Acceptance criteria

- Closing a tab removes any bell-feed entries that pointed at it.
- Closing a pane removes entries for all tabs that were in it.
- Closing a session removes entries for all tabs across all its panes.
- Unseen aggregates (`tab/pane/session.unseenBellCount`) drop by the same amount as the unseen entries removed.
- The Bell Feed popover never shows an entry whose tab/pane/session is gone.
- `jumpToBellEntry` continues to work for surviving entries.
- A unit test in `BellFeedStoreTests` or a new `BellFeedCleanupTests` exercises tab-, pane-, and session-cascade removal.

## Out of scope

- Soft-deletion of entries (showing them with a strikethrough). v1 just removes.
- A "Recently closed" log of pruned entries. Not asked for.
- Cleanup on workspace re-import. With `#0055` defaulting workspace-restore to off, this doesn't come up.

## Notes

- Related: `#0059` (auto-close on shell exit — triggers this cascade), `#0069` (auto-clear on tab focus — the symmetric "user visits the tab" path), `#0068` (per-session mute — orthogonal but in the same module).
- The bell feed has a finite cap (currently 200 entries). Entries are also evicted when the cap fills. This issue adds a separate eviction reason ("the target is gone"), not a replacement for the cap.
- After this fix, `unseenBellCount` aggregates should always be in sync with feed contents. If they ever drift, that's a bug worth a separate ticket.
