# 0136 — Layouts picker: Cmd-Shift-L applies a visual pane layout to the current session

| | |
|---|---|
| **Status** | open |
| **Module** | Pane / Split / App |
| **Platform** | macOS |
| **First seen** | 2026-05-18 |

## Description

A "Layouts" picker that lets the user set up a common pane arrangement in one keystroke. Press **Cmd-Shift-L**, see a grid of thumbnails showing each available layout, pick one with the arrow keys or a click, hit Return — the current session's pane structure is rebuilt to match the chosen layout.

Same UX shape as Open Quickly (`#0128`) and the command palette (`#0126`): centered translucent sheet, keyboard-driven, dismiss with Esc. The differentiator is **visual** — rows are stylized thumbnails of the pane arrangement, not text rows. The user picks a layout by recognizing the shape, not by reading a name.

Primarily aimed at a fresh single-pane session: open a new session for a project, hit Cmd-Shift-L, pick "main-left + 2-right-stack" to instantly get a wide editor pane with two narrow terminals stacked on the right. If the session already has more than one pane, the action is a **no-op** — the picker doesn't try to reconcile an existing split tree with a new layout.

## Acceptance criteria

- **Cmd-Shift-L** from anywhere in the app opens a centered translucent sheet with a grid of layout thumbnails. Follows the visual language of Open Quickly / command palette sheets so it feels like a sibling, not a new style.
- Each thumbnail is a small (≈ 120 × 80 pt) stylized rectangle representing the layout, with internal dividers drawn in the themed chrome accent or divider color (`#0135`'s `ChromePalette`). The thumbnail emphasizes shape and proportions over fidelity; no actual terminal content.
- A small caption under each thumbnail names the layout in plain words ("Horizontal split", "Main left, 2 right", etc.) for accessibility and disambiguation between mirror-image layouts.
- **Keyboard navigation**: Up/Down/Left/Right move selection through the grid. Return applies the selected layout and dismisses the sheet. Esc dismisses without action.
- **Mouse**: click a thumbnail to select; double-click (or click-then-Return) to apply.
- **Applying a layout** when the current session has a single pane:
  - The existing pane's terminal becomes the contents of the "primary" leaf (top-left in reading order).
  - The remaining leaves are created as new panes with the default shell (same logic as a fresh split today via `SplitTree.split…` / pane-creation paths).
  - Keyboard focus stays on (or moves to) the primary leaf so the user keeps typing where they were.
- **Applying a layout** when the current session has **more than one pane**: the action is a **no-op**. No partial application, no destructive reshape. (Visual feedback like a brief shake or a "can't apply — close panes first" footer is optional and explicitly deferred — silently doing nothing is acceptable for v1.)
- The picker appears in a mirrored menu item — likely **View → Layouts…** — for discoverability, following the `#0128` / `#0126` pattern.

## Initial layout set

Cover the common cases without being exhaustive. Order in the grid is left-to-right, top-to-bottom in reading order:

| # | Name | Shape |
|---|---|---|
| 1 | Single pane | `▢` (no-op layout — exists for symmetry with the dismiss path) |
| 2 | Horizontal split | `▢│▢` (left \| right) |
| 3 | Vertical split | `▢ / ▢` (top / bottom) |
| 4 | Three columns | `▢│▢│▢` |
| 5 | Three rows | `▢ / ▢ / ▢` |
| 6 | Main left, two right (stacked) | left pane fills the left half; right half is split top/bottom |
| 7 | Main right, two left (stacked) | mirror of #6 |
| 8 | Main top, two bottom (side by side) | top pane fills the top half; bottom half is split left/right |
| 9 | Main bottom, two top (side by side) | mirror of #8 |
| 10 | 2×2 grid | four panes, two columns by two rows |

Pin ratios to clean halves and thirds (50/50, 33/33/33, 50/50 with nested 50/50). No fancy proportions in v1.

## Out of scope

- **Custom user-defined layouts** — pick from a fixed set in v1. A future issue can add user templates.
- **Saving the current layout as a template** — same.
- **Applying layouts to a session that already has splits** — v1 is no-op when pane count > 1. Reshape semantics (close existing panes, then build the new layout) is a follow-up worth its own issue.
- **Multi-window layout** — apply only affects the current window's focused session.
- **Animated transitions when applying** — panes just appear in their new positions. Animation could come later.
- **Per-pane content / templating** — every new pane opens the default shell. No "this layout has a build pane that runs `make`" magic.
- **Cross-session layout** — applies to the current session, not "set this layout on every session."

## Notes

- Cmd-Shift-L is the natural mnemonic and continues the Cmd-Shift-O / Cmd-Shift-P / Cmd-Shift-B family. Grep `BattyShortcuts` / `BattyCommands` to confirm it isn't already taken; if it is, free it for this and move whatever else lives there.
- The thumbnail rendering can be a small SwiftUI view: a `RoundedRectangle` outline at the cell's frame, with internal lines drawn by a `Canvas` or nested `HStack`/`VStack` of `Rectangle`s. Keep it cheap — these thumbnails render every time the sheet opens.
- Thumbnails should read from the `ThemeChrome` palette (`#0135`) so they match the rest of the app's chrome. Border = themed `chromeForeground` at low alpha; internal dividers = themed `divider`; the "primary" leaf could be tinted with `accent` at low alpha to hint at the focus target.
- Layout application boils down to: take the current single `PaneRuntime`, then call into the existing split paths (the SplitTree mutations used by `#0127` and the existing Split menu) in the right order to build the target tree. The split mechanics are already there; this is sequencing them, not new infrastructure.
- The "single pane" gate is on the **session's** pane count, not the focused pane. Even if the session has only one pane that's focused, that's the case we want to handle; the gate just enforces "session has exactly one leaf."
- Related to `#0126` (command palette): once the palette lands a "Layouts: <name>" entry per layout in the command palette would be a nice second entry point. Defer to `#0126`'s scope.
- The picker is a centered sheet, like Open Quickly and the command palette — not a popover. Visual style should match those two.
- The layout list is small enough (10 items) that the grid can be a single static layout; no need for fuzzy filtering. If the list grows to 20+ later, a filter field can be added in a follow-up.
