## Description

A Tab's chip title resolves as: focused-surface process name → cwd basename → user-set override (first non-empty wins) — `Concepts.md` → Tab. Title updates as the user `cd`s around or runs different programs.

**Acceptance criteria:**
- Tab chip text reflects the running process inside its surface (e.g. `vim`, `bash`, `node`).
- When the surface is idle (just a shell), the title falls back to the cwd basename (e.g. `Batty`, `~`).
- A user-set title override (set via tab context menu — separate follow-up if needed) wins over both.
- Title updates within ~500ms of the underlying state changing — not instant, but not laggy.

## Notes

- libghostty surfaces emit OSC 0/1/2 title-set escapes; capture those if exposed. If only OSC is exposed, use that as the override path; cwd-tracking comes from libghostty's shell integration.
- Don't poll process state aggressively — driven updates from libghostty callbacks are preferred. If we have to poll, debounce.
- Add a tab context menu with "Rename" / "Reset title" as a follow-up if not in scope here.

## Revised approach — 2026-05-08

`GhosttyTerminal` exposes title and cwd via two delegate protocols and via `TerminalViewState` itself:

- `TerminalSurfaceTitleDelegate.terminalDidChangeTitle(_ title: String)` — fires on OSC 0/1/2.
- `TerminalSurfacePwdDelegate.terminalDidChangeWorkingDirectory(_ path: String)` — fires on shell-integration cwd reports.
- `TerminalViewState.title` — already published (`@Observable`); the SlidingTabs chip can bind directly.

**Revised acceptance criteria:**
- The tab chip displays `TerminalViewState.title` if non-empty, else the cwd basename from the pwd delegate, else the user-set override (`Tab.titleOverride`).
- A small adapter in `BattyKit` listens for `terminalDidChangeWorkingDirectory` and updates `Tab.lastKnownCWD` for persistence (#0030 cadence).
- No polling. Updates are driven by the delegate callbacks; SwiftUI re-renders the chip via the `@Observable` change.

**No more BEL-only fallback worry**: `TerminalSurfaceTitleDelegate` is on the public API, so the OSC 0/1/2 path is reliably exposed.

### Phase 1 already shipped via #0014 — title via OSC 0/1/2

`PaneView`'s `chipTitle(for:)` already resolves: `tab.titleOverride` → `tab.terminal.title` → `"Tab"`. `TerminalViewState.title` is set by `terminalDidChangeTitle(_:)` (TerminalViewState conforms to `TerminalSurfaceTitleDelegate` itself), and the `@Observable` macro causes SwiftUI to re-render the chip immediately when it changes. So the "running process" / "shell-set title" path of #0016's acceptance criteria is satisfied — no Batty-side code needed beyond #0014.

### Why this is still `open` — cwd basename fallback

`TerminalViewState` (in libghostty-spm 1.0.1777879537) only conforms to four of the twelve `TerminalSurfaceViewDelegate` sub-protocols:
- `TerminalSurfaceTitleDelegate` ✓
- `TerminalSurfaceGridResizeDelegate` ✓
- `TerminalSurfaceFocusDelegate` ✓
- `TerminalSurfaceCloseDelegate` ✓

It does **not** conform to `TerminalSurfacePwdDelegate`, `TerminalSurfaceBellDelegate`, `TerminalSurfaceDesktopNotificationDelegate`, etc. To capture cwd changes, we'd need to attach an additional delegate at the AppKit `TerminalView.delegate` level, but `TerminalSurfaceView` (the SwiftUI wrapper used in `PaneView`) doesn't expose that AppKit hook. Three viable paths:

1. **Bypass `TerminalSurfaceView` and use `TerminalView` directly.** Wrap it in our own `NSViewRepresentable` and add a delegate-routing object. That moves us partway toward what we *thought* we were avoiding by adopting GhosttyTerminal — but only for the parts the SwiftUI path can't reach.
2. **Extend `TerminalViewState` upstream.** Open a PR against `libghostty-spm` to make `TerminalViewState` conform to the remaining protocols and publish `cwd`, `lastBellAt`, `lastDesktopNotification` as @Observable properties. Cleanest long-term but blocks on someone else.
3. **Skip cwd fallback for v1.** When the shell doesn't set a title via OSC 0/1/2, the chip says `"Tab"`. Most shells (bash, zsh, fish with default config) DO set a title, so this is a small UX gap that only affects exotic shell configs.

Same blocker affects #0024 (bell capture), #0028 (notification routing), #0036 (close-confirmation `processAlive` — actually that one *is* exposed via `TerminalViewState.onClose`), and the cwd inheritance follow-up from #0014's Gotchas.

### What's left — when delegate plumbing is figured out

1. Pick path 1 (BattyKit-side wrapper) or path 2 (upstream PR). Either way, route `terminalDidChangeWorkingDirectory(_:)` into a `TabRuntime.lastKnownCWD: String?` field.
2. Update `chipTitle(for:)` to use `URL(fileURLWithPath: cwd).lastPathComponent` when `tab.terminal.title` is empty.
3. Use `lastKnownCWD` for cwd inheritance when a tab is added (`PaneRuntime.addTab(in:)`) so new tabs spawn in the same directory as the focused one — completes the cwd inheritance from #0014's Gotchas.
4. Add a tab context menu with "Rename" / "Reset title" so `Tab.titleOverride` has a UX (currently exists in the model but no surface-level UI to set it).

## Root cause

Two gaps remained after the OSC 0/1/2 phase shipped via #0014:

1. The cwd basename fallback never had a data source — `TerminalSurfacePwdDelegate` existed in `libghostty-spm` but `TerminalViewState` didn't conform to it, so the OSC 7 working-directory updates that libghostty's shell-integration emits never reached SwiftUI.
2. New tabs spawned via `PaneRuntime.addTab()` always started in the user's home directory (or whatever the shell defaults to) instead of inheriting the focused tab's cwd, and persisted workspaces always restored to the same default — `WorkspaceConversion.Tab(from:)` hard-coded `lastKnownCWD: nil`.

Both gaps shared a single upstream blocker: `TerminalViewState` was missing the Pwd delegate conformance and a `workingDirectory` published property. #0044 closed that gap by adding both.

## Fix

- `TabRuntime.init` accepts an optional `workingDirectory: String?` and forwards it into `TerminalViewState.configuration.workingDirectory` so libghostty spawns the surface in that directory.
- `PaneRuntime.addTab(inheritingCWDFrom:)` reads `TabRuntime.terminal.workingDirectory` from the source tab and passes it to the new `TabRuntime`. `PaneView`'s "+" button now passes `pane.activeTab` so new tabs spawn in the focused tab's cwd.
- `PaneView.chipTitle(for:)` and `BattyCommands.tabMenuTitle(at:)` both fall back to `URL(fileURLWithPath: cwd).lastPathComponent` when neither `titleOverride` nor `terminal.title` yields a label. `"/"` is filtered so a root cwd doesn't display as a slash.
- `WorkspaceConversion`:
  - `Tab(from runtime:)` persists `runtime.terminal.workingDirectory` into `lastKnownCWD` (was hard-coded `nil`).
  - `TabRuntime(from persisted:)` re-injects `persisted.lastKnownCWD` into the new `TabRuntime`, so a re-launched workspace respawns each surface in its previous directory.

## Files changed

- `BattyKit/Sources/BattyKit/TabRuntime.swift` — new optional `workingDirectory` init parameter; sets `terminal.configuration.workingDirectory` when provided.
- `BattyKit/Sources/BattyKit/PaneRuntime.swift` — `addTab(inheritingCWDFrom:)` reads cwd from a source tab and threads it into the new `TabRuntime`.
- `BattyKit/Sources/BattyKit/PaneView.swift` — "+" button passes `pane.activeTab`; `chipTitle` falls back to cwd basename.
- `BattyKit/Sources/BattyKit/BattyCommands.swift` — `tabMenuTitle(at:)` mirrors `chipTitle`'s cwd-basename fallback so the menu and chip stay in sync.
- `BattyKit/Sources/BattyKit/WorkspaceConversion.swift` — persist + restore `lastKnownCWD` round-trip via `terminal.workingDirectory`.

## Gotchas

- **Cwd persistence is "best known cwd at save time", not "live cwd at quit".** `WorkspaceConversion.Tab(from:)` snapshots `terminal.workingDirectory` at the moment the workspace serializes (#0030 cadence: on quit, on structural changes, every 30s). Between serializations, the workspace cwd lags the live shell cwd. This is fine for restore-on-launch — the user typically wants where they were *recently*, not where they were one second ago.
- **Cwd inheritance only works after the source tab has emitted at least one OSC 7.** Until libghostty's shell-integration runs and reports the cwd, `terminal.workingDirectory` is `nil` and `addTab(inheritingCWDFrom:)` falls back to the shell default. This is acceptable because shells configured for shell-integration emit OSC 7 on every prompt — the lag is at most one prompt cycle. Shells without shell-integration get the default-home behavior we had before, which is the right behavior for them.
- **`URL(fileURLWithPath:).lastPathComponent` returns `"/"` for the root,** which is why the chip-title fallback explicitly filters that case. Without the filter, a tab at `/` would display a slash, which is worse than the `"Tab"` placeholder.
- **Tab context-menu rename / reset (item 4 in the prior bail's "what's left") is intentionally out of scope.** `Tab.titleOverride` is in the persistence model and the chip title resolution honors it, but no surface-level UX exposes it yet. That's a separate UI/UX issue to file when the menu work happens.
