# 0242 — Theme picker opens in every window instead of only the key window

| | |
|---|---|
| **Status** | open |
| **Module** | Theme / Window / App |
| **Platform** | macOS |
| **First seen** | 2026-06-16 |

## Description

Multi-window regression: invoking the theme picker (Cmd-T) with two windows open brought up the picker in **both** windows at once, instead of only the current (key) window. Window-scoped UI that used to be a non-issue in single-window now fans out to every open window.

This is almost certainly not unique to the theme picker — the same routing flaw likely affects the **Layout picker** and any other command/overlay that presents per-window UI. Audit all such commands and constrain each to the key window.

## Steps to reproduce

1. Open a second window (Shift-Cmd-N) so two windows are visible.
2. Make one of them the key window.
3. Hit Cmd-T to bring up the theme picker.

## Expected behavior

The theme picker opens only in the current (key) window. Other windows are unaffected.

## Actual behavior

The theme picker opened in **both** open windows simultaneously.

## Notes

- Reported by the user during multi-window regression testing (related to the #0234 multi-window umbrella; theme work landed in #0241 "Add per-appearance Dark/Light theme with live re-apply").
- **The fix must cover more than the theme picker.** Audit every command/overlay that now presents per-window and confirm it targets the key window only. Known candidates to check explicitly:
  - Theme picker (the reported case).
  - Layout picker.
  - Any other Command-Palette / picker / sheet / popover-style presentation driven by a menu command or global keyboard shortcut (e.g. Open Quickly, bell-feed popover, rename, paste-confirm).
- Likely root cause: the presentation state (e.g. an `@Observable` "show picker" flag) lives in app- or scene-shared state rather than per-window state, so every `WindowRuntime`/window observing it presents. Per-window presentation flags were introduced around #0235–#0238 (per-window `WindowRuntime`, per-window sidebar state); verify the picker-presentation flags moved to that same per-window container. See `docs/multi-window-design.md`.
- This belongs to the same regression class #0240 (Phase 7) is meant to catch; once #0240's UI suite can run again, add multi-window coverage asserting a picker opens in exactly one window.
