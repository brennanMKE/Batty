## Description

Each session should support an optional local theme override. When a session has a local theme set, switching to that session applies that theme instead of the global active theme. Sessions without a local override continue to show whatever the global theme is. The override is set and cleared via the session sidebar row's context menu.

## Expected behavior

- Right-clicking a session row in the sidebar shows a context menu with a "Set Session Theme…" item and, when a local theme is already set, a "Clear Session Theme" item.
- "Set Session Theme…" opens a compact theme picker (reuse `ThemeSelectorView` or a trimmed variant) anchored to the sidebar row or presented as a popover.
- When the user picks a theme, it becomes the local override for that session.
- Switching to a session with a local override applies that theme live (the same way the global selector does via `store.applyThemeToAllSurfaces`).
- Switching away does NOT change the global theme — the override is session-local and transient.
- "Clear Session Theme" removes the override; switching to the session then falls back to the global theme.
- Local overrides are stored in the session model (not persisted to disk — they reset on launch, keeping the persistence model simple for v1).

## Actual behavior

No per-session theme concept exists. All sessions share the global active theme at all times.

## Notes

- The session sidebar row context menu is in `SessionSidebarView.swift`. Add the new items alongside any existing context-menu actions.
- The theme override should live as an optional property on `SessionRuntime` (or its underlying model). On session focus change, check for a local override before applying the global theme.
- `store.applyThemeToAllSurfaces(_:)` applies a theme to the currently active session's surfaces. The per-session override should apply only to the surfaces belonging to that session (already the case if `selectedSession` is set to the target session before calling).
- Consider whether the override should apply immediately when set, or only on next focus switch. Applying immediately is simpler and more responsive.
- The global "Open Theme Selector" (Cmd-Shift-T) and Theme menu always operate on the global theme; the per-session override does not affect those controls.

## Root cause

No per-session theme model existed. All theme application paths wrote the global `ThemePreference` and called `applyThemeToAllSurfaces` with no per-session scope.

## Fix

Added `localThemeName: String?` to `SessionRuntime` as a non-persisted in-memory override. Added `applyActiveSessionTheme()` to `AppStateStore` which reads the focused session's override first, then falls back to the global `ThemePreference`. Hooked it into `SessionDetailView`'s `onChange(of: store.selectedSessionID)` so every focus switch picks up the correct theme. Added `SessionThemeSelectorView` (a session-scoped variant of `ThemeSelectorView`) that sets `session.localThemeName` on confirm rather than writing `UserDefaults`. Wired "Set Session Theme…" and "Clear Session Theme" context menu items into `SessionSidebarView` using an item-binding sheet pattern matching the existing rename sheet.

## Files changed

- `BattyKit/Sources/BattyKit/Runtime/SessionRuntime.swift` — added `localThemeName: String?` property.
- `BattyKit/Sources/BattyKit/Theme/ThemePreference.swift` — added `applyActiveSessionTheme()` extension on `AppStateStore`.
- `BattyKit/Sources/BattyKit/Views/SessionDetailView.swift` — call `store.applyActiveSessionTheme()` in `onChange(of: store.selectedSessionID)`.
- `BattyKit/Sources/BattyKit/Views/ThemeSelectorView.swift` — added `SessionThemeSelectorView` which mirrors `ThemeSelectorView` but sets `session.localThemeName` on confirm.
- `BattyKit/Sources/BattyKit/Views/SessionSidebarView.swift` — added "Set Session Theme…" and "Clear Session Theme" context menu items; wired `SessionThemeSelectorView` sheet via `themingSessionID` state.

## Gotchas

- `ThemeSelectorView.confirmSelection()` writes `UserDefaults` — `SessionThemeSelectorView` deliberately does not. Live-preview in the session picker applies via `applyThemeToAllSurfaces` (affects all surfaces). This is acceptable for v1: the preview is transient and cancel restores the correct theme via `applyActiveSessionTheme()`.
- The context menu "Clear Session Theme" item only appears when `session.localThemeName != nil`. SwiftUI evaluates this at menu-build time, so the item appears/disappears correctly across sessions.
- New panes created by splitting init from global UserDefaults only (`TabRuntime.activeTheme()` has no session context). Fixed by watching `tree.allPanes.count` in `SessionDetailView.configuredStack` and re-calling `applyActiveSessionTheme()` when pane count changes (commit `60f69f7`).
