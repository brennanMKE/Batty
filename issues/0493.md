## Description

Since #0492 every Projects list ranks by recency: the Open Project picker, File ▸ Open Project ›, the Command Palette rows and `batty project list` all call `ProjectRecency.ranked`, and `Project.lastOpenedAt` is written on every successful open. The picker, though, still draws one uniform grid of equal cards, so the Projects ranked first look exactly like the ones ranked last. The user's direction (2026-10-12): "I would show a top row with bigger cards for the most used projects followed by smaller cards. When we get to that point we can work with proposed designs in a web page to decide details."

This issue carries #0492 §3 forward as its own child of #0469: a **two-tier picker**, a top row of larger cards for the Projects ranked first, then smaller cards for the rest. It was design-gated; the user chose a design on 2026-10-13 and the choice is recorded under `## Decision` below. **The gate is lifted: this issue is ready to implement.** The "Open now" strip the user also asked for is split out as [#0500](0500.md), which depends on this issue.

Ships on `main` for 1.3.0, behind the Projects flag. With the flag off the picker never presents, so nothing here is visible.

## Decision (user, 2026-10-13)

The proposal canvas had six boards (copied to `issues/0493/`, see Attachments): "Questions to decide" (Main), Option A (three featured, compact grid), Option B (two featured, list), Option C (four featured, open Projects in their own strip), "Filtering collapses to one tier" and "Two Projects, and none". The user's decision, verbatim:

> From the designs I like option A with 3 featured projects. The All Projects section also looks good. I also like the parts of option C which shows Open Now which allows the user to switch or open another copy. Filtering UI looks good too. The last board which allows you to create a new project is also good. When there are fewer than 3 projects we should show that option. We will always need a New Project option visible some where, perhaps at the bottom like I am seeing with cmd-N.

This section is the `## Chosen design` record the design gate required; the rules below are binding for the implementer and the reviewer. Where the user's words and the Main board's recommendation differ, the user's words win and the override is called out.

### D1. Layout: Option A

- The sheet grows from `720 × 520` (`ProjectPickerView.swift:82`) to **`860 × 600`**. Still a fixed-size sheet, not resizable.
- **Featured tier** (`project-picker.featured`): heading `Recent`; the first **3** Projects of `ProjectRecency.ranked` as **large cards** in **3** flexible columns, 12 pt gap. A large card is today's card content with a **132 pt** thumbnail (today 108 pt, `ProjectPickerView.swift:288`), the kind glyph badges in each slot, the symbol, the name at 14 pt semibold, a **relative opened time** right-aligned on the name row (D6), the `~` path and the summary line.
- **All Projects tier** (`project-picker.rest`): heading `All Projects`; every Project after the third, same order, as **compact cards** in **4** flexible columns, 10 pt gap. A compact card is a **58 pt** thumbnail (slot frames only, no glyph badges), the symbol, the name and the OPEN badge, and the `~` path. No summary, no time.
- Both tiers come from the one ranked list split at 3; there is no second ranking and no sorter other than `ProjectRecency`. Open Projects sit wherever `ProjectRecency.defaultPlacement` puts them (`.last` today, `ProjectRecency.swift:9`, so an open Project is the last compact card and carries its OPEN badge, exactly as Option A draws `Homelab`). #0500 later lifts open Projects out of both tiers into their own strip; **this issue does not change `defaultPlacement`** and adds no placement logic of its own.
- Both tiers live in the one `ScrollView`; the featured row scrolls away with the rest. Each tier's container is a `.contain` accessibility element (the #0484 pattern, `ProjectPickerView.swift:86-87`) carrying its identifier. Cards keep `project-picker.card.<name>` (`:264`) and the OPEN badge keeps `project-picker.open-badge.<name>` (`:237`), so `ProjectsOpenTests` keeps passing.
- Footer unchanged in content: the hint (`project-picker.hint`), `⌥↩ Open another copy`, `⌘E Edit`, `⌘N New Project…` (`ProjectPickerView.swift:171-189`). **`⌘N New Project…` is always visible in the footer, whatever the Project count**, including with the filter active and in both empty states. Today it already is (`:181` sits outside the `selectedID != nil` branch); the implementer keeps it that way and the UI test asserts it.

### D2. Fewer than three Projects, and none (user override of the board caption)

The user's line "When there are fewer than 3 projects we should show that option" is read as: **when fewer than 3 Projects fill the featured row, the slot after the last Project shows a `New Project…` card**; with **zero** Projects the existing empty state with its `New Project…` button shows. That overrides the "Two Projects, and none" board's caption ("no '+' card in the grid") and the Main board's recommendation on question 6. Concretely:

- `ranked.count < 3` (and the filter is empty): the featured row holds the `ranked.count` large cards followed by **one** `New Project…` card (`project-picker.new-project-card`), drawn as a large-card-sized dashed outline with `folder.badge.plus` and the text `New Project…`. Any further empty slot stays empty. There is no All Projects tier and **no headings** (the board shows none at this count).
- `ranked.count == 0`: today's empty state (`project-picker.empty`, `project-picker.new-project`, `ProjectPickerView.swift:147-169`), unchanged.
- `ranked.count >= 3`: no `New Project…` card anywhere; ⌘N in the footer is the only route, as the Main board recommends.
- The `New Project…` card is a button: a click reports `ProjectPickerAction.newProject` (the same action as the footer's hidden ⌘N button, `ProjectPickerView.swift:208-209`). It is **not** part of the keyboard cursor (D5): arrows never land on it and Return never triggers it; ⌘N is the keyboard route. It is never shown while a filter is active and never in the no-matches state.
- In this count the open-Project rule of D1 still applies: with 2 Projects of which one is open, the row is one closed large card, one open large card with its OPEN badge, then the `New Project…` card.

### D3. Filtering collapses to one tier (board as drawn; Main recommendation on question 4)

- A non-blank query hides both tiers and their headings and shows **one compact 4-column grid** (`project-picker.rest` is reused as its container; `project-picker.featured` is absent) of every match, in the order today's `filtered` already produces (`ProjectPicker.swift:179-193`: name fuzzy score ×2 beats path substring, ties keep the ranked offset). Compact cards, identical to All Projects, OPEN badge included. The board draws the filtered cards without thumbnails; that simplification is not required.
- A one-line heading above the grid reads `1 match` / `N matches` (localized, like `ProjectPickerModel.summary`).
- The no-matches state is unchanged (`.noMatches`, `ProjectPickerView.swift:160-163`).
- **Escape becomes two-step**: with a non-blank query, Escape clears the query (the two tiers come back, the selection moves to the first ranked card as `setQuery("")` already does, `ProjectPicker.swift:89-93`); with a blank query, Escape dismisses as today (`onCancel`, `:110`). The header caption reads `Esc to clear` while a query is present and `Esc to dismiss` otherwise, as the Filtering board draws. The existing UI test `ProjectsOpenTests.testOpenBadgeAndFileMenuCheckMarkFollowTheOpenProject` presses Escape with a blank query (`ProjectsOpenTests.swift:215-216`) and is unaffected.

### D4. Placement of open Projects (question 1)

Keep **`.last`** as `ProjectRecency.defaultPlacement` for every surface. The picker-specific "Open now" strip the user asked for is [#0500](0500.md); it is a presentation partition inside the picker, not a placement change, so the File menu, the palette, Open Quickly and `batty project list` are untouched by either issue.

### D5. Keyboard: a pure multi-section cursor (question 5)

- The cursor math becomes a **pure value type**, `ProjectPickerGridCursor` (`BattyKit/Sources/BattyKit/Model/ProjectPickerGridCursor.swift`), modeled on `SessionColorGridCursor` (`Views/SessionColorPickerView.swift:13`) and `ProjectSymbolGridCursor` (`Model/ProjectSymbolGridCursor.swift:9`). It is built from an ordered list of sections, each `(columns: Int, count: Int)`, and maps a flat index in reading order (featured, then rest) to a new index for `left`, `right`, `up`, `down`, `home`, `end`. `ProjectPickerModel.columnCount` (`ProjectPicker.swift:45`) and the `index ± columns` arithmetic in `move` (`:103-129`) are deleted; `move` builds the sections from the current tier shape (`[(3, featured.count), (4, rest.count)]` unfiltered, `[(4, matches.count)]` filtered, `[(3, ranked.count)]` with fewer than three Projects) and calls the cursor. The view's `onKeyPress` handlers (`ProjectPickerView.swift:100-103`) gain `.home` and `.end` and still only call the model. No arithmetic in the view.
- **Left / Right** step by one through the whole reading order and cross the tier boundary (right from the last featured card lands on the first compact card). Clamped at the first and last card, as today.
- **Down within a section**: same column one row down; if that row exists but is short of the column, the section's last card (today's short-last-row rule, `:120-126`). **Down from a section's last row** goes to the first row of the next section, to the mapped column (below), clamped to that row's count. **Down from the last row of the last section** is a no-op.
- **Up within a section**: same column one row up. **Up from a section's first row** goes to the last row of the previous section, to the mapped column, clamped to that row's count. **Up from the first row of the first section** is a no-op.
- **Mapped column** between a section of `C` columns and one of `C′`: `c′ = Int(floor((Double(c) + 0.5) / Double(C) * Double(C′)))`, the column whose horizontal centre is nearest. For 3 → 4 that is `0, 1, 2 → 0, 2, 3`; for 4 → 3 it is `0, 1, 2, 3 → 0, 1, 1, 2`. The cursor tests pin exactly these tables.
- **Home** is the first card overall; **End** is the last card overall; both from every cell.
- `ProjectPickerDirection` (`ProjectPicker.swift:16-18`) gains `home` and `end`. Return, Option-Return, ⌘E, ⌘N, click and double-click behave as today (`docs/ui-features.md:897-899`).
- After a re-rank moves the selected card (a Session opened or closed while the sheet is up), the view scrolls to it. Today it scrolls only when the selected id changes (`ProjectPickerView.swift:140-142`). The fix is an `onChange` keyed on the selected card's position (tier and index) that the model exposes, not a write from `body`.

### D6. Card extras (question 7): relative time on large cards only

- Large cards show `lastOpenedAt` as a relative time (`12 min ago`, `2 h ago`, `Yesterday`) right-aligned on the name row, as Option A draws; compact cards show none. A never-opened Project shows no time.
- The text comes from a pure function with an explicit reference date, `ProjectRecency.relativeOpenedText(_ date: Date?, now: Date) -> String?`, implemented over `RelativeDateTimeFormatter.localizedString(for:relativeTo:)` (which takes the reference date; no `Date()` inside, #0492's rule for the ranking function applies to formatting too). The view passes `Date()` from `body` as a plain read, which is allowed; nothing writes state. Unit tests use fixed dates.
- No Tab counts in the large thumbnail; the kind glyph badges already there are enough.

### D7. Frequency (question 8)

Recency only for 1.3.0, as the Main board recommends. No `openCount` field; `ProjectStore.recordOpen` (`ProjectStore.swift:169`) is untouched.

## Current code (verified on `main` at `6ee01ad0`, 2026-10-13)

**Order.** `ProjectRecency.ranked(_:openProjectIDs:placement:)` (`BattyKit/Sources/BattyKit/Model/ProjectRecency.swift:14-33`) sorts most recently opened first, then never-opened Projects in store order, with equal dates keeping store order through the enumerated offset. `OpenPlacement` is `.last`, `.inPlace` or `.first` (`:7`); `defaultPlacement` is `.last` (`:9`), so open Projects sink below closed ones. `ProjectPickerModel` ranks in `init` (`Model/ProjectPicker.swift:53-59`) and in `refreshed(projects:openProjectIDs:)` (`:64-71`), and the view calls `refreshed` on every render (`Views/ProjectPickerView.swift:53-56`, `:59`). The filter's tie-break is the ranked offset (`ProjectPicker.swift:191`).

**Actions.** `ProjectPickerAction` (`ProjectPicker.swift:10-14`) is `.open(UUID, AppStateStore.ProjectOpenMode)`, `.edit(UUID)` or `.newProject`. `openAction(optionHeld:)` (`:133-136`) returns `.open(id, .openNew)` with Option held and `.open(id, .focusExistingOrOpen)` otherwise; `AppStateStore.ProjectOpenMode` (`Runtime/AppStateStore.swift:1258-1263`) and `openProject(id:mode:)` (`:1299-1321`) select the existing Session (`window.setSelectedSession`, `activateWindow`) for `.focusExistingOrOpen` when one is open, and build a new one otherwise. The sheet is presented from `WindowRuntime.projectPickerShown` (`Runtime/WindowRuntime.swift:78`) through `SessionDetailView`'s `projectPickerBinding` (`Views/SessionDetailView.swift:315-320`); the view hands the picker `store.projectStore?.projects` and `store.openProjectIDs` (`Runtime/AppStateStore.swift:1273-1275`) as closures and acts in the sheet's `onDismiss` (`SessionDetailView.swift:104-113`).

**Layout.** `ProjectPickerView` is a fixed `720 × 520` sheet (`ProjectPickerView.swift:82`). Header (`:62-68`), filter field (`:91-119`), `Divider`, then the empty state or the grid, then the footer (`:171-189`). The grid is a `LazyVGrid` with `ProjectPickerModel.columnCount` (= 3, `ProjectPicker.swift:45`) `.flexible()` columns, 12 pt spacing and 16 pt padding (`ProjectPickerView.swift:121-139`), so every card is the same width, about 221 pt. `ProjectPickerCardView` (`:217-293`) is a 108 pt-tall thumbnail (`:288`), the Project symbol and name with the OPEN badge (`:224-239`), the `~` path and the summary line, with 10 pt padding, a 9 pt corner radius and a 2 pt accent border when selected (`:253-259`). About two rows are visible at once. The only grid test is the layout smoke test `ProjectPickerViewTests.theSheetLaysOutWithCardsAndWithTheEmptyState` (`BattyKit/Tests/BattyKitTests/ProjectPickerTests.swift:479-480`).

**Keyboard.** The filter field handles the four arrows, Return / Option-Return and Escape through `onKeyPress` (`ProjectPickerView.swift:100-110`); ⌘E and ⌘N are hidden buttons with key equivalents (`:201-214`). `ProjectPickerModel.move(_:)` (`ProjectPicker.swift:103-129`) is row-major over a uniform grid: left/right step by one, up/down use `index ± columnCount`, nothing wraps, and down from a column the short last row lacks lands on the last card. There is no Home/End. A two-tier grid with different column counts per tier breaks the `index ± columns` arithmetic. Unit tests: `selectionMovesOverTheGridWithoutWrapping` (`ProjectPickerTests.swift:171`), `downFromAColumnThePartialLastRowLacksLandsOnTheLastCard` (`:194`), `arrowKeysFollowTheRankedOrder` (`:86`), `cardsAreRankedByRecencyWithOpenProjectsLastAndStillMarkedOpen` (`:65`).

**Scrolling.** `onChange(of: selectedID)` scrolls to the selected card (`ProjectPickerView.swift:140-142`). It fires only when the id changes, so a re-rank that moves the selected card (a Session opening or closing while the sheet is up) does not scroll to it (#0492 Gotchas).

**Identifiers** (`docs/ui-features.md:965-972`): root `project-picker.root` (a `.contain` element since #0484, `ProjectPickerView.swift:86-87`), `project-picker.filter`, `project-picker.hint`, cards `project-picker.card.<name>` (`:264`), OPEN badge `project-picker.open-badge.<name>` (`:237`), empty state `project-picker.empty` (`:168`) with `project-picker.new-project` (`:159`). There is no identifier for the grid itself.

**Pure cursor precedents.** `SessionColorGridCursor` (`Views/SessionColorPickerView.swift:13-78`): a 5-column swatch grid plus a full-width "Automatic" row below it, with vertical moves crossing between the two sections (down from the last swatch row lands on Automatic; up from Automatic returns to column 0 of the last row), all 44 transitions tested. `ProjectSymbolGridCursor` (`Model/ProjectSymbolGridCursor.swift:9`): a 6×6 grid, clamped, no wrap, 144 transitions tested. The two-tier picker cursor is the same kind of type with sections of different column counts.

**UI-test seams.** `ProjectFixture.project(name:root:layout:preset:runStartupCommands:symbol:lastOpenedAt:id:)` (`BattyUITests/Support/ProjectsHarness.swift:31-54`) emits `lastOpenedAt` as an ISO 8601 string (`:38`, `:52`); `ProjectsCLITests.swift:36-38` seeds two Projects that way. `ProjectsUITestCase` (`:94`), `launchApp` (`:124`), `presentPicker` (`:227`), `presentPickerFromSidebar` (`:235`), `filterPicker` (`:248`; its narrowing check counts every `project-picker.card.` identifier, `:255`), `pressReturn(in:option:)` (`:261`), `openThroughPicker` (`:268`), `waitForSessions` (`:483`). `ProjectsOpenTests` reads cards and badges by identifier; `testOpenBadgeAndFileMenuCheckMarkFollowTheOpenProject` (`ProjectsOpenTests.swift:207`) presents the picker unfiltered and expects `project-picker.open-badge.Alpha Stack` after the Project is opened. `ProjectsFlagOffTests.testFlagOffRemovesEveryProjectsEntryPointAndWritesNothing` already asserts that the seeded `projects.json` bytes are unchanged after launching and using the menus, palette and Open Quickly (`BattyUITests/ProjectsFlagOffTests.swift:75-77`).

**Design artboards.** The approved #0469 picker artboard is `issues/0469/OpenProject.dc.html` (canvas: https://claude.ai/artifact/WoKFESyWFnQFkM64TF2P5o). It shows one uniform grid; this issue's boards (`issues/0493/`) supersede it for the picker only.

## Expected behavior

The rules in `## Decision` D1–D7, restated as the checklist the reviewer judges the diff against:

1. **Layout (D1, D2).** `860 × 600` sheet. Three large cards under `Recent` in `project-picker.featured`, the rest as compact 4-column cards under `All Projects` in `project-picker.rest`, both from the one ranked list split at 3. Below three Projects: large cards only, no headings, one `New Project…` card (`project-picker.new-project-card`) after the last Project. Zero Projects: today's empty state. Open Projects stay where `.last` ranks them, OPEN badge intact. `⌘N New Project…` always in the footer.
2. **Filtering (D3).** A query collapses to one compact grid in `project-picker.rest` with a `N matches` heading; Escape clears a non-blank query first and dismisses on a blank one; the header caption follows.
3. **Keyboard (D5).** `ProjectPickerGridCursor`, sections `(columns, count)`, the mapped-column rule, Home/End, Left/Right crossing tiers, no wrapping, the short-last-row rule within a section. `ProjectPickerModel.move` delegates to it; the view only forwards key presses.
4. **Scroll after re-rank (D5, last bullet).** An `onChange` on the selected card's position, not a `body` write.
5. **Relative time (D6).** `ProjectRecency.relativeOpenedText(_:now:)` on large cards only; nil for a never-opened Project.
6. **Flag off.** Nothing new. The picker presents only with `featureFlags.projects` on (`docs/feature-flags.md:34`), and the cursor type and the formatter have no I/O. No new gate site; add no row to `docs/feature-flags.md`.

## Notes

- **Binding docs:** `docs/swiftui-observation-rules.md`. The picker's `model` getter is a pure read on every render (`ProjectPickerView.swift:53-56`) and only `base` (query and selection) is state, written from `onKeyPress` and tap handlers. The two-tier view keeps that: tier membership is derived in `body` from the ranked cards; nothing in `body`, `onAppear` or a geometry callback writes `base`. The scroll-after-re-rank fix in D5 must be an `onChange` keyed on something the model exposes (the selected card's tier and index), not a write from `body`. `docs/view-hierarchy.md` is unaffected: nothing here goes near the terminal host.
- **Why a pure cursor type.** `SessionColorGridCursor` exists because the inline math shipped broken in #0336's first review round. A multi-section grid with different column counts is harder than either existing cursor, and every arrow from every cell is cheap to pin in a test. Building it over a section list rather than a hard-coded pair is what lets #0500 add the Open now strip as a third section without touching the arithmetic.
- **Why the strip is a separate issue.** With `.last`, open Projects are a suffix of the ranked list, so Option A as drawn (open Projects at the end of All Projects, OPEN badge on) is a complete, reviewable step on its own and is exactly what the A board shows. #0500 then partitions that suffix into its own strip, adds the chip view with its switch / open-another-copy actions and the third cursor section, and carries its own tests. ## Resolution notes

> 🟢 Resolved 2026-10-13. The Open Project picker is now the two-tier Option A design the user chose:
> - **Layout:** an 860×600 sheet. Three large **Recent** cards, each with a 132 pt thumbnail, summary and relative time, sit over a 4-column compact **All Projects** grid.
> - **Filtering:** typing collapses everything into one grid with an "N matches" heading. Escape first clears the filter, then dismisses the picker.
> - **Few Projects:** with 1 or 2 Projects, every Project is a large card, followed by a **New Project…** card. With 0, the existing empty state shows. ⌘N **New Project…** is always in the footer.

## Fix

- `ProjectPickerGridCursor` is a pure, multi-section cursor. It maps columns 3→4 as `0,1,2→0,2,3` and 4→3 as `0,1,2,3→0,1,1,2`. A column is clamped to the target row's card count, and nothing wraps.
- `ProjectPickerModel` gained:
  - `featured`, `rest`, `featuredColumns` and `restColumns`;
  - `escape() -> ProjectPickerEscape`;
  - the match count;
  - `selectedPosition`. After a re-rank, the view scrolls through an `onChange` on it.
- `ProjectRecency.relativeOpenedText(_:now:)` produces the relative time.
- The New Project card is sized by a hidden stand-in with the large card's structure.
- The hint has an explicit accessibility label.
- With the flag off, nothing changes.
