## Description

Phase 3 of the #0234 multi-window umbrella: make `TerminalHostStore` manage **one persistent `TerminalHostView` per content window** instead of a single `hostView`, per `docs/multi-window-design.md` §3. This is the highest-risk phase — it touches the terminal-lifetime architecture from #0072/#0074/#0075.

Scope:

- `TerminalHostStore.shared.hostView(forWindowID:)` lazily creates and permanently owns one host per `WindowID`; `TerminalHostInstaller` gains a `windowID` parameter and returns that window's host from `makeNSView` (still Pattern 3 from `docs/nsviewrepresentable-state-persistence.md`; `updateNSView`/`dismantleNSView` stay no-ops).
- `terminalViews` stays one tab-keyed map (sessions are partitioned, #0234 decision); the store records which window each tab's view lives in, and placement updates flow per window so one window's preference emissions cannot hide another's terminals.
- Host teardown only when its window closes and only after every tab in the window has gone through `releaseTerminalView(forTabID:)` — which remains the sole `removeFromSuperview` caller.
- Extend `docs/view-hierarchy.md` §§3–6 in the same change per the design doc's four amendments (never reparent across hosts; `attached host to window` fires once **per window**; window close routes through the per-tab close path; per-window placement maps guard cross-window churn).

With one window everything must behave byte-for-byte like today; multi-window behavior is only exercisable after #0237.

## Acceptance criteria

- `view.window` is the same `NSWindow` for the entire lifetime of every `AppTerminalView` (per-window invariant, `docs/view-hierarchy.md` §5).
- Log signals: `created`/`released terminal view` exactly once per tab; `attached host to window` exactly once per content window; no `io_exec: started subcommand` outside tab creation.
- `scripts/build.sh unit` passes; full UI suite passes; the manual `docs/terminal-pane-requirements.md` §6 checklist passes (pointer, keyboard, file/text drop, IME).
- `docs/view-hierarchy.md` updated for multi-host in the same commits.

## Resolution notes

> 🟢 Resolved 2026-06-15 — `TerminalHostStore` now owns one persistent `TerminalHostView` per `WindowID` (`hosts: [WindowID: TerminalHostView]`) instead of a single host. Single-window behavior is byte-for-byte unchanged; multi-window host isolation is correct by construction (exercisable after #0237).

Highest-risk phase of the umbrella (terminal lifetime, #0072/#0074/#0075). No surface can be reparented across hosts; `view.window` is stable per host for each `AppTerminalView`'s lifetime; host teardown is gated on all tabs being released and has no caller until window-close lands in #0239.

## Root cause

Not a bug — Phase 3 of the #0234 umbrella. Starting state: `TerminalHostStore.shared` owned a single process-wide `hostView`, and an `NSView` can live in only one window, so a second window was impossible. This phase makes the host store window-aware.

## Fix

`TerminalHostStore` replaced its single `hostView` with `hosts: [WindowID: TerminalHostView]` and added `hostView(forWindowID:)` (lazy, idempotent per window). `TerminalHostInstaller` gained a `windowID` parameter and returns that window's host from `makeNSView` (Pattern 3 preserved — `updateNSView`/`dismantleNSView` stay no-ops). The single tab-keyed `terminalViews` map is retained (sessions are partitioned); a new `tabWindowMap: [UUID: WindowID]` scopes placement updates per window so one window's emissions can't hide another's terminals. `releaseTerminalView(forTabID:)` remains the sole `removeFromSuperview` caller and now clears the tab's window mapping; `releaseHost(forWindowID:)` tears a host down only after all its tabs are released (no caller yet — window close is #0239). `windowID` reaches the placeholder via a new `\.windowID` environment key injected in `SessionDetailView`. `docs/view-hierarchy.md` §§3–6 were amended in the same change per the design doc's four amendments. A `attached host to window <UUID>` log was added in `TerminalHostView.viewDidMoveToWindow()` (round 2) to satisfy the acceptance criterion's per-window log signal.

## Gotchas

- **`store.windows[0]` is the #0237 seam:** `SessionDetailView` is the only place that reads `windows[0]` directly. #0237 swaps that single source for the per-scene `WindowID` from the `WindowGroup` presented value; the `\.windowID` environment key is already the right abstraction, so only the injector site changes.
- **`releaseHost` has no caller yet (by design):** teardown gating is implemented and unit-tested, but window close — the only legitimate caller — lands in #0239. Until then hosts are created and never torn down, which is correct for the single persistent window.
- **`placements` dict is now effectively write-only:** visibility is reconciled against the `updatePlacements` parameter and `tabWindowMap`, not the stored `placements` dict, so cross-window stale entries are harmless. (Noted by review; not worth a change this phase.)
- **`view.window` stability depends on never reparenting:** the cross-window reparent guard is the backstop — if a tab's view is ever requested for a different window, it logs an error and returns the existing view rather than moving it, preserving the per-window `view.window` invariant.
