## Description

Phase 7 (final) of the #0234 multi-window umbrella: the dedicated regression pass after #0235–#0239 land, per `docs/multi-window-design.md` §9. The umbrella exists because multi-window crosses the app's riskiest paths (#0072/#0074/#0075 terminal lifetime, #0227/#0229/#0230 observation, #0143 pane input); this phase is the backstop for anything the per-phase verification missed.

Scope:

- **Full `BattyUITests` suite on the Mac mini** via `scripts/run-ui-tests.sh` (not raw `xcodebuild test`). The suite was written single-window — audit and update tests that assume one window, and add multi-window coverage (second window opens, per-window selection, cross-window bell jump, window close, restoration).
- **Manual `docs/terminal-pane-requirements.md` §6 checklist executed in every window** (at minimum two windows on two displays): pointer input, keyboard input, file drop, text drop, IME, overlays.
- **Log-signal audit per window** per `docs/view-hierarchy.md` §6: `created`/`released terminal view` once per tab, `attached host to window` once per window, no PTY respawns during navigation or window switching.
- Any regression found is filed as its own issue (per CLAUDE.md test strategy) and fixed before this phase resolves.

## Acceptance criteria

- Full UI suite green on the Mac mini, including the new multi-window tests.
- Manual checklist documented as executed per window, with results noted on this issue (anything not verifiable noted in `## Gotchas` — visual sign-off stays with the user; mark `resolved`, not `closed`).
- Log-signal audit clean in a two-window, two-display session.
