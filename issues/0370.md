# 0370 — `docs/themes.md` still documents a single pre-split `co.sstools.Batty.themeName` key and a Theme-menu checkmark that no longer exists

## Description

`docs/themes.md` describes theme persistence as "one string in `UserDefaults`"
under `co.sstools.Batty.themeName`. #0241 split that into per-appearance slots
over a year of issues ago in tracker terms, and the single key is now only the
legacy migration source. The doc states the old model in three places and cites a
file path that does not exist. A separate paragraph describes a Theme-menu
checkmark that is not in the code either.

A contributor following the "Quick answer key for new contributors" section at
the bottom of this doc — which exists specifically to be trusted without reading
code — would write against the wrong key.

## Expected behavior

`docs/themes.md` describes the shipped model: two per-appearance keys, a legacy
key read once during migration and never again, and whatever the Theme menu's
active-Theme presentation actually is.

## Actual behavior

Verified stale statements:

- **`docs/themes.md:44-45`** — "Writes the theme's display name to `UserDefaults`
  under `co.sstools.Batty.themeName`."
- **`docs/themes.md:129`** — the persistence table: "The complete persistence
  state is one string in `UserDefaults`", with `| Key | co.sstools.Batty.themeName |`.
- **`docs/themes.md:497`** — the Quick answer key: "*Where is the active theme
  stored?* — In `UserDefaults` under `co.sstools.Batty.themeName`
  (`ThemePreference.defaultsKey`)."
- **`docs/themes.md:130`** — cites `BattyKit/Sources/BattyKit/ThemePreference.swift`.
  The actual path is `BattyKit/Sources/BattyKit/Theme/ThemePreference.swift`.
- **`docs/themes.md:33-35`** — "The active theme is marked with a `checkmark`
  system image; non-active themes render as plain text." `grep` for `checkmark`
  across `BattyKit/Sources/BattyKit/Theme/` and
  `BattyKit/Sources/BattyKit/Views/` returns hits only in `SettingsView.swift`
  and `SessionColorPickerView.swift` — nothing in `ThemeSelectorView.swift` or the
  Theme menu path. This was first noted by the filer of **#0363**.

The shipped model, from `BattyKit/Sources/BattyKit/Theme/ThemePreference.swift:15-21`:

```swift
public static let darkDefaultsKey  = "co.sstools.Batty.themeName.dark"
public static let lightDefaultsKey = "co.sstools.Batty.themeName.light"
/// The legacy single-appearance key. Read once during migration; never
/// written after the upgrade path runs.
static let legacyDefaultsKey = "co.sstools.Batty.themeName"
```

with `defaultDarkThemeName = "TokyoNight"` and a light companion default. The
symbol `ThemePreference.defaultsKey` that `:497` names **no longer exists**.

## Notes

### Sequencing

The active-Theme presentation half (`:33-35`) overlaps **#0363**, which is about
the Theme Selector opening on the first Theme rather than the active one. #0363's
notes explicitly park the doc update ("Update `docs/themes.md` when this lands;
the stale key reference is out of scope for this issue"). If #0363 changes how
the active Theme is indicated, write that paragraph once, after it lands, rather
than describing today's behavior and then rewriting it.

The `UserDefaults` half has no such dependency and can be corrected immediately.

### Why this is separate from #0368

**#0368** covers CLI/XPC documentation drift caused by #0361. This is a different
module and a different cause; a prior filer suggested folding it in, and it was
deliberately split out so each issue's citations can be verified independently.
