## Description

Sparkle is wired (per `#0038`) and Batty has a `SUFeedURL` pointing at the as-yet-unbuilt site. Create a static website that serves three purposes:

1. **Marketing / landing page** — what Batty is, screenshots, download link.
2. **Sparkle appcast endpoint** — `appcast.xml` at a stable URL the app polls for updates.
3. **Direct DMG download** — the latest release for users who don't go through the App Store (we're unsandboxed per `CLAUDE.md`; App Store distribution isn't on the roadmap).

The site lives in a new `website/` folder at the repo root. Static HTML/CSS — no framework, no build step beyond maybe copying assets. Will be deployed to `https://batty.sstools.co/` (user manages DNS + hosting).

`Artwork/AppIcon.png` (and the siblings `AppIcon-glow1/2.png`, `AppIcon-original.png`, `BattyLogo.png`) supply the visual identity.

## What `website/` contains

### Folder layout

```
website/
├── index.html              # Landing page
├── changelog.html          # Versioned change log (linked from appcast)
├── privacy.html            # Privacy policy (terminal apps need one for notarization)
├── appcast.xml             # Sparkle feed; updated by the release pipeline
├── assets/
│   ├── batty-icon.png      # Copy of Artwork/AppIcon.png at 512x512
│   ├── batty-icon@2x.png   # 1024x1024 for retina
│   ├── batty-logo.png      # Copy of Artwork/BattyLogo.png
│   ├── og-image.png        # OpenGraph card (1200x630), see "Branding" below
│   ├── screenshots/
│   │   ├── hero.png        # 1600x1000 main shot
│   │   ├── splits.png      # Show panes/splits feature
│   │   ├── tabs.png        # Show tab strip
│   │   └── bell-feed.png   # Bell feed popover
│   └── favicon.ico
├── css/
│   └── style.css           # Single stylesheet, hand-written
└── downloads/
    └── README.md           # Notes on where DMG files land (populated by release.sh)
```

### `index.html` content sections

1. **Hero** — app icon, tagline ("A native macOS terminal multiplexer built on libghostty"), Download button. Subtle glow background using `AppIcon-glow1.png`.
2. **Features at a glance** — three-column grid:
   - Sessions, panes, tabs (with a small splits screenshot).
   - Native AppKit performance via libghostty.
   - Bell feed + per-session mute.
3. **Why Batty?** — one paragraph explaining the niche (Ghostty's engine, multiplexer's structure, native Mac feel). Reference Terminal.app / iTerm2 / tmux as adjacent tools.
4. **Download** — current version, DMG link, system requirements (macOS 15.6+, Apple Silicon and Intel).
5. **Open source** — link to GitHub repo, "built in the open."
6. **Footer** — links to Changelog, Privacy, Contact / Issues, copyright.

### `changelog.html`

A simple reverse-chronological list of versions with their release notes. Sparkle reads release notes from each `<item>` in `appcast.xml`; the HTML changelog is the human-readable canonical copy.

### `privacy.html`

Short policy stating: Batty collects no telemetry, makes no network requests except Sparkle's appcast polling, stores all data locally. Required by macOS notarization in some flows.

### `appcast.xml`

Sparkle's RSS-style feed. Each item has version, build number, release notes (CDATA HTML or `<sparkle:releaseNotesLink>`), enclosure URL pointing at the DMG, EdDSA signature, and macOS minimum version.

Template:

```xml
<?xml version="1.0" encoding="utf-8"?>
<rss version="2.0" xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle">
  <channel>
    <title>Batty</title>
    <link>https://batty.sstools.co/</link>
    <description>Updates for Batty.</description>
    <language>en</language>
    <item>
      <title>Version 0.1.0</title>
      <pubDate>Mon, 12 May 2026 00:00:00 +0000</pubDate>
      <sparkle:version>1</sparkle:version>
      <sparkle:shortVersionString>0.1.0</sparkle:shortVersionString>
      <sparkle:minimumSystemVersion>15.6</sparkle:minimumSystemVersion>
      <sparkle:releaseNotesLink>https://batty.sstools.co/changelog.html#v0-1-0</sparkle:releaseNotesLink>
      <enclosure
        url="https://batty.sstools.co/downloads/Batty-0.1.0.dmg"
        length="0"
        type="application/octet-stream"
        sparkle:edSignature="..."
      />
    </item>
  </channel>
</rss>
```

The `release.sh` script (per `CLAUDE.md`'s scripts section) should generate or update this file on each release. That wiring is its own follow-up.

## Visual / branding

- Color palette derived from `Artwork/AppIcon.png` — the bat purple as the accent, dark backgrounds throughout (it's a terminal app; light theme would clash with the screenshots).
- Use `AppIcon-glow1.png` as a soft hero-background element. CSS `background-image` + `filter: blur(60px)` for a halo behind the icon.
- Typography: system fonts (`-apple-system, BlinkMacSystemFont, sans-serif`) for chrome; a monospace stack (`SF Mono, Menlo`) for any code / terminal-output mockups.
- Mobile-responsive but not mobile-first — desktop is the primary view since Batty is a Mac app.

## Implementation guidance

- **No build step.** Plain HTML + a single CSS file. Easier to maintain, no node_modules.
- **Inline minimal JS** for anything dynamic (e.g. detecting the latest version from `appcast.xml` to populate the Download button). Keep it to ~50 lines.
- **OpenGraph + Twitter card meta tags** on `index.html` so social previews look right.
- **Validate HTML** with `tidy` and check for accessibility issues (alt text on all images, semantic headings).
- **No tracking.** No Google Analytics, no Plausible, no anything. Privacy matters and the audience is technical.

## Deployment

Hosting is the user's call. Likely options:

- **GitHub Pages** off a `gh-pages` branch of this repo or a separate `batty-website` repo. Free, integrates with `release.sh`.
- **Static S3 + CloudFront** if more control is needed.
- **Netlify** for trivial deploys with previews.

Update `Configuration/Build.xcconfig`'s `SUFeedURL` to match the final URL if it isn't already `https://batty.sstools.co/appcast.xml`. Confirm by reading the current value.

## Acceptance criteria

- `website/` exists at the repo root with the folder layout above.
- `index.html` renders a usable landing page with the hero, features, download button, and footer.
- `appcast.xml` is a valid Sparkle 2.x feed with at least one item (can be a placeholder until the first signed release).
- `privacy.html` and `changelog.html` exist with reasonable content.
- Assets (icons, logo, screenshots) are present in `website/assets/`.
- CSS is one file, hand-written, accessibility-friendly.
- The site passes basic HTML / accessibility validation.
- README in `website/` explaining how to preview locally (e.g. `python3 -m http.server`) and how to deploy.

## Out of scope

- Hosting infrastructure setup (DNS, CDN, certificate management) — the user owns this.
- Auto-generated screenshots from a UI-test capture pipeline.
- Marketing copy iteration / SEO optimization.
- Translation / localization.
