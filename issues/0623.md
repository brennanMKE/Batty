## Description

**Related to #0622.** Doc-only. `AGENTS.md`, in "UI test automation (binding)", lists what the standing VM authorization covers. Line 199 says:

```
- Clones, boots, and deletes `batty-uitest-<run-id>` VMs from the `batty-uitest-golden` image,
```

That is out of date. `tools/run-ui-tests-vm.sh` no longer names a per-project golden. It resolves the one shared golden for every project on this host with `tart-golden require --xcode 27.0` (Homelab `protocols/tart-golden/PROTOCOL.md`), as `docs/ui-testing-vm.md` "The golden image" now describes. #0622's review flagged the stale line and left it out of scope.

A grep of `AGENTS.md`, `CLAUDE.md`, `docs/` and `tools/` for `batty-uitest-golden` finds only that one line:

- `AGENTS.md:199` — the line quoted above.

No other hits in `CLAUDE.md` (which only imports `AGENTS.md`), `docs/` or `tools/`.

## Expected behavior

The authorization bullet names the shared golden resolved by `tart-golden require --xcode 27.0`, for example "VMs cloned from the shared golden that `tart-golden require --xcode 27.0` resolves", and keeps the rest of the bullet (sweeping stale `batty-uitest-*` clones) unchanged. The "does not cover" list's "touching the golden image" stays.

## Notes

- `AGENTS.md` is binding guidance; the edit changes wording only, not the scope of the authorization.
