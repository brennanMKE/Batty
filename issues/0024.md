## Description

Detect bell events at the surface level and convert them to per-Tab events. Two sources (PRD §6.13, Concepts → Bell event):

- **ASCII BEL (`\a`, 0x07)** — the classic bell.
- **OSC 9** — `ESC ] 9 ; <message> BEL`, the iTerm-style notification escape with an attached message.

**Acceptance criteria:**
- libghostty's per-surface bell callback is wired and fires a Swift function on every BEL.
- If libghostty exposes the OSC 9 message body, capture it as a `String?` alongside the bell.
- Each event is recorded against the originating Terminal Session: `bellCount`, `lastBellAt`, `lastBellMessage`.
- Hook installation is idempotent and surface-scoped (registering twice for the same surface doesn't double-fire).
- Manually verified: running `printf '\a'` in a shell triggers a bell event; `printf '\033]9;hello\a'` triggers a bell with `lastBellMessage == "hello"`.

## Notes

- **API discovery is part of this issue.** The libghostty API for bell + OSC 9 needs to be confirmed against the current Doxygen / `libghostty.tip.ghostty.org` docs. If only BEL is exposed, capture that and note OSC 9 as a follow-up.
- The actual feed UI, unseen counters, and visual indicators are downstream issues (#0025–#0028).

## Revised approach — 2026-05-08

`GhosttyTerminal` exposes both bell sources via dedicated delegate protocols — no need to dig into raw libghostty callbacks:

- **ASCII BEL (`\a`)** — `TerminalSurfaceBellDelegate.terminalDidRingBell()`.
- **OSC 9** — `TerminalSurfaceDesktopNotificationDelegate.terminalDidRequestDesktopNotification(title: String, body: String)`. This fires on `ESC ] 9 ; <message> BEL` *and* on the iTerm2 `OSC 777 ; notify ; ...` form, with the parsed title and body delivered as Swift `String`s. We get the message body for free.

Together they cover both bell sources from PRD §6.13.

**Revised acceptance criteria:**
- Implement a delegate adapter in `BattyKit` that conforms to both `TerminalSurfaceBellDelegate` and `TerminalSurfaceDesktopNotificationDelegate`.
- Each callback records a bell event against the originating surface — fields per `Concepts.md` → Bell event (`bellCount`, `lastBellAt`, `lastBellMessage`).
- For BEL, `lastBellMessage` is `nil`; for desktop-notification, it's `"<title>: <body>"` (or just `body` if title is generic like "Terminal").
- Hook installation is idempotent and surface-scoped — attaching the delegate to a `TerminalViewState` does not re-fire on view rebuilds.
- Manually verified via `printf '\a'` (BEL) and `printf '\033]9;hello\a'` (OSC 9).

**The downstream feed (#0025) and indicators (#0028) consume from this adapter via `BellFeedStore`.**

### Deferred — 2026-05-08

`TerminalViewState` (the SwiftUI-facing @Observable from GhosttyTerminal) only conforms to four of the twelve delegate protocols: `Title`, `GridResize`, `Focus`, `Close`. **`TerminalSurfaceBellDelegate` and `TerminalSurfaceDesktopNotificationDelegate` are not on `TerminalViewState`**, so there's no SwiftUI-side hook for these events. Same blocker as `#0016` / `#0022`. Routing bell events into our model needs either:

1. A custom AppKit wrapper around `TerminalView` that attaches our own delegate object — substantial rework of the surface integration.
2. An upstream PR that makes `TerminalViewState` conform to the missing protocols and publish `lastBellAt`, `lastDesktopNotification`, `lastPwd`, etc. as `@Observable` properties.

Path 2 is the right long-term fix; this issue and the related ones (#0025, #0026, #0027, #0028) depend on it. Deferred.

## Root cause

`TerminalViewState` didn't conform to `TerminalSurfaceBellDelegate` or `TerminalSurfaceDesktopNotificationDelegate`. BEL and OSC 9 events fired inside `TerminalCallbackBridge` but had no consumer-facing forwarding path. Closed by #0044, which added both conformances and the `bellCount` / `lastBellAt` / `lastDesktopNotification{Title,Body,At}` published properties.

## Fix

`TabRuntime` becomes the per-tab bell record-keeper that the downstream feed/popover/indicators (#0025–#0028) read from.

- New `@Observable` properties on `TabRuntime`: `bellCount`, `unseenBellCount`, `lastBellAt`, `lastBellMessage` (mirroring the long-existing fields on the persisted `Tab`).
- Two recorder methods snapshot the upstream delta and apply it once per "tick":
  - `recordBellTickIfNeeded()` — reads `terminal.bellCount` (monotonic), compares to a private `lastObservedBellCount`, applies the delta into `bellCount` and `unseenBellCount`. Sets `lastBellAt` from `terminal.lastBellAt` (or `Date()` as fallback) and clears `lastBellMessage`.
  - `recordDesktopNotificationIfNeeded()` — keys off `terminal.lastDesktopNotificationAt` so the same OSC 9 doesn't double-count if the recorder is invoked multiple times. Increments by one and sets `lastBellMessage` to `"<title>: <body>"`, `<title>`, or `<body>` depending on which fields are non-empty.
  - Both private "last observed" trackers are `@ObservationIgnored` so recorder invocations don't churn observers.
- `markBellsSeen()` zeros `unseenBellCount`; `bellCount` is the running total for persistence and never resets.
- `PaneView` attaches `.onChange(of: terminal.bellCount)` and `.onChange(of: terminal.lastDesktopNotificationAt)` to each tab, so events arriving in background tabs are still recorded — the SwiftUI hierarchy contains all tabs (just hidden via opacity), so `.onChange` is reliable for any pane currently rendered.
- `WorkspaceConversion` round-trips the new fields through the persisted `Tab` struct (its bell fields were already in the model).

## Files changed

- `BattyKit/Sources/BattyKit/TabRuntime.swift` — added the four `@Observable` bell properties, the two recorder methods, `markBellsSeen()`, and the private notification formatter.
- `BattyKit/Sources/BattyKit/PaneView.swift` — `.onChange` triggers per-tab that call into the recorders.
- `BattyKit/Sources/BattyKit/WorkspaceConversion.swift` — persist + restore the bell fields (no longer hardcoded to zero/nil).
- `BattyKit/Tests/BattyKitTests/TabRuntimeBellTests.swift` (new) — 7 tests covering monotonic delta, burst delta, idempotency, the OSC 9 formatter (both fields, title-only, body-only), idempotent OSC 9 recording, and `markBellsSeen` semantics.

## Gotchas

- **Tests drive bell events through the public delegate methods (`terminalDidRingBell()`, `terminalDidRequestDesktopNotification(title:body:)`)**, not by writing the published properties directly. Those properties are `public internal(set)` in the fork, so external consumers can read but not write. The delegate-method path is also what libghostty uses at runtime, so testing through it is the most realistic harness.
- **Bell events from background tabs are still recorded** because the SwiftUI hierarchy contains every tab via the `ForEach(pane.tabs)`; opacity 0 hides them but they're still in the view tree, so `.onChange` fires. If we ever switch to a lazy-instantiation model for tabs (e.g., to defer surface allocation), this will break and we'll need to move the wiring into `TabRuntime` itself via an Observation tracking closure.
- **BEL and OSC 9 are accumulated as one stream** — both increment the same `bellCount`/`unseenBellCount`. If a shell setup emits BEL alongside an OSC 9 (rare but legal), the user sees a count of 2 for what they perceive as one event. Acceptable for v1; revisit if it shows up in practice.
- **`lastBellMessage` is `nil` for bare BEL events** by design. The bell feed UI (#0026) should treat `nil` as "no message attached" rather than rendering a blank string.
- **Persistence reads/writes `unseenBellCount` literally.** A workspace restored after a crash will show whatever unseen counts were captured at the last save tick — not zero. This is intentional: if the user had unseen bells before the crash, they probably still want to know. They can dismiss via the popover when #0026 lands.
