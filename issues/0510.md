# 0510 — `GatedSampler` can strand a late caller, hanging the System Metrics stale-sample tests instead of failing them

| | |
|---|---|
| **Status** | open |
| **Module** | Tests / System Metrics pane |
| **Platform** | macOS |
| **First seen** | 2026-10-14 |

## Description

The three stale-sample tests each have **two** callers racing the same gate: `setUp(visible: true)` starts `SystemMetricsPaneContent`'s own periodic `Task`, whose first iteration calls `sampleOnce()` immediately, and the test separately creates `tickTask`. `GatedSampler.waitUntilStarted()` only proves that *one* caller has entered, and `release()` only resumes the continuations registered *at that moment* — it records no permanently-released state.

So this interleaving is legal and hangs: the periodic tick enters `sampleOnce()` first and parks; `waitUntilStarted()` returns; the test calls `release()`, resuming it; `tickTask` enters `sampleOnce()` afterwards and parks with nobody left to release it. `await tickTask.value` then waits forever — there is no timeout, and cancelling the task would not resume a `withCheckedContinuation` either. The suite hangs rather than failing, which is the worst failure mode for CI.

The gate's own doc comment already works through the multi-caller problem for `startedContinuations`; it stops one step short for `releaseContinuations`.

Found by an external review of `ad239f9e..v1.2.0` — review id `20261014T193909Z-Batty-883c427`, finding 2 of 2 (medium, tests, confidence high).

## Steps to reproduce

`./build.sh unit` repeatedly. The hang needs the periodic tick to win the race into `sampleOnce()` and `tickTask` to lose it by enough that `release()` lands in between, so it is rare and scheduler-dependent.

## Expected behavior

Once released, the gate stays released: any caller arriving afterwards returns immediately. The tests either pass or fail, never hang.

## Actual behavior

`BattyKit/Tests/BattyKitTests/SystemMetricsPaneContentTests.swift:110-114` drops the released state on the floor after resuming whoever is parked.

## Notes

- Fix: latch it. `release()` sets `isReleased = true` as well as resuming the parked continuations, and `sampleOnce()` returns without parking when `isReleased` is already set.
- The assertions still hold under the latch: every caller in these tests reads `generation` inside `performTick()` before the hide/teardown the gate exists to straddle, so a caller that sails straight through reaches the same discard verdict as one that parked.
