## Description

**Stop asking upstream and start building.** #0293 produced a reviewed, submission-ready upstream write-up asking libghostty to release an occluded surface's GPU resources — and it was never filed. #0388 then proved, with direct runtime evidence, that no Batty-side change can reclaim that memory. This issue implements those asks in **the user's own fork of `libghostty-spm`**, proves the change works against a Beta build of Batty, and stops there: **the PR to upstream is a separate, later step gated on the user.**

The deliverable is: a patch in the fork, a rebuilt xcframework, a measured before/after against Batty Beta showing the drawable histogram change, and a PR branch prepared but **not** pushed or submitted.

Two changes, in this order:

1. **Ask 1 — cheap and additive.** Lower the swap chain's buffer count from 3 to 2 for occluded surfaces, restoring on un-occlusion. Worth ~100–120 MB on the measured instance. Implement this first: it is the smaller, lower-risk change and it validates the whole build-and-measure loop before anything structural is attempted.
2. **Ask 2 — structural.** Free the swap-chain IOSurfaces on occlusion and reallocate them lazily on the next draw, **or** add an explicit suspend/resume pair that releases GPU resources while leaving the surface handle, terminal state, and PTY untouched. This is the one that makes footprint scale with *visible* surfaces rather than *open* ones.

`issues/0293/upstream-issue.md` is the substance of this work — **read it in full before writing code.** It carries the API survey, the measured 3:1 drawable-to-layer ratio, the repo-boundary argument, and the caveats on each ask. Do not paraphrase its evidence away; this issue summarizes it, it does not replace it.

## The problem, now proven rather than suspected

`ghostty_surface_set_occlusion(surface, false)` does not release a surface's Metal swap chain.

#0388 established this by measurement, not inference. Its *Investigation findings (2026-08-31)* section records: occlusion `false` was observed in **live logs** reaching all five hidden Panes, and `vmmap` still showed **21 IOSurfaces = 7 layers × 3** — one clean triple per Pane, `swap_chain_count = 3`, unchanged. Forcibly detaching hidden Panes' `AppTerminalView`s from the window changed nothing either, refuting the retained-`CAMetalLayer` hypothesis the supplied spec had proposed. Hiding the whole app with Cmd-H, which drove `effective=false` for all 7 tabs, also left the histogram at 21.

*(Those findings currently live on branch `issue/0388` and are not yet on `main` — read them with `git show issue/0388:issues/0388.md`, or after that issue lands.)*

On the user's Prod instance this is roughly **510 MB of an 833 MB footprint** held by Panes that are not on screen (17 Terminal Sessions, 578 MB graphics = 69%, 51 large IOSurfaces = 17 swap chains, ~34 MB graphics per Session).

Across the whole public surface lifecycle block there is nothing between "pause rendering" and "destroy everything" — only `ghostty_surface_set_occlusion` and `ghostty_surface_free`, and the latter takes the PTY down with it.

## Implementation

### Ask 1 first

Lower the effective swap-chain buffer count from 3 to 2 when a surface's occlusion flag is set to non-visible, and restore it on un-occlusion. Occlusion tracking already exists at the surface/renderer level; the signal to key off already exists.

**Carry this risk forward from `issues/0293/upstream-issue.md`, which raises it explicitly:** if the buffer pool drains lazily as drawables recycle through drawing, an occluded surface that has *stopped drawing* may never actually shrink from 3 to 2 — the count would only drop the next time that surface draws, which may never happen while it stays hidden. **If that is what the measurement shows, the useful form of the change is an active purge at the occlusion transition** — drop the now-unneeded buffer immediately rather than lowering a target count and waiting.

Note also: `CAMetalLayer.maximumDrawableCount` only accepts 2 or 3, so there is no "lower than 2" variant on that path — though the renderer's actual `IOSurfaceLayer` swap chain may not share that constraint.

### Ask 2 second, only once Ask 1 is measured

Either extend `ghostty_surface_set_occlusion(surface, false)` to free the swap-chain IOSurfaces and reallocate lazily on the next `ghostty_surface_draw`, or add an explicit pair (e.g. `ghostty_surface_suspend_gpu` with an implicit resume on next draw) that releases GPU-side resources while leaving the surface handle, terminal state, and PTY untouched. If a new C entry point is added, it has to reach the Swift wrapper too (`Sources/GhosttyTerminal/Surface/TerminalSurface.swift` — `setOcclusion` at `:201-205` is the model for a thin 1:1 passthrough).

### 3. Establish a baseline on the *unmodified* fork first

Before applying any patch, build the fork's untouched `main`, point Batty at it, and take a full measurement. Two reasons:

- It proves the local-fork plumbing works before any change is in flight.
- It isolates the memory delta to the change rather than to the version swap. The fork's `main` is currently content-identical to Batty's pin (see above), so today this is confirmation rather than confound-removal — **but if the fork's `main` has moved by the time this is worked, the baseline is the only thing that keeps the measurement interpretable.**

### 4. Measure — Beta only

**Measure on the Beta build.** Batty's `./build.sh` defaults to the Beta scheme (`build.sh:42`, `BETA_SCHEME="Batty (Beta)"`); Prod is `./build.sh release`. **Never touch the user's Prod app at `/Applications/Batty.app`.** *(`CLAUDE.md` and `issues/Issues.md` both still describe `./build.sh` as invoking `Batty (Prod)`; the script is authoritative and defaults to Beta.)*

Reproduce #0388's scenario: **one Window, several Sessions, ~7 Panes with only 2 visible**, hidden Panes filled with heavy scrollback. Measure **as the selected Session and the selected Pane change** — that is the transition this work hooks — and cover the Window-occlusion round trip (Cmd-H, minimize, full cover by another window).

**Measure `phys_footprint`, never RSS and never VM size.** `ps -o rss` under-reported by 5.4× on the 2026-08-30 sample and 29× on the original #0285 report; scrollback compression uses `MADV_FREE_REUSABLE`, so VM size will not move either.

```sh
PID=$(ps -Ao pid=,comm= | awk '/Batty Beta\.app\/Contents\/MacOS\/Batty Beta$/{print $1; exit}')
footprint -p $PID | head -14
vmmap $PID | grep '^IOSurface'
```

Use the existing tooling rather than reinventing it: `tools/memsample.sh` is the #0291 harness (see `tools/README.md`) and already diffs before/after by geometry class, not just totals. `BattyKit/Sources/BattyKit/Runtime/TerminalMetalMetricsLogger.swift` logs per-surface `contentsScale` and `drawableSize` and can name a surface's owner.

### 5. The acceptance signal is the drawable histogram

Today: **21 IOSurfaces = 7 layers × 3** — one clean triple per Pane regardless of visibility (672×416 ×15, 334×416 ×6).

- **Ask 1 succeeding means hidden Panes drop from triples to pairs.**
- **Ask 2 succeeding means their triples disappear entirely.**

Baselines to beat: **833 MB footprint / 578 MB graphics / 17 Sessions** on the Prod instance (2026-08-31), and the Beta scenario's own before/after from step 3.

Also confirm, on reveal of an occluded Pane: the swap chain rebuilds with **no visible flash and no stale frame**; terminal content is **current** (the PTY kept reading); cursor blink and any Kitty graphics animation resume. Regression-check Pane drag between Windows, zoom/unzoom, and Window miniaturize/restore.

### 6. Confirm occlusion actually reaches the surface — reuse #0388's logging

Branch `issue/0388` adds `occlusionApply` debug logging at all three `TerminalHostStore` call sites (`TerminalHostStore.swift:407`, `:436`, `:467`), logging `tab`, `isHidden`, `windowVisible`, and `effective`. **Reuse it rather than re-inventing it**, e.g.:

```sh
log stream --predicate 'subsystem == "co.sstools.Batty.beta" AND category == "TerminalHostStore"' --level debug
```

**A fix can look correct everywhere and free nothing.** That trap cost #0387 an entire round: `CAMetalLayer` only reallocates its drawable pool when something calls `nextDrawable()`, which in this stack happens only through `tick() → surface.draw()`, and `scheduleTickIfNeeded()` refuses to schedule once `canRenderFrame` is false. So a change that mutates renderer state and then marks the surface non-visible updates every observable property while freeing nothing. **Sequence the change and the occlusion call deliberately, and verify with `vmmap`, not with the layer's reported `drawableSize`.**

## Scope boundaries

- **The upstream PR is a separate, later step gated on the user.** Publishing to a third-party repo is the user's call. The work stops at *proven locally, PR branch prepared but not pushed or submitted*. Do not open a PR, do not push to `origin`, do not comment on any upstream issue.
- **Whether Batty ultimately re-pins to a fork revision, or the change lands at `Lakr233` and Batty pins that, is a follow-up decision for the user.** Note the options; do not decide.
- **Do not resize hidden Panes.** That was #0387, archived `wontfix` — `ghostty_surface_set_size` reflows and destroys scrollback wrapping.
- **Do not free and recreate surfaces.** `ghostty_surface_free` takes the PTY down with it. The upstream draft also records an open **use-after-free** on that path: `SwapChain.deinit` waits only on the frame semaphore, not on the deferred main-queue present block or the Core Animation transaction flush, so Metal can present a freed IOSurface after renderer teardown.
- **Scrollback limits are out of scope** — a different mechanism (the MALLOC_SMALL ~196 MB / ~11.5 MB-per-Session observation), tracked separately in #0387's Notes and the umbrella.

## Expected behavior

An occluded surface's GPU resources — swap-chain IOSurfaces at minimum — can be released and later reacquired without destroying the surface or its PTY, so Batty's graphics footprint scales with *visible* Panes rather than *open* ones. Ask 1 delivers a partial version of this (hidden Panes hold 2 drawables instead of 3); Ask 2 delivers it fully.

## Actual behavior

`ghostty_surface_set_occlusion(surface, false)` reaches every hidden Pane's surface — confirmed in live logs — and the IOSurface histogram does not move. Every Pane, visible or not, holds a full triple-buffered swap chain for the life of the Session. The only lever that frees GPU memory is `ghostty_surface_free`, which also destroys terminal state and kills the PTY.
