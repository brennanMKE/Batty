## Description

Child of #0660. Claude Code plugins can declare a `SessionStart` hook whose standard output is added to the session's context. The `batty` (or `batty-beta`) plugin that `agent install` stages should run `batty agent context` (#0661) at session start, so a Claude Code session started in a Batty Pane knows it is in Batty, and which Pane, before its first turn, with no instruction file and without the agent running `env`.

### Current state

- `AgentGuidanceInstaller.stageMarketplace` (`BattyKit/Sources/BattyCLICore/AgentGuidanceInstaller.swift:358-386`) writes `.claude-plugin/marketplace.json`, the plugin's `.claude-plugin/plugin.json`, `.mcp.json` (the `mcp` server, absolute path to the bundled CLI, `identity.cliExecutablePath`) and `skills/batty-cli/SKILL.md`. No `hooks/hooks.json`.
- The plan then runs `claude plugin marketplace add <dir>` and `claude plugin install <plugin>@<marketplace>` (`AgentGuidanceInstaller.swift:237-249`).
- The user's hand-written `~/.claude/CLAUDE.md` section asks the agent to run `env | grep '^BATTY'` at session start. A hook makes that step unnecessary.

### Claude Code hook format (checked 2026-11-18)

Sources: https://code.claude.com/docs/en/hooks and https://code.claude.com/docs/en/plugins-reference. What they say:
- A plugin's `hooks/hooks.json` at the plugin root loads automatically, with no `hooks` key needed in `plugin.json`. The file has a top-level `"hooks"` wrapper and an optional top-level `description`. A file without the wrapper fails to load.
- `SessionStart` matchers are `startup`, `resume`, `clear`, `compact`, `fork`. An omitted matcher matches every start. **Decision: no matcher**, so the note comes back after `/clear` and compaction (the issue's recommendation).
- For `SessionStart`, plain-text stdout from an exit-0 command is added as context. A non-zero exit never blocks the session. Its stderr goes to the user only.
- Command hook `timeout` is in seconds and defaults to 600.
- A `command` with no `args` runs through `sh -c` (shell form). Exec form (`args`) is newer, and the docs don't give its minimum version. **Decision: shell form**, with the path single-quoted.
- A hook process inherits Claude Code's environment, so it sees the Pane's `BATTY_*` variables.
- `version` pins a plugin, except one loaded in place from a marketplace added from a local path, which is what this is. A re-install is therefore picked up.

### Decisions

1. **Command path: absolute bundled CLI, not `PATH` and not `${CLAUDE_PLUGIN_ROOT}`.** The CLI lives in the app bundle, not in the plugin, and `.mcp.json` already uses the same path. Command string: `'<cliExecutablePath>' agent context`. The path is POSIX single-quoted, with any `'` written as `'\''`. Quote it every time, not only when needed, so the string is predictable and tests can pin it exactly.
2. **Outside Batty:** nothing extra. #0661 guarantees empty stdout and exit 0. No `|| true` wrapper, which would hide a real regression and is not needed for exit 0.
3. **Timeout: `"timeout": 10`.** The command only reads the environment, so 10 s is a hang guard, not a budget. The 600 s default could stall session start if the binary ever hung.
4. **Prod/Beta naming** follows the identity: plugin dir `batty` / `batty-beta`, path into `Batty.app` / `Batty Beta.app`. No new naming.
5. **Description:** top-level `"description": "Tell Claude Code it is running in a Batty Pane, and which one."`. It is optional, but `claude plugin list` shows it.
6. **Other hosts:** out of scope, as the issue recommends. Codex and OpenCode rely on #0662's MCP `instructions` and #0664's prompt.

## Root cause

Feature work. `stageMarketplace` wrote the plugin manifests, `.mcp.json` and the skill, but no `hooks/hooks.json`, so Claude Code learned it was in Batty only if it read a note or ran `env`.

## Fix

As planned. `stageMarketplace` now writes `<plugin>/hooks/hooks.json`: a top-level `description` and one `SessionStart` group, with no `matcher`, holding one command hook (`timeout: 10`). The command is `'<cliExecutablePath>' agent context`, built by the new public `AgentGuidanceInstaller.sessionStartHookCommand(cliExecutablePath:)`, which always single-quotes the path and writes `'` as `'\''`. The `.stageMarketplace` doc comment and the Claude Code bullet in `docs/batty-cli-agent-workflows.md` mention the hook. No deviations.
