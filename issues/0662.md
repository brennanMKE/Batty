# 0662 — `batty mcp`'s `instructions` say the agent "may be" in Batty instead of naming its Session, Tab and Pane

## Description

Child of #0660. MCP hosts put the server's `initialize` `instructions` into the agent's context, so this is the one place every MCP-capable host (Claude Code, Codex, Cursor, OpenCode) tells the agent about Batty without any instruction file. Today the text is fixed and hedged. It should state what the server's own environment says: in Batty with these ids, or not in a Batty Pane.

### Current state

- `MCPServer.instructions` is a static string: "You may be running inside Batty, a macOS terminal multiplexer. These tools mirror the batty command-line verbs … Omitted Session/Pane/Tab targets resolve to your own Pane through the BATTY_* environment variables. Call capabilities for the full vocabulary." (`BattyKit/Sources/batty/MCPServer.swift:72-77`), sent unchanged by `initializeResult` (`MCPServer.swift:147-156`).
- The server runs with the agent's environment, and each tool's child process inherits it (`BattyKit/Sources/batty/MCPToolRunner.swift:16-18`), so the server can read `BATTY_*` at start-up and knows whether targets will default to a Pane.
- The instructions name no tool for any view: nothing maps "git status" to `pane_split` with `view: git-status`, or "dev server" to `server_start`.

## Expected behavior

- `MCPServer` takes its instructions as an init parameter. `MCPCommand.run` builds them from the process environment with #0661's builder.
- In a Batty Pane: "You are running in a terminal Pane of Batty … Session S, Tab T, Pane P. Tools with no target act on this Pane." plus the shared rules and a short tool map: status views → `pane_split` with `view`; dev servers → `server_start`/`server_attach`; static sites → `server_serve` with `open`; a page → `server_preview`; a command in a new Pane or Tab → `pane_split` with `command` / `tab_new` (#0667, #0668); attention → `notify`; later → `session_remind`.
- Outside Batty: says the agent is not in a Batty Pane, that tools act on Batty's focused Pane unless given ids, and to use them only when the user asks for Batty.
- Kept short (MCP hosts may truncate instructions; aim under ~1,500 characters).

## Acceptance criteria

1. `MCPServerTests` asserts the `initialize` result's `instructions` for an in-Batty environment fixture (contains the three ids and the tool names) and for an empty one (contains no id, says "not").
2. A test that every tool name the instructions mention exists in `MCPToolCatalog(payload:)` for the flag-on payload, so a renamed verb fails the build's tests, not the agent.

## Open questions

1. **Codex passes no `BATTY_*`?** If #0665 confirms Codex filters the environment, the server sees none and says "not in a Batty Pane" while it is. Recommended: #0665's `env_vars` fix; no special case here.
