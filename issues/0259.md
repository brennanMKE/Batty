# 0259 — Sidebar pane rows: replace the path label with a column/row position prefix

| | |
|---|---|
| **Status** | open |
| **Module** | Sidebar / Pane |
| **Platform** | macOS |
| **First seen** | 2026-07-08 |

## Description

The pane rows that appear below the session name in the sidebar currently show the pane's path (after #0258 routed the label through `TabTitleFormatter.chipTitle`). The user doesn't like this: the path gives **no way to identify where the pane is** in the split layout. Two problems, in the user's words:

1. "It is currently the path but has no way to identify where the pane is."
2. "The path … also does not change when the user changes directory anyway" — the label is stale: `cd`-ing in the terminal does not update the sidebar row.

## Desired behavior

Use **column and row numbers** to show where the pane is, as a **prefix that replaces the path**:

- `1/1` — the first pane.
- `2/1` — the pane split horizontally from it (second column, first row).
- `1/3` — first column, third row (two vertical splits in column 1).

So a session with one horizontal split then two vertical splits in the left column would list panes as `1/1`, `1/2`, `1/3`, `2/1`.

## Open questions (for the implementer to confirm or the user to decide)

- **Is the position the whole label, or a prefix to something?** The request says "add these numbers as a prefix and replace the path". Reading: the position replaces the path as the label. If a tab has a user-set rename (`titleOverride`), it likely still deserves display — suggest `1/2 — <custom name>` when a rename exists, position alone otherwise. Confirm with the user if unclear during review.
- **Hidden panes** (#0256) keep their slot in the split tree — they should keep their position number too (the slot doesn't collapse), so a restored pane reappears with the same coordinates.
- **Deep/mixed nesting**: column/row reads naturally for layouts that are "columns of rows" (horizontal splits at the top, vertical within). For pathological nesting (a horizontal split *inside* a vertical row), define a sensible rule — e.g. derive coordinates from the pane's actual frame (x-order → column, y-order → row) rather than tree shape.

## Technical notes

- **Position derivation:** two candidate sources —
  - `SplitTree` structure (`.split(id:direction:ratio:left:right:)` in `BattyKit/Sources/BattyKit/Model/SplitTree.swift`): walk the tree, horizontal splits advance the column, vertical splits advance the row. Simple for canonical layouts; needs the nesting rule above.
  - `SessionRuntime.paneFrames` (`PaneFrameTracker`) already tracks real pane frames — sorting frame origins (x → column, y → row) gives coordinates that match what the user *sees*, regardless of tree shape. Likely the more robust source; verify it's populated for background sessions.
- **Label site:** `PaneRow.paneLabel` in `BattyKit/Sources/BattyKit/Views/SessionSidebarView.swift` (the #0258 `chipTitle` call is what gets replaced).
- **The stale-path observation** is worth a quick root-cause look while in there: `chipTitle` reads `tab.terminal.workingDirectory` / `terminal.title`, which should update on OSC title changes — if the sidebar row wasn't re-rendering on cwd change, that staleness may also affect tab chips. Fixing the label to position-based sidesteps it for the sidebar, but note whatever is found for a follow-up if the chips are affected too.
- Positions must update when panes are split, closed, or swapped (`pane swap` / drag) — they're derived state, so compute in the view from observed model state rather than storing.
- The #0257 CLI ("Pane N" fallbacks, future `batty pane list`) would benefit from the same coordinates — keep the position formatter reusable (e.g. a small helper on `SplitTree` or near `PaneFrameTracker`), not buried in the view.

## Verification expectations

- Unit-test the position derivation: single pane → `1/1`; horizontal split → `1/1`, `2/1`; vertical splits in a column → `1/1`, `1/2`, `1/3`; positions stable when a pane is hidden; positions correct after close/swap.
- `scripts/build.sh unit` + `scripts/build.sh` green.
- Visual sign-off (user): rows read `1/1`, `2/1`, … and no longer show paths.
