## Description

Terminal backgrounds and see-through windows are built on `main` but stay Beta-only behind `FeatureFlags.terminalBackgrounds`. Prod has no gear on a Pane row, no Session background menu items, no background section in Settings, no Background row in the Project Editor, and its windows never go see-through. The user asked for this feature in 1.3.5. `AGENTS.md` "Release branches" says to remove a flag in the release that ships the feature, and [#0504](0504.md) is the precedent. This issue removes the flag, so the feature is always on in Prod and Beta, and writes the Help text the flag held back.

**The release stays gated on the user's go-ahead.** Landing this issue doesn't cut 1.3.5.

**The user hasn't signed off on see-through visually.** No agent has seen the desktop show through a window (#0539 `## Gotchas`), and that sign-off is the user's. The issue can reach `resolved`, not `closed`, without it. Beta already runs this code path, so the check can happen in Batty Beta at any time, and it should happen before the user approves the release. See "User sign-off" below.

## Verified facts (2026-11-03, `main` at `a4732d0e`)

- **`terminalBackgrounds` is the only flag.** `FeatureFlags.swift` has that one property, plus `resolved(bundleIdentifier:environment:)`, `applyingUITestOverride`, `uiTestEnvironmentVar` and `uiTestForceBackgroundsOffVar`. It has no `current`, and nothing in the CLI reads it. `UITestDriver.scriptEnvVar` is already its own literal (`Testing/UITestDriver.swift:17`), so it doesn't depend on `FeatureFlags`.
- **`docs/feature-flags.md` is current but incomplete.** Each of its 11 bullets matches the code. The grep below finds a few sites the page doesn't list, marked **new**.
- **A Prod user who sets nothing should see no change.** `withBackground` emits no line for an unset image or for opacity 1 (`SettingsPreferences.swift:370`), and `isWindowSeeThrough` needs a Pane below 1. This is from reading the code. Prod hasn't been launched with the flag on.
- **Image folders are per variant.** `TerminalBackgroundImageImporter.appWideDirectory()` builds on `SessionNameCache.resolvedDirectoryName`, so Prod and Beta don't share copies. The plan should confirm this for `ProjectBackgroundLibrary` too.
- **`release/1.3` has no `FeatureFlags.swift`.** #0504 removed the old flag before 1.3.0, and #0374 re-created the file on `main` after that branch was cut. See "Release branch".

## Decisions

These follow #0504. The planner can change them with a reason.

1. **Delete the `FeatureFlags` type, not only the property.** An empty struct, `AppStateStore.featureFlags` and the `featureFlags:` init parameter would be dead code. The next flag re-adds it from the recipe in `docs/feature-flags.md`. `ServiceNames.Variant` and `ServiceNames.current` stay, because they have other users.
2. **Every gate collapses to its flag-on branch.** Nothing visible in Beta changes. Prod gains the Beta behaviour.
3. **`AppWideBackgroundGate` stays, without `isEnabled`.** It is still the only route from the persisted keys to a config builder, because it proves an image is the importer's unchanged output. Only the flag check goes. `TerminalBackgroundSettings.off` also stays, because `withSharedPreferences` tests and `?? .off` fallbacks use it.

## Unverified risk for the plan

**A Mac on 1.3.4 and a Mac on 1.3.5 can now exchange Project records that carry a background.** While the flag was on only in Beta, #0540 noted that Prod was unlikely to meet the field. With the flag gone, Prod Macs can save it and sync it while another of the user's Macs is still on 1.3.4. Whether 1.3.4 drops the unknown field when it writes the record back hasn't been checked. The plan should read `release/1.3`'s `ProjectSync.swift` and report the result. If the field gets dropped, the plan should say whether that needs a change or a line in the release notes.
