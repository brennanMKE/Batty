# 0161 — UI test suite: theme application (global, per-session, fallback chain)

| | |
|---|---|
| **Status** | resolved |
| **Module** | Tests / Theme |
| **Platform** | macOS |
| **First seen** | 2026-05-20 |

## Description

The theme system has accumulated bugs at a high rate — [[0033]], [[0135]], [[0137]], [[0138]], [[0139]], [[0140]], [[0147]], [[0149]] — and every one of them was a "looks wrong" bug only catchable by eyeballing the running app. A UI suite that asserts on `accessibilityValue` for the resolved theme name on every visible chrome surface (window background, tab bar, sidebar, pane border, divider) would have caught most of them.

## Regressions this suite would have caught

- [[0033]] — Initial View → Theme menu wiring. A test selecting a theme and asserting the resolved theme on a surface changes accordingly is the regression baseline.
- [[0135]] — Window chrome should change with the active theme. A test asserting `accessibilityValue` on the toolbar / title-bar surface includes the theme name would have caught the omission.
- [[0137]] — Theme selector sheet with filter and color grid. A test opening the sheet, typing in the filter, asserting the visible grid count drops, would have caught wiring breaks.
- [[0138]] — Pin themes to the top of the selector. A test pinning a theme and asserting it appears in the pinned section would have caught it.
- [[0139]] — Per-session theme override from the sidebar context menu. A test setting Session 1 to theme A and Session 2 to theme B, then asserting each session's visible chrome differs, would have caught fallback-chain bugs.
- [[0147]] — New sessions auto-apply the persisted global theme. A test setting a global theme, creating a new session, asserting it uses the global, would have caught the wiring miss.
- [[0149]] — Theme system broken: global/local fallback chain not implemented correctly. The session-vs-global precedence has explicit tests.

## Test cases

All tests use [[0158]] driver intents.

### Global theme application — would catch [[0033]], [[0135]]

- **`applyTheme(name: "Aardvark Blue")` changes visible chrome.** Assert toolbar / sidebar / pane border accessibility values include `"theme=Aardvark Blue"` (add the value on the chromed views).
- **Cold launch applies persisted global theme.** Launch script: set theme, restart app (via terminate + launch). Assert the chrome reflects the persisted theme on the second launch.

### Per-session override — would catch [[0139]], [[0147]], [[0149]]

- **Per-session theme overrides global.** Driver: `applyTheme("A")` then `applyThemeToActiveSession("B")`. Assert Session 1's chrome shows B and a newly created Session 2 shows A (the global default).
- **Reset session theme returns to global.** Driver: same as above, then a new `resetSessionTheme(name:)` intent. Assert Session 1's chrome returns to A.
- **New session inherits global, not previous session's override.** Set Session 1 to B (per-session), create Session 2, assert it shows A (global).

### Theme selector sheet — would catch [[0137]], [[0138]]

- **Opening the selector lists themes.** A new `openThemeSelector` intent. Assert at least N theme rows are visible (use `theme-row.<name>` identifiers).
- **Filter narrows visible rows.** Type into the filter field (existing identifier or new `theme-selector.filter`). Assert visible row count drops.
- **Pinning surfaces in the pinned section.** Click pin on a row (new `theme-row-pin.<name>` identifier). Reopen selector. Assert the pinned theme appears in a `theme-selector.pinned-section`.

### Window chrome — would catch [[0135]], [[0140]]

- **Toolbar background reflects the active theme.** Capture toolbar `accessibilityValue`; compare for two themes with distinctly different chrome colors.
- **No divider lines through themed chrome.** Visual regression that's hard to assert via XCUITest alone — gate this on a snapshot test or accept that it stays manual. Document explicitly.

## Accessibility identifiers / values needed

- `accessibilityValue("theme=<name>")` on: toolbar root, sidebar root, each pane border, each split divider, each tab bar.
- `theme-selector.root` on the selector sheet view.
- `theme-selector.filter` on the search field inside the sheet.
- `theme-row.<name>` on each row in the selector.
- `theme-row-pin.<name>` on each row's pin button.
- `theme-selector.pinned-section` on the pinned subgroup.

## Driver intents needed (from [[0158]])

- `applyTheme(name:)` — global.
- `applyThemeToActiveSession(name:)` — per-session.
- `resetSessionTheme(name:)` — clear override.
- `openThemeSelector` / `closeThemeSelector`.
- `pinTheme(name:)` / `unpinTheme(name:)`.

## Out of scope

- Parsing of `.ghostty` theme files (covered by [[0032]] in BattyKit unit tests; no UI surface).
- Visual snapshot testing of pixel-accurate chrome (a separate concern; recommend a separate issue if pursued).
- Theme migration / format changes.

## Acceptance criteria

- All test cases pass under `xcodebuild -scheme 'Batty (Beta)' -destination 'platform=macOS' test`.
- Each test comment names the regression it covers.
- The "[[0140]] divider lines" case is documented as visual-only and listed in the test file's header comment as a known gap.

## Notes

- Depends on [[0158]].
- The fallback chain assertions (global vs per-session vs default) are the highest-value subset — the [[0149]] regression cost the most user pain. Prioritize those when implementing.
