# 0644 — Exit Shell pastes `exit` into zsh's line editor instead of running it

| | |
|---|---|
| **Status** | open |
| **Module** | Tabs / TerminalSurface |
| **Platform** | macOS |
| **First seen** | 2026-11-15 |
| **Priority** | high |
| **Target** | 1.4.0 |

## Description

Tab ▸ Exit Shell (⇧⌘X, also in the Command Palette) is meant to type `exit` and press Return. Instead it delivers `exit\n` as a **bracketed paste**. zsh turns bracketed paste on by default, so under the default macOS shell `exit` sits in the line editor as a highlighted paste region and the shell does not exit. The Tab stays open until the user presses Return.

`ExitDispatcher` sends through `tab.terminal.send(_:)` (`BattyKit/Sources/BattyKit/Commands/ExitDispatcher.swift:28`, `:35`). In the pinned libghostty-spm, `TerminalViewState.send(_:)` is a deprecated alias of `paste(text:)`. That method calls `TerminalSurface.sendText` and from there `ghostty_surface_text`, which is the paste path. Exit Shell has shipped since #0309 (1.x) and is user-facing.

#0641's VM run (`issue/0641`, `issues/0641.md` Verification, "VM failure on `ec69fc29` and round-2 fix") saw this exact mechanism on the paste path. A confirmed multi-line paste sent through the same `terminal.send` reached the VM's zsh prompt as a highlighted bracketed-paste region and did not run until Return.

## Steps to reproduce

1. In Batty Beta, open a Terminal Tab running zsh (the macOS default login shell; bracketed paste on, which is zsh's default).
2. Open a second Tab in the same Pane (⌘T) so closing one is easy to see.
3. Press ⇧⌘X (or choose Tab ▸ Exit Shell, or run Exit Shell from the Command Palette).

## Expected behavior

The shell runs `exit` and its process ends. The Tab closes under the normal terminal-lifecycle rules (`PaneView.swift:235`, `tab.terminal.onClose`), the same as typing `exit` and pressing Return.

## Actual behavior

Expected from the code, not yet observed on this exact path: `exit` appears at the prompt inside a bracketed-paste region (with a trailing newline in the edit buffer) and is not executed. The Tab stays open. Pressing Return then runs it.

## Notes

### Premise check (code)

- `BattyKit/.build/checkouts/libghostty-spm/Sources/GhosttyTerminal/State/TerminalViewState.swift:118-130`, `paste(text:)`: "a program that enabled bracketed paste receives it framed as a paste, so a `\r` in it lands in the shell's edit line instead of running it. Keystrokes — Enter, Tab, Ctrl+C — go through `sendKey(_:)`." It calls `surface.sendText(text)`.
- Same file, `:132-140`, `send(_:)`: `@available(*, deprecated, renamed: "paste(text:)", message: "The text path is a paste; press keys with sendKey(_:).")`. Its doc comment: "the name led hosts to `send("ls\r")`, which a shell with bracketed paste on does not run." The body is `paste(text: text)`.
- `.../Surface/TerminalSurface.swift:46-59`, `sendText`: calls `ghostty_surface_text`.
- `.../Surface/TerminalKeyPress.swift:8-17`: `ghostty_surface_text` "is a paste. A pasted `\r` under bracketed paste is text in the shell's edit line, not Enter."
- libghostty-spm is pinned at `a2565ccf` (`BattyKit/Package.resolved`, pinned by #0389/#0397).

### Contradicting evidence searched for, none found

- No UI test runs Exit Shell end to end. In `BattyUITests/AuxiliaryWindowShortcutTests.swift:32`, ⇧⌘X is one chord in a *negative* test. That test asserts the chord does **not** change the topology while an auxiliary window is key, so it would pass whether or not the shell exits. No other test in `BattyUITests` mentions Exit Shell, `exitShell` or `sendExit`.
- `ExitDispatcherTests` covers only target resolution and no-trap behavior. #0309's Verification says "Nothing asserts the payload is `"exit\n"`" and "Not verified headlessly — needs your sign-off: pressing ⌘⇧X in a real Terminal pane". No later issue records that sign-off.
- The codebase already knows about this trap. #0473 (`issues/0473.md:20`) hit it for Project startup commands. `StartupCommandDelivery` (`BattyKit/Sources/BattyKit/Runtime/StartupCommandDelivery.swift:52-55`) documents "`paste(text:)` is a bracketed paste, so a trailing newline would land in the edit line instead of running it". It pastes each line and then presses a real Return (`TerminalStartupInputSink`, `:22-35`, `terminal.sendKey(TerminalKeyPress(.enter))`). `ProjectsStartupTests.testTrustSheetGatesStartupCommandsAndRemembersApproval` passes in the VM with that pattern, because its `touch` marker file appears.

### Every Batty caller of `terminal.send(_:)`

| Call site | Payload | Affected? |
|---|---|---|
| `Commands/ExitDispatcher.swift:35` (via `sendExit`, `:28`) | `"exit\n"`: meant as typed input plus Return | **Yes, this bug.** |
| `Views/PasteConfirmation.swift:100` (unconfirmed paste) | clipboard text | No. A paste is the intended semantics. |
| `Views/PasteConfirmation.swift:106` (`PasteDispatcher.confirm`) | clipboard text | No. A paste, as #0641 concluded. |
| `Views/TerminalHostView.swift:161` (file drop) | shell-quoted paths, no newline | No. Pasting dropped paths is the intended behavior. |
| `Testing/UITestDriver.swift:304` (`.dropFileURLs`) | mirrors the file drop | No. |

All five use the deprecated name. Renaming the four paste callers to `paste(text:)` would clear the warnings without changing behavior, but it is optional and separate from the fix. Entry points into `ExitDispatcher.sendExit`: `Commands/BattyCommands.swift:662` (Tab menu), `Commands/BattyShortcuts.swift:195` (⇧⌘X), `Views/CommandPaletteView.swift:438` (Command Palette).

### Upstream API that does not bracket

- `TerminalViewState.sendKey(_ press: TerminalKeyPress)` at `TerminalViewState.swift:143-151`, and `sendKey(_ key: TerminalKey, modifiers:)` at `:153-157`. Both use the key path (`ghostty_surface_key`, `TerminalSurface.swift:32-43`), which the key encoder turns into real keystrokes.
- `TerminalKey.enter` is at `Surface/TerminalKey.swift:79`. `TerminalKeyPress(typing: Character)` (`Surface/TerminalKeyPress.swift:30`) maps US-layout characters to key presses, so `exit` could also be typed key by key.
- The simplest fix that is already proven is the `StartupCommandDelivery` pattern: `paste(text: "exit")` (no newline), then `sendKey(TerminalKeyPress(.enter))`, through the Tab's `TerminalViewState`. Like startup delivery, it must not go through `AppTerminalView`: the view's `sendKey` commits an open IME composition first (`StartupCommandDelivery.swift:17-20`). The planner chooses between that and typing each character, and could share `StartupInputSink`.

### Tests that must fail first

- **Unit (BattyKit).** The current seam is `ExitDispatcher.sendText: (TabRuntime, String) -> Void` (`ExitDispatcher.swift:31-36`). It hides which upstream API is called, so it cannot tell a paste from a keystroke. Replace it with a recording sink that separates paste from key press, in the style of `StartupInputSink` / `ProjectStartupTests.swift:14`. Then add `ExitDispatcherTests.sendExitPastesWithoutNewlineThenPressesReturn`. It asserts the recorded sequence is a paste of `"exit"` (no `\n` or `\r` in any pasted text) followed by one Return key press. Against today's seam, an equivalent assertion fails: a recorder on `sendText` receives `"exit\n"`, and a no-newline assertion on it fails.
- **VM UI test** (`tools/run-ui-tests-vm.sh`). Add a new class `BattyUITests/ExitShellTests.swift` with `testExitShellShortcutEndsZshAndClosesTheTab`: launch, press ⌘T so the focused Pane has two Tabs, record the focused Tab's id, press ⇧⌘X, and assert through `BattyCLI.waitForTopology` that the Pane drops to one Tab and the recorded Tab id is gone. Leave zsh's bracketed paste at its default; do not set `unset zle_bracketed_paste`. The test should fail on `main` today. A sibling, `testExitShellMenuItemEndsZshAndClosesTheTab`, covers Tab ▸ Exit Shell. Filter: `BattyUITests/ExitShellTests`.
