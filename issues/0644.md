## Description

Tab ▸ Exit Shell (⇧⌘X, also in the Command Palette) is meant to type `exit` and press Return. Instead it delivers `exit\n` as a **bracketed paste**. zsh turns bracketed paste on by default, so under the default macOS shell `exit` sits in the line editor as a highlighted paste region and the shell does not exit. The Tab stays open until the user presses Return.

`ExitDispatcher` sends through `tab.terminal.send(_:)` (`BattyKit/Sources/BattyKit/Commands/ExitDispatcher.swift:28`, `:35`). In the pinned libghostty-spm, `TerminalViewState.send(_:)` is a deprecated alias of `paste(text:)`. That method calls `TerminalSurface.sendText` and from there `ghostty_surface_text`, which is the paste path. Exit Shell has shipped since #0309 (1.x) and is user-facing.

#0641's VM run (`issue/0641`, `issues/0641.md` Verification, "VM failure on `ec69fc29` and round-2 fix") saw this exact mechanism on the paste path. A confirmed multi-line paste sent through the same `terminal.send` reached the VM's zsh prompt as a highlighted bracketed-paste region and did not run until Return.

## Root cause

Confirmed by reproduction. `ExitDispatcher` sent `"exit\n"` through `tab.terminal.send(_:)`, upstream's deprecated alias of `TerminalViewState.paste(text:)`, which calls `ghostty_surface_text`: the paste path. zsh has bracketed paste on by default, so `exit` and its newline landed in zsh's line editor as a paste region and did not run until the user pressed Return. The VM run on the Stage 1 commit (product code unchanged) failed all three new UI tests with exactly that message.

## Fix

Follows the Plan's Stage 2 with no deviations.

- The startup-command sink is shared and no longer startup-specific. `StartupInputSink` became `TerminalInputSink` and `TerminalStartupInputSink` became `TerminalViewStateInputSink`, both moved to the new `Runtime/TerminalInputSink.swift`. The IME doc comment is kept: input goes through `TerminalViewState`, not `AppTerminalView`, so an open composition is left alone. A new `runLine(_:)` extension pastes a line with no newline, then presses a real Return. `StartupCommandDelivery.deliver()` now calls `sink.runLine(line)`, which short-circuits the same way as the old `guard paste, pressReturn`. Its now-unused `import GhosttyTerminal` was dropped.
- `ExitDispatcher`: the `sendText: (TabRuntime, String) -> Void` seam is replaced by `inputSink: (TabRuntime) -> any TerminalInputSink`. Both `sendExit` overloads call a private `typeExit(into:)`, which runs `inputSink(tab).runLine("exit")` and logs an error if the surface refuses input. The type doc now explains why the text is pasted without a newline and followed by Return.
- Tests: a shared `RecordingTerminalInputSink` and a `recordingExitShell { }` helper record paste and Return events separately. Two new `ExitDispatcherTests` cover the shortcut/menu path and the palette path. The three Exit Shell tests in `AuxiliaryWindowGateTests` now use the recorder, so #0641's gating stays pinned: the menu and shortcut send nothing over a key auxiliary window or an attached sheet, and the palette still sends `[.paste("exit"), .pressReturn]` over its own sheet.
- `PasteConfirmation.swift`, `TerminalHostView.swift` and `UITestDriver.swift` are unchanged. Their `send` calls are meant to be pastes.

## Steps to reproduce

1. In Batty Beta, open a Terminal Tab running zsh (the macOS default login shell; bracketed paste on, which is zsh's default).
2. Open a second Tab in the same Pane (⌘T) so closing one is easy to see.
3. Press ⇧⌘X (or choose Tab ▸ Exit Shell, or run Exit Shell from the Command Palette).

## Expected behavior

The shell runs `exit` and its process ends. The Tab closes under the normal terminal-lifecycle rules (`PaneView.swift:235`, `tab.terminal.onClose`), the same as typing `exit` and pressing Return.

## Actual behavior

Observed in the VM on the Stage 1 commit (`build/ui-tests/20261116-001540-26261/`): `exit` appears at the prompt inside a bracketed-paste region (with a trailing newline in the edit buffer) and is not executed. The Tab stays open. Pressing Return then runs it.
