## Description

With "Keep terminals running when Batty quits" on (`co.sstools.Batty.keepTerminalsRunningWhenBattyQuits = 1`) and the BattyHost PTY helper from #0696 in use (SMAppService launch agent `co.sstools.Batty.beta.host`, XPC `co.sstools.Batty.beta.host.xpc`), **File → Restart quits the app and never brings it back.** BattyHost keeps the terminals alive. When the user reopens the app by hand, it reattaches to them correctly:

```
restore: tabs=4 attach=3 exited=0 fresh=1 helperSessions=3
```

So the reattach works. The relaunch never happens.

Seen in Batty Beta 1.5.0 (build 202611220231), `/Applications/Batty Beta.app`, `co.sstools.Batty.beta`, Developer ID signed, on the user's MacBook Air, 2026-11-21.

## Suspected cause (hypothesis, not verified)

Sudden termination is enabled, so AppKit's `terminate:` kills the process right away. It never calls `applicationShouldTerminate(_:)` or `applicationWillTerminate(_:)`. If Restart starts its relauncher, or records the pending restart, from either of those, that code never runs. Nothing in the logs contradicts this. The source has not been read to confirm it.

**Where the code is:** the Restart command, the `HostRestore` logger and the relauncher are **not on `main`**. A `git grep` of every local branch in this checkout finds no `relauncher`, `restart: requested` or `HostRestore`. According to #0716, the BattyHost code (`BattyKit/Sources/BattyHost/main.swift`, `BattyHostCore`, `HostProtocol`, the app's `HostClient`) exists only on `issue/0696`, and that branch is not in this clone. The planner must find that branch, cite the Restart/relauncher code with file:line, and confirm or reject this hypothesis before planning a fix. #0716's Background cites a section of #0696's Findings titled "Restart quit without relaunching: sudden termination". That section is also only on `issue/0696`, so check whether a fix for this was already drafted there.

**Fix direction, if the hypothesis holds:**
- start the relauncher (or durably record the pending restart) *before* calling `terminate:`, and cancel it if the quit is refused; or
- call `ProcessInfo.processInfo.disableSuddenTermination()` while a restart is pending, so AppKit goes through `applicationShouldTerminate`.

Either way, the relauncher must not depend on a termination callback that sudden termination skips.

## Done when

- With Keep Terminals Running on, File → Restart quits Batty Beta and relaunches it on its own, with no Dock click. The relaunched app reattaches every kept Terminal Session (`restore: ... attach=N` matching the live helper sessions).
- With Keep Terminals Running off, Restart behaves as its existing `dropped` path describes, and that path is logged.
- Choosing Restart and then cancelling the quit (if a confirmation can refuse it) does not relaunch later.

## Verification note

Restart is a UI action that quits and relaunches the real app. It needs **manual verification by the user** on the host with Batty Beta installed. Agents must not restart the user's running Batty without asking. Unit tests can cover the ordering, for example that a pending restart starts the relauncher before `terminate:` or disables sudden termination. They cannot prove the relaunch itself.
