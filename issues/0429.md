## Description

This is the LM Studio child of umbrella [#0427](0427.md), and it is **blocked by [#0428](0428.md)** (the shared clock, readiness helper, completion-signal conventions and reap gate). It covers 27 sites. `LMStudioDashboardPaneContent` already has injectable intervals (`modelsPollInterval`, `psPollInterval`, `respawnDelay`: `Runtime/LMStudioDashboardPaneContent.swift:59-71`). But every loop reads them through a real `Task.sleep` (`:271`, `:349`, `:728`). The pipe reader applies parsed lines on its own schedule, and no event tells a test that it has done so. So the tests sleep for "long enough", or poll `waitUntil` to a 30s deadline, or dodge the timers with 30s/24h values.

Work: route the three loops and the stale-in-flight comparison through #0428's clock protocol. Add the completion events #0427 lists (parsed-line applied, poll applied, stream-termination handled, and stream-process launched where launch isn't already synchronous with the factory), in the shape #0428's conventions prescribe. Apply #0428's reap gate to `tearDown`. Then rewrite each row below.
