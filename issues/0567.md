# 0567 — The batty CLI cannot set, show or cancel a Session's Reminder

| | |
|---|---|
| **Status** | open |
| **Module** | App / Session |
| **Platform** | macOS |
| **First seen** | 2026-11-09 |

## Description

Reminders (#0514) can only be set from the GUI: the Session menu, the Sidebar context menu and the Command Palette. An agent running in a Pane can't set its own Session aside with "remind me at 9am to check PRs", and a script can't read whether a Session has a pending Reminder. Add a `batty session remind` verb, and add pending-Reminder fields to the `batty list` / `batty session info` JSON. #0514's "CLI" section recommended this follow-up once the model and scheduler settled; they have. Targets 1.4.0, with no feature flag (#0514: "A later CLI follow-up does not count as 'unfinished' and needs no flag"). Parent: [#0514](0514.md).

## Proposed grammar

```
batty session remind [--session <id>] (--in <5m|90m|1h30m> | --tomorrow [--at 09:00] | --cancel) [--note <text>]
```

- **Exactly one of** `--in`, `--tomorrow` or `--cancel`. `--at` requires `--tomorrow`, and `--note` is invalid with `--cancel`. These are validation errors (ArgumentParser `validate()`), so nothing is sent.
- **`--in` duration.** Accepts `Nm`, `Nh` and `NhMm`, resolved to minutes. It must lie within `ReminderSpec.minMinutes...maxMinutes`, 1 minute to 7 days (`BattyKit/Sources/BattyKit/Model/SessionReminder.swift:57-58`).
- **`--at HH:MM`** is 24-hour, 0-23 and 0-59. When omitted, it uses the same default the GUI uses. That is 9:00 today, or the remembered time once [#0568](0568.md) lands. The plan should decide whether the CLI reads the remembered time or stays fixed at 09:00, and document the choice.
- **`--note`** is normalized by `SessionReminder.normalizedNote`: trimmed, capped at 500 characters.
- **`--session`** resolution matches `session info` / `session close`: flag, then `BATTY_SESSION_ID`, then the focused Session. Use `resolveTargetSessionID(flag:)` (`BattyKit/Sources/batty/SessionInfoCommand.swift:29`).
- **Output.** On success, print the resolved due time, for example "Reminder set for Tue, Nov 10 at 9:00 AM". With `--json`, if the verb family supports it, return `{sessionID, reminderID, dueAt, note, kind}`. `--cancel` on a Session with no Reminder succeeds quietly (idempotent, like `pane hide`).
- **Exit codes.** An unknown or stale Session id, or "no session to target", returns `XPCExitCode.requestFailed` (4, `BattyXPCCore/XPCExitCode.swift:25`). Broker and app failures map the same way as every other verb.

Setting a Reminder replaces any existing one, the same as the GUI (one per Session). It records no feed entry and posts nothing until it fires.

## Verified facts: where the pieces go (main `254cfb2a`)

- **CLI root.** `BattyKit/Sources/batty/BattyCLI.swift:15-19` lists the subcommands. The Session noun is `SessionNounCommand` in `batty/SessionInfoCommand.swift:11-16`, with `subcommands: [SessionInfoCommand, SessionFocusCommand, SessionCloseCommand]`. Add `SessionRemindCommand` there.
- **Closest template: `SessionCloseCommand`** (`SessionInfoCommand.swift:269-322`). It covers the `--session` option, `AppConnectDance.resolveEndpoint()` failure mapping, the `AppServiceClient.sessionClose(...)` call and result mapping, and a `CapabilitiesDescribable` conformance with `capabilitiesInputSchema` (`:322-328`).
- **Client.** `BattyKit/Sources/batty/AppServiceClient.swift`, where `sessionClose` is at `:193` and `notify` at `:118`. Add `sessionRemind(...)`.
- **Verb name.** `BattyKit/Sources/BattyXPCCore/XPCVerb.swift`, where each verb is a documented `static let`; `sessionClose` is at `:102`. Add `sessionRemind`.
- **Payload.** Add a new `BattyXPCCore/SessionRemindPayload.swift` modeled on `SessionClosePayload.swift`, with `SessionRemindRequest` (`sessionID: UUID?`, an action enum of `after(minutes)` / `tomorrow(hour, minute)` / `cancel`, and `note: String?`) and `SessionRemindReply`.
- **App dispatch.** `BattyKit/Sources/BattyKit/XPC/AppXPCService.swift`, where the `case XPCVerb.sessionClose:` block (`:319-351`) is the pattern. It does a main-actor `Task`, decodes the payload, falls back to `AppStateStore.shared.focusedSessionIDFallback()`, and resolves through `pendingRequests`. The handler calls the existing `AppStateStore.setReminder(_:note:forSessionID:)` / `cancelReminder(forSessionID:)` (`Runtime/AppStateStore+Reminders.swift:13`, `:50`). `setReminder` returns nil for an unknown Session or an out-of-bounds spec, which maps to a failure reply.
- **Topology JSON.** `TopologySessionPayload` (`BattyXPCCore/TopologyPayload.swift:197-218`) has no Reminder field. Add an optional `reminder: TopologyReminderPayload?` with `id`, `dueAt` (resolved with the scheduler's calendar), `note`, `kind` (`"instant"` / `"tomorrow"`) and `createdAt`. Encode it so older decoders ignore it. It is built in `XPC/TopologyPayloadBuilder.swift:55`. `batty list` (`batty/ListCommand.swift:71`, `:86`) and `batty session info` (`AppStateStore.sessionInfoPayload`, `Runtime/AppStateStore.swift:657`) both pick it up. Plain-text `list` output could show a clock marker; the plan decides.
- **Capabilities.** `batty capabilities` collects verbs from `BattyCLI.configuration.subcommands` automatically (`batty/CapabilitiesCommand.swift:89-118`), and each verb supplies its input schema through `CapabilitiesDescribable` (`:32`). `CapabilitiesCommandTests` / `CapabilitiesInputSchemaTests` enforce coverage.
- **Tests can reach the CLI target.** `BattyKitTests` depends on `batty` (`BattyKit/Package.swift:99-109`), and existing suites `@testable import batty` (for example `CapabilitiesCommandTests.swift`). The relevant patterns are `AppXPCServiceCloseHideShowTests.swift`, `AppStateStoreCloseSessionForXPCTests.swift`, `ProjectCLITests.swift`, `NotifyPayloadTests.swift` and `XPCContractTests.swift`.

## Acceptance criteria

1. `batty session remind --in 15m` sets a 15-minute Reminder on the calling Session. The Sidebar badge appears, and it fires exactly as a GUI-set one does.
2. `batty session remind --tomorrow --at 09:00 --note "check PRs"` sets a wall-clock Tomorrow Reminder with that note, and the output shows the absolute due time.
3. `--cancel` removes a pending Reminder. Run again, it succeeds without error.
4. Invalid combinations and out-of-range values fail validation with a clear message. An unknown `--session` exits 4.
5. `batty list --json` and `batty session info --json` include a `reminder` object for a Session that has one, and omit it (or give `null`) otherwise.
6. `batty capabilities` lists `session remind` with its input schema.
7. The docs and the skill describe the verb and the agent use case.

## Test ideas

- `remindDurationParsing`: `5m`, `90m`, `1h30m` and `2h` are accepted; `0m`, `10081m`, `1x` and the empty string are rejected.
- `remindArgumentValidation`: none or two of `--in` / `--tomorrow` / `--cancel`; `--at` without `--tomorrow`; `--note` with `--cancel`.
- `sessionRemindRequestRoundTrips` (Codable)

- `xpcSessionRemindCancelIsIdempotent`
