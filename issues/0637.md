## Description

Since #0631 a Session row with a pending or due Reminder grows from one line to three: the title, the Reminder's text and its time ("in 15 min", "due 2 min ago"), with a clock button at the trailing edge. The user's verdict: "Reminders is causing layout problems. And I don't think we should be shoving new content where the session title is anyway." Their screenshots show the three-line row and, once the Reminder had gone and the row had shrunk, a disclosure chevron left drawn over the next row.

The user chose **Design D** for Reminders (`0637/spec.md`, Part 2; mockup `0637/option-D.html`): Reminders get their own toolbar button and popover, and the Sidebar row goes back to one fixed height with at most one fixed-size glyph. This issue is **step 1 of 4** of that change. It is the Sidebar part only and can land on its own.

## Steps to reproduce

1. Launch Batty Beta with two Sessions.
2. Set a Reminder on the first Session (⇧⌘R, In 5 Minutes, or `batty-beta session remind "check" --in 1m`).
3. Look at the Sidebar row: it is three lines tall.
4. Wait for it to fire, then select the Session so the row shrinks back to one line.

## Expected behavior

- A Session row has the same fixed height in every state: no Reminder, pending, fired and unread, or fired and read. The outline goes back to the uniform row height it had after #0627.
- Nothing is drawn under the title or next to it. The only Reminder mark is one fixed 16 x 16 glyph in the trailing badge area, next to the unseen-bell count. It may shorten a long title, as the count already does. It never changes the row's height:
  - pending: `clock`, `.secondary`;
  - fired and unread: `alarm.fill`, in the row's `accent ?? Color.accentColor` (the values `ReminderBadge` and `DueReminderAlarm` use today);
  - otherwise nothing, with no space reserved.
- The glyph is a plain image with a tooltip, not a button. Tooltips are unchanged: "Reminder at 3:45 PM — <text>" (`ReminderActions.detail`), and the due form `DueReminderAlarm` builds today.
- The row's accessibility value keeps its `, reminder pending: …` / `, reminder due` suffix. UI tests read it (`BattyUITests/SessionReminderTests.swift:38-46`).
- A click on the row selects the Session, as for any row. The "click the Reminder lines to edit" entry point goes away. Edit stays on ⇧⌘R, Session ▸ Edit Reminder…, the row's context menu and the Command Palette.
- No disclosure chevron or other stale drawing is left behind as Reminders come and go.

## Actual behavior

The row height varies through `heightOfRowByItem` and `noteHeightOfRows(withIndexesChanged:)`, driven from the representable's update. The stale chevron appeared after a shrink. The design spec treats the `noteHeightOfRows` call made from `apply` as the likely cause but did not reproduce or trace it (`0637/spec.md`, "About the stale chevron"). Removing variable row heights removes the trigger either way. If a chevron artifact shows up again with fixed heights, it is a separate bug in the disclosure positioning restored by #0627; file it then.

## Root cause

Since #0631 the Sidebar row mounted `ReminderLines` (text plus a `TimelineView` time line) under the title while a Reminder was pending or due, and the outline sized rows per item: `SessionSidebarCoordinator.outlineView(_:heightOfRowByItem:)` answered from a `reminderLines` snapshot, and `apply` (run from the representable's update) called `noteHeightOfRows(withIndexesChanged:)` when a row's Reminder state flipped. Confirmed by the red-first run: a row with a Reminder measured 64 pt against a 32 pt baseline. The stale chevron was not reproduced or traced; the spec's hypothesis (the `noteHeightOfRows` call from `apply`) is unconfirmed, but its trigger is gone with variable row heights.

## Fix

As planned. The outline has a uniform `.medium` row height again: `SidebarRowMetrics`, `baseRowHeight`, the `reminderLines` snapshot, the `noteHeightOfRows` block and `heightOfRowByItem` are deleted, so `apply` reads no Bell Feed or Reminder state. `SessionSidebarRow.body` is the single `HStack` again. `ReminderBadge` is a plain, non-button image in a fixed 16 x 16 frame: `clock` (`.secondary`) while pending, `alarm.fill` in `accent ?? Color.accentColor` while fired and unread (absorbing `DueReminderAlarm` and its tooltip), nothing otherwise. `ReminderLines` is deleted; Edit stays on ⇧⌘R, the Session menu, the row's context menu and the Command Palette. The row's accessibility value suffix is unchanged. Docs: Concepts.md (0.33), Help 06-notifications, docs/ui-features.md.

Deviation: also dropped "and Reminder lines" from the `WindowRuntime.reminderBarSessionID` doc comment (`Runtime/WindowRuntime.swift:140`), which the plan's leftover grep caught.
