# 0263 — Sidebar pane list under a session should always be sorted by row then column

| | |
|---|---|
| **Status** | open |
| **Module** | Sidebar / Split |
| **Platform** | macOS |
| **First seen** | 2026-07-09 |

## Description

The per-pane rows under each Session heading in the left-column sidebar (added in #0259) must always be sorted **by row, then column** — all panes in row 1 left-to-right, then all panes in row 2, and so on — and must keep that order as the split layout changes. The user's request, verbatim:

> "The list of panes under the session heading in the left column should always be sorted by row then column. New panes could be added at any time but should maintain this sort order."

To be precise about the sort keys: each pane carries a `column/row` position derived from the split tree (#0259, label form `col/row`). "Sorted by row then column" means primary key = `row` ascending, secondary key = `column` ascending — row-major order, even though the label prints column first.

## Current behavior

The sidebar emits pane rows in `session.tree.allPanes` order (`SessionSidebarView.swift`, the `ForEach(session.tree.allPanes)` around line 39), which is `allLeafPanes` — a depth-first, left/top-first traversal of the split tree. That traversal is not row-major in general. Concrete example: start with pane A, split horizontally (B appears beside it at 2/1), then split A vertically (C appears below it at 1/2). The tree is `horizontal(vertical(A, C), B)`, so the sidebar lists **A (1/1), C (1/2), B (2/1)** — row 2's pane appears before row 1 is finished.

## Expected behavior

- Pane rows under a Session heading are ordered by `row` ascending, then `column` ascending within each row. The example above lists A (1/1), B (2/1), C (1/2).
- The order holds continuously: panes added by splits (at any time, in any pane), removed panes, and rearranged layouts all re-sort into row-then-column order rather than drifting into tree-traversal order.

## Notes

- **View side** — `BattyKit/Sources/BattyKit/Views/SessionSidebarView.swift`: the `ForEach(session.tree.allPanes)` (~line 39) feeding `PaneRow`. `PaneRow` already reads `session.tree.panePositions[pane.id]` for its label (~line 263), so the sort inputs are already at hand.
- **Sort inputs** — `SplitTree.panePositions` / `PanePosition.row` and `.column` in `BattyKit/Sources/BattyKit/Model/SplitTree.swift` (`panePositions()` ~line 460, `PanePosition` ~line 506). The fix is to sort the pane array by `(row, column)` from these positions rather than taking `allPanes` order.
- The sort should be **derived** — recomputed from `panePositions` whenever the tree changes — not a stored order that needs maintenance. Since `panePositions` is itself derived from tree shape, sorting on it self-maintains through splits, closes, and rearrangements.
- Cross-references: **#0259** introduced these pane rows and the position derivation. **#0260** also edits the same `SessionSidebarView` pane-row path (row *labels* / auto-naming); the sort is orthogonal to the naming, but whoever implements either should be aware of the other.
