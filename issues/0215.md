# 0215 — BattyKit swift test target is broken; stale tests reference removed types

| | |
|---|---|
| **Status** | open |
| **Module** | Build / Persistence |
| **Platform** | macOS |
| **First seen** | 2026-05-25 |

## Description

`swift test` in `BattyKit/` does not compile. Four test files reference types that no longer exist:

- `BattyKit/Tests/BattyKitTests/LayoutModelTests.swift`
- `BattyKit/Tests/BattyKitTests/WorkspaceTests.swift`
- `BattyKit/Tests/BattyKitTests/WorkspaceConversionTests.swift`
- `BattyKit/Tests/BattyKitTests/WorkspaceStoreTests.swift`

They reference `Pane`, `Tab`, `SplitNode`, and `Workspace` (the pure-value-type layout model). Those types appear to have been removed or renamed in favor of the current runtime types but the tests were not updated.

The same target is also **not part of the `Batty (Prod)` xcodebuild scheme**, which is why this hasn't surfaced in `scripts/build.sh` runs — so `BattyKitTests` aren't running in CI at all. Discovered during [[0213]] when the subagent needed `swift test --filter ...` to run new tests and had to move the broken files aside temporarily.

## Expected behavior

`swift test` in `BattyKit/` runs all `BattyKitTests` clean, and the `Batty (Prod)` scheme includes `BattyKitTests` so the test target runs in the canonical `scripts/build.sh test` invocation.

## Notes

- Two possible fixes:
  1. **Port the stale tests** to whatever the current runtime types are. Best for keeping coverage of layout/workspace serialization round-trips.
  2. **Delete the stale tests** if the underlying behavior is now covered elsewhere (or never landed). Cheapest, but loses coverage if no replacement exists.
- Either way, add `BattyKitTests` to the `Batty (Prod)` xcodebuild scheme so `scripts/build.sh test` actually exercises it. Otherwise this rot will recur.
- Worth a quick audit while in there: confirm no other `BattyKitTests/*.swift` file is silently broken. The four named above are the ones the [[0213]] subagent hit; there may be more.
