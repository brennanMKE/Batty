# 0225 — Extract tab and session rename logic tests from BattyUITests into BattyKit unit tests

| | |
|---|---|
| **Status** | open |
| **Module** | Testing |
| **Platform** | macOS |
| **First seen** | 2026-05-28 |

## Description

`BattyUITests/TabRenameTests.swift` mixes two concerns: rename logic (pure model state) and UI wiring (does the chip update on screen). The logic half — override priority, empty rename is a no-op, reset clears the override, session rename updates the name cache — can be unit-tested directly against `TabRuntime` and `SessionRuntime` without launching the app.

## Fix

Add `BattyKit/Tests/BattyKitTests/TabRenameLogicTests.swift`. Instantiate `TabRuntime` / `SessionRuntime` / `AppStateStore` directly and call `setTitleOverride(_:)`, `resetTitleOverride()`, `renameSession(id:to:)`. Assert model state, not accessibility identifiers.

Candidate tests to cover (logic slice of `TabRenameTests.swift`):
- `renameOverrideWinsOverShellTitle`
- `emptyRenameStringIsNoOp` — `setTitleOverride("")` should not change the effective title
- `resetTitleOverrideClearsOverride` — `resetTitleOverride()` sets `titleOverride` back to nil
- `renameSessionUpdatesNameInStore`
- `homeDirectoryInTitleIsCollapsedToTilde` — `TabTitleFormatter` path-prettification logic

Keep the UI-facing rename tests in `BattyUITests/TabRenameTests.swift` for the wiring layer (chip-ID updates, accessibility label propagation).
