## Description

#0531 added Build / Unit / UI / Haiku timing columns to `tools/worklog.py`. Its reviewer noted two non-blocking measurement defects. Both are confirmed below against `issue/0531`'s `tools/worklog.py`. Once #0531 is squash-merged, that is the code on `main`.

A Bash `tool_use` is classified by `VM_COMMAND` (UI runs) or `CHECK_COMMAND` via `check_stage()` (Build/Unit runs). A foreground run is then counted only if its `tool_result` has a matching result line: `VM_SUMMARY` for `vm`, or a `CHECK_RESULT` stage in `command_stages(command)` for build/unit. A background run is counted when its task notification arrives, with no result-line check.

### 1. A bare `./build.sh` that is piped or redirected is not counted (undercount)

`CHECK_COMMAND` only accepts the no-action form when `build.sh` is followed by end of string or one of `;&|\n)` right after optional whitespace (`\s*($|[;&|\n)])`). `2>&1`, `>` and `| tail` start with a digit or `>`, so they don't match. The `unit` / `build` / `ui-typecheck` forms pass, because `\b` after the action word matches.

Repro (regexes only):

| Command | `check_stage` | `command_stages` |
|---|---|---|
| `./build.sh` | `build` | `{BUILD}` |
| `./build.sh unit 2>&1 \| tail -40` | `unit` | `{UNIT}` |
| `./build.sh 2>&1 \| tail -20` | **`None`** | **`{}`** |
| `./build.sh > /tmp/b.log 2>&1; tail -3 /tmp/b.log` | **`None`** | **`{}`** |

End to end, `measure()` on a synthetic transcript whose `tool_result` is `CHECK BUILD: PASSED (40s)` gives `build_runs: 0` for both bold rows.

**Expected:** any redirection or pipe after a bare `./build.sh` (`2>&1`, `>file`, `>>file`, `| tail`, `| tee`) is a Build run, with the same prefix tolerance as now. `./build.sh --verbose 2>&1 | tail` is also a Build run.

### 2. Runner and `build.sh` lines inside heredoc bodies match as commands (false counts, and real runs get lost)

`VM_COMMAND` and `CHECK_COMMAND` both accept `\n` as a command boundary. So any heredoc body line that starts with `tools/run-ui-tests-vm.sh`, `./build.sh ui` or `./build.sh [unit]` counts as a command, whether it's in a `git commit -F - <<'EOF'` message or a file written via `cat > f <<'EOF'`. `measure()` checks `VM_COMMAND` first, so a heredoc mention also changes the call's kind to `vm`. That hides a real `./build.sh unit` in the same call.

Repro (`measure()` on one-call synthetic transcripts):

| Command | `tool_result` | Got | Expected |
|---|---|---|---|
| `cat > notes.md <<'EOF'`⏎`tools/run-ui-tests-vm.sh BattyUITests/Foo`⏎`EOF`, `run_in_background: true`, task notification 10 min later | `Command running in background with ID: abc` | `vm_runs: 1` (10 min) | `vm_runs: 0` |
| `git commit -q -F - <<'EOF'`⏎`#0531 x`⏎`tools/run-ui-tests-vm.sh BattyUITests/Foo`⏎`EOF`⏎`./build.sh unit` | `CHECK UNIT: PASSED (25s)` | `unit_runs: 0` (kind became `vm`, and `VM_SUMMARY` has no `CHECK UNIT`) | `unit_runs: 1` |
| `cat > notes.md <<'EOF'`⏎`tools/run-ui-tests-vm.sh`⏎`EOF`⏎`./build.sh unit` | `Executed 412 tests, with 0 failures`⏎`CHECK UNIT: PASSED` | `vm_runs: 1`, `unit_runs: 0` (`VM_SUMMARY`'s `Executed \d+ tests?` matched unit-test output) | `vm_runs: 0`, `unit_runs: 1` |
| `cat <<'EOF'`⏎`./build.sh unit`⏎`EOF` | `./build.sh unit`⏎`CHECK UNIT: PASSED (25s)` (e.g. echoing a saved log) | `unit_runs: 1` | `unit_runs: 0` |

(⏎ = a newline inside the `command` string.)

**Expected:** heredoc bodies are removed before the command regexes run (from the `<<[-~]?'?WORD'?` line through the terminating `WORD` line), so only real shell command lines can match. A call that has both a heredoc mention and a real `./build.sh unit` should be counted as a Unit run. The `vm` kind should not take precedence over a real check stage just because a VM regex matched somewhere in the string.

## Resolution notes

> 🟢 Resolved 2026-10-24 — `tools/worklog.py` now counts a piped or redirected bare `./build.sh` as Build and ignores heredoc bodies when classifying runs, with a 28-case offline self-test.

## Root cause

Confirmed against `main`'s `tools/worklog.py` (the self-test fails 17/28 cases there):

1. `CHECK_COMMAND`'s no-action alternative `\s*($|[;&|\n)])` didn't accept a redirection, so `./build.sh 2>&1 | tail`, `./build.sh > f` and `./build.sh >> f` weren't classified.
2. `VM_COMMAND` and `CHECK_COMMAND` treat `\n` as a command boundary and saw heredoc body lines as commands. `measure()` also picked `vm` whenever `VM_COMMAND` matched anywhere, so a heredoc mention of the runner hid a real `./build.sh unit` in the same call, and `VM_SUMMARY`'s `Executed N tests` matched unit output.

## Fix

- `CHECK_COMMAND`: the no-action alternative also accepts `<`, `>` (so `>>`, `>|` too) and `\d+>` (`2>&1`). Words like `package` or `release`, and `./build.sh 2 foo`, still don't match.
- New `strip_heredocs()`: keeps each heredoc operator's line, drops the body through the terminator line (compared after stripping whitespace, so `<<-` works). It handles several operators on one line, drops everything after an unterminated heredoc, and ignores `<<<` here-strings. `check_stage` and `command_stages` call it, so it's applied once per Bash call (it's idempotent).
- New `run_kind(command, background)`: a foreground call with a BUILD/UNIT/UI-TYPECHECK stage gets the check kind (its `CHECK UI:` line still credits a VM run). `vm` is used only when UI is the sole stage, or for a background call that runs the VM.
- Module docstring and the "Measuring a phase" paragraph in `issues/Issues.md` now say this. No divergence from the plan, apart from one extra command case (`./build.sh 2 foo` → not a check).

## Gotchas

- Heredoc detection is lexical: a `<<WORD` inside a quoted string (`echo "a <<b"`) is treated as a heredoc and hides the lines after it, up to a `b` line. This is rare in agent commands and affects only measurement.
- A background call that runs both a check and the VM runner charges its whole duration to `vm`, because the transcript has no per-stage timing.
- `tools/worklog.py --scan | head` prints a `BrokenPipeError` when `head` closes the pipe. That predates this change and isn't fixed here.

### Files

- **`tools/worklog.py`**
  1. **Redirection after a bare `build.sh`.** In `CHECK_COMMAND`, widen the no-action alternative `\s*($|[;&|\n)])` so it also accepts a redirection: `<`, `>` (covers `>`, `>>`, `>|`), and a file-descriptor redirection `\d+>` (`2>&1`, `1>f`). `&>` is already covered by `&`. Keep `(\s+--verbose)*` before it so `./build.sh --verbose 2>&1 | tail` matches. Do not accept arbitrary words: `package`, `release`, `archive`, `analyze` must still give `None`. `./build.sh 2 foo` (digit not followed by `>`) must not match.
  2. **Strip heredoc bodies.** Add `strip_heredocs(command)`: walk the command line by line; on a line containing one or more heredoc operators (`(?<!<)<<(?!<)` then optional `-` or `~`, optional whitespace, then a word optionally wrapped in `'` or `"`), keep that line as-is (the rest of it, e.g. `&& ./build.sh unit`, is a real command) and drop the following lines up to and including the line whose content, with leading/trailing whitespace stripped, equals the word. Several operators on one line are consumed in order. An unterminated heredoc drops everything to the end. `<<<` here-strings are not heredocs. Apply it once per Bash `tool_use` in `measure()` before any classification; `check_stage` and `command_stages` also call it, so they are correct when called on their own (it is idempotent).
  3. **Kind precedence.** Today `measure()` sets `kind = "vm" if VM_COMMAND.search(command) else check_stage(command)`. Change it so that, after stripping, a **foreground** call with any BUILD/UNIT/UI-TYPECHECK stage in `command_stages` gets the check kind (`unit` if UNIT, else `build`). The check branch already credits a `CHECK UI:` line to `vm` when `UI` is in the allowed stages, and the VM runner ends with `CHECK UI:`, so a real `./build.sh unit && tools/run-ui-tests-vm.sh` in one call still counts both. The `vm` kind (with its looser `VM_SUMMARY` match) is used only when UI is the only stage. For **background** calls keep `vm` first when a real (post-strip) VM command is present, since the whole duration up to the notification is mostly the VM run. Factoring this into one small helper (for example `run_kind(command, background)` returning `(kind, stages)`) is fine; keep it stdlib-only.
  4. Update the module docstring's measurement paragraph in a few words: heredoc bodies are ignored, and a bare `./build.sh` with a pipe or redirection counts as Build.
- **`tools/worklog-selftest.py`** (new, executable, stdlib only), modelled on `tools/check-report-selftest.py`: load `worklog.py` via `importlib.util.spec_from_file_location`, run two case tables, print `ok  <name>` / `FAIL <name>: got …; want …`, then `k/N passed`, and exit 1 on any failure. Transcripts are written to a `tempfile.TemporaryDirectory()` and measured with `measure(path, {})`. No result text may contain a `build/checks/*.log` path, so `haiku_usage` never shells out to git.
- **`issues/Issues.md`**, "Measuring a phase: `tools/worklog.py`": one sentence saying heredoc bodies are ignored when classifying runs and that `python3 tools/worklog-selftest.py` checks the classifier. Do not touch anything else in that file.
- `scripts/` and `build.sh` are not touched.
