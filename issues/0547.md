## Resolution notes

> 🟢 Resolved 2026-11-04 — The Session row is now one accessibility element with a single `session-row.<title>` identifier, so `testMissingBackgroundImageOpensAndShowsTheSidebarWarning` finds the row and passes in the VM.

## Description

The test added by #0540 looks up the Session row by the exact identifier `session-row.Faded`. While the warning icon shows, the row's identifier is `session-row.Faded-session-row.Faded`, so the lookup finds nothing. The feature itself appears to work, and users aren't affected: the Project opens, its Session is named Faded, and the warning is on the row. This is a test defect, caused by an existing quirk of the row's accessibility.

**Blocks 1.3.5**, because the Release-tier UI suite has to pass. It fails on `release/1.3` at `b95e088c` and on `main` at `c3ee2772`. Fix on `main` first, then cherry-pick to `release/1.3`. Needs the **UI confirmation** tier: the implementer and the reviewer each re-run the failing test below.

## Root cause

Confirmed in the VM. The row put `.accessibilityIdentifier("session-row.<title>")` on content with no `.accessibilityElement(children:)`, so the identifier spread to each accessible leaf and SwiftUI folded the leaves with `-`. The warning image was a second leaf, which produced `session-row.Faded-session-row.Faded`. The app published the wrong identifier, so this was a product defect that the test exposed, not a test defect. The harness's exact lookup was right.

The badge is fixed by the same change: `CLIBackgroundSessionTests` now finds a badged row by its exact identifier and passes. That shows the fix, not that the doubling on the badge had the same cause, since the original form was never captured from a bundle.

## Fix

As planned. `SessionRow`'s label in `SessionSidebarView` is now one `.accessibilityElement(children: .ignore)` with an explicit label from the new `rowAccessibilityLabel(for:)`, the `.isStaticText` trait, and the existing identifier and value. The row's `HStack` gains `.contentShape(Rectangle())` so clicks and right-clicks in its empty middle hit the row. The dead identifiers and labels on the warning and icons are gone.

Tests: `CLIBackgroundSessionTests.rowValue` uses the exact `BattyUITestHarness.sessionRow` lookup, and the badge test now also calls `BattyScreen.expectMatches`. The target test also checks the row's label.

One small divergence from the plan: in `docs/ui-features.md`, `, background image problem` is described as coming last, after the test-only `, icon <name>`, because that is the order `rowAccessibilityValue` builds. The plan placed it before the icon sentence.

## Plan

### Premises checked

- **This isn't only a test defect.** The app publishes the wrong identifier, against the contract in `BattyUITests/README.md:47` and `docs/ui-features.md:148`. So the fix is in the product, and `BattyUITestHarness.sessionRow` stays exact. Loosening it would hide the defect from every other exact lookup, including `BattyScreen.mismatch`, which compares the whole identifier set.
- **#0467 is the same defect and is still open.** This issue's Related list omits it. It reports the doubling on the badge and was never reproduced from a result bundle. The tree in this issue confirms the doubling for the warning. No VM log on this host has the badge form, because the tree is only in the `.xcresult`. Both states add a second accessible leaf to the same fold, so the badge is very likely the same cause. The fix below removes every leaf, so it doesn't depend on that being certain.
- **The row doesn't depend on the fold.** The issue calls a product fix riskier because of the row's comment. That comment (`SessionSidebarView.swift:115-121`) only says the fold is harmless, which is wrong for a row with two leaves. `rowAccessibilityValue` already carries the icon, badge and warning state.
- **`session-row.background-problem` is a dead identifier.** The outer identifier overwrites it, yet `docs/ui-features.md:234` documents it as reachable. The same goes for `session-row.icon` and `session-row.project-glyph`. Nothing in `BattyUITests` or `BattyKit/Tests` reads any of the three.
- **Confirmed as stated:** the test's lookup is exact, the unit test exists, and the failure-time label carries the warning.

### Decisions

**Use `.accessibilityElement(children: .ignore)` with an explicit label.**

- `.contain` is rejected. The children become elements, so `session-row.icon` and the warning's identifier match the `session-row.` prefix. That breaks `BattyScreen.mismatch` and inflates the row counts in `CLIRemoteControlTests:570`. Each row also needs `.accessibilityHidden` on its children to avoid speaking twice.
- `.combine` is rejected. It keeps the merge rules this bug comes from, and whether the circle's label joins the row label is untested. `ProjectsSymbolTests:30` requires that label to equal the Session's name exactly, because of a past regression.
- `.ignore` gives one element whose label, value and identifier are all stated by the app. `GitStatusPaneView.swift:385-416` is the same shape already in the app: a row with a `Spacer`, `.contentShape(Rectangle())`, `.contextMenu`, `.ignore`, a label and an identifier.

**Add `.contentShape(Rectangle())` to the row's `HStack`, before `.contextMenu`.** This is required, not cosmetic. An `.ignore` element's frame is the whole `HStack`, so XCUITest's `click()` and `rightClick()` land mid-row, on the `Spacer`, which doesn't hit-test without a content shape. `SessionBackgroundSettingsTests` and `DemoSceneTests:655` right-click the row, and `docs/ui-features.md:498` requires the menu to open on it. The one visible change is that right-clicking the row's empty middle now opens the Session menu. `PaneRow` in the same `List` already has a content shape.

**Remove the `CLIBackgroundSessionTests` workaround in this issue.** It is cheap, one lookup, and it is the only test that puts a badge on a row, so it proves the badge half of the fix. If only the badge half fails in the VM, restore the workaround, leave #0467 open, and record that in `## Gotchas`. Don't hold the release for it, because the blocker is the warning.

**Leave the other `BEGINSWITH` lookups alone** (`MultiWindowCLITests:162`, `DemoSceneTests:552`, and the row counts). They don't encode the doubled form and they still match. #0467's criterion 4 says the same about the row counts.

**Don't add a badge identifier or simplify `sessionRow`'s cell-first lookup** (#0467's open questions 2 and 3). The first isn't needed and the second isn't needed for a release blocker.

## Notes

### Established

- The failure is in the row lookup, after the Project opened. The picker flow worked, and the test's `waitForSessions(named: "Faded")` assertion at line 383 passed. So the test's image path handling doesn't break `openThroughPicker`.
- The missing image is detected. The app log has `project background image not used (missing)` for the test's path, and the row's label carries the warning text.
- The doubling is a known quirk. `CLIBackgroundSessionTests.rowValue` already works around it for the unseen badge, with the comment "With an unseen badge the row's identifier is doubled", and matches with `BEGINSWITH`. `BattyUITestHarness.sessionRow` matches the exact identifier and has no such handling.
- `session-row.background-problem`, the icon's own identifier in `SessionRow`, doesn't appear in the failure-time row's identifier. Nothing in `BattyUITests` or `BattyKit/Tests` references it.

### Inferred

- **Mechanism.** The row's `.accessibilityIdentifier("session-row.<title>")` is applied to a label with no `.accessibilityElement(children:)`, so it spreads to the row's children and SwiftUI folds them into one element. Comments in `SessionSidebarView` describe this spreading for `PaneRow`. A second accessible child in the row, whether the badge or this icon, would then join the identifier to itself.
- **Whether the rest of the test passes is unknown.** The debug output truncates the value at `selected, Project,...`, so it doesn't show ` background image problem`. The unit test `rowAccessibilityValueNamesTheProblem` covers that string, but the UI test has never reached its last assertion.

### For the planner

- `BattyUITestHarness.sessionRow` is the shared lookup, so changing it would fix this test and any other that looks up a row with a badge or warning. A plain `BEGINSWITH` can confuse `Session 1` with `Session 10`. Matching either `session-row.X` or `session-row.X-session-row.X` wouldn't.
- Alternatively, fix the product so the identifier isn't doubled. That is riskier: the comment on the row says it depends on the children folding together, and other tests read the row by its identifier and value.
