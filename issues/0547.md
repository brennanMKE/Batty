## Description

The test added by #0540 looks up the Session row by the exact identifier `session-row.Faded`. While the warning icon shows, the row's identifier is `session-row.Faded-session-row.Faded`, so the lookup finds nothing. The feature itself appears to work, and users aren't affected: the Project opens, its Session is named Faded, and the warning is on the row. This is a test defect, caused by an existing quirk of the row's accessibility.

**Blocks 1.3.5**, because the Release-tier UI suite has to pass. It fails on `release/1.3` at `b95e088c` and on `main` at `c3ee2772`. Fix on `main` first, then cherry-pick to `release/1.3`. Needs the **UI confirmation** tier: the implementer and the reviewer each re-run the failing test below.

## Notes

### Established

- The failure is in the row lookup, after the Project opened. The picker flow worked, and the test's `waitForSessions(named: "Faded")` assertion at line 383 passed. So the test's image path handling doesn't break `openThroughPicker`.
- The missing image is detected. The app log has `project background image not used (missing)` for the test's path, and the row's label carries the warning text.
- The doubling is a known quirk. `CLIBackgroundSessionTests.rowValue` already works around it for the unseen badge, with the comment "With an unseen badge the row's identifier is doubled", and matches with `BEGINSWITH`. `BattyUITestHarness.sessionRow` matches the exact identifier and has no such handling.
- `session-row.background-problem`, the icon's own identifier in `SessionRow`, doesn't appear in the failure-time row's identifier. Nothing in `BattyUITests` or `BattyKit/Tests` references it.

### Inferred

- **Mechanism.** The row's `.accessibilityIdentifier("session-row.<title>")` is applied to a label with no `.accessibilityElement(children:)`, so it spreads to the row's children and SwiftUI folds them into one element. Comments in `SessionSidebarView` describe this spreading for `PaneRow`. A second accessible child in the row, whether the badge or this icon, would then join the identifier to itself.
- **Whether the rest of the test passes is unknown.** The debug output truncates the value at `selected, Project,...`, so it doesn't show ` background image problem`. The unit test `rowAccessibilityValueNamesTheProblem` covers that string, but the UI test has never reached its last assertion.

### For the planner

- `BattyUITestHarness.sessionRow` is the shared lookup, so changing it would fix this test and any other that looks up a row with a badge or warning. A plain `BEGINSWITH` can confuse `Session 1` with `Session 10`. Matching either `session-row.X` or `session-row.X-session-row.X` wouldn't.
- Alternatively, fix the product so the identifier isn't doubled. That is riskier: the comment on the row says it depends on the children folding together, and other tests read the row by its identifier and value.
