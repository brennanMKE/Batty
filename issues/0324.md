## Description

`Concepts.md` is the canonical vocabulary document — `CLAUDE.md` and `issues/Issues.md` both instruct every session and subagent to read it and treat its terms as authoritative — and five of its bullets describe a feature that does not exist. Each of the Window, Session, Pane, Tab, and Terminal Session sections carries a `**Persisted:**` bullet describing layout persistence that #0172 removed entirely on 2026-05-20. Nothing serializes any of it today.

The five bullets, verified at these lines on current `main`:

- `Concepts.md:37` (Window) — "**Persisted:** ordered list of Windows, the selected Session in each, and frame/zoom state."
- `Concepts.md:53` (Session) — "**Persisted:** ordered list per Window, plus everything inside."
- `Concepts.md:75` (Pane) — "**Persisted:** position in the Split tree, ordered Tab list, active Tab."
- `Concepts.md:94` (Tab) — "**Persisted:** id, title override, ordering, the surface's cwd at last snapshot."
- `Concepts.md:111` (Terminal Session) — "**Persisted:** working directory and last-set title only. We do **not** restore running processes — relaunched shells start fresh in the saved cwd."

The fifth is the worst: it makes a specific, falsifiable promise about relaunch behavior that is untrue. Nothing is saved, so nothing "starts fresh in the saved cwd" — a relaunched shell starts wherever the shell's default takes it.

How the drift happened: #0172 landed in two commits. `5628db1` deleted the persistence source (`WorkspaceManager` call sites, 134 lines of `LayoutModel.swift` serialization). `6a9f58c` cleaned the docs — it removed `Concepts.md`'s `## Workspace` section, corrected the Bell Feed `Lifetime` bullet to "in-memory only; does not survive a relaunch", and dropped Workspace from the At-a-glance list — but missed these five per-concept bullets, which each pointed at the Workspace schema that commit was deleting.

Verified against current source: no `workspace.json`, `WorkspaceManager`, or frame-autosave/`NSWindowRestoration` code exists anywhere under `Batty/` or `BattyKit/Sources/`. The layout value types remain `Codable` with no serialization call site (deliberately, per `docs/pane-kinds.md` §4), and the `Codable` types in `BattyKit/Sources/BattyXPCCore/` are XPC wire messages, not disk persistence.

The doc commit removed `Concepts.md`'s `## Workspace` section, corrected the Bell Feed lifetime bullet to "in-memory only", and dropped Workspace from the At-a-glance list — but missed the five per-concept `**Persisted:**` rows. ## Fix

All five bullets **rewritten, not deleted** — each section keeps a `**Persisted:**` line stating non-durability plainly, following the house style #0172's own doc cleanup established for the Bell Feed ("in-memory only; does not survive a relaunch"):

- **Window** — no Window list, no per-Window selected Session, no frame/zoom state saved by Batty, with an explicit carve-out for the two things that *do* survive: sidebar collapse state via `@SceneStorage`, and window frame, which macOS's own state restoration may restore.
- **Session**, **Pane**, **Tab** — in-memory only, with the Session bullet carrying a parenthetical distinguishing it from the real Name cache documented directly above it.
- **Terminal Session** — the false "relaunched shells start fresh in the saved cwd" replaced with "a relaunched shell starts wherever the shell's own default takes it (typically `$HOME`)".

Folded in during review: `Concepts.md`'s Bell Feed **Contents** row dropped "persisted across launches" (which contradicted its own Lifetime row 13 lines below) and tightened "capped (e.g. 200 entries)" to the actual `cap = 200`; the Split **ratio** row corrected to in-memory-only; and all three `docs/pane-kinds.md` statements vouching for `Concepts.md` corrected, not just the two the issue enumerated.

## Gotchas

- **Batty does opt into macOS scene restoration**, via `@SceneStorage` for the sidebar's per-window collapse state (`RootWindowView.swift:20`). It is the only `@SceneStorage` in the codebase. Any future claim that Batty persists nothing window-level is wrong because of it — and it is gated by System Settings → Desktop & Dock → "Close windows when quitting an application", so its behavior varies by machine.
- **A Split's ratio is in-memory but not ephemeral.** A divider drag writes it through `SplitTree.updateRatio`; it survives for the session and dies at relaunch. "In-memory only" is the accurate phrase, not "not saved".
- **#0172's doc cleanup was partial.** It fixed the section-level structure and one bullet but left five others. Anything that cites #0172 as having made `Concepts.md` correct is citing a half-truth — that assumption is what put wrong text in `docs/pane-kinds.md` in three separate places.

## Expected behavior

What that means per bullet is an implementer decision, not a mechanical strip: each concept's section may still want to say *something* about durability — e.g. that nothing about layout survives relaunch today, in the same style as the corrected Bell Feed bullet ("in-memory only; does not survive a relaunch") — and `Concepts.md` does document real persistence elsewhere (the session-name cache at `Concepts.md:51`, Theme selection in `UserDefaults` at `Concepts.md:158`) that per-concept wording should not contradict. Decide per-bullet whether to rewrite or remove.
