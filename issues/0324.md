## Description

`Concepts.md` is the canonical vocabulary document — `CLAUDE.md` and `issues/Issues.md` both instruct every session and subagent to read it and treat its terms as authoritative — and five of its bullets describe a feature that does not exist. Each of the Window, Session, Pane, Tab, and Terminal Session sections carries a `**Persisted:**` bullet describing layout persistence that #0172 removed entirely on 2026-05-20. Nothing serializes any of it today.

The five bullets, verified at these lines on current `main`:

- `Concepts.md:37` (Window) — "**Persisted:** ordered list of Windows, the selected Session in each, and frame/zoom state."
- `Concepts.md:53` (Session) — "**Persisted:** ordered list per Window, plus everything inside."
- `Concepts.md:75` (Pane) — "**Persisted:** position in the Split tree, ordered Tab list, active Tab."
- `Concepts.md:94` (Tab) — "**Persisted:** id, title override, ordering, the surface's cwd at last snapshot."
- `Concepts.md:111` (Terminal Session) — "**Persisted:** working directory and last-set title only. We do **not** restore running processes — relaunched shells start fresh in the saved cwd."

The fifth is the worst: it makes a specific, falsifiable promise about relaunch behavior that is untrue. Nothing is saved, so nothing "starts fresh in the saved cwd" — a relaunched shell starts wherever the shell's default takes it.

How the drift happened: #0172 landed in two commits. `5628db1` deleted the persistence source (`WorkspaceManager` call sites, 134 lines of `LayoutModel.swift` serialization). `6a9f58c` cleaned the docs — it removed `Concepts.md`'s `## Workspace` section, corrected the Bell Feed `Lifetime` bullet to "in-memory only; does not survive a relaunch", and dropped Workspace from the At-a-glance list — but missed these five per-concept bullets, which each pointed at the Workspace schema that commit was deleting.

Verified against current source: no `workspace.json`, `WorkspaceManager`, or frame-autosave/`NSWindowRestoration` code exists anywhere under `Batty/` or `BattyKit/Sources/`. The layout value types remain `Codable` with no serialization call site (deliberately, per `docs/pane-kinds.md` §4), and the `Codable` types in `BattyKit/Sources/BattyXPCCore/` are XPC wire messages, not disk persistence.

## Expected behavior

`Concepts.md` describes only persistence that actually exists. What that means per bullet is an implementer decision, not a mechanical strip: each concept's section may still want to say *something* about durability — e.g. that nothing about layout survives relaunch today, in the same style as the corrected Bell Feed bullet ("in-memory only; does not survive a relaunch") — and `Concepts.md` does document real persistence elsewhere (the session-name cache at `Concepts.md:51`, Theme selection in `UserDefaults` at `Concepts.md:158`) that per-concept wording should not contradict. Decide per-bullet whether to rewrite or remove.

Scope also includes the second-order correction in `docs/pane-kinds.md` (landed by #0302), which vouches for the wrong text in two places:

- `docs/pane-kinds.md:458` — "Neither edit touches `Concepts.md` (already correct post-`#0172`; …)"
- `docs/pane-kinds.md:766` (summary table, row 4) — "`Concepts.md` was already accurate on persistence but its Pane definition (`Concepts.md:63`) is falsified by this design…"

Both statements are true of the `## Workspace` section's removal but false of the five `**Persisted:**` bullets. Left uncorrected, `pane-kinds.md` keeps certifying text this issue exists to fix.

## Actual behavior

Five `**Persisted:**` bullets assert layout persistence (and a specific relaunch-cwd guarantee) that has had no implementation since 2026-05-20, in the document every subagent is told to treat as canonical; and `docs/pane-kinds.md` asserts twice that `Concepts.md` is already correct on this exact topic.

## Notes

- One nuance for the implementer on the Window bullet (`Concepts.md:37`): macOS/SwiftUI may incidentally restore window frame via system-default state restoration — no Batty code opts in or out — but the bullet's substantive claims (persisted ordered Window list, selected Session per Window) are false regardless, and multi-window itself is not yet implemented (#0234, noted at `Concepts.md:34`).
- Line numbers cited above were verified on `main` at filing time (2026-08-08); re-verify before editing, since `Concepts.md` and `docs/pane-kinds.md` are both actively edited.
- `Concepts.md`'s footer carries a document-version line that #0172's own doc commit bumped ("0.3 — 2026-05-20. Removes Workspace persistence (never a planned feature)."); the fix should bump it again per its own instruction.
