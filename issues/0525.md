# 0525 — The Bell Feed capture log can't record the Tab's screen text, so every event is written with `screen: null`

| | |
|---|---|
| **Status** | open |
| **Module** | BellFeed / GhosttyKit |
| **Platform** | macOS |
| **First seen** | 2026-10-18 |

## Description

Follow-up to #0523, and depends on it. #0523 is implemented on branch `issue/0523` and not yet merged. The Bell Feed capture log it adds writes `screen: null` with `screenUnavailableReason: "unsupportedByTerminalHost"` on every event record. BattyKit has no sanctioned way to read the visible screen text of the Tab that rang. The screen text is the most useful raw input for tuning the Bell Feed, because it shows what the user was looking at when the Bell fired. Without it the week of capture data is missing its best field.

**Release target:** not targeted at 1.3.2 unless the user decides otherwise. #0523 ships without screen text.

## Current state (verified against libghostty-spm `a2565ccf`, the revision pinned in `BattyKit/Package.swift`)

The checked-out package is at `BattyKit/.build/checkouts/libghostty-spm`.

- **The capture writes null.** `AppStateStore+BellCapture.swift` on `issue/0523` hard-codes `screen: nil, screenUnavailableReason: "unsupportedByTerminalHost"`.
- **The surface wrapper is reachable, but its raw handle is not.**
  - `TerminalViewState.surface` is `public internal(set) weak var surface: TerminalSurface?` (`State/TerminalViewState.swift:34`). BattyKit creates one `TerminalViewState` per Tab (`TabRuntime.swift:146`), so it can already get the Tab's public `TerminalSurface` object.
  - `TerminalSurface.rawValue` (the `ghostty_surface_t`) is internal (`Surface/TerminalSurface.swift:24`).
  - `AppTerminalView.surface` is internal (`Platform/AppKit/AppTerminalView.swift:53`).
  - The `TerminalSurface` public API has input, `performBindingAction`, `jumpToPrompt`, `scrollToRow`, `hasSelection()` and `readSelection()`. It has no viewport or screen text read.
- **The read that's needed already exists, on the wrong type.** `InMemoryTerminalSession.readViewportText()` (`InMemory/InMemoryTerminalSession.swift:113`) is public. It does one `ghostty_surface_read_text` per viewport row (`GHOSTTY_POINT_VIEWPORT` / `GHOSTTY_POINT_COORD_EXACT`), frees each buffer with `ghostty_surface_free_text`, and runs inside `surfaceAccess.withCurrentSurface`, which keeps the surface alive and makes the read safe off the main thread. Batty's Panes use `AppTerminalView` with a `TerminalSurface`, not `InMemoryTerminalSession`, so they can't call it. `TerminalSurface` itself is `@MainActor`.
- **The C functions are callable from BattyKit.** BattyKit re-exports `GhosttyKit` (`@_exported import`), so `ghostty_surface_read_text` / `ghostty_surface_free_text` work once BattyKit holds a `ghostty_surface_t`.
- **`SurfaceRegistry` doesn't help today.** `Runtime/SurfaceRegistry.swift` stores `ghostty_surface_t` handles keyed by UUID, but nothing in production registers into it.

## Rejected route

`performBindingAction("write_screen_file:copy")` writes the screen to a file and copies it to the pasteboard. That overwrites the user's clipboard, so it's a user-visible side effect. Rejected. The other `write_screen_file` variants are also off the table if they have any effect the user can see: pasteboard, opening a file, or terminal output.

## Possible routes

1. **Upstream change plus pin bump (preferred).** Add a public viewport read to libghostty-spm. Either:
   - a `public func readViewportText() -> String?` on `TerminalSurface`, or on `TerminalViewState` / `TerminalView` forwarding to it, built like the `InMemoryTerminalSession` version; or
   - a public accessor for the raw `ghostty_surface_t`.

   Then bump the revision in `BattyKit/Package.swift`. libghostty-spm is the upstream `Lakr233/libghostty-spm` package, not a fork. **Opening an upstream PR is a shared-state action, so the user must approve it first.** The pin bump must also pass `./build.sh unit` and the Release archive check (`./build.sh release archive ...`), because it changes a vendored dependency.
2. **Another sanctioned route to the Tab's `ghostty_surface_t`** that this survey missed, so BattyKit can call `ghostty_surface_read_text` per viewport row itself. Any such route must not depend on undocumented memory layout or Objective-C runtime tricks against internal members. If the route registers handles into `SurfaceRegistry`, it must also unregister them when the surface is freed, so the registry never holds a dangling handle.

If neither route is approved, leave #0523's `screen: null` behavior in place and record why in this issue.

## Expected behavior

- With capture on, each event record's `screen` holds the last ~20 non-trailing-blank lines of the **originating Tab's** visible viewport at record time. `screenUnavailableReason` is omitted or null when `screen` is present.
- When the read can't happen (no attached surface, Tab torn down, read failed), `screen` stays null and `screenUnavailableReason` names the cause, for example `noSurface` or `readFailed`. Drop `unsupportedByTerminalHost` once the read is wired.
- The read is bounded to the viewport rows, with no scrollback. Run it off the main thread where the API allows, as `InMemoryTerminalSession.readViewportText()` does under `surfaceAccess`. If the only route is main-actor (`TerminalSurface` is `@MainActor`), do one bounded synchronous read on the bell path, and do the trimming and encoding on #0523's background writer.
- With capture off, no screen read happens at all, as #0523 requires.
- **No side effects:** no pasteboard writes, no selection change, no scroll position change, no focus or first-responder change, no bytes sent to the PTY, no change to rendering. Follow `docs/terminal-pane-requirements.md` and `docs/swiftui-observation-rules.md`: the read must not run inside view construction or a layout pass.

## Acceptance

- [ ] A capture event for a Bell from a live Pane has `screen` containing the last ~20 lines of that Tab's visible screen. For a Bell from a background Tab, the text is that Tab's, not the focused Tab's.
- [ ] Clipboard contents are unchanged across a captured Bell. A unit test asserts this, or the issue records why it can't be tested.
- [ ] No terminal behaviour changes: selection, scroll position, focus and input are unaffected.
- [ ] Unit tests cover the trimming (last N lines, trailing blank lines dropped) and the null-with-reason paths. No sleeps (AGENTS.md "Asynchronous tests").
- [ ] If the route is an upstream change, the user approved the PR, the pin is bumped, and `./build.sh unit` and the Release archive check pass.
