## Description

Every Sidebar Session row draws `rectangle.split.3x1` tinted with the Session color. A Project-backed Session draws `folder.fill` instead, since #0472. The user asked for two changes. A plain Session row should show a **solid circle** in its Session color. A **Project** should carry a **symbol the user picks** from a small curated set of SF Symbols, and its Sessions show that symbol in place of the circle. The user capped the set at **36**, chosen to fit the kinds of projects they actually work on.

The user's words (2026-10-12): "The sessions listed in Batty use an SF Symbol which represents 3 columns which has been good, but it may be better to just use a solid circle instead and for projects let the user select from a small number of SF Symbols. Limit it to 36 which would be good for projects using my projects as a reference."

**Orchestrator decision: this ships with Projects in 1.3.0, behind the Projects feature flag.** With `featureFlags.projects` off (Prod), every Sidebar row draws `rectangle.split.3x1` exactly as today. With it on (Beta), rows draw the circle or the Project's symbol. When the flag is removed in the 1.3.0 release, the circle becomes unconditional and the `rectangle.split.3x1` branch is deleted. Add this site to `docs/feature-flags.md` so the flag-removal issue finds it.

## Expected behavior

### 1. Sidebar row icon (`SessionRow`)

- **Flag off:** `rectangle.split.3x1` tinted with the Session color. This is byte-for-byte today's branch.
- **Flag on, plain Session** (`projectID == nil`): `circle.fill` tinted with the Session color.
- **Flag on, Project-backed Session**: the Project's symbol (§2) tinted with the Session color. This replaces #0472's hard-coded `folder.fill`. Keep `accessibilityIdentifier("session-row.project-glyph")` and the "Project" accessibility label on this branch, because #0478 already queries that identifier.
- Give the icon a **fixed frame width** so the title text starts at the same x for a circle and for every catalog symbol. SF Symbols have different natural widths, so without the frame the titles in a list of mixed Sessions jag. Pick the size and weight to sit well next to the title (`circle.fill` at full Label size may look heavy; `.imageScale(.small)` or a smaller font for the circle only is fine). Visual sign-off is the user's.
- The plain-Session icon needs an accessibility identifier the UI test can find, for example `session-row.icon`, plus a way to read which symbol is drawn (for example `accessibilityValue` = the SF Symbol name). Do not make VoiceOver speak raw symbol names such as "circle.fill". If the element needs a spoken label, use the Session color's `displayName`.
- **Where the symbol comes from.** `SessionRuntime` gains an in-memory `projectSymbol: ProjectSymbol?` next to `projectID`. It is never persisted, like `projectID`. `addProjectSession` sets it at open. The row reads only `session.projectSymbol`. It must **not** look the Project up in `store.projectStore` from `body`, because that getter constructs the store lazily, and constructing it during a view update is exactly what `docs/swiftui-observation-rules.md` forbids. Editing a Project's symbol in the editor and pressing **Save** (or Save & Open) also updates `projectSymbol` on every open Session whose `projectID` matches, across all Windows. That write runs from the Save button action, so it is event-origin. Title and color stay pinned at open as today. Only the symbol follows edits, because the symbol is a property of the Project, while title and color are per-Session values the user can change.

### 2. `Project.symbol` and the curated catalog

- New `ProjectSymbol` type in `BattyKit/Sources/BattyKit/Model/` (next to `Project.swift`): `enum ProjectSymbol: String, CaseIterable, Codable, Sendable, Hashable`, with exactly **36** cases in the order below.
  - **Stable identifiers.** The raw value (what `projects.json` stores) is the short key in the table below. It is **not** the SF Symbol name. A computed `systemName` maps the key to the SF Symbol, so a symbol can be swapped later (Apple renames one, or the user dislikes a glyph) without migrating stored data.
  - **Append-only.** Never reorder, rename or remove a case. Document this on the type the way `SessionColor` does (`Runtime/SessionColor.swift:5-11`). The picker shows cases in declaration order.
  - `displayName` is a localized, human-readable name for accessibility labels and tooltips, for example "Terminal" or "Server Rack".
- `Project` gains `symbol: ProjectSymbol`. It is **non-optional in Swift**, defaults to `.folder` in `init`, and is **optional on disk**. This mirrors `color` exactly. A Project with no symbol chosen (every Project saved before this change) shows `.folder`, so its Sessions look exactly as #0472 made them.
  - Why `.folder` and not the circle: the folder keeps Project-backed Sessions visibly different from plain Sessions, which was the point of #0472's glyph. The circle stays reserved for "not from a Project".
  - Why non-optional: an optional field would make "nil" and "explicitly `.folder`" two states that look identical but compare unequal, so the editor's dirty check would report a change the user can't see.
- **Lenient decode, matching `color`:**
  - a missing `symbol` key decodes to `.folder` and does not log;
  - an unknown string (a key from a newer build, a hand edit, or a case renamed by mistake) decodes to `.folder` and logs an error;
  - a non-string value decodes to `.folder` and logs.

  None of these ever throws or drops the Project. Add `symbol` to `Project.CodingKeys` (`Project.swift`, the private enum before `init(from:)`); the synthesized `encode` then always writes the raw key.
- **Older Beta builds.** A Beta build from before this change ignores the unknown `symbol` key on load, because unknown fields are already ignored (#0471). If that build then saves, the key is dropped and the Project reverts to `.folder`. That is acceptable for Beta-only data. Record it in Gotchas, and do not bump `ProjectsFile.version` for it.
- Hashing and equality include `symbol`, so the editor's dirty check sees symbol changes. `startupCommandsHash` does **not** include it, so changing only the symbol never re-prompts the trust sheet.

## Notes

- **Binding docs:** `docs/swiftui-observation-rules.md`. The row reads only `session.projectSymbol`, and the propagation write happens in the Save action. `docs/view-hierarchy.md` applies only in that this touches the Sidebar row; nothing here goes near the terminal host.
- **Why the user wants the circle.** With Projects, a row's icon starts to carry meaning (from a Project or not, and which Project). A neutral circle in the Session color keeps plain Sessions quiet and lets Project symbols stand out. The three-column symbol also implies a fixed three-Pane layout that most Sessions don't have.
- **Why 36.** It is the user's cap, and it fits a 6×6 grid. Adding a symbol later means appending a case and growing the grid. Removing or replacing one needs the user's approval, because stored Projects reference the raw keys. Renaming the SF Symbol behind a key is safe.
- #0472's Sidebar-glyph acceptance ("with the flag off the Sidebar never shows the glyph") still holds and must stay covered.

## Resolution notes

> 🟢 Resolved 2026-10-12. With the Projects flag on, a plain Session row in the Sidebar shows a solid circle in its Session color, and a Project-backed Session shows its Project's symbol. Each Project has a symbol picked from a curated set of 36 SF Symbols, chosen in the Project Editor's 6×6 popover. The default is the folder. The same symbol appears on the picker cards and on the File ▸ Open Project items. With the flag off, the Sidebar row is unchanged (`rectangle.split.3x1`).

Owed to the user, as visual sign-off:
- the circle;
- the 36 glyphs and the popover;
- the File-menu item images next to the check mark on macOS 15.6;
- Tab and focus behaviour of the Symbol field with Full Keyboard Access on.

## Root cause

This is a feature request (user, 2026-10-12), not a defect. Every Sidebar row drew the same `rectangle.split.3x1`, and Project-backed rows drew `folder.fill`, so Projects had no identity of their own.

## Fix

- **Model.**
  - `ProjectSymbol` has 36 cases, with stored keys and SF Symbol names. Its availability is cached once.
  - `Project.symbol` and `ProjectDraft.symbol` default to `.folder`.
  - Decoding is lenient: a missing key falls back silently; an unknown or non-string value falls back and logs.
  - `startupCommandsHash` is untouched, so changing a symbol never re-prompts for trust.
- **Sidebar.**
  - `SessionRowIcon.systemName(flagOn:projectSymbol:)` chooses the icon.
  - `SessionRuntime.projectSymbol` is set when the Project opens.
  - A save in the editor updates matching Sessions in every window, through `ProjectEditorViewModel.projectSaved` → `AppStateStore.applyProjectSymbol(of:)`, an event-origin write.
- **Editor.**
  - `ProjectSymbolPicker` is a focusable Symbol field. Return and Space open the popover.
  - While the popover is open, the field owns a `ProjectSymbolGridCursor` that it shares with the grid.
  - Focus returns to the field only after Return, Space or Escape, never after a click elsewhere.
  - The editor's list rows show the symbol.
- **Other surfaces.**
  - Picker cards carry the symbol.
  - The File ▸ Open Project items are `Toggle`s with a `Label` image. Their check-mark meaning is unchanged (#0475).
- **Test seam.** `UITestDriver.sidebarIconsEnvVar` appends `, icon <symbol>` to the row's accessibility value. It is active only when `BATTY_UI_TEST_SCRIPT` is also set, because the icon is merged into the row element (#0484).
- **Docs.**
  - `Concepts.md` is now v0.8.
  - `docs/feature-flags.md` gets a gate-site row and a flag-removal paragraph.
  - `docs/ui-features.md` lists the identifiers.

## Review

Opus reviewed it in 2 rounds.

- **Round 1:** requested changes.
  - **Blocking:** the Symbol button wasn't reachable from the keyboard without Full Keyboard Access, and had no Return/Space handling.
  - **Non-blocking:**
    - focus returned to the field even after a click elsewhere;
    - the test env seam wasn't gated on UI-test mode;
    - there were no unit tests for the row value;
    - symbol availability was re-checked on every `body` evaluation;
    - the row label might merge with the icon's label.
- **Round 2:** approved, after the VM phase moved key handling to the field (the popover window isn't key in the VM). The reviewer found:
  - no writes from `body`;
  - no double-firing, because a key event goes only to the key window's first responder;
  - three non-blocking accessibility nits, recorded in Gotchas for #0484.
