# 0093 — UI tests: keyboard shortcuts fire from terminal focus

## Description

UI regression tests for the keyboard-shortcut routing introduced in `#0062` (NSEvent local monitor) and customized via `#0070` (Settings → Shortcuts). The chain of bugs we hit during development (`Cmd-W` closing the window, `Cmd-N` opening a duplicate window, recorder eating keystrokes) needs regression coverage so they don't come back.

Depends on `#0091` (UI test harness bootstrap).

## What this issue ships

A `KeyboardShortcutTests` UI test class. All tests start from terminal focus (the hardest case — pre-`#0062`, menu shortcuts didn't fire at all from there).

### Default-binding tests

1. `cmdN_fromTerminalFocus_createsSession` — click in the terminal, press `Cmd-N`, assert a new session appears in the sidebar.
2. `cmdW_fromTerminalFocus_closesActiveTab` — open a second tab, press `Cmd-W` from terminal focus, assert the second tab closes (and is NOT the window closing — that's the `#0062` regression).
3. `cmdT_fromTerminalFocus_createsTab` — assert a new tab chip appears.
4. `cmdD_fromTerminalFocus_splitsHorizontally` — assert two panes are visible after.
5. `cmdShiftD_fromTerminalFocus_splitsVertically` — same.
6. `cmdShiftBracket_switchesTabs` — `Cmd-Shift-]` then `Cmd-Shift-[` cycle.
7. `cmd1Through9_selectsTabByIndex` — open 3 tabs, press `Cmd-2`, assert the second chip is active.
8. `cmdOption1Through9_selectsSessionByIndex` — open 3 sessions, press `Cmd-Option-2`, assert Session 2 is selected in the sidebar.
9. `cmdControlS_togglesSidebar` — press the chord, assert the sidebar collapses then re-expands.
10. `cmdShiftN_togglesBellFeed` — press the chord, assert the bell-feed popover appears.

### Last-session-closes-window

11. `cmdW_onLastSession_quitsApp` — single session, single tab, press `Cmd-W`, assert the app terminates cleanly (no `QuitConfirmation` prompt because openTabs == 0 by then).

### Recorder doesn't intercept shortcut

12. `recorderFocused_swallowsKeystrokes` — open Settings → Shortcuts, click a recorder, press `Cmd-W`. Assert the recorder captured the binding (does NOT close a tab). Then click outside the recorder, press `Cmd-W`. Assert the focused tab closes. This protects the fix added after the recorder ate keystrokes.

### Custom binding round-trip

13. `customBinding_takesEffect` — open Settings → Shortcuts, rebind Close Tab to `Cmd-K`, close Settings, press `Cmd-K` from terminal focus, assert the tab closes. Press `Cmd-W` from terminal focus, assert it does NOT close a tab (it should now be unbound or fall through).
14. `customBinding_persistsAcrossLaunch` — set a custom binding, terminate the app, relaunch, assert the new binding is still in effect. (Requires the harness to support a clean relaunch with the same UserDefaults suite.)
15. `resetAll_restoresDefaults` — set custom bindings, press Reset All, assert defaults are back.

### Reserved combo warning

16. `reservedCombo_showsWarning` — open Settings → Shortcuts, try to record `Cmd-Q`. Assert the warning row appears and the binding still saves (matches Issues app's warn-but-allow design).

## Sentinel-file pattern

For tests where "did the action fire?" matters more than what changed on screen, use the sentinel-file helper from `#0091`. Example for test 1: after pressing `Cmd-N`, type `printf 'new-session' > /tmp/batty-ui-test-<uuid>-new-session` in the new session's terminal and assert the file appears.

For tests where the UI directly reflects state (e.g. test 4 — "two panes visible"), assert via accessibility identifiers.

## Acceptance criteria

- All 16 tests pass on the current build.
- A regression that re-introduces the `Cmd-W → close window` bug (`#0062`) makes test 2 fail.
- A regression that re-introduces the `Cmd-N → open new window` bug fails test 1.
- A regression that re-breaks the recorder fix (#0070's late patch) fails test 12.
- The harness can run a clean relaunch with isolated UserDefaults (test 14).

## Out of scope

- Testing every customizable action's default binding individually beyond the most common ones — the catalog above covers the high-value cases.
- Cross-locale keyboard layouts.
- Testing macOS-reserved system shortcuts (Mission Control, Spotlight, etc.).

## Notes

- Tests should use the harness flag from `#0091` to bypass `QuitConfirmation` so teardown is clean.
- Custom-binding tests need test-isolated UserDefaults (the launch flag should redirect to a temp suite so the user's real shortcut bindings aren't trampled).
- Related: `#0062` (the routing bug), `#0063` (Cmd-N rebind), `#0070` (the customization pane).
