## Description

An Xcode-style "Open Quickly" panel: press **Cmd-Shift-O**, type a few characters, see a fuzzy-matched list of named sessions and tabs across the current window, hit Return to jump straight to that session and tab. Xcode uses Cmd-Shift-O to match source files in a project; Batty's parallel is matching the navigable units of the multiplexer.

The killer use case: a dozen sessions are open, each with multiple tabs running different long-lived processes (`web`, `worker`, `db`, `tail-logs`, …). Cmd-Shift-O → `wor` → focus jumps to the right tab in the right session in one beat.

## Acceptance criteria

- Cmd-Shift-O from anywhere in the app opens a centered translucent sheet with a search field and a results list.
- The corpus searched is: every session name + every tab title in the current window. Result rows show `Session name › Tab title` (right-chevron separator), with the matched substring(s) highlighted in the row.
- Typing filters by case-insensitive fuzzy match (subsequence match, then ranked by tightness of match and recency of focus — recent-first feels right when the user is jumping back-and-forth between two areas).
- Up / Down arrow keys move selection; Return activates: brings the chosen session forward in the sidebar, focuses the chosen tab in its pane, and gives keyboard focus to the terminal. Esc dismisses without action.
- An empty query shows the most-recently-focused sessions/tabs ordered by recency — supports "Cmd-Shift-O, Return" as a quick toggle between two locations.
- Sessions and tabs with auto-derived titles (`#0089`) participate normally — what the sidebar / tab chip displays is what the panel searches against.

## Out of scope

- Searching panes by themselves (panes don't have user-facing names; tabs are the right granularity).
- Searching terminal content (scrollback). That's `Cmd-F`, a separate feature.
- Searching across multiple windows. Until multi-window lands (`#0027`), the corpus is the single window's content.
- Filtering by session-color tag or any other dimension. Pure name match for v1.
- Surfacing in-app commands. Those belong to the command palette (`#0126`); the two features are intentionally distinct entry points with distinct domains.

## Notes

- Xcode parallel: Cmd-Shift-O in Xcode matches *files in the project*. Batty's Cmd-Shift-O matches *places you can put your cursor*. Same keyboard shortcut, same fuzzy-find shape, different corpus.
- Related to `#0126` (command palette): both are fuzzy-find panels. Worth deciding whether they share a generic `FuzzyFinder<T>` SwiftUI component, or remain independent. Lean toward shared — the corpora differ but the row chrome, keyboard navigation, and highlight logic are identical.
- Fuzzy ranking: subsequence match is the table-stakes algorithm. For ranking, prefer contiguous matches over scattered ones (e.g. `wor` in "worker" beats `wor` in "wandering-orange"), then break ties by recency. A small Swift fuzzy-matcher (≈100 lines) is plenty — no need for an external dependency.
- Recency: track per-session and per-tab `lastFocusedAt: Date?` in the runtime store. Reset on every focus change.
- The bell feed (`#0027`) is the most-similar existing UI surface — popover with a list, click-to-jump. Match its visual style for consistency, but Open Quickly is a centered sheet (more prominent, keyboard-driven), not an anchored popover.

## Root cause

Feature gap. The app had no way to jump directly to a named (session, tab) location without manually clicking through the sidebar and tab strip — painful once a window holds a dozen sessions with multiple tabs each.

## Fix

- Added a centered sheet `OpenQuicklyView` that lists every (session, tab) pair in the current window and filters them by a case-insensitive subsequence match. Rows render as `Session › Tab` with matched characters bolded in the accent color.
- Cmd-Shift-O is dispatched from `BattyShortcuts.handle(_:)` as a fixed combo (the load-bearing path that fires regardless of which view holds first responder) and posts a `.battyOpenQuickly` notification. `SessionDetailView` observes the notification and toggles a sheet binding. A mirrored File-menu item provides discoverability with the same shortcut.
- Recency: added `lastFocusedAt: Date?` to `SessionRuntime` and `TabRuntime`, both `@ObservationIgnored` so stamping them doesn't churn SwiftUI. They are written from `AppStateStore.markActiveTabSeen()`, which is already called from every focus-change path (sidebar selection, pane focus change, tab switch), so no parallel notification path is introduced.
- Ranking: a small `FuzzyMatcher` enum in `Util/` returns `(score, matchedIndices)`. The score rewards contiguous matched pairs, a start-of-string match, and matches that follow a word-boundary character (`_`, `-`, ` `, `/`, `.`), then penalizes scattered matches via a span-vs-query-length term. Ties are broken by recency. An empty query short-circuits the matcher and orders all rows by recency descending — supports the "Cmd-Shift-O, Return" toggle between two locations.
- Activation reuses `TerminalSurfaceFocuser.focusWhenReady(terminal:)` (hardened in `#0129`) so the keyboard lands on the terminal even when the chosen session was previously off-screen and its host subview is still hidden.

## Gotchas

- `Cmd-Shift-O` is a fixed combo (handled in `BattyShortcuts` like `Cmd-1..9` / `Cmd-Option-1..9`), not part of the customizable `ShortcutsStore` catalog. If we ever decide to make it customizable, add a `ShortcutAction.openQuickly` case and dispatch through `ShortcutsStore` like the other customizables.
- Recency is `@ObservationIgnored`. Open Quickly re-evaluates results inside `computeResults()` on every `body` recomputation (driven by `@State query` changes), which is when the date snapshot is read — observability is not needed because nothing else watches these fields.
- A shared `FuzzyFinder<T>` SwiftUI component for `#0126` was deliberately not built. `#0126` is still in design ("Details TBD") and speculating a generic before its concrete shape is known would be premature. The fuzzy matcher itself is small and reusable when the palette lands.
- Headless build verified, but the following interactive behaviors must be checked by hand: (1) the sheet appears centered with a translucent background when Cmd-Shift-O is pressed; (2) Up/Down/Return/Esc behave as described from inside the search field; (3) after Return the chosen terminal actually accepts keystrokes (the `focusWhenReady` retry schedule should cover the cross-session case where the host subview is still hidden, but timing-sensitive cases can race); (4) the focus-stamping side-effect is observed when re-opening the sheet — the most-recently-visited tab should sit at the top.
