## Description

Bridge the AppKit NSView from #0007 into SwiftUI and implement the IME protocol so CJK, dead keys, and emoji input work. SwiftUI rebuilding views must not destroy the underlying Terminal Session — view identity is decoupled from surface identity via `surfaceID: UUID`.

**Acceptance criteria:**
- `TerminalSurfaceView: NSViewRepresentable` exposes `surfaceID: UUID` and:
  - `makeNSView(context:)` looks up or creates a `TerminalSurfaceNSView` bound to that surfaceID.
  - `updateNSView(_:context:)` pushes config / theme / focus changes down without recreating the surface.
  - `dismantleNSView(_:coordinator:)` triggers `SurfaceRegistry.destroy(surfaceID)` (and only then).
- `TerminalSurfaceNSView` adopts `NSTextInputClient` and routes IME events into libghostty's text input API (`ghostty_surface_text` for committed text). The full ~15-method protocol is implemented; defaults are fine for methods we don't use.
- Verified manually: typing CJK via Romaji, `é` via Option-E + E on US-International, and emoji via Ctrl-Cmd-Space all produce the expected characters in a running shell.

## Notes

- `NSTextInputClient` is non-negotiable per PRD §6.11 — skipping it breaks CJK, dead keys, and emoji input entirely.
- Drag-and-drop (`NSDraggingDestination`) is **not** in this issue — see #0022.
- A dummy IME edge-case test (e.g., a Romaji input session) makes a good manual checklist item before resolving.

## Revised approach — 2026-05-08

This issue is **largely obsoleted** by the addition of `GhosttyTerminal` to `BattyKit`'s dependencies. `GhosttyTerminal` ships:

- `TerminalSurfaceView: View` — the SwiftUI wrapper this issue was going to write.
- `TerminalView` (`NSView`) plus `TerminalViewRepresentable@AppKit.swift` — the `NSViewRepresentable` bridge.
- Full IME pipeline. The `libghostty-spm` README explicitly notes `Input handling (key, mouse, IME)` is **retained** in the trimmed build, and `TerminalKeyEventHandler` is the platform key translator.

**Revised scope:** verify CJK / dead keys / emoji input work end-to-end via `GhosttyTerminal`'s wrapper once `#0009`'s hello-surface is alive. If anything is broken, file a focused follow-up against the specific input method, not against the entire IME plumbing. Otherwise this issue becomes effectively a manual smoke-test checklist that the user runs once.

## Root cause

Same as `#0007` — the original scope (hand-rolled `NSViewRepresentable` + `NSTextInputClient` conformance) was made redundant when the project adopted GhosttyTerminal's `TerminalSurfaceView` on 2026-05-08. GhosttyTerminal ships the entire IME pipeline (key event translation, marked-text state, IME point calculation, etc.) inside its `AppTerminalView` / `UITerminalView` platform classes, with the `TerminalSurfaceViewDelegate` protocols already wired to the runtime.

## Fix

No new code. The IME pipeline is in `GhosttyTerminal` and is exercised every time a Batty surface is rendered via `TerminalSurfaceView(context: tab.terminal)` (see `PaneView`). The libghostty-spm README and CLAUDE.md explicitly note that `Input handling (key, mouse, IME)` is retained in the trimmed build, including `TerminalKeyEventHandler`, `TerminalMarkedTextState`, and `TerminalInputText` (the latter two are covered by tests inside the libghostty-spm fork's `Tests/GhosttyKitTest/`).
