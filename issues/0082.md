## Description

Write the **Sessions** section of Batty's user Help: `Batty/Help/02-sessions.md`. Sessions are the top-level workspace concept — sidebar entries each containing their own set of panes and tabs.

Depends on `#0080` (Help window bootstrap).

## What `02-sessions.md` covers

### What a session is

A workspace entry shown in the left sidebar. Each session has its own pane tree (one or more splits) and its own tab strip per pane. Sessions are independent — running `vim` in Session A doesn't affect Session B's tabs.

### Creating a session

- Click `+` at the bottom of the sidebar.
- `Cmd-N` from anywhere in the app.
- New sessions inherit the **working directory** of the currently focused pane's active tab (per `#0057`). If you're in `~/Developer/Batty`, the new session starts there too.

### Renaming a session

- Right-click the session in the sidebar → **Rename**.
- Sessions can also be renamed automatically. If you've named a session in a specific directory before (e.g. you renamed a session to "Batty" while at `~/Developer/Batty`), Batty remembers the name. Next time a session's first pane lands in that directory — whether by creation, `cd`-ing in, or duplicating — the session re-applies the name (per `#0058`). The cache survives across launches.

### Reordering sessions

Drag a session up or down in the sidebar.

### Duplicating

Right-click → **Duplicate**. Creates a new session with the same name suffixed `Copy`. Tabs are not copied — duplication is a fresh shell with the same name.

### Muting a session's notifications

Right-click → **Mute Notifications**. Suppresses desktop notifications for bells fired inside that session. The sidebar badge and bell-feed entries still update. Right-click again → **Unmute Notifications** to restore.

### Closing a session

- Right-click → **Close**.
- `Cmd-W` while focused — closes the active tab, cascading: last tab closes its pane, last pane closes the session.
- When the last session closes, Batty quits.
- The next session to focus after closing is the one immediately preceding the closed one in the sidebar (per `#0067`) — not always the first session.

### Selecting a session

- Click in the sidebar.
- `Cmd-Option-1` through `Cmd-Option-9` to select session by index.

### What's persisted across launches

By default, Batty starts fresh on launch — one session, one pane, one tab (per `#0055`). The list of sessions from your last run is written to disk but not read back; if you want a fresh shell every time, that's already the behavior. The session-name cache (mapping directory → name) survives.

## Root cause

Not a bug — a planned documentation gap. `Batty/Help/02-sessions.md`
shipped as a one-line stub from `#0080` (the Help window bootstrap)
waiting for real content. With the four-level hierarchy named in the
overview (`#0081`), the Sessions page is the next layer of the in-app
Help, and the first reference users hit when they want to know what
the sidebar is for.

## Fix

Replaced the stub with a ~500-word user-facing page covering every
required subtopic from the issue spec:

- What a session is — named workspaces in the sidebar, independent
  pane trees and tabs, "one per project/host/task".
- Creating — `+` button, `Cmd-N`, CWD inheritance from the focused
  tab (per `#0057`), `$HOME` fallback when nothing is focused.
- Renaming — right-click → Rename plus the automatic re-apply via the
  directory-to-name cache (per `#0058`), described in plain user
  terms ("Batty remembers that pairing", "survives quit and
  relaunch").
- Reordering — drag in the sidebar.
- Duplicating — right-click → Duplicate, `Copy` suffix, fresh shell,
  tabs not carried over.
- Muting — right-click → Mute Notifications, sidebar badge / bell
  feed still update (per `#0068`), Unmute restores.
- Closing — right-click → Close, `Cmd-W` cascade (tab → pane →
  session), last-session-quits, previous-sibling focus on close
  (per `#0067`).
- Selecting — click, `Cmd-Option-1..9`; non-selected sessions stay
  alive.
- Persisted — write-only workspace by default (per `#0055`); name
  cache does survive.

Second person, concrete shortcuts, no internal types or Swift
symbols. Cross-links to `03-panes.md`, `04-tabs.md`, `05-shortcuts.md`,
and `06-notifications.md` so the page doesn't try to be its own
keyboard reference.
