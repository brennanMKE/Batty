## Description

Batty owns zero themes. The bulk of the catalog is upstream Ghostty's dump — ~485 entries in the upstream `Lakr233/libghostty-spm` package (the package `BattyKit/Package.swift` is actually pinned to; **not** a Batty fork) as `Sources/GhosttyTheme/Themes/Themes_<Letter>.swift` buckets plus `Themes/ThemeCatalog_Generated.swift` (see `docs/themes.md` §2).

> **Corrected premise (2026-08-05):** an earlier version of this Description claimed "the catalog is read-only at runtime; there is no API to register a theme on the fly, so any Batty-original theme has to land in the fork and reach the app via a package-revision bump in `BattyKit/Package.swift`." **That claim was false.** `GhosttyThemeDefinition` (`Sources/GhosttyTheme/GhosttyThemeDefinition.swift` in the upstream package) is a `public struct` with a **public memberwise init**, so Batty can construct catalog-shaped theme values entirely on its own side of the package boundary — no fork, no dependency change, no `BattyKit/Package.swift` edit. A first implementation round acted on the false premise and landed the eight Hackers-set themes in the `brennanMKE/libghostty-spm` fork instead; that work was reverted (see Notes) and redone the correct way: a Batty-owned `BattyThemeCatalog` in `BattyKit` that merges the upstream catalog with a Batty-original bucket at call time. `docs/themes.md` has been corrected to match. The `Build` module tag this issue originally carried is dropped along with the false premise — no build/package-plumbing work turned out to be needed.

This issue adds a curated set of Batty-original pop-culture terminal themes on top of that catalog: **8 collections, 11 dark/light pairs, 22 catalog entries total** — four pairs drawn from *Hackers* (1995) (Hackers, Hackers Blue, Acid Burn, The Gibson) plus one pair each from Blade Runner, Max Headroom, Nostromo (MU-TH-UR), Swordfish, Tron, Weird Science, and WarGames (WOPR). The palettes are already designed and previewed (see Attachments). (Corrected 2026-08-05: an earlier pass through this issue implemented only the 4-pair Hackers set and described it as the full deliverable — `issues/0310/index.html` links all 8 collections. See Notes.)

**Per-appearance support already exists and shapes the deliverable.** Batty selects between two catalog themes — one per macOS appearance — via `ThemePreference.darkDefaultsKey` / `lightDefaultsKey` (`co.sstools.Batty.themeName.dark` / `.light`, with migration off the legacy single key) in `BattyKit/Sources/BattyKit/Theme/ThemePreference.swift`, defaulting to `TokyoNight` (dark) and `TokyoNight Day` (light). `BattyKit/Sources/BattyKit/Theme/AppearanceObserver.swift` observes `NSApp.effectiveAppearance` and re-applies the global theme on change. The mechanism is two catalog themes, one per appearance — not the `TerminalTheme(light:dark:)` pair, which `toTerminalTheme()` still collapses to the same config. A dark-only theme therefore drops Light-mode users back to `TokyoNight Day`, which is why every Batty-original theme must ship a light companion (see acceptance criteria).

## Expected behavior

All 11 theme pairs (22 catalog entries — each dark theme plus its light companion) appear in the Theme menu and Settings picker like any catalog theme, and every theme in the set meets all of these acceptance criteria:

- **Owns an unclaimed hue pairing.** No existing catalog theme may already occupy the same identity. The neon space is crowded — `Cyberpunk`, `Cyberpunk Scarlet Protocol`, `Cyberdyne`, `Synthwave` (plus `Synthwave Alpha` and `Synthwave Everything`), `Neon`, `Warm Neon`, `Cobalt Neon`, `Laser`, `Retro Legends`, `Hacktober`, `Matrix`, `Blue Matrix`, `Spacegray Eighties`, `C64`, `Borland`, `IRIX Console`, `IRIX Terminal` — so each new theme must stake out a bg/accent pairing none of those hold. (2026-08-05: this caught a real hit — Batty's `Encom` collided case-insensitively with upstream's `ENCOM`, `Themes_E.swift`, a Tron reference, distinct palette. Resolved by renaming to `Tron` / `Tron Day`, not by accepting the coexistence; see round 4 Notes.)
- **Foreground-on-background contrast clears WCAG 4.5:1.** Verified mechanically for all 22 (range 8.12:1–16.15:1); see Notes.
- **All 16 ANSI slots stay semantically usable** — red reads as error, yellow as warning, green as success — verified against real output (`git status`, a failing build log, `ls --color`), not just against swatches. An "aesthetic" theme that makes a compiler error invisible is a failure.
- **Slot 2 (green) must not read as Matrix green on any theme**, or the set loses its identity.
- **Every theme ships a light companion**, so a user can set the pair in both appearance slots and appearance switching stays inside the set instead of falling back to `TokyoNight Day`. The companion is usually named `<Name> Day` (the `TokyoNight` / `TokyoNight Day` precedent) — **except `weird-science.html`, which inverts it**: the light variant is the primary form and is named plain `Weird Science`; its dark companion is `Weird Science Night`.
- **Light companions follow the light-palette conversion convention** (`TokyoNight Day`'s palette shows it) — this is the part implementers get wrong: slot 0 is a near-background light tint, not black; slot 15 is the ink (the foreground), not white; slots 9–14 **repeat** 1–6 rather than brightening, because a "brighter" variant on a light background is less legible and bold text would vanish; and neon accents must darken substantially to hold 4.5:1 on paper — the acid yellow `f0e800` becomes ochre `8a6a00`, and Acid Burn can't simply invert at all (lime ink on white is unreadable), so its companion changes the relationship: acid-tinted stock, plum ink, lime demoted to an accent. Verified to hold on all 11 pairs, not just the original 4 (see Notes).
- Themes survive an upstream catalog refresh — regenerating `ThemeCatalog_Generated.swift` from a new upstream commit, or bumping the `libghostty-spm` package revision, must not touch or require re-adding anything in `BattyThemeCatalog.battyThemes`. (Superseded requirement, corrected 2026-08-05: earlier phrasing assumed the fork-hosted architecture from round 1, which was reverted — see Notes.)

### 2026-08-05 (round 1, reverted) — palettes landed in the fork on a false premise

A first implementation round landed the eight Hackers-set themes inside the
`brennanMKE/libghostty-spm` fork (`batty-delegates` branch, 3 commits:
`39921b5`, `06d1a1f`, `967af0c`) on the theory in the original Description
that the catalog was "read-only at runtime" and required a package-revision
bump. That premise was **false** — `GhosttyThemeDefinition` has a public
memberwise init, so Batty can build catalog entries on its own side without
a fork. The fork route also turned out to be a dead end on its own terms:
`BattyKit/Package.swift` pins the **upstream** `Lakr233/libghostty-spm`
package, not the `brennanMKE` fork, and the pinned commit and
`batty-delegates` had diverged by 96 commits — repointing the dependency
would have rolled the terminal core back 96 commits and undone `#0286`.

The user was explicit that themes must be **exclusive to Batty with no
dependency change**, so this round reverted the fork work
(`git reset --hard 8915065` on `batty-delegates`, dropping exactly those 3
commits; the unrelated delegate work below them, `8915065` and `ef88eed`,
was preserved and `swift build` still succeeds there) and redid the
delivery entirely inside `BattyKit`.

### 2026-08-05 (round 2) — themes delivered inside BattyKit, no fork, no dependency change

**Architecture:** `BattyKit/Sources/BattyKit/Theme/BattyThemes.swift` holds
the 8 `GhosttyThemeDefinition` values (4 dark + 4 `<Name> Day` companions)
as a `public extension GhosttyThemeDefinition`, built directly via the
upstream type's public memberwise init — no fork involved.
`BattyKit/Sources/BattyKit/Theme/BattyThemeCatalog.swift` is the new
catalog facade: `battyThemes` (the 8 entries), a testable
`merge(batty:upstream:)` that dedupes by name (Batty wins on collision) and
sorts case-insensitively, `allThemes` (the merged, sorted result — what
call sites read), and `theme(named:)`. All 12 call sites that previously
read `GhosttyThemeCatalog` directly now read `BattyThemeCatalog` instead:
`BattyCommands.swift` (Theme menu), `SettingsView.swift` (×2 — the picker
and its `onChange`), `CommandPaletteView.swift`, `ThemeSelectorView.swift`
(×4, across the global and per-session selector structs),
`UITestDriver.swift` (×2), `ThemePreference.swift` (×2). Zero changes to
`BattyKit/Package.swift`, `Package.resolved`, or anything in the fork.

**Palette verification:** all 176 values (8 themes × 6 top-level hex fields
+ 16-slot palette) were re-checked by hand against
`issues/0310/hackers-themes.html` — the authoritative source — not trusted
from the prior round's transcription. All byte-identical; no drift.

**Collision policy:** Batty wins. `merge(batty:upstream:)` deduplicates the
Batty bucket into the merged array first, so a same-named upstream entry
(none currently exists) would be dropped rather than shadowing the Batty
theme. Directly tested with synthetic collisions
(`mergePolicyPrefersBattyOnNameCollision`,
`mergeDropsUpstreamDuplicateRatherThanBattyDuplicate`) since no real
collision exists in the current ~485-entry upstream catalog to test
against (also pinned: `noBattyThemeNameCollidesWithRealUpstreamCatalog`).

**Tests:** `BattyKit/Tests/BattyKitTests/BattyThemeCatalogTests.swift`, 22
tests — presence of all 8 in the merged catalog; sort-order monotonicity
and correct neighbour placement; no upstream collision; no duplicate names;
the two synthetic collision-policy tests above; `theme(named:)` resolution;
per-theme palette pins against the HTML (one test per theme, all 8); the
light-companion convention (slot 15 byte-equal to foreground, slots 9–14
repeating 1–6) verified on all 4 companions, with a companion test proving
the *dark* themes do NOT follow that convention (so the light-side
assertions aren't vacuously true); WCAG 4.5:1 contrast on all 8 themes
using the same luminance formula as the HTML preview page.

**Mutation-tested:** emptying `battyThemes` fails 7 of the 22 tests (41
assertion failures) — presence, resolution, sort-neighbour, light-companion,
and WCAG tests all catch it. Reverting the `.sorted(...)` call in `merge`
to a no-op fails exactly the 2 sort-specific tests (8 assertion failures)
and nothing else. Corrupting one hex digit in the Hackers dark palette
fails exactly the one test pinning that theme's values
(`hackersDarkMatchesHTMLSource`) and nothing else. All three mutations were
reverted after observing the failures; `scripts/build.sh unit` was
re-run clean afterward (888 tests / 102 suites).

**Fork state confirmed after revert:** `batty-delegates` HEAD is `8915065`
(`Expose ghostty_surface_needs_confirm_quit and process_exited on
TerminalSurface`), with `ef88eed` immediately below it — both unrelated
delegate work, both preserved. `swift build` succeeds in the fork checkout.
Nothing pushed.

**`docs/themes.md` corrected:** §1–2 no longer claim the catalog is
upstream-only or read-only at runtime; §8's file table and §10's "adding a
theme" workflow now describe the `BattyThemeCatalog` route as the primary
path, with the upstream-regeneration route kept as the secondary one for
picking up new upstream themes. The quick-answer key and document version
footer were updated to match.

**Not verified:** ANSI semantics and light/dark rendering against a real
terminal and display — this implementer round had no way to visually
inspect the palettes on an actual display; the palette-pin and WCAG
contrast tests are the mechanical proxy. Final visual sign-off is the
user's, per the acceptance criteria's "verified against real output"
requirement.

**Scope note (added after this round, see round 3 below):** round 2 above
only implemented the 4-pair Hackers set (`hackers-themes.html`). The
Description and Expected behavior at the time undersold this as the full
deliverable, when `issues/0310/index.html` (linked from Attachments since
this issue was filed) always pointed at 8 collections. That scope miss was
caught in review and corrected in round 3.

### 2026-08-05 (round 3) — scope correction: all 8 collections, 22 themes

Round 2 implemented only 1 of 8 collections linked from
`issues/0310/index.html`. This round added the other 7 (14 more theme
entries): Blade Runner, Max Headroom, Nostromo (MU-TH-UR), Swordfish, Tron
(Encom), Weird Science, and WarGames (WOPR) — see the table above for core
values.

**Naming preserved exactly, not normalized:** `weird-science.html` inverts
the `<Name> Day` convention (light = plain `Weird Science`, dark = `Weird
Science Night`) — kept as authored rather than forced to fit the pattern.
`BattyThemeCatalogTests`'s `companionPairs` fixture now spells out each
dark→light pair explicitly instead of assuming a `" Day"` suffix, and a new
`companionPairsCoverEveryBattyTheme` test guards the fixture itself against
drifting out of sync with the full name list.

**Extraction was mechanical, not hand-copied.** `hackers-themes.html` uses
unquoted JS object keys; the other 7 files are strict JSON inside `const
THEMES = [...]`. A Python script parsed all 7 with `json.loads` directly
(after regexing the `note` field out of the one non-strict file, since it
contains a colon inside prose that would otherwise break a naive
key-quoting pass) and generated the Swift `GhosttyThemeDefinition` blocks
mechanically. A second script then parsed the *emitted* `BattyThemes.swift`
back out with a regex and diffed every field against the HTML-sourced
values independently. **Result: 22 themes × 22 fields (6 top-level hex
values + 16-slot palette) = 484 values compared, 0 mismatches.**

**Collision check across all 22 against upstream (~485 entries), exact and
case-insensitive, actually run rather than assumed:**

- **Exact-name collisions: none.**
- **Case-insensitive collision found: `Encom` vs upstream's `ENCOM`**
  (`Sources/GhosttyTheme/Themes/Themes_E.swift`, a Tron reference,
  `background: "000000"`, `foreground: "00a595"` — a different palette from
  Batty's `Encom`). This is exactly the kind of hit flagged as plausible
  before checking. **Resolved in round 4 by renaming, not by accepting
  coexistence** — see round 4 Notes below.

**WCAG 4.5:1 contrast, computed mechanically for all 22** (same luminance
formula as the HTML preview pages): foreground/background ranges **8.12:1
(Max Headroom) to 16.15:1 (WOPR)** — every theme clears AAA (7:1), not just
AA. No failures — nothing needed loosening or hiding.

**Slot 8 (bright black — the dim/comment role) runs low against
background on every theme, by design, not as a regression:** computed
mechanically across all 22, range **1.72:1 (WOPR Day) to 3.31:1 (Acid
Burn)** — worst five are WOPR Day 1.72, MU-TH-UR Day 1.73, Swordfish Day
1.78, then Hackers Blue Day and Blade Runner Day tied at 1.84. Slot 8 is
never used for foreground text (`toTerminalConfiguration()` doesn't touch
it beyond the palette slot itself), only as the dim/comment/faint-text
tone real terminal apps set explicitly — low contrast there is the
intended effect, the same way `ThemeSelectorView`'s "dim" chrome reads
lighter than body text on purpose. Recorded here so a future pass doesn't
rediscover this as a "new" finding introduced by the 14 additional
entries; it's present across the whole set, old and new alike.

**Light-companion convention holds on all 11 pairs**, not just the
original 4: slot 15 byte-equal to foreground and slots 9–14 repeating 1–6,
verified for Blade Runner Day, Max Headroom Day, MU-TH-UR Day, Swordfish
Day, Tron Day, Weird Science (the inverted-naming light side), and WOPR
Day, same as the original 4.

**Tests:** `BattyThemeCatalogTests.swift` grew from 22 to 39 tests (all
existing test names generalized from "eight"/"Eight" to the full set, e.g.
