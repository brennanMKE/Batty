## Description

Today's session auto-naming (from [[0089]]) only sets the session name once, at session creation time, based on the working directory's project artifacts. Once set, the name stays put even if the user `cd`s the shell into or out of a project directory afterwards. The user wants the name to react to cwd changes for **single-pane sessions** so the sidebar always reflects where the session "is."

## Expected behavior

For a session that contains exactly one pane (single Terminal Session):

- When the shell's cwd is inside a project directory, the session name reflects that directory (same logic as today's create-time auto-naming).
- When the shell's cwd moves **out of** any project directory, the session name resets to the default (the same name it would have if it had been created with no project context — e.g. "Session N").
- When the shell's cwd moves **into a different** project directory, the session name updates to the new directory's name.

The user-overridden name case (a name the user typed manually) should be preserved — auto-naming should never clobber an explicit user rename. Only auto-derived names should be live-updated.

## Actual behavior

The session name is captured once at creation and never changes in response to subsequent `cd` activity. Walking out of the original project directory leaves the old name stuck in the sidebar; walking into a new project doesn't pick the new project's name up.

## Notes

- Trigger source: this needs the OSC sequence the shell already emits for cwd (`OSC 7` / `OSC 1337 ; CurrentDir=…`) or whatever channel [[0089]] is using to detect project artifacts at create-time. Whichever signal it's on, hook the same code path on every emission, not just the first.
- Constraint to single-pane sessions is deliberate: with multiple panes, each pane has its own cwd and there's no obvious "the" cwd for the session — picking one would be arbitrary. If the session is later split, behavior should freeze on the last single-pane name (or follow whatever rule a follow-up issue decides for multi-pane).
- "Project directory" detection should reuse the same rule as [[0089]] (project-artifact detection — likely `.git`, `package.json`, `Cargo.toml`, etc.) so create-time and live-update naming stay consistent.
- "Reset" target: whatever name a freshly-created session in a non-project directory gets today (probably `Session N` or the shell's last-component cwd). Don't invent a new default — match what [[0089]] does for the no-project case.
- User-renamed sessions must not be overwritten. Need a flag on the Session model that says "name is user-authored, do not auto-update" (or use the existing override flag if [[0153]]-style rename-reset already tracks one — worth checking before adding a new one).

## Design

[[0089]] already wired `AppStateStore.handleWorkingDirectoryChange(forTabID:)` as the live CWD signal handler: it fires on every emission of the underlying CWD-update signal, looks up the anchor tab's CWD in the name cache, falls through to `ProjectNameResolver.shared.resolve(at:)`, and skips entirely when `session.titleOverride == true` (a user rename pins permanently). [[0089]] added the `SessionRuntime.titleOverride: Bool` flag for that gate and [[0153]] added the inverse `clearSessionName(id:)` action — the flag is already the single source of truth for "is this name user-authored?", so this issue reuses it rather than introducing a new one.

What was missing was the **reset branch**: when CWD walks out of any project directory, the handler returned silently and left the stale name in place. This issue adds that branch behind two gates — single-pane only, and only when the name is not user-authored.

## Fix

`handleWorkingDirectoryChange(forTabID:)` now:
1. Skips multi-pane sessions (`session.tree.allPanes.count == 1` gate). Multi-pane sessions have no canonical CWD — freeze on whatever name they had.
2. Computes the target title via a new pure helper `AppStateStore.resolveAutoTitle(forCWD:sessionIndex:cache:resolver:)` that returns cache-hit > project-name > `Session N` default.
3. Applies the target title only if it differs from the current title (idempotency / no spurious observer churn).

The default-fallback branch is what's new — that's the "leaving any project directory resets to default" path. The cache-hit and project-name branches continue to behave exactly as in [[0089]].

## Gotchas

- The `BattyKit` SPM test target is currently broken at the source level (`LayoutModelTests.swift`, `Workspace*Tests.swift` reference removed types — pre-existing breakage, see `swift test` output). Running this issue's tests requires temporarily disabling those broken files or filtering them out at the runner; the `scripts/build.sh` xcodebuild path does not include `BattyKitTests` in the `Batty (Prod)` scheme. Worth a follow-up issue to either delete the stale tests or migrate them to the runtime types so `swift test` is green again.
- The "default reset" target uses the session's current array index (`Session \(index + 1)`), not the index at creation time. If sessions ahead of this one have been removed, walking out of a project directory will give the session a `Session N` name with a different N than it originally had. That mirrors what `addSession` does for a fresh session in a non-project directory, so the rule stays internally consistent — but a user who opened "Session 3" first, closed sessions 1 and 2, then walked out of a project in the surviving session would see it rename to "Session 1". This is acceptable for an auto-derived name (it gets re-derived on every CWD change anyway) and isn't worth special-casing.
- The cache-hit branch wins over the project-name branch. That means if the user previously typed a custom name in a directory (recorded in `SessionNameCache`), walking back into that directory restores the custom name even though `titleOverride` is `false`. This is intentional and matches [[0089]]'s precedence — the cache is "user-chosen for this CWD" and beats the auto-derived project name.
- The new `resolveAutoTitle` helper centralizes the cache > project > default chain. The `addSession` create-time path still has its own slightly different chain (it uses `title ?? cachedName ?? Session N`, with no project-name step at create time). That's a pre-existing inconsistency from [[0089]] — create-time auto-naming relies on the post-spawn CWD update to land the project-name pass — and is out of scope here. Worth a follow-up to unify the two call sites against `resolveAutoTitle`.
