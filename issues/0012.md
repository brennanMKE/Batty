## Description

Wire Cmd-Shift-1 through Cmd-Shift-9 to select the Nth session in the sidebar of the active window (PRD §6.3, Concepts → Session). Keyboard-first selection is a v1 goal.

**Acceptance criteria:**
- Cmd-Shift-1..9 select sessions 1..9 in the active window's sidebar list.
- If fewer than N sessions exist, the keypress is a no-op (don't crash, don't wrap).
- Keybindings are exposed in the menu bar under a "Session" or "View" menu so VoiceOver / discoverability work.
- Focus moves to that session's `focusedPaneID`'s active Tab on selection (so typing immediately goes to the right surface).

## Notes

- Use SwiftUI `Menu` / `Button` with `.keyboardShortcut(...)` so the shortcuts show up in the standard Mac menu.
- This is the only Cmd-Shift-N collision risk to check: Cmd-Shift-N is also used by the Bell Feed (#0026). The Bell Feed shortcut is single-press, distinct from numeric Cmd-Shift-1..9 — no conflict, but flag if AppKit reports an ambiguity.

## Root cause

Feature gap. M2 keyboard navigation: Cmd-Shift-1..9 to pick the Nth session.

## Fix

SwiftUI commands at the Scene level need to reach the focused window's `AppStateStore`. The standard pattern: publish the store via `.focusedSceneValue` and read it in commands via `@FocusedValue`.

Three new files:

- `BattyKit/Sources/BattyKit/FocusedValues.swift` — defines `FocusedAppStateStoreKey: FocusedValueKey` and exposes `FocusedValues.appStateStore: AppStateStore?`.
- `BattyKit/Sources/BattyKit/BattyCommands.swift` — public `BattyCommands: Commands` struct emitting a `CommandMenu("Session")` with 10 buttons: "New Session" (Cmd-Shift-Option-N to avoid colliding with default Cmd-N) plus 9 "select Nth" buttons (Cmd-Shift-1..9). Each button reads `@FocusedValue(\.appStateStore)` and acts on it. Disabled when fewer than N sessions exist; live session title is shown so the menu reflects state.
- `RootWindowView` updated with `.focusedSceneValue(\.appStateStore, store)` so each window's store is published when that window is focused.
- `Batty/BattyApp.swift` updated to attach `.commands { BattyCommands() }` to the WindowGroup.

## Files changed

- `BattyKit/Sources/BattyKit/FocusedValues.swift` — new (~12 lines).
- `BattyKit/Sources/BattyKit/BattyCommands.swift` — new (~45 lines).
- `BattyKit/Sources/BattyKit/RootWindowView.swift` — added one `.focusedSceneValue` modifier.
- `Batty/BattyApp.swift` — added `.commands { BattyCommands() }`.

## Gotchas

- **Visual verification needed:** menu shows under "Session" in the menu bar, Cmd-Shift-1..9 select the right session in the focused window, disabled state for indices ≥ session count looks right, multi-window scenarios route to the focused window's store. `xcodebuild build` passes.
- **`@FocusedValue` is Optional**, returns `nil` if no window is focused. Buttons are `.disabled(store == nil)` to avoid silent no-ops.
- **Cmd-Shift-Option-N for "New Session"** — Cmd-N is reserved for "new window" by default WindowGroup behavior, and Cmd-Shift-N is reserved for Bell Feed (#0026). Cmd-Shift-Option-N is unusual but unambiguous; can revisit if the user wants something else.
- **No conflict with #0026's Cmd-Shift-N** — the bell feed shortcut is the literal letter N, distinct from the numeric Cmd-Shift-1..9.
- **Live title in menu items** is a nice UX win: the menu shows what each session is currently running, not just "Session 1".
