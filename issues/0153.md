## Description

Once a session has been manually renamed (via the sidebar "Rename" action), the custom name is pinned (`titleOverride = true`) and persists across app launches. There is no way to clear that name and return to auto-derived naming from the working directory. The session sidebar context menu only offers "Rename" — there is no "Reset Name" or equivalent.

By contrast, tabs already have a "Reset Title" item in their context menu (`tab.titleOverride = nil`, disabled when no override is set). Sessions need the same capability.

## Steps to reproduce

1. Start Batty. Session 1 is named automatically (e.g. "Batty" from the CWD).
2. Right-click Session 1 in the sidebar → Rename → type "Work" → confirm.
3. The session is now named "Work" and `titleOverride = true` is persisted.
4. Quit and relaunch — session comes back as "Work".
5. Right-click Session 1. Observe there is no option to clear the custom name.

## Expected behavior

The session context menu offers a **"Reset Name"** item (or "Clear Name") that:
- Sets `session.titleOverride = false` on the `SessionRuntime`.
- Triggers the CWD-based auto-naming to run immediately so the session title updates to the derived name rather than staying as the old custom name until the next CWD change.
- Is disabled when `session.titleOverride == false` (no custom name is set), mirroring the tab "Reset Title" disabled-state rule.

On next launch, the session resumes auto-naming normally.

## Actual behavior

No "Reset Name" action exists. The custom name is permanent once set.

## Notes

- The session rename flow lives in `BattyKit/Sources/BattyKit/Views/SessionSidebarView.swift` — the context menu at line 30 only contains `Button("Rename")`. "Reset Name" belongs in the same context menu, below "Rename", mirroring the tab context menu structure in `PaneView.swift` (lines 309–316).
- `AppStateStore.renameSession(id:to:)` sets `session.titleOverride = true`. A new `clearSessionName(id:)` method (or an equivalent inline action) should set `session.titleOverride = false` and re-run the CWD-based name derivation for that session.
- The CWD auto-derivation logic lives in `AppStateStore` (around line 330, guarded by `!session.titleOverride`). After clearing the override, the derivation should be triggered immediately rather than waiting for the next CWD change.

## Root cause

`renameSession(id:to:)` sets `session.titleOverride = true` and writes to the name cache. No inverse operation existed to clear the flag and resume auto-naming.

## Fix

Added `clearSessionName(id:)` to `AppStateStore`: sets `titleOverride = false`, then immediately re-derives the session title from the anchor tab's CWD (name-cache hit → `ProjectNameResolver` → leave title as-is). This gives instant visual feedback in the common case where the CWD has a known derived name, while gracefully degrading (flag cleared, title unchanged, auto-naming resumes on next CWD change) when no derived name is available.

Added "Reset Name" to the session context menu in `SessionSidebarView`, positioned directly below "Rename" and disabled when `titleOverride == false`, mirroring the tab "Reset Title" pattern already in `PaneView`.

## Files changed

- `BattyKit/Sources/BattyKit/Runtime/AppStateStore.swift` — `clearSessionName(id:)` method
- `BattyKit/Sources/BattyKit/Views/SessionSidebarView.swift` — "Reset Name" context menu item
