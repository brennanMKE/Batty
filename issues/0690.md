## Root cause

Starting state: #0649 shipped a `web-preview` Pane kind (a `WKWebView` for loopback pages), `batty server preview` with its XPC verb and MCP tool, `serve --open` opening that Pane by default, a Server Pane "Open in Batty" button, and a Settings "Open served sites in" picker, all behind `serverPane` (Beta). The user decided on 2026-11-19 to remove the web view entirely.

## Resolution notes

> 🟢 Resolved 2026-11-19 — The Web Preview Pane, `batty server preview`, its XPC verb and MCP tool, WebKit use, the "Open served sites in" Setting and the Open in Batty button are gone; `serve --open` opens the default browser.

## Fix

Followed the plan. The `webPreview` case is gone, with no decode shim, and `WebPreviewURLPolicy` is deleted. `serve --open` now always calls `openURLInBrowser` (`NSWorkspace.shared.open`), including on a reused server. The `BattyPreview/` User-Agent exemption, `staticReloadBroadcaster(forPort:)`, `ServerReply.previewPaneID`, `ServerXPCError.previewURLNotAllowed`, `ServedSiteOpenTarget` and its Settings row, and the Server Pane's Open in Batty button are removed. WebKit was linked only implicitly, through `import WebKit`, so there were no link settings to edit. Docs, the skill, Concepts.md and PRD.md are updated. No deviations, except one extra doc edit in Gotchas.

### Premises checked

- Everything the Description lists exists as stated (`ServerPreviewCommand` is at `ServerCommand.swift:270`). There is no `AppStateStoreWebPreviewTests.swift`: `AppStateStoreWebPreviewTests` is a struct inside `WebPreviewPaneTests.swift`.
- **WebKit linkage:** no `WebKit` in `Batty.xcodeproj/project.pbxproj`, `BattyKit/Package.swift`, `Configuration/*.xcconfig` or an Info.plist (no ATS keys). It is auto-linked only through `import WebKit` in `WebPreviewEngine.swift` (and two test files). Deleting those files removes it; there are no link settings to edit.
- **Persistence:** nothing stored can hold `web-preview`. Workspace persistence is gone (#0172), and `Pane` is never serialized outside tests. Projects never write it: the Project Editor offers only `projectSlotKinds` (excludes it), `SessionProjectCapture` turns a Web Preview Pane into an empty terminal slot, and `ProjectTreeBuilder` maps it to terminal. Only a hand-edited Project file could carry it, and `ProjectPane.init(from:)` already throws on any unknown kind by design (its doc comment). `TopologyPanePayload` decodes the kind leniently (`String` → `PaneContentKind(rawValue:)`, nil if unknown). **Decision: delete the case outright; no decode shim.** A unit test pins that the raw value is now unknown.
- **`WebPreviewURLPolicy` does not move.** After removal its only users are `server preview` (deleted), `ServerXPCError.previewURLNotAllowed` (deleted) and `ServerPaneContent.canOpenPreview` (deleted). `serve --open` always opens the server's own `http://127.0.0.1:<port>/` URL, which needs no check. Delete the file.
- The `StaticHTTPResponder.previewUserAgentToken` exemption (no reload script for a `BattyPreview/` User-Agent) and `AppStateStore.staticReloadBroadcaster(forPort:)` exist only for the preview. Remove both. Keep `StaticReloadBroadcaster.addObserver/removeObserver/observerCount`: `InAppStaticServerTests` and `StaticFileServerTests` use them, and #0693 replaces this server anyway.
- `docs/nsviewrepresentable-state-persistence.md` uses `WKWebView` as a general SwiftUI example (from #0076, 2026-05-12). It is not about the preview. Leave it, and record it in `## Gotchas` as the one expected hit of acceptance criterion 2's grep.
