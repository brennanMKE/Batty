## Description

Closing Tabs with a Tab chip's **Close Other Tabs** removes them without cleaning up the Bell Feed. Their rows stay in the list and keep pointing at Tabs that are gone. If any of those rows were unread, the Pane and Session unseen counts stay too, along with the Sidebar badge and the `bell.badge` toolbar icon. Every other close path purges them.

The goal, from the user (2026-11-05):

> We should make it our goal to declutter the notification list as much as possible so only what is useful remains.

Split out of [#0555](0555.md), "Further decluttering". The candidate there was "entries for Tabs or Sessions that have since closed". Most of that already works. This is the gap that's left.

## Verified (main `c51a7e1b`)

These paths all call `WindowRuntime.cleanUpBellState(forTabIDs:)` (`BattyKit/Sources/BattyKit/Runtime/WindowRuntime.swift:1121`), which removes the rows and decrements the unseen counters (#0071):

- `WindowRuntime.closeTab(id:)` (`:425`, cleanup at `:430`). That includes a Tab whose process exits: `PaneView`'s `terminal.onClose` calls `AppStateStore.closeTab`.
- `closePane` (`:688`).
- `removeSession(id:)` (`:293`), from the GUI or the CLI.
- Window close: `RootWindowView` (`Views/RootWindowView.swift:242`) cleans every Tab in the Window.

This path doesn't:

- **`PaneRuntime.closeOtherTabs(keeping:)`** (`Runtime/PaneRuntime.swift:299`). It is called from `WindowRuntime.requestCloseOtherTabs` (`WindowRuntime.swift:560`) and from `confirmPendingClose`'s `.otherTabs` case (`:587`). It replaces `tabs` and releases the terminal views, and it never touches `bellFeed` or the counters.

A related view path also bypasses cleanup. When `PaneView` has no `appStore` (`PaneView.swift:221`, `:297`, `:680`), it falls back to `pane.removeTab(id:)` directly. That only happens in previews and tests, but note it in the plan.

## Expected behavior

Close Other Tabs removes the closed Tabs' Feed rows and decrements the unseen counters exactly as `closeTab` does. The kept Tab's rows are untouched. #0297 and #0523 records are not touched.

## Recommended default

Call `cleanUpBellState(forTabIDs:)` with the closed Tab ids in `WindowRuntime` before `pane.closeOtherTabs(keeping:)`, on both call sites. Or, better, route both through one `WindowRuntime.closeOtherTabs(paneID:keepingTabID:)` so the next caller can't miss it. Keep `PaneRuntime` free of Feed knowledge, as `removeTab` is.

## Tests

Use non-default fixtures:

- Unread rows on two victim Tabs and on the kept Tab.
- After Close Other Tabs, only the kept Tab's row remains, and the Pane and Session counters equal the kept Tab's count.
- The same through the confirmation path (`confirmPendingClose`) with a busy victim.

See `BellFeedCleanupTests` and `AppStateStoreClosePaneTests` for the existing pattern.

## Resolution notes

> 🟢 Resolved 2026-11-05 — Close Other Tabs now routes through `WindowRuntime.closeOtherTabs(in:keeping:)`, which purges the closed Tabs' Bell Feed rows and unseen counts before removing them, on both the all-idle and confirmed paths.

## Root cause

`PaneRuntime.closeOtherTabs(keeping:)` replaces `tabs` and releases terminal views but has no Bell Feed knowledge, and both `WindowRuntime` callers (`requestCloseOtherTabs`'s all-idle branch and `confirmPendingClose`'s `.otherTabs` case) called it directly, skipping `cleanUpBellState(forTabIDs:)`. Confirmed by the mutation run below.

## Fix

Followed the Plan. New internal funnel `WindowRuntime.closeOtherTabs(in:keeping:)`: guards that the kept Tab is in the Pane, computes the victim ids, logs, calls `cleanUpBellState(forTabIDs:)`, then `pane.closeOtherTabs(keeping:)`. Both callers route through it; `grep "\.closeOtherTabs(keeping"` now shows only the funnel and the preview-only `PaneView.swift:687` fallback. `PaneRuntime.closeOtherTabs` doc comment notes it does no Feed cleanup. `docs/notifications.md` §6 table updated (closeTab, closePane, closeOtherTabs, removeSession, Window close; owner corrected to `WindowRuntime`; Reminder rows purged by Session id), and the answer-key entry now names `cleanUpBellState(forTabIDs:)`. No departures.

It never touches `bellFeed` or the counters. Both callers hand it the Pane directly: `WindowRuntime.requestCloseOtherTabs` (`WindowRuntime.swift:609`, the all-idle branch) and `confirmPendingClose`'s `.otherTabs` case (`:636`).
- **Line numbers have moved** since `c51a7e1b`: `closeTab(id:)` is now `:474` (cleanup at `:479`), `removeSession(id:)` `:286` (cleanup at `:305`), `closePane` `:724` (cleanup at `:737`), `cleanUpBellState(forTabIDs:)` `:1252`, `RootWindowView.windowWillClose` cleanup `:245`. `PaneView`'s no-`appStore` fallbacks are at `:221`, `:297` and `:680`, and **`:687` too**, which the issue left out: the Close Other Tabs menu item itself falls back to `pane.closeOtherTabs(keeping:)` when there is no `appStore`.
- **Reminder rows already survive this cleanup.** Since #0514, `BellFeedStore.removeEntries(matchingTabIDs:)` removes only `kind == .bell` rows. The footprint row (`BellFeedEntry.systemID`) never matches a real Tab id, so it survives too.
- **The process-exit path is fine.** `PaneView`'s `tab.terminal.onClose` (`:292`) calls `AppStateStore.closeTab`, which cleans up.

### Approach

**`BattyKit/Sources/BattyKit/Runtime/WindowRuntime.swift`**

- Add one funnel, next to `requestCloseOtherTabs`:

  ```swift
  func closeOtherTabs(in pane: PaneRuntime, keeping keptTabID: UUID)
  ```

  1. `guard pane.tabs.contains(where: { $0.id == keptTabID }) else { return }`. This mirrors `PaneRuntime.closeOtherTabs`'s own guard, so an unknown kept id purges nothing. Without it the cleanup would remove every row in the Pane while the Pane keeps every Tab.
  2. `let victims = Set(pane.tabs.map(\.id)).subtracting([keptTabID])`.
  3. `cleanUpBellState(forTabIDs: victims)` **before** `pane.closeOtherTabs(keeping:)`, the same order as `closeTab` and `closePane`. `decrementUnseen(for:)` walks `pane.tabs` to find the Tab, so the victims must still be there for their Tab counters, though only Pane and Session counters matter after removal.
  4. `pane.closeOtherTabs(keeping: keptTabID)`.
  5. One `logger.info` line with the Pane id and victim count, as `closePane` does.

  Make it `internal` (not `public`): both callers are in this file, and tests use `@testable import`. It takes the already-located `PaneRuntime` because both callers have just looked it up.
- `requestCloseOtherTabs`, all-idle branch (`:609`): call `closeOtherTabs(in: pane, keeping: keepingTabID)` instead of `pane.closeOtherTabs(keeping:)`.
- `confirmPendingClose`, `.otherTabs` case (`:636`): the same replacement.
- After this, `grep -n "\.closeOtherTabs(keeping" BattyKit/Sources` must show only the funnel and `PaneView.swift:687`.

**`BattyKit/Sources/BattyKit/Runtime/PaneRuntime.swift`**: no behavior change. Add one sentence to `closeOtherTabs(keeping:)`'s doc comment: it does no Bell Feed cleanup, and production callers go through `WindowRuntime.closeOtherTabs(in:keeping:)`. That matches how `removeTab(id:)`'s comment points at the `closeTab` cascade. Grep the claim before committing.

**`BattyKit/Sources/BattyKit/Views/PaneView.swift`**: no change. The `:221`, `:297`, `:680`, `:687` fallbacks run only when `appStore` is nil (previews). There is no Bell Feed there to clean. Routing them through a Window would need an `appStore` they don't have.

**`docs/notifications.md` §6**: the "Wired in" table (`:328`) lists only `closeTab` and `removeSession`, which is already stale. Bring it up to date: `closeTab`, `closePane`, `removeSession`, Window close, and the new `closeOtherTabs(in:keeping:)` row ("every Tab in the Pane except the kept one"). Add one sentence saying Reminder rows are not matched by Tab id and are purged by Session id instead (#0514). Fix the wording in the same section from `AppStateStore.cleanUpBellState` to `WindowRuntime.cleanUpBellState`, its real owner. The "Quick answer key" entry at `:503` ("a path that doesn't route through `closeTab(id:)`") becomes "doesn't route through `cleanUpBellState(forTabIDs:)`".

No Help text change: Help 04 lists the menu item and says nothing about the Feed.

### Decisions

- **One funnel in `WindowRuntime`, and `PaneRuntime` keeps no Feed knowledge.** The issue recommended this. A single funnel means a third caller can't skip the cleanup, and `PaneRuntime` has no `bellFeed` reference to use anyway.
- **The kept Tab's rows are left alone. Close Other Tabs is not a visit.** It does not call `visitFocusedTab()`. The kept Tab need not be in the focused Pane or the selected Session. #0556 limits removal-on-visit to navigation gestures, and `visitFocusedTab`'s doc says focus that lands somewhere because something closed goes through `markActiveTabSeen()` only. If the kept Tab is focused and newly active, the existing `PaneView` `onChange` fallback may mark its rows seen, as it does today. They are not removed.
- **Nothing is purged before confirmation.** With a busy victim, `requestCloseOtherTabs` only raises `pendingCloseRequest`. Cleanup runs in `confirmPendingClose`. A cancel leaves the Feed untouched.
- **Seen victim rows are removed too, with no counter change.** `cleanUpBellState` already does this. Every other close path removes a closed Tab's seen rows, and the user's goal is decluttering.
- **#0297 decision records and #0523 capture records are untouched.** `cleanUpBellState` never writes them. A test pins this.
- **Out of scope, noted only:** `AppStateStore.closeTab` cancels an in-flight AI Tab-name suggestion (`cancelTabNameSuggestion`). `closePane`, `removeSession` and Close Other Tabs don't. That is not a Bell Feed problem, and the task holds the Tab weakly. File it separately if it matters.

### User checklist

1. Open a Session with three Tabs. From another Session, `batty notify` each Tab (or ring a bell in each while you're elsewhere), so the Sidebar badge shows 3.
2. Right-click one Tab's chip > **Close Other Tabs**. The Feed keeps only that Tab's row, and the Sidebar badge and chip dots show 1. `bell.badge` stays only if the remaining row is unread.
3. Repeat with a running process in a victim Tab. Nothing changes in the Feed until you confirm. Cancel leaves it all as it was. Confirm cleans it up as in step 2.
4. Set a Reminder on the Session, let it fire, then Close Other Tabs. The Reminder row stays until you visit the Session.
