## Description

Make the session list mutable: drag a session to reorder; right-click for Rename / Duplicate / Close. Mirrors the "Sidebar affordances" bullets in `Concepts.md` → Session.

**Acceptance criteria:**
- Dragging a session row in the sidebar reorders the list. New order persists in the in-memory model (persistence to disk is #0029+).
- Right-click on a row presents a context menu with Rename, Duplicate, Close.
- Rename presents an inline-editable title (or a small sheet) and commits on Enter.
- Duplicate creates a new session whose split tree is a deep copy of the source's, but **with fresh Terminal Sessions** — we never duplicate live PTYs.
- Close removes the session and tears down all its surfaces. If it was the last session, replace it with a fresh empty session (we don't leave the window with zero sessions).

## Notes

- "Close" here is destructive — consider a confirm if any surface has a running foreground process. Polish-level confirmation lives in #0036; an unconditional close is fine for v1 of this issue.
- Sessions have an optional `icon`/`color`; out of scope here. Open a follow-up if useful.

## Root cause

Feature gap. M2's foundation (#0010) gave us add/select/move; this issue layers in the rest of the per-session lifecycle (rename, duplicate, close).

## Fix

Two extension points:

1. **`AppStateStore`** — added `renameSession(id:to:)`, `duplicateSession(id:)`, plus the auto-spawn-on-empty already covered by `removeSession`. Rename trims whitespace and refuses empty titles. Duplicate creates a fresh `SessionRuntime` (fresh `TerminalViewState`, fresh shell — never clones a live PTY), inserts it after the source, and selects it.
2. **`SessionSidebarView`** — `.contextMenu` on each row with Rename / Duplicate / Close (Close is `.destructive`). A `.sheet` driven by `renamingSessionID` shows `RenameSessionSheet` — a small focused `TextField` with Esc-cancel / Enter-commit, disabled-when-empty.

`onMove` (drag-to-reorder) already shipped in #0010. The duplicate flow honors PRD §6.11 (Session) explicitly: "with **fresh Terminal Sessions** — we never duplicate live PTYs."

## Files changed

- `BattyKit/Sources/BattyKit/AppStateStore.swift` — added `renameSession`, `duplicateSession`.
- `BattyKit/Sources/BattyKit/SessionSidebarView.swift` — added `.contextMenu`, `.sheet`-based rename UI, private `RenameSessionSheet` view.

## Gotchas

- **Visual verification needed:** context menu shows on right-click, rename sheet focuses and commits, duplicate spawns a fresh shell (not a clone), close moves selection to a neighbor. `xcodebuild build` passes. Resolved-not-closed.
- **Close on a session with running processes** is unconditional. PRD §6.9 / `#0036` will add a confirmation prompt.
- **Inline rename** (e.g. via `.renameAction` modifier) was considered but rejected — the modal sheet is more predictable across List-with-selection scenarios in macOS SwiftUI. If a future polish issue wants inline rename, the rename method on the store is the same regardless of UI affordance.
- **Duplicate's title is `"<source> Copy"`** without uniqueness checking. Two duplicates produce `"Foo Copy"` and `"Foo Copy Copy"`. Acceptable for v1.
