# 0222 — Extract layout preset tests from BattyUITests into BattyKit unit tests

| | |
|---|---|
| **Status** | open |
| **Module** | Testing |
| **Platform** | macOS |
| **First seen** | 2026-05-28 |

## Description

`BattyUITests/LayoutTests.swift` tests layout preset pane counts (2×2 grid → 4 panes, horizontal split → 2 panes, etc.) entirely through UI intents and accessibility-element counts. These tests exercise pure `LayoutModel` / `SplitTreeNode` logic with no visual component — they are UI tests only because no unit alternative existed. All six tests can move to `BattyKitTests`.

## Fix

Add `BattyKit/Tests/BattyKitTests/LayoutModelApplyTests.swift` with one `@Test` per layout preset. Call `AppStateStore.applyLayout(_:)` (or the underlying `LayoutModel` helper) directly and assert `session.tree.allPanes.count`. No accessibility identifiers, no app launch.

Candidate tests to cover (mirrors `LayoutTests.swift`):
- `twoByTwoGridProducesFourPanes`
- `horizontalSplitProducesTwoPanes`
- `verticalSplitProducesTwoPanes`
- `threeColumnProducesThreePanes`
- `twoByThreeGridProducesSixPanes` (if present)
- `layoutPickerDefaultIsCorrect`

Once the unit tests exist and pass, the corresponding cases in `BattyUITests/LayoutTests.swift` may be removed or kept as a shallow smoke-test (one case to confirm the UI intent wires through).
