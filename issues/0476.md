# 0476 — A Session the user has arranged by hand cannot be saved as a Project, from the Sidebar, the File menu, the Command Palette, or the editor's "Copy from current Session"

## Description

The fastest way to make a Project is from a Session that is already set up. Artboard 4 (`issues/0469/EntryPoints.dc.html`) says: "Saving captures the Session's current Panes, their kinds, every Tab's working directory and title, and opens the Project Editor so you can add startup commands. Pane sizes are not saved." This issue builds the live-tree → `ProjectLayout` converter. That converter is the narrow slice of #0172's deleted `WorkspaceConversion.swift` that #0371 asked for, extended with Tabs. The issue also wires the converter to four entry points: Sidebar **Save as Project…**, File ▸ **Save Session as Project…**, the Command Palette's **Save Session as Project…**, and the Project Editor's **Copy from current Session** button.

## Expected behavior

**1. Converter** (pure, unit-tested, in `Model/`): `SessionRuntime` → a draft `Project` (#0471):

- **Topology.** Walk `SplitTreeNode` (`Model/SplitTree.swift:27-29`, `.leaf(PaneRuntime)` / `.split(id:direction:ratio:left:right:)`) into `ProjectLayout`. Record direction and nesting. **Drop `ratio`** and every other piece of geometry. If the captured topology equals a `PaneLayout` preset's topology, set the preset marker (#0471) so the editor highlights the right thumbnail. Otherwise mark it Custom.
- **Hidden Panes.** `Pane` has `isHidden` (`Model/LayoutModel.swift:15-24`). Decide whether hidden Panes are captured (default: yes, as ordinary slots, because the Project has no hidden state) and test the choice.
- **Kinds.** Read each Pane's `kind`. A non-terminal Pane's placeholder Tab is never captured (`Concepts.md` Tab "Exception (#0315)").
- **Root.** Use the anchor Tab's cwd (first leaf Pane's first Tab, the same anchor auto-naming uses, `Runtime/AppStateStore.swift:1933-1973`), read from the live `terminal.workingDirectory`, falling back to `configuration.workingDirectory`. If the anchor is non-terminal or has no cwd, use the first Terminal Tab that has a cwd. If none has one, use `$HOME`, and the editor asks for a root.
- **Tabs.** For each Terminal Tab, store its working directory **relative to the root**. A cwd outside the root is stored as `"."` (root), and the editor flags it so the user can fix it, because #0471's resolver rejects paths that escape the root. Store the **title** only if the user set one (`TabRuntime.titleOverride`, `Runtime/TabRuntime.swift:11`). An automatic title such as a process name or cwd basename would be frozen into a wrong label. Store **no startup command**: commands are never inferred from running processes.
- **Git Status.** Store the repository folder relative to root, taken from `GitStatusPaneContent.directoryPath` (`Runtime/GitStatusPaneContent.swift:643`).
- **Name and color.** Name = the Session title, or the `ProjectNameResolver` result for the root, or the root's basename, whichever is first non-default. A default `Session N` title is not used as a name. Color = the Session's current `SessionColor`.
- **Run toggle.** Off by default for a captured Project, because a captured Project has no commands.

**2. Entry points.** Each one captures the relevant Session and opens #0474's editor with the draft. **Nothing is saved until the user clicks Save** in the editor.

- **Sidebar context menu.** Add **Save as Project…** to the row's `.contextMenu` (`Views/SessionSidebarView.swift:274-308`), after the Theme items and before the destructive Close, behind a `Divider`. It captures *that row's* Session, which need not be the selected one.
- **File ▸ Save Session as Project….** Put it in the Projects group #0474 and #0475 added to `CommandGroup(replacing: .newItem)` (`Commands/BattyCommands.swift:66-87`). It captures the key Window's selected Session, and is disabled when there is none.
- **Command Palette.** `PaletteCommand(id: "extra:saveSessionAsProject", title: "Save Session as Project…")` in `allCommands` (`Views/CommandPaletteView.swift:52-114`). It captures the key Window's selected Session.
- **Project Editor ▸ Copy from current Session.** Next to the Layout strip (artboard 1). It replaces the draft's layout, Pane kinds and Tabs with a capture of the content window's selected Session (`defaultTargetWindow()`, not the editor window). It keeps the draft's name, root and color, and asks before discarding configured Tabs or commands.
- **Already Project-backed Sessions.** If the Session has a `projectID` (#0472), Save as Project… offers **Update "<name>"** (replace that Project's layout and Tabs, keeping its commands where the slot and Tab still line up) or **Save as New Project…**. Whether a confirmation dialog or two menu items is better is the implementer's call. State the choice in the resolution.
- No keyboard shortcut and no `ShortcutAction` case (#0469).

**3. Flag gate, per entry point.** With `featureFlags.projects == false`: no Sidebar menu item, no File item, no palette entry, the converter is never called, and `ProjectStore` is never constructed. The editor button doesn't exist, because the editor doesn't (#0474). Append each site to #0470's gate-site list.

## Acceptance criteria

- Converter unit tests use trees built with `contentFactory: { _ in nil }` (so no real FSEvents, subprocesses or sampling `Task`s, `SplitTree.swift:341-344`) and with no mounted surfaces. They cover:
  - each `PaneLayout` preset → the preset marker set;
  - a hand-built nested tree three levels deep → Custom, with the topology preserved;
  - mixed kinds;
  - a Terminal Pane with three Tabs at root, a subdirectory, and outside the root;
  - Tabs with and without `titleOverride`;
  - a Git Status path;
  - a non-terminal anchor;
  - a hand-resized tree (non-0.5 ratios) whose capture contains no ratio.
- **Round trip.** Capture a hand-resized Session, open the resulting Project (#0472), and get the same shape with **equal** sizing per #0255. Assert this as intended behavior, not as a defect (#0371's acceptance criterion).
- The palette contains `extra:saveSessionAsProject` with the flag on and not with it off. The Sidebar and File menu gate functions are unit-tested for both flag values.
- "Unchanged" assertions (for example, the Project is not updated on Cancel) use non-default fixtures.
- No sleeps or polling in tests (`AGENTS.md` "Asynchronous tests").
- `./build.sh unit` passes. The Sidebar menu item and the editor button need the user's visual sign-off. Mark `resolved`, not `closed`.

## Notes

- **#0172 squaring.** This re-introduces a live-model → Codable converter. It is explicitly invoked, writes nothing until the user saves in the editor, and never runs on quit or on a timer. Say so in the resolution, so a later reader comparing it with `WorkspaceConversion.swift` sees the difference.
- **Binding:** `docs/swiftui-observation-rules.md`. Capture reads observed state from a menu, palette or button action, and must not write anything during capture. Opening the editor is an event-origin action. Don't call `makeFirstResponder` from the context-menu action. `docs/terminal-pane-requirements.md` applies to the Sidebar row: the new menu item must not disturb row selection, drag-reorder (#0410), or the row's accessibility identifiers.
- `WindowRuntime.duplicateSession(id:)` (`Runtime/WindowRuntime.swift:339-349`) copies only the title and creates a fresh one-Pane Session, so there is no existing topology copier to reuse.
