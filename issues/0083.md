## Description

Write the **Panes and Splits** section of Batty's user Help: `Batty/Help/03-panes.md`. Panes are the recursive split structure inside a session — left/right or top/bottom regions, each potentially split further.

Depends on `#0080` (Help window bootstrap).

## What `03-panes.md` covers

### What a pane is

A region inside a session that hosts a tab bar and terminal area. A session starts with one pane. You can split a pane into two, then split either of those into two more, and so on.

### Creating a split

- **`Cmd-D`** — split the focused pane horizontally (new pane appears to the right).
- **`Cmd-Shift-D`** — split vertically (new pane appears below).
- The toolbar has split-horizontal and split-vertical buttons that do the same.

The new pane inherits the focused pane's working directory (per `#0061`), so splitting in `~/Developer/Batty` gives you another pane already at `~/Developer/Batty`.

### The focused pane

Only one pane in a session is "focused" — keyboard input goes to it, and split / new-tab actions target it. The focused pane has an accent-colored border and non-focused panes are slightly dimmed (per `#0052`).

### Moving focus between panes

- **`Cmd-Option-←` / `Cmd-Option-→` / `Cmd-Option-↑` / `Cmd-Option-↓`** — focus the pane in that geometric direction.
- **Click** anywhere inside a pane (tab chip or terminal body) — focuses that pane (per `#0060`).

### Resizing splits

Drag the divider between two panes. The cursor changes to a resize handle on hover. Drag past the divider's edges to make one side disappear (down to a minimum size).

### Closing a pane

`Cmd-W` closes the active tab. When the last tab in a pane closes, the pane closes and the remaining sibling absorbs the freed space. When the shell exits naturally (`exit` or Ctrl-D), the tab — and possibly the pane — closes automatically (per `#0059`).

### Pane vs tab vs session — which to use when

- **Tab** when you want a parallel context inside the same view (e.g. one shell, one `vim`).
- **Pane** when you want side-by-side visibility (e.g. running tests in one half while editing in the other).
- **Session** when you want a fully separate workspace (e.g. a different project, distinct toolchain).
