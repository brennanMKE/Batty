## Description

#0491 added Project rows to Open Quickly: Return opens or focuses the Project, Option-Return opens another copy. It also decided that when a Tab row and a Project row match equally, the Tab row sorts first, because jumping to a live Tab has no side effects. The common tie is exactly a Project and its own Session: a Project-backed Session's title is pinned to the Project name, so typing the name scores the Session's Tab rows and the Project row identically, the Tab row is row 1, and ⌥↩ on it is a plain jump (`choose` ignores the Option modifier for Tab rows). To open another copy the user must press ↓ past every Tab row of that Session first; the UI tests do the same (`selectProjectRowInOpenQuickly` presses ↓ until the hint appears). #0491's Gotchas list two candidate fixes; this issue picks one.

Behind the Projects flag, like all of #0491.

## Current code (verified 2026-10-13 on `main` at `673c6530`)

- **Rows.** `QuickOpenResult` (`BattyKit/Sources/BattyKit/Views/OpenQuicklyView.swift:13-21`) is `(sessionID, sessionTitle, tabID, tabTitle)`; `allResults(for:)` (`:137-149`) builds one per Tab of every `.terminal` Pane in this Window from `session.title`. It carries no Project identity, although `SessionRuntime.projectID` exists (`Runtime/SessionRuntime.swift:47`, `public internal(set)`), set together with the pinned title by `WindowRuntime.addProjectSession` (`Runtime/WindowRuntime.swift:242`).
- **Ranking.** `OpenQuicklyFilter.apply(query:tabs:projects:)` (`:49-75`) sorts by score, then kind (`0` Tab, `1` Project name match, `2` Project path-only match), then input offset (`:68-72`). `FuzzyMatcher.score` (`Util/FuzzyMatcher.swift:24-32`) is 3 prefix / 2 interior / 1 scattered; an exact whole-name match is a prefix match and scores 3, the same as any other prefix. There is no exact tier.
- **Actions.** `OpenQuicklyFilter.choose(_:optionHeld:in:)` (`:115-124`): `.tab` jumps through `windowRuntime.jumpToTab` and returns nil whatever `optionHeld` is (`:117-120`); `.project` returns `.openProject(row.id, optionHeld ? .openNew : .focusExistingOrOpen)` (`:122`). The view's `activate` (`:320-325`) reads the Option modifier from the Return key press and passes it through.
- **Footer.** `open-quickly.hint` (`:294-297`) shows `project.hint` only for a selected Project row (`ProjectPickerModel.hint(name:isOpen:)`, `Model/ProjectPicker.swift:147-151`: "↩ Switch to the open <name> Session" / "↩ Open <name> in a new Session"); nothing is shown for a Tab row.
- **Flag gate.** `SessionDetailView` passes `projectRows:` and `onAction:` to `OpenQuicklyView` only when the flag is on (`Views/SessionDetailView.swift:91-98`); otherwise both are nil (`docs/feature-flags.md`, the #0491 row).
- **Tests.** `OpenQuicklyProjectRowsTests` (`BattyKit/Tests/BattyKitTests/OpenQuicklyProjectRowsTests.swift`): `tabRowsComeBeforeProjectRowsInTheSameTier` (`:117`), `aTabRowJumpsWithOrWithoutOptionAndReportsNoAction` (`:289`), `returnOnAProjectFocusesOrOpensAndOptionReturnOpensAnother` (`:266`). UI: `ProjectsHarness.selectProjectRowInOpenQuickly` (`BattyUITests/Support/ProjectsHarness.swift:281-290`) and `openThroughOpenQuickly(_:option:in:)` used by `ProjectsOpenTests.swift:138`. `docs/ui-features.md` "Fuzzy finders" documents the tie and the ↓ workaround.

## Expected behavior

**The two options from #0491, and the decision.**

- **Option A (chosen): ⌥↩ on a Tab row of a Project-backed Session acts as `.openProject(projectID, .openNew)`.** Ranking and Return are untouched: row 1 stays the no-side-effect Tab row, Return still jumps to that Tab, and the Project row keeps its place for Return-to-focus and Option-Return as today. Only the modifier that already means "another copy" gains a meaning on a row that already has a Project.
- **Option B (rejected): an exact, case-insensitive whole-name Project match outranks non-exact Tab matches.** It does not fix the case that motivates this issue: the Session title is pinned to the Project name, so the Tab row's match is also exact and the tie stands. It would also reverse #0491's reviewed tie-break for the rows it did reach and change what Return does, for no gain here.

**Option A, in detail:**

1. `QuickOpenResult` gains `projectID: UUID?`, filled from `session.projectID` in `allResults(for:)`. It is nil for every plain Session, and the property is set only by the flag-gated `addProjectSession`.
2. `choose(_:optionHeld:in:)` gains the gate it needs (for example a `projectsEnabled: Bool`, or it returns the action only when the host passed `onAction`): for `.tab` with `optionHeld`, a non-nil `projectID` and the flag on, it returns `.openProject(projectID, .openNew)` **without jumping**; every other `.tab` case jumps and returns nil as today. The host runs the value from the sheet's `onDismiss`, exactly as a Project row's action (#0491 §2; `docs/swiftui-observation-rules.md:179-186`).
3. **Footer.** With a Tab row of a Project-backed Session selected, show "⌥↩ Open another copy of <Project name>" under identifier **`open-quickly.tab-hint`**, distinct from `open-quickly.hint` so `selectProjectRowInOpenQuickly` still stops only on a Project row. Plain Tab rows show no footer, so the flag-off layout is byte-for-byte today's.
4. **Flag off:** `projectID` is never set, `onAction` is nil, no footer, and ⌥↩ on a Tab row is a plain jump (`FuzzyFinderTests` unchanged). No new gate site beyond the existing #0491 row; update that row's wording to mention the Tab-row action.

## Resolution notes

> 🟢 Resolved 2026-10-13. In Open Quickly, ⌥↩ on a Tab row of a Project-backed Session opens another copy of that Project, and plain ↩ still jumps to the Tab. While such a row is selected, a footer line reads "⌥↩ Open another copy of <Project>". It shows the saved Project's own name, looked up by `projectID`, and is absent if the Project was deleted.

Owed to the user:
- Visual check: the footer line on the real sheet, and that it doesn't clip on the 540-pt sheet.
- Help sentence for the flag-removal issue: "…or press Option-Return on one of its Session's Tabs."

## Root cause

A Project's own Session's Tab rows tie with its Project row and sort first (#0491). `choose` ignored Option for `.tab` rows. ⌥↩ on the row the user lands on was therefore a plain jump.

## Fix

- `QuickOpenResult.projectID` is filled from `session.projectID`.
- `choose(…, projectsEnabled:, in:)`: ⌥ on a Tab row with a `projectID` and the flag on returns `.openProject(id, .openNew)` without jumping. The action is routed through the existing `onDismiss` path.
  - `projectsEnabled` is a required parameter, and `activate` passes `onAction != nil`, which is set only with the flag on.
- The footer `open-quickly.tab-hint` uses `OpenQuicklyFilter.tabHintName(for:projects:)`. It looks up the unfiltered Project rows, because a Session can be renamed in the Sidebar and a renamed Project leaves open Sessions' titles pinned.
- Ranking is unchanged. With the flag off, nothing changes.
