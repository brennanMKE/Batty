## Description

When a tab's working directory is the user's home directory, the chip title should always display `~` — never a previously set custom name. A `titleOverride` set via the rename sheet currently takes precedence over the CWD, so a tab renamed while at `~` keeps that name even after navigating elsewhere and back.

## Expected behavior

If `tab.terminal.workingDirectory` is `NSHomeDirectory()` (or `"~"`), the chip title is always `"~"`, regardless of any `titleOverride`.

## Actual behavior

`TabTitleFormatter.chipTitle()` checks `titleOverride` before everything else. A tab renamed while at `~` retains its custom name even after the user navigates away and returns home.

## Root cause

`TabTitleFormatter.chipTitle()` checked `titleOverride` before the CWD, so a tab renamed while at `~` would retain that name permanently.

## Fix

Added a CWD-is-home guard at the top of `chipTitle(for:fallback:)`, before the `titleOverride` branch. If `tab.terminal.workingDirectory` equals `NSHomeDirectory()` or `"~"`, returns `"~"` immediately.

## Files changed

- `BattyKit/Sources/BattyKit/Util/TabTitleFormatter.swift`

## Fix hint

In `TabTitleFormatter.chipTitle()` (`Util/TabTitleFormatter.swift`), insert a CWD-is-home check before the `titleOverride` branch:

```swift
// Home directory always shows as "~" — no set name is retained there.
if let cwd = tab.terminal.workingDirectory {
    if cwd == NSHomeDirectory() || cwd == "~" { return "~" }
}
```

`prettifyPath()` already maps home to `"~"` correctly; this change just ensures the override path doesn't shadow it.
