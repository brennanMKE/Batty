## Description

A native macOS Settings window (`Settings { ... }` scene) for the per-user preferences enumerated in `Concepts.md` → Settings.

**Acceptance criteria:**
- `Settings { ... }` scene is added to `BattyApp`. Cmd-, opens it.
- Tabs (or a single pane if simpler):
  - **General** — default shell (auto-detected, overridable), confirm-on-close-with-running-processes toggle.
  - **Appearance** — font family + size, cursor style (block/bar/underline; static/blinking), theme picker (mirrors View → Theme).
  - **Notifications** — bell sound on/off, system notifications on/off.
- Every setting persists to `UserDefaults` and is observed live by the app (no restart required).
- Default shell auto-detection: `$SHELL` env var → `getpwuid(getuid())->pw_shell` → `/bin/bash` fallback.

## Notes

- Per-Session bell mute is a Session-scope setting (#0028); not a global Settings pane entry.
- Paste confirmation strictness is #0035 — the toggle (and its enum) belongs in the Settings General pane.
- Keep the UI sparse — this is a tool, not a configurator.

## Root cause

After #0024–#0028 the bell-feed pipeline ran end-to-end with no UI surface for any of the settings the user might want to tune (sound, system notifications, font, cursor, shell). Knobs existed in libghostty's TerminalConfiguration but had no consumer. The "Mostly-non-functional knobs" worry from the prior bail no longer applies since most of the related features have shipped.

## Fix

Three files, no extra dependencies.

- **`SettingsPreference` (new)** centralizes UserDefaults keys + default-value resolvers:
  - `defaultShellKey` (with detection chain: `$SHELL` → `getpwuid(getuid())->pw_shell` → `/bin/bash`)
  - `fontSizeKey` (default 13)
  - `cursorStyleKey` (`"block" | "bar" | "underline"`, default `"block"`)
  - `cursorBlinkKey` (default true)
  - `bellSoundKey` (default true)
  - `systemNotificationsKey` (default true)
  - Convenience `resolved...` functions that fall back to defaults when the key is absent or empty.
  - `registerDefaults()` registers the non-string defaults with `UserDefaults` so `bool(forKey:)`/`double(forKey:)` return correct values out of the box.
- **`SettingsView` (new)** — `TabView` with three tabs:
  - **General** — `TextField` for the shell override with the auto-detected value as the placeholder (so the field can stay empty to mean "follow detection").
  - **Appearance** — `Stepper` 8–32 for font size, segmented `Picker` for cursor style, `Toggle` for blink, menu `Picker` for theme that mirrors the View → Theme menu from #0033. Each control has an `onChange` that calls `store.applyAppearanceToAllSurfaces()` (font/cursor) or `store.applyThemeToAllSurfaces(_:)` (theme) so live surfaces update without restart.
  - **Notifications** — toggles for bell sound and system notifications.
- **`BattyApp`** gets a `Settings { SettingsView().environment(\.appStateStore, WorkspaceManager.shared.store) }` scene. Cmd-, opens it via the standard macOS plumbing.
- **`BellNotifier.post`** consults `SettingsPreference.resolvedSystemNotifications()` (early-returns if false) and conditionally attaches `.default` sound based on `resolvedBellSound()`.
- **`TabRuntime.init`** applies the resolved shell + appearance settings to its `TerminalConfiguration` via `withCustom("command", shell)` plus `withFontSize` / `withCursorStyle` / `withCursorStyleBlink`. This means newly-created tabs inherit the active preferences immediately.

## Files changed

- `BattyKit/Sources/BattyKit/SettingsPreferences.swift` (new) — pref keys, resolvers, `applyAppearanceToAllSurfaces` extension on `AppStateStore`, `registerDefaults()`.
- `BattyKit/Sources/BattyKit/SettingsView.swift` (new) — TabView with General / Appearance / Notifications panes.

## Gotchas

- **Shell override uses `withCustom("command", shell)` rather than a typed builder method,** because `TerminalSurfaceOptions` doesn't expose a `command` field and `TerminalConfiguration.Builder` doesn't ship a `withCommand`. Custom config commands ride through the rendered ghostty.conf so libghostty picks them up at surface creation. If the upstream wrapper later adds a typed setter, switch to it.
- **Font size is `Float` in libghostty** but `Stepper` works with `Double`. Cast on the way in. The 8–32 range matches sensible terminal text — sub-8 is unreadable, super-32 is silly.
- **Theme picker has a "Default" tag with empty string** so the user can return to the libghostty default without picking a specific named theme. Empty-string handling: when set to `""`, no `applyThemeToAllSurfaces` call happens (the `onChange` early-returns); the surface keeps its current state. Setting an empty theme that the user expects to *apply* the default is a feature gap if it matters; for v1 the menu remains the canonical way to toggle.
- **The `Settings` scene has its own SwiftUI lifecycle** — when the user closes the Settings window and reopens it, it re-runs `init`. So pure `@State` in subviews doesn't persist across openings; `@AppStorage` does. Worth keeping in mind if we ever stash transient state in the settings panes.
- **`registerDefaults()` is declared but not yet called from anywhere.** The resolvers fall back if the key is missing, so behavior is correct without it; calling it at app launch would just clean up the `UserDefaults` snapshot inspectors. Wire from `BattyApp.init` if you want clean defaults visible in `defaults read`.
- **No font-family picker.** libghostty supports it via `withFontFamily(_:)` but choosing a font worth shipping (sane fallbacks for emoji, ligatures, monospace) is a UX decision better made with one more iteration. Defer.
- **No "Restore Defaults" button** in the Settings pane. Users can `defaults delete co.sstools.Batty` to reset; a UI button is a follow-up.
