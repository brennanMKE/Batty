## Description

A native macOS Settings window (`Settings { ... }` scene) for the per-user preferences enumerated in `Concepts.md` → Settings.

**Acceptance criteria:**
- `Settings { ... }` scene is added to `BattyApp`. Cmd-, opens it.
- Tabs (or a single pane if simpler):
  - **General** — default shell (auto-detected, overridable), confirm-on-close-with-running-processes toggle.
  - **Appearance** — font family + size, cursor style (block/bar/underline; static/blinking), theme picker (mirrors View → Theme).
  - **Notifications** — bell sound on/off, system notifications on/off.
- Every setting persists to `UserDefaults` and is observed live by the app (no restart required).
- Default shell auto-detection: `$SHELL` env var → `getpwuid(getuid())->pw_shell` → `/bin/bash` fallback.

## Notes

- Per-Session bell mute is a Session-scope setting (#0028); not a global Settings pane entry.
- Paste confirmation strictness is #0035 — the toggle (and its enum) belongs in the Settings General pane.
- Keep the UI sparse — this is a tool, not a configurator.

### Deferred — 2026-05-08

Most of the planned settings depend on features that are themselves blocked or deferred:

| Setting | Blocked on | Notes |
|---|---|---|
| Confirm on close with running processes | `#0036` (delegate plumbing for `processAlive` / command-running signal) | Toggle would persist a value with no consumer until #0036 lands |
| Bell sound + system notifications | `#0024` (bell hook), `#0028` (notification posting) | Toggles persist but no events flow yet |
| Paste confirmation strictness | `#0035` (paste interception blocked) | Same blocker family |
| Font family + size | Available via `TerminalConfiguration.withFontSize(_:)` and similar; needs an "apply to every live `TerminalViewState`" walker analogous to `applyThemeToAllSurfaces` | Doable; would also need to thread the active config into newly-created `TabRuntime`s |
| Cursor style | Same as font | Doable |
| Default shell | `UserDefaults`-backed string + auto-detect via `$SHELL`/`getpwuid()` | Doable |
| Theme | Already shipped via `#0033`'s menu; could mirror in Settings | Not a blocker, just duplication |

Building the Settings UI now would land mostly-non-functional knobs — toggles that persist but don't drive anything. Deferring until the blocked downstream features land, then ship the whole pane in one focused commit.

In the meantime, persistent preferences ship as needed via `@AppStorage` directly (sidebar collapse via `SidebarPreference.hiddenKey`, theme via `ThemePreference.defaultsKey`) without a UI surface.

### What's left

When `#0024` / `#0028` / `#0035` / `#0036` clear the delegate-plumbing blocker:

1. Build `Batty/SettingsView.swift` (or in BattyKit) with a `Settings { TabView { ... } }` scene attached to `BattyApp`.
2. General pane: default shell (auto-detected), confirm-on-close toggle, paste-strictness picker.
3. Appearance pane: font family + size pickers (`NSFontPanel` integration), cursor style picker, theme picker (mirroring `#0033`'s menu).
4. Notifications pane: bell sound toggle, system notifications toggle.
5. Bind every toggle/picker to `@AppStorage` keys; provide an `applyAppearanceToAllSurfaces(_:)` extension on `AppStateStore` analogous to `applyThemeToAllSurfaces`.
6. Auto-apply on settings change. New tabs read the active values from `UserDefaults` during creation.
