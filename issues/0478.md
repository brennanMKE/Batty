## Description

Projects (#0469) adds four new surfaces (the Project Editor, the Open Project picker, the trust sheet, the Sidebar glyph), new menu, palette and CLI entry points, and a feature flag whose "off" state must be invisible. Unit tests in #0470–#0477 cover the models and gate functions. This issue adds the `BattyUITests` coverage that only a running app can give, including a **flag-off inertness** run, and runs the full suite in the Tart VM before Projects is called done.

## Expected behavior

**Runs only in the Tart VM** (`AGENTS.md` "UI test automation (binding)", `docs/ui-testing-vm.md`). Never run `xcodebuild … test`, `scripts/run-ui-tests.sh` or `osascript` UI scripting on the host. Commit first, because the runner tests `git archive HEAD`. The standing authorization in `AGENTS.md` covers `tools/run-ui-tests-vm.sh` / `./build.sh ui`. Only one VM runs at a time.

**New UI test class(es)** (for example `BattyUITests/ProjectsTests.swift`). Drive setup through `UITestDriver` intents where the UI path isn't the subject: seed Projects and open by name (#0472). Use real UI where it is the subject. Identify elements by the accessibility identifiers documented in `docs/ui-features.md` by #0474–#0476.

1. **Open from the picker.** Seed two Projects (one `mainTopTwoBottom` with Terminal, Git Status and Terminal; one 2-Pane). Choose Project… from the File menu, type a filter, and press Return. Assert:
   - a new Session titled with the Project name;
   - the Sidebar row's project glyph;
   - the Pane count and kinds, via the existing tree dump that `LayoutTests` uses;
   - each Terminal Tab's title.
2. **Find vs. another copy.** Open the same Project again with Return: no new Session, and the existing one is selected. Open with Option-Return: a second Session.
3. **OPEN badge and menu check mark.** After (1), the picker card shows OPEN and the File ▸ Open Project › item is checked.
4. **Startup commands and trust.** Seed a Project with a Tab whose command writes a marker file (for example `touch <tmp>/ran-<id>`) and with the run toggle on. Open it: the trust sheet appears and lists the command. Choose **Open Without Running**: the Session opens and no marker appears. Close the Session, open again, check "Don't ask again", and choose **Run Commands**: the marker appears, and the Tab is still alive at a prompt afterwards. Open a third time: no sheet. Edit the command in the editor and open again: the sheet is back. **Waiting on the marker must be event-driven, not a sleep.** Use XCTest expectations (`XCTNSPredicateExpectation`/`waitForExistence`) with a timeout as a failure guard only. The marker can be a file the test watches, or terminal output asserted through an accessibility value if one exists.
5. **Project Editor.** Edit Projects… opens the editor. Create a Project (name, root via the driver or a fixture directory, the 2×2 layout, Git Status in slot 2, a second Tab in slot 1 with a working directory) and **Save & Open**. Assert the resulting Session. Re-open the editor and **Cancel** an edit, then confirm the stored Project is unchanged by opening it again.
6. **Save Session as Project.** Build a Session by hand (split, add a Tab, rename it, add a System Metrics Pane). Sidebar context menu ▸ Save as Project… opens the editor with that topology. Save, close the Session, open the Project, and assert the same shape with equal sizing.
7. **Command Palette.** "Open Project: <name>" opens the Project. "Save Session as Project…" opens the editor.
8. **CLI**, if the existing CLI UI-test harness can run the guest's `batty-beta` (`CLIViewPaneTests`, `CLIRemoteControlTests` precedent). `batty-beta project list` lists the seeded Projects with the open marker, and `batty-beta project open <name>` opens one.
9. **Flag-off inertness.** Launch with #0470's UI-test override forcing the flag **off**. Assert:
   - the File menu has no Open Project, Save Session as Project… or Edit Projects… items;
   - the Sidebar context menu has no Save as Project…;
   - the Command Palette has no "Open Project" or "Save Session as Project…" results;
   - the Window menu lists no Project Editor;
   - no `projects.json` exists in the guest's `~/Library/Application Support/Batty Beta/` after the run (use a fresh guest-side path, or the test's isolated Application Support if the harness provides one).
   - CLI absence in Prod is compile-time and the VM runs the Beta build, so the CLI half of inertness is covered by #0477's unit tests, not here. Say so in the resolution.

**Full suite.** After the new tests pass, run the **entire** `BattyUITests` suite in the VM (`./build.sh ui`) on the branch head. Projects touches the Sidebar row, the File menu and the Command Palette, and the existing `SidebarTests`, `FuzzyFinderTests`, `KeyboardShortcutTests`, `LayoutTests` and `MultiWindowTests` must stay green. Any regression gets its own issue (`AGENTS.md` test strategy).

## Acceptance criteria

- `docs/ui-features.md` lists every Projects accessibility identifier the tests rely on.
- `./build.sh unit` still passes.

## Root cause

Starting state: #0470–#0477 were unit-tested only; their real-window behavior (surfaces, sheets, menus, palette, CLI against a live app) had no automated coverage.

## Fix

- Test-only seam: `UITestDriver.projectsFileOverride()` reads `BATTY_UI_TEST_PROJECTS_FILE` only when `BATTY_UI_TEST_SCRIPT` is set and the path is absolute (the same gate as the flag's force-off override); `AppStateStore.init` defaults `projectsFileURL` to it, so every UI test gets its own `projects.json` and the guest's real store is never touched. Inert in production; unit-tested in `UITestProjectsFileOverrideTests`.
- Harness: `BattyUITests/Support/ProjectsHarness.swift` (`ProjectsUITestCase`, `ProjectFixture`, menu / picker / palette helpers including the shared `paletteRows(containing:in:)` predicate, `closeMenus(levels:)`, pixel helpers); `launchBatty(extraEnvironment:)` and `waitForTopology(includeDimensions:)` with defaults that leave existing tests unchanged.
- Tests:
  - `ProjectsOpenTests` — picker opens a Project with glyph, layout, Pane kinds, Tab titles and Git Status; Return focuses vs Option-Return opens another; OPEN badge and File ▸ Open Project check mark; palette "Open Project: <name>"; palette "Open Project…" by click and by Return (expected failures, #0483).
  - `ProjectsStartupTests` — trust sheet gates commands: Open Without Running runs nothing and stores no approval; Run Commands with remember runs (marker file), keeps the Tab alive, stores the hash; a third open runs without a sheet; editing the command brings the sheet back.
  - `ProjectsEditorTests` — Edit Projects… opens the editor (and its Window-menu entry); building a 2×2 Project with Git Status and a second Tab's working directory, then Save & Open; Cancel leaves the stored Project unchanged; Sidebar Save as Project round-trips a resized Session to equal sizes; palette Save Session as Project opens the editor.
  - `ProjectsCLITests` — `project list` JSON and table with the open marker, `open` → Opened then Focused, `--new --json`, unknown name exits non-zero.
  - `ProjectsFlagOffTests` — with `BATTY_UI_TEST_FORCE_PROJECTS_OFF=1`: no File, Window, Sidebar or palette entry points (each absence paired with a positive control), stored bytes unchanged, no `projects.json` / `.bak` created; a flag-on control proves the palette predicate does see Project rows.
- `docs/ui-features.md` "Projects UI tests (#0478)": identifiers relied on, the identifiers Accessibility doesn't honor (#0484), the coverage map and remaining manual checks.

## Gotchas

- Pixel checks (Sidebar Project glyph, File-menu check mark) are the least robust assertions; #0484 replaces them with accessibility values/identifiers. #0482 changes the Sidebar glyph, which also affects the glyph pixel check.
- The two #0483 tests are strict expected failures: they fail once the bug is fixed until the `XCTExpectFailure` wrapper is removed.
- `paletteRows` queries `app.staticTexts` app-wide; scoping to the palette container would make the flag-on control self-evidently about palette rows.
- `list --json` reports non-terminal Panes with 0 Tabs and frames only for terminal Panes, so equal-size checks cover terminal Panes.
- The UI-test runner is sandboxed and can't see the guest's real Application Support, so flag-off file absence is asserted at the override path.
- Subagent transcripts in this harness record stream-start `output_tokens`, so Work log output counts and costs are understated.
