# 0264 — No way to adjust the font size of an individual Pane

| | |
|---|---|
| **Status** | open |
| **Module** | Pane / App |
| **Platform** | macOS |
| **First seen** | 2026-07-24 |

## Description

Font size in Batty is a single global preference — the Settings → Appearance slider (`SettingsPreference.fontSizeKey`, default 13pt) applies one size to every Terminal Session in every Pane. There is no way to make one Pane's text larger or smaller than the rest, which is a common need in a multiplexer: a log-tailing Pane can shrink to fit more lines while the Pane being actively worked in stays readable. The user's request, verbatim:

> "In an individual pane it would be useful to adjust the font size. This should be supported by a hotkey which can also be in the Pane menu."

Requested: per-Pane font size adjustment — increase, decrease, and reset to the default — driven by the standard macOS hotkeys and matching entries in the existing Pane menu.

## Current behavior

- Font size is app-wide only. `SettingsPreference.resolvedFontSize()` feeds `builder.withFontSize(...)` in a `TerminalConfiguration`, applied per surface at Terminal Session creation (`TabRuntime.applyShellAndAppearancePreferences`) and re-applied to every surface in every window when Settings change (`AppStateStore.applyAppearanceToAllSurfaces()`).
- No hotkey or menu item touches font size; the only control is the Settings slider.
- libghostty's own default `cmd+=` / `cmd+-` font-size keybinds are inactive in Batty: `TabRuntime` issues `keybind clear` when configuring each surface (deliberately, so Cmd chords fall through to Batty's own dispatch), so nothing reaches the surface's built-in bindings.

## Expected behavior

- With a Pane focused:
  - **Cmd-Plus** (`cmd+=`) increases the focused Pane's font size.
  - **Cmd-Minus** (`cmd+-`) decreases it.
  - **Cmd-0** resets it to the default (the Settings font size).
- The change is scoped to the focused Pane only — all of that Pane's Tabs (each Tab owns one Terminal Session) render at the adjusted size; every other Pane is untouched.
- Matching menu items (Increase Font Size / Decrease Font Size / Reset Font Size) appear in the existing **Pane** menu, alongside the split and focus-movement commands.
- The shortcuts should be new `ShortcutAction` cases so they show up in Settings → Shortcuts and the Command Palette automatically (both enumerate `ShortcutAction.allCases`).

## Notes

Mechanism — verified against the codebase, not guessed:

- **Per-surface font-size control exists in libghostty via keybind actions.** `ghostty_surface_binding_action(ghostty_surface_t, const char*, uintptr_t)` (declared in the xcframework's `ghostty.h`) executes a named keybind action against one surface. The `libghostty-spm` fork wraps it as the **public** `AppTerminalView.performBindingAction(_ action: String) -> Bool` (`Sources/GhosttyTerminal/Platform/AppKit/AppTerminalView+PublicInput.swift`), and the fork's own UIKit pinch-zoom handler calls `performBindingAction("increase_font_size:1")` / `performBindingAction("decrease_font_size:1")` (`UITerminalView+PinchZoom.swift`) — so those two action strings are proven working against this exact fork. `reset_font_size` is the documented Ghostty action name for reset but is **not** exercised anywhere in the fork's Swift sources; `performBindingAction` returns `Bool`, so the implementer should confirm it returns `true` (and visibly resets) rather than assuming.
- **Getting from a Pane to its surfaces:** the focused Pane is `keyWindow.selectedSession?.focusedPane` (`PaneRuntime`), whose `tabs: [TabRuntime]` each own one Terminal Session. The live `AppTerminalView` per Tab is vended by `TerminalHostStore.shared` (keyed by `TabRuntime.id`, `BattyKit/Sources/BattyKit/Runtime/TerminalHostStore.swift`). "Per-Pane" therefore means looping the Pane's tabs and applying the action to each tab's terminal view — and deciding what a Tab created in that Pane *later* (Cmd-T) starts at (see open questions).
- **Hotkey path:** shortcuts dispatch through the `NSEvent` local monitor `BattyShortcuts.handle` → `run(_:appStore:)` (`BattyKit/Sources/BattyKit/Commands/BattyShortcuts.swift`), with actions declared in `BattyKit/Sources/BattyKit/Shortcuts/ShortcutAction.swift` (follow the #0262 pattern: new cases + default `ShortcutBinding`s + `run` dispatch + `CommandPaletteView.dispatch` wiring). `Cmd-0` is free — the positional Cmd-digit handling in `BattyShortcuts.handle` only accepts `1...9`. `Cmd-=` and `Cmd--` are unbound today. Note the macOS convention: "Cmd-Plus" is physically `cmd+=` (no shift required); menu items conventionally display it as Cmd-+.
- **Menu:** the Pane menu is `CommandMenu("Pane")` in `BattyKit/Sources/BattyKit/Commands/BattyCommands.swift` (around line 196). Add the three items there with `shortcuts.keyboardShortcut(for:)` like the neighboring split entries, disabled when no Pane is focused.
- **Interaction gotcha — global appearance re-apply clobbers per-surface state.** `AppStateStore.applyAppearanceToAllSurfaces()` (in `BattyKit/Sources/BattyKit/Settings/SettingsPreferences.swift`) pushes a fresh `TerminalConfiguration` with the global `withFontSize(...)` to *every* surface whenever appearance settings change, and `setTerminalConfiguration` triggers a config reload on the surface. Any binding-action-based per-pane adjustment will likely be reset by that reload. The implementer must decide how a per-pane delta survives (or is deliberately reset by) a Settings change, and verify what a config reload actually does to a runtime font-size change on this fork.

Open questions (decide during implementation, or split follow-ups):

- **Persistence.** Should a Pane's adjusted font size survive quit/relaunch? The `Pane` layout model (`BattyKit/Sources/BattyKit/Model/LayoutModel.swift`) is a pure Codable/Sendable value type serialized into the Workspace — adding an optional `fontSize`/`fontSizeDelta` field is a persistence-format change (old `workspace.json` files must still decode). If v1 keeps the adjustment session-only, say so in the resolution.
- **Inheritance.** Does a new Tab in an adjusted Pane (Cmd-T) get the Pane's adjusted size or the config default? Does a Pane split off an adjusted Pane (Cmd-D) inherit? Consistency with cwd inheritance (`Concepts.md`) suggests inheriting, but either answer is defensible if documented.
- **Reset target.** `reset_font_size` presumably returns to the surface's *configured* size — which is the global Settings value Batty pushed via `withFontSize`. Confirm Cmd-0 lands on the Settings size, not libghostty's own 13pt fallback.
- **Semantics: delta vs. absolute.** Binding actions step the surface's runtime size (`increase_font_size:1`); if per-Pane state is persisted or re-applied after config reloads, Batty needs its own notion of the Pane's current size (delta from default, or absolute points) rather than relying on surface-internal state it can't read back.
