## Description

The Project Editor's bottom bar has three buttons in a row: Cancel, Save and Save & Open. A settings toggle sits on the same bar, and Escape does nothing. This doesn't feel like a Mac app's Settings or dialog windows. The rest of Batty's sheets and dialogs each lay out their buttons differently: some have Cancel and a default button, some only a keyboard-hint caption, one puts the default button left of its Back button, and one has no way to cancel. The user's request (2026-11-18): "improve the projects buttons. It shows multiple options at the bottom and they don't quite match how Apple does Settings on macOS. We should make this better across all pop up screens."

This is UI work. Visual sign-off is the user's, so the review resolves it and the user closes it.

### The Project Editor today (checked against `main`)

`ProjectEditorWindowController` opens a standalone `NSWindow` titled "Projects" (`Views/ProjectEditorWindowController.swift:79-82`), not a sheet. It has a Projects list on the left and the selected Project's form on the right. `ProjectEditorFooter` (`Views/ProjectEditorView.swift:1117-1159`) is one bar across the form:

| Position | Control | Role / shortcut |
|---|---|---|
| leading | Toggle "Run startup commands when the Project opens", plus a caption hint when commands are off | a Project setting, not an action |
| middle | the save error text, red, when a save failed | |
| trailing 1 | **Cancel**: `model.cancel()` reloads the stored Project and **closes the window** (`Model/ProjectEditorViewModel.swift:988-996`) | no `.cancelAction`, so Escape does nothing |
| trailing 2 | **Save**: saves and keeps the window open | no shortcut |
| trailing 3 | **Save & Open**: saves, closes, opens with `.focusExistingOrOpen` (`:980-985`; `ProjectEditorWindowController.swift:56-59`) | `.defaultAction` (Return) |

The window has more action buttons elsewhere. The list column ends in a large **New Project…** button (`ProjectEditorView.swift:296-306`, `.controlSize(.large)`), and an empty form shows its own **New Project…** (`:236-249`). Delete is only in the list row's context menu and on the Delete key (`:282-293`). The window's close button already runs the unsaved-changes prompt (`windowShouldClose`, `ProjectEditorWindowController.swift:131-135`; dialog at `ProjectEditorView.swift:147-158`: Save, Discard Changes (destructive), Cancel). So Cancel duplicates the close button, and Save & Open does the same as Save for a Project that is already open, because it then only focuses the existing Session.

What's off against macOS conventions:

- Three peer buttons on the trailing edge, two of them Save variants. Apple's dialogs have one default button and at most one alternative beside Cancel.
- Cancel has no Escape key equivalent.
- Cancel closes a non-modal window. A Mac app's window closes with its close button or Cmd-W, and a form's Cancel belongs to a sheet.
- A Project setting (the run-startup-commands toggle) sits in the action bar. It belongs in the form, near the Tabs and commands it controls.
- The window looks like a Settings-style list-and-detail window, but it saves explicitly. A macOS Settings window applies changes as they're made and has no OK, Apply or Save buttons. The fix has to pick one model on purpose (see Target convention).

## Root cause

Feature work, not a defect. Each sheet built its own `HStack` of buttons, so order, shortcuts, spacing and size drifted: Paste, Rename Tab and Rename Session bound Cancel to `.escape` instead of `.cancelAction`, the Reminder bar's date step put Set left of Back, the trust sheet had no Cancel and bound Return to Run Commands, and Settings ▸ Clear Capture swapped buttons inline. The Project Editor footer carried three actions (Cancel, Save, Save & Open) and a settings toggle, with no Escape or Cmd-S handling.

## Fix

Followed the plan's four steps and its decisions 1 to 11.

- **`DialogButtonRow`** (new, `Views/DialogButtonRow.swift`): `DialogButton`, the pure `DialogButtonRowLayout.placements` (alternative, Cancel, confirm; Cancel on `.cancelAction`; confirm on `.defaultAction` unless `confirmIsDefault: false`), and the generic row view with `.inline` and `.bar` styles.
- **Project Editor** (explicit save): footer is Open (leading), save error, then Revert and Save (default, plus Cmd-S through a hidden zero-size button). `ProjectEditorViewModel` lost `saveAndOpen()`, `canSaveAndOpen` and `cancel()` and gained `revert()`, `canRevert`, `openSelected()` and `canOpen`. The run-startup-commands toggle moved to a new `ProjectStartupCommandsRow` under the Background row. New Project… is regular size.
- **Trust sheet**: Open Without Running, Cancel (Escape, `cancelStartupTrust`), Run Commands with no default button; the caption moved above the row.
- **Other sheets**: Paste, Rename Tab, Rename Session, Background, Project Theme, Symbol picker, Background Images (Cancel only, pick on click kept) and the Reminder bar's date step (Back, Set) build their rows with `DialogButtonRow`. Settings ▸ Clear Capture is a `.confirmationDialog`.
- **UI tests and docs** updated as the plan lists.

Divergences from the plan:

- `DialogButtonRow`'s spacer is `Spacer(minLength: 0)`, and the Background Images leading content is an inner `HStack` with `.layoutPriority(1)` holding the buttons, its own spacer and the total. A plain `Spacer` at the end of `leading` would have shared the free width with the row's spacer and left the total in the middle of the bar.
- `DialogButton.cancel` carries `role: .cancel`, as the Paste and Rename sheets' Cancel buttons already did.
- Clear Capture and its dialog's Delete got identifiers (`settings.bellCapture.clear`, `settings.bellCapture.confirm-clear`); the plan named none.
- The Reminder picker bar's horizontal padding goes from 16 to 20 (the `.bar` style).

## Target convention

A short rule set. It should become **one shared SwiftUI button-row component or modifier in `BattyKit/Sources/BattyKit/Views/`** so every sheet gets it by construction. No such component exists today: nothing under `BattyKit/Sources` is named `DialogButton`, `ButtonRow` or `SheetFooter`.

1. **Trailing pair.** The default (Return) button is rightmost. Cancel (Escape) is immediately to its left. At most one more alternative goes left of Cancel.
2. **Shortcuts.** The default button uses `.keyboardShortcut(.defaultAction)` and Cancel uses `.keyboardShortcut(.cancelAction)`, not `.escape`. Every sheet that can be abandoned has a Cancel.
3. **Safe default.** When the main action does harm or runs something (destructive, or runs commands), Return isn't bound to it, or a confirmation dialog stands in front of it.
4. **Leading edge** holds secondary actions that don't close the sheet (Add from File…, Remove…, Restore Defaults). Destructive actions there are set apart from the trailing pair.
5. **No redundant buttons.** One Save-type action. A non-modal window closes through its close button or Cmd-W, not a Cancel button.
6. **No settings in the action row.** Toggles and fields belong in the form.
7. **Settings-model windows apply live**, with no OK / Apply / Save. Explicit-save windows say so in a standard way. The Project Editor has to choose one:
   - (a) **Live-save**, like System Settings. Each field writes as it changes, and the footer goes away. This needs a decision on validation errors, the startup-command trust hash (re-approval on every keystroke-level edit), and the "written only on explicit user action" rule in `Concepts.md`, Project → Storage.
   - (b) **Explicit-save**, like a document. The footer is reduced to Revert (or nothing) plus one **Save** default button, with Cmd-S. Open stays in the Open Project picker or moves to a separate menu item or toolbar control, and the close button keeps the unsaved-changes prompt.
   
   The plan phase picks one and records why.
8. **Keyboard pickers** (Layout, Theme, color, Open Project, Open Quickly, Command Palette) keep hint captions instead of buttons, but put them in one place and one style. The Session color picker either becomes a picker like the others or gets Cancel / **Set** buttons.
9. **Consistent sizing.** Regular control size for dialog buttons, the same spacing and padding in every sheet, and no `.large` action buttons in a dialog footer.

### Decisions

1. **Save model: explicit save (rule 7b), one Save button, Return and Cmd-S.** Not live-save. Reasons:
   - `Concepts.md` (Project → Storage) says a Project is written only on explicit user action. Explicit save keeps that rule; live-save would rewrite it.
   - The store refuses invalid Projects (empty or duplicate name, missing root). A half-typed name can't be written, so live-save would need a second "pending invalid edit" state, which is a draft by another name.
   - A new Project and a handed-in draft (Save as Project, Update Project) don't exist in the store until saved. Live-save has no answer for them short of writing an "Untitled" Project the user never asked for.
   - #0653 will push each save into open Sessions, and its expected behavior 4 is "closing the editor without saving changes nothing in the open Session". That needs a save boundary.
   - A Shared Project's save goes to iCloud (`ProjectSyncError` path in `save()`); per-keystroke writes there are wrong.
   - The unsaved-changes prompt, the Quit path and the draft hand-in are acceptance criteria and are all built on the draft.
   
   The window keeps its "Projects" title and close-button prompt. Batty's Settings window stays live-apply; the Project Editor is a document-style editor, and the footer now says so with a single Save.
2. **Footer.** Leading: **Open**, then the save error text. Trailing: **Revert**, **Save**. No Cancel. Escape does nothing in the window itself (it still cancels a sheet over it). Return and Cmd-S save.
   - **Revert** replaces Cancel's "throw away my edits" half without closing: it reloads the stored Project. Enabled when the draft is dirty and the Project exists in the store. An unsaved new Project is discarded as today, by Delete on its row or by closing and choosing Discard Changes. No shortcut, so Escape can't lose edits.
   - Closing is the close button or Cmd-W, with the existing prompt.
3. **Save & Open is replaced by a separate Open button on the leading edge** (`project-editor.open`). It is enabled only when the Project is stored and has no unsaved changes, calls the existing `openProject` seam (`.focusExistingOrOpen`, through the trust check), and leaves the editor open; the content window comes forward (#0485). Reason: create-then-open is the first-run flow and should stay two clicks (Save, Open), but it must not be a second Save variant. Dropping it entirely would send the user to File ▸ Open Project for the Project they just made.
4. **The run-startup-commands toggle moves into the form** as a new row under the Background row, in the same label-plus-control style as the Theme and Background rows: label "Startup commands", checkbox "Run when the Project opens", and the existing off-hint caption. Identifiers `project-editor.run-commands` and `project-editor.commands-off-hint` are kept. It is not put in the Pane inspector because it is one setting for the whole Project. ### `DialogButtonRow` shape

One file, three small types. All internal to BattyKit.

- `struct DialogButton`: `title: LocalizedStringKey`, `identifier: String?`, `role: ButtonRole?`, `isEnabled: Bool` (default true), `action: () -> Void`. A static `cancel(identifier:action:)` gives every sheet the same "Cancel" title; a caller that needs another word (the Reminder bar's "Back") builds the value itself.
- `enum DialogButtonRowLayout` (pure, the unit-tested part): `static func placements(hasAlternative: Bool, hasCancel: Bool, hasConfirm: Bool, confirmIsDefault: Bool) -> [Placement]`, where `Placement` is `Equatable` with `slot: .alternative | .cancel | .confirm` and `key: .none | .cancelAction | .defaultAction`. Rules: order is always alternative, cancel, confirm; cancel always carries `.cancelAction`; confirm carries `.defaultAction` only when `confirmIsDefault`; alternative never carries a shortcut; absent slots are skipped.
- `struct DialogButtonRow<Leading: View>: View`: `init(confirm: DialogButton?, cancel: DialogButton?, alternative: DialogButton? = nil, confirmIsDefault: Bool = true, style: Style = .inline, @ViewBuilder leading: () -> Leading)`, with an overload for no leading content. Body: `HStack(spacing: 12) { leading; Spacer(); <buttons in placements order> }`, `.controlSize(.regular)`. `Style.inline` adds no padding (the row sits in a sheet that pads its content by 20). `Style.bar` adds `.padding(.horizontal, 20).padding(.vertical, 12)` for a row that is its own bar under a `Divider` (Project Editor, Project Theme, Background Images, Reminder picker).

The view reads no observed state of its own and writes none; every action is the caller's button action. `docs/swiftui-observation-rules.md` is not engaged: no write moves out of an event handler anywhere in this plan (the trust sheet's Cancel calls the store from a button, the Clear Capture dialog writes from its button).

### User checklist

1. Projects… window: the footer shows Open on the left and Revert, Save on the right. No Cancel, no Save & Open, no toggle in the bar.
2. Edit a field: Save and Revert enable, Open disables. Return saves. Cmd-S saves. Escape does nothing. Revert restores the stored values and the window stays.
3. After a save, Open brings the Session forward (or opens it) and the Projects window stays open behind it. Check this feels right; the old Save & Open closed the window.
4. "Startup commands: Run when the Project opens" sits under the Background row, with its hint when off.
5. Close the window with unsaved edits: Save / Discard Changes / Cancel still appears. Same on switching Projects and on Quit.
6. Open a Project with new startup commands: the sheet shows Open Without Running, Cancel, Run Commands. Return does nothing, Escape cancels the open, and no button is highlighted as default. Check that losing Return-to-run is acceptable.
7. Quick Reminder bar, Pick Date and Time: Back then Set, Set rightmost and highlighted.
8. Paste, Rename Tab, Rename Session, Background, Project Theme, Symbol and Background Images sheets: same button spacing and size, Escape cancels each.
9. Settings ▸ Advanced ▸ Clear Capture asks in a dialog.
10. New Project… under the list is a regular-size button.
