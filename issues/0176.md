## Description

UI test `BattyUITests.DragDropTests.testSwapFocusedPanePreservesFocus` (`BattyUITests/DragDropTests.swift:132`) fails with:

```
XCTAssertTrue failed - Exactly one pane should be focused after swap
```

This test was created by [[0159]] as part of the UI test automation suite. The test was previously masked by the `Thread.sleep` runloop-blocking bug fixed in [[0170]] — the failure is now visible on every test run.

## What to investigate

Open `BattyUITests/DragDropTests.swift:132` and trace what state the assertion is checking. Cross-reference [[0159]] for the test's design and acceptance criteria.

The failure is one of:

- **App bug** — the behavior the test asserts on is genuinely broken; fix the app.
- **Test bug** — the test's assertion, setup, or accessibility-identifier expectation is wrong; fix the test.
- **Test infra gap** — a required driver intent or accessibility identifier referenced by the test doesn't exist yet; add it.

Look at the lines around `:132` and at the driver script (if any) in the test's launch call to determine which.

## Root cause

`TerminalPlaceholderView` is rooted on `Color.clear`. The
`.accessibilityValue("focused"/"unfocused")` modifier set on it never
propagated to the accessibility tree — `XCUIElement.value` came back
empty (Optional()) in every UI test that tried to read pane focus
state. The `.accessibilityIdentifier` did propagate (via the geometry
tracking modifiers) but value did not, on this macOS SDK.

Latent since `#0141` removed the enclosing `GeometryReader` (which was
acting as an implicit accessibility container) when switching to
`onGeometryChange`. Masked first by `#0170`'s `Thread.sleep` runloop
block, then by the UI-test-runner kill problem until
`scripts/run-ui-tests.sh` (`#0205`-era) unblocked tests.

## Fix

Resolved by code commit `a33de29`. Three pieces:

1. `TerminalPlaceholderView`: declare the placeholder as an explicit
   `.accessibilityElement()` and move the focus-state string from
   `.accessibilityValue` to `.accessibilityLabel`. Label propagates;
   value did not.
2. `DragDropTests` `focusedIndex`/`focusedCount` helpers: read
   `.label` instead of `.value`.
3. `PaneFocusTests` `focusedIndex` helper: same change.

Verified locally with `scripts/run-ui-tests.sh
BattyUITests/DragDropTests/testSwapFocusedPanePreservesFocus
BattyUITests/PaneFocusTests` — all 9 affected tests pass (1 DragDrop
+ 8 PaneFocus) in ~40s.
