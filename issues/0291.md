## Description

Every other child of the #0285 umbrella claims a memory improvement that currently cannot be verified except by hand-running `footprint` / `vmmap` one-liners and eyeballing the output. The umbrella's acceptance criteria require a measured before/after on `phys_footprint`, so a small developer-side sampling harness is needed:

- **Resolve the pid.** Note: `pgrep Batty` returns nothing on the reporting machine; match the full binary path instead: `ps -Ao pid=,comm= | awk '/Batty\.app\/Contents\/MacOS\/Batty$/{print $1; exit}'`.
- **Sample** `phys_footprint` (never RSS — `ps -o rss` under-reported by 29× in the original report, 7× on the live-sampled instance) plus IOSurface / IOAccelerator / owned-unmapped-graphics dirty sizes and region counts, plus thread and stack-region counts.
- **Run the layer census and assert the invariants** (below) — the live instrumentation proved these are the numbers that carry signal.
- **Emit** a timestamped table or JSONL.
- **Support a before/after diff** between two samples or runs — **diffing geometry-class counts, not just totals** (see the methodological lesson below).

The live instrumentation (`issues/0285/investigation-live.md` § Reproduction recipe) already contains the proven, working commands; the harness should incorporate them rather than reinvent:

```bash
BATTY=$(ps -Ao pid=,comm= | awk '/Batty\.app\/Contents\/MacOS\/Batty$/{print $1; exit}')

# Layer census: geometry, count, and derived layer count
vmmap $BATTY | grep -oE "[0-9]+x[0-9]+ \([A-Z0-9]+\) [0-9.]+[KM]  '[^']*'" | sort | uniq -c | sort -rn

# The invariants that must hold on a healthy instance
echo "Batty IOSurfaces: $(vmmap $BATTY | grep -c "SurfaceID.*'Batty'")   (expect layers x 3)"
echo "held by WindowServer: $(vmmap $BATTY | grep "SurfaceID.*'Batty'" | grep -c WindowServer)   (expect exactly layers x 1)"
echo "grayscale atlases 1040K: $(vmmap $BATTY | grep -cE '^IOAccelerator \(graphics\).*\[ *1040K')   (expect = IOSurface count)"
echo "live Terminal Sessions:  $(pgrep -P $BATTY | wc -l)"
```

Required harness output: the geometry-class census plus the three invariants — **Batty IOSurface count = layers × 3** (the `CAMetalLayer` default triple-buffer signature), **surfaces held by WindowServer = layers × 1** (front buffers), and **1040 K atlas count = IOSurface count**. All three held exactly across the live samples; a deviation is itself a finding.

**Methodological lesson (binding for the harness design):** region-count diffing caught the resize behaviour that a footprint total completely hid — between two samples the 820×962 class went 66 → 60 while a new 934×962 class appeared with exactly 6, at an unchanged total of 93 surfaces and a footprint delta of only +8 MB. A harness that only reports totals would have called that "nothing happened". The before/after diff must operate on geometry-class counts (`vmmap … | sort | uniq -c`, then `diff`), not just aggregate MB.

**Restricted-area constraint (record-keeping for the implementer):** `scripts/` is a restricted area per `CLAUDE.md` — adding anything there needs explicit user confirmation. The implementer must ask before creating a script in `scripts/`, or place the harness elsewhere.

## Resolution notes

> 🟢 Resolved 2026-08-01 — `tools/memsample.sh` samples `phys_footprint`, the graphics categories, and a geometry-class census, and diffs two samples.

Three review rounds, each of which found a defect that would have produced a **wrong measurement or a silent failure** — appropriate for a tool whose only value is that its numbers can be trusted.

## Root cause

Every other child in the #0285 umbrella claims a memory improvement that could not be verified except by hand, with `vmmap` one-liners copied out of an investigation document.

## Fix

`tools/memsample.sh` (bash, no dependencies beyond stock `footprint`/`vmmap`/`ps`/`awk`) plus `tools/README.md`. Commands: `list`, `pid`, `sample`, `invariants`, `diff`. Per sample it writes `<tag>.json`, `<tag>.kv`, `<tag>.census.txt` and appends to `samples.jsonl`; `tools/memsamples/` is gitignored.

- Reads `footprint -p -f bytes`, so every size is **byte-exact** — no parsing of the rounded human table.
- Resolves the surface-owner label from the target binary's own basename plus a `.debug.dylib` variant, so it works for release *and* Beta.
- **Geometry-class census with class-level diffing.** This is the methodological point: in the original investigation, counting region classes caught a resize behaving correctly where a footprint total showed only noise.
- Three invariants, with invariant 2 as a **range**, plus a per-geometry total-vs-WindowServer table that localizes a real deviation to one row.
- Samples carry a `schema` version; `diff` dies on mismatch and on any missing key rather than treating absence as zero.

Placed in a new `tools/` directory, not `scripts/` — that is a restricted area per `CLAUDE.md` and permission was not sought. `tools/` also sits outside the `Batty/` synchronized group, so Xcode does not pick it up.

## Review

Reviewed by claude-opus-5 over three rounds. Every round ran the tool rather than only reading it, and every round found something that reading would not have.

**Round 1** blocked on two things. The harness hardcoded `SurfaceID.*'Batty'` — but that string is the creating *image* name, not the process name; the Beta build is a 40 KB stub whose code lives in `Batty Beta.debug.dylib`, so `--target beta` would have silently reported **zero surfaces** while all four documented experiments use it. And invariant 2 was a strict equality on a value that oscillates on an idle process, making it a false-signal generator aimed at the people using it to judge #0287/#0288. The implementer's reported "genuine deviation" (32 vs 31) was a **single sample of a coin flip**; the reviewer sampled 25 times and got 13/12.

**Round 2** confirmed both fixed, then found two more from its own testing: `diff` treated a missing key as `0`, demonstrated by diffing a leftover KB-schema sample against a byte-schema sample of the *same idle process* and getting a phantom **+1.4 GB**; and a mute abort under `set -euo pipefail` when `pgrep -P` finds no children — reachable via `--pid`, and via any Batty with zero Terminal Sessions, which is the baseline state of two of the four experiments.

**Round 3** approved. It attempted to make `diff` fabricate a delta from every damaged-sample shape it could construct (missing key, missing schema, schema mismatch, empty file, truncated file, non-numeric value, duplicate schema lines) and could not; audited every other command substitution for the round-2 mute-death class and found them all guarded; and confirmed N5's re-anchoring disambiguates the dangerous near-miss category names.

## Verification

- **Byte-exactness confirmed independently**: on one captured snapshot, every field matched raw `footprint -p 9870 -f bytes` digit for digit — IOAccelerator (graphics) 489537536 B / 563, IOSurface 395116544 B / 118, unmapped-graphics 260538368 B / 717.
- **Category disambiguation verified**: querying `IOAccelerator` returns the small standalone category (262144 B / 6) and `Owned physical footprint (unmapped)` returns 3932160 B / 945 — neither bleeds into its `(graphics)` sibling.
- **vmmap-derived stats match the canonical one-liners exactly** on the same snapshot: 93 IOSurfaces, 93 atlases, 125 thread lines, 26 children.
- **Invariants run 25× by the reviewer**: 1 → 25/25 PASS (93/3 = 31 every run); 3 → 25/25 PASS; 2 → 25/25 in range, observed 33 shared on 16 runs and 32 on 9.
- `bash -n` and `shellcheck` clean; verified under macOS system bash 3.2.57; all error paths exit 1 with clear messages; JSON output parses.
- `scripts/build.sh unit` — 783 tests in 92 suites (unchanged; the diff contains no Swift).

## Gotchas

- **The harness has never observed a driven state change.** The screen was locked for every session, so it is validated as a *sampler and differ* only. No Tab was opened or closed, `setSurfaceVisible` was never called, no content-driven growth was run. **Experiment (a)'s predicted "+3 atlases / +3 surfaces per Tab" signature is an unverified prediction**, and experiments (b), (c), (d) are entirely unexercised.
- **`--target beta` has never run against a live Beta process.** Verified statically only — bundle layout, dylib name, and that the pattern matches the executable path. That the Beta's real owner label is exactly `'Batty Beta.debug.dylib'` remains inference. A wrong guess self-diagnoses loudly through the owner histogram (demonstrated live against Finder), so the failure is visible rather than silent — but check the histogram on the first Beta run.
- **Invariant 2 is a bound, not a value, and the oscillation is wider than first thought.** Three independent 25-run samples gave 13/12, 22/3, and 19/6 splits, and the reviewer's run never sat at `layers` at all — it moved between `layers+1` and `layers+2`, meaning the original strict-equality check would have failed **25 out of 25 times**. `investigation-live.md`'s claim that this held "exactly" across two samples was luck at n=2; a footnote there now records this. **Do not reintroduce an equality check.**
- **Measured idle noise floor**, the "nothing happened" baseline any experiment must clear: 16,384 B (one page) of `phys_footprint` drift over ~80 s, zero geometry-class changes, and `batty_windowserver_shared` moving ±1 to ±2.
- **Sample skew.** `footprint` and `vmmap` are separate passes taken a moment apart, so a footprint total and its surface census are not from the same instant. Irrelevant when idle; relevant during experiment (d)'s 10-minute `find /` run.
- `threads` is a vmmap `Stack …thread` proxy, not a syscall count. `terminal_sessions` counts *direct* children only.
- **Samples are comparable only within one schema version.** The `schema` stamp exists because a cross-schema diff previously fabricated a +1.4 GB delta at exit 0.
- One residual, non-blocking: a key *present with an empty value* would still print a bogus delta at exit 0. Not reachable from any harness-written sample (every metric goes through `awk '{print $x+0}'`, `wc -l`, or `grep -c || true`), and the cell renders visibly blank.

## Expected behavior

A developer can take a baseline sample, perform an experiment, take a second sample, and get a diff — in one or two commands. The harness must make the following specific experiments easy, because these are the open questions the #0285 source investigation could not settle from source alone:

1. **(a) Atlas scaling — decides #0287's premise (now a hard gate on that issue).** Open one new Tab against a running instance and check whether the 1040 K atlas count rises by 3 (per-surface ownership — the #0287 refactor won't reduce atlas memory) or by 0 (shared within the App — it will). The live data already tilted this toward per-surface (93 atlases for 31 layers); this experiment settles it.
2. **(b) Does occlusion free anything?** Call `setSurfaceVisible(false)` on a few Terminal Sessions and watch the IOSurface region count. A drop means #0288 is a real reclaim and #0293 is unnecessary; no drop means #0293 goes upstream.
3. **(c) Teardown check.** Open 20 Tabs, close them, compare both `phys_footprint` **and** IOSurface region count to baseline. Regions returning to baseline while footprint doesn't points at "owned unmapped (graphics)" accounting, not a leak; regions staying high points at something holding the `TabRuntime` past close (see #0289).
4. **(d) Content-driven vs frame-driven growth.** Scroll novel content (`find /`) for 10 min, then a small repeating buffer (`yes`) for 10 min. Atlas growth predicts the first grows and the second plateaus; a per-frame drawable leak predicts both grow equally.

## Actual behavior

Ad-hoc one-liners in `issues/0285/memory-report.md` (§ Suggested reproduction) and the proven-but-uncaptured commands in `issues/0285/investigation-live.md` are the only tooling; nothing packaged, nothing that asserts the invariants automatically.

## Notes

Useful primitives from the original report: `footprint -p $BATTY`, `vmmap -summary $BATTY | grep -E "IOSurface|IOAccelerator"`, and `top`'s MEM column all read `phys_footprint`-consistent numbers; only `ps`/RSS is wrong.

**The harness should target the Beta build** for driven experiments: scheme `Batty (Beta)`, bundle id `co.sstools.Batty.beta` (`Configuration/Beta.xcconfig:4`), built with `SCHEME="Batty (Beta)" scripts/build.sh`. Its distinct bundle id gives it separate UserDefaults and workspace persistence, so experiments (a)–(d) — which open, close, and drive Tabs — can run without disturbing the user's release instance (the pid-matching pattern needs to account for the beta binary path as well as the release one). Passive sampling of the release instance stays read-only.
