## Description

Every other child of the #0285 umbrella claims a memory improvement that currently cannot be verified except by hand-running `footprint` / `vmmap` one-liners and eyeballing the output. The umbrella's acceptance criteria require a measured before/after on `phys_footprint`, so a small developer-side sampling harness is needed:

- **Resolve the pid.** Note: `pgrep Batty` returns nothing on the reporting machine; match the full binary path instead: `ps -Ao pid=,comm= | awk '/Batty\.app\/Contents\/MacOS\/Batty$/{print $1; exit}'`.
- **Sample** `phys_footprint` (never RSS — `ps -o rss` under-reported by 29× in the original report, 7× on the live-sampled instance) plus IOSurface / IOAccelerator / owned-unmapped-graphics dirty sizes and region counts, plus thread and stack-region counts.
- **Run the layer census and assert the invariants** (below) — the live instrumentation proved these are the numbers that carry signal.
- **Emit** a timestamped table or JSONL.
- **Support a before/after diff** between two samples or runs — **diffing geometry-class counts, not just totals** (see the methodological lesson below).

The live instrumentation (`issues/0285/investigation-live.md` § Reproduction recipe) already contains the proven, working commands; the harness should incorporate them rather than reinvent:

```bash
BATTY=$(ps -Ao pid=,comm= | awk '/Batty\.app\/Contents\/MacOS\/Batty$/{print $1; exit}')

# Layer census: geometry, count, and derived layer count
vmmap $BATTY | grep -oE "[0-9]+x[0-9]+ \([A-Z0-9]+\) [0-9.]+[KM]  '[^']*'" | sort | uniq -c | sort -rn

# The invariants that must hold on a healthy instance
echo "Batty IOSurfaces: $(vmmap $BATTY | grep -c "SurfaceID.*'Batty'")   (expect layers x 3)"
echo "held by WindowServer: $(vmmap $BATTY | grep "SurfaceID.*'Batty'" | grep -c WindowServer)   (expect exactly layers x 1)"
echo "grayscale atlases 1040K: $(vmmap $BATTY | grep -cE '^IOAccelerator \(graphics\).*\[ *1040K')   (expect = IOSurface count)"
echo "live Terminal Sessions:  $(pgrep -P $BATTY | wc -l)"
```

Required harness output: the geometry-class census plus the three invariants — **Batty IOSurface count = layers × 3** (the `CAMetalLayer` default triple-buffer signature), **surfaces held by WindowServer = layers × 1** (front buffers), and **1040 K atlas count = IOSurface count**. All three held exactly across the live samples; a deviation is itself a finding.

**Methodological lesson (binding for the harness design):** region-count diffing caught the resize behaviour that a footprint total completely hid — between two samples the 820×962 class went 66 → 60 while a new 934×962 class appeared with exactly 6, at an unchanged total of 93 surfaces and a footprint delta of only +8 MB. A harness that only reports totals would have called that "nothing happened". The before/after diff must operate on geometry-class counts (`vmmap … | sort | uniq -c`, then `diff`), not just aggregate MB.

**Restricted-area constraint (record-keeping for the implementer):** `scripts/` is a restricted area per `CLAUDE.md` — adding anything there needs explicit user confirmation. The implementer must ask before creating a script in `scripts/`, or place the harness elsewhere.

## Expected behavior

A developer can take a baseline sample, perform an experiment, take a second sample, and get a diff — in one or two commands. The harness must make the following specific experiments easy, because these are the open questions the #0285 source investigation could not settle from source alone:

1. **(a) Atlas scaling — decides #0287's premise (now a hard gate on that issue).** Open one new Tab against a running instance and check whether the 1040 K atlas count rises by 3 (per-surface ownership — the #0287 refactor won't reduce atlas memory) or by 0 (shared within the App — it will). The live data already tilted this toward per-surface (93 atlases for 31 layers); this experiment settles it.
2. **(b) Does occlusion free anything?** Call `setSurfaceVisible(false)` on a few Terminal Sessions and watch the IOSurface region count. A drop means #0288 is a real reclaim and #0293 is unnecessary; no drop means #0293 goes upstream.
3. **(c) Teardown check.** Open 20 Tabs, close them, compare both `phys_footprint` **and** IOSurface region count to baseline. Regions returning to baseline while footprint doesn't points at "owned unmapped (graphics)" accounting, not a leak; regions staying high points at something holding the `TabRuntime` past close (see #0289).
4. **(d) Content-driven vs frame-driven growth.** Scroll novel content (`find /`) for 10 min, then a small repeating buffer (`yes`) for 10 min. Atlas growth predicts the first grows and the second plateaus; a per-frame drawable leak predicts both grow equally.

## Actual behavior

Ad-hoc one-liners in `issues/0285/memory-report.md` (§ Suggested reproduction) and the proven-but-uncaptured commands in `issues/0285/investigation-live.md` are the only tooling; nothing packaged, nothing that asserts the invariants automatically.

## Notes

Useful primitives from the original report: `footprint -p $BATTY`, `vmmap -summary $BATTY | grep -E "IOSurface|IOAccelerator"`, and `top`'s MEM column all read `phys_footprint`-consistent numbers; only `ps`/RSS is wrong.

**The harness should target the Beta build** for driven experiments: scheme `Batty (Beta)`, bundle id `co.sstools.Batty.beta` (`Configuration/Beta.xcconfig:4`), built with `SCHEME="Batty (Beta)" scripts/build.sh`. Its distinct bundle id gives it separate UserDefaults and workspace persistence, so experiments (a)–(d) — which open, close, and drive Tabs — can run without disturbing the user's release instance (the pid-matching pattern needs to account for the beta binary path as well as the release one). Passive sampling of the release instance stays read-only.
