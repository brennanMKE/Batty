## Root cause

Feature work. Starting state: dev servers were shown in a `server`-kind Server Pane (`ServerPaneContent`, `ServerPaneView`), placed by a Settings choice, behind the `serverPane` flag. User decision C (#0689) moves them into an app-wide list behind a toolbar button.

## Fix

Followed the plan's three steps, one commit each.

1. `ServerPaneContent` became `ServerEntry` (`git mv`), minus metrics and expvar stats and the visibility lifecycle; default URL is `http://127.0.0.1:<port>/`. New `@Observable ServerRegistry` on `AppStateStore.servers` registers entries (`setUp(visible: true)`), removes and tears them down. An entry calls `onFinished` when it is no longer running and no Stop/Restart/convert task is in flight (checked in `setState` and when the task clears), so a Restart's intermediate Stopped never removes it. `server start` splits a terminal Pane from the caller (`--split right` default, `down` vertical); `attach` and `serve` open no Pane; stop/restart resolve by `serverID` or port app-wide. Wire fields renamed `ServerReply.serverID`, `ServerControlRequest.serverID`. `PaneContentKind.server`, `ServerPaneView`, `ServerStats`, `ServerStatSparkline`, `paneSplitRefusal` and the Project/PaneView `.server` arms are gone. CLI help no longer says Server Pane; `--split`/`--pane` on `serve` and `--stats-url` say "Accepted for compatibility; has no effect."
2. Flag `serverPane` → `servers`, override `BATTY_UI_TEST_FORCE_SERVERS_OFF`. `ServerPanePlacement` removed; Settings › General › Servers has "Always show Servers in the toolbar" (`alwaysShowServersKey`, default off). `ServersToolbarItem` (before Reminders in the existing `ToolbarItemGroup`) shows `ServersToolbarButton` only when `ServersToolbarVisibility.isVisible`; the button owns its popover `@State`. `ServersListView` rows: name, `127.0.0.1:<port>`, state, Copy URL, Copy Tailnet URL (only with a tailnet URL), and a "…" menu (Open in Browser, Show Terminal, Restart/Stop only for terminal and in-app kinds). All writes are button actions (event origin).
3. Docs: `docs/design/servers-list.md`; Server Pane note and mock-up marked superseded; Concepts, PRD, feature-flags, pane-kinds, CLI docs and skill corrected.

Divergences from the plan:
- `attach --pane` is kept meaningful (it sets the anchor Restart splits a new terminal Pane from), so its help says that rather than "no effect".
- Tests whose flow assumed a stopped entry stays listed were reworked, because a stopped entry now leaves the registry: `serveOnAStoppedRootResumesIt` → `serveAfterStopServesAgainInAFreshEntry`; `stopAndRestartResolve…` restart first, then stop. In unit tests a terminal Restart's `rerun()` fails (no surface), which leaves the entry Stopped and removes it, so `startTwiceOnSamePortReusesEntryAndTabAndRestarts` checks the entry count before awaiting.
- `ServerEntry.setUp(visible:)` keeps its parameter (tests use `visible: false` to set up without ticks); the registry always passes `true`.
- Toolbar gap: not checked by hand (no app launch allowed here); the item lives inside the `ToolbarItemGroup` as planned.

Round 2 (2026-11-19): `CLIServersListTests.testServerAttachListsAnExternalListener` queried `app.menuItems["Restart"]` app-wide, which matched the menu bar's Apple-menu Restart. The row menu's items now carry identifiers (`servers.row.open-in-browser`, `servers.row.show-terminal`, `servers.row.restart`, `servers.row.stop`), and the test finds the opened row menu (the `menu` containing `servers.row.open-in-browser`) and queries only its items by identifier. No other `app.menuItems` query exists in `CLIServersListTests` or `CLIServerServeTests`. No behavior change.

## Plan

Written 2026-11-19 against `main` at `395c74fb` (after #0690). Premises checked: every file the Description names exists as stated; `ServerPaneContent.swift` is 612 lines. `ServerPaneDisplay`, `ServerStats.swift` (expvar parser and history) and `Views/ServerStatSparkline.swift` exist only for the Server Pane view. Nothing persists `Pane.kind` (workspace persistence is gone, #0172; Projects never store `server`, `projectSlotKinds` excludes it and `SessionProjectCapture` turns it into a terminal slot), so the `server` case is deleted outright with no decode shim, as #0690 did for `web-preview`.

### Decisions this plan makes

1. **Model: rename and re-home, don't rewrite.** `ServerPaneContent` becomes `ServerEntry` (same file contents moved to `Runtime/ServerEntry.swift`): same state machine, ticks, listener scan, HTTP probe, ownership checks, `stop()`/`restart()`/`convert(to:)`/`replaceBackend`, `waitForState`. `ServerPaneState` becomes `ServerEntryState`. A new `@Observable ServerRegistry` (`Runtime/ServerRegistry.swift`) owns the entries, one per app: `public let servers = ServerRegistry()` on `AppStateStore`. `ServerBackend.swift`, `ServerJobOwnership.swift`, `ListeningPortScanner.swift`, `ServerHTTPProbe.swift` and `InAppStaticServerBackend.swift` don't change in behavior (doc comments that say "Server Pane" are reworded).
2. **What goes from the entry** (only the view read it): process metrics sampling (`metricsProvider`, `ServerProcessMetrics`, `ServerProcessSample`, `liveSample`), expvar stats (`statsURL`, `explicitStatsURL`, `nonLoopbackStatsHost`, `stats`, `statsVisible`, `statsUnavailableReason`, `fetchStats`, `statsSuspended`, `statsEveryTicks`). Delete `Runtime/ServerStats.swift` and `Views/ServerStatSparkline.swift`. Keep the `ServerStatsFetching` protocol and `URLSessionHTTPProbe`'s conformance: #0693 reuses that fetch for `GET /_batty/status`. Keep `servingFacts` (cheap, and #0693's seam for static entries). Keep `recoveredCommandLine` (the row's name for an attached server).
3. **Lifecycle without a Pane.** `ServerEntry` drops `PaneContentLifecycle` and `setVisible`; it keeps its private `PaneLifecycleController` so `tearDown()` stays idempotent. The registry calls `setUp(visible: true)` on register (ticks run for as long as the entry exists) and `tearDown()` on removal. No entries means no tasks and no scans (#0692 AC4 holds by construction).
4. **Leaving the list.** An entry leaves the registry when it reaches `.stopped` or `.crashed` with no Stop/Restart/convert task in flight. `ServerEntry` gets `@ObservationIgnored var onFinished: (@MainActor (ServerEntry) -> Void)?`, called from `setState` when `!new.isRunning && stopTask == nil`, and again when a `stopTask` clears while the state is not running (so a Restart's intermediate `.stopped` never removes it). The registry's handler removes and tears the entry down. Writers are tick tasks, XPC handlers, tab-observer events and button taps: none is view-update origin (`docs/swiftui-observation-rules.md`).
5. **Lookup is app-wide.** One entry per port (only one process can listen on `127.0.0.1:N`); `entry(port:)`, `entry(id:)`, `entry(root:)` for static. `server stop|restart --port N` no longer needs the calling Pane's Session. `attach` and `serve` no longer need a calling Pane at all (they open none); `start` still needs one, to split the terminal Pane from.
6. **`server start` placement.** The terminal Pane is split from the calling Pane: `--split right` (default) → `.horizontal`, `--split down` → `.vertical`; focus stays on the caller. This replaces the Server Pane + terminal-below layout and the `ServerPanePlacement` Setting. Restart after the terminal is gone splits a new terminal Pane from the entry's `anchorPaneID` (the calling Pane recorded at registration), or the focused Pane if that is gone.
7. **Wire ids.** `ServerReply.paneID` becomes `serverID` (the entry id) and `ServerControlRequest.serverPaneID` becomes `serverID`; the CLI prints the server id. `terminalPaneID`/`tabID` stay. CLI and app ship in one bundle, and the noun is Beta-only, so no compatibility shim. `--split` on `attach`/`serve` and `--stats-url` on `start`/`attach` stay accepted (no grammar change here) with help "Accepted for compatibility; has no effect."; #0692 decides their fate.
8. **URL.** The entry's default `url` becomes `http://127.0.0.1:<port>/` (was `localhost`), so Copy URL matches the acceptance criterion and what `tailscale serve` proxies to (#0694); `--url` still overrides. The HTTP probe uses the same URL. Caveat for Gotchas/design note: a server bound only to `::1` answers the scanner but not the probe or the copied URL.
9. **Row actions — amendment to Expected behavior.** The issue says "no buttons beyond Copy"; the orchestrator's dispatch for this plan asks for Open in Browser, Show Terminal, and Stop/Restart only for Batty-started servers. Resolution, keeping the row minimal: the row shows **one** visible button, Copy URL (plus Copy Tailnet URL when #0694 sets one). Everything else is in a row `Menu` ("…", `servers.row-menu`): Open in Browser; Show Terminal (terminal kind with a live Tab); Stop and Restart only for managed kinds (`.terminal`, `.inApp`), disabled with the `stopRefusal` as help text when refused. `.external` rows never offer Stop/Restart (the CLI `stop` on an attached server keeps today's behavior until #0692). **Open question for the user (non-blocking):** drop the menu and ship Copy-only, as the issue text says? The menu is self-contained in `ServersListView`, so removing it later is a one-file change.
10. **Toolbar visibility.** `ServersToolbarItem` is a wrapper view inside the existing `ToolbarItemGroup`, before `RemindersToolbarButton` (order: splits, Servers, Reminders, Bell Feed). Its `body` reads `ServersToolbarVisibility.isVisible(flagOn:activeCount:alwaysShow:)` and contains `if visible { ServersToolbarButton(...) }`. `ServersToolbarButton` owns `@State private var isShown`, so popover state is discarded when the button leaves (a stale `true` can never reopen the popover). `SessionDetailView.body` reads nothing new. No menu command, shortcut or notification toggle (keep the default surface small).
11. **Setting.** `SettingsPreference.alwaysShowServersKey = "co.sstools.Batty.alwaysShowServers"`, default `false`. Settings › General: the "Server Panes" section is replaced by `Section("Servers")` with one `Toggle("Always show Servers in the toolbar")` (`settings-always-show-servers`) and a caption ("Servers appears in the toolbar while a server started with batty server is running. Turn this on to keep it there."). Shown only with the flag on.
12. **Kind name.** Keep `ServerBackendKind.inApp` (Swift keyword clash with `static`); docs call it the static kind. #0692's `server list --json` maps it to `"static"`.

## Expected behavior

- **Registry.** An app-wide `@Observable` server registry on `AppStateStore` (one per app, not per Window), entries keyed by id with: name (command or folder), port, kind (`terminal` = started by `server start` in a terminal Pane; `external` = tracked by `share`/`attach`; `static` = a PhotonHTTP CLI server started by `server serve` in a terminal Pane, #0693), Session/Pane ids where known, listening pid, state (Starting, Listening, Stopped, Exited), localhost URL, optional tailnet URL (#0694). The liveness/ownership logic of `ServerPaneContent` and `ServerBackend` (#0648, #0658) moves into the registry entries, unchanged in behavior; only the view goes.
- **Toolbar icon** next to Bell Feed and Reminders (symbol chosen in the design note), with a popover listing active servers: name, `127.0.0.1:port`, state; per row **Copy URL** and, when #0694 provides one, **Copy Tailnet URL**. No metrics, no expvar block, no buttons beyond Copy (Stop/Restart are CLI verbs, #0692; tailnet on/off is #0694). Exited/stopped entries leave the list.
- **Progressive disclosure** (`AGENTS.md`, "Top design goal"): the icon is shown **only** while the registry has at least one active server, or when the user turned on "Always show Servers in the toolbar" in Settings (default off). A fresh install never shows it.
- **Remove the Server Pane:** delete `PaneContentKind.server` (or decode it as unknown, as #0690 decides for `web-preview`), `ServerPaneContent`'s view role, `ServerPaneDisplay`, `ServerPaneView`, the `PaneView` branch, `ServerPanePlacement` and the Settings › General › Server Panes section. Until #0692 lands, `server start`/`attach`/`serve` register in the registry instead of creating a Server Pane (minimal adapter; no grammar change here).
- **Flag:** rename `serverPane` → `servers` (and the UI-test override → `BATTY_UI_TEST_FORCE_SERVERS_OFF`); on in Beta, off in Prod; gates the icon, the Settings row and the `server` noun. #0670 removes it.
- **Design note:** `docs/design/servers-list.md` (short: purpose, when the icon shows, row anatomy, Copy actions, accessibility identifiers `toolbar.servers`, `servers.row.<id>`, `servers.copy-url`, `servers.copy-tailnet-url`, why there are no controls). `docs/design/server-pane-view.md` gets "**Superseded** by #0691 and `docs/design/servers-list.md`". `Concepts.md` replaces the Server Pane entry with **Servers list**; `PRD.md:364` updated.
