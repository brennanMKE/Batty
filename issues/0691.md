## Description

Child of #0689. User decision C (2026-11-19): "Servers move out of a custom Pane into a new icon alongside the Bell Feed and Reminders icons: a minimal list of active servers with Copy URL actions — a localhost URL, and a tailnet URL when Tailscale is available. Remove the Server Pane view." This issue builds the app-wide server registry, the toolbar icon and its popover list, and removes the `server` Pane kind. The CLI verbs that add servers are reworked in #0692; the tailnet URL is #0694.

## Expected behavior

- **Registry.** An app-wide `@Observable` server registry on `AppStateStore` (one per app, not per Window), entries keyed by id with: name (command or folder), port, kind (`terminal` = started by `server start` in a terminal Pane; `external` = tracked by `share`/`attach`; `static` = a PhotonHTTP CLI server started by `server serve` in a terminal Pane, #0693), Session/Pane ids where known, listening pid, state (Starting, Listening, Stopped, Exited), localhost URL, optional tailnet URL (#0694). The liveness/ownership logic of `ServerPaneContent` and `ServerBackend` (#0648, #0658) moves into the registry entries, unchanged in behavior; only the view goes.
- **Toolbar icon** next to Bell Feed and Reminders (symbol chosen in the design note), with a popover listing active servers: name, `127.0.0.1:port`, state; per row **Copy URL** and, when #0694 provides one, **Copy Tailnet URL**. No metrics, no expvar block, no buttons beyond Copy (Stop/Restart are CLI verbs, #0692; tailnet on/off is #0694). Exited/stopped entries leave the list.
- **Progressive disclosure** (`AGENTS.md`, "Top design goal"): the icon is shown **only** while the registry has at least one active server, or when the user turned on "Always show Servers in the toolbar" in Settings (default off). A fresh install never shows it.
- **Remove the Server Pane:** delete `PaneContentKind.server` (or decode it as unknown, as #0690 decides for `web-preview`), `ServerPaneContent`'s view role, `ServerPaneDisplay`, `ServerPaneView`, the `PaneView` branch, `ServerPanePlacement` and the Settings › General › Server Panes section. Until #0692 lands, `server start`/`attach`/`serve` register in the registry instead of creating a Server Pane (minimal adapter; no grammar change here).
- **Flag:** rename `serverPane` → `servers` (and the UI-test override → `BATTY_UI_TEST_FORCE_SERVERS_OFF`); on in Beta, off in Prod; gates the icon, the Settings row and the `server` noun. #0670 removes it.
- **Design note:** `docs/design/servers-list.md` (short: purpose, when the icon shows, row anatomy, Copy actions, accessibility identifiers `toolbar.servers`, `servers.row.<id>`, `servers.copy-url`, `servers.copy-tailnet-url`, why there are no controls). `docs/design/server-pane-view.md` gets "**Superseded** by #0691 and `docs/design/servers-list.md`". `Concepts.md` replaces the Server Pane entry with **Servers list**; `PRD.md:364` updated.

## Acceptance criteria

1. Unit tests: registry add/remove/state transitions; the icon-visibility rule (no servers + setting off → hidden; one active server → shown; setting on → shown with an empty-state row); Copy URL writes `http://127.0.0.1:<port>/` (through an injected pasteboard).
2. Existing ownership tests from #0648/#0658 (`ServerPaneContentTests` and friends) keep passing, moved to the registry types.
3. New UI test (typecheck only per issue): with the UI-test script, `server start` makes `toolbar.servers` appear and its row shows the port; it disappears after `server stop`.
4. A fresh install with no `server` use shows nothing new: no `toolbar.servers` button, no new Settings section beyond the default-off "Always show" row.
5. `./build.sh`, `./build.sh unit`, `./build.sh ui-typecheck` pass.

## Decisions (orchestrator defaults, 2026-11-19; the user may override)

- **Setting:** an "Always show Servers" toggle in Settings, off by default.
- **Icon:** SF Symbol `server.rack`.
