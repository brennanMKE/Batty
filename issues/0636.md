## Description

Hovering the toolbar bell shows "Bell Feed (⌘⇧N)". The Bell Feed's shortcut is ⌘⇧B, and ⌘⇧N is New Window, so the tooltip sends the user to the wrong command. The text is a string literal, so it also ignores a rebinding in Settings → Shortcuts. The tooltip should be built from the live binding of `ShortcutAction.toggleBellFeed`.

The two split buttons beside it have the same pattern: their tooltips hard-code ⌘D / ⌘⇧D / ⌥⌘D / ⌥⌘⇧D, while `splitHorizontal`, `splitVertical`, `splitFullHeightColumn` and `splitFullWidthRow` are all rebindable. Their defaults happen to match today, so they only go wrong after a rebinding. Fix them in the same change.

Found while preparing the Reminders design (`issues/0637/spec.md`, "Toolbar bell" and "The toolbar item"). #0640 adds a Reminders button beside the bell whose tooltip is built from the live binding the same way, so this issue lands first and sets the pattern.

### Files

1. **New: `BattyKit/Sources/BattyKit/Views/ToolbarHelpText.swift`.** An internal `enum ToolbarHelpText` of pure static funcs. It is main-actor by default, which is fine because its only callers are views and `@MainActor` tests. #0640's Reminders button reuses it.
   - `static func labelled(_ title: String, _ binding: ShortcutBinding) -> String` returns `"\(title) (\(binding.displayString))"`. This is the reusable core. #0640 calls it, or a `reminders(...)` func added beside it, for "Reminders (⌥⌘R)" plus its state text.
   - `static func bellFeed(_ shortcuts: ShortcutsStore) -> String` returns `labelled(String(localized: "Bell Feed"), shortcuts.binding(for: .toggleBellFeed))`.
   - `static func splitHorizontal(_ shortcuts: ShortcutsStore) -> String` returns `"\(labelled(String(localized: "Split Horizontally"), shortcuts.binding(for: .splitHorizontal))) \u{2014} \(labelled(String(localized: "Option for a full-height column"), shortcuts.binding(for: .splitFullHeightColumn)))"`.
   - `static func splitVertical(_ shortcuts: ShortcutsStore) -> String` follows the same pattern with `.splitVertical` and "Option for a full-width row" / `.splitFullWidthRow`.
   - Each func takes the store as a parameter instead of reaching for `.shared`, so tests can pass an isolated store. Call sites pass `ShortcutsStore.shared`.
   - Header `// ToolbarHelpText.swift` and no logger, because nothing here logs.
2. **`BattyKit/Sources/BattyKit/Views/SessionDetailView.swift`**
   - `BellFeedToolbarButton.body`: change `.help(...)` to `.help(ToolbarHelpText.bellFeed(ShortcutsStore.shared))`. Use the `String` overload of `.help`, not a `LocalizedStringKey`, because the text is already composed. Add `.accessibilityIdentifier("toolbar.bell-feed")` on the `Button`, after `.help` and before `.popover`, the same place the split buttons put theirs. Extend the struct's doc comment by one clause: it is also the toolbar's only reader of the Toggle Bell Feed binding.
   - Split buttons: move the two inline `Button`s into a new `private struct SplitToolbarButton: View { let windowRuntime: WindowRuntime; let direction: SplitDirection }`. Its body keeps today's action unchanged (the `NSEvent.modifierFlags.contains(.option)` branch to `splitFullDimension` / `splitFocusedPane`). It picks the label, SF Symbol, `toolbar.split-horizontal` / `toolbar.split-vertical` identifier and `ToolbarHelpText.splitHorizontal/splitVertical(ShortcutsStore.shared)` by `direction`, and keeps `.disabled(windowRuntime.selectedSession == nil)`. `toolbarItems` then reads `SplitToolbarButton(windowRuntime: windowRuntime, direction: .horizontal)`, `SplitToolbarButton(windowRuntime: windowRuntime, direction: .vertical)`, then `BellFeedToolbarButton(...)`.
   - Why the extraction: reading `ShortcutsStore.shared` inside `toolbarItems` would make `SessionDetailView.body` depend on the store's `bindings` dictionary, and a rebinding would then re-render the whole detail view. Each button reads the store only in its own `body`, so the re-render stays local to it, as the issue's Notes ask. #0640's `RemindersToolbarButton` should follow the same shape.
   - Observation rules (`docs/swiftui-observation-rules.md`): the change only reads observed state in `body` and writes nothing. No `onChange`, no `Task`. The button actions are event-origin and are unchanged.
   - Keep the identifiers and labels exactly as they are. `toolbar.split-horizontal` and `toolbar.split-vertical` are used by UI tests.

No other source file changes. `docs/` has no copy of these tooltip strings; this was checked by grep.

## Fix

The two inline split buttons moved into `private struct SplitToolbarButton(windowRuntime:direction:)` so only the button, not `SessionDetailView.body`, observes the store; action, labels, symbols, identifiers and `.disabled` are unchanged. No deviation from the plan.

## Steps to reproduce

1. Launch Batty Beta with default shortcuts.
2. Hover the bell button at the trailing end of the toolbar.
3. Optionally rebind Toggle Bell Feed in Settings → Shortcuts and hover again.

## Expected behavior

- The tooltip reads "Bell Feed (⇧⌘B)", using `ShortcutBinding.displayString`'s glyph order, and changes when Toggle Bell Feed is rebound.
- The split tooltips show their live bindings too: "Split Horizontally (⌘D) — Option for a full-height column (⌥⌘D)" and "Split Vertically (⇧⌘D) — Option for a full-width row (⌥⇧⌘D)", with the bound chords in place of the literals.
- The bell button gets the accessibility identifier `toolbar.bell-feed`, after the convention of `toolbar.split-horizontal`. It has no identifier today, and UI tests find it by its label (`BattyUITests/BellFeedTests.swift:38`, `CLIRemoteControlTests.swift:478`). Existing label lookups keep working.

## Actual behavior

- `BattyKit/Sources/BattyKit/Views/SessionDetailView.swift:420`: `.help("Bell Feed (\u{2318}\u{21E7}N)")`.
- Defaults: `toggleBellFeed` is ⌘⇧B (`Shortcuts/ShortcutAction.swift:157-158`), `newWindow` is ⌘⇧N (`:167-168`).
- Split literals: `SessionDetailView.swift:214` and `:228`.

## Notes

- Paths are under `BattyKit/Sources/BattyKit/` and were checked at `main` = `6b8dfde7`.
- The live binding: `ShortcutsStore.shared.binding(for:)` (`Shortcuts/ShortcutsStore.swift`), formatted with `ShortcutBinding.displayString` (`Shortcuts/ShortcutBinding.swift:81`). The Command Palette already uses this pair (`Views/CommandPaletteView.swift:68-72`). `ShortcutsStore` is `@Observable`, so a rebinding re-renders a view that reads it in `body`. Reading the shortcut only inside `BellFeedToolbarButton` keeps the re-render local to that button.
- Composing the text in a small pure helper, for example a static func that takes a `ShortcutBinding` and returns the tooltip, lets a unit test check it without a view.
