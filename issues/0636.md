# 0636 — The bell button's tooltip names ⌘⇧N, but the Bell Feed shortcut is ⌘⇧B

## Description

Hovering the toolbar bell shows "Bell Feed (⌘⇧N)". The Bell Feed's shortcut is ⌘⇧B, and ⌘⇧N is New Window, so the tooltip sends the user to the wrong command. The text is a string literal, so it also ignores a rebinding in Settings → Shortcuts. The tooltip should be built from the live binding of `ShortcutAction.toggleBellFeed`.

The two split buttons beside it have the same pattern: their tooltips hard-code ⌘D / ⌘⇧D / ⌥⌘D / ⌥⌘⇧D, while `splitHorizontal`, `splitVertical`, `splitFullHeightColumn` and `splitFullWidthRow` are all rebindable. Their defaults happen to match today, so they only go wrong after a rebinding. Fix them in the same change.

Found while preparing the Reminders design (`issues/0637/spec.md`, "Toolbar bell" and "The toolbar item"). #0640 adds a Reminders button beside the bell whose tooltip is built from the live binding the same way, so this issue lands first and sets the pattern.

## Steps to reproduce

1. Launch Batty Beta with default shortcuts.
2. Hover the bell button at the trailing end of the toolbar.
3. Optionally rebind Toggle Bell Feed in Settings → Shortcuts and hover again.

## Expected behavior

- The tooltip reads "Bell Feed (⇧⌘B)", using `ShortcutBinding.displayString`'s glyph order, and changes when Toggle Bell Feed is rebound.
- The split tooltips show their live bindings too: "Split Horizontally (⌘D) — Option for a full-height column (⌥⌘D)" and "Split Vertically (⇧⌘D) — Option for a full-width row (⌥⇧⌘D)", with the bound chords in place of the literals.
- The bell button gets the accessibility identifier `toolbar.bell-feed`, after the convention of `toolbar.split-horizontal`. It has no identifier today, and UI tests find it by its label (`BattyUITests/BellFeedTests.swift:38`, `CLIRemoteControlTests.swift:478`). Existing label lookups keep working.

## Actual behavior

- `BattyKit/Sources/BattyKit/Views/SessionDetailView.swift:420`: `.help("Bell Feed (\u{2318}\u{21E7}N)")`.
- Defaults: `toggleBellFeed` is ⌘⇧B (`Shortcuts/ShortcutAction.swift:157-158`), `newWindow` is ⌘⇧N (`:167-168`).
- Split literals: `SessionDetailView.swift:214` and `:228`.

## Notes

- Paths are under `BattyKit/Sources/BattyKit/` and were checked at `main` = `6b8dfde7`.
- The live binding: `ShortcutsStore.shared.binding(for:)` (`Shortcuts/ShortcutsStore.swift`), formatted with `ShortcutBinding.displayString` (`Shortcuts/ShortcutBinding.swift:81`). The Command Palette already uses this pair (`Views/CommandPaletteView.swift:68-72`). `ShortcutsStore` is `@Observable`, so a rebinding re-renders a view that reads it in `body`. Reading the shortcut only inside `BellFeedToolbarButton` keeps the re-render local to that button.
- Composing the text in a small pure helper, for example a static func that takes a `ShortcutBinding` and returns the tooltip, lets a unit test check it without a view.

## Tests

Unit tests to add. Each must fail first against today's literal, or against a helper that returns it:

No UI test. XCUITest does not reliably expose a macOS tooltip.
