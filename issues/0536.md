# 0536 — The home folder gets a Session name that is remembered, as if it were a project folder

| | |
|---|---|
| **Status** | open |
| **Module** | Session / Sidebar / Projects |
| **Platform** | macOS |
| **First seen** | 2026-10-27 |

## Description

Batty treats the user's home folder (`~`) like any project folder when it names Sessions. A Session renamed while its anchor Tab is at home writes a home entry to the Session Name cache (`session-name-cache.json`). Every later Session opened at home then picks up that name. The automatic naming chain (manifest rules, then the AI suggester) also runs for home. Reset Name at home retitles the Session to the account short name. New Project and Save Session as Project suggest the home folder's basename as the Project name. Home is not a project folder, and no name should be derived from it or remembered for it.

User report, 2026-10-27, verbatim:

> I find ~/ is given a name that should not be persisted. It is clearly the user's home directory. It is not a project folder.

**Decision (user, 2026-10-27):** adopt the recommendation in Notes. Target release 1.3.4: fix on `main` through the normal issue workflow, then `git cherry-pick -x` onto `release/1.3`.

Which surface the user actually saw is unknown. A premise check found no home entry in the current Prod or Beta `session-name-cache.json` or `projects.json`. All the unguarded code paths below are confirmed on `main`.

## Steps to reproduce

1. Open a Session whose anchor Tab is at `~`.
2. Rename it in the Sidebar, for example to "Home Stuff".
3. Open a new Session at `~` (or relaunch Batty and open one).
4. Separately: on a Session at `~`, choose Reset Name in the Sidebar.
5. Separately: open New Project with no other root, or Save Session as Project from a Session at `~`.

## Expected behavior

- A rename at home applies to that Session for its lifetime but is not written to the Name cache. New Sessions at home get the default `Session N` title.
- Automatic naming never derives a name for home: no manifest-rule name, no AI suggestion for the Session or its Tab. A Session that `cd`s to home goes back to `Session N`.
- Reset Name at home gives `Session N`, not the account short name.
- New Project rooted at home starts as "Untitled Project". Save Session as Project from a Session at home keeps the home root, suggests no name from the folder, and shows a note that home is not usually a Project root.
- The same rules apply to `/`, any top-level directory (`/Users`, `/Volumes`, `/Applications`, `/private`, `/tmp`, ...), and the temp roots. Subfolders of home (`~/Desktop`, `~/Documents`, `~/Downloads`, `~/Developer/...`) stay nameable.
- A home entry already in `session-name-cache.json` is dropped on load and is gone after the next save.
- To name home durably, the user creates a Project rooted at `~`. That path is unchanged.

## Actual behavior

- Renaming a Session at home persists `(home path, name)`, and later Sessions at home reuse that name.
- The manifest rules run at home, so a stray `~/package.json` or `~/go.mod` names every home Session. The AI suggester runs for home, its result is memoized per cwd for the process and reapplied to later home Sessions, and it also feeds Tab chip naming.
- Reset Name at home retitles the Session to the home folder's basename (the account short name).
- New Project and Save Session as Project pre-fill the home basename as the Project name.

## Notes

### Findings (line numbers checked on `main`, 2026-10-27)

All paths are under `BattyKit/Sources/BattyKit/`.

**A. Session Name cache (persisted)**: `session-name-cache.json` (`Model/SessionNameCache.swift:52-53`, `canonicalFileURL` :104-113).
- Write: `WindowRuntime.renameSession(id:to:)` (`Runtime/WindowRuntime.swift:339-351`), called from the Sidebar rename (`Views/SessionSidebarView.swift:184`). It records `(anchor Tab cwd, name)` for any name that isn't `Session N`. Neither it nor `SessionNameCache.record` (`Model/SessionNameCache.swift:134-141`) filters the path; any non-empty path is accepted.
- Read: `WindowRuntime.addSession` (`Runtime/WindowRuntime.swift:213-216`, `nameCache.lookup`), and `AppStateStore.resolveAutoTitle` (`Runtime/AppStateStore.swift:2347-2361`, cache lookup first), called from `applySessionAutoNaming` (:2234-2280, call at :2248).
- Remove: `clearSessionName` (`Runtime/WindowRuntime.swift:353-370`), from Sidebar Reset Name (`Views/SessionSidebarView.swift:376`).
- `loadFromDisk` (`Model/SessionNameCache.swift:185-200`) keeps every entry with a non-empty path and name.

**B. Automatically derived Session titles at home (in memory)**
- Reset Name at home: `clearSessionName` tries `ProjectNameResolver`, then falls back to `URL(fileURLWithPath: cwd).lastPathComponent` (`Runtime/WindowRuntime.swift:361-368`), which is the account short name at home.
- `ProjectNameResolver.resolve(at:)` (`ProjectName/ProjectNameResolver.swift:20-37`, rules in `Resources/project-name-rules.json`) runs for any cwd.
- The AI suggester runs for home: `applySessionAutoNaming` falls through to `scheduleNameSuggestion` (`Runtime/AppStateStore.swift:2255-2270`, scheduler ~:2292-2312). The model instructions (`ProjectName/SessionNameSuggester.swift:236-245`; prompt at :309) only decline "temporary folders, untitled folders, random hashes". Results are memoized per cwd for the process (`nameSuggestionMemo`, `Runtime/AppStateStore.swift:208-209`) and reapplied to later Sessions at home. `applyTabAutoNaming` (:2400, AI call ~:2450) also schedules for home.
- Already handled: the Tab chip shows `~` at home (`Util/TabTitleFormatter.swift:14-18`, #0142). That is the precedent for this issue.

**C. Projects (`projects.json`, iCloud when Shared)**
- New Project: `ProjectEditorViewModel.makeNewDraftReportingSuggestion` (`Model/ProjectEditorViewModel.swift:468-490`) defaults the root to `NSHomeDirectory()` and names it with `suggestedName(forRoot:)` (:157-161). That function excludes `/` (#0474) but not home.
- Save Session as Project: `SessionProjectCapture.capture` (`Model/SessionProjectCapture.swift:55-70`, `rootIsFallback` set only when no cwd is known), `derivedRoot` (:161-172), and `suggestedName(session:capture:)` (:218-227), which returns the root's basename.
- Display already shows home as `~` (`ProjectPicker.abbreviate`, `OpenQuicklyView.projectRows`).

**D. Ruled out**: there is no recent-folders list; the Git Status Pane persists nothing; Tab `titleOverride` is in memory only; the CLI and XPC have no rename verb. Not behind a feature flag (the Projects flag was removed in #0504).

Related: #0142, #0058, #0089, #0213, #0231, #0232, #0233, #0474, #0279.

### Adopted recommendation (user-approved 2026-10-27, for 1.3.4)

Add one shared predicate and enforce it in the stores and the naming chain, not at UI call sites: `NonProjectDirectory.contains(_ path: String, home: String = NSHomeDirectory(), temporaryDirectory: String = NSTemporaryDirectory()) -> Bool` in `BattyKit/Sources/BattyKit/Util/`. It standardizes the path first: strips a trailing slash, expands a literal `~`, and resolves the `/private` symlinks.

These are not project folders:
1. The account home (`$HOME`, literal `~`).
2. `/`.
3. Any top-level directory, meaning any path with one component (`/Users`, `/Volumes`, `/Applications`, `/Library`, `/System`, `/private`, `/usr`, `/tmp`, `/var`, `/opt`, ...). This is a structural rule, not a list.
4. Temp roots: `/tmp`, `/private/tmp`, `/var/tmp`, `/private/var/tmp`, and `NSTemporaryDirectory()`.

`~/Desktop`, `~/Documents`, `~/Downloads` and `~/Developer` stay nameable.

Behavior for a path that is not a project folder:
- `SessionNameCache.record` refuses the write. `loadFromDisk` drops such entries, so the next save purges them (no schema bump, no separate migration).
- `applySessionAutoNaming`: skip manifest rules and AI (cancel any in-flight suggestion) and resolve to `Session N`. `applyTabAutoNaming`: don't schedule AI.
- `clearSessionName`: fall back to `Session N`, never the basename.
- `ProjectEditorViewModel.suggestedName(forRoot:)` returns nil, so the draft is "Untitled Project". `SessionProjectCapture.capture` keeps the home root with `rootIsFallback = false` and adds a `notes[.root]` line: "This Session is in your home folder, which is not usually a Project root." Validation stays permissive.
- A rename at home still applies for the Session's lifetime; it just isn't remembered.

### Rejected alternatives

- "No manifest or `.git` means not a project": this would drop real project folders that have no manifest.
- Also excluding `~/Desktop`, `~/Documents` and `~/Downloads`: users do work in them.
- A Settings toggle.
- Forcing the Session title to `~` over a user rename.
- Checking at each call site instead of in the stores and the naming chain.
- A separate migration step (the load filter covers it).
