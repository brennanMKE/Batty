## Description

#0227 (session name stuck on the initial working directory) was fixed and verified manually, but has no automated UI-level coverage. The defect lived in the view→delegate wiring, which the BattyKit model unit tests cannot exercise — so only a UI test can guard against regression. Since UI tests are this project's release gate, add one.

## Expected behavior

A UI test that drives a real terminal `cd` and asserts the sidebar session chip updates:

1. Launch with a session in a recognized project folder; assert the chip shows the project name.
2. Create a new session; `cd` it to a non-project folder.
3. Assert the chip resets to `Session N` (and, optionally, that moving into a different project updates to that project's name).

## Notes

- Driving `cd` from XCUITest means typing into the terminal surface and waiting for the OSC pwd round-trip; allow for async settling before asserting chip text.
- Run on the Mac mini via `scripts/run-ui-tests.sh` (the suite locks the machine ~10 min).

## Resolution notes

> 🟢 Resolved 2026-05-30 — Added `BattyUITests/SessionCwdRenameTests.swift`; it drives a real `cd` and asserts the sidebar row renames into a project and resets out.

The test creates a `package.json` (so `ProjectNameResolver` resolves a known name independent of the directory basename), launches the app, types `cd <projectDir>` and asserts the `session-row.<name>` appears, then types `cd <plainDir>` and asserts it resets to `Session 1`. It uses the launch session (no explicit title) so cwd auto-naming stays live.

Running this for release prep also caught a real regression from the #0227 fix — see [[0227]] (explicitly-titled sessions were being clobbered) — and a pre-existing PaneFocusTests problem filed as [[0229]].

## Verification

- `scripts/run-ui-tests.sh BattyUITests/SessionCwdRenameTests` — 1 test passed (20.9 s).
