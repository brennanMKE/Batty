## Description

Child of #0646; depends on #0648. Two pieces: `batty serve <dir>`, a built-in static file server that reloads on file change and shows in a Server Pane, and a **web preview Pane** kind (WKWebView) so a served page or a dev site can be viewed inside Batty, not only in an external browser.

The use case is previewing locally the web pages made for Claude Artifacts and similar static sites, without reaching for `python3 -m http.server` and a separate browser window.

Feature request from the user (Brennan), 2026-11-17.

### Current state (checked against `main` at `3b5735c3`)

- No Pane kind renders web content. `PaneContentKind` has `terminal`, `git-status`, `process-status`, `lm-studio-dashboard`, `system-metrics`. Nothing under `BattyKit/Sources` or `Batty/` imports WebKit.
- Viewer Panes are in scope: the user asked for a Markdown Viewer Pane on 2026-10-19 (#0527, open) and a Scratch Pad (#0571, open).
- `docs/batty-cli-design.md`'s "Deliberately skip" list names "in-app browser automation". A preview Pane is a viewer the user looks at; it offers no CLI verbs to click, type into or script the page, so it does not cross that line.

## Expected behavior

### `batty serve <dir>`

```sh
batty serve ./site
```

- Starts an in-app static file server rooted at `<dir>` (resolved to an absolute path by the CLI, as `--path` is today) on a free port, bound to **127.0.0.1 only**, and shows it in a Server Pane (#0648) with the URL, state, request count if cheap, Open in Browser and Stop. Restart is not needed (there is no command to rerun); Stop shuts the listener.
- Serves `index.html` for a directory request and sensible MIME types. No directory listing beyond what is needed to find files (see Open questions). Never serves outside `<dir>`: path traversal (`..`, encoded variants, symlinks pointing outside) is refused.
- **Reload on file change:** when a file under `<dir>` changes, open preview Panes and connected browser tabs reload. Watching follows the existing FSEvents patterns (Git Status already debounces filesystem events), off the main actor.
- `--port N` picks a port; `--open` also opens the web preview Pane (or the browser, per Settings); placement follows #0648's Settings and `--split`. Re-running `batty serve` on the same directory reuses its server and Pane.
- The server lives as long as its Pane: closing the Server Pane stops it; quitting Batty stops it.

### Web preview Pane

- A new non-terminal Pane kind (name to be chosen, for example `web-preview`) hosting a `WKWebView` that shows one URL.
- Opened from the Server Pane (an "Open in Batty" button next to Open in Browser) and from the CLI (for example `batty pane split --view web-preview --url http://127.0.0.1:8083/`).
- Minimal chrome: the URL, Back, Forward, Reload, Open in Browser. No tabs, bookmarks or history beyond Back/Forward.
- Reloads when the static server signals a change.
- Loads `http://localhost`/`127.0.0.1` URLs by default. Whether to allow any URL is an open question.

### Rules

- Must respect `docs/pane-kinds.md`, `docs/view-hierarchy.md`, `docs/terminal-pane-requirements.md` and `docs/swiftui-observation-rules.md`. The WKWebView is an AppKit view inside the Pane body, so the z-order and event-routing constraints in `docs/terminal-pane-requirements.md` apply directly: neighboring terminal Panes must keep pointer input, keyboard, file drop, text drop and IME, and focus must move in and out of the web view cleanly. Run that doc's manual checklist. Setup, teardown and show/hide follow `docs/pane-view-lifecycle.md`: a hidden preview Pane releases or suspends its web content.
- The visual design is drafted under `docs/design/` and approved by the user before implementation (#0301's design-first gate).
- `Concepts.md` gains the web preview Pane; `batty capabilities --json` lists the new verb and options; the `batty-cli` skill gets a recipe (#0647).
- Behind a feature flag (`FeatureFlags`, Beta on / Prod off) until the release that ships it.

## Acceptance criteria

- `batty serve ./site` serves the folder on 127.0.0.1 at a free port and shows a Server Pane; the URL loads `index.html`.
- A request for `/../` or a symlink out of the root returns 403/404, never the file. The listener is not reachable on the Mac's LAN address.
- Editing a file under the root reloads an open preview Pane.
- The web preview Pane shows the served page, its Back/Forward/Reload/Open in Browser work, and the `docs/terminal-pane-requirements.md` checklist passes with it next to terminal Panes.
- Closing the Server Pane or quitting Batty frees the port.
- Unit tests cover path resolution and traversal refusal, MIME mapping, the change-to-reload signal (awaited, no sleeps) and port selection. A UI test covers opening and closing a preview Pane, checked with `./build.sh ui-typecheck`.

## Open questions

1. **Grammar.** `batty serve` is a new top-level verb (`docs/batty-cli-design.md` §4). Keep it, or make it `batty server serve <dir>` under #0648's noun?
2. **Server implementation.** `Network.framework` (`NWListener`) with a small HTTP/1.1 handler, or a vendored package? Adding a dependency to `BattyKit/Package.swift` needs the user's approval.
3. **Reload mechanism.** Inject a small script into served HTML that listens on Server-Sent Events or a WebSocket, or reload only the in-Batty preview Pane (no injection, browsers reload by hand)? Injection changes the served bytes, which matters when previewing pages exactly as they will ship.
4. **Security.** Bind to `127.0.0.1` only (proposed, and not configurable?). Serve dotfiles (`.git/`, `.env`)? Proposed: refuse dotfiles by default. Directory listings: off, or on for directories without `index.html`?
5. **Web preview scope.** localhost-only, or any URL? Any URL makes it a general browser Pane, which the "simple, Mac-first" bar argues against. Non-persistent `WKWebsiteDataStore` per Pane, or shared?
6. **Claude Artifacts fidelity.** Artifact pages load scripts from a fixed set of CDNs. Previewing them needs network access from the preview Pane to those hosts even if navigation stays on localhost. Allow subresources from any host while restricting top-level navigation?
7. **Kind name** for the preview Pane, and whether the Server Pane and preview Pane can be one Pane with a toggle instead of two.

## Notes

- The web preview Pane does not depend on the static server; it can show any dev server from #0648. Only `batty serve` depends on #0648's Server Pane.
- WKWebView content processes run out of process; their memory is not in Batty's own footprint, which Process Status / System Metrics users may notice.
