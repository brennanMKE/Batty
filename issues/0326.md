## Description

`docs/shortcuts.md` is the document a user (or engineer) consults to learn Batty's keyboard surface, and it is currently wrong in both directions: it is missing real bindings that exist in the app, and it lists bindings that don't exist. Surfaced by #0325's review; same doc-drift class as #0321, #0324, and #0325. All claims below were re-verified against source on 2026-08-08.

**1. The catalog omits twelve of the twenty-five actions.** `ShortcutAction` (`BattyKit/Sources/BattyKit/Shortcuts/ShortcutAction.swift`) has 25 cases. The Section 2 catalog table (`docs/shortcuts.md:93-107`) lists 13. Missing, with their actual defaults from `ShortcutAction.defaultBinding`:

| `rawValue` | Display name | Actual default |
|---|---|---|
| `splitFullHeightColumn` | Split Full-Height Column | `Cmd-Option-D` |
| `splitFullWidthRow` | Split Full-Width Row | `Cmd-Shift-Option-D` |
| `commandPalette` | Open Command Palette | `Cmd-Shift-P` |
| `openQuickly` | Open Quickly | `Cmd-Shift-O` |
| `layoutPicker` | Open Layout Picker | `Cmd-Shift-L` |
| `themeSelector` | Open Theme Selector | `Cmd-Shift-T` |
| `newWindow` | New Window | `Cmd-Shift-N` |
| `exitShell` | Exit Shell | `Cmd-Shift-X` (landed by #0309) |
| `resizeSplitLeft` | Move Split Divider Left | `Cmd-Ctrl-←` (landed by #0325) |
| `resizeSplitRight` | Move Split Divider Right | `Cmd-Ctrl-→` (#0325) |
| `resizeSplitUp` | Move Split Divider Up | `Cmd-Ctrl-↑` (#0325) |
| `resizeSplitDown` | Move Split Divider Down | `Cmd-Ctrl-↓` (#0325) |

(The #0325 review reported "nine" missing actions; the verified count is twelve — the reviewer's enumeration counted the four resize actions as one entry.)

**2. Two listed defaults are wrong.** Both tables (Section 1 at lines 80–81 and Section 2 at lines 106–107) say:

- Toggle Sidebar → `Cmd-Ctrl-S`. Actual (`ShortcutAction.swift:104-105`): key `"b"`, modifiers `[.command]` → **`Cmd-B`**.
- Toggle Bell Feed → `Cmd-Shift-N`. Actual (`ShortcutAction.swift:106-107`): key `"b"`, modifiers `[.command, .shift]` → **`Cmd-Shift-B`**.

The second is actively misleading: `Cmd-Shift-N` is now the real default for `newWindow`, so a user following the doc opens a new window instead of the bell feed.

**3. Two cited file paths predate a source move.** The doc links (lines 179, 225, 413, 415):

- `../BattyKit/Sources/BattyKit/BattyShortcuts.swift` — actual location `BattyKit/Sources/BattyKit/Commands/BattyShortcuts.swift`.
- `../BattyKit/Sources/BattyKit/TabRuntime.swift` — actual location `BattyKit/Sources/BattyKit/Runtime/TabRuntime.swift`.

All other paths in the doc's "Where to look" table verify as existing.

**4. The "v1" framing does not excuse the drift.** Section 1's table is headed "Default bindings shipped in v1 (from `ShortcutAction.defaultBinding`)" — a partial defence for omitting post-v1 actions, but not for the two wrong defaults, since the table names `ShortcutAction.defaultBinding` as its source and that source now says `Cmd-B` / `Cmd-Shift-B`. Section 2's catalog has no v1 scoping at all — it opens with "The full set is `ShortcutAction.allCases`" and so reads as current and complete, which it is not. The footer ("Document version: 1 — 2026-05-12") confirms the doc has not been revised since May.

**5. Related rot-prone citation in a test comment.** `BattyKit/Tests/BattyKitTests/SplitTreeResizeTests.swift:32` contains `// … matches PRD.md:162 / the #0325 worked example …`. Verified: this is the only surviving `.md:NNN` line-number citation in any Swift file in the repo (`grep -rn '\.md:[0-9]' --include='*.swift'`). The citation happens to still be accurate today (PRD.md:162 is the keyboard-resize line), but it is exactly the rot-prone comment reference `CLAUDE.md` bans, and #0325 removed the equivalent cite from `SplitTree.swift` — this one should go the same way (drop the line number; the surrounding prose already explains the invariant).

## Resolution notes

> 🟢 Resolved 2026-08-08 — `docs/shortcuts.md`'s catalog is re-derived from `ShortcutAction.swift` and now lists all 25 actions with correct defaults; the two wrong bindings, two stale paths, and a reversed description of the positional combos are fixed.

The table was rebuilt from source rather than patched row by row, and the section now tells future editors to do the same.

## Root cause

The catalog drifted because it was maintained by hand, row at a time, while `ShortcutAction.swift` kept growing. Twelve actions accumulated with no entry, and two rows kept defaults that had since changed — one of them, `toggleBellFeed` listed as `Cmd-Shift-N`, is now `newWindow`'s real default, so the doc actively misdirected rather than merely omitting.

## Fix

- **Section 2's table re-derived from `ShortcutAction.swift`** — all 25 cases, in source order, with display names taken verbatim from `displayName` (including #0325's "Move Split Divider …" renames) and Action-column descriptions taken from `BattyShortcuts.run(_:appStore:)`.
- **Twelve actions added**: `splitFullHeightColumn`, `splitFullWidthRow`, `commandPalette`, `openQuickly`, `layoutPicker`, `themeSelector`, `newWindow`, `exitShell` (#0309), and the four `resizeSplit{Left,Right,Up,Down}` (#0325).
- **Two defaults corrected** in both Section 1 and Section 2: `toggleSidebar` `Cmd-Ctrl-S` → `Cmd-B`, `toggleBellFeed` `Cmd-Shift-N` → `Cmd-Shift-B`.
- **Two stale paths corrected**: `BattyShortcuts.swift` → `Commands/`, `TabRuntime.swift` → `Runtime/`.
- **Section 1 re-scoped honestly** rather than deleted — it stays a curated highlight list, but its heading now says so and points at Section 2, whose intro states the count and instructs editors to re-derive on any `ShortcutAction` change.
- **`SplitTreeResizeTests.swift`'s `PRD.md:162` comment cite** replaced with a section citation, per `CLAUDE.md`'s ban on rot-prone references. It was the last `.md:NNN` cite in any Swift file.

Two further defects were found during the work and fixed:

- **`toggleSidebar`'s Action description was also wrong** — the doc said it flips `SidebarPreference.hiddenKey` in `UserDefaults`, but the shortcut posts `.battyToggleSidebar` and `RootWindowView` toggles a per-window `@SceneStorage` value. `hiddenKey` is now read in exactly one place, as a one-time migration seed, and written nowhere.
- **Section 3's account of the key handler was reversed and self-contradictory** — see Review.

## Review

Reviewer: `claude-opus-5`, two rounds.

Round 1 verified the table **programmatically** rather than by eye — extracting all 25 cases, display names and default bindings from source and diffing against the doc — and found zero mismatches, including modifier ordering. It then found the defect in the one place the implementer had certified as swept-and-accurate: **Section 3's step 4 stated the positional bindings backwards**, claiming `Cmd-1..9` selects tabs and `Cmd-Option-1..9` selects sessions, when `SettingsPreference.defaultCmdNumberTarget` is `.sessions` and the dispatch does the opposite. It contradicted this same document's Section 1 table. The same paragraph's rationale was wrong in both halves, the numbered list omitted the load-bearing content-window gate, and the dispatcher was named `run(_:store:)` rather than `run(_:appStore:)`.

Round 2 verified the rewritten six-step account line by line, and deliberately **spot-checked items the implementer had not named** to test whether the second sweep was real — the `#0062` narrative, the keybind-clear snippet, the `PasteDispatcher` comment, and the rewritten test citation all checked out.

## Verification

`scripts/build.sh unit` — **981 tests in 113 suites passed**, `** TEST SUCCEEDED **`, unchanged from baseline. `Configuration/Active.xcconfig` on Prod throughout.

Documentation-only apart from one test comment, so the test run proves the suite still compiles rather than anything about the document. **The real verification was the programmatic diff of the table against `ShortcutAction.swift`** — that is what establishes the catalog is now complete and correct.

## Gotchas

- **Re-derive the table; don't patch a row.** That instruction is now in Section 2's intro. Twelve missing actions is what patching produced.
- **Section 1 and Section 2 both carry a Default column**, so both can drift independently. That is the accepted cost of keeping a short user-facing list; both carried `Cmd-Ctrl-S` before this fix.
- **`Cmd-1..9` selects Sessions by default, not Tabs** — `Cmd-Option-1..9` selects Tabs. The pair swaps together via `SettingsPreference.defaultCmdNumberTarget`. This got documented backwards once already.
- **The same two wrong defaults are still stale elsewhere** — `PRD.md:151` and `:243`, `Concepts.md:143`, `docs/notifications.md:39`/`:331`/`:430`, `docs/ui-features.md:261`/`:301`. The last is phrased as a requirement to do the wrong thing. Out of scope here; filed separately.

## Expected behavior

`docs/shortcuts.md` matches `ShortcutAction.swift`: all 25 customizable actions listed with their real defaults, file links that resolve, and framing that does not present a stale snapshot as the current catalog. No `.md:NNN` line-number citations remain in Swift sources.

## Actual behavior

The catalog covers 13 of 25 actions, states two defaults that no longer exist (one of which now triggers a different action), links two files at pre-move paths, and one test comment carries a banned line-number citation.
