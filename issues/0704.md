# 0704 — The CLI and MCP can't read or clear the Bell Feed

| | |
|---|---|
| **Status** | open |
| **Module** | BellFeed / Session / Docs |
| **Platform** | macOS |
| **First seen** | 2026-11-20 |
| **Target** | 1.5.0 |

## Description

`batty notify` writes into the Bell Feed, but nothing in the CLI or the MCP server can read it back, mark it read, go to the Pane that rang, or mute a noisy Session. An agent that has just finished a task can't check what else rang while it worked, and a script can't clear the rows it posted. User decision 2026-11-20: add these verbs for 1.5.0.

- `batty bell list [--session ID] [--unread] [--json]`
- `batty bell clear [--session ID | --tab ID | --all] [--json]`
- `batty bell jump [--json]`
- `batty session mute [--session ID] [--json]` and `batty session unmute [--session ID] [--json]`

They are CLI verbs and MCP tools only. Nothing changes in the app's UI, defaults or menus (progressive disclosure: a CLI verb is the opt-in surface).

## Current state (checked against `main` at `1b2da996`)

- **Entry model.** `BellFeedEntry` (`BattyKit/Sources/BattyKit/Runtime/BellFeedStore.swift:10-63`) has `id`, `timestamp`, `windowID`, `sessionID`, `paneID`, `tabID`, `surfaceID`, `message?`, `summary?` (Foundation Models), `seen`, `repeatCount` and `firstOccurrenceAt`. It has **no title, body or source field.** `batty notify` stores `"title\nbody"` (or just the title) in `message` (`AppStateStore.formatNotifyMessage`, `AppStateStore.swift:2482`). A bare BEL has `message == nil`. An OSC 9/777 message and a CLI notify can't be told apart after recording. The system footprint entry uses `BellFeedEntry.systemID` for every id (`AppStateStore.swift:2507-2511`).
- **Order.** `BellFeedStore.entries` is newest-first, capped at 200 (see #0699's notes).
- **What the Feed shows.** Every row in `entries`, read and unread. Read rows stay until Clear Read or a visit. Muted Sessions' bells and bells seen at creation while Batty is active never become rows (`AppStateStore.swift:3083`, Concepts "Bell event"). Rows that leave the Feed are gone. `BellFeedStore` keeps no history. Only the opt-in capture log and `BellDecisionHistory` (diagnostics) keep more.
- **How rows become read or leave** (Concepts "Unread and Read"):
  - `AppStateStore.markBellSeen(id:)` (`AppStateStore.swift:2586`) marks one row read and decrements every Window's unseen counters. `markAllBellsSeen()` (`:2593`) does it for every row (popover Mark All Read, Window → Mark All Bells Read). Both leave the rows in the Feed and move no focus.
  - **Clicking a row** calls `markBellSeen` and then `jumpToBellEntry` (`:2615`). That brings the Window forward and visits the Tab. `WindowRuntime.visitFocusedTab()` (`WindowRuntime.swift:1344`) **removes** every row for that Tab (#0556).
  - **Clear Read** (`clearReadBells`, `:2603`) removes read rows only.
  - So no GUI action "marks seen like visiting" without also navigating. Visiting removes rows; Mark All Read marks them read. `bell clear` below uses the **Mark All Read semantics, scoped** (read, rows kept, counters decremented, no focus change). Moving focus is `bell jump`'s job, and removing read rows is Clear Read's (out of scope here).
- **Mute exists.** `SessionRuntime.notificationsMuted` (`SessionRuntime.swift:13`) is toggled only by the Sidebar context menu's Mute/Unmute Notifications (`SessionSidebarView.swift:561-565`, a direct property write). A Project stores it (`Project.notificationsMuted`, `ProjectSync`, restored at `WindowRuntime.swift:367`). Muting drops new bells (`AppStateStore.swift:3083, 3183`) and leaves existing rows alone. `TopologyPayload` does not report it.
- **CLI/XPC/MCP plumbing to copy.** `session remind` is the closest model:
  - XPC verb constant in `BattyXPCCore/XPCVerb.swift`, plus request and reply types in `BattyXPCCore/SessionRemindPayload.swift`.
  - Dispatch in `BattyKit/XPC/AppXPCService.swift` (`case XPCVerb.sessionRemind`, `:409`), into `AppStateStore.remindSessionForXPC` (`AppStateStore+Reminders.swift:298`).
  - The command in `batty/SessionRemindCommand.swift`, registered under `SessionCommand.swift`.
  - Annotations come from `CapabilitiesCommand.leafArchetypeByVerbPath` and `annotationsByArchetype` (`batty/CapabilitiesCommand.swift:170-252`). `CapabilitiesInputSchemaTests` fails for a verb path with no archetype. MCP tools come from the capabilities catalog (`batty/MCPToolCatalog.swift`, `session remind` → `session_remind`). Optional hint lines live in `batty/MCPInstructions.swift`, capped at 1500 characters by `MCPInstructionsTests.instructionsStayUnder1500Characters`.
  - XPC focus verbs (`focusSessionForXPC`, `:2152`) call `visitFocusedTab()` and `activateWindow`. They are the CLI's sanctioned exception to "don't switch the active Session".
- **#0699** (Jump to Latest Unread Bell shortcut, also 1.5.0 now) specifies the shared selection rule and the action. Nothing of it is on `main` yet.

## Expected behavior

### `batty bell list [--session ID] [--unread] [--json]` (read-only)

- Lists exactly the rows the Bell Feed shows, newest-first, in the Feed's order. That covers read and unread rows and the system entry. Nothing is marked read and no focus moves (Concepts rule 3: "Opening the list marks nothing read").
- `--unread` keeps only unread rows. `--session ID` keeps only that Session's rows, which drops the system entry. An unknown Session id exits `4`, as other verbs do.
- **No `--all` for `list`.** The Feed already is everything Batty keeps. Rows that left the Feed are gone, and diagnostics stay in Settings → Advanced → Diagnostics (the declutter goal). If a later need appears for suppressed bells, it belongs to the decision history, not this verb.
- `--json` returns an array of objects with these fields:
  - `id`.
  - `time`: the latest occurrence, ISO 8601 UTC.
  - `firstTime`: `firstOccurrenceAt`.
  - `windowID`, `sessionID`, `paneID` and `tabID`. All four are omitted for the system entry.
  - `title` and `body`. `title` is the first line of `message` and `body` is the rest, both omitted when the row has no message. That round-trips `batty notify --title --body` exactly.
  - `summary`, when present.
  - `source`.
  - `repeatCount`.
  - `seen`. It is the code name; the plain text says `unread`/`read`.
- `source` is one of `bell` (bare BEL), `osc` (OSC 9/777), `cli` (`batty notify`) or `system`. **This needs a new `source` field on `BellFeedEntry`**, set at each record site (the terminal bell/OSC intake, `recordCLINotification`, the footprint warning). It defaults on decode the way `repeatCount` does (custom `init(from:)`), to `bell` when `message` is nil and `osc` otherwise. `recordOrCollapse` must keep collapse matching unchanged, because source isn't part of the rule.
- Plain text is one line per row: `<id>  <local time>  unread|read  <Session title> › Pane N › <Tab label>  <summary ?? message first line>`, with `×N` when `repeatCount > 1`. It uses `BellFeedEntry.pathLabel` as the popover does. An empty Feed prints nothing and exits 0.

### `batty bell clear [--session ID | --tab ID | --all] [--json]` (mutating, idempotent)

- Marks the matching unread rows read, through `markBellSeen(id:)` per row, or `markAllBellsSeen()` for `--all`. Unseen counters, the toolbar glyph, the Tab-chip dots and the Session badges update exactly as Mark All Read updates them. The rows **stay in the Feed** as read. No focus, selection or Window order changes, and no row is removed.
- The targets are mutually exclusive (more than one is a usage error, exit `2`). With none, the default is the calling Session (`BATTY_SESSION_ID`). Outside Batty with no target, it is a usage error. It never silently clears everything.
- Unknown Session or Tab id: exit `4`. Nothing to mark: exit 0. `--json` returns `{"marked": N}`.
- The system entry is marked read only by `--all`, the same as Mark All Read.

### `batty bell jump [--json]` (mutating, activating)

- Runs the shared #0699 action, `jumpToLatestUnreadBell()`. It finds the newest unread non-system row in any Window and does exactly what a row click does: `markBellSeen` and then `jumpToBellEntry`. That brings the owning Window forward and activates Batty (like `session focus`), selects the Session, un-hides the Pane, focuses the Pane, selects the Tab and visits it, which removes that Tab's rows. Rows whose Window, Session, Pane or Tab is gone are marked read and skipped within the same call.
- **Nothing unread: a quiet no-op.** Exit 0, no output in plain text, `{"jumped": false}` in JSON. No beep, no activation and no state write. On success it prints the visited row's id; JSON returns `{"jumped": true, "id": …, "sessionID": …, "paneID": …, "tabID": …}`.
- Repeated calls walk unread rows newest to oldest, one Tab per call (the visit removes the Tab's rows; no cursor is kept).

### `batty session mute|unmute [--session ID] [--json]` (mutating, idempotent)

- Sets `SessionRuntime.notificationsMuted` to true or false for the target Session, which defaults to the calling Session. It makes the same write as the Sidebar's Mute/Unmute Notifications, so a Project-backed Session persists it the same way. Existing Feed rows are untouched. Muting stops new rows, and unmuting doesn't restore dropped bells. Muting an already muted Session succeeds and changes nothing.
- Unknown Session: exit `4`. Outside Batty with no `--session`: usage error.
- `batty list --json` and `batty session info --json` gain `"muted": true` on a muted Session, omitted otherwise. Plain text appends `muted`. This is the only way to read the state back.

### MCP and capabilities

- The tools are `bell_list`, `bell_clear`, `bell_jump`, `session_mute` and `session_unmute`, generated from the capabilities catalog like every other verb.
- New archetypes in `annotationsByArchetype`:
  - `bell list` → `list` (read-only, idempotent).
  - `bell clear` → a new `clear` archetype: not read-only, not destructive (rows stay), idempotent.
  - `bell jump` → a new `jump` archetype: not read-only, not destructive, **not** idempotent (each call moves to the next row).
  - `session mute` and `session unmute` → a new `mute` archetype: not read-only, not destructive, idempotent.
  - All of them are closed-world.
- Optionally add one `MCPInstructions` hint ("What rang: `bell_list`; go there: `bell_jump`."), but only if it fits under the 1500-character cap.
- If the work is not complete when 1.5.0 is cut, gate the new verbs behind a `FeatureFlags` flag (on in Beta, off in Prod) so they are absent from `capabilities` and MCP in Prod, per AGENTS.md "Release branches".

## Acceptance criteria

- [ ] `batty bell list` prints the Feed's rows in Feed order. `--unread` and `--session` filter, and `--json` carries every field above, with ISO 8601 UTC dates. An unknown Session exits 4. Listing marks nothing read.
- [ ] `BellFeedEntry.source` is recorded at every record site, and data without it decodes. Collapse behavior is unchanged.
- [ ] `batty bell clear` marks only the targeted unread rows read, keeps them in the Feed, updates every unseen counter, and changes no focus or selection. It rejects more than one target and rejects running with no target outside Batty.
- [ ] `batty bell jump` matches #0699's action, shares its code, skips dead rows within one call, and with nothing unread exits 0 and writes nothing.
- [ ] `batty session mute` and `unmute` set `notificationsMuted` idempotently, and `list` and `session info` report `muted`.
- [ ] `batty capabilities --json` lists the five verbs with the annotations above, and `batty mcp` exposes them as tools.
- [ ] The docs below are updated, and `CapabilitiesReferenceSiteTests` passes after regenerating `website/docs/cli`.
- [ ] `./build.sh` and `./build.sh unit` pass.
