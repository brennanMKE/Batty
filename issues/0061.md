# 0061 — Split does not inherit the focused pane's working directory

| | |
|---|---|
| **Status** | open |
| **Module** | Split / Pane |
| **Platform** | macOS |
| **First seen** | 2026-05-11 |

## Description

`Cmd-D` / `Cmd-Shift-D` (and the toolbar split buttons) create a new pane via `SplitTree.splitFocusedPane(direction:)`, which constructs a fresh `PaneRuntime()` with no working directory. The new pane's shell spawns at `$HOME` regardless of where the focused pane was working. This is exactly the inconsistency `#0057` fixed for new sessions, but the split path was missed — `#0057`'s fix was scoped to `AppStateStore.addSession`.

Expected behavior is identical to the new-session inheritance: capture the focused pane's active tab's `terminal.workingDirectory` (with `configuration.workingDirectory` fallback) at the moment of split, and thread it into the new pane's first tab. Matches the existing `Cmd-T` behavior (`PaneRuntime.addTab(inheritingCWDFrom:)`).

## Steps to reproduce

1. Open a session whose default tab is at `~`.
2. `cd ~/Developer/Batty`.
3. Hit `Cmd-D`.
4. **Observed:** new pane's shell prompts at `~`.
5. **Expected:** new pane's shell prompts at `~/Developer/Batty`.

## Implementation guidance

`SplitTree.splitFocusedPane`:

```swift
@discardableResult
public func splitFocusedPane(
    direction: SplitDirection,
    ratio: Double = 0.5
) -> PaneRuntime {
    let newPane = PaneRuntime()   // ← no CWD
    ...
}
```

Two paths, pick whichever has smaller blast radius:

1. Add an optional `inheritingFrom: PaneRuntime?` parameter to `splitFocusedPane`. When non-nil, read the source pane's active tab's CWD and pass it into the new `PaneRuntime` via the same `[TabRuntime(workingDirectory: cwd)]` explicit construction used in `AppStateStore.addSession`. Default the parameter to the focused pane (the natural source).
2. Or: read the focused pane's CWD inside `splitFocusedPane` itself before constructing the new pane.

Option 2 is the smallest diff — `splitFocusedPane` already knows `focusedPaneID`, so it can find the source. But it couples `SplitTree` to the active-tab lookup. Option 1 is cleaner.

Either way, update the call sites in `BattyCommands.swift` and `SessionDetailView.swift`'s toolbar buttons to either pass nothing (rely on default of "current focused pane") or pass the focused pane explicitly.

## Acceptance criteria

- `Cmd-D` / `Cmd-Shift-D` / toolbar split buttons create a new pane whose first tab inherits the focused pane's CWD.
- When the focused pane's CWD is nil/empty, fall back to today's default (no working directory → shell starts at `$HOME`).
- Existing `Cmd-T` new-tab inheritance is unchanged.
- Existing `addSession` CWD inheritance from `#0057` is unchanged.
- A unit test exercises the inheritance: set the focused pane's tab CWD, call `splitFocusedPane`, assert the new pane's first tab has the same CWD.
