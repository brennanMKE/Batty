- **Persistence is NOT delivered here** — the hidden flag does **not** survive relaunch yet, because workspace persistence itself isn't implemented (**#0221**, still open). The `Pane {isHidden}` Codable value type + `PaneRuntime.snapshot()` are groundwork so #0221 can carry it. See Relation.

## Description

Let a pane be **hidden** — its terminal removed from view entirely while its Ghostty surface stays alive and its logical position in the split tree is preserved — toggled with an eye icon (`eye` / `eye.slash` SF Symbols). Two entry points:

1. **In the pane's own title section** — an eye button to hide that pane.
2. **In the session sidebar** — the left column expands to list **all panes** under each session (a tree), and each pane row has the same eye toggle to hide/show it.

Because hiding a pane removes its title row, the sidebar pane list is the way to bring it back (hide from the pane; restore from the sidebar).

A hidden pane is **logically kept in place** (still a leaf in the split tree, view state retained, surface running) but is **ignored for layout dimensions** — visible siblings absorb its space, and newly split panes divide only the visible area. This must not regress existing split/layout behavior.

*(Context: an earlier idea was to collapse a pane down to just its title row with the terminal hidden — useful for vertically stacked panes. That's set aside in favor of full hide-with-retained-surface below. The "tap a notification to focus and expand" behavior from that idea still applies here — see Bell interaction.)*

## Desired behavior

- **Toggle:** `eye` (visible) ↔ `eye.slash` (hidden), shown in the pane title row and in the sidebar pane row. Toggling is instant; no confirmation.
- **Hidden pane:** its terminal + tab bar are not rendered and take **zero** layout space; the Ghostty surface (PTY/shell) keeps running in the background; the pane keeps its slot in the split tree.
- **Sidebar:** the session list expands to `Session → [Pane, Pane, …]`. A pane row shows enough to identify it (e.g. active tab title / index) plus the eye toggle and any unseen-bell badge. Selecting/activating a hidden pane's row (or its eye) restores it.
- **Restore:** un-hiding restores the pane's placement in the window using the retained surface reference — the same terminal, scrollback intact, no respawn.
- **Persistence:** the hidden flag and the pane's position survive relaunch (like the rest of the layout). Per existing policy the shell restarts fresh on relaunch, but the pane's hidden state and slot are restored.

## Layout / split impact — prevent regressions (the careful part)

Hidden panes are **excluded from dimension math but retained logically**:

- **Splitting:** when a new pane is created, compute sizes among **visible panes only**. A hidden pane must not receive a fraction of the space. (Directly interacts with **#0255** — even 1/n distribution should be 1/n of the *visible* panes.)
- **Rendering:** in `SplitLayout` (`SplitContainerView.swift`), a split node with a hidden child should give the visible child ~100% (hidden child 0), rather than honoring the stored `ratio`. Preserve the stored ratio so it's restored when the pane un-hides. Don't render a divider adjacent to a fully-hidden subtree.
- **Focus:** if the focused pane is hidden (or becomes hidden), move focus to a visible sibling; never leave focus on a hidden pane.
- **At least one visible pane:** a session must always have ≥1 visible pane. Disallow hiding the last visible pane (grey out its eye), or define the empty-session behavior explicitly.
- **Close / collapse:** closing the last *visible* tab of a pane, or the pane-collapse-on-last-tab-close path, must behave sanely when hidden siblings exist (the hidden sibling shouldn't silently take over or disappear).

## Bell / notification interaction

A hidden pane's surface stays alive and can still fire bells (BEL / OSC 9). Clicking that entry in the **bell feed** (`AppStateStore.jumpToBellEntry` → `focusPane(containingTabID:)`) must **un-hide** the pane, then focus its window → session → pane → tab as usual. Otherwise a hidden pane's belling terminal is only reachable via the sidebar eye — a dead-end we should avoid. The sidebar pane row should also carry the unseen-bell badge so hidden activity is visible.

## Technical notes / where this lives

- **Model:** add an observable `isHidden` to `PaneRuntime` (`BattyKit/Sources/BattyKit/Runtime/PaneRuntime.swift`) for live state, and mirror it into the persisted `Pane` value type so it round-trips through workspace persistence. Keep the split tree structure unchanged (hidden is a property of the leaf, not a tree-shape change).
- **Surface retention (architectural rule #1):** hiding must **not** tear down the surface — "View rebuilds must not destroy surfaces." The surface registry / `TerminalHostStore` already keeps surfaces alive for non-active sessions; hiding a pane should *remove/zero the placement* of its `AppTerminalView` (not release it) and restore placement on show. Read `docs/view-hierarchy.md` and `docs/terminal-pane-requirements.md` for the persistent-host and placement rules before touching this.
- **Layout:** the dimension exclusion lives in `SplitLayout` / `SplitContainerView.swift` and wherever split ratios are computed (`SplitTree.swift`, and #0255's even-distribution logic). This is the regression-critical area.
- **Sidebar:** `SessionSidebarView.swift` grows from a flat session `List` to a session→pane tree (e.g. `DisclosureGroup` or nested rows) with the eye toggle and bell badge per pane row.
- **Pane title row:** add the eye button to the pane's title section (`PaneView.swift`).
- **Observation rules:** the hide/show writes are event-origin (button taps) — fine — but re-read `docs/swiftui-observation-rules.md` since this touches focus/selection flow and geometry (moving focus off a hidden pane, restoring placement) which are exactly the audited paths.

## Open questions

- Sidebar pane-row label: show active tab title, tab count, or a pane index? (Panes aren't named today.)
- Should hiding a pane also be reachable from a menu / keyboard shortcut (a `ShortcutAction` case), or eye-icon-only for v1?
- Does an unseen bell on a hidden pane auto-restore it, or just badge it in the sidebar until the user restores? (Lean: badge only; don't auto-un-hide.)
- Multi-window: hidden state is per-pane, so it travels with the pane's window; confirm no cross-window surprises.

## Root cause

Feature work. Starting state: panes were always visible; no visibility concept, no sidebar pane list, no eye affordance.

## Fix

Eight parts, all in BattyKit:
- **Model:** `PaneRuntime.isHidden` (observable) for live state; a `Pane {id, isHidden}` Codable value type + `PaneRuntime.snapshot()` in `LayoutModel.swift` as persistence groundwork (not yet wired — see Gotchas).
- **Layout exclusion:** `SplitTree` gains `visibleLeafPanes`/`visiblePanes`/`isEntirelyHidden`; `countChainLeaves` returns 0 for hidden leaves and entirely-hidden perpendicular subtrees so the **#0255** equalization divides only visible panes (with a `total > 0` guard). `SplitContainerView` renders a hidden leaf as zero-size and gives a split's visible arm 100% with no divider, preserving the stored `ratio` for restore.
- **Sidebar:** `SessionSidebarView` expands to a `Session → [Pane]` tree; each pane row shows the active-tab title (or "Pane N"), the eye toggle, and the unseen-bell badge.
- **Pane title row:** an eye button in `PaneView`, disabled when only one pane is visible.
- **Surface retention (rule #1):** hiding drives `TerminalHostStore.setPlacement(isVisible: false)` for each of the pane's tabs, which sets the `AppTerminalView.isHidden = true` **without releasing** the view; un-hiding re-mounts the placeholder, which re-reports placement and re-shows the same view (scrollback/PTY intact — no respawn).
- **Focus:** `hidePane` moves focus to a visible sibling before hiding.
- **Bell un-hide:** `jumpToBellEntry` calls `showPane` first, so a hidden pane's belling terminal is reachable.
- **≥1 visible pane:** `hidePane` refuses to hide the last visible pane; the eye is disabled in that case.
- All hide/show is centralized through `AppStateStore`/`WindowRuntime` `hidePane`/`showPane` so every entry point drives the host (no view flips `isHidden` directly).

## Review

Reviewed by Opus (claude-opus-4-8), **two rounds**. Round 1 approved the model/layout/observation work but found a **blocker**: the first cut set `isHidden` and unmounted the `PaneView` but never hid the terminal `AppTerminalView` (the placeholder unmounts so `onGeometryChange` never fires; `updatePlacements` has no production caller; `hidePane` didn't touch `TerminalHostStore`), so the terminal stayed floating on screen — and the eye buttons wrote `isHidden` directly, bypassing `hidePane`. ## Gotchas

- **`isHidden` does not persist across relaunch yet.** Workspace persistence isn't implemented (**#0221**); `SplitTree` isn't Codable and `PaneRuntime.snapshot()` has no production caller. The `Pane {isHidden}` value type is groundwork so #0221 can serialize it. The issue's "survives relaunch" bullet is therefore **deferred to #0221**, not delivered here.
- **Hiding must go through `hidePane`/`showPane`.** Those drive `TerminalHostStore`; flipping `pane.isHidden` directly would leave the terminal `AppTerminalView` floating on screen (the round-1 blocker). Don't add a hide path that bypasses them.
- **`AppTerminalView.isHidden` isn't unit-testable** (needs libghostty); tests assert the `TerminalHostStore` placement record instead.
- Pane-close re-balancing remains out of scope (deferred with #0255); closing a pane doesn't re-equalize survivors.
