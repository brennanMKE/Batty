## Description

`BattyKit/Sources/BattyKit/Help/05-shortcuts.md:3` promises "Every shortcut Batty understands" — and the tables then list 13 of the 25 `ShortcutAction` cases. The 12 omitted actions' chords appear **nowhere else in the Help catalog either** (verified by grep across `BattyKit/Sources/BattyKit/Help/`), so a user reading in-app Help has no way to discover the command palette, Open Quickly, the layout picker, the theme selector's shortcut, keyboard split resizing, or the full-dimension splits at all. This is the same completeness defect #0326 fixed in `docs/shortcuts.md`, now in the catalog that ships inside the app.

The second half is the more valuable one: **nothing prevents this from recurring.** #0328's Gotchas records it plainly — "Nothing ties documented chords to `ShortcutAction.defaultBinding`. This drift will recur." #0326 and #0328 between them corrected shortcut documentation in more than thirty places across nine files, and the only thing stopping a thirty-first is care. The ask: a `BattyKitTests` test that parses the shipped Help catalog's shortcut tables and asserts every chord it names matches `ShortcutAction.defaultBinding` — failing loudly in the pre-commit gate (`scripts/build.sh unit`) instead of surfacing three issues later.

## Resolution notes

> 🟢 Resolved 2026-08-08 — the in-app Help catalog now lists all 25 shortcut actions, and a new test pins every documented chord in the repo to `ShortcutAction.defaultBinding` so this drift class fails in the pre-commit gate.

The test is the substantive half. #0326 and #0328 between them corrected shortcut documentation in **more than thirty places across nine files**; before this, the only thing preventing a thirty-first was care.

## Root cause

Two independent gaps.

The Help catalog's `05-shortcuts.md:3` claimed to list "Every shortcut Batty understands" while covering 13 of 25 actions. The missing twelve — `splitFullHeightColumn`, `splitFullWidthRow`, `commandPalette`, `openQuickly`, `layoutPicker`, `themeSelector`, `newWindow`, `exitShell`, and the four `resizeSplit*` — appeared **nowhere else in the catalog either**, so in-app Help never taught those chords at all.

Underneath that: nothing tied a documented chord to `ShortcutAction.defaultBinding`. Every shortcut correction in this project's history has been a manual sweep, and three of them reported themselves complete while missing something.

## Fix

**Part 1** — the twelve missing actions added to `05-shortcuts.md`'s existing Sessions/Panes/Tabs/Other tables. The page now covers all 25 catalog actions plus the 7 non-catalog rows (the positional `Cmd-1..9` pair, Settings, Help, Copy, Paste, Quit).

**Part 2** — `BattyKit/Tests/BattyKitTests/ShortcutDocsSyncTests.swift`, guarding three tables:

| Table | Correctness | Completeness |
|---|---|---|
| `Help/05-shortcuts.md` (4 subsection tables) | ✅ | ✅ |
| `docs/shortcuts.md` Section 2 (full catalog) | ✅ | ✅ |
| `docs/shortcuts.md` Section 1 (curated subset) | ✅ | — |

A test-local `proseDefault(for:)` renders `defaultBinding` in the docs' prose form (`Cmd-Shift-D`, `Cmd-Ctrl-←`) with fixed modifier order, deliberately independent of `ShortcutBinding.displayString`'s glyph renderer. Malformed rows are recorded failures rather than silent skips, and each parse carries a non-empty assertion so a restructured or renamed table fails loudly instead of passing vacuously.

Section 1 gets correctness but not completeness because its own prose says it is "a curated subset, not the complete catalog" — but a curated subset still has to state right chords.

**Deliberately not built:** generating the Help table from `ShortcutAction`. It would change how shipped content is authored and belongs in its own issue if wanted.

## Review

Reviewer: `claude-opus-5`, two rounds.

Round 1 treated the normalizer as the load-bearing risk — correctly, since a bug there would make *wrong* documentation pass, which is worse than no test. It verified `proseDefault` for all 25 actions two ways: case-by-case against `defaultBinding`, and transitively against the independently-authored Section 2 table row by row. It byte-checked the arrow glyphs as U+2190/2192/2191/2193 in both markdown files, confirmed the 25 rendered strings are mutually distinct, and verified all twelve new Help rows **by hand rather than through the test being reviewed**.

Its finding: `docs/shortcuts.md` **Section 1 was unguarded**, and the test's own doc comment was worded so it read as though correctness covered it. Rather than assert that from the header shape alone, the reviewer pulled #0326's fix commit `4bd44fc` and showed Section 1 is a *demonstrated* drift site — the wrong `Cmd-Ctrl-S`/`Cmd-Shift-N` pair had existed in both sections and needed separate corrections. So the branch guarded the copy that drifted and left the other exposed.

Round 2 mutated **all 13** Section 1 chords at once and confirmed exactly 13 failures, one per row, each resolving through `byDisplayName` rather than falling into the allow-list branch — ruling out the subtle vacuity mode where rows appear checked but aren't. It also renamed the table header to confirm the inline non-empty assertion fires, and verified the omitted `*TableIsNonEmpty` test could not have been reused anyway, since it asserts `count >= 25` and a 13-row subset can never satisfy that.

## Gotchas

- **The markdown table format is now load-bearing.** The guard parses `| Action | Default |` in the Help catalog and `| Action | Default | Notes |` / the 4-column `rawValue` table in `docs/shortcuts.md`, matched on exact header cells. Renaming a header column breaks the parse — which fails loudly by design, but is a surprise if you don't know why.
- **`proseDefault` is a second renderer, deliberately not `ShortcutBinding.displayString`.** `displayString` emits glyphs (`⌘⇧B`); the docs write prose (`Cmd-Shift-B`). Using the production renderer would have made the test agree with itself rather than with the docs.
- **Section 1 of `docs/shortcuts.md` is checked for correctness only.** Adding an action there is optional; stating its chord wrongly is not.
- **Six actions still have no explanatory Help page** — Command Palette, Open Quickly, Layout Picker, Theme Selector, New Window and Exit Shell appear in the shortcut table but are described nowhere else in the catalog. The guard cares about chords, not prose; writing those pages is separate work.
- **`Dictionary(uniqueKeysWithValues:)` in the display-name map would trap** if two actions ever shared a `displayName`. All 25 are distinct today; the risk is documented in the test rather than defended against.

## Expected behavior

- The in-app Help shortcuts page either lists every `ShortcutAction` (its own tables live up to the "Every shortcut" claim) or stops claiming exhaustiveness — the former is clearly better, since Help is the only in-app discovery surface for these chords.
- A unit test in `BattyKitTests` ties the Help catalog's stated chords to `ShortcutAction.defaultBinding`, so the next binding change that skips the docs fails the pre-commit gate.

## Actual behavior

The page claims completeness, omits 12 of 25 actions, and no automated check exists. The chords the page *does* state are currently all correct (fixed by #0328) — the defect today is completeness plus the missing guard, not wrong chords.

Any completeness assertion in the test needs to account for the tables mixing catalog and non-catalog rows.

### Design questions for the implementer (framed, not decided)

1. **What does the test parse?** If it parses the markdown tables as they are, the table format becomes load-bearing — a benign reformat breaks the test. Acceptable, or should the shortcut tables in `05-shortcuts.md` be *generated* from the catalog instead, making drift structurally impossible?
2. **Correctness only, or completeness too?** Asserting every chord the page names is right is the cheap half; asserting every `ShortcutAction` appears is what fixes this issue's Part 1 permanently. If completeness is asserted, decide how non-catalog rows (positional pair, Cmd-C/V, system chords) are exempted.
3. **Is `docs/shortcuts.md` covered too?** It doesn't ship in the app, but it drifted identically (#0326). Same test, second target file, or left out?
4. **Chord rendering.** `ShortcutBinding.displayString` (`ShortcutBinding.swift:81-95`) emits glyph form (`⌘⇧B`), while the Help catalog writes prose (`Cmd-Shift-B`). The test needs its own prose renderer or a normalization step — or the shared renderer becomes the thing both the test and any generation step use.

### Precedent

`BattyKit/Tests/BattyKitTests/ThirdPartyLicensesSyncTests.swift` is a usable template for the mechanics: it reads the real files off disk via a `#filePath` walk-up to the repo root (no fixture copies), exactly what this test needs to reach `05-shortcuts.md`. What it does *not* provide is the comparison — it pins two files byte-identical, whereas this test must parse a table and compare semantically against `defaultBinding`. Its second test (guarding against a vacuously-passing empty comparison) is a pattern worth copying too.
