## Description

Batty pins libghostty-spm to revision `c69c34354e511af7a3e6d7e5e2a4fa2fed4b90ff` (= tag **1.2.2**) in `BattyKit/Package.swift:31-34`. Latest upstream is **1.3.2** (`b146b73`, published 2026-07-27), vendoring ghostty commit `35e1a0160c4f6797e1bb1ef8e7a2b8c6b114ab58`. The stale pin blocks the headline fix of the #0285 umbrella: 1.3.2 adds `TerminalSurfaceOptions.envVars` (per-surface env vars, wired to `ghostty_surface_config_s.env_vars` in `TerminalController+Surface.swift:34-35` @ 1.3.2), which is exactly what #0287 needs to collapse Batty's one-`ghostty_app_t`-per-Tab design into a shared controller.

The bump also picks up ~2 months of vendored ghostty (8 autopublish rounds). That window is not empty: ghostty upstream acknowledged leaks in the 1.2.3 era — a PageList leak and a styles leak triggered by TUIs emitting many styles, with Claude Code CLI named as a trigger (ghostty-org/ghostty#10289) — with fixes landing for 1.3. Batty is pinned *behind* those. Whether they touch the graphics half of the footprint is unverified; the source investigation found no renderer or Metal changes in the wrapper's Swift layer across 1.2.2 → 1.3.2, so the memory-relevant delta is entirely in the vendored xcframework.

Wrapper API additions across the range (`git log 1.2.2..1.3.2`): per-surface `envVars` (#32), prompt navigation (#30), host-managed output queueing (#29), foreground PID / tty (#27), scrollbar action (#37), arm64e slices, and **namespaced xcframework headers** (`Headers/libghostty/`) — the last is a possible import-path break worth checking during the bump.

Files to update:

- `BattyKit/Package.swift:31-34` — the pinned revision.
- `BattyKit/Package.resolved` — resolved pin.
- `Batty.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` — the app workspace's resolved pin.

Acceptance: builds clean (`scripts/build.sh`), `scripts/build.sh unit` passes, the app runs, no behavior regressions.

## Relation

## Notes

- The namespaced-headers change (`Headers/libghostty/` in the xcframework) may require import-path adjustments — flag and fix as part of the bump.
- The `wait-after-command` verification comment in `TabRuntime.swift:172-183` cites the old pinned revision explicitly; it may need updating after the bump.
- 1.3.2 does **not** add per-surface `command` or `wait_after_command` — that gap is tracked separately as #0292 and does not block this bump.
- One small fix in the range is unrelated to graphics: `Fix AppKit selection copy leak (#23)` is a C-string leak in `readSelection`, kilobytes.
