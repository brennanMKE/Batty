# 0512 — Git status scanner can deadlock against a git subprocess that writes enough to stderr

| | |
|---|---|
| **Status** | open |
| **Module** | Git Status pane |
| **Platform** | macOS |
| **First seen** | 2026-10-14 |

## Description

`ProcessGitStatusScanner.run(_:)` drains stdout to EOF, *then* drains stderr, *then* waits. Both are pipes with a finite kernel buffer. If the child fills stderr while the parent is still blocked in `readDataToEndOfFile()` on stdout, the child blocks writing stderr, never closes stdout, and the parent blocks forever. The existing comment at `:591-593` identifies the *other* deadlock (reading after `waitUntilExit()`) and fixes that one; the two-pipe case is still open.

Found by an external review of `v1.1.0..ad239f9e` — review id `20261014T193749Z-Batty-883c427`, finding 2 of 5 (medium, correctness, confidence high).

## Steps to reproduce

Not reproducible with a plain `git status`, which writes nothing to stderr. It needs a repo whose git configuration makes git emit more than one pipe buffer (64 KB on Darwin) of stderr before stdout closes — e.g. a noisy `core.fsmonitor`/credential helper, or a `GIT_TRACE`-style variable in the app's environment.

## Expected behavior

Both pipes are drained concurrently, so neither can wedge the other, and the scan either completes or fails.

## Actual behavior

`BattyKit/Sources/BattyKit/Runtime/GitStatusPaneContent.swift:594-596` reads stdout to EOF, then stderr, then waits. With a full stderr buffer the scan never returns; the scanning task is stuck until `tearDown()` terminates the child.

## Notes

- Fix: drain both file handles on separate background queues and join them before `waitUntilExit()`. That is the standard two-pipe pattern and keeps the function synchronous, which is what the call sites expect.
- **Not fixed here:** the review also noted "there is no execution timeout to recover the scan." That is a design change (what the pane should show for a hung `git`, and whether `terminateAndWaitBriefly`'s existing reap path covers it), not part of this defect. Filed as a note rather than silently bolted on.
