## Background

`TerminalViewState` (the `@Observable` class consumed from BattyKit's SwiftUI views) currently conforms to **4 of 12** `TerminalSurfaceViewDelegate` sub-protocols (`Title`, `GridResize`, `Focus`, `Close`). The remaining sub-protocols (`Bell`, `DesktopNotification`, `Pwd`, `CommandFinished`, `ProgressReport`, `OpenURL`, `HoverLink`, `Resize` columns/rows) are reachable only at the AppKit `TerminalView.delegate` level, which our SwiftUI consumer doesn't expose. Additionally, `TerminalSurface.sendText(_:)` — the only public-ish way to inject text into a running surface — is `internal`, not `public`, and there's no public path through `TerminalController` or `TerminalViewState` to reach it.

See `delegate-plumbing.md` for the full analysis.

## Implementation notes

- Mirror the existing pattern in `Sources/GhosttyTerminal/State/TerminalViewState+Delegate.swift` — one extension that conforms to multiple delegate protocols, each with one or two lines updating the corresponding published property.
- `TerminalSurface.sendText(_:)` is the existing internal method; `TerminalController` already has the `surface` instance internally (it owns the controller→surface relationship). The public `sendText(_:)` on `TerminalController` should be a one-line forwarder.
- `TerminalViewState.send(_:)` is purely ergonomic — saves consumers from having to dig into `viewState.controller.sendText(...)`. Optional but worth it for API tidiness.
- Don't change libghostty.a or the binary target. This issue is purely additive Swift on top of the existing wrappers.
- Don't break source compatibility. Other libghostty-spm consumers should still build.

## Root cause

Two unrelated gaps in `libghostty-spm`'s SwiftUI surface:

1. **Eight of the twelve `TerminalSurfaceViewDelegate` sub-protocols were unreachable from `TerminalViewState`.** The four already wired (`Title`, `GridResize`, `Focus`, `Close`) used the standard pattern of conforming `TerminalViewState` to the sub-protocol and storing the event into an `@Observable` property. The other eight (`Bell`, `DesktopNotification`, `Pwd`, `CommandFinished`, `ProgressReport`, `OpenURL`, `HoverLink`, `Resize`-by-cols/rows) were dispatched correctly inside `TerminalCallbackBridge` but had no consumer-facing forwarding.

2. **`TerminalSurface.sendText(_:)` was `internal`,** so SwiftUI consumers had no way to inject text into a running surface. The original issue posited that `TerminalController` "owns the controller→surface relationship" and could expose a one-line forwarder, but that's not how the package is actually structured (see Gotchas).

## Fix

In the fork (`brennanMKE/libghostty-spm`, branch `batty-delegates`, commit `ef88eed`):

- **`TerminalSurface.sendText(_:)` is now `public`.** No semantic change; only the access level moved.
- **New `TerminalSurfaceLifecycleDelegate` sub-protocol** with `terminalDidAttachSurface(_:)` / `terminalDidDetachSurface()`. The per-platform `TerminalSurfaceCoordinator` notifies the delegate after a successful surface rebuild and before tearing it down. This gives `TerminalViewState` (which sits in the delegate slot) a way to hold a weak reference to the live `TerminalSurface`.
- **`TerminalViewState` gained `@Observable internal(set)` properties** for `bellCount`, `lastBellAt`, `lastDesktopNotification{Title,Body,At}`, `workingDirectory`, `lastCommandExitCode`, `lastCommandDurationNanos`, plus an `@ObservationIgnored weak var surface: TerminalSurface?`.
- **`TerminalViewState` gained a public `send(_ text: String)`** that forwards to `surface?.sendText(text)`. Skipping `TerminalController.sendText(_:)` is intentional (see Gotchas).
- **`TerminalViewState+Delegate.swift` adds five new conformances** (`Bell`, `DesktopNotification`, `Pwd`, `CommandFinished`, `Lifecycle`) mirroring the existing 4-delegate pattern.

In Batty:

- **`BattyKit/Package.swift` switches** from `.package(url: "https://github.com/Lakr233/libghostty-spm", exact: "1.0.1777879537")` to `.package(path: "../../libghostty-spm")`. Once `batty-delegates` is pushed to `brennanMKE/libghostty-spm` on GitHub, this should be swapped to `.package(url:..., revision: "ef88eed")` for reproducibility on other machines (follow-up commit).

Verified with the canonical `xcodebuild -scheme Batty -destination 'platform=macOS' build` and `swift test --package-path BattyKit` (43/43 tests passing) against the local fork.

## Gotchas

- **The issue's premise that `TerminalController` "already has the surface instance internally" is incorrect.** The `TerminalController` owns the `ghostty_app_t` and creates raw `ghostty_surface_t` handles via `createSurface(...)`, but it doesn't retain `TerminalSurface` wrappers — those live on `TerminalSurfaceCoordinator`, which is a per-platform-view internal type. A `TerminalController.sendText(_:)` forwarder would have ambiguous semantics in the multi-surface case (one controller can back N surfaces). The fix instead exposes `sendText` on the wrapper class directly and threads the active surface to `TerminalViewState` via a new lifecycle delegate. Net result for consumers is the same: `viewState.send(text)` works, and that's the API the downstream issues actually needed.
- **`weak var surface: TerminalSurface?` is `@ObservationIgnored` deliberately.** The lifecycle protocol drives it explicitly (single source of truth is the coordinator), and observers don't need to react to attach/detach — they react to the events that flow through the other delegate methods. Including it in observation would create a churn whenever the platform view re-attaches.
- **`swift test` against the fork fails on this toolchain with `no such module 'Testing'`** — this is a pre-existing condition on a clean checkout of `main`, not a regression from these changes. Verified by stashing the fork edits and re-running. The fork builds cleanly via `xcodebuild -scheme GhosttyTerminal -destination 'generic/platform=macOS' build` and downstream BattyKit tests all pass, which is what we actually need.
- **The `path:` form is intentional for local development** (matches how `SlidingTabs` is consumed per #0002) but means a fresh checkout on a different machine needs `brennanMKE/libghostty-spm` cloned to a sibling directory before `xcodebuild` can resolve the package graph. The follow-up swap to URL+revision after pushing `batty-delegates` is what makes the dependency portable.
- **`TerminalViewState` already imported `Foundation` only transitively via `SwiftUI`.** The new `lastBellAt: Date?` etc. force a direct `import Foundation` in `TerminalViewState+Delegate.swift` so `Date()` resolves cleanly without relying on the platform module.
