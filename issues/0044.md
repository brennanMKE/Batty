## Background

`TerminalViewState` (the `@Observable` class consumed from BattyKit's SwiftUI views) currently conforms to **4 of 12** `TerminalSurfaceViewDelegate` sub-protocols (`Title`, `GridResize`, `Focus`, `Close`). The remaining sub-protocols (`Bell`, `DesktopNotification`, `Pwd`, `CommandFinished`, `ProgressReport`, `OpenURL`, `HoverLink`, `Resize` columns/rows) are reachable only at the AppKit `TerminalView.delegate` level, which our SwiftUI consumer doesn't expose. Additionally, `TerminalSurface.sendText(_:)` — the only public-ish way to inject text into a running surface — is `internal`, not `public`, and there's no public path through `TerminalController` or `TerminalViewState` to reach it.

See `delegate-plumbing.md` for the full analysis.

## Implementation notes

- Mirror the existing pattern in `Sources/GhosttyTerminal/State/TerminalViewState+Delegate.swift` — one extension that conforms to multiple delegate protocols, each with one or two lines updating the corresponding published property.
- `TerminalSurface.sendText(_:)` is the existing internal method; `TerminalController` already has the `surface` instance internally (it owns the controller→surface relationship). The public `sendText(_:)` on `TerminalController` should be a one-line forwarder.
- `TerminalViewState.send(_:)` is purely ergonomic — saves consumers from having to dig into `viewState.controller.sendText(...)`. Optional but worth it for API tidiness.
- Don't change libghostty.a or the binary target. This issue is purely additive Swift on top of the existing wrappers.
- Don't break source compatibility. Other libghostty-spm consumers should still build.
