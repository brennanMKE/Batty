## Description

Shortcut documentation is wrong in eight files, and one instance is written as a requirement — `docs/ui-features.md:301` states "The `Cmd-Shift-N` shortcut must open the Bell Feed popover," which is now a requirement to do the wrong thing. `Cmd-Shift-N` is `newWindow`'s shipped default (`ShortcutAction.swift:117`), so a future implementer following that line could "correct" working code to match a stale doc, and a reader following any of the bell-feed citations gets a chord that opens a new window instead.

Three classes of drift, all verified against `BattyKit/Sources/BattyKit/Shortcuts/ShortcutAction.swift` and `BattyKit/Sources/BattyKit/Settings/SettingsPreferences.swift` (line citations in Notes):

1. **`toggleSidebar` documented as `Cmd-Ctrl-S`** — actual default `Cmd-B` (`ShortcutAction.swift:105`; changed by #0129). 2 locations.
2. **`toggleBellFeed` documented as `Cmd-Shift-N`** — actual default `Cmd-Shift-B` (`ShortcutAction.swift:107`; changed by #0134), and `Cmd-Shift-N` now belongs to `newWindow`. 7 locations, including the requirement line.
3. **Cmd-number dispatch inverted** — docs state `Cmd-1..9` selects Tabs and `Cmd-Option-1..9` selects Sessions. The shipped default is the reverse: `SettingsPreference.defaultCmdNumberTarget` is `.sessions` (`SettingsPreferences.swift:28`, introduced by #0131), so `Cmd-1..9` selects Sessions and `Cmd-Option-1..9` selects Tabs (`BattyCommands.swift:116-119` and `:376-379`). #0326 fixed this exact inversion in `docs/shortcuts.md`; it survives in 13 more locations, including the module-conventions table in `issues/Issues.md` itself.

Plus one stray from the sweep: `docs/supacode-feature-review.md:118` gives the command palette as `Cmd-P`; the actual default is `Cmd-Shift-P` (`ShortcutAction.swift:109`).

The history explains the drift: all of these were correct when written. At #0070 (955c77f), `toggleSidebar` *was* `Cmd-Ctrl-S` and `toggleBellFeed` *was* `Cmd-Shift-N`; #0129 (2026-05-18) and #0134 (2026-05-20) moved the code, and #0131 added the Cmd-number preference with `.sessions` as default. The docs never followed. PRD.md §6.3 is the likely origin the others transcribed from.

## Resolution notes

> 🟢 Resolved 2026-08-08 — every live shortcut claim in the repo now matches `ShortcutAction.defaultBinding`. The only stale instance left is `website/changelog.html`'s v1.0.0 entry, deliberately preserved as a historical record.

Scope grew twice during the work: the in-app Help catalog was folded in when it turned out to carry the same wrong chords (it ships inside the app, so it was the highest-impact instance), and `README.md` — the project's front page — was caught only by the review's own sweep.

## Root cause

Not a single mistake. Every stale line was **correct when written**: #0070 shipped `Cmd-Ctrl-S` and `Cmd-Shift-N`, then #0129, #0131 and #0134 moved the bindings in code without touching the prose. Nothing in the repo ties a documented chord to `ShortcutAction.defaultBinding`, so the drift accumulated silently across five files and two years of issues.

The sharpest instance was `docs/ui-features.md:301`, phrased as a requirement — *"The `Cmd-Shift-N` shortcut must open the Bell Feed popover"* — which had become a requirement to do the wrong thing, since `Cmd-Shift-N` is `newWindow`'s default.

## Fix

Four classes of correction, applied across 16 files:

- **`toggleSidebar`** `Cmd-Ctrl-S` → `Cmd-B`.
- **`toggleBellFeed`** `Cmd-Shift-N` → `Cmd-Shift-B`.
- **`commandPalette`** `Cmd-P` → `Cmd-Shift-P` (one location).
- **Cmd-number inversion**, the largest class: the default is `Cmd-1..9` = **Sessions**, `Cmd-Option-1..9` = **Tabs**, per `SettingsPreference.defaultCmdNumberTarget == .sessions`. Corrected in `PRD.md` (×8), `Concepts.md` (×4), `docs/multi-window-design.md`, `issues/Issues.md`'s module table, the Help catalog (×4), `Ship-v1.md` (×2), and `README.md`.

Also fixed along the way:

- **`ShortcutAction.swift`'s own header comment** carried the same inversion and claimed the pair "stays fixed" — wrong since #0131 made it swappable.
- **`Ship-v1.md`** said "Cmd-Option-N for new"; `newSession` is plain `Cmd-N`.
- **`docs/ui-features.md:301`** rewritten action-first so it names `toggleBellFeed` rather than hardcoding a chord that can rot again.
- **`docs/multi-window-design.md`** line-number citations into `ShortcutAction.swift` replaced with symbol references, after the header edit shifted them mid-work for the second time.
- **`Concepts.md:52`**'s rationale, which had claimed "Cmd-Shift-Number is reserved by macOS" — overbroad, since only `Cmd-Shift-3/4/5` are screenshot hotkeys and the catalog ships ten `Cmd-Shift-<key>` defaults.

**Deliberately left:** `website/changelog.html:250` (v1.0.0 is dated 2026-05-13; #0134 was first seen 2026-05-16, so the entry was accurate for the release it describes — amending it would make the history lie), and `batty-getting-started.md:280` (external libghostty reference, not a Batty claim).

## Review

Reviewer: `claude-opus-5`, two rounds, both of which found real defects.

Round 1 verified **all 40+ chord claims** across the 16 files mechanically against source rather than by eye, and confirmed every Cmd-number rewrite was in the correct direction. It then found two things:

- **`README.md:12` — the project's front page — still said "Cmd-1–9 for tabs".** It had survived three separate sweeps because it uses an **en-dash**, which every `Cmd-1..9` grep missed. The implementer's claim that only the changelog remained was therefore false.
- **`Concepts.md:52` transferred an iTerm2 rationale onto the chord it was written to argue against.** `issues/0042.md:29` credits iTerm2 for *Cmd-Option*-Number and `:31` recommends `Cmd-Option-1..9`; the correction re-attached that credit to the default `Cmd-1..9`, so the line asserted the reverse of the repo's own recorded reasoning. This issue's own text had warned that rationale should be rewritten or dropped, not transcribed.

Round 2 re-ran the sweep with **its own** regex families rather than reusing the implementer's — matching any non-alphanumeric separator, spelled-out ranges, and glyph forms across `.md`, `.html`, `.swift`, `.json`, `.xml`, `.xcstrings`, `.txt`, `.plist` and `.strings` — and found no misses.

## Gotchas

- **`Cmd-1..9` selects Sessions; `Cmd-Option-1..9` selects Tabs.** This has now been documented backwards in at least fifteen places and corrected twice in review. If you are writing it down, check `SettingsPreference.defaultCmdNumberTarget` first.
- **Grep for chords with a permissive separator class.** `Cmd-1..9`, `Cmd-1–9` (en-dash), `⌘1–9`, and "one through nine" all appear in this repo. A sweep that only matches one form will report itself complete and be wrong — that happened three times on this issue alone.
- **The in-app Help catalog under `BattyKit/Sources/BattyKit/Help/` ships inside the app.** It is the highest-impact place for a wrong shortcut and is easy to forget when sweeping "the docs".
- **`website/changelog.html` is a historical record.** Its entries describe what shipped in a given release and must not be amended to match current behaviour.
- **Nothing ties documented chords to `ShortcutAction.defaultBinding`.** This drift will recur. A test asserting that every chord named in the Help catalog matches the catalog would prevent the user-facing half of it.

## Expected behavior

Every shortcut chord stated in `PRD.md`, `Concepts.md`, `docs/`, `issues/Issues.md`, and the website matches `ShortcutAction.defaultBinding` and the actual Cmd-number dispatch, or is explicitly qualified as customizable/swapped. Requirement-phrased lines describe behavior in terms of the bound action, not a hardcoded chord.

## Actual behavior

23 locations across eight files state stale chords or the inverted Cmd-number mapping as unqualified fact. Full inventory below.

### Adjacent finding: the source file's own header comment is inverted

`ShortcutAction.swift:5-7` reads "Cmd-1..9 (tab activation), Cmd-Option-1..9 (session selection), Cmd-C, and Cmd-V stay fixed — positional and pasteboard standards (see issue #0070)." The parenthetical labels describe the non-default (`.tabs`) configuration, and "stay fixed" is only half-true since #0131 — the pair is not rebindable in Settings → Shortcuts but does swap via Settings → General → "Cmd-1…9 switches". Code comment, not docs, but a reader checking source hits it first; same fix pass should catch it.

### Concepts.md:52's rationale claim, checked

The parenthetical says "Cmd-Shift-Number is reserved by macOS for screenshot hotkeys." Checked: only `Cmd-Shift-3/4/5` are macOS screenshot shortcuts; 1, 2, and 6–9 are free. The claim is overbroad as stated (though avoiding the family because three of nine collide is a defensible design note). Separately, the catalog now ships ten `Cmd-Shift-<key>` defaults (D, [, ], B, P, O, L, T, N, X), so "we avoid Cmd-Shift" no longer describes the app's chord vocabulary — the rationale should be rewritten or dropped when the line is fixed, not transcribed.

### Judgment calls for the implementer (framed, not decided)

- **`docs/ui-features.md:301`** — is the requirement that *the Bell Feed opens on its bound shortcut* (fine — update the chord to `Cmd-Shift-B` and keep the "customizable" sentence), or a requirement about that specific chord (stale — rewrite)? The neighboring sidebar section (`ui-features.md:445/:456/:467`) already uses the correct `Cmd-B` with `[0129]` citations, so the file has a house style to match.
- **`website/changelog.html:250`** — the v1.0.0 entry (2026-05-13) predates #0134 (2026-05-20), so `Cmd-Shift-N` was accurate for the release it describes. Amending a historical changelog vs. annotating it (or leaving it) is a judgment call; it is the only user-facing web copy on the list.
