# 0328 — Shortcut docs contradict the shipped defaults in 23 places across eight files, one phrased as a requirement

| | |
|---|---|
| **Status** | open |
| **Module** | Docs / Website |
| **Platform** | macOS |

## Description

Shortcut documentation is wrong in eight files, and one instance is written as a requirement — `docs/ui-features.md:301` states "The `Cmd-Shift-N` shortcut must open the Bell Feed popover," which is now a requirement to do the wrong thing. `Cmd-Shift-N` is `newWindow`'s shipped default (`ShortcutAction.swift:117`), so a future implementer following that line could "correct" working code to match a stale doc, and a reader following any of the bell-feed citations gets a chord that opens a new window instead.

Three classes of drift, all verified against `BattyKit/Sources/BattyKit/Shortcuts/ShortcutAction.swift` and `BattyKit/Sources/BattyKit/Settings/SettingsPreferences.swift` (line citations in Notes):

1. **`toggleSidebar` documented as `Cmd-Ctrl-S`** — actual default `Cmd-B` (`ShortcutAction.swift:105`; changed by #0129). 2 locations.
2. **`toggleBellFeed` documented as `Cmd-Shift-N`** — actual default `Cmd-Shift-B` (`ShortcutAction.swift:107`; changed by #0134), and `Cmd-Shift-N` now belongs to `newWindow`. 7 locations, including the requirement line.
3. **Cmd-number dispatch inverted** — docs state `Cmd-1..9` selects Tabs and `Cmd-Option-1..9` selects Sessions. The shipped default is the reverse: `SettingsPreference.defaultCmdNumberTarget` is `.sessions` (`SettingsPreferences.swift:28`, introduced by #0131), so `Cmd-1..9` selects Sessions and `Cmd-Option-1..9` selects Tabs (`BattyCommands.swift:116-119` and `:376-379`). #0326 fixed this exact inversion in `docs/shortcuts.md`; it survives in 13 more locations, including the module-conventions table in `issues/Issues.md` itself.

Plus one stray from the sweep: `docs/supacode-feature-review.md:118` gives the command palette as `Cmd-P`; the actual default is `Cmd-Shift-P` (`ShortcutAction.swift:109`).

The history explains the drift: all of these were correct when written. At #0070 (955c77f), `toggleSidebar` *was* `Cmd-Ctrl-S` and `toggleBellFeed` *was* `Cmd-Shift-N`; #0129 (2026-05-18) and #0134 (2026-05-20) moved the code, and #0131 added the Cmd-number preference with `.sessions` as default. The docs never followed. PRD.md §6.3 is the likely origin the others transcribed from.

## Expected behavior

Every shortcut chord stated in `PRD.md`, `Concepts.md`, `docs/`, `issues/Issues.md`, and the website matches `ShortcutAction.defaultBinding` and the actual Cmd-number dispatch, or is explicitly qualified as customizable/swapped. Requirement-phrased lines describe behavior in terms of the bound action, not a hardcoded chord.

## Actual behavior

23 locations across eight files state stale chords or the inverted Cmd-number mapping as unqualified fact. Full inventory below.

### Adjacent finding: the source file's own header comment is inverted

`ShortcutAction.swift:5-7` reads "Cmd-1..9 (tab activation), Cmd-Option-1..9 (session selection), Cmd-C, and Cmd-V stay fixed — positional and pasteboard standards (see issue #0070)." The parenthetical labels describe the non-default (`.tabs`) configuration, and "stay fixed" is only half-true since #0131 — the pair is not rebindable in Settings → Shortcuts but does swap via Settings → General → "Cmd-1…9 switches". Code comment, not docs, but a reader checking source hits it first; same fix pass should catch it.

### Concepts.md:52's rationale claim, checked

The parenthetical says "Cmd-Shift-Number is reserved by macOS for screenshot hotkeys." Checked: only `Cmd-Shift-3/4/5` are macOS screenshot shortcuts; 1, 2, and 6–9 are free. The claim is overbroad as stated (though avoiding the family because three of nine collide is a defensible design note). Separately, the catalog now ships ten `Cmd-Shift-<key>` defaults (D, [, ], B, P, O, L, T, N, X), so "we avoid Cmd-Shift" no longer describes the app's chord vocabulary — the rationale should be rewritten or dropped when the line is fixed, not transcribed.

### Judgment calls for the implementer (framed, not decided)

- **`docs/ui-features.md:301`** — is the requirement that *the Bell Feed opens on its bound shortcut* (fine — update the chord to `Cmd-Shift-B` and keep the "customizable" sentence), or a requirement about that specific chord (stale — rewrite)? The neighboring sidebar section (`ui-features.md:445/:456/:467`) already uses the correct `Cmd-B` with `[0129]` citations, so the file has a house style to match.
- **`website/changelog.html:250`** — the v1.0.0 entry (2026-05-13) predates #0134 (2026-05-20), so `Cmd-Shift-N` was accurate for the release it describes. Amending a historical changelog vs. annotating it (or leaving it) is a judgment call; it is the only user-facing web copy on the list.
