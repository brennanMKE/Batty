# 0579 — Background Sets has no keyboard navigation, so arrow keys select nothing and Return doesn't pick an image in a Choose… sheet

| | |
|---|---|
| **Status** | open |
| **Module** | Settings / Theme |
| **Platform** | macOS |
| **First seen** | 2026-11-11 |

## Description

The Background Sets tab of the Background Images window and of every **Choose…** sheet can only be used with the mouse. The arrow keys don't move a selection between thumbnails, and Return doesn't pick the selected image in a Choose… sheet. My Images, the tab next to it, already supports both. Background Sets should work the same way: arrow keys move the selection across every set in reading order, Return in a Choose… sheet picks the selected image exactly as a click does, and VoiceOver can find, read and activate each image. Child of [#0574](0574.md), and a follow-up from the #0576 review ("Judged non-blocking", round 1).

**Depends on #0576 landing.** `BackgroundSetsView` and the tab picker exist only on branch `issue/0576` today. They are not on `main` yet. Start this work only once #0576 has been squash-merged, including its fix for the review's "latest pick wins" bug.

## What exists today (branch `issue/0576`, checked 2026-11-11)

**My Images** (`BattyKit/Sources/BattyKit/Views/BackgroundImagesView.swift`, the same on `main` apart from the tab gating):
- The grid's `ScrollView` is `.focusable()`, `.focusEffectDisabled()` and `.focused($gridFocused)`. It handles `.onKeyPress` for the four arrows, `.return` (`activateSelection()`: pick mode only) and Delete / Forward Delete (manage mode only: Remove…).
- `move(_:columns:)` uses `ProjectPickerGridCursor` (`BattyKit/Sources/BattyKit/Model/ProjectPickerGridCursor.swift`) with one section. The column count comes from the `GeometryReader` around the grid. The first arrow press starts from the selection, then from the current background, and falls back to the first cell.
- Focus goes to the grid from `.defaultFocus`, `.onAppear` and `.onChange(of: model.entries.isEmpty)`, and when the segmented control switches back to My Images (`tabBinding`'s setter). All of these are gated on `tab == .myImages`.
- UI test `BackgroundImagesWindowTests.testArrowKeySelectsACellOnTheFirstOpen` covers the arrow key on the first open.

**Background Sets** (`BattyKit/Sources/BattyKit/Views/BackgroundSetsView.swift`):
- No `.focusable`, no `@FocusState` and no `.onKeyPress`. The `selected: HostedImageKey?` `@State` is set only by `click(_:key:)` from `.onTapGesture`.
- Thumbnails are laid out per catalog, then per set, each set in its own `LazyVGrid` with `GridItem(.adaptive(minimum: 170))`. There is no single column count to hand to a cursor.
- In pick mode, `click` calls `hosted.select(image, catalogURL:)`, awaits the returned task and calls `onPick(path)`. In manage mode a click only selects.
- Switching to Background Sets moves focus nowhere: `tabBinding` sets `gridFocused` only for `.myImages`, so focus stays on the segmented control or wherever it was.
- Each cell is `.accessibilityElement(children: .contain)` with identifier `background-sets.cell.<image id>`. It has no label of its own, no `isSelected` trait and no activation action, so VoiceOver can't pick an image. My Images cells have the same gap, because they also select through `.onTapGesture` only.
- #0576's plan item 8 said "clicking a cell (or Return on a selected cell)". The implementation left Return out on purpose (#0576 `## Fix`: "Return on a selected Background Sets cell does not pick (click only)").

**App-wide key handling.** `Batty/BattyApp.swift` installs one local `.keyDown` monitor: `BattyShortcuts.handle(event) ? nil : PlainShellKeyRewrite.rewrite(event)`.
- `BattyShortcuts.handle` (`BattyKit/Sources/BattyKit/Commands/BattyShortcuts.swift`) returns `false` straight away unless `AppStateStore.keyWindowIsContentWindow()` holds, which means the key window is in `nsWindowMap`. The Background Images window (`BackgroundImagesWindowController`, an `NSHostingController`) is not a registered content window, and neither is Settings. So customizable shortcuts and the Cmd-digit bindings never see keys typed there.
- The Choose… sheets come from SwiftUI `.sheet` in `TerminalBackgroundControls`, shown from Settings (`SettingsView`), the Pane and Session sheets (`SessionSidebarView`) and the Project Editor (`ProjectEditorView`). The plan must confirm that a sheet over a content window is key as its own window and is not in `nsWindowMap`. If it were, a user shortcut bound to an arrow or Return would take the key before the grid saw it. That would affect My Images in the same sheet today too.
- `PlainShellKeyRewrite.rewrite` only touches Return when the first responder is an `AppTerminalView`, so it never rewrites a key aimed at this grid.
- The sheet's Cancel button has `.keyboardShortcut(.cancelAction)` (Escape). No button in the window or sheet has `.defaultAction`, so a Return handled by the grid doesn't compete with a default button.

## Expected behavior

1. **Focus.** Switching to Background Sets with the segmented control (click, or keyboard with Full Keyboard Access) moves keyboard focus to the Background Sets grid, the same way switching back to My Images focuses its grid. Switching back to My Images still focuses My Images. Nothing is fetched because focus moved: thumbnails load as they do now, and no full-size image is fetched (#0574 decision 5).
2. **Arrow keys.** Left/Right move to the previous/next image in reading order, crossing from the end of one set to the start of the next and across catalogs. Up/Down move by row, and from the top or bottom row of a set into the nearest column of the neighbouring set (the multi-section rule `ProjectPickerGridCursor` already implements for the Open Project picker). Moves clamp at the first and last image and never wrap. With nothing selected, the first arrow press selects the first image. The column counts must match what the adaptive grid actually shows at the current window width.
3. **Visible selection.** The selected cell shows the same outline a clicked cell shows today, and the grid scrolls so the selected cell is fully visible after each move. The 460-point-high sheet can't show three sets at once.
4. **Return in a Choose… sheet** does exactly what a click on the selected cell does, through the same code path:
   - **Downloaded image:** the sheet closes and the background changes at once.
   - **Image not yet downloaded:** the full-size download starts (only now, #0574 decision 5), the cell shows progress and Cancel, the sheet stays open, and the background changes only when the download finishes.
   - **Image already downloading:** Return reuses the running download and doesn't start a second one (`select` returns the running task).
   - **Failed image:** Return tries again, as a second click does.
   - **Latest pick wins** (#0576 review round 1, Required item 1, as landed with #0576). A Return pick is a pick like any click, so a later click or Return on another image, a My Images pick, Cancel or closing the sheet supersedes it, and its result is dropped. Moving the selection with the arrow keys is *not* a pick: it neither supersedes nor cancels a download already running.
5. **Return in the Background Images window** (manage mode) does nothing, as a click there only selects, and starts no download. Delete and Forward Delete do nothing in Background Sets in either mode, since hosted images can't be removed there.
6. **Escape** still cancels the Choose… sheet, through its Cancel button.
7. **VoiceOver / accessibility.**
   - Each image is one element VoiceOver can land on, with a label made of its title, its credit if any, its size and its status ("Available offline", "In use", downloading with progress, or the failure reason).
   - The selected image carries the `isSelected` trait.
   - In a Choose… sheet, each image is a button whose default action (VO-Space) picks it exactly as a click or Return does. In the Background Images window, its action selects it.
   - The Cancel button of a downloading cell and the banner's Retry button stay reachable as their own elements.
   - Set and catalog titles are headings, so VO-Command-H jumps between sets.
   - Existing accessibility identifiers (`background-sets.cell.<id>`, `.progress`, `.cancel`, `.failed`, `.available`, `.in-use`, `background-sets.set.<id>`) stay unchanged so `BattyUITests/BackgroundSetsTests` keeps working.
8. **No conflict with app shortcuts.** In the Background Images window and in every Choose… sheet (Settings, Pane, Session, Project Editor), the arrow keys and Return reach the grid and run no Batty shortcut, and Cmd-digit doesn't switch Sessions or Tabs in the window behind.
9. **Observation rules.** Key handlers and the focus change on tab switch are event-origin writes. Nothing writes observed state from `body` or from layout or geometry callbacks (`docs/swiftui-observation-rules.md`). The column count used by the cursor is read per pass, as My Images does, not stored from a geometry callback.

## Actual behavior

In Background Sets, the arrow keys select nothing and Return does nothing, in both the window and a Choose… sheet. Switching to the tab leaves focus on the segmented control. VoiceOver reads the cell's texts but can't activate a cell, so no hosted image can be chosen without a mouse or trackpad.

## Acceptance criteria (user-verifiable)

Run these with the built-in catalog reachable (after #0575 deploys) or with the UI-test fixture catalog.

1. File → Background Images…, click **Background Sets**, then press Right Arrow without clicking anything else: the first thumbnail is outlined. Further Right/Left/Up/Down presses move the outline, crossing from one set into the next, and the view scrolls to keep it visible. Nothing downloads (no progress appears in any cell).
2. In that window, press Return on a selected image that isn't downloaded: nothing downloads and nothing changes.
3. Pane gear → Choose… → Background Sets, arrow to an image that isn't downloaded, press Return: the cell shows progress and Cancel, the sheet stays open, and when the download finishes the sheet closes and the Pane shows the image. The same works from Settings → Appearance → Choose… and from a Session's and a Project's background Choose….
4. In a Choose… sheet, arrow to an already-downloaded ("Available offline") image and press Return: the sheet closes at once with that image applied.
5. In a Choose… sheet, press Return on image A (downloading), then arrow to image B and press Return on it. When A's download finishes later, the background is B, not A.
6. In a Choose… sheet, press Return on image A (downloading), then just arrow away without pressing Return: A keeps downloading and, when it finishes, A is applied.
7. Escape closes a Choose… sheet and leaves the background unchanged, including while a download is running.
8. Switch between My Images and Background Sets several times: after each switch the arrow keys work in the tab that's showing without a click first.
9. With VoiceOver on, in a Choose… sheet on Background Sets: VO-Command-H moves between set titles, VO-arrow reads each image's title, size and status, and VO-Space on an image picks it the same way Return does.
10. My Images keyboard behaviour is unchanged: arrows, Return in a sheet, Delete in the window.

## Notes

- **Reuse, don't fork.** `ProjectPickerGridCursor` already handles several sections with different column counts (`ProjectPickerGridCursorTests`). Background Sets maps to it as one section per set, in catalog order. The flat ordering of `HostedImageKey`s and the section column counts belong in a small pure helper that unit tests can call. A Return or a click should land in one function, so the "latest pick wins" rule from #0576 covers both without a second copy.
- **Adaptive columns.** The adaptive `GridItem` decides its own column count. Either compute the count from the width the way My Images does (`GeometryReader`, read per pass) and use a matching fixed column layout, or derive it from the same width formula. Arrow-key movement must agree with what's on screen at every window width.
- **Tests.**
  - Unit (BattyKit): the helper that flattens catalogs and sets into cursor sections (empty sets skipped, a catalog with a problem and no sets contributes nothing, order follows `hosted.catalogs`).
  - Unit: a Return-initiated pick goes through the same latest-pick-wins path as a click (hold A, Return-pick A, pick B, release A, only B delivered), with the fake fetcher's holds and the returned tasks. No sleeps (AGENTS.md "Asynchronous tests").
  - UI tests in `BattyUITests/BackgroundSetsTests` (compile with `./build.sh ui-typecheck`; they run in the daily VM run): arrow key selects on Background Sets after the tab switch; Return in a Pane Choose… sheet downloads and applies a not-yet-downloaded fixture image; Return on the fixture's missing full-size file shows the failure and keeps the sheet open.
- **Out of scope:** My Images' own VoiceOver gaps (no `isSelected` trait, no activation action) and its missing scroll-to-selection are the same pattern. Fix them here only if the shared cell modifier makes it free. Otherwise file them separately.
- **Help.** If keyboard use is documented anywhere in `BattyKit/Sources/BattyKit/Help/11-backgrounds.md` by then, add Background Sets to it. It isn't today, on `main` or on `issue/0576`.
