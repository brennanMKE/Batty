## Description

The user wants a fourth hosted Background Set: space and sci-fi, with spaceships, nebulas and stars. `docs/background-image-prompts.md` is the file Codex reads to generate the images. It has prompts only for the three existing sets. Add **Set 4** with eight prompts (01–08) in the style of sets 1–3. Point "What to generate now" at the new set's eight images only. Reconcile the new set with the doc's rule against star fields.

User request (2026-11-11, verbatim):

> "I want to add another background image set. This one will be a space/sci-fi set with cool space ships, nebulas and stars. Basically super cool space shots. Update the markdown file we will share with Codex to generate the images."

**Scope.** This issue changes `docs/background-image-prompts.md` only. Codex generates the images, thumbnails and `website/backgrounds/catalog.json` entries later, following the doc's "Output" section, and regenerates `website/backgrounds.html` with `tools/build-backgrounds-page.py`. None of that is part of this issue, and no image or catalog change lands here.

## Expected behavior

`docs/background-image-prompts.md` (checked on `main` at `3b78562`, 2026-11-11):

1. **A new `## Set 4: <name>` section** after Set 3 (which ends at line 189), laid out like sets 1–3:
   - A name in the style of the others: "Future Cities", "Cool Vehicles", "Beautiful Landscapes". For example "Deep Space", or "Space Odyssey". The planner or the user picks the name.
   - A `Palette:` line, such as deep navy and violet with small cool-white highlights and a restrained accent of nebula teal or magenta.
   - A one-line note like Set 2's (line 107-108): every spaceship is an original, unbranded design.
   - Eight numbered prompts, each headed by a bold, backticked path `<folder>/0N-<slug>.png`. The folder is the set name in kebab case (`deep-space/`) under `website/backgrounds/`.
   - A spread of subjects in the user's three themes:
     - **spaceships:** a lone cruiser in silhouette against a nebula; a small craft leaving a soft engine trail; a ship in orbit over the night side of a planet
     - **nebulas:** a wide, soft emission nebula low in the frame; a dark dust lane edged with faint glow
     - **stars and space:** a ringed planet's limb at the bottom of the frame; a distant galaxy as a soft smudge; a planetary horizon at sunrise
   - Keep each prompt's subject in the right side and bottom third, as the universal rules require.
2. **"What to generate now"** (lines 9-12) currently says images 01–05 exist and to generate 06–08 in each set ("nine new images"). Rewrite it: sets 1–3 are complete, so generate only the eight Set 4 images, 01 through 08.
3. **Intro** (lines 3-7): "Prompts for the 24 images in the three hosted background sets". Change it to 32 images in four sets, or reword it so it carries no count.
4. **Reconcile the star-field rule.** The universal block (lines 44-56), which "Add this block to every prompt" (line 42) puts on every image, says "Avoid fine, busy, high-frequency detail such as … small repeating patterns or star fields, especially in the calm area". Sets 1 and 3 go further and ask for "no stars" (lines 88, 148, 170). A space set can't do without stars, so the doc must resolve this without weakening the rule for the other sets. Options for the planner:
   - Add a short "Set 4 exception" paragraph, or a sentence in each Set 4 prompt: stars are allowed but sparse, soft, dim and slightly out of focus, a handful rather than a field. No dense or sharp pinpoint star field, no Milky Way band across the frame, and none in the upper-left two-thirds calm area. There the sky stays a smooth dark gradient or a soft, low-contrast nebula wash.
   - Nebulas follow the same rules as the aurora in Set 3, prompt 4 (line 167-170): dim, wide and smooth, without filaments, sharp edges or bright cores near white.
   - Spaceships: smooth, simple hull forms lit by a thin rim light. No dense greebles or panel detail, which is the "fine, busy detail" the rules ban.
   - "Dark overall … nothing near pure white" matters most here, since stars and engine glows tend to come out pure white.
5. **Real and franchise designs.** The universal rule says "no real vehicle makes or models: every design is original and unbranded" (lines 54-55). For spaceships, extend that in Set 4's note: no real spacecraft (ISS, Shuttle, Starship and the like), no agency or mission markings, and no ship that resembles a recognizable film, TV or game design. The "no recognizable real landmarks" rule should cover planets too. Use fictional planets, not a recognizable Earth from orbit or Saturn, unless the user wants those.
6. The "Output" section (lines 14-38) needs no change. Its file-name, thumbnail, catalog and page steps already apply to a new set. Check that its example names (`06-name.png`, `01-skyline-fog.png`) still read correctly when "What to generate now" names a new set's 01–08. The catalog step says "add each new image to its set … after the last one", and a new set needs a new `{ "name": …, "images": [ … ] }` entry appended to `sets`. Add a sentence for that.
