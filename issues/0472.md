## Description

This is the core of Projects (#0469) and of #0371: turning a saved `Project` (#0471) into a live Session. The new Session is titled with the Project name and pinned, colored with the Project color and pinned. Its Panes have the declared topology and each Pane's declared kind. Each Terminal Pane has its declared Tabs, each in its own directory resolved against the Project root. Today none of that is possible in one action. `PaneLayout.apply(to:)` creates only Terminal Panes, because every branch calls `SplitTree.splitFocusedPane(direction:inheritingFrom:)` (`Model/PaneLayout.swift:132-209`), which has no `kind` parameter. `WindowRuntime.addSession(title:workingDirectory:)` (`Runtime/WindowRuntime.swift:185-214`) always builds a single-Tab Terminal Pane.

This issue adds an `openProject` path with no UI of its own. #0475 (picker and menu), #0477 (CLI) and #0474 (Save & Open) call it, and unit tests and the UI-test driver drive it directly. Startup commands are **not** run here (#0473). This issue builds the Tabs and leaves them at their prompts.

## Expected behavior

**1. Build the tree from a `ProjectLayout`.**

- Replaying the topology must produce **the same tree shape and the same ratios as performing the equivalent splits by hand**, per the #0255 chain-equalization rule (`Model/SplitTree.swift:204-210`). Go through `SplitTree.splitPane(id:direction:ratio:command:kind:processStatusPid:path:contentFactory:isSessionSelected:)` (`:418-428`), which is the kind-aware entry point. For a topology equal to a `PaneLayout` preset, the result must match what `PaneLayout.apply` produces today. That makes this the generalization of `apply` that #0371 asked for. Either generalize `PaneLayout.apply` to take a per-slot kind, or write a topology replayer and re-express `apply` through it. Do not fork a second copy of the ten split recipes.
- **Slot 0 may be non-terminal.** `PaneLayout.apply` keeps the existing first Pane as `primary` and never changes its kind (`PaneLayout.swift:134`), and `PaneRuntime.kind` drives content construction at `init` (`Runtime/PaneRuntime.swift:93-121`). Build the first Pane with the right kind up front, rather than mutating a Terminal Pane in place. `PaneRuntime.init(id:tabs:…kind:isSessionSelected:contentFactory:)` (`:93-101`) already supports this.
- **Git Status** Panes get `path:` = the Project's repository folder resolved against root (#0471's resolver). **Process Status** Panes pass no pid, so they follow the split-source Pane's active Tab (`SplitTree.swift:345-355`). **System Metrics** and **LM Studio Dashboard** take no options.
- **Terminal Panes get their declared Tabs**: one `TabRuntime` per `ProjectTab`, with `workingDirectory:` resolved against root and `titleOverride:` set from the Tab title when one is given (`Runtime/TabRuntime.swift:127-140`). The first Tab is active. `SplitTree.makePane` today gives a new Terminal Pane exactly one Tab inheriting the source's cwd (`SplitTree.swift:369-374`, terminal branch of `makePane`), so the implementation needs a way to supply the Pane's Tabs. Either the split API accepts pre-built Tabs, or Tabs are appended after the split through `PaneRuntime`'s existing Tab-add path. Choose one and keep `TabRuntime.attachContext(paneID:sessionID:)`'s id wiring intact (`TabRuntime.swift:160-182`).
- Every Terminal Tab is a normal shell Tab. Do **not** use the per-Tab `command:` override (`TabRuntime.swift:28-33`, `:247-283`). That override *replaces* the shell with the command (`command = …` plus `wait-after-command`), which is the opposite of the approved design, where the command is typed into a shell and the Tab stays at the prompt afterwards (#0473).
- **Missing directories.** If the root no longer exists, fail the open with a clear user-facing error that names the path. Do not silently open a `$HOME` Session with the Project's name. If a Tab's or repository's relative directory is missing but the root exists, fall back to the root for that Tab, log it, and still open.

**2. Session identity.**

- Title = Project name, `titleOverride = true`, so cwd auto-naming leaves it alone (`AppStateStore.applySessionAutoNaming` honors `titleOverride`, `Runtime/AppStateStore.swift:1933-1945`). Do **not** write `SessionNameCache`. Opening a Project is not a rename.
- Color = the Project's `SessionColor`, pinned through `WindowRuntime.setSessionColor(id:to:)` (`WindowRuntime.swift:155`), which sets `colorOverride`.
- `SessionRuntime` gains an in-memory `projectID: UUID?`. It is informational only, never persisted, and nothing writes it back to the Project.
- The Session is created **and selected before** the non-terminal Panes are constructed, or each Pane receives the correct `isSessionSelected`. Otherwise non-terminal content starts in the wrong active/suspended state (`SplitTree.splitPane` doc comment on `isSessionSelected`, #0349; `docs/pane-view-lifecycle.md`).
- The Session is added through the same targeting as `AppStateStore.addSession` (`AppStateStore.swift:1082-1100`): `defaultTargetWindow()` (#0439), plus the `session_created` watch event.

**3. Find-and-focus vs. open another copy.** `AppStateStore.openProject(id:, mode:)` with `mode` either `.focusExistingOrOpen` (the default: if any Window has a Session whose `projectID` matches, select it and bring its Window forward, the same way `focusSessionForXPC` does at `AppStateStore.swift:1412-1419`; otherwise open a new Session) or `.openNew` (always open another copy). Return the Session and whether it was newly created, so callers (picker hint, CLI output) can report which happened. A helper reports which Projects currently have an open Session, for the OPEN badge and the File-menu check marks.

**4. Sidebar folder glyph.** A Project-backed Session's Sidebar row shows a small folder glyph. Today the row's icon is `rectangle.split.3x1` tinted with the Session color (`Views/SessionSidebarView.swift:255-263`). Either swap that icon for a folder symbol tinted with the Session color, or add a small trailing glyph. Match artboard 3 (`issues/0469/Opened.dc.html`). The glyph renders only when `projectID != nil`, so it is inert by construction with the flag off (nothing sets `projectID`), but the row code should still read the flag so the gate-site list is complete. Give it an accessibility identifier (for example `session-row.project-glyph`) for #0478.

**5. UI-test driver.** Add `UITestDriver` intents so #0478 can open a Project without UI. One seeds a Project into the store from JSON (only when the flag is on). The other opens a Project by name, with a mode. The existing intents are listed in `Testing/UITestDriver.swift:236-254`.

**6. Flag gate.** `openProject` and the driver intents are no-ops that log when `featureFlags.projects` is false. Append these sites, and the Sidebar row, to #0470's gate-site list.

## Acceptance criteria

- For each `PaneLayout` case with all-Terminal slots, opening a Project built from that preset yields a tree whose shape and ratios equal `PaneLayout.apply` on a fresh single-Pane Session. Assert by comparing the two trees, not against hard-coded numbers. `BattyUITests/LayoutTests.swift`'s `dumpSplitTree` S-expression is the existing precedent for describing a tree.
- A mixed-kind Project (for example `mainTopTwoBottom` with Terminal, Git Status and System Metrics, and a 2×2 grid with a non-terminal slot 0) yields the declared kind in each slot.
- A Terminal Pane declared with three Tabs has three Tabs in declared order, with resolved working directories (`TabRuntime.workingDirectory` / `terminal.configuration.workingDirectory`) and title overrides. A Tab declared `".."`-escaping falls back to the root.
- Git Status receives the resolved repository path.
- The Session title equals the Project name with `titleOverride == true`. The color equals the Project color with `colorOverride == true`. `projectID` is set. `SessionNameCache` is unchanged. Use a fixture cache that already holds a non-default entry for the root path, so the "unchanged" assertion is not vacuous.
- `.focusExistingOrOpen` selects the existing Session the second time without creating a new one. `.openNew` creates a second Session. Both are tested across two Windows.
- A missing root returns an error and creates no Session.
- **All unit tests inject `contentFactory: { _ in nil }`** (or the equivalent seam), so no test spawns a real `FSEventStream`, subprocess or sampling `Task`. The explicit-factory branch must run first (`SplitTree.swift:341-344`, #0304's trap). No surfaces are mounted in unit tests.
- With `FeatureFlags(projects: false)`, `openProject` creates nothing and the Sidebar never shows the glyph.
- No sleeps or polling in tests (`AGENTS.md` "Asynchronous tests").
- `./build.sh unit` passes and the new tests appear in the output. Visual sign-off of the glyph is the user's. Mark `resolved`, not `closed`.

Surfaces mount through the normal placeholder path when the new Session is shown. Also `docs/swiftui-observation-rules.md`. Every write here (`projectID`, title, color, tree mutations, selection) originates from an event (menu, palette, sheet button, XPC, UI-test intent), never from `body`/`onAppear`/geometry callbacks. Read `docs/terminal-pane-requirements.md` before touching the Sidebar row.
- **Resource cost.** A Project with several non-terminal Panes starts several sets of background work in one action: an `FSEventStream`/subprocess for Git Status, sampling `Task`s for Process Status and System Metrics, and a subprocess/HTTP poll for LM Studio (`SplitTree.swift` doc comment around `:290-325`). #0371's Gotchas record #0285's footprint history. Read `docs/pane-view-lifecycle.md` before implementing.
- **Occlusion at creation.** #0371's last note (from #0388): creating several Panes in one action is the first real path that may mount surfaces into an already-hidden state. Here the new Session is selected and visible, so every Pane is visible at creation. Confirm that, and do not rely on a later occlusion pass.
- **Duplicate kinds.** Two Panes of the same non-terminal kind are allowed (`PaneContentKind.swift:43-60`: `isSingletonPerSession` is deliberately not built). Don't police it.
- Multi-window: Projects are process-global (like `SessionNameCache`, `docs/multi-window-design.md`). Find-and-focus searches every Window.

## Resolution notes

> 🟢 Resolved 2026-10-12 — `AppStateStore.openProject` builds a Session from a Project: multi-kind Pane topology, Tabs in their own directories, pinned title and color, and a Sidebar folder glyph; it focuses an already-open Project Session or opens another copy.

No user-facing entry point yet — the editor (#0474), picker/menus (#0475) and CLI (#0477) call this. Visual sign-off of the Sidebar glyph is the user's.

## Root cause

Starting state: `PaneLayout.apply` could only build all-Terminal arrangements (`SplitTree.splitFocusedPane` has no kind), Tabs could not be created with per-Tab directories at split time, and Sessions had no notion of a backing Project.

## Fix

- `Model/ProjectTreeBuilder.swift` (new) replays a `ProjectLayout` through `SplitTree.splitPane` — all siblings first, then each child expanded from its first Pane, the same split order as `PaneLayout.apply`, so #0255 chain equalization supplies the ratios. Slot 0 gets its real kind via the new `SplitTree.withFirstPane(...)`.
- `SplitTree.splitPane` / `makePane` take `tabs: [TabRuntime]? = nil`; non-empty tabs win over cwd inheritance on the Terminal branch only (existing callers unchanged).
- Terminal Panes get one `TabRuntime` per `ProjectTab` with a resolved working directory and a `titleOverride` when the title is non-blank; Git Status gets its resolved repository path. A missing/escaping Tab or repository directory falls back to the root with a log; a missing, relative or non-directory root throws `ProjectOpenError` before anything is created.
- `SessionRuntime.projectID` (in memory); `WindowRuntime.addProjectSession(_:tree:)` appends, selects, pins the title and color — `SessionNameCache` untouched.
- `AppStateStore.openProject(id:mode:contentFactory:)` → `ProjectOpenResult(session, wasCreated)`; `.focusExistingOrOpen` searches every Window, `.openNew` always creates; `openProjectIDs` for badges/check marks. Throws `.featureDisabled` with the flag off, creating nothing.
- `SessionRow` shows a `folder.fill` glyph tinted with the Session color (`session-row.project-glyph`) when the flag is on and the Session has a `projectID`.
- `UITestDriver` intents `seedProject(json:)` and `openProject(name:mode:)`, inert with the flag off. Three gate-site rows in `docs/feature-flags.md`.

## Gotchas

- `SessionRuntime.tree` is a `let`, so the tree is built with `isSessionSelected: true` and the Session is appended and selected in the same synchronous call — every Pane is visible at creation.
- A Process Status Pane follows its split source's active Tab. When the source is a non-terminal Pane, that is the placeholder `TabRuntime` that never spawns, so Process Status shows nothing useful; place Process Status after a Terminal slot. (Same as `pane split --view` today.)
- `openProject` does not update `lastOpenedAt`.
- `ProjectTreeBuilder.build(gitStatusContent:)` is a test-only seam (a real `GitStatusPaneContent` starts an `FSEventStream`); nil in production.
