# 0576 — The Background Images window can't show the hosted Background Sets, so a hosted image can't be previewed or downloaded from inside Batty

| | |
|---|---|
| **Status** | open |
| **Module** | Settings / Theme |
| **Platform** | macOS |
| **First seen** | 2026-11-11 |

## Description

Add a Browse view to the Background Images window. It shows the Background Sets from the built-in catalog, `https://batty.sstools.co/backgrounds/catalog.json`, using **thumbnails only**. One click downloads an image's full-size file into Batty's image library. After that the image is marked Downloaded and can be picked like any other library image. Child of [#0574](0574.md), which defines the catalog format and the decisions this follows. Targets 1.4.0. [#0577](0577.md) adds user catalog URLs on top of this, so build the catalog code for a list of catalogs, of which this issue ships one.

**Read first:** `docs/swiftui-observation-rules.md` (binding: the window is `NSHostingController`-hosted and every model write here follows an `await`), `docs/async-test-seams.md` (`SchedulingClock`, completion signals), and Concepts.md `## Background Images`.

## What exists today

- **Window and picker.** `BackgroundImagesWindowController` (`BattyKit/Sources/BattyKit/Views/BackgroundImagesWindowController.swift`) hosts `BackgroundImagesView(model:mode: .manage)`. It opens from File → Background Images… (`BattyCommands.swift`), from the Command Palette (`CommandPaletteView.swift`) and from Settings → Appearance → Manage Images… (`SettingsView.swift`, `TerminalBackgroundSettingsSection`). The same view runs as a sheet in `.pick(current:onPick:onCancel:)` mode from `TerminalBackgroundControls.swift`, for the Pane, Session, Project and app-wide controls.
- **Model.** `BackgroundImagesModel` (`BattyKit/Sources/BattyKit/Model/BackgroundImagesModel.swift`), `@MainActor @Observable`, writes only on change. It is built by `AppStateStore.makeBackgroundImagesModel` (`Runtime/AppStateStore+BackgroundImages.swift`).
- **Library.** `BackgroundImageLibrary` (`Settings/BackgroundImageLibrary.swift`) is an actor over `BackgroundImages/` beside `projects.json` (`directory(forProjectsFile:)`), with one folder per digest. Its `add(from:)` imports through `TerminalBackgroundImageImporter.importImage`, which decodes the image (downsampled to `maxPixelSize`, 4096), re-encodes it to sRGB PNG, and names the folder for the SHA-256 of **that** PNG. The file's name comes from the source file's name, through `sanitizedImageName`.
- **Thumbnails.** `BackgroundImageThumbnailer` (`Settings/BackgroundImageThumbnailer.swift`) downsamples from a file URL with `CGImageSourceCreateThumbnailAtIndex` to `maxThumbnailPixelSize` (360), after `inspect` and `isWithinPixelLimit`. It only accepts library paths, so hosted thumbnails need their own path (below).
- **Networking.** None for this feature. The only `URLSession` use in BattyKit is `Runtime/LMStudioCLI.swift`.

## Behaviour

1. **Where it lives.** A segmented control at the top of the window, **My Images | Browse**, in both `.manage` and `.pick` modes. In pick mode, downloading an image from Browse and then choosing it calls `onPick` with the library path, the same as picking from My Images. Browse shows one section per Background Set, with the set's title and optional description, in catalog order. Each cell shows the thumbnail, the title, the `credit` if there is one, the full-size dimensions, the size if `bytes` is given, and a state.
2. **Cell states:** *Not downloaded* (a Download button), *Downloading* (progress and Cancel), *Downloaded* (a check mark, and in pick mode a Use button), and *Failed* (a short reason and Retry).
3. **Nothing is fetched until Browse is first shown.** Showing it fetches the catalog (or uses the cached copy, see 7), then the thumbnails for the cells that are visible. A full-size file is fetched only from a Download click (#0574 decision 5).
4. **Download.** The full-size file goes to a temporary file named `<sanitized title>.png`, so the library entry gets the image's title as its name. Batty checks it, then calls `BackgroundImageLibrary.add(from:)`, deletes the temporary file, refreshes the model and posts `.battyBackgroundImagesDidChange`. The checks, in order: a status of 200, the size against `bytes` (when given) and against the limit, `sha256` (when given), the decoded type `public.png`, and the `IHDR` width and height against the catalog's, all **before any pixels are decoded**. Any failure keeps nothing. One download per image at a time. Several images may download at once (at most 2 concurrent).
5. **Downloaded state.** The library digest isn't the hosted hash (#0574 decision 3), so keep a record `BackgroundImages/hosted-downloads.json` that maps catalog URL + image `id` (+ the hosted `sha256`, when known) to the library digest. The library's `digestFolders` lists only folders named like a digest, so a file at the root of `BackgroundImages/` doesn't appear as an image. An image counts as Downloaded while its record exists **and** that digest folder is still in the library. After Remove in My Images, it goes back to Not downloaded on the next refresh. A record whose `sha256` differs from the catalog's current one means the picture changed under the same id. Show it as Not downloaded, and keep the old library entry.
6. **Thumbnail cache.** Thumbnails are stored under `~/Library/Caches/<bundle id>/BackgroundCatalogs/<hash of catalog URL>/` by image id, alongside each one's `ETag`/`Last-Modified`. They are decoded with `CGImageSourceCreateThumbnailAtIndex` at `BackgroundImageThumbnailer.maxThumbnailPixelSize`, after a header check (PNG type and dimensions within #0577's thumbnail limit). They are never imported into the library. A deleted cache only means a refetch.
7. **Catalog cache.** The last catalog that parsed is kept in the same cache folder with its validators. Browse shows it immediately and refreshes behind it with a conditional request (`If-None-Match` / `If-Modified-Since`). A `304` keeps the cache. A new body that fails to parse keeps the old one and shows the error. The regular refresh schedule belongs to #0577. This issue refreshes when Browse is shown, at most once per 10 minutes.
8. **Offline and failure.** No network: Browse shows the cached catalog and cached thumbnails, cells without a thumbnail show a placeholder, and a banner reads "Can't reach batty.sstools.co. Showing the last copy." With no cache at all, the banner reads "Can't reach batty.sstools.co. Try again when you're online." and has a Retry button. A failed download leaves the cell in *Failed*. Downloaded images and every existing background keep working, since nothing in the library depends on the network. Requests time out (30 s for the catalog and thumbnails, 60 s of no progress for a full-size file), and nothing blocks the main actor.
9. **Catalog changes.** An image that the catalog no longer lists drops out of Browse. Its library copy and its uses stay, since only the user's Remove deletes from the library (Concepts.md). Same for a whole set.
10. **Networking.** A dedicated `URLSession` with an ephemeral configuration and no cookies, behind a small protocol (for example `BackgroundCatalogFetching`) so unit tests inject a fake and never touch the network. Redirects are allowed only to `https`. Logs use the file-scoped `Logger` per AGENTS.md "Logging", with URLs `.private` except the built-in host.
11. **Observation.** The view writes nothing from `body`. Model writes start from a button, `.task`, or after an `await`, and only on change (`docs/swiftui-observation-rules.md`). No `Task` hop to dodge an update-cycle warning.
12. **Help and Concepts.** Add a "Background Sets" part to `BattyKit/Sources/BattyKit/Help/11-backgrounds.md`. Add the #0574 terms to Concepts.md `## Background Images`, with a version line.

## Tests (unit, BattyKit)

- Catalog parsing: the draft `website/backgrounds/catalog.json` parses. Unknown fields are ignored. `schemaVersion: 2` gives "needs a newer version". Each missing or wrongly typed required field, each duplicate id and each non-https resolved URL is rejected, naming the path. Relative URLs resolve against the catalog URL.
- Download pipeline, against a fake fetcher and a temporary library folder: a good PNG lands in the library under the catalog title and gets a record. A wrong `sha256`, a size over `bytes`, a JPEG, a header width mismatch and an over-limit header each keep nothing and produce the matching failure.
- Downloaded state: after `BackgroundImageLibrary.remove(digest:)`, the image reads as Not downloaded. A changed `sha256` reads as Not downloaded, and the old entry stays.
- Conditional fetch: a `304` keeps the cached catalog, and a bad new body keeps the old copy with the error.
- No sleeps or polling. Await the model's async methods and the fake fetcher's continuations (AGENTS.md "Asynchronous tests").

UI test (to write, typecheck with `./build.sh ui-typecheck`, run in the daily VM run): open the window, switch to Browse, and see three sets from a catalog served to the app through a UI-test launch override pointing at a local fixture. Never use the live site in a UI test.

## Open questions

1. Should Browse also be reachable directly, for example as a "Get Images…" button next to Choose… in `TerminalBackgroundControls`, or is the segmented control enough?
2. Should a downloaded image keep its hosted `credit` anywhere after download? The library entry has only a name (`BackgroundImageEntry`).

## Acceptance criteria

1. File → Background Images… → Browse shows Future Cities, Cool Vehicles and Beautiful Landscapes with five thumbnails each, and Activity Monitor's Network tab (or a proxy) shows that no full-size PNG was fetched.
2. Clicking Download on one image shows progress, then a check mark. My Images then lists it under its title, and Settings → Appearance → Background → Choose… can use it.
3. Removing that image in My Images puts it back to Download in Browse.
4. With Wi-Fi off, Browse still opens with the last catalog and its thumbnails, the banner says it can't reach the site, and choosing a downloaded image still works.
5. In a Pane's background sheet, Browse → Download → Use sets that Pane's image.
