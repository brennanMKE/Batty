## Description

Add a Browse view to the Background Images window. It shows the Background Sets from the built-in catalog, `https://batty.sstools.co/backgrounds/catalog.json`, using **thumbnails only**. One click downloads an image's full-size file into Batty's image library. After that the image is marked Downloaded and can be picked like any other library image. Child of [#0574](0574.md), which defines the catalog format and the decisions this follows. Targets 1.4.0. [#0577](0577.md) adds user catalog URLs on top of this, so build the catalog code for a list of catalogs, of which this issue ships one.

**Read first:** `docs/swiftui-observation-rules.md` (binding: the window is `NSHostingController`-hosted and every model write here follows an `await`), `docs/async-test-seams.md` (`SchedulingClock`, completion signals), and Concepts.md `## Background Images`.

## What exists today

- **Window and picker.** `BackgroundImagesWindowController` (`BattyKit/Sources/BattyKit/Views/BackgroundImagesWindowController.swift`) hosts `BackgroundImagesView(model:mode: .manage)`. It opens from File → Background Images… (`BattyCommands.swift`), from the Command Palette (`CommandPaletteView.swift`) and from Settings → Appearance → Manage Images… (`SettingsView.swift`, `TerminalBackgroundSettingsSection`). The same view runs as a sheet in `.pick(current:onPick:onCancel:)` mode from `TerminalBackgroundControls.swift`, for the Pane, Session, Project and app-wide controls.
- **Model.** `BackgroundImagesModel` (`BattyKit/Sources/BattyKit/Model/BackgroundImagesModel.swift`), `@MainActor @Observable`, writes only on change. It is built by `AppStateStore.makeBackgroundImagesModel` (`Runtime/AppStateStore+BackgroundImages.swift`).
- **Library.** `BackgroundImageLibrary` (`Settings/BackgroundImageLibrary.swift`) is an actor over `BackgroundImages/` beside `projects.json` (`directory(forProjectsFile:)`), with one folder per digest. Its `add(from:)` imports through `TerminalBackgroundImageImporter.importImage`, which decodes the image (downsampled to `maxPixelSize`, 4096), re-encodes it to sRGB PNG, and names the folder for the SHA-256 of **that** PNG. The file's name comes from the source file's name, through `sanitizedImageName`.
- **Thumbnails.** `BackgroundImageThumbnailer` (`Settings/BackgroundImageThumbnailer.swift`) downsamples from a file URL with `CGImageSourceCreateThumbnailAtIndex` to `maxThumbnailPixelSize` (360), after `inspect` and `isWithinPixelLimit`. It only accepts library paths, so hosted thumbnails need their own path (below).
- **Networking.** None for this feature. The only `URLSession` use in BattyKit is `Runtime/LMStudioCLI.swift`.

## Behaviour

1. **Where it lives.** A segmented control at the top of the window, **My Images | Browse**, in both `.manage` and `.pick` modes. In pick mode, downloading an image from Browse and then choosing it calls `onPick` with the library path, the same as picking from My Images. Browse shows one section per Background Set, with the set's title and optional description, in catalog order. Each cell shows the thumbnail, the title, the `credit` if there is one, the full-size dimensions, the size if `bytes` is given, and a state.
2. **Cell states:** *Not downloaded* (a Download button), *Downloading* (progress and Cancel), *Downloaded* (a check mark, and in pick mode a Use button), and *Failed* (a short reason and Retry).
3. **Nothing is fetched until Browse is first shown.** Showing it fetches the catalog (or uses the cached copy, see 7), then the thumbnails for the cells that are visible. A full-size file is fetched only from a Download click (#0574 decision 5).
4. **Download.** The full-size file goes to a temporary file named `<sanitized title>.png`, so the library entry gets the image's title as its name. Batty checks it, then calls `BackgroundImageLibrary.add(from:)`, deletes the temporary file, refreshes the model and posts `.battyBackgroundImagesDidChange`. The checks, in order: a status of 200, the size against `bytes` (when given) and against the limit, `sha256` (when given), the decoded type `public.png`, and the `IHDR` width and height against the catalog's, all **before any pixels are decoded**. Any failure keeps nothing. One download per image at a time. Several images may download at once (at most 2 concurrent).
5. **Downloaded state.** The library digest isn't the hosted hash (#0574 decision 3), so keep a record `BackgroundImages/hosted-downloads.json` that maps catalog URL + image `id` (+ the hosted `sha256`, when known) to the library digest. The library's `digestFolders` lists only folders named like a digest, so a file at the root of `BackgroundImages/` doesn't appear as an image. An image counts as Downloaded while its record exists **and** that digest folder is still in the library. After Remove in My Images, it goes back to Not downloaded on the next refresh. A record whose `sha256` differs from the catalog's current one means the picture changed under the same id. Show it as Not downloaded, and keep the old library entry.
6. **Thumbnail cache.** Thumbnails are stored under `~/Library/Caches/<bundle id>/BackgroundCatalogs/<hash of catalog URL>/` by image id, alongside each one's `ETag`/`Last-Modified`. They are decoded with `CGImageSourceCreateThumbnailAtIndex` at `BackgroundImageThumbnailer.maxThumbnailPixelSize`, after a header check (PNG type and dimensions within #0577's thumbnail limit). They are never imported into the library. A deleted cache only means a refetch.
7. **Catalog cache.** The last catalog that parsed is kept in the same cache folder with its validators. Browse shows it immediately and refreshes behind it with a conditional request (`If-None-Match` / `If-Modified-Since`). A `304` keeps the cache. A new body that fails to parse keeps the old one and shows the error. The regular refresh schedule belongs to #0577. This issue refreshes when Browse is shown, at most once per 10 minutes.
8. **Offline and failure.** No network: Browse shows the cached catalog and cached thumbnails, cells without a thumbnail show a placeholder, and a banner reads "Can't reach batty.sstools.co. Showing the last copy." With no cache at all, the banner reads "Can't reach batty.sstools.co. Try again when you're online." and has a Retry button. A failed download leaves the cell in *Failed*. Downloaded images and every existing background keep working, since nothing in the library depends on the network. Requests time out (30 s for the catalog and thumbnails, 60 s of no progress for a full-size file), and nothing blocks the main actor.
9. **Catalog changes.** An image that the catalog no longer lists drops out of Browse. Its library copy and its uses stay, since only the user's Remove deletes from the library (Concepts.md). Same for a whole set.
10. **Networking.** A dedicated `URLSession` with an ephemeral configuration and no cookies, behind a small protocol (for example `BackgroundCatalogFetching`) so unit tests inject a fake and never touch the network. Redirects are allowed only to `https`. Logs use the file-scoped `Logger` per AGENTS.md "Logging", with URLs `.private` except the built-in host.
11. **Observation.** The view writes nothing from `body`. Model writes start from a button, `.task`, or after an `await`, and only on change (`docs/swiftui-observation-rules.md`). No `Task` hop to dodge an update-cycle warning.
12. **Help and Concepts.** Add a "Background Sets" part to `BattyKit/Sources/BattyKit/Help/11-backgrounds.md`. Add the #0574 terms to Concepts.md `## Background Images`, with a version line.

## Tests (unit, BattyKit)

- Catalog parsing: the draft `website/backgrounds/catalog.json` parses. Unknown fields are ignored. `schemaVersion: 2` gives "needs a newer version". Each missing or wrongly typed required field, each duplicate id and each non-https resolved URL is rejected, naming the path. Relative URLs resolve against the catalog URL.
- Download pipeline, against a fake fetcher and a temporary library folder: a good PNG lands in the library under the catalog title and gets a record. A wrong `sha256`, a size over `bytes`, a JPEG, a header width mismatch and an over-limit header each keep nothing and produce the matching failure.
- Downloaded state: after `BackgroundImageLibrary.remove(digest:)`, the image reads as Not downloaded. A changed `sha256` reads as Not downloaded, and the old entry stays.
- Conditional fetch: a `304` keeps the cached catalog, and a bad new body keeps the old copy with the error.
- No sleeps or polling. Await the model's async methods and the fake fetcher's continuations (AGENTS.md "Asynchronous tests").

UI test (to write, typecheck with `./build.sh ui-typecheck`, run in the daily VM run): open the window, switch to Browse, and see three sets from a catalog served to the app through a UI-test launch override pointing at a local fixture. Never use the live site in a UI test.

## Open questions

1. Should Browse also be reachable directly, for example as a "Get Images…" button next to Choose… in `TerminalBackgroundControls`, or is the segmented control enough?
2. Should a downloaded image keep its hosted `credit` anywhere after download? The library entry has only a name (`BackgroundImageEntry`).

## Acceptance criteria

1. File → Background Images… → Browse shows Future Cities, Cool Vehicles and Beautiful Landscapes with five thumbnails each, and Activity Monitor's Network tab (or a proxy) shows that no full-size PNG was fetched.
2. Clicking Download on one image shows progress, then a check mark. My Images then lists it under its title, and Settings → Appearance → Background → Choose… can use it.
3. Removing that image in My Images puts it back to Download in Browse.
4. With Wi-Fi off, Browse still opens with the last catalog and its thumbnails, the banner says it can't reach the site, and choosing a downloaded image still works.
5. In a Pane's background sheet, Browse → Download → Use sets that Pane's image.

## Plan

Written 2026-11-11 against `main` at `df2baf51`. **This plan follows #0574 decisions 8 to 11, which change the Behaviour section above:** there is no Download button, a full-size image is fetched when the user selects it as a background, and hosted images stay in their sets instead of joining My Images. Where Behaviour items 1, 2, 4 and 5 disagree with this plan, the plan wins.

Premises checked in the code:
- `BackgroundImageLibrary.digestFolders` keeps only names passing `TerminalBackgroundImageImporter.isDigest`, so a `Hosted/` folder inside `BackgroundImages/` never lists as an image.
- `importImage` decodes from `Data` whatever the extension, and names its output from the source file's name plus `.png`.
- `scan()` **promotes** every digest found in the app-wide, Project and Pane folders into the library. A hosted image picked for the app-wide default would therefore show up in My Images on the next scan, unless the scan skips hosted digests (below).
- Every place an image is chosen goes through `TerminalBackgroundControls` → `BackgroundImagesView(.pick)` → `onPickedLibraryImage(path)`. Two functions handle that path: `BackgroundOverrideSettingsView.startAdopt(ofLibraryPath:)`, used for Pane, Session and the Project Editor, and `SettingsView`'s `startAdopt(ofLibraryPath:)`, for the app-wide default. Both call `importer.adoptImage(path:from: [library.directory])`, and `adopt` accepts a path only from a listed source. A hosted path works once the hosted store is added to those sources.
- `BackgroundImagesModel` is one instance per store (`AppStateStore.backgroundImages`), shared by the window, every Choose… sheet and the Project Editor.
- The only `URLSession` in BattyKit is `LMStudioCLI`. `UITestDriver.projectsFileOverride` is the pattern for an env-gated override.
- Codex may be editing `website/backgrounds/catalog.json` on `main` right now. Tests rely only on it being a valid `schemaVersion` 1 catalog with at least one set, not on its counts, titles or extensions.

### Decisions this plan follows (#0574)

- **8, JPEG or PNG.** For both `full` and `thumbnail`. Every "`public.png`" check in this issue means `public.png` or `public.jpeg`. The hosted store always holds Batty's re-encoded PNG.
- **9, no request before the first Browse.** The first time the user shows Background Sets, `SettingsPreference.backgroundCatalogsBrowsedKey` (`co.sstools.Batty.backgroundCatalogsBrowsed`, Bool, default false) is set. #0577's launch refresh reads it, and #0577 owns the auto-check toggle.
- **10, binaries not in git.** Affects #0575 only. Unit tests make their own images.
- **11, select to download, hosted images stay in their sets.** The rest of this plan.
- No feature flag (decision 1), unless the orchestrator says 1.4.0 is cut before #0577 lands.

### Files to add (`BattyKit/Sources/BattyKit/`; header `// FileName.swift`; a file-scoped `logger` where it logs)

1. **`Settings/BackgroundCatalog.swift`**: the model and parser, as `nonisolated`, `Sendable`, `Equatable` value types.
   - **Types:**
     - `BackgroundCatalog { schemaVersion; name; updated: String?; homepage: URL?; sets: [BackgroundSet] }`
     - `BackgroundSet { id; title; description: String?; images: [HostedBackgroundImage] }`
     - `HostedBackgroundImage { id; title; credit: String?; full: HostedImageFile; thumbnail: HostedImageFile }`
     - `HostedImageFile { url: URL /* resolved, https */; width; height; sha256: String?; bytes: Int64? }`
     - `static let builtInURL`: `https://batty.sstools.co/backgrounds/catalog.json`.
   - **`BackgroundCatalogLimits`:**
     - catalog JSON 1 MB;
     - 50 sets, 100 images per set, 1,000 per catalog;
     - name and title 100 characters, description 300, credit 200;
     - thumbnail 2 MB and 1024 px;
     - full size 50 MB and 8192 px;
     - 5 redirects;
     - timeouts: 30 s for the catalog and thumbnails, 60 s without progress for a full-size file;
     - `supportedTypes`: png and jpeg.
   - **`BackgroundCatalogError`:**
     - `.invalid(path:)`: the first bad path, with array indices as `[n]`, e.g. `sets[1].images[3].full.width`;
     - `.needsNewerVersion(Int)`;
     - `.tooLarge`;
     - `message` gives "Not a background catalog: <path>", "This catalog needs a newer version of Batty" or "Catalog is larger than 1 MB".
   - **`BackgroundCatalogParser.parse(_ data: Data, catalogURL: URL) throws(BackgroundCatalogError)`.** Hand-walks `JSONSerialization` output, so each error names its path without decoding a `codingPath`. In order:
     1. A body over 1 MB is `.tooLarge`.
     2. A top level that isn't an object is invalid at the root.
     3. `schemaVersion` first. It must be an integral `NSNumber` that isn't a Bool, so `"1"`, `1.5` and `true` are invalid. A value above 1 is `.needsNewerVersion`.
     4. Unknown keys are ignored.
     5. Strings are trimmed, then length-checked. An empty description or credit counts as absent.
     6. Ids match `^[a-z0-9][a-z0-9-]{0,63}$`. Set ids are unique, and image ids are unique across the whole catalog.
     7. Each `url` resolves with `URL(string:relativeTo:)?.absoluteURL` and must be `https` with a host.
     8. Width and height are integers ≥ 1. `sha256`, when present, is 64 lowercase hex characters. `bytes`, when present, is ≥ 1. `homepage` must be absolute `https`.
     No `try!` and no force casts.
   - `displayText(_:)` strips control characters. Catalog text appears only through `Text(verbatim:)`, never as Markdown or a link.
2. **`Settings/BackgroundCatalogFetching.swift`**: the network seam.
   - `nonisolated protocol BackgroundCatalogFetching: Sendable { func fetch(_ request: HostedFetchRequest, progress: (@Sendable (Int64) -> Void)?) async throws(HostedFetchError) -> HostedFetchResponse }`
   - `HostedFetchRequest { url; etag?; lastModified?; byteLimit; timeout; destination: .memory | .file(URL) }`
   - `HostedFetchResponse { status /* 200 or 304 */; body: Data?; etag?; lastModified?; expectedLength: Int64? }`
   - `HostedFetchError`: `.notFound`, `.server(Int)`, `.http(Int)`, `.unreachable`, `.untrustedCertificate`, `.insecureRedirect`, `.tooManyRedirects`, `.tooLarge`, `.timedOut`, `.cancelled`. `message(host:)` gives #0577's wording ("Not found (404)", "Can't reach <host>", and so on).
   - **Pure helpers, unit-tested:**
     - `HostedFetchPolicy.allowsRedirect(to:count:)`;
     - `error(forStatus:)`;
     - `error(for: URLError)`, mapping the connectivity codes to unreachable, the `serverCertificate…` codes and `.secureConnectionFailed` to untrustedCertificate, plus `.timedOut` and `.cancelled`;
     - `ByteLimitCounter`.
3. **`Settings/URLSessionBackgroundCatalogFetcher.swift`**: the live conformer, a delegate-based class with lock-guarded per-task state.
   - **Session:** one `URLSession` on `URLSessionConfiguration.ephemeral`, with `httpCookieStorage = nil`, `httpShouldSetCookies = false`, `urlCache = nil` and `.reloadIgnoringLocalCacheData`.
   - **Requests:** sends `If-None-Match` and `If-Modified-Since` when given. `request.timeoutInterval` is an inactivity timeout, which is what "60 s without progress" needs.
   - **Streaming:** `didReceive data` counts against the byte limit and cancels the task past it, or past an oversized `Content-Length`. It reports progress, and writes to memory or a `FileHandle`.
   - **Redirects:** `willPerformHTTPRedirection` applies the redirect policy.
   - **Cancellation:** cancelling the Swift `Task` cancels the data task (`withTaskCancellationHandler`).
   - **Logging:** a URL is `.public` only for `batty.sstools.co`, otherwise `.private`.
4. **`Settings/BackgroundCatalogCache.swift`**: `actor BackgroundCatalogCache(root:)`. This is a pure cache, and a missing file never becomes a user-visible error.
   - **Root:** `~/Library/Caches/<bundle id>/BackgroundCatalogs/`, found the same way as `TerminalBackgroundImageImporter.defaultDirectory()`.
   - **Per catalog,** a folder named for the SHA-256 of the URL's `absoluteString`, holding:
     - `catalog.json`: the last body that parsed;
     - `state.json`: `etag`, `lastModified`, `lastChecked`, `lastError`;
     - `thumbnails/<image id>` with `thumbnails/<image id>.json`: `url`, `sha256`, `etag`, `lastModified`.
   - **Methods:** `cachedCatalog(for:)` (a stored copy that no longer parses is ignored), `store(body:validators:for:)`, `markChecked(for:at:error:)`, `thumbnail(for:imageID:)`, `storeThumbnail(...)`, `removeAll(for:)`. All writes are atomic.
5. **`Settings/HostedImageStore.swift`**: `actor HostedImageStore(directory:fetcher:temporaryRoot:)`. The directory is `BackgroundImages/Hosted/`, i.e. `library.directory.appendingPathComponent("Hosted")`. It owns:
   - its own `TerminalBackgroundImageImporter(directory:, cleanup: .keepAll)`;
   - the records file `Hosted/hosted-images.json`: `[HostedImageRecord { catalogURL; imageID; sha256?; digest; fetchedAt }]`, newest replacing older per (catalog URL, image id). A missing or corrupt file means no records, and the next write replaces it.

   **`localPath(for image:, catalogURL:) -> String?`** returns a path when a record matches the catalog URL and image id, its `sha256` matches the catalog's (or either is nil), and `TerminalBackgroundImageImporter.existingCopy(digest:in: directory)` finds an intact file.

   **`fetch(_ image:, catalogURL:, progress:) async throws(HostedImageError) -> String`** returns `localPath` when there is one. Otherwise it downloads, checking everything before any pixel is decoded:
   1. Declared `bytes` over 50 MB is `.tooLarge`, with no request.
   2. Fetch into `<temporaryRoot>/<UUID>/download` with limit `min(bytes ?? limit, limit)` and a 60 s timeout. The status must be 200.
   3. The size must equal `bytes` when declared.
   4. The file's SHA-256 must equal `sha256` when declared. Hash in chunks.
   5. Read the header only (`CGImageSourceGetType` and `CopyPropertiesAtIndex`): the type is png or jpeg, the pixel size equals the catalog's, and the longest side is ≤ 8192.
   6. Rename the file to `<sanitizedImageName(title)>.<png|jpg>` and run `importer.importImage(from:)`, the re-encode.
   7. Write the record.
   8. `defer` removes the temporary folder on every path.

   Also `digests() -> Set<String>` (for the library exclusion and "in use"), `records()`, and `removeAll(catalogURL:)` for #0577. `HostedImageError` wraps `HostedFetchError` and adds `.sizeMismatch`, `.hashMismatch`, `.unsupportedType`, `.dimensionMismatch`, `.tooManyPixels` and `.importFailed`, each with a short `message`. The live `temporaryRoot` is `FileManager.default.temporaryDirectory/batty-hosted-downloads`.
6. **`Settings/HostedThumbnailLoader.swift`**: `actor HostedThumbnailLoader(fetcher:cache:decode:)`. `decode` defaults to `BackgroundImageThumbnailer.downsample`.
   - `thumbnail(for:catalogURL:) async -> BackgroundImageThumbnail` reuses the existing type.
   - A cached file with the same `url` and `sha256` is decoded with no request.
   - Otherwise it fetches: 2 MB, 30 s, conditional when the `url` matches, and a 304 reuses the file. Then it checks `sha256`, checks the header (png or jpeg, ≤ 1024 px), stores and decodes.
   - Failure returns `.rejected`. An unreachable network with a cached file uses that file.
   - At most 4 fetches at once. Memoized in an `NSCache`. Never touches the library or the hosted store.
7. **`Model/HostedBackgroundsModel.swift`**: `@MainActor @Observable`, writing only on change.
   - **Observed:**
     - `catalogs: [HostedCatalogState]`: `url`, `isBuiltIn`, `catalog?`, `isChecking`, and `problem?`, one of `.offlineShowingCache(host)`, `.offlineNoCache(host)`, `.invalid(message)`, `.needsNewerVersion` or `.fetchFailed(message)`;
     - `fetches: [HostedImageKey: HostedFetchState]`, with `HostedImageKey { catalogURL; imageID }` and states `.fetching(fraction?)` or `.failed(message)`;
     - `available: Set<HostedImageKey>`: a full-size copy is held, so it can be chosen offline.
   - **`@ObservationIgnored`:** `fetcher`, `cache`, `store`, `thumbnails`, `defaults`, `clock: SchedulingClock`, `catalogURLs: @MainActor () -> [URL]` (`{ [BackgroundCatalog.builtInURL] }`, which #0577 extends), the running fetch `Task`s, and the last-refresh instants.
   - **`browseAppeared() async`:**
     1. Marks the browsed flag, writing only if it isn't already set.
     2. Shows each catalog's cached copy at once.
     3. Calls `refresh(url)` for each catalog this model hasn't refreshed in the last 10 minutes by `clock.now`.
     4. Calls `reconcileAvailability()`.

     It runs only from the Background Sets view's `.task`.
   - **`refresh(_ url:) async`**, also the banner's Retry and #0577's hook. A conditional fetch: 1 MB, 30 s.
     - 200 → parse. Success stores the body and validators and replaces `catalog`. A parse failure keeps the old copy and sets `.invalid` or `.needsNewerVersion`.
     - 304 → keep the cache and update `lastChecked`.
     - Unreachable or timed out → keep the cache, with `.offlineShowingCache` or `.offlineNoCache`.
     - Any other error → `.fetchFailed`.
     One catalog at a time.
   - **`select(_ image:, catalogURL:) -> Task<String?, Never>`**, the select-to-download path. With a `localPath`, the task returns it right away. Otherwise it sets `.fetching(nil)` and runs `store.fetch`. Progress hops to the main actor and writes only when the fraction moves ≥ 1%. Results:
     - **Success:** clears the fetch state, inserts the key into `available` and returns the path.
     - **Failure:** sets `.failed(message)` and returns nil.
     - **Cancellation:** clears the state and returns nil.

     At most 2 full-size fetches run at once, and the rest wait in `.fetching(nil)`. Selecting a key that is already fetching returns the running task. The view awaits the returned task (the completion-signal shape in `docs/async-test-seams.md` §4).
   - **`cancelFetch(_ key)`.**
   - **`reconcileAvailability() async`** recomputes `available` from `store.localPath` for every listed image.
   - **`thumbnail(for:catalogURL:)`** passes through to the loader.
   - **`imageDirectory`** (nonisolated) is the hosted store's folder, for the adopt sources.
8. **`Views/BackgroundSetsView.swift`**: the Background Sets tab.
   - **Banner:** one per catalog `problem`, with the wording from Behaviour 8 and Retry.
   - **Sections:** for each catalog (a header with its name; with only the built-in catalog, one header), then each set (title, description; identifier `background-sets.set.<set id>`). Each holds a `LazyVGrid` of cells sized by the thumbnail's aspect ratio.
   - **Cell** (identifier `background-sets.cell.<image id>`):
     - the thumbnail, in the cell's own `@State` from `.task(id:)`;
     - the title, credit, "W × H" and the `bytes` size;
     - a status line: "Available offline" (`.available`) when held; "In use" (`.in-use`) when its digest has uses in `model.uses`; a `ProgressView` with Cancel (`.progress`, `.cancel`) while fetching; the reason (`.failed`) after a failure.
   - **Pick mode:** clicking a cell (or Return on a selected cell) awaits `hosted.select(...)` and then calls `onPick(path)`. The sheet stays open while the cell shows progress. A failure leaves the sheet open with the reason, and the current background untouched, since `onPick` is never called. The sheet's Cancel cancels a running fetch.
   - **Manage mode:** clicking only selects. Nothing is fetched.
   - **Observation:** no writes from `body`. Writes come only from `.task`, button actions and post-`await` code.
9. **`Testing/FixtureBackgroundCatalogFetcher.swift`**: used only when a UI-test launch sets `BATTY_UI_TEST_BACKGROUND_CATALOG_DIR` beside `BATTY_UI_TEST_SCRIPT`.
   - Serves `https://batty.sstools.co/backgrounds/<rest>` from `<dir>/<rest>`, refusing `..`.
   - Answers 200 with an `ETag` of the file's SHA-256, and 304 on a matching `If-None-Match`.
   - A missing file is `.notFound`. Any other host is `.unreachable`.
   - Appends every requested path to `<dir>/requests.log`.

## Root cause

Feature work. The starting state: the Background Images window showed only the local library (My Images), BattyKit had no networking for backgrounds, and nothing could read the hosted catalog that #0575 publishes.

## Fix

Followed the Plan (decisions 8 to 11: select-to-download, hosted images stay in their sets, PNG or JPEG).

- **Core (BattyKit/Settings):** (format as first built; see the simplified-format bullet below for what changed) `BackgroundCatalog` (model, `BackgroundCatalogLimits`, hand-walked `BackgroundCatalogParser` naming the first bad path), `BackgroundCatalogFetching` (protocol, `HostedFetchError`, pure `HostedFetchPolicy` and `ByteLimitCounter`), `URLSessionBackgroundCatalogFetcher` (ephemeral, cookie-less, delegate-based streaming with byte limit, https-only redirects capped at 5, cancellation through `withTaskCancellationHandler`, URLs `.public` only for batty.sstools.co), `BackgroundCatalogCache` (per-catalog folder under Caches, catalog + validators + thumbnails), `HostedImageStore` (`BackgroundImages/Hosted/`, records in `hosted-images.json`, every check before any pixel decode, temp folder removed on every path) and `HostedThumbnailLoader` (4 concurrent, conditional refetch, offline fallback to cache).
- **Model:** `HostedBackgroundsModel` (`browseAppeared`, `refresh` with a 10-minute gate on `SchedulingClock.now`, `select` returning a `Task<String?, Never>`, 2 concurrent full-size fetches, `cancelFetch`, `reconcileAvailability`). `BackgroundImagesModel` gains `hosted` and `pickSources`; `AppStateStore.makeBackgroundImagesModel(hosting:)` wires live or UI-test fixture dependencies. `SettingsPreference.backgroundCatalogsBrowsedKey` is set on first Browse.
- **Library:** `BackgroundImageLibrary(hostedDirectory:)`; `scan()` never promotes a digest held in `Hosted/`.
- **Pick wiring:** both `startAdopt(ofLibraryPath:)` (BackgroundOverrideSettingsView, SettingsView) adopt from `pickSources`.
- **UI:** `BackgroundImagesView` has a My Images | Background Sets segmented control in both modes; `BackgroundSetsView` shows banners, set sections and cells (thumbnail, title, credit, W × H, bytes, status: progress + Cancel, failure reason, In use, Available offline). In pick mode a click goes through `HostedBackgroundsModel.pick(_:catalogURL:onPicked:)`; the sheet's Cancel cancels running fetches.
- **Latest pick wins (review round 1):** `HostedBackgroundsModel.pick` keeps a pick generation and the pending key (both observation-ignored). A new hosted pick cancels the previous pick's fetch (different key) and bumps the generation; `onPicked` runs only if the generation is unchanged when the fetch finishes. `supersedePicks()` bumps it and cancels the pending fetch; `BackgroundImagesView` calls it on a My Images pick, Add from File… in pick mode, the sheet's Cancel, and the sheet's `.onDisappear`. So a superseded or dismissed pick never reaches `onPick`.
- **Cancelling a queued fetch (review round 1):** `acquireFetchSlot(for:)` returns `false` when the task is already cancelled or `cancelFetch`/`cancelAllFetches` takes its key out of the waiter queue; `runSelect` then clears the cell's state and returns nil. `onFetchQueued` is a test seam fired when a fetch parks for a slot.
- **Re-pick and shared fetches (review round 2):** `select` no longer hands back a cancelled task. A fresh select of a key whose task was cancelled starts a new task that first awaits the cancelled one, so the two never overlap, and each `running` entry carries an id so the old task's cleanup can't remove the new one. A pick records whether it started its fetch (`pendingPick.ownsFetch`); a pick that joins a fetch something else started never cancels it, and only a pick of a *different* image, Cancel or dismissal cancels a fetch the pick started. The sheet's Cancel no longer calls `cancelAllFetches`.
- **UI test (review round 2):** `BackgroundSetsTests.pick` scrolls `background-sets.root` until the cell exists and is hittable (`scrollToCell`), since the 460 pt sheet's lazy grid builds only the visible rows. The step count bounds a regression; the sheet's `ScrollView` is what a user scrolls to reach the last cell.
- **Simplified catalog format (#0574 decision 12, user 2026-11-11):** `BackgroundCatalog` is `sets` of `BackgroundSet(name, images)`; `HostedBackgroundImage` is `title` (falls back to the full-size file's name without extension), `full` and `thumbnail` URLs, and its identity (`id`, `HostedImageKey`) is the resolved full-size URL. No `schemaVersion`, ids, dimensions, `sha256` or `bytes`; the `needsNewerVersion` problem, `.sizeMismatch`, `.hashMismatch` and `.dimensionMismatch` are gone. The same full-size URL twice is rejected. `hosted-images.json` records map URL → digest; the thumbnail cache files by a hash of the full-size URL and revalidates a cached thumbnail with a conditional request when it isn't in memory (offline it uses the cached file). Kept: https only, byte limits while streaming, PNG/JPEG decoded type that must match the URL's extension (`BackgroundCatalogLimits.isAccepted`, #0574 Decision 8 as rewritten on `main`), header pixel limits before decode, then the importer. `select`/`pick`/`store.fetch`/`localPath` no longer take a catalog URL. Cells are a fixed 16:10 with the thumbnail fitted; credit and size lines are gone; progress is indeterminate (`HostedFetchState.fetching` has no fraction). Set sections are identified as `background-sets.set.<name>`, cells as `background-sets.cell.<full-size file stem>`.
- **UI-test seam:** `UITestDriver.backgroundCatalogFixtureDirectory` + `FixtureBackgroundCatalogFetcher` (serves `https://batty.sstools.co/backgrounds/<rest>` from a folder, ETag = file SHA-256, logs `requests.log`).
- Help (`11-backgrounds.md` "Background Sets") and Concepts.md (Background Catalog, Background Set, hosted image store).

Divergences from the plan:
- `HostedImageHeader.read` parses a PNG's IHDR directly. ImageIO returns **no properties at all** for an IHDR past its limits (20000 × 20000), which would have reported an oversized PNG as `.unsupportedType` instead of `.tooManyPixels`. JPEG still goes through `CGImageSourceCopyPropertiesAtIndex`.
- Return on a selected Background Sets cell does not pick (click only); My Images keyboard handling is unchanged.
- `projectEditorAdoptsAHostedPath` was not written; the pick tests cover app-wide and Pane adopt plus the refusal outside `pickSources`. The Project Editor uses the same `BackgroundOverrideSettingsView.startAdopt` path.
- `imageDroppedFromTheCatalogKeepsItsHostedCopyAndUse` is `imageDroppedFromTheCatalogKeepsItsHostedCopy` (checks the hosted file survives and availability drops), without going through `AppWideBackgroundEditor`. Added `hostedImageStaysOutOfMyImages`.
- UITestDriver tests live in a new `UITestBackgroundCatalogFixtureTests` suite (there is no `UITestDriverTests` suite; the precedent is `UITestProjectsFileOverrideTests`).

The type must match the extension (`isAccepted`), checked at download and thumbnail time. The app does not reject a duplicate `thumbnail`; that is a website-tool rule only, so it is non-blocking.
- **Identity and safety.** `HostedImageStore` and `hosted-images.json` key on the resolved full URL. Byte limits apply while streaming and again on the file. Header type and pixel limits are checked before any decode, for both full-size and thumbnail. A thumbnail cached on disk but not in memory is revalidated with its ETag or Last-Modified, and is used as is offline. Nothing fetches before the Background Sets `.task` calls `browseAppeared`.

Non-blocking: a thumbnail that fails the header check is still written to the catalog cache before it is rejected (harmless, since it is rejected again on every read).
