## Description

The sidebar toggle ([[0065]], [[0129]]) and window chrome interactions are small surface-area but high-frequency — every user toggles the sidebar dozens of times a session. [[0065]] documented jarring behavior (no animation, `+` button disappearing, chevron shift). [[0129]] added `Cmd-B` and the Settings entry. Neither has UI test coverage and both are exactly the kind of "looks wrong" bug that ships unnoticed.

## Regressions this suite would have caught

- [[0065]] — Sidebar toggle was jarring: no animation, `+` button disappeared, chevron shifted position. The behavioral subset (button presence, chevron stable) is XCUI-testable; the animation smoothness is not.
- [[0129]] — `Cmd-B` toggle and Settings binding. Test that the shortcut is bound and the Settings row shows it.

## Test cases

### Sidebar visibility toggle — would catch [[0065]] / [[0129]]

- **`Cmd-B` collapses sidebar.** Assert `session-sidebar` becomes non-hittable (or its width drops below a threshold). XCUITest can't read SwiftUI's collapsed-state directly; use the sidebar element's frame.
- **`Cmd-B` re-expands sidebar.** Toggle twice; assert sidebar returns to its prior width within a tolerance.
- **`+` button visible in both collapsed and expanded states (or only in expanded, per spec).** Document and test the chosen behavior — [[0065]] called this out as bug-prone.
- **Chevron remains at consistent position across toggle.** Capture chevron frame before and after; assert delta within tolerance.

### Sidebar interaction — defensive

- **Selecting a session row keeps sidebar expanded.** Click `session-row.X`. Assert sidebar width unchanged.
- **Sidebar context menu opens on right-click.** Right-click `session-row.X`. Assert `menu.sidebar.session.X` becomes visible. (Identifier may be different — confirm during implementation.)

### Settings parity — would catch [[0129]] documentation drift

- **Cmd-B appears in Settings → Shortcuts as the sidebar toggle.** Open Settings → Shortcuts. Assert `settings.shortcut-row.toggle-sidebar` shows `Cmd-B`.

## Accessibility identifiers needed

- `session-sidebar` — already exists.
- `session-sidebar.add-session-button` on the `+` button (if not already present).
- `session-sidebar.chevron` on the disclosure chevron.

## Driver intents needed (from [[0158]])

- `toggleSidebar`.
- Existing `setPreference` for any toggle-related defaults.

## Out of scope

- Animation smoothness / frame-by-frame inspection (snapshot territory).
- Window resize behavior (separate concern; not part of [[0065]] / [[0129]]).
- Drag-to-resize the sidebar divider (if that's a feature).

## Acceptance criteria

- All test cases pass under `xcodebuild -scheme 'Batty (Beta)' -destination 'platform=macOS' test`.
- The chevron-position assertion uses a reasonable tolerance (e.g. ≤ 2pt delta) so SwiftUI layout jitter doesn't flake the test.

## Notes

- Depends on [[0158]].
- This is a small suite; could be expanded later to cover other window-chrome elements (window-title-bar interactions, focus-ring rendering) if those start regressing.
