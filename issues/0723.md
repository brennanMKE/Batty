# 0723 — A Session color the user picks is forgotten on relaunch, while a Session name chosen in the same folder comes back

| | |
|---|---|
| **Status** | open |
| **Module** | Session / Sidebar / Persistence |
| **Platform** | macOS |
| **First seen** | 2026-11-22 |
| **Target** | 1.5.0 |

## Description

User request (2026-11-22), verbatim: "We also let the user rename the session and set the color which are persisted. At least the name is persisted. Why not let them pick the symbol as well. File issues to let the user select the SF Symbol of a session and also make sure we persist the color change. We also want to use AFM to automatically select a symbol as long as we can get back a high confidence the symbol is a good match. This also makes it very easy to save as a project as we can take the name, color and symbol along with the path to use in the project."

Verified: **the Session color is not persisted today.** A Session name is remembered per working directory in the Name cache, and comes back on a new Session in that folder; a color picked with **Set Color…** is in-memory only and is gone after a relaunch. That was a deliberate scope cut in [#0336](0336.md) ("A chosen color does **not** survive relaunch. That is by design per this issue's Persistence section"), and `Concepts.md` says so. The user now wants it to persist the same way the name does.

Sessions themselves do not survive a relaunch (#0172 removed workspace persistence), so "persist" here means what it means for the name: remember the user's choice **per working directory** and apply it when a Session is next in that folder.

## Steps to reproduce

1. In a Session, `cd` into a project folder (for example a git repo with a `Package.swift`).
2. Right-click its Sidebar row → **Rename**, enter "Batty Work". Right-click → **Set Color…**, pick red.
3. Quit Batty and relaunch.
4. In the new Session 1, `cd` into the same folder (or open a new Session while a Session is in that folder).

## Expected behavior

The Session is named "Batty Work" **and** its row is red.

## Actual behavior

The name is restored, the color is whatever the automatic assigner chose.

## Current state (verified 2026-11-22)

- Name memory: `WindowRuntime.renameSession` records `(anchor cwd, name)` with `nameCache.record(path:name:)` — `BattyKit/Sources/BattyKit/Runtime/WindowRuntime.swift:499-511`; `clearSessionName` removes it — `WindowRuntime.swift:513-520`.
- Name restore: `addSession` looks up the inherited cwd — `WindowRuntime.swift:334-337`; cwd-driven auto-naming resolves cache hit > project rules > default in `AppStateStore.resolveAutoTitle` — `BattyKit/Sources/BattyKit/Runtime/AppStateStore.swift:2927-2941`, applied from `applySessionAutoNaming` — `AppStateStore.swift:2771-2816`.
- Storage: `SessionNameCache` writes `~/Library/Application Support/<Batty|Batty Beta>/session-name-cache.json`; entries are `{path, name, lastUsedAt}`, schema version 1 — `BattyKit/Sources/BattyKit/Model/SessionNameCache.swift:10-33`; API `isProjectDirectory`/`lookup`/`removeName`/`record` at `SessionNameCache.swift:127,131,140,146`. Non-project folders (home, `/`, top-level folders, temp roots) are never recorded (`Concepts.md` → Session → Name cache).
- Color: `SessionRuntime.colorIndex` + `colorOverride` — `BattyKit/Sources/BattyKit/Runtime/SessionRuntime.swift:61,71`. `WindowRuntime.setSessionColor(id:to:)` and `resetSessionColor(id:)` — `WindowRuntime.swift:288-308` — write only the in-memory Session; nothing touches `nameCache` or any other store. The picker calls them from `SessionColorPickerView.swift:202-204`; the menu's **Reset Color** from `SessionSidebarView.swift:539-541`.
- `addSession` assigns `nextColorIndex()` unconditionally — `WindowRuntime.swift:341`.
- `Concepts.md:63`: "Not persisted: a Session's color, chosen or automatic, resets on relaunch".

Session colors are palette indices only (`SessionColor`, 10 cases); custom hex exists only on Projects (#0517, shown on a Session as the nearest palette color, #0653). So there is no hex-vs-index gap to cover for a plain Session.

## Proposed behavior

- **Set Color…** on a Session whose anchor Tab (first Pane's first Tab) is in a project folder records `(cwd, colorIndex)` in the same per-directory store as the name. **Reset Color** removes the recorded color for that folder (mirroring Reset Name).
- A new Session whose inherited cwd has a recorded color starts in that color instead of `nextColorIndex()`.
- When a single-Pane Session's anchor cwd moves into a folder with a recorded color, and the user hasn't pinned a color on this Session (`colorOverride == false`), the Session takes that color. Leaving the folder keeps the current color (no jump back) — unlike the name, which resets to `Session N`.
- A color applied from memory does **not** set `colorOverride`, the same standing as a name applied from the cache (`titleOverride` stays false), so a later `cd` can change it.
- Project-backed Sessions are unaffected: the Project's color wins and nothing is recorded for them (their identity already persists in `projects.json`).
- Duplicate Session still gets a fresh automatic color (#0336, #0340).
- The same record is where [#0724](0724.md) stores the user's Session symbol, so the storage shape should anticipate a second optional field.

## Storage (decide in Plan)

Recommended: extend `SessionNameCacheEntry` with optional `colorIndex: Int?` (and later `symbolName: String?`), make `name` optional so a folder can remember a color without a name, bump `SessionNameCacheFile.currentSchemaVersion` to 2, and decode version-1 files unchanged. Keep the file name `session-name-cache.json` so no migration is needed; one LRU cap (100) covers all fields. Alternative: a sibling `session-appearance-cache.json` store; rejected unless the Plan finds a reason, since it doubles the debounce/cap/LRU code.

## Acceptance criteria

- Picking a color on a Session in a project folder, relaunching, and opening a Session in that folder shows the picked color.
- Reset Color forgets the folder's color; the next Session there gets an automatic color.
- A user-pinned color on a live Session is never replaced by a remembered color on `cd`.
- Home folder and other non-project directories never record a color (existing `NonProjectDirectory` rule).
- An existing version-1 `session-name-cache.json` loads with every name intact.
- `Concepts.md` → Session → Identity and Name cache updated; the "Not persisted" sentence removed. Help/changelog note.
