## Description

On launch, read `workspace.json`, instantiate Windows / Sessions / Panes / Tabs / Terminal Sessions matching the saved tree, and replay focus and selection. Shells start fresh in the saved cwd — running processes are not restored (Concepts → Workspace).

**Acceptance criteria:**
- On launch, if `workspace.json` exists and parses, every Window / Session / Pane / Tab is recreated with its prior layout, ordering, focus, and titles.
- For each Tab, a fresh Terminal Session is started in the saved cwd.
- Bell Feed history is rehydrated from the file.
- If the file is missing, start with a single empty Window: one Session, one Pane, one Tab, one fresh Terminal Session.
- If the file exists but fails to parse, rename it to `workspace.json.broken-<unix-timestamp>` and start with the empty default. Surface a one-time alert on next launch ("Your workspace file was corrupt; the previous file is preserved at …") — non-blocking.

## Notes

- The cwd for the new shell is best-effort: if the saved path no longer exists, fall back to `$HOME` and silently log.
- A successful load is the canonical M7 success criterion (PRD §12 #2 needs 10+ relaunches with no data loss).

### Phase 1 landed in `7afe781` — load + corrupt-file recovery

Added to `Batty/WorkspaceStore.swift`:

- `WorkspaceLoadResult` enum with `.loaded(Workspace)`, `.missing`, `.recovered(default:brokenFileURL:underlyingError:)`. Has a `.workspace` computed property so callers that don't care about the case can just take the value (`Workspace.empty()` for missing/recovered).
- `WorkspaceStore.load()` — never throws. Returns `.missing` when the file isn't present, `.loaded` on successful parse, `.recovered` when the file exists but fails to decode. On failure, the file is renamed in place to `workspace.json.broken-<unix-timestamp>` and the path is included in the result so a future "workspace was corrupt" alert can point at the preserved file.

Tests in `BattyTests/WorkspaceStoreTests.swift`: 4 new tests covering the three load result cases plus the `.workspace` fallback for missing files. Combined with #0030's tests, the WorkspaceStore now has 8 unit tests, all passing.

### Why this is still `open`

Two acceptance criteria need running-app context:

1. "For each Tab, a fresh Terminal Session is started in the saved cwd." — needs M0 #0003 (resource bundle), M1 #0006-#0009 (libghostty surface plumbing), and the `BattyApp` scene wiring to instantiate live surfaces from the loaded `Workspace`.
2. "Surface a one-time alert on next launch (Your workspace file was corrupt; the previous file is preserved at …)." — needs the SwiftUI app to be able to present an alert, which requires basic app shell + window structure (M1).

The IO + recovery primitive is complete, tested, and ready to be called from `BattyApp.init` once the surrounding pieces exist. The recovery path includes the broken file URL specifically so the alert UI can show it without re-parsing.

### What's left — when M0–M1 lands

1. In `BattyApp` (or a startup coordinator), call `WorkspaceStore().load()` early.
2. For `.loaded` and `.recovered`, walk the `Workspace` and create one libghostty surface per `Tab`, in the saved `lastKnownCWD` (falling back to `$HOME` if the dir no longer exists).
3. For `.recovered`, post a one-time `Alert` on next-window-key with the `brokenFileURL` shown.
4. Add an integration test that writes a corrupt file, launches the test host, and asserts it boots into the empty default with the broken file preserved.

`Workspace.decoder` already uses ISO 8601 dates, matching the encoder — no surprises on date formats.

## Phase 2 fix — `7beddf3`

`WorkspaceManager.shared` (new in this commit, see #0030's resolution) handles load-on-launch:

1. Resolves the `WorkspaceStore` (URL → `~/Library/Application Support/Batty/workspace.json`).
2. Calls `workspaceStore.load()` and switches on the three-case result:
   - `.loaded(workspace)` → `AppStateStore(from: workspace.windows[0])` if any window exists, else empty default. `lastLoadResultDescription` records the load count for diagnostics.
   - `.recovered(workspace, brokenURL, error)` → same store-build path; `lastLoadResultDescription` records the broken-file path and the parse error for the (deferred) alert UI.
   - `.missing` → fresh empty `AppStateStore`.
3. The store becomes `WorkspaceManager.shared.store`, consumed by `RootWindowView`.

`AppStateStore(from: WindowState)` walks the persisted Codable tree and reconstructs `SessionRuntime` / `PaneRuntime` / `TabRuntime` / `SplitTreeNode` instances. Each `TabRuntime` gets a fresh `TerminalViewState` (and thus a fresh shell) — per PRD §6.7, running processes are not restored.

The corrupt-file path was already covered by `WorkspaceStore.load()`'s rename-to-broken-<timestamp> behavior (#0031 Phase 1 in `7afe781`). The manager surfaces the recovery state via `lastLoadResultDescription` for a future alert UI.

## Gotchas

- **No "your workspace was corrupt" alert UI yet.** The `WorkspaceManager` records the recovery state in `lastLoadResultDescription`, but no SwiftUI surface shows it. Adding a one-time `.alert` on next-window-key is a small follow-up — the data is in place; just needs a view binding.
- **Single-window load.** Only `windows[0]` is read; if a future user has multiple windows persisted, only the first one is restored. See #0030's Gotchas.
- **Shells start in `$HOME`, not the saved cwd.** `Tab.lastKnownCWD` is always nil at save time because pwd-tracking is `TerminalSurfacePwdDelegate`-blocked. When that delegate plumbing lands, the load path can pass `cwd:` through to `TerminalViewState` initialization and shells will respawn in their previous directories.
- **Bell feed history loads but stays empty.** `Workspace.bellFeed` is decoded into the manager's representation, but `BellFeedStore` (the consumer) is `#0025`-deferred. When `#0025` lands, wire the loaded entries into the store.
- **The `SurfaceRegistry` from `#0006` is not exercised** by this load path. Each `TabRuntime` creates its own `TerminalViewState`, which owns its own libghostty surface internally — the `[UUID: ghostty_surface_t]` registry is currently unused. May be retired in a cleanup pass; the registry's eventual purpose was for the bell-feed click-to-jump flow which has different state needs now that we have the runtime tree.
