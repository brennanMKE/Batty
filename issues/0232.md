## Description

Upgrade `FoundationModelsNameSuggester` (#0231) from a single-shot prompt to a tool-calling session. Give the model two tools: `ReadFile` (read the beginning of one top-level file, so README/config contents can supply the signal the path alone lacks) and `SetSessionName` (explicitly set the name). The model either calls `SetSessionName` once or ends without calling it — ending without a call is the "no good name" outcome, replacing the NONE sentinel-string convention.

## Long Description

FoundationModels supports tool calling: `LanguageModelSession(tools:instructions:)` accepts `[any Tool]`, and during a single `respond(to:)` the model may invoke tools repeatedly, with each tool's output fed back into its context, before finishing. Verified against the local macOS 26 SDK swiftinterface:

```swift
public protocol Tool<Arguments, Output>: Sendable {
    associatedtype Output: PromptRepresentable          // String works
    associatedtype Arguments: ConvertibleFromGeneratedContent
    var name: String { get }                            // defaulted
    var description: String { get }
    var parameters: GenerationSchema { get }            // auto-derived from @Generable Arguments
    func call(arguments: Arguments) async throws -> Output
}
```

Design:

- **`ReadFileTool`** — arguments: `fileName` (`@Generable` struct with a `@Guide` description saying it must be an exact name from the listing). Confined by construction: holds the folder path plus the precomputed set of allowed top-level entry names; any argument not in that set is rejected (no path traversal possible). Reads up to a small cap (~4 KB) and returns the excerpt; unreadable/binary files return a short "(not a readable text file)" string rather than throwing.
- **`SetSessionNameTool`** — arguments: `name`. Writes into a small `Sendable` result box and returns a confirmation string. **It must not touch `AppStateStore`** — the tool fires mid-inference; all staleness re-validation (`applySuggestedName`: session exists, `titleOverride` false, single-pane, anchor cwd unchanged, title still default) and `SessionNameSuggestion.sanitize` stay exactly where they are in the store. After `respond(to:)` returns, the suggester reads the box and returns its value (or nil); the model's final text response is ignored.
- **Instructions** updated for the tool flow: examine the path and listing; optionally call ReadFile on at most 2–3 promising files (README, manifest, notes); then either call SetSessionName once with a 2–4 word name, or finish without calling it if there is no meaningful signal.
- **Containment:** the change lives entirely inside `FoundationModelsNameSuggester` (plus the new tool types). The `SessionNameSuggesting` protocol seam, `AppStateStore` scheduling/cancellation/memo/apply logic, and all #0231 tests stay unchanged.
- **Context budget:** the on-device model's context window is small and tool outputs consume it (see the ChatGPT repo's context-window-exceeded handling). Keep the per-file excerpt cap tight, keep the entry listing at 20, and instruct "at most 2–3 files". If `respond(to:)` throws a context-window error, collapse to nil like every other error.
- **Latency:** a tool loop is multiple inference turns, slower than single-shot. Acceptable for a cancellable background task; existing per-session in-flight/cancellation behavior already covers it.
- Tool calls execute locally on-device; file contents never leave the machine.
- All #0231 constraints carry over: macOS 26+ `#available` gate, availability check per call, ephemeral names, never write `SessionNameCache`, never set `titleOverride`.

Testability: `ReadFileTool` argument validation (rejects names outside the allowed set, including `../` forms), excerpt capping, and binary-file handling are unit-testable directly with temp directories. `SetSessionNameTool` box behavior (last-call-wins or first-call-wins — pick one and test it) is unit-testable. The live tool-loop inference is manual-verification-only, like #0231.

## Steps to reproduce

1. On a macOS 26 machine with Apple Intelligence enabled, open a fresh single-pane session.
2. `cd` into a markerless folder whose folder name is opaque but which contains a descriptive README (e.g. `~/Projects/proj-x7` containing `README.md` describing a recipe manager).
3. Observe the session title.

## Expected behavior

The model reads the README via the ReadFile tool and names the session after what the folder actually contains (e.g. "Recipe Manager"), not just the path. With no meaningful files and an opaque path, it ends without calling SetSessionName and the title stays "Session N".

## Actual behavior

The #0231 implementation prompts with the path and the file-name listing only; file contents are never consulted, so an opaque path with a descriptive README still falls to "Session N".

## Resolution notes

> Replaced the single-shot prompt with a tool-calling `LanguageModelSession` (readFile + setSessionName); the name now arrives via a first-call-wins result box, and finishing without a tool call is the "no good name" outcome.

## Root cause

Feature gap, not a bug: the #0231 suggester prompted with the path and the file-name listing only, so a folder whose name carries no signal but whose README/manifest does still fell to `Session N`. FoundationModels tool calling lets the model consult file contents on demand without inflating every prompt.

## Fix

All inside `SessionNameSuggester.swift`; `SessionNameSuggesting`, `SessionNameSuggestion.sanitize`, and `AppStateStore` are untouched (verified — no edits needed; the suggester seam absorbs the whole change).

- **`SessionNameToolSupport`** (nonisolated enum, availability-independent) — `readExcerpt(fileName:folderPath:allowedNames:byteLimit:)`: rejects any name outside the precomputed allowed set with `"(no such file in the folder listing)"` — directory listings never contain `/`, so `../etc/passwd`-style traversal is impossible by construction. Reads up to 4096 bytes via `FileHandle`; binary/non-UTF-8/empty/unopenable content returns `"(not a readable text file)"` instead of throwing. The byte cap can split a multi-byte UTF-8 sequence, so up to 3 trailing bytes are dropped before declaring a file binary.
- **`SuggestedNameBox`** (nonisolated final class, `Sendable` via `OSAllocatedUnfairLock<String?>`) — the only thing `SetSessionNameTool` writes. **Policy: first-call-wins.** If the model errantly calls setSessionName more than once, the first name sticks, later `set` calls return `false`, and the tool's confirmation message tells the model the first name was kept. Chosen because it is deterministic if the model loops and the feedback discourages further calls.
- **`ReadFileTool` / `SetSessionNameTool`** — `#if canImport(FoundationModels)` + `@available(macOS 26.0, *)`, declared `nonisolated` so the `@concurrent` `Tool.call` requirement compiles under the package's MainActor default isolation; both are structs with only-`Sendable` stored properties (folder path + allowed-name set; the box). `@Generable` Arguments with `@Guide` descriptions; explicit tool names `readFile` / `setSessionName` matching the instructions.
- **Logging pass (09660ce)** — OSLog coverage of the whole naming flow via the existing file-scoped `SessionNameSuggester` logger: suggestion start (path + top-level entry count), every readFile call (rejected / unreadable-fallback / bytes read, logged from `SessionNameToolSupport.readExcerpt` so all model-initiated reads are visible), every setSessionName call (accepted or ignored under first-call-wins), and the final outcome (name via tool, or "model finished without calling setSessionName") with the `respond(to:)` duration. Logging only; no behavior change.
- **Failure-classification pass (283bf95)** — `readExcerpt` no longer collapses every failure into the single "unreadable, returning fallback" log + `(not a readable text file)` message. It now distinguishes, each with its own log line and tool message: directory entries (`entry is a directory` / `(this entry is a folder, not a readable file)`), missing read permission via `isReadableFile` checked before open (`no read permission` at .error with the full path / `(permission denied reading this file)`), open/read errors via do/catch with the underlying POSIX code in the log (`open failed:` / `read failed:` at .error; EACCES/EPERM-shaped errors return the permission message, others `(could not read this file)`), empty or whitespace-only files (`file is empty` / `(this file is empty)`), and non-UTF-8 content (`content is not UTF-8 text` / the existing `(not a readable text file)`). The prompt's folder listing now annotates directories as `name (folder)` via a `listingLine(forEntry:inFolderAtPath:)` helper — prompt text only; `topLevelEntries` and the readFile allowed-name set stay raw so tool arguments still match.
- **`FoundationModelsNameSuggester.suggestName`** — same per-call gates as before (`#available(macOS 26.0, *)`, `SystemLanguageModel.default.availability`). Builds `LanguageModelSession(tools: [readFile, setSessionName], instructions:)`; instructions tell the model to examine the path/listing, optionally readFile at most 2-3 promising entries, then either call setSessionName once (2-4 words, no punctuation) or finish without calling it. After `respond(to:)` the response text is ignored and the box value is returned (nil if never set). Every thrown error — including context-window-exceeded — collapses to nil. The allowed-name set is exactly the (non-hidden, 20-capped) listing shown in the prompt.

All #0231 guarantees carry over automatically since the store is untouched: ephemeral names, never write `SessionNameCache`, never set `titleOverride`, staleness re-validation in `applySuggestedName`, sanitize on the caller side.

## Gotchas

- **The live tool loop needs manual sign-off on a macOS 26 + Apple Intelligence machine** — unit tests cover the helpers, not the model actually invoking the tools. To verify: cd a fresh single-pane session into a markerless folder with an opaque name but a descriptive README (e.g. `~/Projects/proj-x7` containing a README describing a recipe manager) and confirm the title reflects the contents (e.g. "Recipe Manager"); with no meaningful files the title must stay `Session N`. Marked `resolved`, not `closed`, pending that verification.
- The Tool protocol's `call` is `@concurrent`, so under the package's `defaultIsolation(MainActor.self)` the tool types and their helpers must be `nonisolated` — a MainActor-isolated `call` does not satisfy the witness. Same reason `SuggestedNameBox` uses `OSAllocatedUnfairLock` instead of relying on actor isolation.
- A 4 KB `FileHandle.read(upToCount:)` of a valid UTF-8 file can land mid-scalar; without the drop-up-to-3-trailing-bytes retry in `decodeUTF8Prefix`, real text files would be misreported as binary.
- Tool error behavior is "return a message string", not "throw" — a thrown tool error would surface as a session error and kill the whole suggestion, whereas a short diagnostic string lets the model recover (pick another file or give up gracefully).
- Latency: the tool loop is multiple inference turns, slower than #0231's single shot. Acceptable: the request is a cancellable background task and the store's per-session in-flight/cancellation behavior already covers it.
- The "many readFile calls log unreadable" symptom had a silent major contributor: subdirectories appear in the prompt listing, the model readFiles them, open succeeds but read fails (EISDIR), and everything collapsed into the one fallback. Directories are now classified explicitly and annotated `(folder)` in the listing. Separately on TCC: `isReadableFile` uses access(2) and never triggers a macOS consent prompt, but open(2) in a TCC-protected folder does — so the first model-initiated read in Documents/Desktop/Downloads may pop a consent dialog for Batty, and a denial then surfaces as permission-denied in these logs.
