# 0232 — Use FoundationModels tool calling (ReadFile, SetSessionName) in the session name suggester

| | |
|---|---|
| **Status** | open |
| **Module** | Session |
| **Platform** | macOS |
| **First seen** | 2026-06-10 |

## Description

Upgrade `FoundationModelsNameSuggester` (#0231) from a single-shot prompt to a tool-calling session. Give the model two tools: `ReadFile` (read the beginning of one top-level file, so README/config contents can supply the signal the path alone lacks) and `SetSessionName` (explicitly set the name). The model either calls `SetSessionName` once or ends without calling it — ending without a call is the "no good name" outcome, replacing the NONE sentinel-string convention.

## Long Description

FoundationModels supports tool calling: `LanguageModelSession(tools:instructions:)` accepts `[any Tool]`, and during a single `respond(to:)` the model may invoke tools repeatedly, with each tool's output fed back into its context, before finishing. Verified against the local macOS 26 SDK swiftinterface:

```swift
public protocol Tool<Arguments, Output>: Sendable {
    associatedtype Output: PromptRepresentable          // String works
    associatedtype Arguments: ConvertibleFromGeneratedContent
    var name: String { get }                            // defaulted
    var description: String { get }
    var parameters: GenerationSchema { get }            // auto-derived from @Generable Arguments
    func call(arguments: Arguments) async throws -> Output
}
```

Design:

- **`ReadFileTool`** — arguments: `fileName` (`@Generable` struct with a `@Guide` description saying it must be an exact name from the listing). Confined by construction: holds the folder path plus the precomputed set of allowed top-level entry names; any argument not in that set is rejected (no path traversal possible). Reads up to a small cap (~4 KB) and returns the excerpt; unreadable/binary files return a short "(not a readable text file)" string rather than throwing.
- **`SetSessionNameTool`** — arguments: `name`. Writes into a small `Sendable` result box and returns a confirmation string. **It must not touch `AppStateStore`** — the tool fires mid-inference; all staleness re-validation (`applySuggestedName`: session exists, `titleOverride` false, single-pane, anchor cwd unchanged, title still default) and `SessionNameSuggestion.sanitize` stay exactly where they are in the store. After `respond(to:)` returns, the suggester reads the box and returns its value (or nil); the model's final text response is ignored.
- **Instructions** updated for the tool flow: examine the path and listing; optionally call ReadFile on at most 2–3 promising files (README, manifest, notes); then either call SetSessionName once with a 2–4 word name, or finish without calling it if there is no meaningful signal.
- **Containment:** the change lives entirely inside `FoundationModelsNameSuggester` (plus the new tool types). The `SessionNameSuggesting` protocol seam, `AppStateStore` scheduling/cancellation/memo/apply logic, and all #0231 tests stay unchanged.
- **Context budget:** the on-device model's context window is small and tool outputs consume it (see the ChatGPT repo's context-window-exceeded handling). Keep the per-file excerpt cap tight, keep the entry listing at 20, and instruct "at most 2–3 files". If `respond(to:)` throws a context-window error, collapse to nil like every other error.
- **Latency:** a tool loop is multiple inference turns, slower than single-shot. Acceptable for a cancellable background task; existing per-session in-flight/cancellation behavior already covers it.
- Tool calls execute locally on-device; file contents never leave the machine.
- All #0231 constraints carry over: macOS 26+ `#available` gate, availability check per call, ephemeral names, never write `SessionNameCache`, never set `titleOverride`.

Testability: `ReadFileTool` argument validation (rejects names outside the allowed set, including `../` forms), excerpt capping, and binary-file handling are unit-testable directly with temp directories. `SetSessionNameTool` box behavior (last-call-wins or first-call-wins — pick one and test it) is unit-testable. The live tool-loop inference is manual-verification-only, like #0231.

## Steps to reproduce

1. On a macOS 26 machine with Apple Intelligence enabled, open a fresh single-pane session.
2. `cd` into a markerless folder whose folder name is opaque but which contains a descriptive README (e.g. `~/Projects/proj-x7` containing `README.md` describing a recipe manager).
3. Observe the session title.

## Expected behavior

The model reads the README via the ReadFile tool and names the session after what the folder actually contains (e.g. "Recipe Manager"), not just the path. With no meaningful files and an opaque path, it ends without calling SetSessionName and the title stays "Session N".

## Actual behavior

The #0231 implementation prompts with the path and the file-name listing only; file contents are never consulted, so an opaque path with a descriptive README still falls to "Session N".
