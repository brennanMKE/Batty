## Description

Expose theme selection in the View menu and apply the chosen theme to every live Terminal Session without restarting them. Concepts → Theme: scope is app-wide for v1.

**Acceptance criteria:**
- A "Theme" submenu appears under View, populated with every theme discovered in #0032.
- Selecting a theme applies it to every live Terminal Session immediately (no surface restart, no flicker).
- The selection is persisted in `UserDefaults` and restored on launch.
- The current theme is indicated with a checkmark in the menu.

## Notes

- libghostty surfaces accept config updates at runtime — push the new color palette via the surface config API instead of reconstructing surfaces.
- Per-surface theme overrides are out of scope for v1 (Concepts → Theme).
- If Theme application turns out to require a surface restart (libghostty limitation), document that and reduce the acceptance criterion to "applies on next surface creation"; flag a follow-up.

## Revised approach — 2026-05-08

`GhosttyTheme` (now a `BattyKit` dependency) ships **485 prebuilt themes** via `GhosttyThemeCatalog` plus `GhosttyThemeDefinition+TerminalConfiguration.swift` which produces a `TerminalConfiguration` directly applicable to a `TerminalViewState.theme`. This subsumes most of #0032's `builtInThemes` and dramatically simplifies the menu UI.

**Revised acceptance criteria:**
- The View → Theme submenu is populated from `GhosttyThemeCatalog.allThemes` plus user-installed `.ghostty` files discovered by our existing `ThemeStore.discoverAll(...)` (from #0032). Discovered themes shadow catalog entries of the same name.
- Selection writes to `UserDefaults` and pushes a `TerminalConfiguration` (built via `GhosttyThemeDefinition`'s extension) into every live `TerminalViewState.theme`. Live application without surface restart is the expected path.
- Search-as-you-type within the menu is nice-to-have, leveraging `GhosttyThemeCatalog.search(_:)`. Skip if it adds complexity to the menu wiring.

**On overlap with #0032:** our `Theme` / `ThemeColor` / `ThemeParser` are still useful for parsing user-installed `.ghostty` files in `~/.config/ghostty/themes/`. The `builtInThemes` constant becomes dead code once the catalog is live; remove it as part of this issue (see #0032's Notes for the deprecation reference).

## Root cause

Feature gap. M8 needs a way for the user to pick a theme; with `GhosttyTheme` shipping a 485-theme catalog and `GhosttyThemeDefinition.toTerminalTheme()` doing the format conversion, the work reduces to a SwiftUI menu plus a "walk all surfaces and apply" helper.

## Fix

- `BattyKit/Sources/BattyKit/ThemePreference.swift` — defines `ThemePreference.defaultsKey` (the `@AppStorage` key) and an `applyThemeToAllSurfaces(_:)` extension on `AppStateStore` that walks `sessions × tree.allPanes × pane.tabs` and calls `controller.setTheme(theme.toTerminalTheme())` on each.
- `BattyKit/Sources/BattyKit/BattyCommands.swift` — adds a new `CommandMenu("Theme")` containing one Button per `GhosttyThemeCatalog.allThemes` entry. Active selection shows with a checkmark via `Label(systemImage: "checkmark")`. Disabled when no store is focused. Picking a theme writes the `@AppStorage` key and calls `applyThemeToAllSurfaces`. The selection persists across launches.

`TerminalController.setTheme(_:)` is GhosttyTerminal's public live-update API — `reconfigure()` runs internally and applies to the existing surface; no restart needed.

## Files changed

- `BattyKit/Sources/BattyKit/ThemePreference.swift` — new (~17 lines).
- `BattyKit/Sources/BattyKit/BattyCommands.swift` — new `@AppStorage`, new `CommandMenu("Theme")`, new `selectTheme(_:)` helper.

## Gotchas

- **Visual verification needed.** Theme menu has 485 entries; macOS will scroll. Click one → all live terminals update colors/palette without restart. Checkmark moves to the new selection. Quit + relaunch → selection restored. `xcodebuild build` passes; resolved-not-closed.
- **Newly-created tabs after a theme change use GhosttyTerminal's default**, not the active theme. The user has to re-pick from the menu to push the theme through to new terminals. Threading the active theme into `TabRuntime.init` (or having `applyThemeToAllSurfaces` re-fire on every `addTab`) is reasonable polish; deferred. Worth a follow-up.
- **ThemeStore.builtInThemes** (from #0032) is now redundant given the catalog. Left in place — retiring it is a one-liner removal that can ride in any future change.
- **Flat 485-theme menu** is wide UX. A grouped-by-letter submenu structure or a searchable picker (using `GhosttyThemeCatalog.search(_:)`) would be nicer; deferred. macOS scrolls long menus natively.
- **Default theme on first launch is empty `""`** which doesn't match any theme. The active-state checkmark won't appear; first user click sets the default. Acceptable; could pre-populate with a sensible default like "Tokyo Night" in a polish pass.
