# 0281 — Agent context: inject `BATTY_*` env vars at spawn, add `batty whoami`, and build the shared target-resolution chain

|---|---|

## Description

First child of the #0257 umbrella and the prerequisite for every agent-facing verb: an agent (Claude Code) running *inside* a pane must know which session/pane/tab it is in before it can split, close, or inspect anything relative to itself. Three deliverables:

1. **Env injection at spawn:** inject `BATTY_SESSION_ID`, `BATTY_PANE_ID`, `BATTY_TAB_ID` into every surface at spawn, so every child process in the pane (the shell, Claude Code, `batty` itself) inherits them. #0257 Foundation §2 describes prepending `export …;` to the launch command (supacode's pattern).
2. **`batty whoami [--json]`** — prints that context **from env alone**, no app round-trip (#0257 Foundation §3). Works even when the app is unreachable.
3. **The shared target-resolution chain** — explicit flag → `BATTY_*` env → focused element — implemented once as a unit-testable helper that #0282 (`pane split`), #0283 (`pane close`), and the already-shipped `batty session info` all consume.

## As-built starting points (verified against source 2026-07-26)

- **The CLI today** (`BattyKit/Sources/batty/BattyCLI.swift`) has subcommands `new` (default; bare `batty` / `batty <path>`), `ping`, `status`, `list`, and `session` (with only `info`). No `whoami`, no `pane` noun, and `BATTY_*` appears nowhere in app code — only in comments anticipating this issue.
- **#0274 left the seam for exactly this work.** `SessionInfoCommand.resolveSessionID()` (`BattyKit/Sources/batty/SessionInfoCommand.swift`) implements `--session` flag → `nil` fallthrough, with a marked comment: *"the eventual resolution order is `--session` flag → `BATTY_SESSION_ID` env var → focused session … its env-var read slots in as a middle branch in `resolveSessionID()` below, between the flag check and the `nil` fallthrough."* And `AppStateStore.sessionInfoPayload(sessionID: UUID? = nil)` (`BattyKit/Sources/BattyKit/Runtime/AppStateStore.swift`, ~line 211) already accepts `nil` as "no explicit target," so retrofitting the env branch touches nothing app-side. Retrofit `session info` onto the shared helper as part of this issue so there is one chain, not two.
- **The spawn-time configuration point** is `TabRuntime.applyShellAndAppearancePreferences(to:)` (`BattyKit/Sources/BattyKit/Runtime/TabRuntime.swift`), which builds the `TerminalConfiguration` and sets `builder.withCustom("command", shell)` — but **only when the custom-shell preference is non-empty**. The default case sets no `command` at all, so the "prepend `export …;`" approach must also synthesize a command line for the default-shell case (or find an env-passing mechanism in the libghostty configuration — not verified whether one exists).
- **An ordering wrinkle the implementer must resolve:** that configuration is applied inside `TabRuntime.init`, but a `TabRuntime` is constructed *before* it is placed into a `PaneRuntime` (`SplitTree.makePane` builds `PaneRuntime(tabs: [TabRuntime(...)])`) and before the pane joins a session — so `BATTY_PANE_ID`/`BATTY_SESSION_ID` are not knowable at the point the config is currently set. The ids are all stable UUIDs, so the fix is plumbing (pass ids down, or set/update the config later, before the surface actually spawns), not a model change. Not deciding the mechanism here; flagging that the obvious injection point does not currently have the data.

## Decisions carried from #0257 / #0274

- **`whoami` is env-only in v1.** #0274 dropped the topology snapshot and with it the pty-device-path field that would have powered a `ttyname(stdin)` fallback for scrubbed environments (`sudo`, nested shells). No runtime plumbing exposes a tab's pty device path today; #0257's amendment says the implementer must either add that plumbing or accept env-only. **This issue accepts env-only** — `whoami` fails cleanly (exit 1, message on stderr) when the env is absent. If the scrubbed-env case proves painful, the pty plumbing is a new child under #0257, not scope creep here.
- **Env is a hint, not truth** (#0257 Notes): `BATTY_*` reflects spawn time. Ids are stable UUIDs so this holds today; if panes ever move between sessions, the authoritative pane→session mapping is a live `batty list` reply, and the app should resolve session from the pane id rather than trust `BATTY_SESSION_ID`.
- **Helper placement:** the chain needs only Foundation (env access + UUID parsing), so it belongs in a target the CLI links without pulling in the app — `BattyCLICore` or `BattyXPCCore`, never full `BattyKit` (the #0252 link-dependency hazard and the #0249 build-graph hazard both apply to anything the `batty` executable links).

## Binding constraints (copied — do not merely cross-reference)

- **Payloads are `Codable, Sendable` structs carried as JSON-encoded `Data`** inside the `@objc` protocols, `nonisolated` at type level; protocol requirements are `nonisolated func`; reply blocks `@escaping @Sendable`. Guard any new payload type with off-actor round-trip helpers as `XPCContractTests` does. (`whoami` itself does no XPC; this binds any payload work done while retrofitting `session info`.)
- **Every Foundation-supplied handler closure gets `@Sendable`** — there is no compiler warning, and the failure is a silent `SIGTRAP` inside the very handler that would have logged the error.
- **`os.Logger` interpolation of a dynamic `String` defaults to `.private`** — add `privacy: .public` explicitly (#0274 nearly shipped eight blinded log lines this way).
- **Verify isolation guards under a forced rebuild** (`rm -rf .build`); stale targets produced false "still builds" results twice on the XPC track.
- **Code-signing protocol:** never run `scripts/build.sh` for iteration (its `unit` path can't disable signing); use `cd BattyKit && swift test` and `xcodebuild … CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO`. The user's Developer ID certificate was revoked once by repeated signed local builds.
- **Anything aimed at a background session must not steal focus or change the active session** — assert against the store (`selectedSessionID`, focused pane, active tab), not merely absence of a crash.

## Verification expectations

Follow the #0271/#0274 pattern:

- **Unit tests for the pure parts:** the resolution chain's precedence (explicit flag beats env; env beats the `nil`/focused fallthrough; each id — session, pane, tab — resolved independently), malformed-UUID handling for both flag and env values (decide and test whether a malformed env value errors or falls through — document the choice), and `whoami` output shape for both plain and `--json` forms, including the missing-env failure.
- **Retrofit test:** `session info` with `BATTY_SESSION_ID` set and no `--session` flag targets the env session; with both set, the flag wins.
- `cd BattyKit && swift test` and `xcodebuild … CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO` green; `otool -L` on `batty` still shows zero `@rpath` dependencies.
- **Needs the user's runtime sign-off** (do not disturb the running app; coordinate): in a freshly spawned pane, `echo $BATTY_PANE_ID` prints a UUID matching `batty list` output; `batty whoami` agrees; a pane created by a split carries its *own* ids, not the parent's; ids survive into a nested shell and into a running agent's environment.
