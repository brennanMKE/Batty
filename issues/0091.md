## Description

`BattyUITests/BattyUITests.swift` and `BattyUITestsLaunchTests.swift` ship the Xcode-generated placeholders — `testExample()` that calls `app.launch()` with no assertions, and `testLaunchPerformance()` that depends on baseline measurements that aren't set up. They produce no signal AND have actively hurt CI: prior runs reported "Failed to terminate co.sstools.Batty" because `QuitConfirmation` blocks teardown when sessions are still open.

Bootstrap this target into something useful before the regression tests in `#0092`–`#0095` land. Replace the placeholders, set up a clean teardown that bypasses `QuitConfirmation`, and add a small harness with helpers the regression tests can lean on.

## What this issue ships

### 1. Delete the placeholders

- Remove `testExample()` and `testLaunchPerformance()` from `BattyUITests.swift`.
- Remove `BattyUITestsLaunchTests.swift` entirely (or keep the file with one assertion-bearing replacement test if it carries useful Xcode-generated boilerplate).

### 2. Clean shutdown that survives `QuitConfirmation`

Prior runs broke because `xcodebuild test`'s teardown sends `terminate()` to the app, but `applicationShouldTerminate` returns `.terminateCancel` when `QuitConfirmation.shouldQuitOrPrompt` shows a modal alert and the test process can't dismiss it.

Two paths to fix, pick whichever is cleanest:

- **Launch flag.** Pass `-co.sstools.Batty.bypass-quit-confirmation YES` (or env `BATTY_UI_TEST_MODE=1`) when the test launches the app. `QuitConfirmation.shouldQuitOrPrompt` early-returns `true` when the flag is set. Doesn't affect production behavior.
- **Force-kill teardown.** Call `app.terminate()` and follow with a SIGKILL fallback after a timeout. Less clean — leaves Workspace's `applicationWillTerminate` save unflushed.

Recommend the launch flag.

### 3. Test harness helpers

A `BattyUITests/Support/` directory with helpers:

- `func launchBatty(testMode: Bool = true) -> XCUIApplication` — launches with the bypass flag set.
- `func mainWindow(in app: XCUIApplication) -> XCUIElement` — fetches the primary window with a stable identifier.
- `func sidebar(in app: XCUIApplication) -> XCUIElement` — the sessions sidebar.
- `func sessionRow(named: String) -> XCUIElement` — by visible title.
- `func tabChip(named: String) -> XCUIElement` — by chip title.
- `func paneArea(at index: Int) -> XCUIElement` — for click-to-focus tests.
- `func newSession()` / `func newTab()` / `func splitHorizontal()` / `func splitVertical()` — convenience that uses keyboard shortcuts.
- `func typeAtPrompt(_ text: String, in app: XCUIApplication)` — types into the focused terminal.

The SwiftUI views need stable `.accessibilityIdentifier(...)` so XCUITest can find them reliably. Audit `SessionSidebarView`, `PaneView`, `BattyTabChip`, `SessionDetailView`, and the toolbar — add identifiers as needed.

### 4. Sentinel-file shell helper

UI tests can't read terminal text (libghostty renders via Metal; XCUI sees opaque pixels). The escape hatch is to have the shell write to a sentinel file the test can read:

- A helper `func touchSentinel(name: String, in app: XCUIApplication)` types `echo done > /tmp/batty-ui-test-<uuid>-<name>` into the focused terminal.
- A helper `func waitForSentinel(name: String, timeout: TimeInterval) throws` polls the file system until the file exists.
- A teardown helper that sweeps `/tmp/batty-ui-test-*` files after each test.

This is essential for `#0095` (terminal persistence — "did this process survive a tab switch?") which is otherwise un-assertable.

### 5. One smoke test that actually asserts

After deleting the placeholders, leave ONE smoke test in the target that:

- Launches the app.
- Asserts the main window exists.
- Asserts the default session "Session 1" appears in the sidebar.
- Asserts a terminal placeholder is visible in the detail area.

This proves cold-launch UI integrity in the simplest way.

### 6. CI / Xcode wiring

- The test scheme already has `BattyUITests` enabled — verify it still does.
- Document in `docs/` (or a new `BattyUITests/README.md`) how to run UI tests locally and what the launch flag does.

## Build / test

```
xcodebuild -scheme Batty -destination 'platform=macOS' test
```

The full test run should pass without "Failed to terminate co.sstools.Batty" errors. UI tests run in ~30s for the single smoke test.

## Notes

- `BattyUITests` shares the user's UserDefaults / Application Support directory by default. Tests should NOT mutate the user's persisted state (workspace.json, session-name-cache.json). The bypass flag can also set a temp UserDefaults suite for test runs — recommend doing this to keep test isolation.
- Related: `#0090` (the vertical-split focus bug a UI test would catch), `#0092`–`#0095` (the actual regression coverage that builds on this harness).
