## Description

Tier 2 localization target. Brazil is the largest developer cohort in Latin America by a wide margin and a major Apple market. Brazilian Portuguese is distinct enough from European Portuguese that they're tracked as separate locales — only `pt-BR` is in scope here.

Depends on `#0107`.

## Acceptance criteria

- Every key in `Localizable.xcstrings` has a non-empty `pt-BR` translation, reviewed by a native speaker.
- Launching with macOS Language & Region set to Português (Brasil) shows the full UI translated.
- Visual sweep for string-length expansion (~15–25% longer than English).
- `## Files changed` should list the `.xcstrings` diff.

## Notes

- European Portuguese (`pt-PT`) is *not* in scope and is intentionally not in the Tier 1–3 list — significantly smaller dev population. Can be added later as a separate issue if requested.
- Terminology: "guia" or "aba" (tab), "painel" (pane), "atalho" (shortcut), "sessão" (session). Confirm against Terminal.app's pt-BR strings for parity.
- Sparkle ships pt-BR strings.

## Root cause

`Localizable.xcstrings` had no `pt-BR` translations after the
localization foundation (`#0107`) landed. Users running macOS with
Language & Region set to Português (Brasil) fell back to English for
every catalog-driven string in the app shell (quit-confirmation alert,
paste-confirmation sheet, sidebar bell-count tooltip).

## Fix

Populated every key in `Batty/Localizable.xcstrings` with Brazilian
Portuguese (`pt-BR`) translations. Strings follow Apple's macOS pt-BR
UI register — *Colar* for paste, *Encerrar* for quit (mirroring system
menu bar entries like "Encerrar Finder" and "Encerrar Safari"),
*Cancelar* for cancel, and the *você* form throughout. Plural
variations follow pt-BR CLDR rules where `one` covers 0–1 and `other`
covers 2+. The `Batty` brand stays in Latin script.

## Files changed

- `Batty/Localizable.xcstrings` — added `pt-BR` entries for all 7
  keys (Batty, Paste %lld lines?, There %lld open terminal(s).,
  %lld unseen bell event(s), Quit Batty?, Quit, Cancel).

## Gotchas

- Translations are LLM-authored, not native-speaker reviewed; a
  Brazilian-Portuguese pass before release is still advisable per the
  issue's acceptance criteria.
- **Encerrar vs Sair.** Apple's pt-BR macOS menu bar uses *Encerrar*
  for the application-quit command (Encerrar Finder, Encerrar Safari,
  Encerrar Mail), so this catalog matches: the alert title reads
  *Encerrar o Batty?* and the primary button reads *Encerrar*. *Sair*
  is also widely understood in Brazilian Portuguese and is the form
  Android / web apps tend to use, but it would diverge from system
  idiom on macOS specifically. If a future review prefers *Sair*, the
  swap is two strings: the alert title and the button.
- **Brand article.** Brazilian Portuguese typically uses the definite
  article in front of proper-noun apps in running prose
  (*Encerrar **o** Batty?* the way Apple writes *Encerrar **o**
  Safari?*), so the title carries the leading *o*. The standalone
  *Quit* button stays bare — buttons don't take an article.
- **Plural rule.** pt-BR follows CLDR's two-form English-style rule:
  `one` for `n == 1` (Apple's pt-BR also routes `n == 0` through the
  singular branch in alert text, e.g. *Há 0 terminal aberto.* —
  though that path is unreachable here because the quit alert is
  suppressed when no terminals are open), `other` for `n >= 2`. Plural
  agreement on adjectives is reflected: *aberto / abertos*,
  *visto / vistos*.
- **Bell terminology.** Used *campainha* (Apple's standard pt-BR for
  notification-style "bell" indicators) rather than *sino* (which
  reads as a literal church bell) or *campana* (European Portuguese).
  *Não visto / não vistos* mirrors *unseen* better than *não lido /
  não lidos* (read), because bell events aren't really "read" — they
  flash and are dismissed.
- **Length expansion.** pt-BR runs ~15–25% longer than English; the
  longest plural string here is `%lld eventos de campainha não vistos`
  (about 1.8× the English source), so the bell-count tooltip layout
  in the sidebar deserves a visual check.
- "Batty" stays in Latin script — *not* hispanicized or accented.
  Apple consistently keeps Latin product names un-localized in pt-BR
  UI (Safari, Mail, Xcode all appear in Latin form), so the brand
  survives every alert as-is.
- Catalog-only change; no Swift source touched. `project.pbxproj`
  `knownRegions` does not need to enumerate `pt-BR` — Xcode 15+
  String Catalogs are self-describing and read locale columns
  directly.
