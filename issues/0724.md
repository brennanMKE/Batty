# 0724 — The user cannot choose a Session's SF Symbol, so a plain Session always shows a dot and Save as Project starts every Project with the folder symbol

| | |
|---|---|
| **Status** | open |
| **Module** | Session / Sidebar / Projects |
| **Platform** | macOS |
| **First seen** | 2026-11-22 |
| **Target** | 1.5.0 |

## Description

User request (2026-11-22), verbatim: "We also let the user rename the session and set the color which are persisted. At least the name is persisted. Why not let them pick the symbol as well. File issues to let the user select the SF Symbol of a session and also make sure we persist the color change. We also want to use AFM to automatically select a symbol as long as we can get back a high confidence the symbol is a good match. This also makes it very easy to save as a project as we can take the name, color and symbol along with the path to use in the project."

A plain (non-Project) Session's Sidebar row always draws a small `circle.fill` tinted with the Session color. Only a Project-backed Session gets a symbol, and only the Project's. The user wants to pick a Session's SF Symbol the same way they rename it and set its color: from the Sidebar row's context menu, remembered with the Session the same way the name is, and carried into **Save as Project** so a Project is name + color + symbol + path in one step.

## Current state (verified 2026-11-22)

- Row icon: `SessionRowIcon.systemName(projectSymbol:customName:)` returns `plainSystemName = "circle.fill"` when the Session is not Project-backed — `BattyKit/Sources/BattyKit/Views/SessionSidebarView.swift:403-410`; `SessionRowIconView` draws it `.imageScale(.small)`, a Project symbol at normal scale, both in an 18pt-wide frame — `SessionSidebarView.swift:412-433`.
- Session symbol state exists only for Projects: `SessionRuntime.projectSymbol: ProjectSymbol?` and `projectSymbolName: String?`, `internal(set)`, documented as in-memory — `BattyKit/Sources/BattyKit/Runtime/SessionRuntime.swift:75-88`. They are written only by `WindowRuntime.applyProjectIdentity` — `WindowRuntime.swift:383-393` — and `AppStateStore.applyProjectSave`, which overwrites them unconditionally on every Project save — `AppStateStore.swift:1727-1728`.
- Where rename and color are set today: the row's context menu `SessionRowMenu` — **Rename**, **Reset Name**, **Set Color…**, **Reset Color** — `SessionSidebarView.swift:522-545`; the sheets are presented from `SessionSidebarView` (`RenameSessionSheet`, `SessionColorPickerView`) — `SessionSidebarView.swift:142-167`.
- Reusable picker: the Project Editor's `ProjectSymbolPicker` opens a private `ProjectSymbolSheet` (name filter + grid over `SFSymbolCatalog`, curated `ProjectSymbol` names always kept) — `BattyKit/Sources/BattyKit/Views/ProjectSymbolPicker.swift:11,49,84`. It is bound to `ProjectEditorViewModel` (`model.setSymbolName`), so the sheet needs to be lifted out (taking `selectedName`, `color`, `choose`, `cancel`, which it already does) to be shared.
- Save as Project: `SaveSessionAsProject.draft(for:destination:store:)` — `BattyKit/Sources/BattyKit/Views/SaveSessionAsProject.swift:24-61` — fills name (`SessionProjectCapture.suggestedName`, the Session title unless it is still `Session N`), root path and the Session color (`SessionProjectCapture.newDraft`, `SessionProjectCapture.swift:304-313`); the symbol is left at `ProjectDraft`'s default `.folder` (`ProjectDraft.swift:79`). After [#0712](0712.md) the save links the source Session to the new Project, so whatever symbol the user had would be replaced by `folder.fill` unless the draft carries it.
- Name memory is per working directory (`SessionNameCache`); see [#0723](0723.md) for the color half and the storage shape this issue extends.

## Expected behavior

1. The Sidebar row context menu gains **Set Symbol…** (after Set Color…) and, when a symbol is set, **Reset Symbol**. Set Symbol… opens the shared symbol sheet (filter + grid), tinted with the Session's color, with the current symbol selected.
2. The row draws the chosen symbol in place of the dot, in the **same 18pt icon frame** — the row gets no new element, line or height (binding: never grow the Session row). Without a choice the dot stays exactly as today.
3. Remembered the same way as the name: choosing a symbol on a Session whose anchor cwd is a project folder records it per directory in the store extended by [#0723](0723.md); Reset Symbol forgets it; a new Session, or a single-Pane Session that `cd`s into that folder, shows the remembered symbol. Non-project folders (home, `/`, temp) are not recorded. A user-chosen symbol on a live Session is never replaced by `cd`.
4. Save as Project (new Project) pre-fills the draft's symbol from the Session's symbol (a curated `ProjectSymbol` name maps to `symbol`, anything else to `customSymbolName`), alongside the name, color and root path it already fills. With no Session symbol the draft keeps `.folder`.
5. VoiceOver: the row's accessibility value names a chosen Session symbol the way it names a Project symbol (`SessionSidebarView.swift:51`); the UI-test icon hook (`rowIconName`, `SessionSidebarView.swift:73-77`) reports it.
6. Settings/Help/docs: Help and `Concepts.md` → Session describe the symbol; no new Settings row is needed (the feature appears only when the user opens the menu).

## Decision for the user: Project-backed Sessions

A Project-backed Session shows the Project's symbol, and every Project Editor save overwrites the Session's symbol (`AppStateStore.swift:1727-1728`). Options:

- **(A, recommended)** No **Set Symbol…** on a Project-backed Session; the menu already has **Edit Project…**, which owns the symbol. Simplest, and the Project stays the one source of truth.
- **(B)** Mirror color: Set Symbol… writes a Session-level symbol that wins on the row until a Project Editor save **that changes the symbol** (gate `applyProjectSave` on a `symbolChanged` check like `colorChanged`), and **Update "Project"…** carries it into the draft as Update already does for color (`SaveSessionAsProject.swift:46-49`).

## Acceptance criteria

- A plain Session can be given any SF Symbol from the catalog via the row's context menu, and reset to the dot.
- The row's height and layout are unchanged with or without a symbol (same icon frame).
- The choice is remembered per project folder across relaunch, by the same store as the name and color (#0723), and never overrides a live user choice on `cd`.
- Save as Project from a Session with a symbol opens the Project Editor with that symbol, the Session's name (unless default), color, and root path pre-filled; after saving, the linked Session (#0712) still shows the same symbol.
- Project-backed Sessions behave per the decision above.
- The Project Editor's symbol picker still works unchanged after the sheet is shared.
