## Description

Any change to font size, cursor style or cursor blink in Settings replaces the terminal configuration of every existing Tab with a smaller one that has no `keybind = clear`. All of Ghostty's default bindings return on those live surfaces, and a binding wins over Batty's menu. A Cmd chord that Batty's key monitor doesn't claim now goes to libghostty until the Tab is replaced. Tabs that have not spawned their surface yet also lose their command and `BATTY_*` environment.

**Shipped 1.3.4 has this.** `TabRuntime.swift`, `SettingsPreferences.swift`, `SettingsView.swift`, `Package.swift` and `Package.resolved` are identical on `v1.3.4`, `release/1.3` and `main`.

**The clipboard regression does not recur.** This was reported as selections overwriting the clipboard again (#0286). The line `copy-on-select = false` is dropped, but at the current pin a selection no longer reaches the system pasteboard either way. See "Clipboard: measured, no regression" below.

## Resolution notes

> 🟢 Resolved 2026-11-03 — An appearance change now re-renders every Tab of every terminal Pane through the Tab's own builder, so font and cursor change and no other configuration line is lost.

## Root cause

Confirmed from the code and the measurements below. Batty built a Tab's override set in two places, and `setTerminalConfiguration` replaces the whole set. `AppStateStore.applyAppearanceToAllSurfaces` built one configuration per Pane from `withSharedPreferences` alone, so every font or cursor change removed `keybind = clear`, `cmd+c`, `copy-on-select`, `command`, `wait-after-command`, `abnormal-command-exit-runtime` and `env BATTY_*` from every Tab of that Pane. `release/1.3` has the bug in its older one-configuration-for-every-Tab form. The issue text's corrections are listed under "Corrections to this issue's text" in the Plan.

## Fix

Removed the second builder, as planned. `applyAppearanceToAllSurfaces` resolves a new `TerminalAppearance` from `store.preferences`, reads `backgroundGate.settings()` once, and calls `PaneRuntime.refreshAppearance` on every Pane of every window. That guards on `kind == .terminal` only, so overridden Panes get the font and keep their override. `TabRuntime.refreshAppearance` re-renders through `applyShellAndAppearancePreferences`, which takes the appearance as a parameter defaulting to the `.standard` reads.

Also: replaced the stale `copy-on-select` comment, reworded the `withSharedPreferences` and `applyAppWideBackgroundToAllSurfaces` doc comments, corrected `docs/ssh-colors-and-terminfo.md`, and renamed the tests and comments that described two builders.

No deviation from the plan.

## Plan

Written 2026-11-03 against `main` at `6a12d2ff` (#0376 landed). Tier: fast. Patch-release candidate for 1.3.5.

### Approach

Remove the second builder. `applyAppearanceToAllSurfaces` stops building a configuration and asks each Tab to re-render through `TabRuntime.applyShellAndAppearancePreferences`, as `applyAppWideBackgroundToAllSurfaces` already does. An appearance change then can't drop a line, including lines added later.

The design is right, with three traps if `refreshAppWideBackground` is copied as it stands:

1. **Font and cursor must be passed in.** The Tab builder reads them from `.standard`, while the store reads `store.preferences`. Re-rendering with the Tab's own reads would break the #0426 behaviour that `applyAppearanceToAllSurfacesUpdatesEveryWindow` guards.
2. **Don't copy the Pane guard.** `PaneRuntime.refreshAppWideBackground` skips Panes with a Pane or Session override. A font change must reach those too, and they keep their override. Guard on `kind == .terminal` only.
3. **Pass the app-wide background in, read once by the store.** Tabs built without an explicit gate hold `.live`, so the Tab's own gate isn't the store's. `refreshAppWideBackground` already takes it as a parameter for this reason.

## Steps to reproduce

Not run in the app yet. In **Batty Beta**:

1. Open a Tab and confirm Cmd-Q and Cmd-, work with the terminal focused.
2. In Settings → Appearance, change the font size.
3. Return to that Tab, click into the terminal, and press Cmd-, and then Cmd-Q.
4. Press Cmd-=.
5. Copy multi-line text and press Cmd-V.
6. Open a new Tab and repeat steps 3 to 5 there.

## Expected behavior

A font or cursor change affects only the font and cursor. The Tab keeps every other line of its configuration, and Cmd chords behave as they did before the change.

## Actual behavior

Measured: the bindings return on the live surface (table below). Expected from reading the code, not yet observed in the app:

- Step 3: Cmd-, and Cmd-Q do nothing, because libghostty consumes them and the package has no handler for the resulting actions.
- Step 4: the font size changes on that one surface. Batty has no such shortcut.
- Step 5: the paste goes through libghostty rather than `PasteDispatcher`, so Batty's multi-line paste confirmation (#0035) is skipped.
- Step 6: a new Tab behaves correctly, because `TabRuntime`'s own builder configured it.

## Root of the problem

Batty builds the override set in two places, and `setTerminalConfiguration` replaces the whole set. `GhosttyConfigRenderer.render` works from the new `TerminalConfiguration` plus the base and Theme, then `applyPreparedConfigToRuntime` pushes the result to the app and to every live surface (`ghostty_surface_update_config`).

- `TabRuntime.applyShellAndAppearancePreferences` (`BattyKit/Sources/BattyKit/Runtime/TabRuntime.swift:235-366`) builds per Tab.
- `AppStateStore.applyAppearanceToAllSurfaces` (`BattyKit/Sources/BattyKit/Settings/SettingsPreferences.swift:207-262`) builds **one** configuration and pushes it to every Tab of every terminal Pane in every window.

The only caller is `applyAppearance()` in `SettingsView.swift:181`, fired by `onChange` of `fontSize`, `cursorStyle` and `cursorBlink` (`:135`, `:145`, `:148`). Theme changes are **not** affected: they go through `setTheme`, which keeps the existing `terminalConfiguration`.

### What the two builders emit

| Line | `TabRuntime` | `applyAppearanceToAllSurfaces` |
|---|---|---|
| `font-size`, `cursor-style`, `cursor-style-blink` | yes | yes |
| `shell-integration-features = ssh-env` | yes | yes |
| `env PATH=…` | yes | yes |
| Six `keybind` lines (`super+left`, `super+right`, `super+backspace`, `alt+left`, `alt+right`, `alt+backspace`) | yes | yes |
| `keybind = clear` | yes | **dropped** |
| `keybind = cmd+c=copy_to_clipboard` | yes | **dropped** (Ghostty's default binds Cmd-C anyway, see table) |
| `copy-on-select = false` | yes | **dropped** |
| `command` (`-c` override, or the shell preference) | when set | **dropped** |
| `wait-after-command = true`, `abnormal-command-exit-runtime = 0` | `-c` Panes only | **dropped** |
| `env BATTY_TAB_ID`, `BATTY_PANE_ID`, `BATTY_SESSION_ID` | yes | **dropped** |

### How a Tab recovers

Only by `TabRuntime` rebuilding its configuration. `attachContext` does that when a Tab moves to a different Pane or Session. It is a no-op when the ids are unchanged, so an ordinary Tab stays degraded until it closes.

It loaded config files mirroring the two builders' `keybind`, `copy-on-select` and `shell-integration-features` lines, applied the appearance config with `ghostty_app_update_config` plus `ghostty_surface_update_config`, and called `ghostty_surface_key_is_binding`. Switching back to the Tab config restored the first column exactly.

| Chord | Tab builder | After the appearance builder | Batty's owner, and the expected result (inferred) |
|---|---|---|---|
| Cmd-C | binding | binding | libghostty both times |
| Cmd-Q | none | **binding** | Standard Quit, reserved in `ShortcutsStore.reservedShortcuts`. The package has no `GHOSTTY_ACTION_QUIT` handler, so it does nothing |
| Cmd-, | none | **binding** | Settings, reserved likewise. No `GHOSTTY_ACTION_OPEN_CONFIG` handler, so it does nothing |
| Cmd-V | none | **binding** (performable) | `PasteDispatcher` menu item, `BattyCommands.swift:282-284`. libghostty pastes instead |
| Cmd-A | none | **binding** | Select All menu item. libghostty selects instead |
| Cmd-=, Cmd--, Cmd-0 | none | **binding** | No owner. Per-surface font size change |
| Cmd-K, Cmd-Z, Cmd-F | none | **binding** (performable) | No menu shortcut found. Performed by libghostty when possible |
| Cmd-Return, Cmd-Up, Cmd-[ | none | **binding** | No owner found. Ghostty's fullscreen, jump-to-prompt and goto-split |
| Cmd-T, Cmd-1 | none | **binding** | `BattyShortcuts`' monitor consumes these first, so no change |
| Ctrl-Tab | none | **binding** | No owner; #0462 covers it |

Why a binding beats the menu: `AppTerminalView.performKeyEquivalent` (`libghostty-spm`, `AppTerminalView+Input.swift:27-35`) sends any chord where `ghostty_surface_key_is_binding` is true to `keyDown` and returns `true`, and AppKit asks the view hierarchy before the main menu. Batty does not override it.

Chords in `ShortcutAction` (Cmd-T, W, N, D and so on) and Cmd-1..9 stay safe because the local `NSEvent` monitor in `BattyApp.swift:84` runs first. If the user rebinds one of those actions, the freed chord falls through to Ghostty's default on a degraded Tab.

## Clipboard: measured, no regression

The same harness drag-selected text on the same surface, with `supports_selection_clipboard = true` as the package sets it (`TerminalController+Config.swift:110`):

| Config on the surface | `copy-on-select` | Standard writes | Selection writes |
|---|---|---|---|
| Tab builder | `false` | 0 | 0 |
| After the appearance builder | `true` (Ghostty's default) | **0** | 1 |

So the drop does re-enable `copy-on-select`, but libghostty writes to the selection clipboard only. The package's `writeClipboard` then discards anything that isn't `GHOSTTY_CLIPBOARD_STANDARD` (`TerminalController+Callbacks.swift:87-92`, added around the 2026-09 clipboard port). The system pasteboard is untouched.

The line should still be restored, since it is what Batty declares and a future pin could change that package behavior. But nothing user-visible depends on it today.

## Not measured

- **Everything in the app itself.** The chord effects above are inferred from the package source and the measured bindings. Nobody has pressed these keys in a degraded Tab. The steps above are the check.
- **Tabs whose surface has not spawned.** Surfaces spawn on the first `TerminalPlaceholderView` render, and `command` and `env` are read at spawn. By reading, such a Tab comes up after an appearance change without its `-c` command, shell preference, `wait-after-command` and `BATTY_*` variables, so `batty` commands inside it lose their context. Not run. The comments at `SettingsPreferences.swift:222-226` and `:231-238` already treat this window as real for `ssh-env` and `PATH`.
- **Live `-c` Panes.** A spawned Pane loses `wait-after-command` and `abnormal-command-exit-runtime` from its config. Whether libghostty reads either from the updated config at exit, rather than at spawn, is unverified.
