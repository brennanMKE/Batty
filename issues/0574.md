## Description

Umbrella for hosted background image sets. Batty's website publishes PNG background images, grouped into sets and listed in one JSON file, the **catalog**. Batty shows the sets with thumbnails in the Background Images window and downloads a full-size image only when the user asks for it. In Settings, users can add their own catalog URLs, and Batty checks every catalog regularly. Targets **1.4.0**.

User request (2026-11-11, verbatim):

> "before we release 1.4.0 I want to publish a set of background images which could be hosted on the Batty website and easily downloaded into Batty. These could be .png files and I want to manage them in sets, so create a .json file which has a list of all .png files which can be organized into sets. I want the following sets. 1. Future cities 2. Cool vehicles (motorcycles, trucks, race cars) 3. Beautiful landscapes. And in Settings we'd allow users to add their own URL to a .json file for background image sets. The URLs for json files in Settings should be checked regularly. Each should support a thumbnail and full size."

Already on `main` (37704a2b): the draft catalog `website/backgrounds/catalog.json` (3 sets, 15 images, no PNGs yet) and `docs/background-image-prompts.md`, the generation prompts. The user is having Codex generate the 15 images.

## Decisions

1. **No feature flag, by default.** The user wants this in 1.4.0, so #0576 and #0577 land on `main` unflagged. **If either one can't be reviewed and landed before 1.4.0 is cut**, gate all of it behind a new `FeatureFlags.hostedBackgrounds` in `BattyKit/Sources/BattyXPCCore/FeatureFlags.swift`, following `docs/feature-flags.md`. With the flag off, Batty shows no Browse view and no Settings list, and makes no catalog requests. Don't ship half of it: browsing without user URLs is fine, but user URLs without browsing are not.
2. **A download goes through the existing library, not a new store.** A downloaded full-size image is imported with `BackgroundImageLibrary.add(from:)` (`BattyKit/Sources/BattyKit/Settings/BackgroundImageLibrary.swift`) into `BackgroundImages/` beside `projects.json`. That route runs `TerminalBackgroundImageImporter.importImage`, which re-encodes it into a Batty-owned PNG, downsampled to `maxPixelSize` (4096). From then on it is an ordinary library entry: it can be picked for a Pane, Session, Project or the app-wide default, and only the user's Remove deletes it. The re-encode is required. The importer's doc comment records that libghostty fails or aborts on input that ImageIO accepts (#0374), so hosted bytes never go to libghostty directly.
3. **A library digest is not the hosted file's hash.** The importer names each folder for the SHA-256 of its *re-encoded* PNG, so the catalog's `sha256` (of the hosted bytes) can't be used to find a downloaded image. #0576 keeps a small record that maps (catalog URL, image `id`) to the library digest it produced, and an image counts as downloaded only while that digest folder still exists in the library.
4. **Thumbnails never enter the library.** They are a cache (`~/Library/Caches/<bundle id>/…`), are decoded only for display, and can be deleted at any time.
5. **A full-size image is never downloaded automatically**, not by a refresh, not by opening the window, and not ahead of time. Each full-size download starts from a click.
6. **The built-in catalog** is `https://batty.sstools.co/backgrounds/catalog.json`, the same URL in Beta and Prod. It is always listed first, and it can't be removed (see open question 2).
7. **Vocabulary.** Add to `Concepts.md` under `## Background Images`: **Background Catalog** (a JSON file at an HTTPS URL that lists Background Sets), **Background Set** (a titled group of images in a catalog) and **built-in catalog**. Use these terms in the UI, Help (`BattyKit/Sources/BattyKit/Help/11-backgrounds.md`) and code. #0576 adds them.
8. **Formats, image storage and privacy** (2026-11-11, made for the user while planning #0575). (a) `full` and `thumbnail` may each be PNG or JPEG, and the file's real type must match its extension. (b) Image binaries are not committed: `.gitignore` excludes `website/backgrounds/**/*.png`, `*.jpg` and `*.jpeg`; `catalog.json` stays in git, and the images live only in the local `website/backgrounds/` and on the server. (c) Batty fetches no catalog until the user first opens the hosted-sets browser (#0576), and a Settings toggle stops automatic checks (#0577); thumbnails download while the user browses, and a full-size image downloads only the first time the user selects it as a terminal background (user direction 2026-11-11: the remote images stay in the sets that define them, and only the thumbnail downloads until the image is selected); the privacy page says so.

## Catalog format, `schemaVersion` 1

One UTF-8 JSON object. The draft on `main` is a valid example except that it lacks the recommended `sha256` and `bytes`, which #0575 fills in.

### Top level

| Field | Type | Required | Meaning |
|---|---|---|---|
| `schemaVersion` | integer | yes | `1`. See "Versions and unknown fields". |
| `name` | string | yes | Shown as the catalog's title in Settings and the Browse view. 1 to 100 characters after trimming. |
| `updated` | string | no | `YYYY-MM-DD`. Informational only. Refresh uses HTTP validators, never this field. |
| `homepage` | string | no | An absolute `https` URL, shown as a link in Settings. |
| `sets` | array | yes | 1 to 50 Background Sets, shown in this order. |

### Set

| Field | Type | Required | Meaning |
|---|---|---|---|
| `id` | string | yes | `^[a-z0-9][a-z0-9-]{0,63}$`, unique within the catalog. |
| `title` | string | yes | 1 to 100 characters. |
| `description` | string | no | One line, up to 300 characters. |
| `images` | array | yes | 1 to 100 images, shown in this order. |

### Image

| Field | Type | Required | Meaning |
|---|---|---|---|
| `id` | string | yes | Same pattern as a set id, unique across the **whole catalog**, not just its set. It is the stable key for "downloaded", so it must never be reused for a different picture. Ship a changed picture under a new id. |
| `title` | string | yes | 1 to 100 characters. It becomes the library entry's name, through `TerminalBackgroundImageImporter.sanitizedImageName`. |
| `credit` | string | no | Attribution shown under the thumbnail, up to 200 characters. |
| `full` | file | yes | The full-size image. |
| `thumbnail` | file | yes | The thumbnail. |

### File (`full` and `thumbnail`)

| Field | Type | Required | Meaning |
|---|---|---|---|
| `url` | string | yes | Resolved against the catalog's own URL (RFC 3986, as `URL(string:relativeTo:)` does), so `future-cities/01-skyline-fog.png` in `https://batty.sstools.co/backgrounds/catalog.json` is `https://batty.sstools.co/backgrounds/future-cities/01-skyline-fog.png`. The resolved URL must be `https`. Any other scheme (`http`, `file`, `data`) is rejected. Another host is allowed. |
| `width`, `height` | integer | yes | Pixel size. They must match the file's header. A mismatch fails the download. They also size the grid cell before the thumbnail arrives. |
| `sha256` | string | **recommended** | 64 lowercase hex characters: SHA-256 of the file's bytes as served. When present, a mismatch fails the download and nothing is kept. When absent, Batty relies on HTTPS alone. The built-in catalog always has it, and #0575's check script enforces it. |
| `bytes` | integer | **recommended** | The file's size. Lets Batty show "12.4 MB" before downloading, and refuse a file over the limit before fetching it. A response longer than `bytes` is cut off and fails. |

The format is PNG or JPEG (Decision 8). Batty checks the decoded type (`public.png` or `public.jpeg` from ImageIO), not the `Content-Type`, and the type must match the extension (`.png`, or `.jpg`/`.jpeg`). Full size for the built-in sets is 3840 × 2400 and thumbnails are 480 × 300 (`docs/background-image-prompts.md`). Other catalogs may use other sizes within #0577's limits.

### Versions and unknown fields

- **Unknown fields are ignored** at every level, so new optional fields can be added without changing `schemaVersion`. Batty never writes a catalog, so it never needs to keep them.
- **`schemaVersion` changes only for a breaking change**, such as a renamed or retyped required field or changed URL resolution.
- **A higher `schemaVersion` than Batty knows is not parsed.** The catalog shows "This catalog needs a newer version of Batty". Batty keeps the last copy it parsed and shows it. Images already downloaded are unaffected.
- **A missing or non-integer `schemaVersion`, or any required field missing or of the wrong type, rejects the whole catalog**, with an error naming the first bad path, such as `sets[1].images[3].full.width`. Batty does not show part of a catalog. Duplicate ids are an error too.

## Out of scope

- Formats other than PNG and JPEG, and animated images.
- Uploading or publishing from inside Batty, and editing a catalog.
- Syncing catalog URLs or download state between Macs. Settings stay per Mac. A downloaded image picked for a Shared Project travels the way any library image does (#0551).
- The CLI. No `batty` verb is planned for catalogs.

## Open questions

1. **PNG file size.** *Answered by Decision 8 (a) and (b).* A 3840 × 2400 PNG of a painterly image is likely 10 to 20 MB, so 15 images are 150 to 300 MB on the site and each download is large. The importer then re-encodes to PNG anyway. The user asked for PNG. Should the site serve JPEG or HEIC full-size files instead, or PNG at a lower size? #0575 records the real sizes once the images exist.
2. **Can the built-in catalog be turned off?** *Answered by Decision 8 (c).* `website/privacy.html` says Batty makes "exactly one kind of outbound network request", the Sparkle appcast, and that it can be turned off. Proposed: Batty fetches nothing at launch until the user first opens the Browse view or adds a URL, and a Settings toggle "Check background catalogs automatically" (default on) stops the regular refresh. The privacy page is updated either way (#0575). The user should confirm.
3. **Should a refresh that finds new images say so?** For example, a "New" badge on a set. Proposed: no, not in 1.4.0.

## Acceptance criteria (user-verifiable, across the children)

1. The Background Images window shows the three sets from batty.sstools.co, each with five thumbnails, without downloading any full-size file.
2. Downloading an image adds it to the library, marks it Downloaded in the set, and lets it be chosen in Settings → Appearance → Background.
3. In Settings, a catalog URL can be added and removed. Its sets then appear in the Browse view, and a bad URL shows its error beside it.
4. With the network off, downloaded images still work, cached thumbnails still show, and nothing hangs.
5. `website/privacy.html` describes the new requests before 1.4.0 ships.
