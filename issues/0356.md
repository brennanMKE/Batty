## Description

`ProcessStatusPaneContent.sample(pid:)` handles `.failure(.unexpected(let code))` by logging and returning — it touches neither `runState` nor `snapshot`. The pane keeps rendering the last good snapshot under the green "Running" chip while every subsequent tick fails the same way: the numbers stop moving and nothing tells the user they are stale. Compounding it, `Snapshot.capturedAt` is recorded on every successful sample but never rendered anywhere in `ProcessStatusPaneView`, so staleness is invisible even to a user who knows to look.

The other three outcomes are handled properly (`.processNotFound` → `.exited` + sampling stops; `.permissionDenied` → its own state; success → fresh snapshot); only the unexpected-errno path leaves the UI lying.

## Expected behavior

A persistent unexpected sampling failure surfaces in the UI — either a distinct error state in `RunState` or an explicit staleness indicator driven by `capturedAt` (which exists precisely for this). At minimum the chip must stop claiming "Running" when the content has no evidence the process is still being observed.

## Actual behavior

The pane freezes on the last good snapshot with the green "Running" chip; `capturedAt` is captured but never shown; only Console (a single `logger.error` per tick) knows anything is wrong.

## Resolution notes

> 🟢 Resolved 2026-09-23 — an unexpected-errno sample failure now moves the Process Status pane to a red "Unavailable" state with a "Sampling unavailable — last seen <time>" banner instead of leaving a green Running chip over frozen data; the next successful sample recovers it.

## Root cause

`ProcessStatusPaneContent.sample(pid:)`'s `.failure(.unexpected)` branch only logged and returned, leaving `runState` (usually `.running`) and the old `snapshot` untouched every tick.

## Fix

- New `RunState.unavailable`, set on the first `.unexpected` failure (the same immediate flip `.processNotFound` and `.permissionDenied` use). The sampling task keeps running, so a later success returns to `.running`. The last snapshot is kept (as `.exited` does) and `cpuTracker` is reset so recovery doesn't delta across the gap.
- Logging: `.error` on entering `.unavailable` or when the errno changes, `.debug` on repeats, `.info` on recovery.
- `ProcessStatusPaneView`: red "Unavailable" chip and banner above the dimmed last-known metrics.
- Test seam: `coreMetricsProvider` init parameter (defaults to `ProcessInspector.coreMetrics`), since no live process reliably produces `.unexpected`.

- `.unavailable` shares `.exited`'s disclosure rendering, so it inherits #0357's zero-masking behavior.

- No state chip or banner in this view has an accessibility identifier yet; #0413's UI suite will need them.
