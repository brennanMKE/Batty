# 0385 — The Sidebar has no agent-activity status pill, so "busy / waiting / done" is only visible inside a Pane or as a Bell notification

## Description

**Scheduled 2026-08-27 — in scope for the current CLI agentic-control push.** This issue was filed the same day as a design record, deliberately unscheduled, pending the user's call on whether Tier 2 activity display was in scope. **The user has decided it is.** It is sequenced alongside the CLI control verbs — [#0381](0381.md) (the `focus` verbs) and [#0382](0382.md) (`session close`, `pane hide`/`show`) — and is now a child of the [#0257](0257.md) CLI umbrella. One thing has to be settled before implementation starts: **the grammar** (next section). It remains the one item in the push that adds a genuinely new UI surface rather than exposing behavior the app already has, so it also carries visual sign-off cost — see Notes.

The gap itself: when an agent is working on a developer's behalf, the developer has no ambient way to see *which Session is busy*. `batty notify` (#0284) posts a discrete event into the Bell Feed — good for "I finished", useless for "I have been compiling for the last four minutes". Everything else the agent can show lives *inside* a Pane, which is invisible unless that Session is selected. The Sidebar already lists every Session and is already the place the developer's eye goes; a small state pill on the Session's row is the natural home for continuous agent presence.

This is `docs/batty-cli-design.md` §D's Tier 2 (the cmux `set-status`/`clear-status` analog): "a live status pill on the Session's Sidebar row … lets an agent show **busy / waiting / done** without a presence subsystem." The doc's own design note argues it gives "80% of 'agent presence' at 5% of the cost", against the heavier alternative (§D-adv's full agent-state objects).

## The grammar has to be decided first

The design doc sketched this as `batty status <key> <text>` — **and that name is taken.** `batty status` ships today as the live-state query (pid, uptime, window/Session/Tab counts, bundle path, version), and the doc records the conflict itself: "The bare name now conflicts with the shipped `batty status` live-state query, so this proposal needs a different grammar before implementation."

Proposed, and now the one open decision blocking implementation — the scope question was answered on 2026-08-27, this one was not:

```
batty session activity <text> [--state busy|waiting|done]
batty session activity --clear
```

It reads as a Session-scoped property (which is what a Sidebar-row pill is), it lives under an existing noun, and it leaves `batty status` alone. If the design's per-key pills (`build`, `test`, …) are wanted, `--key` can be added later without changing this shape.

## Sketch

- One XPC mutation verb setting/clearing a small value on the target Session, resolved through the usual chain (`--session` → `BATTY_SESSION_ID` → focused Session).
- A pill on the Session's Sidebar row rendering the text and a state affordance for busy / waiting / done.
- **Setting activity must not steal focus or change the selected Session** — #0257 Foundation §2's standing rule; only the focus verbs ([#0381](0381.md)) are exempt. The entire point of an ambient pill is that it informs without interrupting.
- Decide what clears it and when: process exit does not, since the CLI is a separate short-lived process from the agent. Consider whether a stale pill should age out, or persist until explicitly cleared. Left open deliberately.
- `progress` and `log` from the same doc section are marked optional there and are **not** in scope here.

## Notes

- The Sidebar row already carries per-Session content (name, Pane/Tab counts, the eye toggle); adding a pill has real layout consequences at narrow Sidebar widths. Budget for visual sign-off — this is UI work that will land `resolved`, not `closed`.
- Live agent presence is also what [#0145](0145.md)'s `watch` verb addresses from the other direction (Batty tells the agent what changed, rather than the agent telling the human what it is doing). They are complements, not substitutes, and #0145 is already `in-progress` — worth comparing before committing to a second presence surface.
- The design doc's §D-adv alternative (full agent-state objects) stays out of scope regardless of the Tier 2 decision.
