## Description

The user wants the Projects commands in their own top-level **Projects** menu, and the **Background Images…** item gone from the File menu. User request, verbatim:

> "Change the File menu. Make a top level Projects item and put the Save to Project and Edit Projects there. But just change Edit Projects to Projects since it brings up the window. Remove the Background Images item. It does not do anything when that window is opened. It is a selector UI."

Today the File menu is built in `BattyKit/Sources/BattyKit/Commands/BattyCommands.swift`, in `CommandGroup(replacing: .newItem)` (line 147). In order, it has: New Window, New Session, Open Quickly…, Open Project ▸ (submenu), the Save Session items (`saveSessionMenuItems`, lines 87–109), **Edit Projects…** (lines 181–186, opens `ProjectEditorWindowController.shared.show(store:)`), and **Background Images…** (lines 188–192, opens `BackgroundImagesWindowController.shared.show(store:)`).

"Save to Project" in the request means the Save Session items. Their titles depend on the selected Session:
- From a Session opened from a Project: **Update "Name"…** and **Save Session as New Project…**.
- Otherwise: **Save Session as Project…**.

All of them are disabled when `SaveSessionAsProjectMenuModel.isEnabled` is false. None of the moved items has a keyboard shortcut, and none is behind a feature flag. The Projects flag was removed in #0504 (resolved). `FeatureFlags` (`BattyKit/Sources/BattyXPCCore/FeatureFlags.swift`) now carries only `sharedProjectImages`. The Project Editor window is already titled "Projects" (`ProjectEditorWindowController.swift:79`), so the new item name matches the window.

## Root cause

Feature work. The File menu held Save Session…, Edit Projects… and Background Images…. Background Images had a standalone manage window (File, Command Palette, Settings' Manage Images…) and a picker sheet (Choose…); only the window offered Remove….

## Fix

Follows the Plan, with the orchestrator's override on #0624's diagnostics.

- **Projects menu.** `CommandMenu("Projects")`, inside a `Group` with the File `CommandGroup` (the body was at `CommandsBuilder`'s 10-item limit). It holds the Save Session items unchanged, a divider, and **Projects…** (was Edit Projects…). Open Project ▸ stays in File.
- **Pane ▸ Background Images…** posts `.battyChoosePaneBackgroundImage` with the window and focused terminal Pane ids; `SessionDetailView` presents `PaneBackgroundImagePickerSheet`. A pick goes through `PaneBackgroundImagePicker.apply`: `adoptImage`, then the gear sheet's `BackgroundOverrideEditor` (`selectCustom`, `pickingImage`). Disabled with no focused terminal Pane, or with Settings/Help/the Project Editor key.
- **Picker only.** `BackgroundImagesView` lost `Mode`: it always shows the header and Cancel, and always offers Remove… (context menu, button, Delete). `BackgroundImagesWindowController`, the palette entry, Settings' Manage Images… and `HostedBackgroundsModel.windowBecameKey` are gone. `BackgroundSetsView.onPick` is non-optional.
- **Override: #0624's diagnostics kept.** `BackgroundImagesScrollMonitor`, its ring and every `record` call stay. A new `BackgroundImagesScrollMonitorAttachment` (a hit-test-transparent `NSView` in the picker's background) starts a monitor on the picker's window from `viewDidMoveToWindow` and stops it when the picker leaves. The monitor also records "window became key", "picker opened" and "Background Sets appeared". The `log show` category and subsystem are unchanged. #0624's `contents` split and cell-only dependencies are untouched.
- **Delete key.** The VM showed Delete reaching no `onKeyPress` in the picker sheet, so the grid also has `.onDeleteCommand`.
- **UI tests.** Ported per the Plan. Two #0624 guards kept: `testCatalogCheckAtTheBottomKeepsTheGridStill` (unchanged, Refresh) and `testClickThatMakesTheWindowKeyWithACheckDueKeepsTheGridStill`, ported as `testClickWithACheckDueKeepsTheGridStill`. The picker has no key event that checks catalogs, so the due check it holds in flight is the one Background Sets appearing starts (switch to My Images and back, interval 0); it scrolls to the bottom with the check held, clicks Distant Galaxy (download held) and measures through the check finishing. `testClickThatMakesTheWindowKeyKeepsTheGridStill`, `testClickingACellAfterScrollingKeepsTheGridStill` and `testClickingACellCutOffAtTheBottomKeepsTheGridStill` are deleted (a click now picks and closes). In `testClickingAtTheBottomWithDownloadedImagesInView` the downloaded neighbours stay in view and the clicks go to a held Distant Galaxy (start, then cancel), because Background Sets has no arrow keys.

### Decisions (orchestrator and user; not reopened here)

1. **Projects menu.** A top-level `CommandMenu("Projects")`, placed first among the custom menus, so the bar reads File, Edit, View, **Projects**, Session, Theme, Pane, Tab, Window, Help. 4. **No palette entry for it.** The palette's Pane entries are all shortcut-backed actions (`dispatch(_:)`), and this item has no shortcut, so the palette doesn't mirror it. The palette's `extra:backgroundImages` entry is removed.

### Gotchas

- **Removing images.** Image management now lives only in the picker. There is no way to browse or remove images without opening a background control's picker. Remove is reached by right-click, or by selecting with the arrow keys, because a click picks.
- **#0624's scroll-jump logging goes away.** `BackgroundImagesScrollMonitor` and its event ring watched only the standalone window, where #0624's jumps were reported. If the user still wants that log in the picker sheet, it's a follow-up: attach the monitor to the sheet's window.
- **Picker launches no longer check the catalogs on bring-to-front.** Catalog checks now run on launch and every 24 h (`BackgroundCatalogScheduler`), when Background Sets appears (throttled to 5 min), and on Refresh / Check Now. The website text is updated to match.
- **`CommandsBuilder` limit.** It takes at most 10 items, and `BattyCommands.body` was already at 10. The `Group` wrapper is required, not cosmetic. A future menu needs another `Group`.
- **Pane ▸ Background Images… while a sheet is already up** on that window (for example, the Command Palette): SwiftUI shows one sheet per view at a time. If the VM run shows a conflict, record it here. Don't hop the write into a `Task` (`docs/swiftui-observation-rules.md`).
