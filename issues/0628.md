## Description

The two hosting tests that #0624 added in `BattyKit/Tests/BattyKitTests/BackgroundSetsScrollStabilityTests.swift` guard nothing. They pass against the pre-fix code (7d9292e1) and against the fix (ed0562c5). They also settle layout by always running a fixed 20 main-queue turns, which AGENTS.md "Asynchronous tests (binding)" forbids. Each test must either fail against 7d9292e1 and wait on a real completion signal, or be deleted.

The tests:

- `windowBecomingKeyAtTheBottomKeepsTheVisibleRowsStill`
- `reRenderAtTheBottomKeepsTheVisibleRowsStill`

The #0624 reviewer found this, and `issues/0624.md` records it under Gotchas and Plan (round 3): "passes before and after the fix, because the host shows no movement" / "settles layout with a fixed 20-turn main-queue pump (no wall-clock wait) and passes both before and after the fix, so it is not a regression guard". Leaving them in costs suite time and gives false confidence that the scroll jump has unit-level coverage.

## The wait

`pump(_:turns:)` (line 76) runs `layoutSubtreeIfNeeded()`, then hops `DispatchQueue.main.async` 20 times with no predicate. It always runs all 20 turns and returns without checking whether anything settled:

```swift
private func pump(_ view: NSView, turns: Int = 20) async {
    view.layoutSubtreeIfNeeded()
    for _ in 0..<turns {
        await withCheckedContinuation { (continuation: CheckedContinuation<Void, Never>) in
            DispatchQueue.main.async { continuation.resume() }
        }
        view.layoutSubtreeIfNeeded()
    }
}
```

It is called after every scroll step in `scrollToBottom` and after each state change in both tests. This is not the decided `awaitTerminalStatePublish` exception in AGENTS.md. That helper rechecks a predicate after every turn, returns as soon as it holds, and uses `maxTurns` only as a hang guard. Here the turn count *is* the mechanism, and nothing is rechecked.

The tests also compare with a `< 1` pt tolerance. The movement #0624 measured in the VM was exactly 1 pt, so even if the host reproduced the shift, these assertions would not catch it.

## Expected behavior

For each of the two tests, one of:

1. **Keep it as a real guard.** It fails when run against the pre-fix sources at 7d9292e1 and passes at `main`. It awaits a real completion signal per AGENTS.md and `docs/async-test-seams.md` (for example a predicate-checked, turn-bounded wait in the `awaitTerminalStatePublish` style, or an event the production code emits). Its tolerance is tight enough to see a 1 pt shift. Record the pre-fix failure (command and output) in the issue.
2. **Delete it,** along with any helpers only it uses. If both go, delete the file.

Don't keep a test that passes at 7d9292e1.
