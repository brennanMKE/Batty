## Description

Read Ghostty-format theme files (`.ghostty`) so Batty can consume the existing 200+ Ghostty themes without re-creation (Concepts → Theme). Discovery searches the app bundle and `~/.config/ghostty/themes/`.

**Acceptance criteria:**
- A `Theme` value type captures: name, foreground, background, cursor, selection foreground/background, and the 16 ANSI palette colors.
- A parser reads a `.ghostty` theme file (see Ghostty's repo for the format — INI-ish key/value with `palette = N=#hex` lines).
- Discovery searches in this order, deduplicating by name:
  1. `Batty.app/Contents/Resources/Themes/` — a small set of defaults shipped in the bundle.
  2. `~/.config/ghostty/themes/` — user-installed Ghostty themes if present.
- A unit test parses a fixture `.ghostty` file and verifies all colors are extracted correctly.
- Bundle a few sensible defaults (e.g. light, dark, solarized-dark, dracula) inside `Resources/Themes/` so first-launch users have choices.

## Notes

- The `.ghostty` format is documented in Ghostty's source; check there for edge cases (comments, quoted values).
- Application of the selected theme to live surfaces is #0033 — this issue is parsing + discovery only.

## Root cause

Feature gap, not a bug: M8 (Themes) needs a parser for Ghostty `.ghostty` theme files plus a discovery mechanism that searches the app bundle and the user's existing Ghostty themes folder. Without these, the View → Theme menu (#0033) has nothing to populate.

## Fix

Added `Batty/Theme.swift` with three layers:

- **`ThemeColor`** — sRGB triple, Double components 0..1. `init?(hex:)` accepts `#rrggbb`, `0xrrggbb`, and bare `rrggbb`. Returns nil on wrong length or non-hex bytes. Codable, Sendable, Hashable.
- **`Theme`** — `name`, `foreground`, `background`, optional `cursor`/`selectionForeground`/`selectionBackground`, and a 16-entry `palette` array. Identifiable on `name`.
- **`ThemeParser.parse(_:name:)`** — INI-ish line parser. Strips blank lines and `#` comments; recognizes the standard Ghostty config keys (`foreground`, `background`, `cursor-color`, `selection-foreground`, `selection-background`, plus `palette = N=#hex`). Throws `ThemeParseError` on missing foreground/background, missing palette entry (0..15), or invalid hex.
- **`ThemeStore.discoverAll(...)`** — reads `.ghostty` files from the app bundle's `Themes/` directory and from `~/.config/ghostty/themes/`, parses each, deduplicates by name, then prepends `builtInThemes` for any name not already discovered. Bundle and home directory are injectable for testing.
- **`ThemeStore.builtInThemes`** — four hardcoded themes (Batty Dark, Batty Light, Solarized Dark, Dracula) shipped in code so first-launch users always have choices.

Tests in `BattyTests/ThemeTests.swift` cover:
- hex parsing across formats (`#`, `0x`, bare) and rejection of malformed input.
- Canonical Tokyo Night-style fixture round-trip through the parser.
- Parser rejection of missing background and missing palette entry.
- Comment and blank-line skipping.
- All four built-in themes have 16 palette entries.
- `discoverAll` returns built-ins when no `.ghostty` files exist on disk.

9 new tests, all passing alongside the existing 14 — total 23.

## Files changed

- `Batty/Theme.swift` — new, ThemeColor + Theme + ThemeParser + ThemeStore + builtInThemes (~280 lines).
- `BattyTests/ThemeTests.swift` — new, 9 tests covering parsing, hex, discovery fallback, built-in validity (~115 lines).

## Gotchas

- **Defaults are coded in Swift, not bundled as `.ghostty` files in `Resources/Themes/`.** The acceptance criterion suggested bundling default `.ghostty` files; doing so cleanly requires an Xcode resource build phase change which is out of scope for this issue (and would risk colliding with #0001's pbxproj edits). Hardcoding the four defaults as `Theme` constants achieves the spirit of the criterion (first-launch users have choices) while staying out of the project file. If a future issue wants to ship `.ghostty` files in the bundle, `ThemeStore.discoverAll` already searches `Bundle.main.resourceURL/Themes/` first — files added there will simply override the built-ins of the same name.
- **Palette indices >15 are silently ignored**, not an error. Ghostty's format technically allows 256-color palette entries; we only use 0..15 for now. If a future issue needs 16+ colors, extend `Theme.palette` and the parser.
- **No `selection-foreground` requirement.** Some Ghostty themes specify it, some don't. Our parser leaves it `nil` when absent; rendering falls back to the surface's standard fg color.
- **Hex parsing is case-insensitive** because `UInt8(_, radix: 16)` is. No explicit lowercase normalization needed.
- **The unit-test fixture uses Tokyo Night colors** but is named `tokyonight` for the test only — it's not actually shipped as a built-in.

## Update — 2026-05-08

`BattyKit` now also depends on `GhosttyTheme`, which ships 485 themes via `GhosttyThemeCatalog`. That mostly subsumes the 4-theme `ThemeStore.builtInThemes` constant, and `GhosttyThemeDefinition` parallels our `Theme` value type. **Two changes are queued for #0033:**

1. Replace the `ThemeStore.builtInThemes` source with `GhosttyThemeCatalog.allThemes` (mapped through an adapter to our `Theme` type, or — preferably — switch the rest of the codebase to consume `GhosttyThemeDefinition` directly and retire our `Theme`).
2. Keep `ThemeParser` for user files in `~/.config/ghostty/themes/` since the catalog is closed (compiled into the package).

This issue stays `resolved` — the parser and discovery layer it shipped are still useful for user files. The four hardcoded defaults will be removed as part of #0033's work.
