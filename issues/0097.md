# 0097 — Wire Sparkle SUFeedURL and SUPublicEDKey into Info.plist

| | |
|---|---|
| **Status** | open |
| **Module** | Build / App |
| **Platform** | macOS |
| **First seen** | 2026-05-12 |

## Description

`UpdaterController.isConfigured` checks `Bundle.main.object(forInfoDictionaryKey: "SUFeedURL")`. Until that key is set, "Check for Updates…" stays disabled in the app menu and Sparkle never polls. v1.0.0 needs both `SUFeedURL` and `SUPublicEDKey` wired so the auto-update path is alive on first release.

The Batty target builds its Info.plist via `GENERATE_INFOPLIST_FILE = YES`, which only honors the canonical `INFOPLIST_KEY_*` build settings — Xcode doesn't write arbitrary keys (`SUFeedURL`, `SUPublicEDKey`, `SUEnableAutomaticChecks`) into the generated plist. To add Sparkle's keys we need either a custom Info.plist file (set `INFOPLIST_FILE = Batty/Info.plist` and `GENERATE_INFOPLIST_FILE = NO`) or post-build plist mutation.

## Acceptance criteria

- Built `Batty.app/Contents/Info.plist` contains `SUFeedURL = https://batty.sstools.co/appcast.xml`.
- Built plist contains `SUPublicEDKey = <base64 public key>` matching the EdDSA private key in the developer's keychain.
- `SUEnableAutomaticChecks = true` so the app checks on launch + on a schedule.
- "Check for Updates…" menu item is enabled (no longer `.disabled`) on a fresh build.
- All existing INFOPLIST_KEY_* values continue to be respected (NSHumanReadableCopyright, app icon, etc.). No regression on bundle id, version strings, hardened runtime, etc.
- `swift test --package-path BattyKit` still 216/216.
- Built `Batty.app` opens via `open` and the menu item is interactive.

## Implementation guidance

Two paths:

### Path A — custom Info.plist file (recommended)

1. Create `Batty/Info.plist` with the keys Xcode currently synthesizes plus the Sparkle additions:
   ```xml
   <key>SUFeedURL</key><string>https://batty.sstools.co/appcast.xml</string>
   <key>SUPublicEDKey</key><string>PLACEHOLDER_BASE64_PUBKEY</string>
   <key>SUEnableAutomaticChecks</key><true/>
   ```
2. Set `INFOPLIST_FILE = Batty/Info.plist` and `GENERATE_INFOPLIST_FILE = NO` on the Batty target in `project.pbxproj`.
3. Move other Info.plist values out of `INFOPLIST_KEY_*` build settings into the file (NSHumanReadableCopyright, principal class, etc.).
4. Document the EdDSA pubkey-generation step in `scripts/SPARKLE.md` (already there) and add a one-liner: "after `generate_keys`, paste the printed key into `Batty/Info.plist`'s `SUPublicEDKey` value."

### Path B — Post-build plist mutator

A `scripts/inject-sparkle-plist.sh` build phase that runs `plutil` against the generated plist after the standard Info.plist phase. Keeps `GENERATE_INFOPLIST_FILE = YES` but adds the Sparkle keys.

Pick Path A unless something specific argues for B. A is more discoverable and survives Xcode-internal plist regeneration cleanly.

## Pre-flight before this lands

- Generate the EdDSA key pair via `generate_keys` (Sparkle's bin). Save the public key string.
- Decide whether to commit the public key into git (yes — it's public by definition) or only push to the production plist (no — leaves dev builds unable to verify update signatures, which is fine).

## Out of scope

- Hosting the appcast (`#0096` shipped the static site scaffolding; deployment is in `scripts/deploy-website.sh`).
- Actually generating the EdDSA key pair (one-off user task, documented in `scripts/SPARKLE.md`).
- A Settings UI to surface "Last update check" / "Check now" — Sparkle's default UI is fine for v1.

## Notes

- `UpdaterController.swift` is the consumer; no code changes needed there if the plist provides the keys.
- The placeholder value approach: ship `SUPublicEDKey = PLACEHOLDER_BASE64_PUBKEY` in the committed plist, expect the user to overwrite the placeholder during one-time setup. Or use a build-phase that injects the real key from a keychain item (more complex but avoids ever committing the placeholder). For v1 the placeholder approach is fine — the user replaces it before the first release run.
- See `scripts/SPARKLE.md` for the broader Sparkle setup checklist.
