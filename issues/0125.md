## Description

Modern shell tools emit clickable links via OSC 8 escape sequences (the modern terminal-hyperlink protocol, supported in iTerm2, WezTerm, Kitty, Ghostty, Terminal.app in recent macOS). Common emitters:

- `ls --hyperlink=auto` — filenames become clickable file:// URLs.
- `cargo build` / `rustc` errors — file:line:column references in diagnostics.
- `gcc` / `clang` with `-fdiagnostics-urls=auto` — same.
- `gh` CLI output — PR / issue URLs.
- `eza`, `git`, `pytest`, `jest`, and many others have opt-in OSC 8 modes.

In Batty today, OSC 8 sequences are rendered as plain text with no affordance for clicking. This issue covers showing those links as visually distinct, hover-highlighted, and clickable (Cmd-click to open with the system handler, matching Terminal.app / iTerm2 convention).

Targeted for **1.0.3**.

## Acceptance criteria

- Text wrapped by OSC 8 (`\e]8;;URL\e\\…text…\e]8;;\e\\`) renders with a subtle underline.
- Hovering over hyperlinked text shows a clear hover state (full underline, slight color shift, or both — match the theme).
- Cmd-click opens the URL via `NSWorkspace.shared.open(_:)`. Plain click does not open — terminals universally require a modifier to avoid stealing clicks from shell programs that interpret mouse events (vim, less, fzf).
- `file://` URLs open in the default handler for the file type (or Finder if the URL points at a directory).
- `http://` and `https://` URLs open in the default browser.
- Schemes that aren't `http`, `https`, `file`, `mailto` are still openable but worth verifying with `NSWorkspace.urlForApplication(toOpen:)` first; if no handler exists, Cmd-click is a no-op rather than a misleading "nothing happened" error.
- Standard right-click context menu over a hyperlink offers: **Open Link**, **Copy Link**.
- Click-to-jump on the bell feed (`#0027`) is unaffected — bell-feed entries route through a separate path.
- The behavior is enabled by default with no Settings toggle (matches Terminal.app's default-on behavior). Reconsider if a real use-case for disabling emerges.

## Scope detail

libghostty's terminal model already parses OSC 8 internally — the data is sitting in the surface's grid cells with a hyperlink-id attribute. Two things this issue actually has to build:

1. **Visual rendering**: confirm libghostty's renderer is drawing the underline / styling, or that the wrapper exposes a way to ask "is the cell under this point a hyperlink?" so the SwiftUI / AppKit layer can drive cursor changes and click handling.
2. **Mouse interaction**: hit-test from a mouse-move / mouse-up event to a cell, ask the surface "what hyperlink (if any) is at this cell?", and on Cmd-click invoke `NSWorkspace.shared.open(url)`.

Likely landing in `BattyKit/Sources/BattyKit/Views/TerminalHostView.swift` (or the platform NSView the surface lives inside) plus a small helper in `BattyKit/Sources/BattyKit/Util/` for URL validation / scheme allowlist.

## Out of scope

- Pattern-based linkification of plain text (turning bare `https://…` strings into clickable links even when no OSC 8 wraps them). That's a separate, more invasive feature — useful but not table-stakes, file as a follow-up if users ask.
- Hover preview / link target tooltip. iTerm2 does it; nice-to-have, skip for 1.0.3.
- Right-click menu items beyond Open Link / Copy Link (e.g. "Open in Browser" forcing a browser even for file://).
- Settings toggle for cmd-vs-plain click. Default-on, Cmd-modified, no toggle.

## Notes

- Check what libghostty's `GhosttyTerminal` wrapper already exposes. The fork at `brennanMKE/libghostty-spm` may have an API for "cell at point → hyperlink." If not, this might need a small wrapper-side addition before the Batty work begins; in that case, the work splits into "fork: add hyperlink hit-test API" + "Batty: consume it." Worth investigating before estimating.
- libghostty's renderer should already handle the visual underline if OSC 8 is parsed (Ghostty proper does this) — verify in a manual repro: run `printf '\e]8;;https://example.com\e\\example\e]8;;\e\\\n'` in a Batty pane and see whether the word "example" is rendered with any distinguishing style today.
- Cmd-modified-click is the universal convention (Terminal.app, iTerm2, VSCode integrated terminal). Plain click stays available for shell programs to consume.
- Scheme allowlist for the open path is a security consideration — a malicious shell program could emit `osascript://` or similar handler URLs. Limit to: `http`, `https`, `file`, `mailto`, `ftp`. Anything else: no-op silently (or add to allowlist after explicit user opt-in in a later release).
- File paths in URLs that exceed bundle entitlements (we're unsandboxed, so this shouldn't matter) will fall back to Finder revealing the parent directory. NSWorkspace handles this; no special code needed.

## Root cause

OSC 8 escape sequences were already parsed by libghostty and rendered with the underline glyph attribute, but Batty was attaching the bare `TerminalViewState` as the `AppTerminalView.delegate`. That state object only conforms to the title / resize / focus / close / bell / pwd / notification / command-finished / lifecycle delegate sub-protocols and not to `TerminalSurfaceOpenURLDelegate` or `TerminalSurfaceHoverLinkDelegate`, so the wrapper's hit-test plus cmd-click logic and the hover transitions had nowhere to land. Cmd-clicking a hyperlinked cell did nothing and the pointer never changed on hover.

## Fix

Introduced `TerminalDelegateProxy`, an `NSObject` subclass that adopts every delegate sub-protocol `TerminalViewState` already implements (so all existing observable state still flows through the state) plus the two OSC 8 protocols, and forwards every non-hyperlink call straight through to the wrapped state. `TabRuntime` now owns one proxy per tab and `TerminalHostStore.terminalView(for:)` installs it as the surface delegate. `terminalDidRequestOpenURL` routes through a new `HyperlinkOpener` helper that parses the URL, enforces a scheme allowlist (`http`, `https`, `file`, `mailto`, `ftp`) with a `Logger` warning on rejection, and calls `NSWorkspace.shared.open(_:)`. `terminalDidUpdateHoverLink` pushes `NSCursor.pointingHand` on hover-enter and pops it on hover-leave, guarded by a `Bool` to keep the cursor stack balanced under rapid hover transitions, and caches the URL for future right-click work.

## Files changed

- `BattyKit/Sources/BattyKit/Runtime/TerminalDelegateProxy.swift` — new file. Forwarding delegate that adopts both legacy sub-protocols and the two OSC 8 protocols; handles cursor push/pop and routes URL opens through `HyperlinkOpener`.
- `BattyKit/Sources/BattyKit/Util/HyperlinkOpener.swift` — new file. Validates the URL, applies the scheme allowlist, opens via `NSWorkspace.shared.open(_:)`, and exposes a small clipboard helper for future right-click work.
- `BattyKit/Sources/BattyKit/Runtime/TabRuntime.swift` — added `terminalDelegate: TerminalDelegateProxy` ivar, constructed alongside `TerminalViewState` in `init` so the proxy is alive for the tab's full lifetime.
- `BattyKit/Sources/BattyKit/Runtime/TerminalHostStore.swift` — `view.delegate` now points at the per-tab `TerminalDelegateProxy` instead of the bare `TerminalViewState`.

## Gotchas

- Right-click "Open Link" / "Copy Link" was deferred: the libghostty-spm wrapper's `AppTerminalView+Input.swift` forwards `rightMouseDown` directly to the surface and does not expose a delegate hook for menu construction (nor an `NSMenuDelegate`/`menu(for:)` override). Wiring our own context menu would require a wrapper-side change, which is out of scope per the task instructions. `HyperlinkOpener.copyToPasteboard(_:)` and `TerminalDelegateProxy.hoveredURL` are already in place so the menu work can land cleanly once the wrapper exposes a hook. File a follow-up issue if right-click is needed before then.
- Visual underline rendering was not verified live in this session because the build was headless (`xcodebuild build`); per the task spec, libghostty's renderer is expected to draw the underline automatically and any visual gap is most likely a renderer setting (`link-url` / `link-previews`) rather than a Batty issue. The user should run the OSC 8 `printf` repro in a real Batty session before closing — `printf '\e]8;;https://example.com\e\\example\e]8;;\e\\\n'` and a `file://` variant — and confirm: (1) "example" renders with an underline, (2) hovering shows the pointing-hand cursor, (3) Cmd-click opens the URL in the default handler, (4) plain click does not open.
- `TerminalDelegateProxy` is an `NSObject` so the `view.delegate = …` assignment to a `weak var (any TerminalSurfaceViewDelegate)?` slot resolves through Objective-C runtime semantics; the strong reference lives on `TabRuntime`. If `TabRuntime` is deallocated mid-hover the cursor push could leak by one frame — extremely unlikely in practice (the surface detaches first via `terminalDidDetachSurface`) but worth noting.
