## Description

**Umbrella, 1.5.0.** The user reworked how 1.5.0 handles dev servers and agent setup (decisions below, 2026-11-19). Batty drops the Web Preview Pane and the Server Pane, adds a small **Servers** list in the toolbar next to the Bell Feed and Reminders, lets the CLI share and manage localhost servers (with a Process Status Pane to watch them), shares them on the user's tailnet through `tailscale serve`, and replaces the in-app `NWListener` static server with the user's PhotonHTTP package. Agent setup moves from a one-time sheet into Settings → Advanced → AI Agents, next to the CLI install. No code ships on this issue; the work lands in the children below.

## Decisions (user, 2026-11-19), binding

Recorded as given:

- **A. No web view.** Remove the Web Preview Pane, `batty server preview`, its Setting and WebKit use. Agents use whatever webdriver the developer tells them about (e.g. `safaridriver`); the docs and the skill say so (#0671, #0683).
- **B. No setup popup for MCP.** Drop #0666's sheet. Settings → AI Agents gets guided setup next to the CLI tool install: the developer chooses to install the CLI and/or MCP. The already-built silent refresh after app updates (only for what the user installed) stays.
- **C. Servers move out of a custom Pane** into a new icon alongside the Bell Feed and Reminders icons: a minimal list of active servers with Copy URL actions — a localhost URL, and a tailnet URL when Tailscale is available. Remove the Server Pane view. The CLI tells Batty to share/track a localhost server (e.g. `batty server share --port N`; exact grammar decided in the child's plan), and it also opens a Process Status view (the existing `process-status` Pane kind) to watch the server process. The CLI can terminate or restart servers Batty manages.
- **D. Tailnet: detect automatically** — `tailscale` in `PATH` and `tailscale status --json` with `.BackendState == "Running"` (parse the JSON; `jq` not required). Serve a port to the tailnet with `tailscale serve --bg <port>`; the URL comes from the status JSON (`Self.DNSName`). `tailscale serve` changes the tailnet serve config, so it runs only when the user or agent asks to share on the tailnet, and Batty offers turning it off (`off` appended to the command that turned it on, per Tailscale's docs).
- **E. Static server:** replace the in-app `NWListener` static server (#0649) with the PhotonHTTP Swift package (SPM dependency in `BattyKit/Package.swift`). Batty's static server exposes a standard minimal REST API for status and stats (e.g. `GET /_batty/status` → JSON) that the Servers list reads; the CLI stops and restarts it. Binding stays `127.0.0.1`; tailnet exposure is through `tailscale serve`.
- **F. Future (not 1.5.0):** PhotonHTTP may later serve remote interactions with Batty from another Mac via SSH or Tailscale. Filed as idea only: #0695 (Target 1.6.0).
- **G.** All of A–E target 1.5.0.

### Progressive disclosure (binding)

Every child follows `AGENTS.md`, "Top design goal: progressive disclosure" (commit `94b038c1`, user directive 2026-11-19): simple on day 1, no unsolicited UI, optional features opt in through Settings, documented rather than pushed, quiet defaults. For this rework that means:

- The Servers toolbar icon appears **only** while Batty tracks at least one active server, or when the user turned it on in Settings. A fresh install never shows it. (The toolbar icon itself is the user's explicit request, decision C.)
- Tailscale sharing is opt-in **per server** and never automatic: detection only decides whether the share action is offered.
- CLI and MCP setup live only in Settings → Advanced → AI Agents, with guidance; no launch sheet, banner or prompt.
- The PhotonHTTP static server runs only when `batty server serve` (or a Settings/CLI action) asks for it; nothing listens at launch.
- Each relevant child carries an acceptance criterion that a fresh install with no use of the feature shows nothing new.

## Acceptance criteria

This umbrella can be resolved only when every child is resolved, and:

1. Nothing under `BattyKit/Sources` or `Batty/` imports WebKit; `PaneContentKind` has no `server` or `web-preview` case usable for new Panes.
2. In Batty Beta, `batty server share --port N` (grammar per #0692) makes the server appear in the toolbar Servers list with a working Copy URL, and opens a Process Status Pane on its listening process.
3. `batty server serve <dir>` runs on PhotonHTTP, bound to `127.0.0.1`, and `GET /_batty/status` returns JSON the Servers list shows.
4. With Tailscale running, sharing a server on the tailnet gives a Copy Tailnet URL that opens from another tailnet device, and turning sharing off removes exactly that serve mapping. With Tailscale absent or stopped, no tailnet row or action appears and nothing runs `tailscale serve`.
5. Settings → Advanced → AI Agents lets the developer install the CLI, the MCP server, or both; no setup sheet appears at launch; the silent refresh touches only what was installed.
6. A fresh install (empty defaults, no CLI use) shows nothing new: no Servers icon, no tailnet action, no setup prompt, no listening socket.

## Risks

- **PhotonHTTP maturity and license.** The repo (`github.com/brennanMKE/PhotonHTTP`, package name `SwiftWebServer`) has **no LICENSE file**, no tags or releases, zero stars, and its last commit is 2026-11-13 (`6c9c1686`). It declares `swift-tools-version: 6.4` (BattyKit is 6.3; the host toolchain is Swift 6.4.2) and uses package traits. Shipping it inside a notarized app needs a license the user chooses and a pinned revision (#0693).
- **A new dependency in the app.** Today BattyKit depends on libghostty-spm, SlidingTabs, Sparkle and Textual. PhotonHTTP adds a large source tree (HTTP/1-3, QUIC, TLS); only `HTTPCore`, `HTTP1`, `HTTPServer`, `NetworkTransport` and `StaticFiles` should be linked. Watch build time (#0588/#0592 budgets) and the Release `-O` archive (#0391).
- **`tailscale serve` changes shared tailnet state.** The serve config belongs to the node, not Batty: other tools and the user's own mappings live there. Batty must only add and remove the mapping it made, never `tailscale serve reset`, and only on an explicit request (#0694).
- **1.5.0 scope growth.** This adds five issues to a milestone that already has #0660's and #0680's open children. Removing the two Panes first (#0690, #0691) shrinks the surface before new code arrives.
