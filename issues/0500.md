## Description

In the picker design the user chose for #0493 (Option A), open Projects sit wherever `ProjectRecency.defaultPlacement` ranks them: `.last`, so they are the final compact cards in All Projects with an OPEN badge. The user also chose, from Option C, the **Open now** strip: "I also like the parts of option C which shows Open Now which allows the user to switch or open another copy." (2026-10-13, recorded in `issues/0493.md` `## Decision`.) This issue adds that strip on top of #0493's two tiers. It is a presentation partition inside the picker only; the ranking and every other Projects surface are untouched.

Split out of #0493 so each branch stays reviewable: #0493 lands the tiers, the cursor, the sheet size, the `New Project…` card, the relative time and the Escape change; this issue lands the strip, its chip view with two actions, the third cursor section and their tests.

Ships on `main` for 1.3.0, behind the Projects flag. With the flag off the picker never presents, so nothing here is visible.

## Current code (verified on `main` at `6ee01ad0`, 2026-10-13, before #0493 lands)

- **Ranking and open ids.** `ProjectRecency.ranked(_:openProjectIDs:placement:)` (`BattyKit/Sources/BattyKit/Model/ProjectRecency.swift:14-33`); `defaultPlacement = .last` (`:9`), so open Projects are a suffix of the ranked list, in recency order among themselves. `AppStateStore.openProjectIDs` (`Runtime/AppStateStore.swift:1273-1275`) is the set of `SessionRuntime.projectID` (`Runtime/SessionRuntime.swift:47`) across every Window; `SessionDetailView` hands it to the picker as a closure read on every render (`Views/SessionDetailView.swift:104-113`, `Views/ProjectPickerView.swift:53-56`). `ProjectPickerCard.isOpen` (`Model/ProjectPicker.swift:32`, set at `:205`) is what the OPEN badge reads (`ProjectPickerView.swift:230-238`).
- **Actions that already exist.** `ProjectPickerAction.open(UUID, AppStateStore.ProjectOpenMode)` (`ProjectPicker.swift:10-14`). `ProjectPickerModel.openAction(optionHeld:)` (`:133-136`) returns `.open(id, .focusExistingOrOpen)` for Return and `.open(id, .openNew)` for Option-Return. `AppStateStore.openProject(id:mode:)` (`AppStateStore.swift:1299-1321`) with `.focusExistingOrOpen` selects the existing Session in whichever Window has it (`window.setSelectedSession(id:)`, `activateWindow`) and records the open; with `.openNew` it always builds another Session. The hint for an open Project already reads `↩ Switch to the open <name> Session` (`ProjectPickerModel.hint(name:isOpen:)`, `:147-151`). So "switch" and "open another copy" are the two existing modes; the strip adds entry points, not actions.
- **Mouse gap.** Double-click calls `openAction(optionHeld: false)` (`ProjectPickerView.swift:131-134`); `onTapGesture` cannot read the Option modifier, so a mouse user has no way to open another copy of an open Project from the picker today. Option-Return (`:104-109`) is the only route.
- **Tests that read the badge.** `ProjectsOpenTests.testOpenBadgeAndFileMenuCheckMarkFollowTheOpenProject` (`BattyUITests/ProjectsOpenTests.swift:207-245`) presents the picker unfiltered and expects `project-picker.open-badge.Alpha Stack` to exist once the Project is open and `project-picker.open-badge.Beta Duo` not to. `testReturnFocusesTheOpenSessionAndOptionReturnOpensAnother` (`:68-96`) goes through `openThroughPicker` (`Support/ProjectsHarness.swift:268`), which filters first, so it exercises the filtered grid, not the strip. Unit: `cardsAreRankedByRecencyWithOpenProjectsLastAndStillMarkedOpen` (`BattyKit/Tests/BattyKitTests/ProjectPickerTests.swift:65`), `hintNamesWhatReturnWillDo` (`:223`), `returnOpensWithFocusAndOptionReturnOpensAnother` (`:208`).
- **After #0493** (its D1 and D5): `ProjectPickerModel` exposes `featured` and `rest`; `ProjectPickerGridCursor` is built from an ordered list of `(columns, count)` sections; tier containers are `project-picker.featured` and `project-picker.rest`. This issue builds on those names.

## Expected behavior

### 1. The strip

- With a blank query, open Projects (`isOpen`) are **removed from both tiers** and shown in an **Open now** strip (`project-picker.open-now`, a `.contain` container): heading `Open now`, then one **chip** per open Project in ranked order (`ProjectRecency.ranked` with `.last` already puts them last and in recency order; the model partitions `ranked` into `closed = ranked.filter { !isOpen }` and `openNow = ranked.filter { isOpen }`; no second sort). The featured and All Projects tiers are built from `closed` exactly as #0493 builds them from `ranked`, so the `New Project…` card rule keys on `closed.count < 3`.
- The strip sits **below the scrolling tiers and above the footer**, as Option C draws it, and does not scroll with the tiers. It is laid out as a **4-column grid** of chips (the same column count as All Projects, 10 pt gap), so five or more open Projects wrap to a second row; it is absent when no Project is open.
- A chip is 36 pt tall with a dashed border: the Project symbol in its color, the name, the OPEN badge (`project-picker.open-badge.<name>`, so `testOpenBadgeAndFileMenuCheckMarkFollowTheOpenProject` keeps passing unfiltered), a `↩ switch` caption, and a trailing **`+` button** (`project-picker.open-now.another.<name>`, help `Open another copy`). The chip itself keeps `project-picker.card.<name>`.
- `ProjectRecency.defaultPlacement` stays `.last`; the File menu, the palette, Open Quickly and `batty project list` are unchanged. `Concepts.md`'s Project entry ("every Projects list except the Project Editor's shows the most recently opened first, with open Projects last") gains a clause that the picker shows open Projects in their own Open now strip.

### 2. Actions

- **Switch:** a click on the chip selects it; a double-click, or Return while it is selected, reports `.open(id, .focusExistingOrOpen)`, which `AppStateStore.openProject` already turns into selecting the open Session. The hint reads `↩ Switch to the open <name> Session`, as today.
- **Open another copy:** Option-Return while the chip is selected reports `.open(id, .openNew)`, as today. The chip's `+` button reports the same `.open(id, .openNew)` on a plain click, closing the mouse gap. The footer's `⌥↩ Open another copy` text stays.
- No new `ProjectPickerAction` case and no new `ProjectOpenMode`; both paths already exist.

### 3. Keyboard

- The strip is the **third cursor section**, `(columns: 4, count: openNow.count)`, after featured and rest. #0493's `ProjectPickerGridCursor` rules apply unchanged: Down from the last All Projects row lands on the strip's first row at the mapped column (4 → 4 is the identity, clamped to the row's count); Up from the strip's first row returns to the last All Projects row (or the featured row when All Projects is empty, 4 → 3 mapped `0, 1, 2, 3 → 0, 1, 1, 2`); Left/Right cross into and out of the strip; End lands on the strip's last chip. With the filter active the strip is hidden and the cursor has one section, as in #0493 D3.
- Scrolling to the selection (`#0493` D5) applies only to the tiers; a strip chip is always visible.

### 4. Filtering

- A non-blank query hides the strip; open Projects appear in the single compact grid with their OPEN badge, in filter order, as #0493 D3 specifies. The existing `openThroughPicker` flow is unaffected.

### 5. Flag off

Nothing new. No new gate site; add no row to `docs/feature-flags.md`.

## Notes

- **Binding docs:** `docs/swiftui-observation-rules.md`. The partition into `closed` and `openNow` is derived in the model from the ranked cards; nothing in `body`, `onAppear` or a geometry callback writes `base`. The `+` button's action is an event-origin write like every other picker action.
- **Why a partition, not a placement.** `ProjectRecency.OpenPlacement` governs every Projects surface at once (#0492). The strip is a picker-only presentation of the same ranked list, so it must not flip `defaultPlacement` or add a fourth placement; with `.last` the open suffix is already in the order the strip wants, which is why the partition is two `filter` calls and no sort.
- **Why the `+` button.** `onTapGesture` cannot read modifiers, so without it a mouse user could only switch to an open Project from the strip, never open another copy, which is half of what the user asked the strip to do.
- Line numbers were grepped on `main` at `6ee01ad0` on 2026-10-13 and will drift when #0493 lands; the implementer re-verifies against #0493's resolution sections first.
