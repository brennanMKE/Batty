## Root cause

Test bug. The test held an `XCUIElementQuery` named `chipsBefore` and
later compared `chipsAfter.count < chipsBefore.count`.
`XCUIElementQuery.count` re-evaluates the query against current UI
state on every read — so both queries returned the current chip count
at comparison time, and the inequality was always false. The tab
close was actually working (`Cmd-W` successfully removed the tab);
the test couldn't detect it.

`LifecycleTests.testCmdTCreatesTabAndCmdWClosesIt` uses the right
pattern (snapshot `chipCount(in:)` to an Int before, then compare),
which is why that test passes.

## Fix

Resolved by code commit `870e7fb`. Snapshot `chipsQuery.count` to an
Int after the `>= 2` wait, then compare the live query against that
snapshot.

Verified locally with `scripts/run-ui-tests.sh
BattyUITests/ModalConfirmationTests/testCleanTabCloseDoesNotPrompt`
— passes.

## Files changed

## Gotchas

`XCUIElementQuery` is always live — storing one and reading `.count`
later returns the current count, not the count at storage time. Any
"compare before/after" test must snapshot the count to a concrete
value first. Worth grepping the test suite for similar mistakes.
