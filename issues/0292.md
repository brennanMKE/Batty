# 0292 — libghostty-spm cannot express per-surface command or wait_after_command, forcing an app per Tab for -c panes

| | |
|---|---|
| **Status** | open |
| **Module** | GhosttyKit |
| **Platform** | macOS |
| **First seen** | 2026-07-31 |

## Description

The C API already supports everything needed to run every Tab on one shared `ghostty_app_t`: `ghostty_surface_config_s` carries per-surface `command`, `env_vars` / `env_var_count`, `wait_after_command`, `working_directory`, and `font_size` (`ghostty.h:452-469`). But the libghostty-spm wrapper at 1.3.2 wires up only `env_vars`, `font_size`, and `working_directory` (`TerminalController+Surface.swift:22-40` @ 1.3.2) — **not `command` and not `wait_after_command`**.

The consequence for Batty: after #0287 moves ordinary Tabs onto a shared controller, `-c` panes (#0282) must stay on dedicated per-pane controllers, because their `command` override and `wait-after-command` can only be expressed at controller (app-config) level (`TabRuntime.swift:143-209`). Adding the two missing fields to `TerminalSurfaceOptions` and `createSurface` is small and additive — the C struct already carries both — and would let `-c` panes join the shared controller too.

This is an **upstream contribution**: file the ask at github.com/Lakr233/libghostty-spm. This Batty issue tracks the upstream ask and the follow-up dependency bump that adopts it.

## Relation

- Child of umbrella #0285.
- Follows #0286 (the 1.3.2 bump establishes the current-API baseline described above).
- Unblocks the last piece of #0287, but is explicitly **not a blocker** for it — #0287 ships with `-c` panes on their own controllers.

## Expected behavior

`TerminalSurfaceOptions` exposes `command` and `waitAfterCommand`, `createSurface` populates the corresponding `ghostty_surface_config_s` fields, and Batty (after a bump to the release containing the change) moves `-c` panes onto the shared controller.

## Actual behavior

Per-surface `command` / `wait_after_command` are unreachable through the wrapper; any pane needing them needs its own `ghostty_app_t`, with its own glyph-atlas set and threads.
