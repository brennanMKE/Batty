# 0223 — Extract theme model tests from BattyUITests into BattyKit unit tests

|---|---|

## Description

`BattyUITests/ThemeTests.swift` tests `AppStateStore` theme logic — applying a global theme doesn't crash, a per-session override doesn't bleed to other sessions, a new session inherits the global theme. None of these tests require the UI to be running; they are pure state-machine assertions on `AppStateStore`. They are UI tests only because no unit alternative existed.

## Fix

Add `BattyKit/Tests/BattyKitTests/AppStateStoreThemeTests.swift`. Instantiate `AppStateStore` directly, call `applyTheme(_:)` / `applyTheme(_:to:)`, and assert model state. No app launch, no accessibility identifiers.

Candidate tests to cover (mirrors `ThemeTests.swift`):
- `applyGlobalThemeDoesNotCrashOrLoseSessions`
- `perSessionThemeOverrideDoesNotAffectOtherSessions`
- `newSessionAfterGlobalThemeApplied_inheritsGlobalTheme`

Once the unit tests exist and pass, the corresponding cases in `BattyUITests/ThemeTests.swift` may be removed or kept as a shallow smoke-test.
