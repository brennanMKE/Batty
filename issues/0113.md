## Description

Tier 2 localization target. Latin American Spanish — covers Mexico, Argentina, Colombia, Chile, and the rest of Spanish-speaking Latin America (the largest combined Spanish-speaking population by far).

Depends on `#0107`. Pairs with `#0112` (European Spanish). Filed as a distinct issue because tech vocabulary diverges enough — particularly around computer terms — that a single neutral `es` reads awkwardly on one side.

## Acceptance criteria

- Every key in `Localizable.xcstrings` has a non-empty `es-419` translation, reviewed by a native LatAm Spanish speaker.
- Launching with macOS Language & Region set to Español (Latinoamérica) shows the full UI translated.
- Visual sweep for string-length expansion (similar to `es`, ~15–20%).
- `## Files changed` should list the `.xcstrings` diff.

## Notes

- Use "ustedes" / "tú" conventions — "vosotros" is rarely used outside Spain.
- Terminology: "computadora" (not "ordenador"), "carpeta" (folder), "pestaña" (tab) is common in both regions. Confirm against Terminal.app's LatAm Spanish translations.
- If a translator is unavailable for both `es` and `es-419` at the same time, ship the available one first and leave the other open; macOS falls back gracefully from `es-MX` / `es-AR` to whichever `es*` is present.
- Sparkle's single `es` covers both regions for update prompts.

## Root cause

`Localizable.xcstrings` had no `es-419` translations after the localization
foundation (`#0107`) and `es` (Spain) translations (`#0112`) landed. Users
running macOS with Language & Region set to Español (Latinoamérica) — or
Spanish-speaking locales like es-MX, es-AR, es-CO — would fall back to the
closest available `es*` (the Castilian entries from `#0112`) rather than
seeing an explicit LatAm rendering. Without an explicit `es-419`, regional
divergences (e.g. gender of "terminal") could not surface.

## Fix

Populated every key in `Batty/Localizable.xcstrings` with Latin American
Spanish (`es-419`) translations. For these short, impersonal/imperative UI
strings, most values are character-identical to the `es` (Spain) entries:
macOS UI conventions are largely shared (Salir, Cancelar, Pegar, ¿…?
punctuation). The catalog is now explicitly populated rather than relying
on fallback, so future strings can diverge cleanly. Plural variations cover
`one` (1) and `other` (0, 2+) per Spanish CLDR rules.

## Files changed

- `Batty/Localizable.xcstrings` — added `es-419` entries for all 7 keys
  (Batty, Paste %lld lines?, There %lld open terminal(s).,
  %lld unseen bell event(s), Quit Batty?, Quit, Cancel).

## Gotchas

- Translations are LLM-authored, not native-speaker reviewed; an es-MX /
  es-419 pass before release is still advisable per the issue's acceptance
  criteria.
- **LatAm vs Spain divergence in this catalog is small** because every
  string here is short and impersonal — Apple's macOS UI conventions
  (Salir, Cancelar, Pegar, the ¿…? punctuation pattern, the "¿Salir de
  Batty?" alert phrasing) read the same on both sides of the Atlantic. The
  one meaningful split is **grammatical gender for "terminal"** in the
  quit-confirmation body: `es-419` uses feminine ("Hay %lld terminal
  abierta." / "Hay %lld terminales abiertas.") which aligns with the more
  common Latin American usage (la terminal de bus, la terminal de
  computadora), while `es` keeps the masculine form Apple Spain uses.
  Both are RAE-accepted, but `la terminal` is more idiomatic in
  Mexico/Argentina/Colombia. Future strings introducing technology
  vocabulary will likely diverge more (e.g. `Tipo de letra` (Spain) vs
  `Fuente` (LatAm) for *Font*; `ordenador` vs `computadora`); none of
  those appear in the current catalog.
- Used inverted opening punctuation (`¿`, `¡`) per RAE and Apple Spanish
  conventions. Plain question/exclamation marks would read as Anglicized.
- Chose **Salir** for the Quit verb (Apple's macOS Spanish convention,
  identical across `es` and `es-419`) rather than *Cerrar* or *Terminar*.
- Spanish runs roughly 15–20% longer than English; layout sweep for
  Settings panes and alert buttons still needs visual confirmation before
  closing.
- Catalog-only change; no Swift source touched. `project.pbxproj`
  `knownRegions` does not need to enumerate `es-419` — Xcode 15+ String
  Catalogs are self-describing and read locale columns directly.
