## Expected behavior

1. `website/docs/index.md` covers, in this order:
   - Batty in one paragraph;
   - **detection:** the three `BATTY_*` variables and `batty agent context`;
   - **MCP or CLI:** use the `batty` MCP tools when the host has `batty mcp` registered, otherwise the CLI; `batty-beta` in Batty Beta; target arguments default to the caller's own Pane;
   - **setup per host:** Claude Code (`batty agent install`, or `claude mcp add`), Codex, Cursor, OpenCode, each with its snippet from `website/docs/snippets/` (#0682) inlined between generated-section markers (`<!-- generated:codex-config.toml -->` … `<!-- /generated -->`);
   - **core verbs with one example each:** `pane split --view git-status --unique` (and the other views), `tab new -c <cmd> --wait`, `server start --port N -- <cmd>`, `server share --port N`, `server serve <dir>`, `server list`, `notify`, `session remind` (server grammar as shipped by #0692; edited 2026-11-19, #0689);
   - **viewing pages:** Batty has no web view; an agent uses the webdriver the developer names (for example `safaridriver`) against the URL from `server list`, localhost or tailnet (#0689 decision A);
   - **share a page from your project (required):** the local way for an agent to publish a web page and hand the user a link. Step by step, CLI with the MCP tool equivalent beside each step:
     1. write static files (HTML/CSS/JS) into a folder in the project, for example `site/`;
     2. `batty server serve site --port 8080` (#0693; MCP: the server-serve tool) runs `photon serve <abs path>/site --host 127.0.0.1 --port 8080` in a terminal Pane, where photon prints `listening 127.0.0.1:8080`; it appears in the Servers list (#0691). PhotonHTTP is an optional, separately installed tool: the step says so, shows the install command `curl -fsSL https://photon-http.sstools.co/install.sh | bash` (macOS 15+, Swift 6.4 toolchain; installs `photon` to `/usr/local/bin`; check with `photon --help`), links `https://photon-http.sstools.co/docs/getting-started.md`, and shows what `serve` prints when `photon` is missing;
     3. `batty server list` (or `--json`) prints the localhost URL; the agent prints or copies it for the user;
     4. only if the user asks to share it off this Mac: `batty server share --port 8080 --tailnet` (grammar per #0692/#0694) runs `tailscale serve`, and the tailnet URL (`tailnetURL` in `server list --json`) opens from another computer on the user's tailnet;
     5. `batty server stop` (or unshare) when done; Batty removes only the tailnet mappings it added.
     Tailnet sharing is opt-in and never automatic; the page names no other product's hosted-page feature;
   - **close what you open:** `pane close`/`session close` for Panes and Sessions the agent created;
   - **global instructions:** the #0664 prompt, inlined from `global-instructions-prompt.txt`, in a copyable block;
   - **versions:** which Batty version each feature needs (1.5.0 for `agent context`, `tab new`, `--wait`, `mcp`, `agent install`, `server`; 1.3.0 for Projects);
   - links to the CLI reference (`docs/cli/`, #0684), the skill download (#0687), the changelog and GitHub.

## Decisions (user, 2026-11-19)

- Facts from PhotonHTTP llms.txt (2026-11-19, `https://photon-http.sstools.co/llms.txt`, summary bullets, and its `docs/getting-started.md`): the command is `photon`; install with `curl -fsSL https://photon-http.sstools.co/install.sh | bash` (builds from source; `--prefix DIR`, `--version REF` after `bash -s --`); `photon serve [DIR] [--port PORT] [--host HOST]`, defaults `127.0.0.1:8080`, prints `listening HOST:PORT`. The page uses these exact commands (details in #0693).
- PhotonHTTP is optional and installed separately by the user; Batty does not bundle it (user, 2026-11-19: "We may not need to install PhotonHTTP directly in Batty. Instead we can simply offer to use it if the user installs it separately as a CLI tool."). The Docs say so and how to install it.
- The Docs include a "Share a page from your project" workflow: an agent writes static files into a project folder, serves them with `batty server serve <dir>` (#0693), the server shows in the Servers list (#0691), and, only when the user opts in, shares it on the tailnet with `tailscale serve` (#0694) so the user can open the tailnet URL from another computer. The agent prints or copies the localhost and tailnet URLs. Neutral wording; progressive disclosure (tailnet sharing is opt-in, nothing automatic).
