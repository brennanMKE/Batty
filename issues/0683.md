## Description

Child of #0680. An agent, or a person setting one up, has no page on the site that says how to tell it is in Batty, whether to use `batty mcp` or the `batty` CLI, which verbs matter, or how to register the MCP server. This issue adds `/docs/index.md` (hand-written source) and `/docs/index.html` (generated from it), held off the server until 1.5.0 (#0681). The nav link and home-page line are added on release day by #0688, not here, so nothing deployable links a held page.

### Current state (checked against `main` at `3a7c12ec`)

- `website/` has `index.html`, `demo.html`, `backgrounds.html`, `changelog.html`, `privacy.html` and nothing for agents. The footer nav (`website/index.html:97-102`) links Demo, Backgrounds, Changelog, Privacy and issues.
- The existing generator pattern is `tools/build-backgrounds-page.py` (stdlib Python, `--check`, self-test `tools/build-backgrounds-page-selftest.py`).
- The content exists elsewhere: `BATTY_SESSION_ID`/`BATTY_TAB_ID`/`BATTY_PANE_ID` (`BattyKit/Sources/BattyKit/Runtime/TabRuntime.swift:471-476`), `batty agent context` (#0661), MCP setup (#0682's snippets), the global-instructions prompt (#0664, `AgentGlobalInstructionsPrompt.text`), and the skill's sequencing guidance (`.claude/skills/batty-cli/SKILL.md` §1-§10).

## Expected behavior

1. `website/docs/index.md` covers, in this order:
   - Batty in one paragraph;
   - **detection:** the three `BATTY_*` variables and `batty agent context`;
   - **MCP or CLI:** use the `batty` MCP tools when the host has `batty mcp` registered, otherwise the CLI; `batty-beta` in Batty Beta; target arguments default to the caller's own Pane;
   - **setup per host:** Claude Code (`batty agent install`, or `claude mcp add`), Codex, Cursor, OpenCode, each with its snippet from `website/docs/snippets/` (#0682) inlined between generated-section markers (`<!-- generated:codex-config.toml -->` … `<!-- /generated -->`);
   - **core verbs with one example each:** `pane split --view git-status --unique` (and the other views), `tab new -c <cmd> --wait`, `server start --port N -- <cmd>`, `server share --port N`, `server serve <dir>`, `server list`, `notify`, `session remind` (server grammar as shipped by #0692; edited 2026-11-19, #0689);
   - **viewing pages:** Batty has no web view; an agent uses the webdriver the developer names (for example `safaridriver`) against the URL from `server list`, localhost or tailnet (#0689 decision A);
   - **close what you open:** `pane close`/`session close` for Panes and Sessions the agent created;
   - **global instructions:** the #0664 prompt, inlined from `global-instructions-prompt.txt`, in a copyable block;
   - **versions:** which Batty version each feature needs (1.5.0 for `agent context`, `tab new`, `--wait`, `mcp`, `agent install`, `server`; 1.3.0 for Projects);
   - links to the CLI reference (`docs/cli/`, #0684), the skill download (#0687), the changelog and GitHub.
2. `tools/build-docs-page.py` (stdlib Python, `python3 -I`) refreshes the generated sections of `docs/index.md` from the snippet files and renders `docs/index.html` with the site's header, footer and `css/` (a minimal Markdown subset: headings, paragraphs, lists, fenced code, links, inline code). `--check` exits non-zero if either file would change. A self-test covers the renderer and the marker refresh.
3. Prose follows `Concepts.md` vocabulary (Session, Tab, Pane) and the house rules: no external JS, no tracking (`website/README.md` "House rules").
4. Everything under `docs/` stays in `website/.deploy-hold` (#0681).

## Acceptance criteria

1. `python3 -I tools/build-docs-page.py --check` and its self-test exit 0; `tidy -e -q website/docs/index.html` reports no errors.
2. Every verb the page names exists in `batty capabilities --json` from a Batty Beta build of `main` (and from the 1.5.0 Prod build, checked again in #0688).
3. Editing a snippet file without regenerating makes `--check` fail.
4. No deployable page links `docs/index.html` (`tools/check-website-hold.py` passes).
