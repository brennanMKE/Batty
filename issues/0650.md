# 0650 — The Background Images picker always opens on My Images and never shows the current Background Sets image selected or scrolled into view

| | |
|---|---|
| **Status** | open |
| **Module** | Pane / Projects / Settings |
| **Platform** | macOS |
| **First seen** | 2026-11-17 |
| **Target** | 1.5.0 |

## Description

The Background Images picker always opens on the My Images tab. For a user who picks hosted images from Background Sets, My Images is empty (hosted images never join My Images, per `Concepts.md`), so every open lands on "No background images yet." and they must switch tabs by hand. When the current background is already a Background Sets image, the Background Sets tab does not highlight it or scroll to it either, so there is no way to see what is chosen without hunting through every set.

User report, 2026-11-17: "Make background image selection better. When I bring it up it starts on the empty tab instead of the list of sets, which would be better. Also, if I have already selected an image from those sets it should show that tab and also have the image selected and scrolled into view. The fact that it does not do this is weak UX." The user was choosing Pane backgrounds in the Project Editor, picking images such as "Sky Gardens at Dawn" from the Future Cities set.

### Current state (checked against `main` at `5ca5c9ca`)

- **The tab is fixed at My Images.** `BackgroundImagesView` declares `@State private var tab: Tab = .myImages` (`BattyKit/Sources/BattyKit/Views/BackgroundImagesView.swift:22`). Nothing sets the initial tab from `current` or from what the user last used. Focus also goes to the My Images grid on appear (`:75-79`).
- **"The empty tab" is My Images with no library images.** `content` shows "No background images yet." with an Add from File… button when `model.entries` is empty (`BackgroundImagesView.swift:103-118`). `model.entries` is the My Images library scan (`Model/BackgroundImagesModel.swift:64-70`). Hosted images live in the hosted image store (`BackgroundImages/Hosted/`) and "never join My Images" (`Concepts.md:186`), so a user who only uses Background Sets always sees this empty state.
- **Only My Images knows the current image.** `BackgroundImagesView` gets `current: String?` (`:18`), works out `currentDigest` from the path's digest folder (`:33-35`), and passes `isCurrent: entry.digest == currentDigest` to each My Images cell (`:140`, highlighted at `:333`). `BackgroundSetsView` is built with only `model` and `onPick` (`:61`; `BackgroundSetsView.swift:14-16`). Its `GridSelection<HostedImageKey>` starts empty (`BackgroundSetsView.swift:18`), and a cell is outlined only when `selection.id == key` (`:230`), which happens only after a click in this sheet (`:143-146`).
- **Nothing scrolls to any image.** Neither view uses `ScrollViewReader`, `scrollTo` or `scrollPosition`. In My Images the current cell is outlined but may be off screen. `BackgroundImagesScrollMonitor.swift` is a diagnostics ring for scroll jumps, not scroll positioning.
- **The current image can be matched to a set image.** A picked hosted image is copied into the target's folder under its digest folder (`TerminalBackgroundImageImporter.adoptImage`, `Settings/TerminalBackgroundImageImporter.swift:240-244`; `digest(ofPath:)` at `:104-108`), so `current`'s digest equals the hosted copy's digest. Each `HostedBackgroundCell` already works out its own digest from `hosted.store.localPath(for:)` (`BackgroundSetsView.swift:240-243`), and `HostedImageRecord` maps `url` to `digest` (`Settings/HostedImageStore.swift:10-14`). A Project Tab's image identity is `.hosted(url:name:)` for a Background Sets image (`Model/ProjectTabImage.swift:11-13`, `derive` at `:82-93`; `Settings/TabImageIdentity.swift`). So both a digest match and a URL match are possible.

### Every place the picker opens (all open on My Images today)

`BackgroundImagesView` is built in two places, and both pass `current`:

1. `TerminalBackgroundControls` Choose… sheet (`Views/TerminalBackgroundControls.swift:51`, sheet at `:65-75`, `current: current.imagePath`). This is used by:
   - Settings → Appearance → Background, the app-wide default (`Views/SettingsView.swift:292`);
   - `BackgroundOverrideSettingsView` (`Views/BackgroundOverrideSettingsView.swift:294`), which is the gear sheet for a Pane (`Views/PaneView.swift:156`), a Tab (`Views/SessionSidebarView.swift:162`) and a Session (`SessionSidebarView.swift:172`), and the Project Editor's Project background (`Views/ProjectEditorView.swift:456`), Pane background (`ProjectEditorView.swift:957`) and Tab background (`ProjectEditorView.swift:1102`).
2. Pane → Background Images… (`Commands/BattyCommands.swift:612-622`), received in `Views/SessionDetailView.swift:72-77`, which shows `PaneBackgroundImagePickerSheet` (`Views/PaneBackgroundImagePicker.swift:38-50`, `current:` the Pane's effective image path).

## Steps to reproduce

1. With no images in My Images, open the Project Editor for a Project and click a terminal Pane's background edit button, then Choose….
2. The picker opens on My Images, showing "No background images yet."
3. Switch to Background Sets and pick an image (for example "Sky Gardens at Dawn" in Future Cities). The sheet closes and the Pane's image is set.
4. Click Choose… again.

## Expected behavior

- **Default tab is Background Sets** when the current image is not a My Images image (including when there is no image).
- **Current image is a Background Sets image:** the picker opens on Background Sets with that image's cell selected (outlined, the same highlight a click gives) and scrolled into view, so its set is visible without scrolling by hand.
- **Current image is a My Images image** (the natural generalization): the picker opens on My Images with that cell selected and scrolled into view.
- This applies to every entry point listed above, since they all share `BackgroundImagesView`.
- Arrow keys and Return start from the selected current image, as My Images already does via `currentDigest` (`BackgroundImagesView.swift:239-246`).
- No new writes in `body`, and the scroll must not cause the visible-row jumps `GridSelection` and the scroll monitor were added to prevent (`GridSelection.swift:5-7`). See `docs/swiftui-observation-rules.md`.

## Actual behavior

At step 4 the picker opens on the empty My Images tab again. After switching to Background Sets, no cell is outlined and the list is scrolled to the top, so the user has to find "Sky Gardens at Dawn" by hand. In My Images, the current image is outlined but not scrolled to.

## Notes

### Open questions

1. **Matching rule.** Should the current path be matched to a set image by digest (the hosted copy's digest folder equals the adopted copy's), by the `HostedImageRecord` URL for that digest, or by both? Hosted downloads are re-encoded per Mac, so the digest is valid only on this Mac. In the Project Editor, a Tab whose identity is `.hosted(url:)` could be matched by URL directly.
2. **Image no longer in any catalog** (dropped by the catalog, or its catalog was removed): open on Background Sets with nothing selected, or on My Images? Suggest Background Sets with nothing selected.
3. **Catalog still loading or offline:** the sets arrive after the sheet appears. Should the selection and scroll happen once the image's set has loaded, at most once per open, and never again after the user scrolls or types in the filter?
4. **Active filter text:** if the filter hides the current image, should it be cleared on open? The query is `@State` (`BackgroundSetsView.swift:19`), so it starts empty on each open today.
5. **Downloaded image cache** (`BackgroundImages/Downloaded/`): a synced Project Tab's image downloaded there is a hosted image with a URL but no hosted-store copy. Is it treated as a Background Sets image for this purpose? It probably should be, matched by URL.
6. **No current image:** should the default be Background Sets always, or should the last tab the user used be remembered? The report asks for Background Sets; remembering the last tab is not requested.
7. **Follow-the-parent sheets:** in a gear sheet that follows (`editor.isFollowing`), the controls are disabled. Should `current` be the effective (inherited) image, as Pane → Background Images… already uses, so the inherited image is shown as current?
