## Description

**Umbrella, child of #0660.** No code ships on this umbrella; the work lands in the children below (#0681-#0688). batty.sstools.co tells people what Batty is and where to download it, but nothing on it is for an AI agent. An agent, or a person setting one up, can't find out from the site how to tell it's running in Batty, how to use the `batty` CLI, or how to register `batty mcp` with Claude Code, Codex, Cursor or OpenCode. The site also has none of the files agents and crawlers look for: `llms.txt`, `robots.txt`, `sitemap.xml` and Markdown copies of pages.

User's request, 2026-11-19: "We need docs we can put on the website to direct agents to use the CLI tool and set up the MCP to use it. There are also other changes to prepare a website for agents, right?"

Scope split with #0671: #0671 keeps in-app Help, `.claude/skills/batty-cli/SKILL.md`, the `docs/batty-cli-*.md` files, `Concepts.md`/`PRD.md` and the 1.5.0 changelog entry. This issue owns the website's agent pages and the machine-readable files the site serves. Where #0671's Expected behavior says "an agent-integration section on the site", this issue delivers it. #0671 adds at most a one-line link from the home page or changelog to `/agents.html`.

### Current state (checked against `main` at `2c5d652a`)

- **No agent page.** `website/` has `index.html`, `demo.html`, `backgrounds.html`, `changelog.html` and `privacy.html`, and nothing else. The footer nav (`website/index.html:97-102`) links Demo, Backgrounds, Changelog, Privacy and issues. `index.html` never mentions the CLI, MCP or agents. The home page's only reference to the CLI is the demo clip `website/demo/09-cli.mp4`.
- **No machine-readable entry points.** `website/llms.txt`, `website/robots.txt` and `website/sitemap.xml` don't exist. There are no `.md` pages (the only Markdown is `website/README.md`, which is not meant to be served).
- **No published CLI reference.** `batty capabilities --json` is the source of truth for verbs and their `inputSchema` (`.claude/skills/batty-cli/SKILL.md:15-20`), but nothing renders it for the web, and no static copy is published.
- **The skill can only be fetched by git clone.** The plain-text `batty capabilities` output ends with a recipe that `git clone`s `https://github.com/brennanMKE/Batty.git` at tag `v<cliVersion>` and runs the skill's `install.sh` (`BattyKit/Sources/batty/CapabilitiesCommand.swift:264, 273-274, 329`). The site has no skill download.
- **The MCP config for each host lives only in code.** `AgentGuidanceInstaller.plan` builds the OpenCode entry (`mcp.<key>`: `type: local`, `command: [<cli>, "mcp"]`, `enabled: true`) and the Cursor entry (`mcpServers.<key>`: `command`, `args: ["mcp"]`) at `BattyKit/Sources/BattyCLICore/AgentGuidanceInstaller.swift:253-279`. It registers Claude Code through a staged plugin marketplace (`claude plugin marketplace add` and `claude plugin install`, lines 239-250). `CodexConfigBlock.lines` (`BattyKit/Sources/BattyCLICore/CodexConfigBlock.swift:23-31`) writes Codex's `[mcp_servers.<key>]` block with `env_vars` for `BATTY_SESSION_ID`, `BATTY_TAB_ID` and `BATTY_PANE_ID` (line 16). Nothing renders these for a reader. `claude mcp add` is not documented anywhere (`git grep "claude mcp add"` finds nothing).
- **The global-instructions prompt exists only in the app and the skill.** `AgentGlobalInstructionsPrompt.text` (`BattyKit/Sources/BattyCLICore/AgentGlobalInstructionsPrompt.swift:36-50`, #0664) is shown by Settings → Advanced → AI Agents → Copy Prompt and copied into `SKILL.md` §9 (lines 296-323). Its rule lines come from `AgentContextNote.ruleLines` (`AgentContextNote.swift:8`).
- **The README's deploy section is out of date.** `website/README.md` "Deployment" still suggests GitHub Pages, Netlify or S3. The process actually in use, rsync to `photon:/var/www/vhosts/batty.sstools.co/` without `--delete`, appears only under "Background images".
- **Two deploy processes disagree.** `scripts/RELEASE.md` step 7 (lines 177-187) deploys with `scripts/deploy-website.sh`, which rsyncs with `--delete` (`scripts/deploy-website.sh:14, 101-106`); `website/README.md` says never use `--delete`. Nothing can hold a file on `main` off the server (#0681).
- **Everything agent-related is Beta-only until #0669/#0670 remove the flags.** The Prod site should not advertise it before 1.5.0 ships.

## Expected behavior

The children below implement these items; the split is in the Children table. Each item comes with a recommended default.

1. **"For AI agents" page.** `website/agents.html`, with a plain-Markdown twin `website/agents.md` holding the same content. It covers:
   - what Batty is, in one paragraph;
   - how an agent detects it is in Batty: `BATTY_SESSION_ID`, `BATTY_TAB_ID` and `BATTY_PANE_ID` in the environment, and `batty agent context` (#0661) for its Session, Tab and Pane;
   - when to use MCP and when to use the CLI. Recommended: use MCP when the host has `batty mcp` registered; otherwise use the CLI. Use `batty-beta` in Batty Beta;
   - the core verbs, each with an example: `pane split --view git-status --unique` (and the other views), `tab new -c <cmd> --wait` (#0667/#0668), `server start --port N -- <cmd>` and `server serve <dir> --open`, `notify`, `session remind`, and closing the Panes and Sessions you open;
   - links to the CLI reference (item 4), the skill download (item 6), the changelog and GitHub.

   Recommended: one hand-written Markdown source, `website/agents.md`, with `agents.html` generated from it by a small `tools/` script (stdlib Python, like `build-backgrounds-page.py`) that has a `--check` mode. The two can't drift, and the site still has no build step at deploy time.
2. **MCP setup for each host, with copy-paste config.**
   - **Claude Code:** `batty agent install` installs the plugin (MCP server, skill and SessionStart hook, #0663). Manual alternative: `claude mcp add batty -- batty mcp`.
   - **Codex:** the `config.toml` block, including `env_vars`.
   - **Cursor:** the `~/.cursor/mcp.json` entry.
   - **OpenCode:** the `opencode.json` entry.

   Each snippet is **generated from the same code the installer uses**, so the docs and the installer can't drift. Recommended: a `batty agent install --print-config <host>` mode, or a small build-time executable target in BattyKit that calls `CodexConfigBlock.lines` and the entry builders in `AgentGuidanceInstaller.plan`, with `cliExecutablePath` set to the bare command name (`batty`) instead of the app-bundle path. Its output is written into `agents.md` between generated-section markers. A BattyKit unit test renders the snippets and compares them byte for byte with the committed `website/agents.md` sections. `--check` fails the pre-deploy step when they differ. To make this possible, factor the entry builders in `plan` out into a reusable function; today they are inline literals.
3. **The global-instructions prompt** (#0664) appears on the page in a copyable block, rendered from `AgentGlobalInstructionsPrompt.text` by the same generator and covered by the same drift test.
4. **CLI reference generated from `batty capabilities --json`.** `website/cli/index.html` (and `cli/index.md`) lists every noun and verb with its description and parameters from `inputSchema`. The JSON is also published as a static file at `website/cli/capabilities.json`, regenerated at each release from the Prod build of that release. Recommended: commit the JSON, generate the pages from it with `tools/build-cli-reference.py` (with `--check`), and add a step to the per-release workflow in `website/README.md`.
5. **Machine-readable entry points.**
   - `website/llms.txt` in llmstxt.org format: an H1, a one-line summary in a blockquote, then link sections pointing at `agents.md`, `cli/index.md`, `cli/capabilities.json`, the skill download and the changelog.
   - `website/llms-full.txt` (optional): the agent docs and CLI reference joined into one file, generated by the same tools. Recommended: yes. It is cheap once the `.md` sources exist.
   - Markdown twins: `agents.md` and `cli/index.md`. Both are served as `text/markdown` or `text/plain`; check the photon server's MIME map.
   - `website/robots.txt`. Recommended: allow everything, AI crawlers included, and point at the sitemap. The site is public product documentation, and agents finding it is the goal. **The user decides this** (open question 1).
   - `website/sitemap.xml`, listing every page, with the generator updating it when pages are added.
6. **The batty-cli skill is downloadable from the site, versioned.** `website/downloads/batty-cli-skill-<X.Y.Z>.zip` holds `SKILL.md` and `install.sh` and is made at release time from the release tag. `agents.html` links the latest one. Recommended: change the plain-text `batty capabilities` pointer to this URL and keep the `git clone` recipe as the fallback. That changes `CapabilitiesCommand.swift` (CLI module); keep the JSON path unchanged (#0384).
7. **Versioning.** Each feature on the agent page says which Batty version it needs: `agent context`, `tab new`, `--wait`, `mcp`, `agent install` and `server` need 1.5.0; Projects needs 1.3.0. Until #0669/#0670 remove the flags, a visible note says these are in Batty Beta only. The note comes off with the 1.5.0 release.
8. **Deploy.** Follow `website/README.md`: dry-run `rsync -avzn website/ photon:/var/www/vhosts/batty.sstools.co/`, then the real run, never `--delete`, with the user's go-ahead each time. **The agent pages go live with the 1.5.0 release**, not before. Recommended: hold them. Land the files on `main`, but leave them out of `sitemap.xml`, `llms.txt` and the nav until release day, and exclude them from rsync until then. The release step for 1.5.0 then adds them to the sitemap, `llms.txt` and the nav and deploys everything together. A hidden staging path on the live server is the alternative, but anything there can still be crawled. Also update `website/README.md`: replace the stale "Deployment" section with the rsync process, list the new pages under "Pages to spot-check", and add the generator `--check` steps to the pre-deploy checks and the capabilities/skill steps to "Per-release workflow".

## Acceptance criteria

This umbrella can be resolved only when every child is resolved, and:

1. 2. The Codex, Cursor and OpenCode snippets and the global-instructions prompt on `agents.md` match what the 1.5.0 code produces byte for byte. A BattyKit unit test fails if either side changes without the other, and the generator's `--check` exits non-zero on drift.
3. `website/cli/capabilities.json` equals the output of `batty capabilities --json` from the 1.5.0 Prod build, and the CLI reference pages list every verb in it.
4. `llms.txt` follows the llmstxt.org structure (H1, blockquote summary, link-list sections), and every link in it returns 200.
5. Before the 1.5.0 deploy, the live site carries none of the new pages, and nothing in the deployed nav, sitemap or `llms.txt` points at them.
6. Every CLI verb named on the agent page exists in `batty capabilities` from the 1.5.0 Prod build. This is the website counterpart of #0671's criterion 2.
7. No rsync in the process uses `--delete`.

## Decisions (orchestrator defaults, user may override, 2026-11-19)

1. **robots.txt** allows every crawler, AI crawlers included, and names the sitemap (open question 1).
2. **`llms-full.txt`: yes**, generated (open question 2).
3. **Pages at `/agents.html` (+ `/agents.md`) and `/cli/`**, with an "AI agents" footer link on every page and one home-page line (open question 3).
4. **Hold until release:** the pages land on `main` but stay off the server, via `website/.deploy-hold`, until the 1.5.0 release deploy (open question 5).
5. **Skill distribution** (replaces open question 4's git-clone fallback): the source of truth stays the `SKILL.md` bundled in the app and installed by `batty agent install`, so its version always matches the installed CLI. The skill is kept thin, deferring verb details to `batty capabilities --json` and `batty agent context`, and states its minimum Batty version (#0686). At release a tool packages it as `downloads/batty-cli-skill-<X.Y.Z>.zip` plus a stable `batty-cli-skill-latest.zip`, in the Agent Skills folder layout, and publishes a Claude Code plugin marketplace with the same plugin `agent install` stages (skill, MCP entry, SessionStart hook) (#0687). `batty capabilities` points at `batty agent install` first and the site URL second; the git-clone recipe goes (#0686).

## Open questions for the user

Questions 1-5 are answered by the defaults above unless the user overrides them. Still open:

6. **Claude Code marketplace hosting.** Recommended: a stable URL on the site. Alternative: a public GitHub repo. #0687 first checks whether a URL-added marketplace supports relative plugin sources.
7. **`scripts/deploy-website.sh` and `scripts/RELEASE.md` step 7** use `--delete`, against the README's rule. Recommended: change both to the README's rsync with the hold list (#0681). `scripts/` is restricted, so this needs the user's confirmation.

Original questions:

1. **robots.txt policy.** Recommended: allow all crawlers, AI crawlers included (GPTBot, ClaudeBot, Google-Extended, PerplexityBot and others), and list the sitemap. The alternative is to disallow AI training crawlers while still allowing agents that fetch on a user's behalf.
2. **`llms-full.txt`: yes or no?** Recommended: yes. It is generated, so it costs nothing to maintain.
3. **Page location and nav.** Recommended: `/agents.html` and `/cli/`, with an "AI agents" link in the footer nav on every page and one line on the home page (the home-page line is coordinated with #0671). The alternative is a `/docs/` tree.
4. **Skill download on the site, with `batty capabilities` pointing at it.** Recommended: yes, keep `git clone` as the fallback.
5. **Hold until release or stage early.** Recommended: hold the pages off the server until the 1.5.0 release deploy.
