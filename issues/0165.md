## Description

Workspace serialization ([[0029]]–[[0031]], [[0055]]) is the only thing standing between a crash and the user losing their work. The Codable round-trip has unit-test coverage but the end-to-end "save on quit → restore on launch → tree matches" loop is not exercised. This suite locks in the workspace flow across the kill-and-relaunch boundary.

## Regressions this suite would have caught

- [[0029]] / [[0030]] — Codable schema and save triggers. The round-trip is unit-tested, but the *trigger* path (save-on-structural-change, save-every-30s) is not.
- [[0031]] — Workspace load on launch with corrupt-file recovery. A test corrupting the workspace file and asserting the app launches with a fresh default session would have caught regressions in the recovery path.
- [[0055]] — Workspace restoration is not normal terminal-app behavior. Whatever the chosen semantics are (clean launch by default, restore on a flag?), they should have explicit tests.

## Test cases

All tests use [[0158]] driver intents plus app terminate/relaunch.

### Round-trip — would catch [[0029]] / [[0030]]

- **Sessions persist across relaunch.** Driver script: create 3 sessions, name them, terminate, relaunch. Assert all 3 session rows reappear with the right names.
- **Layouts persist across relaunch.** Apply a `twoByTwoGrid` to Session 2, terminate, relaunch. Assert Session 2 still has 4 panes.
- **Tab list per pane persists.** Open 3 tabs in a pane, terminate, relaunch. Assert 3 chips reappear in that pane.
- **Title overrides persist.** Rename a tab and a session, terminate, relaunch. Assert the overrides reappear.

### Save triggers — would catch [[0030]]

- **Structural change triggers a save before quit.** Driver: create a session. Read the workspace file's mtime. Wait briefly. Assert mtime advanced (save was queued). Test exercises the save-on-structural-change path.
- **Periodic save fires while idle.** Hard to test in CI without long waits; document as a manual smoke and skip in CI, or use a driver intent `setWorkspaceSaveInterval(seconds:)` to drop it to 1s for the test.

### Corrupt-file recovery — would catch [[0031]]

- **Corrupt workspace file → app launches with a default session.** Driver pre-launch hook: write invalid JSON to the workspace path. Launch. Assert app comes up with a single fresh `session-row.Session 1`.
- **Backup workspace file is created on corruption.** If the recovery path saves a `.corrupt-<date>` backup, assert the backup file exists. Confirms the user can recover their tree manually if needed.

### Restoration semantics — covers [[0055]]

- **Document the chosen behavior and test it.** If clean-launch-by-default: assert relaunch with no flag shows only `Session 1`. If restore-by-default: the [[0029]]–[[0030]] tests already cover this. Whichever the codebase does, write the test.

## Workspace path discovery

The driver / harness needs a way to locate the workspace file under the test's temp `BATTY_UI_TEST_TEMP_HOME`. Either:

- Existing `BATTY_UI_TEST_TEMP_HOME` env var (already in the harness) — derive the path from `<temp>/Library/Application Support/Batty/workspace.json` and ensure the app honors `HOME` redirection for the support directory.
- A new diagnostic intent `workspacePath` that writes the resolved path to a sentinel file at launch.

The diagnostic intent is simpler and more robust.

## Driver intents needed (from [[0158]])

- `workspacePath` — writes the resolved workspace.json path to a sentinel for the test to read.
- `setWorkspaceSaveInterval(seconds:)` — for the idle-save test (or omit and accept manual-only coverage of that path).
- All the create/rename/layout intents from earlier suites.

## Out of scope

- Migration tests for schema version bumps (no schema versioning exists yet; add when it does).
- Cross-window persistence (multi-window gated on a future issue).
- The workspace save spam observed in the test log earlier (logged ~25 times during idle — separate bug, separate issue if pursued).

## Acceptance criteria

- All test cases pass under `xcodebuild -scheme 'Batty (Beta)' -destination 'platform=macOS' test`.
- The corrupt-file test verifies both behaviors: (a) app launches, (b) backup is preserved.
- Each test uses `BATTY_UI_TEST_TEMP_HOME` so tests don't touch the real workspace at `~/Library/Application Support/Batty/`.
