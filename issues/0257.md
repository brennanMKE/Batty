## Description

Grow the `batty` CLI from "open a session at a path" into a coherent, extensible **`batty <noun> <verb> [flags]`** surface. This ticket **defines the concrete v1 argument surface** and implements the foundation + core mutation verbs — all over the existing one-way `batty://` URL scheme (no socket). Design rationale and the full catalog live in `docs/batty-cli-design.md`; this issue pins the exact arguments to build now.

The recent pane work gives the CLI real things to control: `pane split` distributes evenly (#0255) and panes can be hidden/shown (#0256).

## Foundation (Tier 0 — do first)

1. **Grammar:** `batty <noun> <verb> [flags]`. Nouns: **`session`, `pane`, `tab`, `window`** (+ bare app verbs). No `surface`/`workspace`/`worktree` (Batty's tab *is* the terminal). Keep `batty <path>` working as an alias for `batty session new <path>`.
2. **Context env vars:** inject `BATTY_SESSION_ID`, `BATTY_PANE_ID`, `BATTY_TAB_ID` (≡ surface id) into every surface at spawn (prepend `export …;` to the launch command, per supacode's pattern — see the CLI-context discussion). Every context-sensitive verb resolves its target as: explicit `--session/--pane/--tab` flag → else the `BATTY_*` env → else the app's focused element.
3. **`batty whoami`** — print the current session/pane/tab **from env alone** (no app round-trip).
4. **Conventions:** global `--json` (reserved for query verbs later), meaningful exit codes, quiet by default. `batty version` / `help` already exist.
5. **IPC decision (pinned):** mutations go over the **`batty://` URL scheme** (fire-and-forget, no daemon). Query/read verbs (`list`, `read`, `wait`) are **out of scope here** — they need a request/response socket and are deferred (Tier 3 in the design doc). Design the grammar so socket-backed verbs slot in later without changing these.

## Verb surface to build (Tier 1 — all one-way over `batty://`)

Concrete arguments:

```
batty session new [<path>]            # alias: `batty <path>`; defaults to "."
batty session rename <name>           # renames the calling/target session
batty session focus <name|id>
batty session close [--session <id>]

batty pane split [-h|--horizontal | -v|--vertical]   # even 1/n (#0255)
batty pane hide                       # hides the calling/focused pane (#0256)
batty pane show <id>                  # restores a hidden pane by id
batty pane focus <up|down|left|right|id>
batty pane zoom [--on|--off|--toggle]
batty pane close [--pane <id>]

batty tab new [-c|--command <cmd>]    # new tab in the calling/focused pane
batty tab rename <name>               # renames the calling/target tab
batty tab focus <n|id>
batty tab close [--tab <id>]

batty open                            # activate/foreground Batty
batty notify --title <t> [--body <b>] [--sound]   # posts into the bell feed
batty whoami                          # prints BATTY_* context (local, no app call)
```

Each mutation maps to a `batty://…` route the app handles (extending `BattyURLHandler`), targeting the resolved session/pane/tab. Reuse existing app methods where they exist: `AppStateStore.renameSession`, the split path (`SplitTree.splitFocusedPane`), `hidePane`/`showPane` (#0256), `focusPane`, `addSession(workingDirectory:)`; add the small ones missing (tab rename, notify-into-feed).

## Notes / decisions

- **Flag vs subcommand:** use subcommands (`batty pane split`) over bare option flags (`batty --split`) so each verb is unambiguous and the surface scales. `swift-argument-parser` (already a dependency) models `<noun>` as a `ParsableCommand` with `<verb>` subcommands cleanly.
- **`pane show` needs an id** (a hidden pane has no shell to run `batty` from). `batty pane list` (to discover ids) is a *query* → deferred to the socket tier; until then, ids come from `whoami`/logs. Note this limitation.
- **`notify`** is the on-brand "present agent activity" primitive (routes into the existing bell feed + AI summaries) — keep it simple; richer `status`/`progress` pills are Tier 2 (design doc §D), deferred.
- **Out of scope (deferred):** the two-way socket and everything needing it — `list`, `read` (screen), `send`/`send-key`, `wait`, `events subscribe`, and the sidebar activity pills. Also: git/worktree/GitHub/scripts/plugins (off-mission).
- Keep verbs feeling like native actions with keyboard/menu equivalents where sensible; nothing should require a socket to exist for the app to run.

## Verification expectations

- Unit-test the URL build/parse for each new route and the context-resolution logic (env → flag override) — extend the `SessionURLBuilder`/`BattyURLHandler` test pattern from #0250/#0251.
- `swift run batty <verb> …` builds/parses standalone; `scripts/build.sh unit` + `scripts/build.sh` green; the embedded binary still lands in the bundle.
- The live end-to-end (a verb actually mutating the running app) needs the user's runtime sign-off, like #0250/#0251.
