## Description

Compiling `BattyKitTests` produces warnings in tests added recently. Two kinds: a captured `var` counter mutated inside a `NotificationCenter` observer closure (a Swift 6 `#SendableClosureCaptures` warning), and discarded results (`#NoUsage`). None of them fails a test today. They add noise to every `./build.sh unit` log, and the captured-var ones become errors if the test target's concurrency checking is tightened. All are test-only fixes.

Each site below was checked against `main` at `79b4bcd5`. The warning text comes from the unit logs under `build/checks/` and `.claude/worktrees/issue-0640/build/checks/`. Line numbers in those logs are a few lines off the current file in places. The lines below are the current ones.

### Captured `var posted` mutated in an observer closure

`addObserver(forName:object:queue:using:)` takes a `@Sendable` block, so `posted += 1` inside it is a mutation of a captured var in concurrently-executing code:

```
AuxiliaryWindowGateTests.swift:221:124: warning: mutation of captured var 'posted' in concurrently-executing code [#SendableClosureCaptures]
```

- `BattyKit/Tests/BattyKitTests/AuxiliaryWindowGateTests.swift:216-217`, from #0480 (`23ab1fb5`). The test resets the counter with `posted = 0` at `:225`.
- `BattyKit/Tests/BattyKitTests/AuxiliaryWindowGateTests.swift:319-320`, from #0641 (`f44b1817`). The test resets the counter at `:328`.
- `BattyKit/Tests/BattyKitTests/ProjectPickerTests.swift:614-615` uses the same pattern (`.battyToggleProjectPicker`). The logs report the same warning there (`:575:81` and `:615:81`). Fix it at the same time.

`var forwarded` (`AuxiliaryWindowGateTests.swift:219`, `:322`) is mutated in the non-`@Sendable` `PasteDispatcher.forwardStandardPaste` closure, and the compiler does not flag it. Leave it alone.

## Notes

Proposed fix pattern:

- **Counters in `@Sendable` observer blocks:** replace `var posted = 0` with a small `Sendable` box and read it through the box. The test target already has two shapes for this. Prefer the `Mutex` one from `BackgroundImageThumbnailerTests.swift:9-13`:

  ```swift
  nonisolated private final class Counter: Sendable {
      private let value = Mutex(0)
      var count: Int { value.withLock { $0 } }
      func increment() { value.withLock { $0 += 1 } }
  }
  ```

  The `NSLock` shape is `LockedCounter` (`TestClockTests.swift:377`). Both are `private` to their files. The implementer can either add a matching file-private counter to each affected file, with a `reset()` for the `posted = 0` lines, or promote one shared test helper. Whichever is chosen, keep the type `nonisolated` (see `docs/async-test-seams.md` on `EventCounter`). This is a counter swap only. These tests post synchronously (`queue: nil`) and assert straight after, so no waiting is involved, and the no-sleep rule is unaffected.
- **Discarded results:** use `_ = try #require(...)` at `AppStateStoreReminderTests.swift:720`/`:723`, and `_ = fixture.probe.window.makeFirstResponder(nil)` at `SessionDetailLayoutConvergenceTests.swift:414`. If the test depends on the resign succeeding, `#expect(...)` it as `:458` does.

Older unit logs also show other test warnings outside this issue's scope: `'shouldFail'`/`'denied'` mutated after capture in `ProcessStatusPaneContentTests.swift` and `ProcessFollowByNameTests.swift:344`, an always-executing `defer` in `DefaultTargetWindowTests.swift:176`, an always-succeeding cast in `GitStatusPaneContentTests.swift:510`, an unused `session` in `NonTerminalPaneTeardownPathsTests.swift:215`, and an unnecessary `try` in `ProjectSharingTests.swift:349`. These were not re-verified against `main`. If the planner wants a full warning sweep, it can fold in the ones that still reproduce.
