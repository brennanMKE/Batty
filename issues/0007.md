# 0007 — Implement TerminalSurfaceNSView with Metal layer and event forwarding

| | |
|---|---|
| **Status** | open |
| **Module** | TerminalSurface / GhosttyKit |
| **Platform** | macOS |
| **First seen** | 2026-05-08 |

## Description

The native `NSView` that hosts a single Terminal Session: owns a `CAMetalLayer`, attaches a libghostty surface, and forwards keyboard / mouse / scroll events to libghostty.

**Acceptance criteria:**
- `TerminalSurfaceNSView: NSView` owns a `CAMetalLayer` (set as `layer`, with `wantsLayer = true`).
- On creation it requests a surface from `SurfaceRegistry` (#0006) and attaches the Metal layer to it.
- `keyDown(with:)`, `mouseDown(with:)`, `mouseDragged(with:)`, `mouseUp(with:)`, `scrollWheel(with:)` forward to the corresponding libghostty surface APIs.
- On `setFrameSize(_:)` / `viewDidEndLiveResize`, `metalLayer.drawableSize` is updated to `bounds.size * contentsScale` (Kytos's note — wrong here = blurry text).
- The layer's background is set to the terminal's background color before the first draw to avoid the first-frame flash.
- IME / `NSTextInputClient` is **out of scope here** — issue #0008 owns that.

## Notes

- libghostty spawns its own IO and render threads per surface; anything mutating Swift state from those callbacks must marshal to the main actor.
- The Kytos write-up (`batty-getting-started.md` §11) is the best reference for the resize/drawableSize gotcha.
- This issue is paired with #0008 (the SwiftUI wrapper) — they may merge in a single PR but staying separate keeps the work splittable.

## Revised approach — 2026-05-08

`libghostty-spm` ships **`GhosttyTerminal`**, a Swift wrapper that already provides exactly this NSView. We're now consuming it via `BattyKit` (`@_exported import GhosttyTerminal` from `BattyKit.swift`).

Specifically, `GhosttyTerminal` provides:
- `TerminalView` — `typealias` for `AppTerminalView` on macOS (an `NSView`).
- `TerminalSurfaceView` — a SwiftUI `View` already wrapping the NSView (this is what `#0008` was going to write).
- `TerminalSurfaceCoordinator` — handles the display link, metrics, and Metal layer sizing (the Kytos `drawableSize` gotcha is solved upstream).
- `TerminalKeyEventHandler` — keyboard event translation including modifiers.
- Full IME pipeline retained per the `libghostty-spm` README (`Input handling (key, mouse, IME)` is explicitly preserved in the trimmed build).

**Revised scope:**
- Do **not** build `TerminalSurfaceNSView` from scratch.
- If our drag-drop (#0022), bell-feed wiring (#0024), or other custom integrations need NSView access, either:
  1. Use `GhosttyTerminal`'s existing delegate protocols (`TerminalSurfaceBellDelegate`, etc.), or
  2. Wrap `TerminalView` in a thin AppKit subclass / decorator only for drag-drop (`NSDraggingDestination`) which the public delegate API may not expose.
- This issue likely converges to a small "verify `TerminalView`/`TerminalSurfaceView` meets our needs" task plus a tiny wrapper for drag-drop. May get marked `wontfix` if the wrapper isn't needed.

**Updated acceptance criteria:**
- `TerminalSurfaceView` from `GhosttyTerminal` renders a working terminal in our SwiftUI tree (covered by `#0009`'s hello-surface task).
- Any custom NSView shim required for drag-drop is implemented in `BattyKit/Sources/BattyKit/` and documented.
