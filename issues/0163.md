## Description

The bell feed has a long bug history — [[0024]]–[[0028]], [[0068]], [[0069]], [[0071]], [[0134]] — and several of the regressions were quiet (counts wrong, navigation didn't clear, propagation skipped a level). The bell path is hard to manually verify because it requires intentionally triggering a `BEL` or OSC 9 from a shell, then walking the surface→tab→pane→session propagation chain. A UI suite is the right fit.

## Regressions this suite would have caught

- [[0024]] / [[0025]] — Initial bell capture and propagation. Baseline tests for both `BEL` and OSC 9 paths.
- [[0026]] — Bell Feed popover UI. Test that the popover opens, lists entries, dismisses.
- [[0027]] — Click-to-jump flow (Window → Session → Pane → Tab). Test that clicking an entry selects the right session, focuses the right pane, activates the right tab.
- [[0028]] — System notifications + visual indicators on tabs/panes/sidebar. Test that the bell badge appears on each level of the chrome.
- [[0068]] — Settings claimed per-session mute exists in sidebar context menu, but it didn't. Test that the context menu actually contains the documented item.
- [[0069]] — Bell notifications didn't clear when the user navigated to the bell's pane. Direct regression test.
- [[0071]] — Closing a pane didn't clear bell-feed entries that referred to it. Direct regression test.
- [[0134]] (open) — Bell Feed hotkey with keyboard navigation and jump-to-pane. When implemented, tests for the hotkey and arrow-key navigation lock it in.

## Test cases

All tests use [[0158]] driver intents plus shell input via the terminal.

### Bell capture — would catch [[0024]], [[0025]]

- **BEL byte triggers a feed entry.** Type `printf '\a'` into the focused pane's terminal. Wait for a `bell-feed-entry` element to appear (new identifier). Assert at least one entry exists.
- **OSC 9 triggers a feed entry with custom message.** Type `printf '\033]9;hello\007'`. Assert an entry exists with the text "hello" in its accessibility value.
- **Bell badge appears on the source tab, pane, and session.** Assert `tab-chip.<title>` carries `accessibilityValue` `"bell-pending"`, same for `pane-terminal.<id>` and `session-row.<title>`.

### Click-to-jump — would catch [[0027]]

- **Clicking an entry brings the bell's session forward and focuses the right pane.** Driver: create two sessions, send a bell in Session 2, select Session 1. Open the feed popover. Click the entry. Assert Session 2 becomes selected and the right pane has `accessibilityValue == "focused"`.

### Clear behaviors — would catch [[0069]], [[0071]]

- **Navigating to the bell's pane clears its badge.** Send a bell in pane B. Focus pane B (via `focusPane` intent). Assert pane B's `accessibilityValue` no longer contains `"bell-pending"`.
- **Closing the bell's pane clears its feed entry.** Send a bell. Close the pane. Assert the feed has no entry referring to the closed pane id.
- **Closing the bell's session clears its feed entries.** Same shape, at session level.

### Settings interaction — would catch [[0068]]

- **Per-session mute item is present in the sidebar context menu.** Open context menu on `session-row.<title>`. Assert `menu.sidebar.mute-session.<title>` exists.
- **Muted session does not produce feed entries.** Toggle mute on. Send a bell. Assert feed entry count did not change.

### Hotkey & keyboard nav — would lock in [[0134]]

- **Cmd-Shift-N opens the feed popover.** Assert `bell-feed.popover` exists after the shortcut. (Already in initial scope per [[0026]] — re-verify.)
- **Arrow keys move selection through entries.** When [[0134]] lands, add nav tests.

## Accessibility identifiers / values needed

- `bell-feed.popover` on the popover root.
- `bell-feed.entry.<id>` on each entry row, with `accessibilityValue` containing the message text.
- `accessibilityValue("bell-pending" / "clear")` on `tab-chip.<title>`, `pane-terminal.<id>`, `session-row.<title>`.
- `menu.sidebar.mute-session.<title>` on the context menu item.

## Driver intents needed (from [[0158]])

- `openBellFeed` / `closeBellFeed`.
- `clickBellFeedEntry(at:)`.
- `setSessionMuted(name:, muted:)`.
- (Sending the actual bell is done via shell input through the terminal, not a driver intent — it must exercise the libghostty path.)

## Out of scope

- System notification permission prompts (out-of-process UI; not testable from XCUITest).
- The actual notification *content* delivered to Notification Center (cross-process).
- BellFeed unit tests for `BellFeedStore` (those belong in `BattyKitTests`, not UI tests).

## Acceptance criteria

- All test cases pass under `xcodebuild -scheme 'Batty (Beta)' -destination 'platform=macOS' test`.
- Each test names the regression it covers.
- The hotkey/nav tests for [[0134]] are skipped with `XCTSkip` until [[0134]] lands.

## Notes

- Depends on [[0158]].
- Bell timing is asynchronous — every assertion needs a `waitFor`/`waitForExistence` with a generous (5s) timeout because the path runs across libghostty's callback queue and SwiftUI's update cycle.
