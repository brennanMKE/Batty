## Description

The central store that aggregates Bell events (#0024) into the unified Bell Feed and exposes unseen counts at each containment level. Any Tab/Pane/Session can ask "do I have unseen bells?" without walking the whole tree on every render.

**Acceptance criteria:**
- `BellFeedStore` is `@Observable` (Swift Observation) and `@MainActor`-isolated.
- Bell events flow into the store from #0024's hook. Each event records: timestamp, sourceTabID, sourcePaneID, sourceSessionID, sourceWindowID, optional message body.
- Bell events from the focused Tab record to the feed but do **not** increment unseen counters.
- Bell events from a non-focused Tab increment unseen counters at every level: Tab.unseenBellCount → Pane.unseenBellCount → Session.unseenBellCount.
- Marking an entry seen (or "Clear all") decrements counters at every level it propagated through.
- Feed history is capped (default 200 entries, oldest dropped).

## Notes

- The store owns the canonical entry list; views observe it. Use `@Observable` rather than ObservableObject to align with Swift 6 / MainActor default.
- Persistence of the feed history lives in #0031 (load) / #0030 (save) — the Workspace doc owns it.
- This issue is a hard prerequisite for the popover (#0026), click-to-jump (#0027), and visual indicators (#0028).

### Deferred — 2026-05-08

Depends on `#0024` for actual bell events to populate the store. Building the store now without an event source would land empty plumbing nobody exercises. Deferring with the same blocker as the bell-event capture: GhosttyTerminal's `TerminalViewState` doesn't expose `Bell` or `DesktopNotification` delegates to SwiftUI consumers, and the AppKit-level delegate hooks aren't reachable without either a custom `NSViewRepresentable` wrapper or an upstream PR.

## Root cause

After #0024 there was a per-tab event mirror (`TabRuntime.bellCount`, `lastBellAt`, `lastBellMessage`, `unseenBellCount`), but no global store, no per-Pane / per-Session unseen propagation, and no concept of "focused tab → don't ring up unseen counters." The focused-vs-unfocused distinction is the entire point of the unseen-count machinery — without it, the popover would just always show today's bells without ever giving the user a way to tell what's new.

## Fix

Centralize the bell event accounting in a new `BellFeedStore` and make `AppStateStore` the focus-aware coordinator that drives both the store and the per-runtime unseen counters.

- **`BellFeedStore: @Observable @MainActor`** — owns `entries: [BellFeedEntry]` (capped at 200, newest first). API: `record`, `markSeen(id:)`, `markAllSeen()`, plus `unseenCount(forTab|Pane|SessionID:)` for ad-hoc queries.
- **`BellFeedEntry` is now `public`.** Required so the Batty app target (and downstream UI in #0026/#0027/#0028) can read its fields without going through the BattyKit boundary.
- **New `unseenBellCount` on `PaneRuntime` and `SessionRuntime`,** mirroring the existing field on `TabRuntime`. Persistence model already had these fields on `Pane` and `Session`.
- **`AppStateStore.bellFeed: BellFeedStore`** plus four routing methods:
  - `recordBellTick(forTabID:)` — locates the (session, pane, tab) triple, calls `tab.recordBellTickIfNeeded()` to consume the upstream delta, then records one `BellFeedEntry` per BEL with `seen=true` if the tab is globally focused (selected session AND focused pane AND active tab) or `seen=false` otherwise. Bumps `tab/pane/session.unseenBellCount` only when not focused.
  - `recordDesktopNotification(forTabID:)` — same shape, single entry per OSC 9.
  - `markBellSeen(id:)` / `markAllBellsSeen()` — flip seen on the store and decrement the matching tab/pane/session counters by one each.
- **`TabRuntime` recorders refactored:** `recordBellTickIfNeeded()` now returns the delta consumed; `recordDesktopNotificationIfNeeded()` returns whether it fired. Neither touches `unseenBellCount` anymore — that propagation is `AppStateStore`'s job. This is a deliberate departure from #0024's first cut: the focus-aware split doesn't fit cleanly inside `TabRuntime`, which can't see the rest of the tree.
- **SwiftUI environment plumbing:** new `EnvironmentValues.appStateStore` key; `RootWindowView` injects via `.environment(\.appStateStore, store)`. `PaneView` reads via `@Environment(\.appStateStore)` and routes the `.onChange` handlers to the store's recordBellTick/recordDesktopNotification methods. A nil-fallback to `tab.recordBellTickIfNeeded()` keeps preview/test usage of `PaneView` working without an injected store.
- **`WorkspaceConversion` round-trips** the new `unseenBellCount` on Pane and Session. The `bellFeed` array on `Workspace` is still serialized but not yet wired into `BellFeedStore` initialization on restore — that wiring belongs in #0030/#0031 cadence work and is intentionally out of scope here.

## Gotchas

- **The unseen-count propagation lives in `AppStateStore`, not `TabRuntime`,** because focus is a tree-wide property the tab can't see on its own. If a future refactor moves bell routing back inside the per-tab object, the focus check (selected session + focused pane + active tab) needs to come too — otherwise a focused-tab BEL would silently bump the unseen count and break the "nothing new while you're looking at it" semantics.
- **`bellFeed.entries` is the source of truth for the feed; `unseenCount` queries on the store are O(N) over up to 200 entries.** That's negligible at our scale (sub-microsecond), so keeping the per-runtime stored counters and the store entries as separate-but-coordinated state is fine. If the cap ever grows past a few thousand, switch the store to maintain a `[UUID: Int]` index per containment level.
- **Burst BEL events — the `recordBellTick` loop emits one `BellFeedEntry` per delta unit.** A `printf '\a\a\a'` produces three entries, each with the same timestamp (libghostty doesn't time-disambiguate within a single tick). The popover (#0026) should de-dupe visually if this becomes annoying.
- **`Workspace.bellFeed` persistence is not wired up here.** The model has the field; restoring it into `BellFeedStore.entries` on launch belongs in #0031's restore path. Until that lands, the feed starts empty on each app launch.
- **The `surfaceID` and `windowID` on `BellFeedEntry` are placeholders** (defaulted to `UUID()` per call). Multi-window isn't built out yet (#0009 covers single window), and `surfaceID` isn't tracked at the runtime level. They're recorded so the schema is stable but not yet consulted by anything.
- **`PaneView`'s nil-store fallback is intentional.** Constructing a `PaneView` directly in tests or previews without an `AppStateStore` parent shouldn't crash on bell events — it falls back to the tab-only recorder path that was in place before #0025.
