# 0550 — The terminal background image's Fit options have web jargon names, and the default can leave empty space instead of filling the Pane

| | |
|---|---|
| **Status** | open |
| **Module** | Theme / Settings |
| **Platform** | macOS |
| **First seen** | 2026-11-04 |

## Description

The Fit picker for a terminal background image shows Ghostty's raw values (Contain, Cover, Stretch, None), and its default, `contain`, can leave part of the Pane without any image. Both should change: the options get plain names, and a new background fills the Pane by default. Child of [#0372](0372.md), for release 1.3.5.

The user's words:

> "Now about the background image. We should support a way to fill the background with the image. Either we support scale to fit or size to fit. Apple has 2 options. We could give the choice to the user."

Told that the picker already exists with web jargon labels, and offered a rename plus a default change, the user replied: "Run the beta when the image changes are ready."

## Expected behavior

The orchestrator made these decisions under the user's standing instruction not to stop for choices with a sensible default.

**Display names change:**

| Stored value | Shows today | Shows after |
|---|---|---|
| `contain` | Contain | **Fit** |
| `cover` | Cover | **Fill** |
| `stretch` | Stretch | **Stretch** |
| `none` | None | **Actual Size** |

Fit, Fill and Stretch follow the macOS wallpaper terms. Actual Size doesn't: as far as the filer recalls, the wallpaper menu calls this option Center, which would read wrongly beside the Position picker. Nobody checked that against System Settings.

**The picker needs a new title.** `TerminalBackgroundControls.swift:75` is `Picker("Fit", ...)`, so a picker titled "Fit" would have an option also called "Fit". The plan settles the title, for example "Image Size".

**Stored values don't change.** `contain`, `cover`, `stretch` and `none` are Ghostty's `background-image-fit` values. They are written to `UserDefaults` and to saved Projects, and a shared Project's fit syncs to the user's other Macs (`Concepts.md`). Only what the picker shows changes.

**The default becomes `cover`,** because the user asked for filling and `contain` can leave empty space.

**Help names the options.** The `**Fit** and **Position:**` bullet in `BattyKit/Sources/BattyKit/Help/11-backgrounds.md:22` should name all four and say what each does, using the picker's new title.

## Who the new default reaches

- **The background image has not shipped in a tagged release.** `git tag --contains` is empty for `a7bfb741` (#0375 on `main`), `fe1a14e1` (its cherry-pick on `release/1.3`), `9ac872b5` and `6d977630` (the #0544 flag removal on each branch). The newest tag is `v1.3.4`, so no Prod user has a stored fit. Beta builds have had the feature behind the flag, so only they can.
- **A stored `contain` stays.** It can't be told apart from a choice, so there is no migration. `writeBackground` (`SettingsPreferences.swift:200-211`) writes the fit whenever any background control changes, so anyone who moved any control in a Beta has it stored without having picked it.
- **The user's own Beta is one of these.** `defaults read co.sstools.Batty.beta co.sstools.Batty.backgroundImageFit` prints `contain` as of filing. They need to pick Fill to see it. **Restore Defaults** also reaches the new default, because `clearBackground` removes the key, but it removes their other background settings too.
- **A saved Project keeps its stored fit.** `encode` always writes `fit`, so the decode fallback only applies to a missing or unrecognized value, such as a hand-edited file or a value from a later version.

## Notes

**Known places that hold the default.** The plan must grep for the rest:

- `SettingsPreferences.swift:40` — `defaultBackgroundImageFit`, which is also the registered default at `:399`.
- `SettingsPreferences.swift:189` — the `?? .contain` after the read of that default.
- `TerminalBackgroundSettings.swift:43` — `fit: .contain` in `init`, which callers such as `.off` take through its default argument.
- `TerminalBackgroundSettings.swift:125` — the decode fallback.

**The label** is `Text(verbatim: fit.rawValue.capitalized)` at `TerminalBackgroundControls.swift:80`, in the controls shared by the Settings, Session and Pane levels. `verbatim` skips localization, and the project has `Batty/Localizable.xcstrings`, so the plan should say how the new names are handled.

**Tests that change or lose their meaning:**

- Two tests assert the old fallback: `TerminalBackgroundConfigTests.unknownStoredFitAndPositionFallBackAndKeepOtherOverrides` (`:255`) and `ProjectBackgroundModelTests.unknownFitAndPositionFallBackAndKeepTheRest` (`:105`).
- **Many fixtures use `cover` as their non-default value**, for example `TerminalBackgroundConfigTests.swift:21,34,131`, `AppWideBackgroundGateTests.swift:60,95` and `ProjectBackgroundFixture.swift:125,139`. Once `cover` is the default, a test relying on such a fixture to prove the stored or override value was read can pass without reading it. The plan should review them and move those that depend on it to a value that isn't the default, such as `stretch`.
- `git grep` finds no UI test that reads the Fit picker, and the picker has no accessibility identifier.

**Release.** Fix on `main`, then `git cherry-pick -x` onto `release/1.3`, which already carries the feature and is at `MARKETING_VERSION = 1.3.5`. Record the release-branch commit in the Work log. The user asked to run the Beta once this is ready.

## Unverified

**Nobody has seen the four Fit options rendered on a real display.** `TerminalBackgroundConfigTests.swift:234-237` only proves that each value appears in the config libghostty accepts. What each one is expected to do comes from Ghostty's documented meanings, not from anything observed in Batty.

Check for the user, in the Beta, with an image whose shape differs from the Pane's and a split Session:

1. **Fit** shows the whole image, with empty space on the sides or top and bottom.
2. **Fill** leaves no empty space, keeps the proportions and crops the overflow. Each Pane draws its own copy, so each split crops differently.
3. **Stretch** leaves no empty space and distorts the image to the Pane's shape.
4. **Actual Size** draws the image unscaled, and **Position** moves it.
5. A new background with no stored fit starts on **Fill**. This needs a defaults domain with no stored fit, since the user's own Beta has `contain`.
6. The picker's title and options read properly in Settings → Appearance, and in the Session and Pane background sheets.
