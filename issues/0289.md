## Description

Terminal Session teardown is correct but not deterministic, and its log line is misleading. `TerminalHostStore.releaseTerminalView(forTabID:)` (`TerminalHostStore.swift:184-191`) drops its dictionary entries, calls `view.removeFromSuperview()`, and logs "released terminal view" — but `removeFromSuperview` only stops the display link and drops focus (`AppTerminalView+Lifecycle.swift:94-97`); **it does not free the surface**. The real `ghostty_surface_free` happens whenever ARC drops the last reference to the `TabRuntime`: `AppTerminalView` deallocates → `TerminalSurfaceCoordinator.deinit` (`:262-271`) → `tearDownSurface` (`:273-293`) → `surface?.free()` (`:283`) → `ghostty_surface_free` (`TerminalSurface.swift:239-245`); and `ghostty_app_free` follows via `TerminalController.deinit` (`TerminalController.swift:258-264`).

Two specific gaps make the deferral fragile:

- `releaseTerminalView` leaves `tab.terminalNSView` set (`TabRuntime.swift:73`), and never calls the available explicit teardown `core.freeSurface()` (`TerminalSurfaceCoordinator.swift:257-260`).
- SwiftUI may still hold the `TabRuntime` after close: `TerminalPlaceholderView.tab` (`TerminalPlaceholderView.swift:23`), `PaneView` (`:522`), and `@State private var renamingTab` (`PaneView.swift:19`). In the ordinary case those clear within a render pass or two, but a stuck reference (e.g. a rename sheet left open on a closed tab) silently keeps a whole ghostty app + surface + PTY + ~48 MB alive with no log line to show for it.

Additionally, three close paths never go through `removeTab` at all and rely purely on subtree deallocation: `WindowRuntime.closePane` (`WindowRuntime.swift:314-334`), `WindowRuntime.removeSession` (`WindowRuntime.swift:117-137`), and `RootWindowView.windowWillClose` (`RootWindowView.swift:195-198`).

Because the "released" log fires before any actual teardown, the log described in `docs/view-hierarchy.md` §6 is **not evidence a surface was freed**.

**Framing: this is not believed to be leaking today.** The #0285 source investigation audited the retain graph and found it clean (weak delegate at `TerminalSurfaceCoordinator.swift:19`, `[weak self]` in all platform hooks at `AppTerminalView.swift:69-94`, `Unmanaged.passUnretained` into C, weak `tabRuntimes` at `TerminalHostStore.swift:64, 261-264`, `retainedBridges` balanced at `TerminalController+Surface.swift:41` / `TerminalSurfaceCoordinator.swift:288`, weak `TerminalViewState.surface`, no reopen/undo stack anywhere). The work here is to make teardown **deterministic and verifiable** — nil the back-reference, free explicitly via `core.freeSurface()`, log from the real teardown point — closing a class of future leak and making the logs trustworthy.

## Resolution notes

> 🟢 Resolved 2026-08-01 — `releaseTerminalView` now frees the surface and kills the PTY synchronously at close time, instead of waiting on ARC.

Three review rounds. Rounds 2 and 3 each found that the *previous round's correction* was itself wrong — appropriate for an issue whose whole subject is a log asserting something untrue.

## Root cause

`releaseTerminalView(forTabID:)` logged "released terminal view" but freed nothing. It dropped its dictionary entries and called `removeFromSuperview()`; the actual `ghostty_surface_free` waited on ARC dropping the last reference to `TabRuntime`, which SwiftUI could still hold via `TerminalPlaceholderView.tab`, `PaneView`, or `@State renamingTab`. The log fired before any of that, so `docs/view-hierarchy.md` §6 pointed at it as evidence of something it never demonstrated.

**Two premises in the original issue were wrong**, both established against the pinned checkout:

- It prescribed calling `core.freeSurface()`. `TerminalSurfaceCoordinator` and `freeSurface()` are `internal` to `GhosttyTerminal` and the AppKit path never calls the latter — that fix was unreachable.
- It claimed `closePane`, `removeSession`, and `windowWillClose` bypassed the choke point. All of them already called `releaseTerminalView` directly. The real count is five call sites (`PaneRuntime.removeTab:86`, `closeOtherTabs:101`, `WindowRuntime.removeSession:127`, `closePane:329`, `RootWindowView.windowWillClose:197`).

The reachable fix was found only in review round 2: `AppTerminalView.controller` is `open`, and its `didSet` reaches teardown synchronously.

## Fix

`releaseTerminalView` sets `view.controller = nil` before `removeFromSuperview()`. The wrapper's `didSet` calls `rebuildIfReady(removingBridgeFrom:)`, whose **first statement** is `tearDownSurface` with the old controller — reached before the `guard let controller else { return }`. So the assignment synchronously runs `surface?.free()` → `ghostty_surface_free`, kills the PTY, nils `bridge.rawSurface`, clears `onWakeup`/`shouldProcessWakeup`, and balances `retainedBridges` via `controller?.remove(bridge)`. No rebuild is triggered.

Ordering is load-bearing: `controller = nil` runs *before* `removeFromSuperview()`, so any layout triggered by removal finds `surface == nil` and returns at the missing-controller guard.

Also: `tab.terminalNSView` is nil'd; `verifyReferenceHygiene` logs (at `.notice`, after 0.5 s) when a `TabRuntime` outlives its close; `docs/view-hierarchy.md` §5/§6 corrected so the logs mean what they say.

## Review

Reviewed by claude-opus-5 over three rounds.

Round 1 blocked on a wording over-claim — the comments said nil-ing the back-reference stopped a lingering `TabRuntime` keeping "the surface, the ghostty app, and the PTY" alive, but the app is a separate chain.

Round 2 blocked on two things: the round-1 correction was *itself* wrong (`TerminalSurfaceCoordinator.controller` is a strong `var` and `TerminalHostStore.swift:134` assigns it, so the controller was retained by the view *and* `TabRuntime`), and — decisively — **the real fix was reachable all along** via the `open` `controller` property. Round 1 had verified the narrow claim that `freeSurface()` is internal, which was true but not the whole public surface.

Round 3 approved. The reviewer confirmed the `didSet` → `rebuildIfReady` → `tearDownSurface` ordering in the checkout, verified double-free safety (`hasBeenFreed` set and the raw pointer nil'd before the C call; `TerminalSurface.deinit` empty; the coordinator's later `deinit` a complete no-op), re-enumerated every reader and in-flight callback against a torn-down surface, and took a full census of strong references to `TerminalController` to confirm `TabRuntime` is now genuinely the last one — including that `TerminalController.shared` is a `static let` never referenced in Batty and never instantiated.

## Gotchas

- **What this delivers and what it does not.** It delivers deterministic, synchronous `ghostty_surface_free` + PTY kill at close, through the single choke point, on all five close paths. It does **not** free the ghostty app or its per-Tab glyph atlas — that remains ARC-gated on `TabRuntime` deallocating, and is #0287's territory.
- **The unit suite does not prove the C free.** In the test harness the view never enters an `NSWindow`, so `isAttached()` is false and **no surface is ever created**; the tests exercise the assignment, not `ghostty_surface_free`. The synchronicity rests on the pinned wrapper's `didSet` → `rebuildIfReady` → `tearDownSurface` ordering. **A future libghostty-spm bump that moved teardown after the nil-controller guard would regress this silently** — re-check that ordering whenever the pin moves (#0286 is the precedent for bumps).
- **Two of the original issue's premises were false** (`core.freeSurface()` reachable; three close paths bypassing the choke point). Both were written from a source trace that read access levels incompletely. Verify API reachability against the pinned checkout, not from a source read.
- **A placeholder could in principle resurrect a released tab.** `TerminalPlaceholderView.body` calls `terminalView(for:windowID:)` unconditionally on every body evaluation, so a post-close body pass for a released tab would mint a *new* view + surface + PTY. Judged unreachable today because the tab leaves `pane.tabs` synchronously with the release — but the logs now declare teardown trustworthy, so this is the way that trust could break.
- **Pre-existing doc drift noticed but not fixed here:** §4's first bullet names `AppStateStore.closeTab(id:)` while §5 names `WindowRuntime.closeTab(id:)`, and §6 quotes a focus log string that no longer matches `TerminalSurfaceFocuser.swift:98`.

## Expected behavior

Closing a Tab (via any close path — `removeTab`, `closePane`, `removeSession`, window close) deterministically frees the surface at close time, and a log line fires from the actual teardown point (`tearDownSurface` or equivalent), so the log is evidence of the free.

**Acceptance criteria must include the open/close census** from the live-instrumentation doc: baseline the `'Batty'` IOSurface count and `phys_footprint`, open 20 Tabs (expect +60 surfaces = 20 layers × 3), close all 20, and confirm both numbers return to baseline. Repeat the cycle 10× — a staircase in the surface count is the confirmation of a leak; a clean return is the confirmation of the fix. The census one-liner is in `issues/0285/investigation-live.md` (and #0291).

## Actual behavior

The free is deferred to ARC; the "released terminal view" log fires before teardown; a lingering SwiftUI reference can keep the surface, app, and PTY alive indefinitely with nothing in the logs.
