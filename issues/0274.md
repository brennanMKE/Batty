## Description

Final scheduled step of the XPC track under umbrella #0265: the topology **read verbs** #0257 deferred to Tier 3 — `batty list [sessions|panes|tabs] [--json]` and `batty session info [--json]` — now carried over XPC request/reply instead of the raw Unix socket #0257 originally penciled in (#0265 amends #0257 §5: the Tier 3 two-way transport is XPC).

**Gate — need, not schedule:** this child starts only when the read verbs are *actually needed* (the driving use case in #0257: an agent inside a pane asking "what's around me"). Blocked on #0271 (request/reply channel) and on #0257's groundwork (the `BATTY_*` context env vars, client-generated ids, and `whoami` — none of which exists in the codebase yet per `docs/batty-cli-install.md` §"Known limitations"). ## Resolution notes

> 🟢 Resolved 2026-07-25 — `batty list` and `batty session info` land as live XPC read verbs, and **Option B's JSON topology snapshot is dropped**.

The decision is recorded below and reflected into #0257 and #0265. `batty list --json` against a real multi-session, split, hidden-pane layout still needs the user's runtime sign-off.

## The Option B decision — dropped

**The snapshot does not survive.** `list` and `session info` are live XPC request/reply only, with no file-based fallback. Rationale, in the order it carried weight:

1. **The cost is real and structural, not incidental.** A repo-wide search found **no generic "topology changed" hook anywhere in the runtime**, and no Workspace persistence exists in the repo at all. The only debounced-save precedent is `SessionNameCache.scheduleSave()` with hand-wired call sites, and `AppStateStore.windows` is `@ObservationIgnored`, so even `withObservationTracking` cannot observe topology generically. Keeping the snapshot means hand-wiring save calls across many mutators on `WindowRuntime` / `SessionRuntime` / `PaneRuntime` — squarely in the focus, selection, and observation paths `CLAUDE.md` flags as highest-risk — plus a permanent second serialization path to keep schema-synced.
2. **There is no consumer yet.** #0257's mutation verbs have not landed, so the offline read path would serve nobody today.
3. **Precedent already points this way.** `batty status` (#0271) shipped XPC-only with no offline fallback and was reviewed and accepted. A fallback for two verbs but not a third of the same family would be inconsistent.
4. **The motivating gap is closed by *a* listing, not specifically by a file.** Scope item 4 — `pane show` having no id-discovery path — is satisfied by any live `list`, and `pane show` is itself a `batty://` mutation that needs the same operational envelope to do anything with the discovered id.
5. **Both "keep" scenarios are separately tracked, not permanent.** Beta-has-no-XPC is #0277's explicit job; `requiresApproval` is one-time first-run friction already surfaced honestly in Settings (#0270). And mutations already work with **zero** XPC via the URL scheme — only *reads* degrade.

**Recorded as reversible:** dropped, to be revisited if the approval-gated degraded mode proves painful in practice. Not settled permanently.

Consequence carried forward: dropping the snapshot correctly drops the **pty device path** field, which #0257 conditioned on adopting the snapshot schema. But the *need* it served — `whoami`'s `ttyname(stdin)` fallback for when the environment is scrubbed (`sudo`, nested shells) — survives the drop and now has no source. No plumbing exposes it today; noted in #0257 rather than filed, since `whoami` itself does not exist yet.

## Root cause

Starting state, not a defect. #0257 deferred the topology reads to Tier 3 pending a two-way transport, and #0265 amended that transport to XPC. This child builds them and settles the snapshot question #0265 raised without deciding.

## Fix

**Shared payloads** in `BattyXPCCore/TopologyPayload.swift`: `TopologyPayload` (pid + windows) plus window, session, pane, and tab payloads, and a `TopologySplitNodePayload` indirect enum mirroring `SplitTreeNode`. All `nonisolated` at type level, all pure `Codable` value types — no view or libghostty types, structurally enforced because `BattyXPCCore` has zero dependencies.

**App side:** `TopologyPayloadBuilder` adds read-only extensions over the runtime types; `AppStateStore` gained `topologyPayload()` and `sessionInfoPayload(sessionID:)` mirroring `statusPayload()`; `AppXPCService.perform` dispatches both verbs exactly as it dispatches `status`.

**CLI side:** `AppServiceClient`'s status-only connect dance was generalized into a shared `perform<Payload>(verb:requestPayload:…)` so all three verbs share one implementation. New `ListCommand`, `SessionInfoCommand`, and a `session` noun.

**Deferred to #0257, per this issue's "do not build ahead" gate:** the `BATTY_SESSION_ID` env branch of target resolution — `--session <id>` and the focused-session fallback exist, with the seam marked in `SessionInfoCommand.resolveSessionID()` and `sessionInfoPayload(sessionID:)` already accepting `nil`, so #0257 can add the middle branch without touching the reply schema. Also deferred: `zoomed` pane state and the pty device path, neither of which exists in the runtime model. No `whoami`, no env injection, no client-generated ids.

## Review

Reviewed by `claude-opus-5`, two rounds.

**Round 1** agreed the Option B drop after independently verifying the load-bearing cost claim, and requested three changes:

- **Eight log lines had been silently redacted.** Generalizing three verbs into one implementation replaced literal `"status: …"` prefixes with `"\(logLabel): …"`, and **`os.Logger` interpolation of a dynamic `String` defaults to `.private`**. The reviewer proved it with a standalone probe: `<private>: app connection interrupted` versus `status: app connection interrupted`. A regression against #0271's reviewed diagnostics and #0272's stated verification tool, in the one place where a failure produces its only output.
- **The `--json` contract baked in compiler-synthesized `_0` keys**, because `case leaf(TopologyPanePayload)` had an unlabeled associated value. Scripts would have keyed off a synthesis artifact, and round-trip tests are structurally blind to this: encoder and decoder change together.
- **Off-actor isolation guards covered 3 of 7 payload types.** Nesting does not propagate the check — a `nonisolated` outer struct containing a non-`nonisolated` `Codable` inner compiles clean.

**Round 2 approved**, verifying each fix independently at the wire and diagnostic level rather than by inspection, and closing the one item the implementer had honestly left open (see Verification).

## Gotchas

- **`os.Logger` interpolation of a dynamic `String` defaults to `.private`.** A literal prefix is public; the moment it becomes a variable it renders as `<private>` with no warning. Any refactor that parameterizes a log message must add `privacy: .public` explicitly. This nearly shipped and would have blinded exactly the diagnostics #0272 depends on.
- **`TopologySplitDirection` is genuinely exempt from the `nonisolated` requirement** — as a `String`-backed `RawRepresentable` enum its `Codable` conformance resolves through the standard library's own unisolated extension rather than this module's synthesis, so stripping `nonisolated` compiles clean. Independently confirmed with a control pair (a raw-value enum compiles; a case-only enum fails `[#IsolatedConformances]`). **`nonisolated` was kept anyway**: dropping `: String` later to add an associated value would silently re-arm the trap, and consistency stops a future reader from "cleaning up" the other four by analogy.
- **Round-trip tests cannot catch wire-shape regressions** — encoder and decoder change together. Only assertions against raw decoded JSON keys can. Those exist for the split node, pane, and session; `TopologyTabPayload`, `TopologyWindowPayload`, and `TopologyPayload`'s own `pid`/`windows` keys remain round-trip-only, so a deliberate property rename there would change the wire shape with tests green. The `_0` risk class is enum-only and fully covered.
- **`TopologyPayloadBuilder` reads the `TabRuntime.workingDirectory` Observation-tracked mirror, not the live Combine value.** That is deliberate and correct — the mirror is wired in `.task(id:)` and *not* unwired on disappear, so it keeps tracking for background sessions and hidden panes, exactly the panes `list` exists to report. Note that `TabRuntime.workingDirectory`'s own doc comment says non-view code "may still read the live Combine value," so this reads as a convention violation until you know why.
- **`sessionInfoPayload(sessionID: nil)` is nondeterministic by design** — it falls back through `keyWindowRuntime()` and `selectedSession`, so the answer depends on which window is key at reply time. That is the documented intent, superseded by `--session` and later by `BATTY_SESSION_ID`.
- `listJSONTopLevelKeysAreStableNotCompilerSynthesized` actually exercises `TopologySplitNodePayload` rather than the `list` verb's root payload; the name is slightly off from what it asserts.
- Nothing asserts `.withoutEscapingSlashes`; dropping it would yield uglier but still valid, still decodable JSON.

## The decision this child must resolve (raised in #0265, not decided)

**Does the Option B JSON topology snapshot survive alongside a live `list` reply?**

- **Case for dropping it:** once request/reply exists, a live `list` answers the same question with no staleness and no snapshot-writing machinery in the app.
- **Case for keeping it:** the snapshot works **with no agent installed and no approval granted** — every CLI command over XPC fails while `SMAppService` sits in `requiresApproval` (see #0270), and the snapshot path has no such dependency. It is the cheap degraded mode.
- **If both exist**, #0257's own guidance holds: shape them so the `list` reply **reuses the snapshot's JSON schema verbatim** (#0257 Option B anticipated exactly this: "shape the JSON so a future socket's `list` response reuses it verbatim").

Record the decision and rationale in this issue and reflect it back into #0257 and the umbrella.

## Scope

1. `batty list` — windows → sessions (id, name, path, active) → tabs → pane tree (split axis, hidden, zoomed, focused), per #0257 Option B's shape, including each tab's pty device path and the app's pid if the snapshot schema is adopted.
2. `batty session info [--json]` — the calling/target session's slice.
3. The Option B keep/drop/share-schema decision above, implemented.
4. Closes #0257's known awkwardness: `pane show <id>` has no id-discovery path until a listing exists (hidden panes appear in the listing).
5. Exit codes per the #0269 vocabulary; `--json` output stable enough to script against.

## Traps that apply here (copied)

- **Message payloads stay `Codable, Sendable` structs as JSON-encoded `Data`** inside the `@objc` protocols (#0269 discipline) — the layout model (`Session`, `Pane`, `Tab`, `SplitNode`) is already pure Codable value types, so the reply payload is nearly free; do not embed view or libghostty types.
- **Reply blocks `@escaping @Sendable`;** any new Foundation-supplied handler closure gets `@Sendable` (the #0272 audit extends to code added here).
- **Reads must not mutate:** `list`/`info` aimed at a background session must not steal focus or switch the active session (#0257's cross-session rule for mutations applies doubly to reads).
- If the snapshot is kept: atomic write (temp + rename), debounced; it is a derived, disposable runtime artifact — *not* Workspace persistence.

## Out of scope

- Live screen reads, `wait`, `send`/`send-key`, `events subscribe`, sidebar activity pills — these need streaming or push, which is **explicitly deferred at the umbrella level; no child exists for it by design.** If one of these becomes genuinely needed, file a new child under #0265 then.
- Tier 0/1 mutation verbs (#0257's own scope) and any change to their `batty://` transport.
