# 0064 — Window title becomes "exit" after the shell exits in a pane

| | |
|---|---|
| **Status** | open |
| **Module** | Window / TerminalSurface |
| **Platform** | macOS |
| **First seen** | 2026-05-11 |

## Description

After the user types `exit` in a tab, the window's title bar flips to the literal string `exit`. The shell's last act before terminating is to emit an OSC 1 / OSC 2 title update tied to its prompt's `preexec`/`precmd` hooks, which fires with `exit` as the command name. `SessionDetailView.navigationTitle` prefers the live OSC title (`terminal.title`) over the session title whenever the OSC string is non-empty, so this stale "exit" string lands in the window chrome.

This is downstream of `#0059` (auto-close the pane when the shell exits): if the pane closed immediately when the shell terminated, the OSC string would never persist long enough to be visible. Implementing `#0059` should make this issue largely disappear in the common case. But the underlying behavior — "the window title can show whatever the last shell command was" — is itself a design flaw worth fixing independently, because it'll show transient values like `ls`, `git`, `vim` whenever the shell's title-update hook fires.

## Steps to reproduce

1. Open Batty. The window title shows `Batty` or the session's name or the live OSC title.
2. In any tab, type `exit` and hit Enter.
3. **Observed:** the window title bar shows `exit`.
4. **Expected:** the window title stays as the session title (e.g. `Batty`, `Session 1`) — or, with `#0059` implemented, the pane is gone entirely so the issue doesn't arise.

## Expected behavior

The window's navigation title should be one of:

1. **The session title.** Stable; matches the sidebar entry. Easiest mental model.
2. **The active tab's chip title** (from `TabTitleFormatter.chipTitle`). Stable; mirrors what the user sees in the chip row.
3. **A short fixed value** like the app name + session title.

Recommend option **1**: just the session title. The chip row already shows tab-level identity; the sidebar shows session-level identity; the window title can be redundant or even just show the session title. Drop the `terminal.title` (live OSC) read entirely.

If we want to keep some "what's running now" hint, surface it as a `.navigationSubtitle(...)` instead — visually distinct, less prominent, and clearly transient.

## Actual behavior

`SessionDetailView.swift`, line 90-94:

```swift
private var navigationTitle: String {
    guard let session = store.selectedSession else { return "Batty" }
    let live = session.focusedPane.activeTab.terminal.title
    return live.isEmpty ? session.title : live
}
```

Whenever `terminal.title` is non-empty, it wins. The shell sets `terminal.title` on every prompt cycle (via the OSC 0/2 sequence from zsh's `precmd_hook`), with the value depending on whatever the shell decides to write — often the last command name, or `user@host:cwd`, or just the cwd. Any of those leak into the window chrome.

## Implementation guidance

The cleanest fix is one line:

```swift
private var navigationTitle: String {
    store.selectedSession?.title ?? "Batty"
}
```

If we want the "what's running now" hint, add:

```swift
.navigationTitle(store.selectedSession?.title ?? "Batty")
.navigationSubtitle(activeChipTitle)

private var activeChipTitle: String {
    guard let session = store.selectedSession else { return "" }
    return TabTitleFormatter.chipTitle(for: session.focusedPane.activeTab)
}
```

But the chip title is already on screen. Subtitle is optional polish; v1 should ship without it.

## Acceptance criteria

- After typing `exit` in any tab, the window title does not flip to `exit` (assuming the pane stays — which depends on `#0059`). With `#0059`, the pane is gone so the question is moot.
- During normal use, the window title stays at the session title (`Batty`, `Session 1`, etc.). It does not flicker on every prompt cycle as the shell emits new OSC titles.
- The chip row still shows live per-tab labels (via `TabTitleFormatter.chipTitle`), so the user can still tell tabs apart.
- Renaming the session (`#0043` / `#0049`) updates the window title.

## Notes

- Related: `#0043` (session sidebar title sticking — fixed). The same principle applies here: stable user-set titles over shell-emitted ones.
- Related: `#0059` (auto-close on shell exit — addresses the "exit" string by removing the surface that produced it). Even with `#0059`, the underlying "OSC title can be anything" issue is worth fixing.
- The chip already does its own prettification (`TabTitleFormatter.chipTitle` strips `user@host:` prefixes, prettifies paths). The window title doesn't need to repeat that work — just use the session title.

## Out of scope

- A user-facing setting to choose between "session title" / "live OSC title" / "subtitle hint." v1 picks one; we can add a toggle later if users ask.
- Restoring window titles after relaunch — depends on `#0055`'s decision about workspace persistence. With `#0055`'s default-no-restore, there's nothing to persist.
