> **Edited 2026-11-19 (#0689, user decisions A-E).** The Server Pane and Web Preview Pane no longer ship (#0690, #0691). Wherever this issue says "Server and Web Preview Panes", read: the toolbar **Servers** list, `batty server share|start|list|stop|restart|unshare|serve`, `batty server serve` running the PhotonHTTP CLI, an optional separately installed tool (#0693; Batty bundles no server and serves no `/_batty/status`), and opt-in tailnet sharing (#0694). Setup is offered only in Settings → Advanced → AI Agents (no prompt, rescoped #0666). Add **webdriver guidance** (decision A): Batty has no in-app browser; to look at or test a page an agent uses whatever webdriver the developer has told it about (for example `safaridriver`, after the developer runs `safaridriver --enable` once), against the localhost or tailnet URL from `batty server list`. Help, the skill and the workflow doc say this; Batty never launches a browser automation tool itself. Follows `AGENTS.md`, "Top design goal: progressive disclosure": document features, don't push them.


Child of #0660, last in order. Once #0661–#0670 land, the user-facing and agent-facing text must say what 1.5.0 does: Batty tells an agent it is in Batty, registers its MCP server after one prompt, keeps it current, and lets the agent open Tabs and Panes that run commands and report their exit status. Today the docs call all of this "Beta only" and list Tab creation and waiting as missing.

### Files

1. **New `BattyKit/Sources/BattyKit/Help/12-ai-agents.md`**, title "AI Agents and Servers". Plain user-facing prose in the style of `10-projects.md` (short sections, bold UI labels, `Settings → …` paths, no issue numbers, no "Beta only"). Use `batty` throughout; one sentence says Batty Beta's command is `batty-beta`. Outline:
   - Intro (2-3 sentences): everything here is optional and off until you set it up; Batty works on its own. Agents (Claude Code, Codex, Cursor, OpenCode) running in a terminal Pane can drive Batty with the `batty` command-line tool or its MCP server.
   - **What an agent knows.** Every terminal Pane sets `BATTY_SESSION_ID`, `BATTY_TAB_ID`, `BATTY_PANE_ID`. `batty agent context` prints which Session, Tab and Pane the agent is in, plus the rules for driving Batty; outside Batty it prints nothing. The MCP server's instructions name the same Pane, and a command or tool given no target acts on the caller's own Pane.
   - **Setting it up.** Settings → Advanced → **Command Line and AI Agents**: install the command-line tool (`/usr/local/bin/batty`), and/or the MCP server and agent guidance per detected agent (tick, **Install Selected…**, preview, **Install**). The MCP server works without the command-line tool. `batty agent install` (`--dry-run` to preview) does the same from a shell. Nothing is offered at launch; after an app update Batty quietly refreshes only what you installed.
   - **What is written where.** Claude Code: a local plugin (`batty`) staged in `~/Library/Application Support/Batty/AgentPlugin/` with the skill, the MCP server and a SessionStart hook that runs `batty agent context`, installed with `claude plugin`. Codex: the skill, and a marked block in `~/.codex/config.toml` (backed up first; re-runs replace only that block) that passes the three `BATTY_*` variables. Cursor and OpenCode: the skill and Batty's entry in `~/.cursor/mcp.json` or `opencode.json` (backed up first, only Batty's key changes). Plus `~/.agents/skills`.
   - **Instructions files (optional).** **Add to Project…** adds a marked Batty section to a project's `AGENTS.md` or `CLAUDE.md` after a preview. **Copy Prompt** copies a prompt you give your agent; it adds or updates a Batty section in its own global instructions file. Batty never edits those global files.
   - **Removing it.** **Remove…** on a host's row; removed files go to `AgentGuidanceBackups` in Batty's Application Support folder. Remove a global Batty section by asking the agent or editing the file.
   - **What agents can do.** One line each, CLI with MCP tool name: `pane split --view git-status --unique` (status Panes), `tab new -c "<cmd>" --wait` and `pane split -c "<cmd>" --wait` (run a command and get its exit status), `notify`, `session remind`, `pane close` / `session close` (close what you open). Point to `batty capabilities` for the full list.
   - **Servers.** `batty server start --port N -- <command>` runs a dev server in a terminal Pane; `server share --port N` lists one already running (Batty never stops it; `server unshare` / **Remove from List**); `server list`, `server stop`, `server restart`. A Process Status Pane watches the server. The **Servers** toolbar button appears only while a server is tracked, or with Settings › General › Servers › **Always show Servers in the toolbar**; rows have **Copy URL** and a menu (Open in Browser, Show Terminal, Restart, Stop).
   - **Serving a folder.** `batty server serve <dir>` runs PhotonHTTP's `photon serve <dir> --host 127.0.0.1 --port N` in a terminal Pane. PhotonHTTP is optional and installed separately (macOS 15+, Swift 6.4 toolchain; `curl -fsSL https://photon-http.sstools.co/install.sh | bash`, installs to `/usr/local/bin`, check with `photon --help`; link `https://photon-http.sstools.co/docs/getting-started.md`). Without it, `serve` stops with that guidance. Short "share a page" steps: write files into a project folder → `server serve` → give the localhost URL from `server list` → tailnet only if asked → stop when done.
   - **Tailnet sharing.** Opt-in per server: **Share on Tailnet** or `batty server tailnet --port N` (`--off` to stop) runs `tailscale serve --bg --https=N http://127.0.0.1:N`; offered only when Tailscale is running; **Copy Tailnet URL**. Batty removes only mappings it made (also at quit); a mapping it found already in place shows "Shared on Tailnet outside Batty" and is left alone.
   - **Viewing pages.** Batty has no web view. An agent that needs to look at or test a page uses the webdriver you told it about, for example `safaridriver` (run `safaridriver --enable` once), against the URL from `batty server list`. Batty never starts a browser automation tool.
