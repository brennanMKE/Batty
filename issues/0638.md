## Description

The user wants one concept for the Bell Feed and for Reminders: "There are unread, read and then the option to clear all read items." Today's Bell Feed has the first two states (`seen` / unseen) but not the third. Its **Clear All** button does not clear anything: it marks every row seen and leaves them all in the list (`AppStateStore.markAllBellsSeen()`; `docs/notifications.md:601`, "Mark All Bells Seen and 'Clear All' never remove rows"). A read row can only leave the Feed by a visit to its Tab, its Tab closing, or the 200-row cap. That works against the standing declutter goal: the Feed should list only what the user missed.

This issue defines the shared concept and applies it to the Bell Feed. #0639 applies the same concept to fired Reminders, and #0640 shows it in the Reminders popover. It is step 2 of the Reminders redesign sequence in #0637 and does not depend on step 1.

## The concept: unread, read, Clear Read

This is binding for #0639 and #0640. In code the flag may stay `seen` (`BellFeedEntry.seen`); the words users see are **Unread** and **Read**.

1. **What takes part.** Notifications take part: Bell Feed rows (bells) and fired Reminders. Pending Reminders do not. They are scheduled, not something that happened, so they are never unread or read and no Read action touches them.
2. **Arrival.** A new item is **unread**. The existing exceptions stay: a bell from the focused Tab while Batty is active adds no row at all (#0555), and while Batty is in the background it adds a **read** row (`effectivelySeen`, `Runtime/AppStateStore.swift:2221`, `:2249`, `:2305`). A muted Session's bells add nothing (#0558). Unread items, and only unread items, light the list's toolbar glyph (`bell.badge`; the Reminders button rings in #0640) and the counters below it (chip dot, Pane dot, Sidebar count).
3. **Unread becomes read** by:
   - **Mark All Read**, the action today's Clear All and Window ▸ Mark All Bells Seen perform, renamed;
   - focus landing on the item's Tab, or for a Reminder its Session, as a fallback when something closes (`markActiveTabSeen()`, `Runtime/WindowRuntime.swift:1359`);
   - clicking a row whose Window is gone (`AppStateStore.jumpToBellEntry`, `:2441-2452`).

   Opening the list does **not** mark anything read.
4. **Leaving the list.** An item leaves the list, read or unread, when its Tab or Session is visited (Open Session, a row click, ⌘1–9, a terminal click: #0556), when its Tab or Session closes, or when the cap evicts it. For Reminders it also leaves on Remind Again and Done (#0639).
5. **Clear Read** removes every read item from that one list and touches nothing else. Unread items stay, pending Reminders stay, and the other list is not affected: the Bell Feed's Clear Read never removes a fired Reminder once #0639 has moved them out, and the Reminders popover's Clear Read never removes a bell. Unread counters do not change, because a read item has already left them. The diagnostic records keep everything: the capture log (#0523) and the decision history (#0297) are not touched.

## Goal

Apply the concept to the Bell Feed.

## Acceptance criteria

- **Popover header** (`Views/BellFeedView.swift:137-152`): "Clear All" is replaced by two borderless small buttons:
  - **Mark All Read**, shown while `unseenCount > 0`, which runs today's `markAllBellsSeen()` behaviour;
  - **Clear Read**, shown while at least one row is read, which removes every read row.

  Accessibility identifiers: `bell-feed.mark-all-read` and `bell-feed.clear-read`. With neither applicable the header shows only the title, as today with an empty Feed.
- **Window menu** (`Commands/BattyCommands.swift:331-336`): "Mark All Bells Seen" becomes **Mark All Bells Read**, still disabled when `unseenCount == 0`. Add **Clear Read Bells**, disabled when no row is read.
- **Command Palette** (`Views/CommandPaletteView.swift:110-115`): retitle the row to "Mark All Bells Read" and keep its id `extra:markAllBellsSeen` stable. Add `extra:clearReadBells`, "Clear Read Bells".
- **Store**:
  - `BellFeedStore` gets a removal that drops every `seen` entry. Like `removeEntries(matchingTabIDs:)` (`Runtime/BellFeedStore.swift:400-414`), it skips the write when nothing matches, calls `pruneRatingState()` and reports the removed ids through `onEntriesRemoved`, which cancels their summarizations.
  - A stored aggregate (for example `readCount` or `hasReadEntries`) is kept in `refreshAggregates()` (`:210-219`) beside `unseenCount`, so the header and menu don't scan `entries`.
  - `AppStateStore` gets a `clearReadBells()` entry point beside `markAllBellsSeen()` (`Runtime/AppStateStore.swift:2424`).
- **Selection:** if the selected row is removed, selection moves to the first remaining row, or to nil when none remain.
- **Read rows look as they do today**: no accent dot (`Views/BellFeedView.swift:250-255`, identifier `bell-feed-seen.<id>`).
- Until #0639 lands, fired Reminder entries are still Feed rows, so Clear Read removes the read ones too. That is consistent with the concept and lasts only until #0639.

## Open questions (defaults in place)

1. **Should opening the Feed mark everything read?** Default: no, as today. Read follows from Mark All Read or from passive focus. Opening the popover to glance does not count.
2. **A per-row Mark as Read?** Default: no. A row click visits and removes the row, and Mark All Read covers the rest. Add it to the context menu later if the user asks.
3. **Should Clear Read also be offered when everything is unread?** Default: no, it is hidden. The user can choose Mark All Read, then Clear Read.
4. **Menu wording.** Default: "Mark All Bells Read" / "Clear Read Bells" in the Window menu and the Palette, with the popover's own buttons unqualified ("Mark All Read", "Clear Read") because the popover is the Bell Feed.

## What needs the user's eye

- Popover header: both buttons appear and hide as rows change state, and their labels fit at the 360 pt width.
- That Clear Read does what "clear all read items" meant to the user.
