## Description

Tier 1 localization target. Strong macOS / iOS developer community in DACH (Germany, Austria, Switzerland). German users are also notoriously meticulous bug reporters — shipping German early surfaces layout regressions fast.

Depends on `#0107`.

## Acceptance criteria

- Every key in `Localizable.xcstrings` has a non-empty `de` translation, reviewed by a native speaker.
- Launching Batty with macOS Language & Region set to Deutsch shows the full UI translated.
- Visual sweep specifically for **string-length expansion** — German is typically 30–40% longer than English. Settings labels, alert buttons, and menu items are the highest-risk surfaces for clipping or wrapping.
- `## Files changed` in the resolution should list the `.xcstrings` diff.

## Notes

- Watch for compound-word length explosions in Settings (e.g. "System notifications" → "Systembenachrichtigungen"). Consider abbreviated forms where layout breaks; flag any layout fixes as a follow-up issue if Settings panes need restructuring.
- Use the formal "Sie" address by default — Apple's convention for German macOS UI; switching to "du" reads as informal / consumer-app-ish.
- Sparkle ships German strings.

## Root cause

The `de` locale was a smoke-test stub after `#0107` landed — only three keys (`Quit Batty?`, `Quit`, `Cancel`) had German translations, and four other keys including all three plural-aware entries were empty. Every remaining key in `Localizable.xcstrings` needed a German translation before German users would see a fully localized UI.

## Fix

Populated `de` translations for every key currently in the catalog:

- `Batty` — passes through as the literal Latin-script brand name, matching the catalog's "never translate the product name" convention.
- `Quit Batty?` → `Batty beenden?` (kept from `#0107` stub; matches Apple's quit-alert phrasing across German macOS apps).
- `Quit` → `Beenden` (kept from stub; standard `NSAlert` button label).
- `Cancel` → `Abbrechen` (kept from stub; macOS-wide convention).
- `Paste %lld lines?` (plural) → `%lld Zeile einfügen?` / `%lld Zeilen einfügen?`. German distinguishes `Zeile` (1) from `Zeilen` (≠1); the verb `einfügen` is Apple's standard term for "paste".
- `There %lld open terminal(s).` (plural) → `%lld Terminal ist geöffnet.` / `%lld Terminals sind geöffnet.`. The subject-verb agreement (ist / sind) tracks German number, and the leading numeral keeps the alert body compact.
- `%lld unseen bell event(s)` (plural) → `%lld ungelesenes Glockenereignis` / `%lld ungelesene Glockenereignisse`. `ungelesen` ("unread") is the closer German idiom for unseen notifications than a literal `ungesehen`; the adjective inflects for the neuter compound noun.

Format specifiers (`%lld`) are preserved verbatim. The catalog round-trips through `xcstringstool` to `de.lproj/Localizable.strings` and `Localizable.stringsdict` cleanly (verified with `plutil -p` on the built bundle).

## Files changed

- `Batty/Localizable.xcstrings` — added `de` localizations (4 simple keys + 3 plural-aware keys with `one`/`other` variants each). The pre-existing `de` stubs for `Quit Batty?`, `Quit`, and `Cancel` were retained unchanged.

## Gotchas

- **LLM-authored, not native-speaker reviewed.** Per the acceptance criteria, a native-speaker review pass is still ideal before this ships to German users. The translations follow Apple's published German terminology (Terminal.app, System Settings, the macOS Human Interface Guidelines' German references) and conventional macOS phrasing, but tone choices (`ungelesen` vs `ungesehen` for the bell badge, `einfügen` framing for paste) are judgment calls a native reviewer may want to revisit.
- **Formal `Sie` address throughout** — matches Apple's German macOS convention. None of the current strings actually address the user in second person (all are object-or-imperative phrasings), so the formal/informal choice is latent rather than rendered, but the issue explicitly called this out and it sets the bar for future strings.
- **Stub-locale reality from `#0107`.** Even with `de` now fully populated, `knownRegions` in `Batty.xcodeproj/project.pbxproj` still does not list `de`. The foundation issue noted that `xcstringstool` emits `de.lproj/Localizable.strings` and `Localizable.stringsdict` correctly anyway — confirmed locally: the built `.app` contains both files. Registering `de` in the Xcode Localization UI is only needed to make the catalog editor render the column.
- **Compound-word length not visually verified.** German is typically 30–40% longer than English; the longest entry here is `ungelesene Glockenereignisse` (the bell-badge tooltip), which is unlikely to clip but has not been observed in the UI. The PRD's broader concern about Settings-panel compound nouns (`Systembenachrichtigungen` and friends) does not arise yet because the catalog has no Settings labels; that exposure will appear when more user-facing strings are extracted.
- **Verified by build, not by runtime.** `xcodebuild -scheme Batty -destination 'platform=macOS' build` passed (with `CODE_SIGN_IDENTITY=-` / `CODE_SIGNING_REQUIRED=NO` / `CODE_SIGNING_ALLOWED=NO`, mirroring the foundation subagent's environment). The compiled `de.lproj` resources were inspected with `plutil -p` to confirm the catalog round-trip. A full runtime visual sweep under `-AppleLanguages '(de)'` — the acceptance criterion for clipping/wrapping under string-length expansion — has not been done and is part of what the user needs to confirm before this moves from `resolved` to `closed`.
