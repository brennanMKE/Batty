Batty command-line reference

Generated from batty capabilities --json, Batty 1.5.0. Machine-readable copy: capabilities.json.

Run batty capabilities --json (batty-beta in Batty Beta) for the exact surface of the build you have installed.

Top-level commands

batty new

Create a new Batty session rooted at a directory, printing its id and focused pane id.

Hints: none

ParameterKindTypeRequiredDefaultAllowed valuesRangeDescription
--jsonflagbooleannofalseEmit JSON instead of the two-line session id / pane id text.
--no-waitflagbooleannofalseDispatch the batty:// URL and exit immediately without confirming the new session — the original fire-and-forget behavior.
<path>positionalstringno.Directory for the new session. Defaults to the current directory.
  • --json has no effect with --no-wait, which exits before there is anything to report

Hints: read-only, idempotent

No parameters.

List windows, sessions, panes, and tabs from a running Batty.

Hints: read-only, idempotent

pane

batty pane split

Split the calling/target pane, printing the new pane's id.

Hints: none

ParameterKindTypeRequiredDefaultAllowed valuesRangeDescription
-c, --commandoptionstringnoRun this command in the new pane in place of the default shell; with --wait it is typed into the shell instead.
directionflagstringnohorizontalhorizontal (-h, --horizontal), vertical (-v, --vertical)Split direction. Defaults to horizontal.
--jsonflagbooleannofalseEmit JSON (paneID, created, tabID, and with --wait exitCode, durationMs, waitResult) instead of the id.
--paneoptionstringnoPane id to split. Falls back to BATTY_PANE_ID, then the focused pane, when omitted.
--pathoptionstringnoDirectory for the new pane to monitor (only valid with --view git-status). Resolved to an absolute path.
--pidoptionintegerno1–Pin a process-status pane to this pid instead of following a terminal's foreground process. Only valid with --view process-status.
--timeoutoptionnumberno600–86400Seconds --wait waits, at most 86400. Defaults to 600. The command keeps running after a timeout.
--uniqueflagbooleannofalseWith --view <kind>, print the id of an existing visible pane of that kind instead of creating one. viewOptions differences (--path/--pid) do not defeat the match. Requires a non-terminal --view.
--viewoptionstringnoterminalterminal, git-status, process-status, lm-studio-dashboard, system-metricsPane content kind for the new pane. Defaults to terminal.
--waitflagbooleannofalseType the command into a shell and wait for it to finish, then report its exit status. Needs bash or zsh. Blocks up to --timeout; MCP callers should pass a timeout below their client's tool-call limit.
  • --unique requires a non-terminal --view <kind> (there is no sensible "the terminal pane" to find)
  • --command is not valid with a non-terminal --view <kind> (non-terminal panes have no shell); omitting --view (which defaults to terminal) is fine
  • --pid is only valid with --view process-status
  • --path is not valid with --view <kind> (only git-status accepts --path)
  • --wait requires -c/--command
  • --timeout requires --wait

Exit codes

CodeMeaning
0Success.
1CLI-side failure — invalid path, malformed id, or a bad option combination.
2Broker unreachable — agent not registered, or awaiting SMAppService approval.
3Broker answered but no app endpoint was registered, and the app could not be started.
4Delivered to the app, which replied with a failure.
5The app terminated while the request was in flight.
6The app is running but not registered with the broker, and did not re-register within the poll bound.
7Could not determine, deterministically, which on-disk app bundle to target.
8Reached the app, but the Project's startup commands need approval and the prompt in Batty went unanswered. Nothing was opened.
64Invalid CLI syntax (ArgumentParser usage error).
