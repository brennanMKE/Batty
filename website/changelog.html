1.3.0 — 2026-10-14

Projects: save a session's layout, panes, tabs and startup commands once, then reopen it ready to work. Shared Projects sync through iCloud to your other Macs.

Projects

  • Save a session as a Project with File ▸ Save Session as Project… or the sidebar's right-click menu. A Project keeps the root folder, color and symbol, the pane layout, what each pane shows, and every tab's directory. (#0469, #0476)
  • Project Editor. File ▸ Edit Projects… creates, changes, reorders and deletes Projects. Save & Open saves and opens in one step. (#0474)
  • Open a Project from anywhere: the File ▸ Open Project submenu, the briefcase button in the sidebar, the Command Palette and Open Quickly. The picker shows your recent Projects as large cards over a filterable grid. (#0490, #0491, #0493)
  • Open now. Already-open Projects appear in a strip at the top of the picker: Return switches, Option-Return opens another copy. (#0499, #0500)
  • Startup commands. Each tab can run a command once its shell is ready. Batty asks before running commands the first time and whenever they change. (#0473, #0479, #0502)
  • Shared Projects sync through iCloud. Tick Shared to sync a Project to your other Macs signed into the same Apple ID. (#0501, #0503)
  • Command line: batty project list and batty project open <name> [--new]. (#0477)

Also new

  • Git Status Panes list the repository's worktrees. (#0488)
  • Each Project has its own sidebar symbol, and a new Help page covers Projects. (#0482, #0504)

Bug fixes

  • Cmd-W with a sheet over Settings or Help leaves both alone. (#0496)
  • The Project Editor asks before quitting with unsaved edits. Its folder choosers open as sheets. (#0481, #0497)

1.2.1 — 2026-10-13

Process Status gets easier to point at the process you care about, and can keep following an app or tool across relaunches.

Process Status

  • Filter the process list. Choose Process… → Pick a Running Process… opens with a filter field. Type a name or a PID to narrow the list. ↑/↓ move the highlight, Return picks, and Esc clears the filter, then closes the picker. (#0486)
  • Follow by name. A Process Status Pane can follow a process by name instead of by PID, and picks up the next process with that name when the current one exits. Turn it on with the Follow “name” by Name button under the process name, the button on the “process exited” banner, or the Follow by name checkbox in the picker. A relaunch is picked up straight away, and a reused PID is never mistaken for the process you were following. (#0486, #0498)
  • An empty Process Status Pane shows Follow a Terminal Pane… and Pick a Running Process… buttons. (#0498)

Bug fixes

  • Splitting from a Git Status Pane, or another non-terminal Pane, starts the new terminal in that Pane's directory instead of your home folder. (#0487)
  • While Settings, Help or another auxiliary window is in front, menu commands no longer act on the terminal window behind it. Cmd-W closes Settings or Help. (#0480)

1.2.0 — 2026-10-11

Panes can now show more than a terminal: Git status, a running process, whole-system metrics and thermals, or a live LM Studio dashboard, each opened from the Pane menu. The batty command-line tool grew into a full remote control for scripts and coding agents, with JSON output, focus/close/hide verbs, idempotent setup, and an installable agent skill.

New features

  • Status-view Panes. Besides terminals, a Pane can now host one of four live, read-only views. Git Status shows the branch, ahead/behind counts, stashes, and staged, unstaged, untracked, and conflicted files, refreshing as the working tree changes, with an inline diff preview and a banner during a rebase, merge, or cherry-pick. Process Status follows the foreground process of the terminal it was split from (or a specific pid) and shows CPU, memory, threads, open files, its command line, and child processes. System Metrics shows the thermal state, CPU temperature and fan speed where the Mac reports them, per-core CPU, a memory breakdown with pressure, load average, and a sortable process list. LM Studio Dashboard watches a local LM Studio for loaded models, live requests, throughput, and recent completions; its Prompt Inspector, which shows prompt and response text, is off until you turn it on. (#0304, #0305, #0313, #0314)
  • Creating status views. The Pane menu opens with an Open View section listing Git Status, Process Status, System Metrics, and LM Studio Dashboard; each opens beside the focused Pane. Split Horizontally and Split Vertically are submenus too: Terminal first, then each view kind, for choosing the direction. Every kind also has its own shortcut, Cmd-G Git Status, Cmd-J Process Status, Cmd-Y LM Studio Dashboard, Cmd-E System Metrics, with Shift added to split vertically, and all of them are in the Command Palette and rebindable in Settings → Shortcuts. Cmd-D and Shift-Cmd-D still split a terminal directly. A status view's header has its own close button, and a view pauses its sampling while it is hidden or its Session isn't selected. (#0331, #0378, #0349, #0453)
  • Command-line remote control. The batty tool now covers what a script or coding agent needs to manage its own workspace: batty new confirms the new Session and prints its Session and Pane ids (--json for JSON, --no-wait for the old fire-and-forget behavior); batty session focus, pane focus, and tab focus bring something to your attention; batty session close, pane hide, and pane show undo what a script set up; pane split --view <kind> opens a status view (--path for Git Status, --pid for Process Status), and --unique reuses a visible view of that kind instead of opening a duplicate, so a setup script is safe to re-run. batty list and session info now report each Pane's kind. (#0380, #0381, #0382, #0383, #0379, #0304, #0305)
  • Machine-readable status and capabilities. batty status --json reports the app's state, including which app bundle and version answered, and reports failures as JSON too. The new batty capabilities --json lists every verb with its parameters, allowed values, and defaults, plus the exit codes, so an agent can discover what the installed build supports instead of guessing. (#0384, #0402, #0361)
  • Agent skill for Claude Code, Cursor, OpenCode, and Codex. A batty-cli skill teaches coding agents how to drive Batty from the command line: which ids to keep, how to make setup idempotent, and what to do about each exit code. Run batty capabilities to get a ready-to-paste command that fetches the copy matching your installed version and installs it for every supported agent it finds on your Mac. (#0403, #0404)

Bug fixes

  • The focused Pane's outline now follows the window's rounded corners instead of stopping short of them. (#0339)
  • System Metrics reads the CPU temperature and fan speed on current Macs again, using the hottest of the chip's CPU sensors, and says plainly when it runs in a virtual machine with no sensors. (#0455)
  • The status views lay out cleanly in narrow Panes: status badges stay on one line, tiles and stats reflow, headers stack instead of breaking words, and the Pane's own controls are never cut off. Process ids no longer show a thousands separator. The terminal Pane's header keeps its hide button visible in a narrow Pane, Process Status lists open files and child processes flush left, and the LM Studio Dashboard keeps each request's stats next to its model name in a wide Pane. (#0452, #0454, #0456, #0457, #0458, #0459, #0460, #0461)
  • Shift-Return, Ctrl-Return and Cmd-Return at a zsh or bash prompt run the command, as in Terminal, instead of printing ;2;13~ or ;9;13~. Programs you run from the shell, such as Claude Code, still receive the modified key. (#0393, #0468)
  • Clicking at a shell prompt no longer types characters like 0;42;13M after a program exits without turning mouse reporting off. Shift-drag still selects text. (#0411)
  • Clicking + or Duplicate Tab in a Pane you aren't in now puts the keyboard in the new Tab. (#0408)
  • The batty CLI connects to the Batty that's already running instead of sometimes launching another copy of the app. It now identifies the exact app bundle it belongs to, and recovers on its own when the app's connection to the background helper drops. (#0361)
  • Typing batty in a Batty shell can no longer start a second copy of the app. Shells no longer get the app's own executable directory on their PATH; they get the bundled CLI's directory instead, so batty works in a Pane even if you haven't installed the CLI from Settings → Advanced. (#0364)
  • Closing a Pane now returns focus to the Pane you were in before, instead of jumping to the first Pane in the Session. (#0337)
  • When Batty isn't the active app, CLI commands with no explicit target, batty <path>, and menu commands go to the window you used last, instead of the oldest window. A newly opened window also gets Cmd-B and other window shortcuts right away. (#0439, #0437)
  • The Theme Selector opens scrolled to your current Theme, with it marked and the keyboard selection starting there. Typing a filter scrolls the list to the matching Themes. (#0363, #0394)
  • Open Quickly no longer moves focus onto a hidden Pane; it shows the Pane first. (#0405)
  • Fixed a launch that could show the menu bar but no window. If no window has appeared once launch finishes, Batty now opens one. (#0444)

Changes

  • Windows are no longer restored on relaunch. Batty now always starts with a single new window. The 1.0.5 notes said windows restore with their frames and per-window sidebar state; that no longer applies. Each window still keeps its own Sidebar state while the app is running. (#0444)
  • Clipboard reads need your permission. When a terminal program asks to read your clipboard (for example over OSC 52), Batty asks you first. Your answer covers the rest of that Session and is not kept across relaunches. Denying sends the program an empty reply so it doesn't hang. (#0390)
  • Lower GPU memory for hidden Panes. A Pane you can't see, whether it's hidden or in a Session that isn't selected, now gives back its GPU drawing buffers shortly after it goes out of view and rebuilds them when it's shown again. Memory now grows with the Panes on screen, not with every Pane you have open. (#0388, #0389)

Known issues

  • Shell integration currently works only in bash and zsh. Since the terminal engine update, fish, elvish, and nushell get none, so Session auto-naming from the working directory and command-finished signals don't work in those shells. (#0400)
  • ssh from a Batty Pane no longer forwards COLORTERM or a terminal type the remote host recognizes, which worked in earlier releases. (#0399, #0392)

Under the hood

  • libghostty updated to a newer upstream revision. This update brings the GPU memory and clipboard changes above.
  • The status-view Panes got a reliability pass: System Metrics samples off the main thread, closing an LM Studio or Git Status Pane no longer stalls the UI, quitting cleans up LM Studio helper processes, and Process Status shows real errors instead of stale or zero values. (#0350–#0360, #0354, #0422, #0425)
  • Closing a Session from the Sidebar now uses the same close path as every other way of closing one. (#0396)
  • UI tests now run only inside a disposable virtual machine, never on a developer's Mac, and unit tests wait on completion signals instead of sleeps. (#0412, #0395, #0423, #0428)

1.0.5 — 2026-06-18

Multiple windows, on-device AI for session naming and bell notifications, and terminal themes that follow Light/Dark mode. The AI features require macOS 26 with Apple Intelligence; on earlier systems Batty runs exactly as before with those features disabled.

New features

  • Multiple windows. Open additional windows with Shift-Cmd-N (rebindable in Settings → Keyboard) — handy across multiple displays. Each window is independent, with its own sidebar of sessions and its own selection; Cmd-N still creates a new session in the focused window. Windows restore on relaunch with their frames and per-window sidebar state, bell notifications route to the window that owns the session, and the app quits when the last window closes. (#0234, #0235–#0239)
  • AI session naming. When a session enters a folder with no recognizable project markers, Batty can name it using Apple's on-device Foundation Models, reading the path and a few top-level files to suggest a short name. It runs entirely on-device, never overrides a name you set yourself, and falls back to the default when there's no good signal. Toggle it in Settings → General → Session Naming. (#0231, #0232, #0233)
  • AI bell-notification summaries. A burst of bells used to all read "Bell". Batty can now summarize each notification into a short, distinguishable phrase shown in the Bell Feed, generated on-device. On by default; turn it off in Settings → Notifications. (#0246)
  • Themes follow Light/Dark mode. Batty stores a separate theme per appearance, so your terminal can use one theme in Light mode and another in Dark, switching live with the system. Settings → Appearance has separate Light and Dark theme pickers. (#0241, #0245)

Bug fixes

  • Theme changes, layout application, Open Quickly, paste, and the theme picker now act on the window you're actually using instead of always the first window. (#0242, #0244)
  • Changing the global theme re-themes terminal panes in every window, not just the first. (#0243)
  • Audited and corrected the remaining window-targeting paths so session, tab, pane, and auto-naming operations apply to the key window in a multi-window setup. (#0248)

1.0.4 — 2026-06-05

Stability release. Fixes a crash and an infinite render loop in split-pane focus navigation, makes click-to-select panes reliable, and keeps session auto-naming in sync with the shell's working directory.

Bug fixes

  • Moving focus across a split with Cmd-Option-arrows no longer crashes the app. An AppKit layout exception was triggered by a focus feedback loop between the terminal's focus state and the pane model; the same loop could saturate the event loop after creating a split. Focus changes are now routed explicitly from their source — clicks and keyboard commands — instead of being inferred from terminal focus flips. (#0229, #0230)
  • Clicking a pane that isn't focused now reliably selects it, and pane selection no longer silently reverts right after creating a split. (#0230)
  • Session auto-naming now follows the shell's working directory dependably — names update on cd even when nothing else redraws the pane — and a session you've renamed by hand keeps its title instead of being overwritten by directory changes. (#0227)

Under the hood

  • Strict Swift concurrency checking enabled across the project.
  • UI test coverage added for cd-driven session rename and reset. (#0228)
  • New focus-architecture rules documented in-repo; the split-pane focus path was audited against them end to end. The four click-to-focus UI tests are green again and act as regression guards for pane selection.

1.0.3 — 2026-05-21

Bug-fix release. Cmd-W in Settings now dismisses the sheet instead of quitting the app.

Bug fixes

  • Cmd-W in the Settings window now dismisses it instead of quitting Batty. The global shortcut handler was intercepting the keystroke before AppKit could route it to the sheet. BattyShortcuts is now scoped to the main terminal window, so standard AppKit sheet dismissal takes over when Settings is frontmost. (#0196)

Under the hood

  • libghostty dependency updated to the latest upstream revision.
  • Comprehensive UI test suite added: tab lifecycle, pane focus, sidebar, drag-and-drop, Open Quickly, tab rename, and modal confirmation flows. The test runner now ships as scripts/run-ui-tests.sh to work around a macOS Gatekeeper signing quirk with the Xcode UI test runner.

1.0.2 — 2026-05-16

Clickable hyperlinks from shell programs that speak OSC 8.

OSC 8 hyperlink support

Modern shell tools emit clickable links via OSC 8 escape sequences — ls --hyperlink=auto turns filenames into file:// links, cargo and gcc diagnostics make file:line:column jumpable, the gh CLI links PRs and issues, and eza, git, pytest, and many others have opt-in modes. Batty now renders those links with an underline and a pointing-hand cursor on hover.

  • Cmd-click opens the URL via the system's default handler — browser for http / https, Finder or the bound app for file://.
  • Plain click is preserved so shell programs that consume mouse events (vim, less, fzf) keep working. Matches Terminal.app and iTerm2 convention.
  • URL schemes are restricted to http, https, file, mailto, and ftp; anything else is a silent no-op to keep a malicious shell program from launching arbitrary handlers.

Quick repro in a Batty pane: printf '\e]8;;https://example.com\e\\example\e]8;;\e\\\n' — the word example should be underlined and Cmd-clickable. (#0125)

Under the hood

  • Release pipeline auto-derives CURRENT_PROJECT_VERSION from today's UTC date (YYYYMMDD) so Sparkle build numbers can't collide between releases. (#0124)

Known gaps

  • Right-click Open Link / Copy Link on a hyperlinked cell is deferred — the libghostty wrapper doesn't yet expose a menu hook. Cmd-click works; the context menu will land once the wrapper API is in place.

1.0.1 — 2026-05-14

First update after launch. Cursor-motion shortcuts, friendlier paste, and a fully localized UI.

Cursor motion at the shell prompt

The standard macOS Terminal-style shortcuts for moving and editing the current command line now work out of the box:

  • Option-Left / Right — jump one word at a time.
  • Option-Delete — delete the previous word.
  • Cmd-Left / Right — jump to the start or end of the line.
  • Cmd-Delete — delete to the start of the line.

Previously Option-arrow inserted composed letters and Cmd-arrow did nothing useful. (#0106)

Paste confirmation

The default for multi-line paste changed from always confirm to never confirm — multi-line clipboard contents now land in the terminal directly, matching Terminal.app and iTerm2 defaults. The picker (Cmd-, → Paste Confirmation) is unchanged for anyone who wants the safety net back — pick Always confirm multi-line or Confirm only with shell metacharacters. (#0105)

Localized UI in 14 languages

Menus, settings, alerts, and the Help system now appear in the user's preferred macOS language. Translations are provided for:

  • 日本語 (Japanese), 简体中文 (Simplified Chinese), 繁體中文 (Traditional Chinese), 한국어 (Korean), Deutsch (German), Français (French), Español — España, Español — Latinoamérica, Português (Brasil), Italiano (Italian), Polski (Polish), Nederlands (Dutch), Русский (Russian), Türkçe (Turkish).

Translations were drafted with machine assistance and have not yet been reviewed by native speakers — corrections welcome via GitHub Issues or pull request against Batty/Localizable.xcstrings.

Under the hood

  • BattyKit source files reorganized from a flat root into eight concern folders (Views/, Runtime/, Model/, Commands/, …) for easier navigation. No user-visible change. (#0122)

1.0.0 — 2026-05-13

First public release.

Batty is a native macOS terminal multiplexer built on libghostty. v1.0.0 covers the full sessions / panes / tabs feature set, the unified bell feed, and Sparkle auto-update.

Sessions, panes, and tabs

  • Sessions sidebar with per-session bell counters and a per-session notifications mute.
  • Recursive horizontal / vertical splits with drag-resize.
  • Tab strip with auto-derived titles (project name → live OSC title → cwd basename) and an unseen-bell dot.

Terminal experience

  • libghostty under the hood — Metal-accelerated, true-color, ligature-friendly rendering.
  • IME support for CJK Romaji, dead-key composition (Option-E + E → é), and the Ctrl-Cmd-Space emoji picker.
  • Drag-and-drop of file paths from Finder into a pane, shell-quoted on insert.
  • Multi-line paste confirmation sheet (paste strictness configurable in Settings).
  • Cmd-W busy-tab confirmation when a foreground process is running; auto-close on shell exit cascades through pane and session.
  • Cmd-Q with terminals open prompts; cancel keeps the app running.

Bell feed

  • Every BEL and OSC 9 lands in a unified popover (Cmd-Shift-N).
  • Click an entry to jump to the originating tab.
  • Optional system notifications for background bells; per-session mute when a long build gets noisy.

Themes and settings

  • Live theme switching via View → Theme and Settings → Appearance; choice persists.
  • Settings (Cmd-,) for font size, cursor style, paste strictness, confirm-quit, bell sound, and system-notification policy.

Distribution

  • Signed with Developer ID, notarized, and stapled — launches on a clean Mac with no Gatekeeper warning.
  • Sparkle auto-update wired to appcast.xml; toggleable in Settings → Notifications.
  • Unsandboxed (terminals run arbitrary user processes) with Hardened Runtime enabled.

Known limitations

  • Per-tab close-confirmation is deferred until libghostty exposes a CommandStart shell-integration signal (#0036). Quit-time confirmation still covers the most important case.
  • Window-level click-to-jump is a no-op for the single-window default; multi-window expansion comes later (#0027).
  • Bundled terminfo / shell-integration is currently unbundled — $TERM falls back to xterm-256color and some Ghostty-specific extensions silently degrade (#0003).
