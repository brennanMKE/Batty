System Metrics view — visual design (#0314, phase 1)

Mockup of the fourth non-terminal Pane kind (system-metrics), the whole-machine counterpart to process-status (#0305) — thermal state, CPU, memory, load average, numeric temperature and fan speed, and the full process list, the way a native Mac app can present them rather than a TUI. Switch between the five states below. Every number here traces to docs/design/system-metrics-view.md §1's feasibility spike, including its round-1 mistake and round-2 correction: temperature and fan RPM are read via the classic SMC struct-method technique, unprivileged — a design premised on them being unreadable (this mockup's own earlier draft) was itself wrong, caught on review. State 4 carries the two open verification questions that finding still has. See that document for the exact commands, numbers, and the reasoning behind every other choice.

Temperature and fan readings are real, but ship with two open verification questions
The classic SMC struct-method technique (IOServiceOpen + IOConnectCallStructMethod) reads real values here, unprivileged — confirmed twice, independently, after an earlier spike script's struct-layout bug produced a false "unreadable" result in round 1 of this design. Two things are not yet confirmed: (1) every read so far ran as an ad-hoc swift script, not inside the signed, notarized, hardened-runtime Batty.app — phase 2 must re-verify there before shipping; (2) the SMC key names shown here (Tp09, Te05, F0Ac, FNum, …) are confirmed on this one Mac mini M4 only — Apple has changed SMC key naming across chip generations historically, so a fixed key list will not necessarily resolve on every Mac. Neither caveat is a reason to hide the reading; both are named so phase 2 doesn't have to rediscover them.
1This state replaces an earlier, incorrect one. An earlier round of this same mockup showed a "Temperature — Unavailable" panel here, built on this design document's own round-1 SMC finding — which was itself wrong (a struct-size bug in the spike script, not a fact about this machine). Review caught it, the finding was reversed, and this state now shows what's actually true: the reading works, with two named open questions, not a ruled-out metric.
2"Shown honestly" now means showing the caveats, not showing an absence. The design doc's own accuracy bar (every mockup number must trace to something the spike measured) applies the same way to a positive result as it did to the negative one this replaces — the two open questions above are exactly what the spike did not establish, named directly rather than resolved by assertion.
