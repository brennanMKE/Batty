LM Studio Dashboard view — visual design (#0313, phase 1)

Mockup of the fourth non-terminal Pane kind (lm-studio-dashboard), live observability into a local LM Studio server. Every field shown here was confirmed obtainable by a real spike against a live server on 2026-08-08/09 — see docs/design/lmstudio-dashboard-view.md §1 for the exact commands and captured events, §2 for the two open questions this mockup deliberately does not resolve on the user's behalf, and §4/§6 for why the feed never shows a live token ticker, always flags in-flight pairing as a guess, and defaults to showing no prompt or completion text at all.

1Local-only is this design's recommendation, not yet the user's confirmed decision (§2.2 of the design doc) — this copy states that ceiling plainly rather than silently failing or implying a remote connection was attempted and failed. LM Studio not installed, not running, and version-drifted all land on this same defined state, not a crash or an indefinite spinner, per the issue's own Gotchas.
2This pane isn't stuck waiting for "Retry" to do anything — after two consecutive failed polls it already backs off to a lightweight reachability check every 5s in the background (not the normal 1s cadence, and the two lms log stream subprocesses and the lms ps poll are both stopped while unreachable, per §5 of the design doc) and recovers on its own the moment the server answers again. "Retry" is a manual, immediate reachability probe — the same call the 5s loop would make anyway, just not waiting for the next tick. It is not a re-run of setUp, which only ever executes once per pane's lifetime.
