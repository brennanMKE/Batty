Git Status view — visual design (#0304, phase 1)

Mockup of the first non-terminal Pane kind (git-status), read-only in this ship. Switch between the five states below — this is what review should focus on: does the layout read as a native Batty pane, does the information hierarchy make sense, and is the read-only interaction model (disclosure + selection + inline diff peek, no staging/discard) the right first cut. See docs/design/git-status-view.md for the reasoning and source citations behind each choice.

1Header mirrors PaneView's existing icon language — 22×22pt borderless SF-Symbol buttons at the trailing edge. After the divider, the drag-handle and hide (eye) icons are the same two actions every terminal pane already has — relocated here from the tab-bar row they currently live in, since that row only exists for `.terminal` panes. Without this, a Git Status pane would have no mouse-reachable way to hide itself or start a pane-swap drag.
2Clean state uses the same empty-state shape as BellFeedView/SessionDetailView (icon + title + one-line description) rather than inventing a new pattern — consistent with the rest of the app when there's nothing to show.
